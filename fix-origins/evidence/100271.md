## Fix PR #151003 description (by steipete, opened 2026-09-17T16:49:16Z)

```text
Related: #150950 #151132. Also related: #150942. Reported by @shadesurgeon.

## What Problem This Solves

Successful `openclaw update repair` could leave stale failure warnings and recovery actions visible, full repair delegated service activation to its Doctor child, and updater children omitted valid recovery guidance on ordinary maintenance refusals. An explicit finalization deadline could also exit the parent before asynchronous Gateway restoration, leaving the managed service stopped.

The original 2026.9.4 self-conflict is already fixed on main by #147720 (`fe645cd77de7`), and missing failure reasons by #147286 (`d10ef37bfd56`). Both fixes are included in the 2026.9.5 cut. This is a normal follow-up that completes the recovery UX.

## User Impact

Healthy abandoned-run recovery stays online. Full repair stops and restores its owned Gateway through the update parent; Doctor children never stop or restart it. A fatal phase deadline cancels work, fences late writes, allows bounded settlement, and records the phase/deadline warning. The parent restores and verifies the Gateway before exiting with the original failure code. A restoration failure identifies the problem and the restart command. CLI and Control UI recovery prompts clear after acknowledgement while historical failure records remain available.

Unavailable service inspection still allows state repair under its database owners without claiming service authority. Other maintenance refusals retain the independent `openclaw doctor --fix` recovery step; only the explicit self-parent activation refusal omits that guidance.

## Why This Change Was Made

Reuse Doctor's maintenance owner in the update parent: acquire lifecycle ownership before service stop, release database fences before fresh Doctor children, then restore and verify the owned service after convergence or failure. Inspect newer failed post-core attempts, including legacy rows with empty reasons, so an older abandoned row cannot bypass necessary finalization.

Keep acknowledgement predicates in the browser-safe record owner. Both record and legacy-expiry modules consume the type-only `update-run-recovery-state.ts` contract; the value dependency is record → legacy expiry, which owns the terminal reason. Recovery guidance follows the actual parent-activation refusal, rather than the presence of an update-parent marker.

Finalization reuses the activation deadline owner for cancellation and bounded joining. Native service custody is acquired and restored outside the canceled mutation phase; restoration revalidates the original live maintenance instance and current native service ownership. Terminal exit follows restoration instead of bypassing its `finally`.

No config options, CLI options, database schema, or dependencies change.
