## Fix PR #151686 description (by steipete, opened 2026-09-18T09:52:01Z)

```text
## What Problem This Solves

Valid Codex TOML could select an incompatible approval/sandbox policy, and managed Bun launches could fail artifact validation by looking for an unused Node interpreter.

## User Impact

Quoted keys, multiline strings, native CLI overrides, Unix-socket denials, and managed Bun launches follow the native contracts. Startup can also finish orphan cleanup when the inspected process has already become a plain zombie.

## Why This Change Was Made

Use the existing TOML parser and one concrete spawn invocation for startup and artifact validation. Translate OpenClaw's socket `none` setting to native `deny`, consume `--sock` values correctly, reject proxy-only artifact claims, and remove the retired Code Mode host environment override. Live process identity checks and endpoint trust checks remain in place. The change removes 153 production lines without changing dependency or protocol versions.

## Evidence

- Nineteen regression cases failed against the original configuration/transport code.
- 461 focused and sibling tests passed; 210 configuration tests passed again after their test-file extraction.
- Full build, including declarations and plugin loading, and all selected changed-file checks passed.
- Final independent review through P2 is clean; native contracts were checked at Codex 0.154.0 and the supported 0.149.0 floor.
- A real Bun run with Node absent from the child PATH reproduced the original artifact error. The candidate initialized Codex 0.154.0, finalized its artifact, answered `model/list`, rejected proxy attestation, and shut down successfully. This probe did not perform inference; both runs printed an unrelated Bun tsconfig diagnostic.

Required hosted CI is pending. Real Windows execution has not been run; Windows invocation and artifact cases have focused fixture coverage.
```
