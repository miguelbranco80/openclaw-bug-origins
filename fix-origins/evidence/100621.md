## What Problem This Solves

Fixes candidate Gateway validation spending its startup budget refreshing stale plugins in a disposable state snapshot, then reporting a stopped SQLite integrity worker as a startup failure.

Fixes #148614. Reported by @aaronqianaa (#148614).

## User Impact

Candidate startup verifies copied plugin payloads without downloading replacements and warns that live update finalization owns the refresh. Missing copied payloads remain warnings in the isolated canary. An accepted Gateway stop joins cleanup without misclassifying a SIGTERM/SIGINT-interrupted check as database failure; real integrity verdicts, SIGKILL, and cleanup failures still fail.

The candidate-side changes recognize isolation markers already set by the installed 2026.9.3 updater, protecting that first hop. The new explicit validation-deadline log is updater-side and applies once this updater is installed. No new configuration, schema, dependency, or retention changes.

## Why This Change Was Made

The [shipped updater](https://github.com/openclaw/openclaw/blob/v2026.9.3/src/infra/update-candidate-canary.ts#L112) shares a capped five-minute budget across snapshot, Doctor, lint, config/plugin checks, and Gateway startup. Gateway preflight invokes post-core convergence before its first `loading configuration…` log; convergence can download a replacement only into the disposable snapshot. Repeated validations therefore repeat work that live finalization already owns.

The reported 298-second failed-step duration is the whole validation duration, not Gateway process uptime. In the final attempt, migration continuation finished at 16:34:32.200 and the Gateway's first log arrived at 16:35:42.016: approximately 70 seconds of Gateway pre-log work, with earlier validation consuming the rest. The transcript does not establish that all 4.5 minutes were a registry fetch. Main already replaced the fixed default with state-sized budgets; this change preserves that owner.

The old updater sends SIGTERM to the whole process group. An integrity child's separate admission signal can remain live when that signal kills it. The supervisor now preserves the interruption type, and the run-loop recognizes it only while settling an accepted stop.
