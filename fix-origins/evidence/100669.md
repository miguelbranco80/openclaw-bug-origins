## Fix PR #180414 description (by steipete, opened 2026-10-22T07:44:22Z)

```text
Refs #179481

## What Problem This Solves

Large retained-history inventories can still exceed Node's function-argument limit during Doctor session repair. The alias resolver was already fixed by #162321; the remaining failures come from spreading entire registries, recovery findings, restore results, and warnings into `push`.

## User Impact

Doctor preserves complete archived ownership and recovery diagnostics without a stack overflow. Import, recovery, and restore keep the same ordering, warning content, backup protection, and current-session ownership rules. There are no schema, dependency, or CLI changes.

## Why This Change Was Made

Append unbounded collections one item at a time, and reuse freshly created result arrays where no append is needed. The neighborhood audit also covers legacy-main comparison claims and warning presentation. Remaining argument spreads on this path are bounded by the 256-entry import batch or a one-item producer.

The registry overflow was previously caught and turned into a deferred-history warning, losing the recovered ownership inventory. The settlement-issue overflow escapes `runDoctorSessionSqlite`, matching the failure class caught as `blocked-by-session-repair-failure`. The reporter did not provide an inner stack, and the large settlement-failure population in the regression is synthetic; this PR therefore references the issue rather than claiming its exact production cause is proven.

### Reporter Q2: abandoning retained inputs

`openclaw update cleanup --dry-run` previews eligible rollback originals. After stopping the Gateway and database readers, `openclaw update cleanup` (or `openclaw update cleanup --yes --json`) permanently retires eligible, verified originals. It is not a force-abandon command: incomplete, unverified, or protected recovery inputs remain protected. Database-bound receipts also remain protected until a later completed update. There is no supported command to forget arbitrary unresolved/foreign-receipt inputs. Whether to provide that explicit data-loss escape hatch remains a design question for Peter; none is added here.

Sources: [cleanup command](https://github.com/openclaw/openclaw/blob/0f5ec1bd02ae3d859148da561d10d4e5b3a72785/src/cli/update-cli/cleanup.ts#L57-L67), [maintenance ownership](https://github.com/openclaw/openclaw/blob/0f5ec1bd02ae3d859148da561d10d4e5b3a72785/src/commands/doctor-session-sqlite-retirement.ts#L198), and [eligibility protections](https://github.com/openclaw/openclaw/blob/0f5ec1bd02ae3d859148da561d10d4e5b3a72785/src/commands/doctor-session-sqlite-recovery-inventory.ts#L198-L223).

### Reporter Q3: online inspect/validate

Yes: `openclaw doctor --session-sqlite inspect` and `openclaw doctor --session-sqlite validate` are logical read-only operations and do not take the exclusive maintenance lease. [Doctor dispatch](https://github.com/openclaw/openclaw/blob/0f5ec1bd02ae3d859148da561d10d4e5b3a72785/src/commands/doctor.ts#L93-L104) applies the lock only to [import, compact, restore, and recover](https://github.com/openclaw/openclaw/blob/0f5ec1bd02ae3d859148da561d10d4e5b3a72785/src/commands/doctor-sqlite-maintenance-lock.ts#L141-L143). [Session database readers](https://github.com/openclaw/openclaw/blob/0f5ec1bd02ae3d859148da561d10d4e5b3a72785/src/infra/session-sqlite-migration-readers.ts#L461-L477) open with `readOnly: true` and close afterward. Validation can add load; separate reads can observe different commits while the Gateway runs. SQLite readers may touch WAL/SHM sidecars. Avoid running cleanup concurrently.
