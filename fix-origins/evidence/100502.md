## What Problem This Solves

Fixes repeated full shared-state database copies within a read-only Doctor report, which make diagnostics expensive on large installations.

Fixes #153067 (the read-only Doctor path). Related: #153276 and #153512.

## User Impact

Full Doctor reports reuse private state bytes for ordinary reads while preserving the live database and its WAL files. Each subsequent report reads a fresh snapshot. Selected checks remain on demand; independent verification and writable inspectors retain their copies. No configuration, schema, dependency, or CLI changes are required.

In the matched Linux fixture, seven reports wrote 7.03 GB to staging instead of 21.76 GB. Retaining the report snapshot increases sampled peak temporary occupancy from 184 MiB to 339 MiB for a 154 MiB database; all temporary files were removed afterward.

## Why This Change Was Made

Ordinary idle Gateway, status, and session-list reads produced no snapshot writes in this fixture. Doctor's artifact-preserving contract still requires private copies, but ordinary checks were preparing separate snapshots within the same report. The report now uses the existing retained snapshot lifecycle after update-budget admission and before state inspection. Completed update reports preserve their findings and exit code if private snapshot disposal fails; that disposal-only failure becomes a warning.

Reuse ends with the report; there is no completed-snapshot fingerprint cache. The contributor has since addressed the two initial race findings in their separate cache proposal. Thanks @MasterSwords1 for analyzing the snapshot cost and @dmlau76 for reporting it. This is an independent implementation.

The separate Windows catalog-consent workflow documented by the related PR is outside this Linux fixture; these results do not establish an issue-wide absence of catalog copying.
