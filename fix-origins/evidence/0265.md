## What Problem This Solves

Fixes ID members being able to create a session for an agent excluded by their membership role when linked to a local profile with broader permissions. The same creation policy also applies when resetting a session that does not exist yet.

## User Impact

New sessions honor the member’s agent policy. Existing-session access, local profile permissions, owner access, and reset’s admin-scope requirement keep their current behavior. No configuration or migration is required.

## Why This Change Was Made

Use the operator authority already retained by the session owner for creation checks, including catalog imports, instead of falling back to the linked profile’s role. This adds no new identity channel or state.
