## What Problem This Solves

Fixes slow sidebar catalog polling when unchanged Codex histories repeatedly trigger native discovery and preview parsing.

## User Impact

Catalog pages, cwd filters, and title searches use resident display rows while the home fits in memory. Native events keep Gateway-driven threads current; archive acknowledgements hide rows immediately. Ephemeral helpers are excluded, Codex's selected rollout remains authoritative, and open sources retain their live activity/settings even when cached rows are evicted.

The 20,000-row retention cap does not limit discovery. Saturated searches and older pages use bounded native database-only requests, which can be slower and perform foreground projection. Cold startup uses a bounded first-page wait with existing continuation/retry responses; saved SQLite rows remain available during reconciliation. The wire contract and sidebar polling cadence are unchanged.

## Why This Change Was Made

One index per Codex home replaces per-query TTL/head-page producers. Reconstructible display rows use OpenClaw's SQLite plugin state, C2's 500-character preview bound and prefix selector, and tie-safe pagination. Native metadata owns displayed fields and selected paths. Notifications, database-only metadata walks, and a streamed 30-second day-folder stat scan maintain currency; only changed rollouts receive bounded reads.

A foreground fallback request shares one **20-native-read budget and deadline** across title search, exclusion filling, scheduler steps, and nested metadata/membership/descendant reads. It retains one 64-row page at a time and preserves directional continuation. Source health settles once for the complete fallback outcome; closing abandons its probe. Background hydration keeps its separate grouped attempt and budget. Overflow uses the same live settings/status owners before filtering; remote exact access always verifies fresh non-archived membership, including resident hits. Node lookup no longer treats 100 pages as absence.

Gateway aggregation coalesces concurrent operations only and uses #150196's resident session-row projection. Current binding/state authority checks remain. Progress retains one latest one-host frame per selected catalog/host and one preparation job per subscriber; memory scales with distinct selected pairs. Retirement clears queued frames and joins admitted work. Generic admission/lifetime handling remains for providers, remote transport, progress, and shutdown.

**Zero I/O applies only to local queries answered entirely from resident rows.** Saturation discovery, exact actions, remote enumeration, and Gateway authority checks are outside that claim. Native thread/list has no bounded response projection: the catalog discards unused fields and detaches bounded metadata after decode, but full wire JSON still creates transient allocations.

No new configuration, sidecar, table, or schema version is introduced. Admission and restoration cap each home at 20,000 rows, evicting archived-oldest first.
