## What Problem This Solves

Fixes active CLI-backed tasks showing “Activity unknown” when their live run is known but transient activity events have not arrived or were cleared.

## User Impact

Task details show Running or Queued from the exact live run and update automatically as ownership or queue capacity changes. Explicit waits and unavailable-runtime observations remain authoritative. No configuration, schema, or migration changes are required.

## Why This Change Was Made

Task status previously depended on the transient activity cache even though the run registry already held current execution ownership. The task reader now uses that existing owner when activity is absent, checks the resolved session and agent identity, and republishes task summaries through the existing deduplicated notification path. Capacity and queue-lease changes publish through the run registry, including for runs that suppress session lifecycle updates.
