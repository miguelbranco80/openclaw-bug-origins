## Fix PR #172455 description (by steipete, opened 2026-10-14T18:39:45Z)

```text
## What Problem This Solves

Reopened OpenAI sessions lose prompt-cache hits. The live release gate `embedded-agent-runner.cache.live.test.ts` > openai > "passes the release prompt-prefix gate across instruction refresh, hooks and reopen" failed deterministically on main at turn 4 (the cold reopen): bytes inside already-sent history changed, so every later turn of a long OpenAI session paid for uncached input. Anthropic's identical scenario was stable.

```text
openai release turn 4: prefix changed segment=history[2] path=$.keys[0] leafBytes=9:19
```

## Why This Change Was Made

Two layers, both in how a reasoning item is persisted versus how the warm continuation sends it:

1. Replay and transcript sanitizing dropped a reasoning item's empty `content: []`, so after reopen the item's first key changed from `content` to `encrypted_content`. Empty containers are now preserved; absent stays absent, and nonempty cleartext reasoning is still omitted.
2. The transcript persisted `encrypted_content` from `response.output_item.done`, while the warm continuation reused `response.completed.output`. Both are valid but different ciphertexts, so the bytes still diverged (`$.fields[1]`, 1574:1574). Persistence now uses the normalized terminal item, falling back to the `output_item.done` snapshot when no terminal event arrives.

Review follow-up: async tool calls that follow reasoning wait for terminal settlement so they do not freeze the earlier ciphertext. A single finalization flush now delivers those completed calls on error, abort, or a missing terminal event, so a fully streamed tool call is never dropped.

## User Impact

Long OpenAI sessions keep prompt-cache hits across reopen, instruction refresh, and hooks instead of re-paying full input cost from the first divergent turn. No config or schema changes.

The assertion-safety generator reduced the removed assertion's allowance from two to one.
