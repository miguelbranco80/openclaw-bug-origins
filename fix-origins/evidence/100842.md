## What Problem This Solves

State-read workers load unrelated handlers when restoring subagent records or exporting transcripts. The deployed bundle also pulls the mixed read/write registry owner into the export dependency graph.

## User Impact

These reads load only their selected stream owner. Admission, snapshot, backpressure, cancellation, and cleanup behavior are preserved. No configuration or migration is required.

This does not establish 1GiB or 512MiB Gateway support or quantify a memory reduction.

## Why This Change Was Made

Prepare the selected lazy stream before fresh admission, then execute it within the existing native section. Move restore into a dedicated reader and preserve the owner boundaries in the deployed bundle.

The main integration preserves the newer PostgreSQL bridge and workspace-manifest dispatch, and keeps restore transaction-free. Its existing no-explicit-transaction regression now targets the extracted reader.
