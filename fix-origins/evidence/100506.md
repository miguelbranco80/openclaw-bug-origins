## Fix message body

```text
Updating from 2026.8.x to 2026.9.9, the post-install Doctor started by the old updater had command custody but no OPENCLAW_UPDATE_RUN_ID (8.x never sets it). The missing run ID became an empty, invalid lease owner, so every Doctor subcommand was refused with 'managed handoff admission is invalid' until timeout (~300 s instead of ~60 s) while the Gateway stayed stopped. Managed command custody now uses Doctor's own invocation identity when the run ID is empty; supplied run IDs keep their validation. Closes #167824. Reported and investigated by @GoDiao (#167825).
```

```text
## What Problem This Solves

Fixes post-install Doctor refusing every subprocess with `managed handoff admission is invalid` when updating from an older release such as 2026.8.2, prolonging Gateway downtime and producing misleading maintenance-failure advice.

Closes #167824.

## User Impact

Older updaters can run the candidate Doctor's commands without an update run ID or an environment-variable workaround. Current-driver validation, process ownership, and settlement safeguards remain in place. No new configuration, environment variables, CLI options, dependencies, or schema changes.

## Why This Change Was Made

The older updater supplies the Doctor result channel but no run ID, so command custody passed an empty lease owner into admission. The existing custody owner now derives a nonempty command owner from the Doctor invocation's anchor only when the run ID is empty, using that same identity for reservation and settlement. Supplied run IDs remain unchanged and validated.

Thanks to @GoDiao for the report, instrumented investigation, and proposed repair in #167825. This implementation and environment-boundary regression were authored independently; the contributor branch was not checked out or executed.
```

