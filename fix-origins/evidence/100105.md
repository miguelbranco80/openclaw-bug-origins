## Fix PR #150534 description (by fuller-stack-dev, opened 2026-09-17T03:02:00Z)

```text
## What Problem This Solves

Gateway startup, certificate renewal, and public certificate inspection can buffer an arbitrarily large file when a configured certificate or key path points at oversized input.

## User Impact

Certificate and key files above 64 KiB now fail with a bounded-read error. Normal PEM files, certificate chains, and symlinked deployments remain supported. CA bundles retain their existing behavior, including bundles larger than 64 KiB. Failed renewal retains the previously accepted listener material through the existing reload contract.

## Why This Change Was Made

Use the existing descriptor-bounded reader at the TLS leaf-material owner and close each opened descriptor in `finally`. Preserve current main's read-only public inspection, pair validation, canonical paths, staged generation, timeout, durability, and no-clobber protections.

Maintainer-owned continuation of #111586, credited to @zhanxingxin1998. A replacement preserves contributor attribution without rewriting and squashing the contributor-owned branch's ancestry. The original review's stale-generator and CA-compatibility findings are addressed.

## Evidence

- On current main `90b421ae252ceaea5bf5a9f106eab51bf384431b`, the three new 65,537-byte regressions failed because certificate loading, key loading, and public inspection accepted oversized material.
- With the repair, `node scripts/run-vitest.mjs src/infra/tls/gateway.test.ts src/infra/boundary-file-read.test.ts src/gateway/tls-fingerprint.test.ts` passes all 37 tests on Node 24.20.0/macOS. Coverage includes exact-limit acceptance, overflow, descriptor closure, symlinked chains, 100-certificate CA bundles, generation safeguards, and certificate-only inspection.
- Original #111586 Linux Node 24/OpenSSL source proof is retained as historical evidence; it was not replayed or relabeled as proof for this head. No live Gateway restart, deployment, or Windows symlink proof was performed.
- `node scripts/check-changed.mjs -- src/infra/tls/gateway.ts src/infra/tls/gateway.test.ts src/gateway/tls-fingerprint.test.ts` passed, including core/test typechecks, scoped lint, export scans, formatting, and required guards.
- Fresh independent autoreview is scoped-clean through P2; no actionable findings.
- CI exposed one additional dashboard certificate-only test coupled to `readFile`. The test now observes both read APIs without relaxing the no-key/no-CA invariant; production code is unchanged. `node scripts/run-vitest.mjs src/commands/control-ui-handoff.test.ts` passes all 18 tests, including real CA-signed HTTPS/pinning, and its scoped lint and independent P0–P2 delta review pass. Total focused proof: 55 tests.

## Compatibility Review Disposition

The [completed exact-head review](https://github.com/openclaw/openclaw/pull/150534#issuecomment-5707984869) found no introduced correctness or security defect and recommends retaining the documented leaf-file restriction. Retaining that 64 KiB limit is the intended compatibility decision for this repair: files above the limit are rejected, never truncated or rewritten. The exact boundary and overflow tests cover startup loading and public inspection; symlinked chains and a 100-certificate CA bundle preserve the existing accepted-input contracts.

The review's possible persistent-data-model classification does not apply to this diff. It changes reads only: no config schema, serialized representation, file writer, generation format, migration, or stored bytes change. Existing PEM material at or below 64 KiB remains valid; oversized material needs operator correction rather than an automatic data migration. Generation/pair validation and renewal recovery code are unchanged. This is source and focused regression evidence, not a claim of a live upgrade or renewal run.
```
