## Fix PR #177690 description (by roboclaw-bot, opened 2026-10-19T20:03:26Z)

```text
## What Problem This Solves

Fixes: the sidebar's reconnect Retry action looks like plain text and gives no visible indication that a click started another connection attempt.

## User Impact

Retry now has a visible outline, hover and keyboard-focus feedback, and a spinner while a socket/handshake attempt is active. Duplicate clicks cannot replace an in-flight attempt; Retry becomes available again when a failed attempt returns to backoff. Reduced-motion users get the same busy state without spinning animation. No configuration or migration is required.

## Why This Change Was Made

The existing Gateway snapshot and reconnect deadline own the attempt state, so the UI derives its feedback instead of maintaining a separate timer or loading flag. The shared status component keeps sidebar, collapsed-rail, and mobile feedback consistent.

## Evidence

- Production-built Control UI browser regression exercises outline, hover/focus, two same-task clicks producing one socket, failed attempts, automatic retry, successful reconnect, and reduced motion.
- The new regression fails on the original base's missing outline (0px versus 1px).
- Existing Gateway-status and sidebar/reconnect scenarios pass, including queued offline renames and retained session ownership: 17 scenarios, plus the new regression.
- Focused owner, shell, transport, and status tests: 60 passed. UI typecheck, touched-file lint/format, stylesheet lint, and the Control UI controller guard pass.
- CI follow-up: reproduced the two TS2551 errors in the new browser test with `test/tsconfig/tsconfig.core.test.ui-e2e.json`, then typed the native button callback as `HTMLButtonElement`. - Independent P0–P2 code review found no actionable issues. Simplification removed a proposed second loading flag; the final production change is +61/-9 lines, with no added effects, listeners, or view controllers.
- Inspected before/after crops below show the actual production-built UI at 1280×900, dark theme, with synthetic content. The after state is a real in-flight connection attempt; animation is frozen only for the still.
- Browser proof uses synthetic Gateway WebSocket I/O with the real application and transport adapter. No live operator Gateway was restarted or modified.
```
