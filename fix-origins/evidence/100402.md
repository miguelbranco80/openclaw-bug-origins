## Fix PR #171397 description (by joelagnel, opened 2026-10-13T21:52:26Z)

```text
Related: https://github.com/openclaw/openclaw-windows-node/issues/1717

## What Problem This Solves

Fixes later chat turns failing after an unavailable stdio tool server is removed on POSIX process-group runtimes.

## User Impact

Users can remove a server whose executable cannot start and continue the same conversation. The original launch error and retry diagnostic remain visible.

## Why This Change Was Made

Failed command startup never sends `ready`, so the cleanup owner lost the process-group anchor identity. Include that identity in the failure receipt and join bounded, authoritative cleanup before returning the launch error. Receipt, lineage, relay-exit, and kernel extinction checks remain required; genuine cleanup failures still reject.

## Evidence

Regression negative controls on base `8197f6f8cf4` failed for missing anchor identity, premature failed-start readiness, and same-session removal (`cleanup could not confirm closure`). The production owner files in the rebased parent are unchanged from that baseline. With this fix, the real-process session regression removes the unavailable server and prepares the next turn successfully.
```
