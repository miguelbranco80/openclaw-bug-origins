```text
## What Problem This Solves

Fixes the iOS manual Gateway forms accepting a hostname with an embedded port in the Host field. For example, `gateway.example.com:8443` bypassed the existing host-only guidance because the shared endpoint builder treated every colon-containing value as IPv6 and bracketed it before constructing the URL.

## User Impact

Users now see the existing “Enter only a host name or IP address.” guidance and cannot start a connection until the port is moved to the separate Port field. Valid DNS names and IPv4 addresses continue to work, as do raw, bracketed, scoped, private, and public IPv6 literals. The change does not alter stored Host values, context paths, port bounds, authentication, TLS, permissions, or local-network policy.

## Why This Change Was Made

`GatewayConnectEndpoint` is the shared URL-construction owner used by both manual iOS forms and setup paths. It now asks the existing `LoopbackHost` normalization and Network `IPv6Address` parser whether a value is actually an IPv6 literal before adding brackets. This keeps the decision in the shared owner, preserves the original Host bytes, and avoids duplicating validation in either UI caller or adding another parser.

The shared security suite adds the missing regression for a hostname carrying a port. Existing controls continue to cover DNS, IPv4, raw and bracketed IPv6, scoped IPv6, public IPv6 setup payloads, and encoded context paths. The existing iOS host-only assertion is unchanged.

## Evidence
```
