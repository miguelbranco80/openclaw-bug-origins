## Fix PR #153779 description (by VACInc, opened 2026-09-20T15:11:06Z)

```text
## What Problem This Solves

Fixes misleading tool-failure replies when an agent recovers from an earlier tool error and intentionally yields to wait for a continuation.

## User Impact

A successful pause no longer presents an earlier tool error as the task's final outcome. Real failures, restart messages, and the diagnostic for yielding without a continuation remain visible.

## Why This Change Was Made

Terminal preparation omits the retained error only from reply generation when the attempt yielded and its canonical terminal status is successful. It keeps the original error for execution traces, cron execution-denial diagnostics, and safe Code Mode failure metadata. Continuation admission and scheduling are unchanged.

CI also exposed two existing fixture assumptions in the tested main context. The cold-admission fixture now clears durable clean-close integrity proof as well as its memory cache, matching sibling fixtures; the changed-lanes expectation includes the existing UI TypeScript file selected for Stylelint. These changes retain every assertion and do not change production behavior. Current main was merged while preserving the original contributor commits.

Original fix by @VACInc.
```
