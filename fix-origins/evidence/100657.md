Related: #154370

## What Problem This Solves

The browser's private filename sanitizer misses Windows device aliases such as `CLOCK$`, `CONIN$`, `CONOUT$`, and device stems padded before an extension. Some Unicode padding can also survive the byte limit and leave a staged name that upload-route normalization changes again.

## User Impact

Remote browser uploads use the shared portable filename rules. Reserved names use fs-safe's suffix form, such as `CON_`. Ordinary filenames, file bytes, private permissions, upload limits, per-file isolation, and cleanup remain intact; no configuration or migration is required.

## Why This Change Was Made

Reuse the released fs-safe 0.17 sanitizer through the existing browser SDK bridge, removing the duplicate character loop and device-name regex. The browser keeps its percent/exclamation substitutions and 180-byte UTF-8 limit. Shared normalization also handles C1 controls, and the bounded result is normalized before staging.

The post-truncation ASCII padding and device recheck landed in #153774. This change preserves all four of its regression inputs in the existing 13-case staging table, including one padded `CON` case, and removes the duplicate staging helper. The current-main production delta is **11 lines removed**.

## Evidence

Current-main baseline `fd578cb8a62c` still fails the expanded boundary fixture on the remaining aliases and Unicode padding. Its three distinct ASCII/emoji truncation rows already pass and remain covered by the consolidated fixture.

All 16 upload-owner tests pass. The 13-case fixture took 72 ms, the file's cases totaled 0.254 seconds, and `pnpm test extensions/browser/src/browser-proxy-upload.test.ts --maxWorkers=1` took 35.43 seconds wall time. A separate 14-case real-filesystem run, including an ordinary-file control, verified exact bytes, mode 0600, the 180-byte cap, upload-route admission, and owned cleanup.

All selected changed checks pass, including extension production/test types, scoped lint, plugin boundaries, declaration/closure tests, unused exports, and filesystem/import guards. Fresh managed P2 review is scoped-clean. CI for the updated head remains a landing gate.

* fix(browser): resolve upload paths on the owning browser node, not the Gateway

When a browser session is proxied to a remote node, the upload action
previously ran resolveExistingUploadPaths on the Gateway, pinning paths
to a filesystem the node cannot see and rejecting node-local files. The
node-side /hooks/file-chooser route already re-resolves paths against
its own filesystem, so skip Gateway-local resolution whenever the
request is proxied and forward the requested paths as-is.

Fixes openclaw/openclaw#115251
