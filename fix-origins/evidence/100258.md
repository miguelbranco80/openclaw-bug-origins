## Fix message body

```text
## What Problem This Solves

Deleting a session with default transcript archival fails on PostgreSQL with a SQLite-repair refusal. The archive owner invokes SQLite's lazy schema installer even though PostgreSQL already admitted the complete archive schema when opening the agent database.

## User Impact

PostgreSQL users can delete sessions while retaining their archived transcripts. SQLite keeps its existing lazy archive installation and deletion behavior.

## Why This Change Was Made

Keep the engine distinction in the archive schema owner: install lazily for SQLite and consume the admitted PostgreSQL schema. Existing deletion transactions and archive publication remain with their owners. The regression extends an existing PostgreSQL lifecycle test to archive its final deletion, require an archive receipt, and preserve searchable sibling state.

Production +9/−2; tests +3/−1, with no new fixture. Added requests/wire trips/SQL are 0/0/0 by source inspection. No latency or throughput claim. SQL, transactions, advisory locks, schema, configuration, and durability are unchanged.

## Evidence

- Real Gateway, agent, and model baseline reproduced the default `sessions.delete` refusal.
- Final candidate regression is red on the unchanged archive owner with the intended PostgreSQL/SQLite-repair refusal (one selected failure, 14 unselected cases). The fixed full PostgreSQL owner file passes all 15 cases: 14.52 s file duration, 36.54 s canonical command.
- SQLite archive schema and read suites pass 6 + 6 cases (42.99 s combined command). Core and state-test TSRS, scoped type-aware owner/test lint, and database cleanup pass. These Testbox results cover the exact archive candidate in a transient combined overlay.
- Real Gateway + `openai/gpt-4.1-mini` completed a `session_status` turn, then default `sessions.delete` succeeded. Its compressed archive has 12 events and readable user/assistant markers. Independent PostgreSQL readback found no session row and a published archive. The downloaded archive was decompressed and checked again locally.
- Fresh canonical isolated P0–P2 autoreview completed scoped-clean with no findings; final source verification passed.
- Final-head [CI39570161433](https://github.com/openclaw/openclaw/actions/runs/39570161433) passed, including all three executed PostgreSQL conformance shards. Required CI, dependency-review, and security-sensitive-review contexts passed on `31645949f01e3bca3eca27acc3eb1ce31027afb4`.
```
