## What Problem This Solves

Fixes: updates are refused, or an explicitly pinned Gateway runtime cannot restart after an update, when Node meets the previous compatibility requirements but lacks the latest security-only patches.

## User Impact

Users can update on Node `>=24.16.0 <25 || >=26.1.0` without first upgrading Node. Updates, Doctor, and `openclaw security audit` prominently warn below Node 24.22.1 / 26.12.1. **Upgrade Node promptly:** these patches reject keys compromised in the October 2026 eMudhra incident; continued compatibility does not remove that exposure. SQLite safety checks, excluded release lines, explicit target-package engines and patched provisioning defaults remain enforced.

## Why This Change Was Made

Separate compatibility from security recommendations in the canonical version policy instead of stranding installations. Audit finding `runtime.node_security_patch` describes the audit process runtime, not an unprobed Gateway, and skips Bun. Audit collectors use a coherent sibling module.
