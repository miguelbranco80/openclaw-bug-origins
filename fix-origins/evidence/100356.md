## Fix PR #168329 description (by MoerAI, opened 2026-10-10T08:02:59Z)

```text
Closes #127329

## What Problem This Solves

Settings marks invalid scalar input red but visually hides the existing explanation. Sighted operators cannot tell why a value was rejected.

## User Impact

The existing validation reason is now visible beside an invalid field on desktop and beneath it on narrow screens. Correcting the value removes the explanation. Validation rules, configuration writes, `role="alert"`, and `aria-describedby` are unchanged.

## Implementation

Remove the screen-reader-only clipping class from the existing scalar error span. After merging current main's Solid migration, this span is owned by `FieldRow` in `ui/src/components/config-form.node.shared.tsx`. The browser regression covers visible geometry, correction, the alert role, and the input's description association.

This preserves the accessibility work from #156050 while exposing the same message to sighted users. No overlap with Pash/Sarah changes.

Thanks to @MoerAI for the fix and regression test, and @steipete for the report. The contributor's commits are preserved.

## Evidence

Real Chromium against a built, isolated Gateway serving the real `/settings/advanced` page; no mocked Gateway or substituted renderer. Enter `1.5` in the integer **OpenTelemetry Flush Interval (ms)** field, then correct it to `5`. Tested at 1440px and 390px widths.

- Base `1f7f1e9d7aed7d3e7e7ea74cf2316bceb6262779`: reason text exists but occupies a clipped 1×1px box.
- Head `23ce9bb6e5e3d2bb3adef6f5bc35392576f71b37`: reason is visible at both widths; correction hides it and removes it from layout.
- The description/error IDs and `role="alert"` match before and after.
- Focused Chromium regression passes on the final Solid owner. A pre-fix negative control fails on the clipping assertion.
- Changed-file formatting and lint pass. Built candidate passes a bounded real OpenAI `gpt-5-mini` agent call.
```
