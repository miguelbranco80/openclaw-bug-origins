## Fix PR #199172 description (by roboclaw-bot, opened 2026-11-14T20:19:51Z)

```text
## What Problem This Solves

Fixes: an optional question submitted without a value is summarized as “Answered,” or “Answered elsewhere” when its result is reopened, instead of showing that the field was left blank.

## User Impact

User impact: people can tell the difference between a supplied answer and an intentionally empty response in chat and standalone question links.

## Why This Change Was Made

The Gateway accepts an empty array for a question that allows an empty response. The shared summary previously joined that array into an empty string and fell through to a generic answer status. It now shows **Left blank** only for that explicit, accepted empty value.

Answer validation, submission, and storage are unchanged. Missing answer evidence still uses the existing fallback, secret answers stay hidden, and nonempty, skipped, expired, and unavailable outcomes retain their meaning. The overall request can still be **Answered** while an individual optional field was left blank.

## Evidence

- Two regression cases fail on the main baseline with “Answered” / “Answered elsewhere,” then pass with the fix. Existing nonempty and secret-answer tests remain green.
- 62 focused tests pass across question state, shared chat summaries, and the standalone question page (1.38 seconds total wall time). Hosted CI timing is not yet available.
- Built full-app Chromium proof passes: leave the optional field empty → Submit → inspect the exact empty-array request and accepted outcome; open the recorded outcome in a fresh mobile document with no local submission provenance and verify it sends no mutation.
- Canonical English/i18n baseline and verification, scoped lint, UI typecheck, formatting, and diff checks pass. No generated translation edits or broad E2E matrix.
- Self-review/simplification: one existing presentation owner gains an explicit-empty branch and one English key; 16 net regression-test lines, no new state owner. No independent agent review was launched.

These are same-frame crops of the actual standalone **Question** page, reached from a question link at **/ask/:id**, with synthetic meal-plan data and Gateway responses. This is a web flow, not a native-app emulation or live agent interaction. Before is verified main **210458b3d434db20073789863d9e493a54217358**; after is this change. Both use the light theme and matching viewports/content.
```
