## Fix PR #146491 description (by steipete, opened 2026-09-12T21:19:50Z)

```text
Related: #130741

## What Problem This Solves

Ready session writes can drain as an uninterrupted microtask backlog, delaying Gateway I/O even after each individual write has finished.

## User Impact

I/O gets a turn while queued writes remain pending. Writes keep their FIFO order, and an active write retains ownership until it settles.

## Why This Change Was Made

The existing queue now yields between completed writers after four completions or four milliseconds. Idle and explicitly reentrant writes still start immediately, and queued callbacks retain their caller context and exact results or rejection values.

## Evidence

The four fairness regressions fail on the main implementation because all queued writes finish before the I/O turn. 61 focused tests passed across queue, SQLite diagnostics, and session lifecycle coverage, including ordering, caller context, rejection, cancellation, and bulk identity locks. This change does not establish the full Swarm latency target.

Canonical changed gates pass on the refreshed base. The full Telegram bot test file also passes (167 tests); its debounce fixtures now await their existing deferred-work promises before checking completed replies, preserving every timer boundary and message assertion.

Earlier CI hit the Gateway profile lifetime fixture's 120-second timeout. This branch now inherits main's fresh-handler-factory repair from #146390, keeping that test change out of the writer slice. The original timeout was not reproduced locally, and replacement-head CI remains required. No timeout or assertion was relaxed.

CI also exposed an intermittent compiler-launch `ETXTBSY` failure in the test fixture. A controlled Linux comparison reproduced Node 24.19's recursive copy leaking a writable descriptor into a concurrently spawned process. The fixture now uses the documented filter option, selecting libuv's close-on-exec copy path. Complete copying and the existing compiler launch remain unchanged.

The unchanged TypeScript compiler failed while the inherited descriptor remained open, then ran after it closed. With the filtered copy it ran while the other process remained alive. All 19 real-compiler tests, the fixture's complete changed gate, and fresh independent P1 review pass. This proves the mechanism and prevention; the holder in the original CI run was not identified. Exact final-head CI remains required.

The next CI run stopped during a Matrix binary download connection reset and exposed a separate Signal test race. After closing its listener, that test assumed the released port remained free. A controlled TCP competitor reproduced the assumption's failure. The positive probe now lets the kernel allocate its port; occupied-port refusal, error guidance and listener cleanup stay intact. This changes only the fixture, not operator Signal configuration. All 10 daemon tests and four port-probe siblings pass (one existing alternate-loopback case skips on this host), with full changed checks and fresh P1 review. The failed run remains recorded; validation proceeds on the corrected head.
```
