## Fix PR #150511 description (by steipete, opened 2026-09-17T02:23:17Z)

```text
## What Problem This Solves

SQLite workers can lose their final diagnostic lines when the last backend closes and the broker immediately terminates the worker.

## User Impact

Graceful final-backend close gives pending console output a bounded chance to reach stdout/stderr before acknowledging completion, including when another open is queued. The existing five-second fallback makes this best effort. Database cleanup, queued-write settlement, and error/forced retirement retain their existing behavior.

## Why This Change Was Made

SQLite replies and Node worker stdio use separate message channels, so a successful close reply does not prove buffered diagnostics were delivered. Drain output after backend and delegation cleanup but before the successful final-actor close reply.

The existing output-drain helper moves to `src/process`; CLI exit, native-hook relay, and sealed-worker error callers move with it. Its callback behavior and timeout stay unchanged, and the old path is removed without an alias. The existing real-worker logging fixture gains a bounded teardown burst while preserving its exact JSON and terminal-diagnostic assertions.
```

```diff
+export function drainProcessOutput(exit: () => void): void {
```
