## Fix PR #162412 description (by boeingchoco, opened 2026-10-01T04:57:56Z)

```text
Closes #162393

## What Problem This Solves

Fixes: replies with a long fenced code block are delivered with a broken fence on Discord and LINE when `streaming.chunkMode` is `"newline"`.

## User Impact

User impact: in newline chunk mode, every delivered part of a long code block opens and closes its own fence, matching the default length mode. Short paragraphs still split on blank lines as before.

## Why This Change Was Made

In newline mode, the shared outbound planner split each paragraph longer than the channel limit with plain-text chunking before the channel's own chunker ran. That cut code fences before a fence-aware chunker such as Discord's or LINE's could see them. The planner now splits on paragraph boundaries only and leaves length splits to the channel chunker, which already enforces the limit for each block. This matches what Discord's own newline helper already does. Channels using the plain-text chunker get the same output as before.

## Evidence

Real outbound delivery path: `deliverOutboundPayloads` with a test channel plugin that uses Discord's outbound chunker (`chunkDiscordTextWithMode`, 2,000 characters, 17 lines), delivering a paragraph plus a 60-line ```ts block. Output as `[length, fence lines, first line]`:

```text

after,  newline: [[19,0,"Here is the script:"],[654,2,"```ts"],[684,2,"```ts"],[684,2,"```ts"],[684,2,"```ts"]]
length (unchanged): [[585,2,"Here is the script:"],[684,2,"```ts"],[684,2,"```ts"],[684,2,"```ts"],[99,2,"```ts"]]
```

Real Discord delivery: the same message (a heading line plus a 60-line ```ts block whose lines contain `*note*` and `_n_`) was sent to a private test channel through `deliverOutboundPayloads` with the real Discord outbound adapter and bot REST API, once from the parent commit and once from this PR head, in newline chunk mode. Output as `[length, fence lines, first line]`:
