## What Problem This Solves

Fixes: Activity briefly replaces a settled permission error with loading placeholders when unrelated sessions change.

## User Impact

User impact: denied Activity views remain stable during automatic refresh, while Retry, changed filters, reconnection and relevant access changes can still refresh them. Existing rows remain visible during a same-query refresh and are cleared if the response denies access.

This does not grant new access or introduce a limited-readable-person view. No configuration change or migration is required.

## Why This Change Was Made

Activity now treats a permission denial as settled for the current selection rather than retrying it for unrelated activity. Explicit retries and authority changes bypass that settled state. Hidden-tab authority updates wait for visibility, and superseded responses cannot restore old rows.
