## Fix message body

```text
sessions.files list/get for managed-worktree sessions re-reads the session
entry during settlement to detect a reset or worktree change. Since #169757
that re-read passed the logical store path to readRetainedSessionEntryFacts,
which only knows the physical SQLite path, so it always returned undefined
and every request failed with "Session workspace changed during file read".

Use the captured read source path, matching the other retained-facts callers.
```

## Fix PR #172579 description (by roboclaw-bot, opened 2026-10-14T21:58:57Z)

```text
## What Problem This Solves

Fixes: files in a project worktree session fail to open in the side panel or Files panel with `Session workspace changed during file read`, even when nothing about the session has changed.

## User Impact

User impact: HTML previews and other files from worktree-backed sessions open again in the Control UI. Sessions without a worktree were not affected.

## Why This Change Was Made

`sessions.files.list` and `sessions.files.get` re-read the session after waiting for sandbox settlement, to refuse the read if the session was reset or moved to a different worktree in the meantime. Since #169757, that re-read used the logical session store path, which the retained-facts reader does not recognize, so it always came back empty and every worktree read was refused. The re-read now uses the session's captured read source, the same way the other retained-facts callers do. The safety check itself is unchanged.
```
