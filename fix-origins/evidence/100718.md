## Fix PR #186032 description (by vyctorbrzezowski, opened 2026-10-27T14:48:31Z)

```text
Fixes #186018

## What Problem This Solves

Consecutive identical chat messages without canonical IDs collapse into one bubble with a repetition count, hiding the original message boundaries.

## User Impact

Each real message stays visible in order, even when adjacent messages have the same text. Repeated delivery of the same proven message identity still appears once.

## Why This Change Was Made

Require proven source identity before suppressing a replay, and remove the repetition-count property, badge, Markdown injection, styles, and obsolete badge tests. Sender and tool grouping stay unchanged. Session activity and accessibility counts now use the actual message entries.

## Evidence

- Reproduced on main through the Control UI renderer; existing regression scenarios failed because two messages became one.
- Chromium with a mock Gateway: desktop dark and mobile light render both unidentified messages and distinct same-content IDs separately; a repeated transport event still renders once. Before/after screenshots inspected.
- 176 focused tests across seven files passed in 5.32 seconds (6.60 seconds including the runner), covering identity, incremental history/search, grouping, Markdown/media, highlighting, and session activity.
- UI typecheck, targeted lint, stylesheet lint, formatting, and locale source verification passed. Lint retained warnings on unchanged Solid callback expressions.
- Canonical autoreview of the complete local diff against 43dc38e6c1370e7682156b8a84ed6fc1abfaa0b7 completed with no P0-P2 findings.
- Retired repetition machinery: production +10/-139 lines; tests +28/-84 lines. Existing media and transcript-boundary coverage retained.

## Risk and coverage

CI on the published head failed two E2E cases that also fail on the clean baseline `43dc38e` and in [baseline CI](https://github.com/openclaw/openclaw/actions/runs/40523031614). It also failed a command-error toast assertion outside this diff: that test mounts a plain chat host and exercises unchanged outbox and toast owners, without the modified transcript renderer. The original toast failure remains unexplained; the full 107-test chat-send file passes on both baseline and this head. These passing replays are not a claimed fix, and CI remains recorded as failed.

The renderer proof uses deterministic Gateway fixtures. No live Gateway or provider was exercised. Broader E2E suites and CI remain separate validation.
```
