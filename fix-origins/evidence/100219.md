## Fix PR #155837 description (by steipete, opened 2026-09-22T16:24:15Z)

```text
Related: #154370

## What Problem This Solves

Fixes cloud workspace reconciliation failing when a supported filename contains control characters, and removes the intermediate file copies used to build rollback snapshots.

## User Impact

Workspace results and recovery snapshots preserve exact supported filenames and file bytes, including data affected by Git attributes or checkout encodings. Cancellation waits for private staging files to be cleaned up. No configuration or migration is required.

## Why This Change Was Made

Result staging and rollback now share one streamed Git-input writer backed by the existing released fs-safe API. The existing manifest worker owns hashing and input preparation, Git path quoting is shared, and authenticated tree reads replace temporary working-tree materialization. The worker's native section keeps descriptor cleanup attached to cancellation.

Stored formats stay compatible: the version-1 journal type, parser, serializer, and persistence are unchanged; rollback still stores a SHA-1 tree and its reachable tree/blob pack. Temporary commit metadata is not stored in that pack. The staged-result version-2 header and raw manifest bytes are unchanged, and the existing reader still accepts versions 1 and 2. No schema, retention, protocol version, or migration changes are needed.

## Evidence

- The reconciliation regression failed before the fix with Git reporting an invalid control-character path, then passed with the shared quoting path.
- A cancelled tree read reproduced a leaked private staging file before the native-section change; the regression now verifies cleanup has settled when cancellation returns.
- Seven focused suites passed: 95 tests, 57.50 seconds Vitest duration and 61.46 seconds wrapper wall time with `--maxWorkers=1`.
- Focused coverage includes staged results, reconciliation, recovery, publication, byte limits, raw-byte preservation, and cancellation. The final cancellation replay also passed after adapting the test's deferred helper to the repository's TypeScript library target (20.16 seconds wall time).
- The existing legacy-journal recovery case passed: it preserves derived files and restores `:literal.ts` from stored blobs. Its added corrupt-digest check refuses recovery before live file writes.
- All selected checks passed across the initial run and focused correction replay: production and test typechecks, formatting, typed lint, documentation and boundary guards, dead exports, and the remaining runtime guards. `git diff --check` passed. Independent scoped review found no actionable issues.
```
