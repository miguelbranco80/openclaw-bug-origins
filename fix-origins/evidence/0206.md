```text
* fix(cron): webhook automations POST skip text when a run skips before it starts

The primary webhook skipped deferred admissions through a scheduling
predicate that ignores runs with a trigger result, so a deferral after a
fired trigger, and other skips before execution such as an empty
scratch, were POSTed with their skip text as the summary. Skip every
result that is skipped with executionStarted false.

Covers the cases a too-broad skip check would drop: a fired trigger
followed by real output, and an error from a run that never started.
```

## Fix PR #200032 description (by daniel-lxs, opened 2026-11-16T08:24:38Z)

```text
Closes #200030

## What Problem This Solves

Fixes: an automation with webhook delivery POSTs a "finished" event carrying skip text ("Automation admission deferred by its current window or foreground activity", "Automation scratch is explicitly empty") as its summary when the run skipped before it started, most visibly when a trigger fires while the agent is busy.

## User Impact

Webhook receivers get a POST only when a run actually executed (or failed). A run that skipped before execution, with or without a fired trigger, sends nothing and records `deliveryStatus: "not-requested"`. Skip reasons stay in automation history.

**Behavior change:** skipped runs no longer POST to the job's primary webhook (`delivery.mode: "webhook"`). Integrations that need skip events can read them from run history (`openclaw automations runs` or `cron.runs`), set `failureAlert.includeSkipped: true` to get a failure alert after repeated skips, or use announce delivery with a `delivery.completionDestination` webhook, which this change does not affect.

## Why This Change Was Made

The primary webhook already skips deferred admissions, but its check reuses a scheduling predicate that ignores any run with a trigger result (a fired trigger spends the occurrence, so scheduling must not retry it). That is right for scheduling and wrong for delivery: the run still has no output. The webhook skips every result that is `skipped` with `executionStarted: false`. That covers the trigger case and other skips before execution, such as an empty scratch. Scheduling and run finalization keep using the existing predicate unchanged.

## Evidence

Tests in `src/cron/service.trigger-eval.test.ts`, run against the real cron service harness:

- A trigger fires, the isolated run defers its admission: no webhook call, the finished event is `skipped` with `triggerFired: true`, and the trigger counts once.
- A non-trigger run skips on an empty scratch: no webhook call, the skip text stays in the finished event.
- A trigger fires and the run returns output (`ok`), or fails before it starts (`error` with `executionStarted: false`): one webhook call carrying that status and its summary or error.

Without the change, the first two fail at `sendCronWebhook` being called once (with `status: "skipped"` and the skip text as `summary`). With it, all pass. The third guards against a check that is too broad: without the `skipped` status condition the error case fails, and skipping every run after a fired trigger fails both cases. Output and error delivery without a trigger are covered by the existing optional-output cases in the same file and the busy-deferral tests in `src/cron/service.session-payload.test.ts`, which deliver the run's output once the agent is idle.

Nearby cron suites with the change: 14 files, 218 tests pass (trigger evaluation, session payload, restart delivery, persisted delivery status, failure alerts, delivery plan, manual delivery, cross-tick admission, jobs, timer outcomes, webhook interruption, batch finalization, trigger timer, command timeout). `src/cron/cron-delivery-outcomes.e2e.test.ts` passes 5 of 6: "applies threshold and cooldown once before transporting execution failure alerts" fails the same way on unmodified main (2 of 2 runs), on failure-alert message text for an errored run, which this change does not touch.

Typecheck (`tsconfig.core.json` and the cron test config), oxlint, oxfmt, `git diff --check` and the test-line budget (+85 of 400) on the touched files pass.

One isolated agent-turn automation with `skipIfScratchEmpty: true` and webhook delivery, created with `cron.add`, scratch emptied with `cron.scratch.set`, run with `cron.run` in `force` mode:

| Build | Scratch | Receiver got | Run record |
| --- | --- | --- | --- |
| main | empty | `POST /hook` with `status: "skipped"`, `summary: "Automation scratch is explicitly empty"` | `deliveryStatus: "delivered"` |
| this change | empty | nothing | `skipped`, same summary, `deliveryStatus: "not-requested"` |

The third row shows a run that executes still delivers its output. The trigger-fires-while-busy deferral is covered by the first regression test: reproducing it on a Gateway needs the agent to turn busy between the preflight check and the run start.
```
