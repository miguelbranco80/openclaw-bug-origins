## What Problem This Solves

Fixes HTTP 500 when a required-worker session prepares its workspace while retaining a canonical session reader.

## User Impact

Required native workers can bind a new session workspace without invalidating their admitted session read. No configuration, schema, permission, or migration changes.

## Why This Change Was Made

The opaque commit callback selects a native transaction on the same handle retained by dispatch admission. Its canonical-reader check rejects that active transaction with `Canonical session reader continuation is no longer current` before the first model request can run.

Source-free workspace bindings now use the existing worker-write grant contract, which validates host authority at planning and commit boundaries without opening a transaction on the retained reader. Inherited workspace source callbacks keep their native atomicity because they may read other stores. The strict reader-currency and revocation checks remain unchanged.
