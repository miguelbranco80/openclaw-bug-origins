## Fix PR #166406 description (by steipete, opened 2026-10-07T02:50:42Z)

```text
## What Problem This Solves

Two `/hooks` endpoint behaviors did something other than what the request asked for, without an error:

1. **Malformed session keys were silently ignored.** An authenticated `/hooks/agent` request with a malformed `sessionKey` (`null`, a number, boolean, object, array, empty, or whitespace) returned 200 and dispatched to the fallback session, so the caller's routing intent was dropped without telling them.
2. **Transforms could not make a wake immediate.** When a mapping was configured for `next-heartbeat`, a transform returning `mode: "now"` or `wakeMode: "now"` was ignored. Both the wake HTTP response and the agent job stayed deferred.

## Why This Change Was Made

1. `normalizeAgentPayload` in `src/gateway/hooks.ts` discarded supplied but invalid keys instead of rejecting them (behavior since `1ed5ca3fdeb`). A supplied key must now be a valid session key, or the request gets 400 with nothing dispatched. An omitted key still uses the documented default.
2. `mergeAction` in `src/gateway/hooks-mapping.ts` only recognized overrides toward the deferred mode (since `aeb54555558`). It now honors a transform's immediate override as well. Invalid transform values keep the existing fallback and validation.

## User Impact

Hook callers get a clear 400 for bad session keys instead of a silent reroute, and transforms can make a wake immediate.

## Evidence

- Regressions: malformed keys returned 200 before the fix and return 400 with no dispatch after. A `now` override stayed `next-heartbeat` before and is honored after, in both the HTTP response and the job.
- 12 related suites (205 tests) and the full `check-changed` gate passed remotely, and `server.hooks.test.ts` passed 19/19 on Linux.
- An isolated CLI and Gateway on a remote box exercised missing or bad auth, 429 throttling and reset, malformed JSON, oversized bodies, invalid routing, queue-full 503, wake coalescing, restart, external-content wrapping with stub inference, mock-channel delivery, and eight concurrent replays with exactly one delivery.
- Production +10/-2; tests +44; docs +4.

Found but not changed here: after a restart, an immediate wake followed quickly by an agent request using `waitForCompletion` can get a recorded 502 (`AgentDatabaseRegistryChangedError`) from the registry-ownership guard. This is being investigated separately; the guard is correct and stays.
```
