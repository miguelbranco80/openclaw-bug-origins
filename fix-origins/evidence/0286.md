## What Problem This Solves

Capturing a shell snapshot before a host command could freeze the entire Gateway for several seconds while btrfs committed a transaction. Exec preparation and a detached upload-cleanup timer also lacked task names in main-thread stall reports.

## User Impact

Shell snapshot capture now creates its temporary directory and output file asynchronously, so those filesystem operations no longer block the Gateway event loop. Remaining preparation or upload-cleanup stalls have structural task names. No configuration, protocol, dependency, or operator action changes.

## Why This Change Was Made

Production kernel samples showed 6.3-second and 7.9-second main-thread freezes in `D / wait_current_trans / syscall 437` (`openat2`); one overlapped a 13.5-second btrfs commit and had no CPU profile. Subsequent tracing identified `.` followed by `openclaw-shell-snapshot-<uuid>-<rand>` as the main-thread opens. The async fs-safe temp-workspace API synchronously creates its native root and exclusive file, identifying shell snapshot capture as the owner.

Use async `node:fs/promises` at that owner: `mkdtemp` creates a fresh private directory, directory permissions are 0700, and the output opens with `O_CREAT | O_EXCL | O_NOFOLLOW` and 0600 permissions. Capture reads the retained descriptor and closes it before recursive cleanup in `finally`, including failure exits. The existing capture subprocess still writes its output inside that private directory. This removes the fs-safe temp-workspace path without adding a worker or changing fs-safe; the existing trusted temp-root resolver remains responsible for root admission.

Exec preparation runs under `exec:spawn-prepare`; detached upload expiration runs under `terminal-upload:cleanup`, both using the existing stall-attribution owner. No path contents or user data enter either label.

## Evidence

Existing shell behavior, cache, subprocess and broker-deadline suites pass. The Node-specific exec-entrypoint test records a simulated 1,200 ms resumed preparation stall as `exec:spawn-prepare`; the existing upload-expiry test checks its detached callback's task name.
