## What Problem This Solves

Session-entry worker publication rebuilds a sharing projection that its owner already prepared, making the existing cancellation-ordering regression fail with four entry-shaped clones against its unchanged budget of three.

## User Impact

Removes a redundant publication clone without changing session contents, mutable patch results, commit ordering, or authority checks. No schema, configuration, or migration changes.

## Why This Change Was Made

`prepareSessionEntryReplacementChanges` computes the sharing projection once. Its current-publication reader omitted that fact, so `readPreparedSessionEntryChange` recomputed and cloned it when the replica subscriber read the publication. Carry the existing sharing projection through the same supersession check as the entry.

The regression starts at **36190da70d0e8797be4db0eec82b30479210393a**, PR #183276: its resident-entry lookup installs the replica subscription. The new subscriber exposed the missing prepared fact; the mutable-result copy in that PR is not the redundant clone. That copy remains intact.

Production LOC delta: **+1 / −0**. This adds the missing field to the existing owner result and eliminates repeated work; it adds no state, cache, or alternate path. The existing regression is unchanged, including its `<= 3` budget and nested caller-mutation assertion.
