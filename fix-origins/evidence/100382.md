## Fix PR #147421 description (by steipete, opened 2026-09-13T21:10:39Z)

```text
## Problem

Browser relay and network-backed plugins can hang, ignore proxy options, or fail during startup when Bun substitutes partial package-entry implementations for `ws` and `undici`.

This affects Browser relay, Mattermost, Slack relay and API proxying, Reef, Codex inference, Nextcloud Talk, and Crabbox when OpenClaw runs under Bun.

## Solution

Publish the existing gateway-client npm-`ws` loader as the typed `openclaw/plugin-sdk/websocket-runtime` contract, migrate bundled callers to it, and remove Mattermost's duplicate loader. The new public subpath exposes the same maintained WebSocket implementation already used by the Gateway client; it adds no dependency.

Slack now uses the shared HTTP/1 environment-proxy dispatcher and runtime fetch adapter instead of Bun's placeholder bare-`undici` exports. Nextcloud tracks the listen callback as the safe close boundary, while Crabbox fault fixtures and the intentional Node child path use runtime-neutral owners.

The package manifests remove direct `ws` declarations superseded by the shared owner and Slack's redundant direct `@slack/socket-mode` declaration. Slack retains Undici 7 because Bolt loads Socket Mode transitively and Socket Mode requires that peer version. Node installs keep the same compatible vendor graph while omitting unused top-level declarations; no dependency was added.

The Codex remote and Unix app-server transports, along with their sandbox-close proof, resolve WebSocket through the shared owner. When Bun hosts OpenClaw, it invokes the managed Codex JavaScript launcher through Bun so the upstream launcher still owns platform selection, package-manager markers, signal forwarding, and exit mirroring without requiring a separate Node binary on the child PATH.

## Maintainer decision

Accepted: `openclaw/plugin-sdk/websocket-runtime` is intentionally promoted to a typed public plugin SDK contract for both Node and Bun. Its exported WebSocket client/server constructors, option and data types, and existing ticket, keepalive, and upgrade-rejection helpers follow the SDK's compatibility and deprecation policy. This is the supported adapter boundary for external plugins that need the same maintained WebSocket implementation as OpenClaw core.
```
