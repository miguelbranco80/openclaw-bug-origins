## Fix PR #175300 description (by steipete, opened 2026-10-17T07:35:04Z)

```text
## What Problem This Solves

Doctor could move legacy session sources despite unavailable shared-state recovery history, and an updater could reuse stale schema admission after its Doctor child migrated the database.

## User Impact

Destructive Doctor session migrations now refuse before importing or archiving legacy sources when the shared-state database is missing but its SQLite sidecars remain. The error asks operators to restore the matching database and preserve the sidecars. After an update Doctor child settles, including a failed exit, the next parent access admits the resulting schema again and refuses unsupported newer versions.

## Why This Change Was Made

The canonical-path optimization in #175129 removed a registry read that had incidentally blocked the unsafe migration. Put the explicit orphan-sidecar refusal in Doctor's existing target-preparation owner, before source mutations, and retain the optimization.

The warm-cache simplification in #175077 left existing parent handles usable after admission revocation. Drain the affected handles through the existing path-scoped asynchronous lifecycle owner before revoking admission and releasing process custody. No per-read schema probes, new state, or new migration machinery are introduced. Both contracts are documented.
```
