## Fix PR #176001 description (by shakkernerd, opened 2026-10-18T02:12:49Z)

```text
## What Problem This Solves

After a local managed workspace accepts a refreshed upstream base, Review can include upstream-only changes when the checkout's shared default-branch refs still point to an older commit. That makes a small task look larger and exposes upstream commits in the task's Review history.

## User Impact

Review now compares all changes against the managed workspace's accepted source base and uses the same base for branch history and individual-commit admission. Uncommitted content remains relative to HEAD, and an admitted individual commit still shows its real first-parent diff. Authorized archived reads and the existing fallback for workspaces without a stored projection remain available.

The change requires no configuration, migration, ref fetch, or worktree reconciliation. Remote repository and stored-artifact reads keep their existing behavior.

## Why This Change Was Made

The workspace owner already records the accepted base, and the Git diff implementation already accepts it. The local route was omitting that input and inferring a base from shared refs instead.

A narrow state-worker read now returns only the accepted base and session binding facts. The local consumer checks the agent, session identity, and managed registry identity/path, retains the current session lifecycle and source guards across Git reads, and passes the selected base to the existing diff owner. It does not load the projection's manifests or recovery payloads. A normal session reset can advance the current lifecycle while preserving the same workspace and accepted base; Review remains available immediately, without reconciling the projection.

## Evidence
```
