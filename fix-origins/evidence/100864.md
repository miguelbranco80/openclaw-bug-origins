## Summary

- return EX_TEMPFAIL (75) after a managed-service update handoff instead of reporting success
- keep the detached helper as the only settlement authority and leave terminal observation to the printed status commands
- document the changed exit contract for automation

## Review repair

The first revision added `--wait`. ClawSweeper correctly identified that a waiter inside the managed Gateway systemd process tree is terminated by `KillMode=mixed` during activation, and that an old runtime can permanently lose ledger readability after a schema upgrade. This revision removes that unsafe path instead of promising terminal observation it cannot deliver.

## Upgrade behavior

The installed updater owns the first hop and cannot be retroactively patched: upgrading from v2026.9.4 initially retains that release’s exit-0 handoff. Subsequent handoffs initiated by the candidate CLI exit 75 after successful ownership transfer. Automation should treat 75 as accepted/in-progress, then observe `openclaw update status --json` or `openclaw update history --json` for the helper’s terminal result; other nonzero exits remain failures.
