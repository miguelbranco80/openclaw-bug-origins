## Fix message body

```text
fix(cli): keep the Gateway URL security error when --url is malformed

With a malformed --url (for example ws://[bad), openclaw attach failed the secure-WebSocket check, and then the connection-error formatter called new URL() on the same string and threw "TypeError: Invalid URL", hiding the existing SECURITY ERROR. The formatter now uses URL.parse, so the existing messages come through. The security check and its decision are unchanged. No new text.

Evidence: the built CLI in a secretless node:24.22.1 container with isolated state, main once and candidate once (OPENCLAW_DEBUG=1 to show the reason line). --url 'ws://[bad': main printed "TypeError: Invalid URL" (exit 1); the candidate prints the existing SECURITY ERROR and the existing "Could not reach gateway" hint (exit 1), with no connection attempted. The OPENCLAW_GATEWAY_URL form already showed the SECURITY ERROR on main and is unchanged. Controls matched on both: a valid non-loopback ws:// URL, loopback ECONNREFUSED and a .ts.net host with its Tailscale hint. The folded regression fails on main and passes here; net -1 test lines. Details: https://github.com/openclaw/openclaw/pull/198728#issuecomment-6874523266.

Thanks @YangManBOBO.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```

## Fix PR #198728 description (by YangManBOBO, opened 2026-11-14T07:29:10Z)

```text
## What Problem This Solves

Fixes: a malformed explicit gateway URL (`--url` / `--gateway-url` / `OPENCLAW_GATEWAY_URL`) makes `sessions attach`, `sessions import`, and related session-target commands crash with an unhandled `TypeError: Invalid URL` instead of surfacing the actionable security error.

## User Impact

User impact: users who pass a malformed gateway URL now get the intended actionable message — `SECURITY ERROR: Gateway URL "..." uses plaintext ws:// to a non-loopback address.` — with a clear path forward, instead of a raw `TypeError: Invalid URL` crash. No behavior change for valid URLs.

## Why This Change Was Made

The secure-websocket guard (`isSecureWebSocketUrl` in `src/gateway/net.ts`) rejects malformed URLs without throwing, so `callSessionTargetGateway` fails early with the SECURITY ERROR before any connect attempt. The error shaper (`shapeTargetError` in `src/cli/session-target.ts`) then classified that error as "unreachable" and ran `new URL(effectiveGatewayUrl)`, which throws on the exact same malformed input and replaced the actionable security error with a crash. Parsing defensively with `URL.parse` (already used elsewhere in the repo, e.g. `connection-details.ts`) lets the SECURITY ERROR message surface intact.

## Evidence

Shipped-entry-point proof: ran the actual CLI command `openclaw attach --url "not a valid url"` on Windows 11 with Node v24.16.0 (isolated `OPENCLAW_HOME`/`OPENCLAW_STATE_DIR`, `OPENCLAW_DEBUG=1`). The malformed URL fails the secure-ws check before any connect attempt.
```
