## What Problem This Solves

Fixes overlapping executions when a cron job times out but its original runner continues past the retry deadline.

## User Impact

Timeout retries remain enabled and wait for the original execution to settle. Late completion preserves the single recorded timeout outcome. No public API, configuration, or schema changes are required.

## Why This Change Was Made

The worker-owned finalizer now retains the active receipt while recording the timeout, then finishes only that receipt after the underlying execution settles. The scheduler owns the subsequent refresh, and startup recovery reuses the recorded outcome.

The older settlement module was removed by #169946, so this is an independent repair of the current owner. The contributor branch was read with `gh pr view` / `gh pr diff` and was never checked out or executed.
