## Fix PR #199255 description (by roboclaw-bot, opened 2026-11-14T22:06:09Z)

```text
## What Problem This Solves

Fixes: channel settings let read-only users edit fields and press Save, but nothing is saved and no explanation appears.

## User Impact

User impact: read-only viewers can inspect channel settings without entering an unsavable draft. The existing administrator-access explanation appears beside the settings, and editing and Save reflect that restriction. Existing drafts remain discardable; administrator editing is unchanged.

## Why This Change Was Made

The channel page already has a retained administrator-access fact, and the configuration owner already refuses unauthorized writes. The shared form now presents that existing decision instead of offering a silent dead end. Both core channel details and plugin-mounted configuration use this form.

No backend permission, configuration format, persistence or reconnect policy changes. The patch adds no state or helper, and reuses existing translated copy. Related: #199239 separately fixes Nostr’s plugin-owned profile editor, not this shared configuration form.

## Evidence

- Reproduced on main at a02b7418374f9b49b63ab6e34811b443cb771cd0 through Settings → Channels → Telegram and Nostr. With read-only access, toggling Enabled and clicking Save left an unsaved draft, sent no configuration request, and showed no error. Discard still worked.
- The new readonly regression failed before the fix. All **55 focused channel view/save tests pass**, including basic/advanced fields, retained-draft Save/Discard, conflicts and interrupted saves.
- Three full-app browser flows pass: readonly Telegram and Nostr now show the restriction with disabled fields; the existing packaged Nostr administrator flow still edits, saves, refreshes and navigates normally.
- UI typecheck, scoped lint, i18n verification, formatting and diff checks pass. Current-main reconciliation found no intervening changes to the affected owners. No broad CI or live messaging-service test was run.
```

```text
fix(ui): validate a visible invalid channel draft before explicit Save

In the channel settings editor, clicking Save while a field showed invalid text (for example a non-numeric Discord mention alias ID) submitted the previous valid value instead. The user believed the visible value was saved, but it wasn't. Explicit Save now validates the visible draft first: it focuses the invalid field, shows the message and writes nothing. A corrected draft saves on explicit Save, and ordinary autosave is unchanged.

Evidence: built Gateway and Control UI in real Chromium on Linux, with real pointer clicks on the enabled Save button.
```
