```text
## What Problem This Solves

Fixes: Claude CLI turns lose nested subagent or workflow answers when a `background_tasks_changed` snapshot lists a child before its parent.

## User Impact

Replies from nested Agent and Workflow tasks reach the user at any depth and in any snapshot order, instead of the turn ending after the root's answer. The warm session stays reusable afterward.

## Why This Change Was Made

Main evaluated holds in one pass over the snapshot, so a child seen before its parent found no held parent and was skipped. Hold acquisition is now a fixed-point scan in `cli-runtime-tasks.ts`: ownership is recorded for the whole snapshot first, then each productive pass adds at least one hold, so cycles without a held ancestor terminate. The input, subagent-owned, task-type, and held-parent gates are unchanged.

Forward-port of `8bf0e03aa413` from `release/2026.11.1`, adapted to main's code. Main's scan was a single pass, not the release's two-pass one, so this also fixes two-level child-first snapshots. The logic moved next to `recordTaskOwnership` to stay inside the `cli.runtime.ts` line cap.

Deliberate difference: the release also gates on `session.notifiedTasks`, which main does not have. Main already holds a re-listed root task with no such gate. Adding that set is a separate behavior change, so this PR does not port it, and it does not port the release's `notified` test case. A task re-listed after its notification could therefore gain a hold; that gap already exists on main for roots.
```
