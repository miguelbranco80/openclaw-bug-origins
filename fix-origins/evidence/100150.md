## What Problem This Solves

Fixes: another update is reported as “already running” when a failed or cancelled updater has exited but its installation custody is still retained.

## User Impact

The refusal now names the lease type, owner, lease version, helper/executor PIDs, observed process identity state, and last activity. It gives profile-aware status and repair commands instead of suggesting that waiting will necessarily finish the update. RPC, CLI and automatic-update history preserve the explanation; chat no longer claims the updater is running.

This does not delete locks or weaken admission. Live or unverified writers remain protected. An older installed Gateway/CLI needs this code before its messages change.

## Why This Change Was Made

The underlying cancelled-custody repair already landed in #177932 (`45314c992e24721bba62685795f1be533807656b`), including recovery after Doctor failure/deferral without restarting the cancelled family’s grace period. Current-main tests confirm that repair settles dead custody and permits the next update, while retaining live children and unverified recovery. This PR fixes the remaining misleading report at both fresh-helper and cached-handoff admission. It adds no new state or recovery policy.

## Evidence

- New production-boundary regression: a real child acquires and cancels an update lease, exits, then a real managed helper and its concurrent cached join both refuse with the actual dead owner’s details. A live-owner control and unchanged-custody assertions protect admission. The missing message fails on base; both cases pass with the fix, including profile-specific repair/status guidance.
- Existing repair cancellation (3), recovery (33), reclamation (12), and finalization refusal (17) cases exercise release/retry, failed/deferred repair, retained live children and unchanged custody protections.
- Gateway RPC/history tests: 36 passed. Handoff single-flight/cross-process plus startup consumers: 84 passed, one Windows-only case skipped on macOS. Final changed startup/busy suites: 47 passed; notice renderer: 10 passed. New busy test execution is about three seconds; CI duration will be available on this PR.
- Targeted CLI/update and Gateway-methods type graphs, scoped oxlint, oxfmt and diff checks pass. The compiler requires checkout-local declaration inputs, so only this disposable checkout used a project virtual store with the same global content store and import method auto; no per-task package store.
- An initial baseline assertion used a very long private TMPDIR and hit the existing 2048-character ledger detail limit; the same repair suite passed with a shorter private TMPDIR. No production expectation was weakened.
- Whole touched-test-file audit retained distinct outcome, timing, custody and failure coverage; no source-text mirrors or mocked lease/reclamation logic were introduced. No live Gateway, configuration, lease or database was changed.

Independent API-only full review found one P2 (profile-aware recovery commands); it is fixed and the independent delta review is P0–P2 clean. To satisfy existing line-cap ratchets, the unchanged root-identity assertion moved to a sibling module (same export) and the unchanged startup fixture type moved to its existing test-support module. No coverage was removed. Exact-head required CI remains the landing gate.
