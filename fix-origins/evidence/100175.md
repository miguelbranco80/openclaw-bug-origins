## Fix PR #184707 description (by wr-web, opened 2026-10-26T14:12:11Z)

```text
Fixes #184580

## What Problem This Solves

In Control UI Usage, selecting a filter value that contains a space (for example the model `Local Model`) from the Model, Provider, Agent, Channel or Tool menus writes `model:Local Model` into the query. The query parser splits on whitespace outside double quotes, so this becomes the term `model:Local` plus a free-text term `Model`. The menu option stays unchecked and the matching session and its usage disappear.

## User Impact

Selecting a multiword value now writes `model:"Local Model"`. The option stays checked and the matching sessions and totals remain visible, as they already did when the user typed the quotes by hand. Single-word values are written exactly as before.

## Why This Change Was Made

The parser already supports quoted multiword values (`extractQueryTerms`), so the fix is at the serialization boundary in `ui/src/pages/usage/query.ts`:

- New `formatQueryToken(key, value)` quotes a value when it contains whitespace.
- `setQueryTokensForKey` (menu selections) uses it for newly added values. Retained terms keep their authored spelling, as before.
- `buildQuerySuggestions` uses it for the inserted suggestion value; the visible label is unchanged.

Accepted edge case: a value containing a literal `"` still cannot be expressed, because the query grammar has no escape for it. This PR does not change that.
