## Fix PR #162542 description (by steipete, opened 2026-10-01T08:22:27Z)

```text
## What Problem This Solves

Fixes: when a parent waits on several subagents and one of them finishes successfully with an empty final reply, that child silently disappears from the parent's completion batch (for example, five results for six children).

## User Impact

Parents can account for every child: an empty successful completion shows up with its task identity, `ok` status, and an explicit `(no output)` result. Intentional silence (`NO_REPLY`) and announce skip tokens are still suppressed as before.

## Why This Change Was Made

`buildChildCompletionFindings` skipped any successful child without result text that had captured terminal evidence, which treated an `empty` terminal disposition the same as an intentional suppression. The `empty` disposition is now excluded from that skip, and the single-use helper is inlined (production LOC +4/-9).

## Evidence

- Found by a live run on an isolated Gateway with a real model: six concurrently spawned children, one of which ended `ok` with an empty reply. The parent's admitted batch listed five results.
- The new regression in `subagent-announce.requester-settle-results.test.ts` drives `maybeWakeRequesterAfterAllChildrenSettled` and inspects the delivered parent message. It fails on base with five of six results and passes with the fix. The existing `buildChildCompletionFindings` table now expects `(no output)` for the `empty` case and still asserts that stale captured output and fallbacks are not leaked.
- 119 focused announce/completion tests pass. `pnpm tsgo:core`, targeted lint, oxfmt, deslop, and `git diff --check` pass. Codex autoreview through P2 is scoped-clean.
- Test cost: the new case runs in 8 ms; suite wall times with `--maxWorkers=1` are dominated by worker preparation on a heavily loaded host.
```
