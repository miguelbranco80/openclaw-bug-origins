## What Problem This Solves

Fixes an update refusal that reports only `target-metadata-preflight` and `mode: unknown`, leaving the operator without a useful cause or next step.

## User Impact

Updates preserve the detected npm, pnpm, Bun, or Git mode and explain which target metadata could not be inspected. Unclassifiable installations skip before target lookup with the inspected root, Git metadata, node_modules layout, service target, and recovery commands. Unowned installs remain successful skips with no package replacement or Gateway restart.

The new diagnostics appear in terminal summaries, JSON results and recorded `update status --json` history. Bounded public reports retain fixed descriptions and next steps without exposing local paths or raw registry responses. No options, dependencies, or database schemas change. This repairs the candidate's updater; an installed updater that refuses before staging cannot pick up the fix, and old reports cannot establish which unrecorded metadata check failed.

## Why This Change Was Made

The reported unknown mode was not proof of failed installation detection: the terminal reporting boundary discarded every known non-Git mode. Installation inspection also treated every non-Git directory as a package, including missing or invalid manifests. The fix validates package identity at inspection, carries the resolved manager into terminal outcomes, and uses existing failure-fact and ledger fields for typed metadata diagnostics. Fresh-target admission stays with the target owner, and public reporting projects approved fixed messages from those codes. Skip diagnostics enrich the existing admission phase so `update repair` still acknowledges an untouched installation without finalization.
