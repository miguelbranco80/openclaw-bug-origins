## Fix PR #146343 description (by roboclaw-bot, opened 2026-09-12T19:10:53Z)

```text
## What Problem This Solves

Fixes an issue where users with ordinary session write access could change a conversation’s model but could not change its thinking level or fast mode. The same mismatch affected the Control UI pickers and its /think and /fast commands.

Related: #120875, which enabled write-scoped model changes while leaving effort controls admin-only.

## Why This Change Was Made

Treat `thinkingLevel` and `fastMode` as session-only write-scoped preferences in the existing shared policy, including clearing them with `null`. Gateway single/batch patches and the Control UI use that same policy. Give the context-window control its own permission check so enabling effort controls does not accidentally enable an unrelated admin-only setting.

Read-only clients remain read-only. Context-window, verbose, tool, full-permission, and unknown-field restrictions are unchanged. No configuration migration, new setting, or active-inference hot-switching is introduced.

## User Impact

Users with `operator.write` can change thinking level and fast mode without starting a new conversation or receiving administrator access. Changes are persisted session preferences for subsequent turns; the composer still disables model/effort controls while a reply is running. Existing model/provider capability validation remains in place.

Reported by @VACInc.
