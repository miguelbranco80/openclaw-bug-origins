Fixes #172188

## What Problem This Solves

Discord bot and thread-bound persona replies leave known aliases such as `@alice.` and `@alice.dev...` as literal text, so the intended recipient is not mentioned.

## User Impact

Known aliases resolve before sentence punctuation while preserving that punctuation. Dotted usernames and exact known handles ending in periods retain longest-known-match precedence. Mentions immediately after Markdown links resolve, while URL contents, email addresses, code spans and backtick fences, unknown handles, and reserved broadcasts remain literal. No configuration changes or migration are required.

## Why This Change Was Made

The existing mention owner captures periods as part of a handle. It now tries the full handle, then removes only trailing periods until the longest known handle resolves. Configured aliases still precede the account-scoped directory for each candidate.

URL protection uses the existing Discord Markdown URL-range scanner, extracted into a small shared module. It preserves balanced parentheses inside URLs, stops at unmatched closing parentheses, and leaves trailing sentence punctuation outside the URL. The original mention tokenizer scans prose around these ranges; the greedy URL alternative has been removed. This fixes ClawSweeper's concrete P2 for `See [docs](https://example.com),@alice` without adding a second mention parser or loading the Markdown parser into mention resolution.
