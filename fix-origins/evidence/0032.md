```text
Fixes #195636

## What Problem This Solves

Fixes: Android camera capture retains a destroyed Activity while the longer-lived runtime waits for a replacement Activity to attach.

## User Impact

Camera capture releases its stale Activity reference after destruction, while ordinary background/foreground transitions and a replacement Activity keep working. No configuration changes or user action are required.

## Why This Change Was Made

Observe the attached lifecycle owner until destruction, remove the old observer when replacing it, and reject already-destroyed owners. Clear the reference only when the destroyed owner is still current. Existing foreground admission and active-capture cancellation remain unchanged.

This applies the exact parent-to-commit patch from [d38c7c12db5e61c273486053908709dcfe691b4c](https://github.com/saariuslystoned/openclaw/commit/d38c7c12db5e61c273486053908709dcfe691b4c) onto current main without implementation rewrites.
```
