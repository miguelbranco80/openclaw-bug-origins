```text
## What Problem This Solves

Prompt-cache drops on continuation requests can be classified as `unattributed:continuation-wire-input` without enough evidence to compare the successful and missing-cache requests.

## User Impact

Operators get one bounded diagnostic line containing both the last measured cache hit and the dropping request. Request behavior, cache policy, and defaults are unchanged. Transports that do not expose encoded bodies leave these fields absent.

## Why This Change Was Made

Reuse the provider request encoder and its run-owned snapshot to record request bytes, a SHA-256 digest of the first 4 KiB, cache-key presence/hash, continuation-ID presence, and model/route hashes. Reuse the response callback for status, numeric processing time, and hashed values from a fixed header allowlist. The existing cache tracker retains the measured predecessor; no separate cache or state owner is introduced. Recovery metadata counts encoded attempts within a model call, not unobserved transport or cross-call retries.

Production delta: +88 lines (95 added, 7 removed; tests and docs excluded). The additional lines are required by the new diagnostic contract: the existing prefix fingerprints do not retain wire bytes, key presence, response metadata, or recovery counts. Existing fingerprints still own context-rejection and prefix comparison, so deleting them would remove working behavior. Raw keys, IDs, header values, and prompt content are excluded.
```
