## Fix PR #163254 description (by steipete, opened 2026-10-02T04:38:08Z)

```text
Related: #162792 (follow-up; it left these suites for an SDK decision and core splits), #161637

## What Problem This Solves

Fixes: the first test or hook of 70 more Vitest files (extension, package, and oversized core suites) absorbs the one-time compiled worker preparation (tens of seconds warm, minutes cold) and slows down or times out, because the file first reaches a compiled-subprocess declaration inside a test body or hook instead of at collection.

## User Impact

No product change. Developers running `pnpm test <file>` and CI shards whose first declaration load came from one of these files no longer pay the worker preparation inside a test or hook deadline; it happens during collection, where #156011 and #162792 put it.

## Why This Change Was Made

#162792 fixed 335 files but could not reach the rest: extensions and packages cannot import core test utilities, and three core files were already over the line cap. This PR closes those gaps at the owner of each lazy load:

- **New repo-local SDK preload.** `openclaw/plugin-sdk/compiled-subprocess-testing` is one side-effect line, `import "../test-utils/prepare-compiled-subprocesses.js";`, with no exports. It is registered like `test-node-mocks` and `sqlite-runtime-testing`: private-local-only, non-production, excluded from npm `files` and package exports, absent from the production build. The public SDK entrypoint set and export map are unchanged. Agreed with the SDK owner before adding it.
- **Shared Codex owner.** 35 Codex app-server deadline rows came from one place: the `test/setup.extensions.ts` `beforeEach` that calls `vi.importActual("../src/infra/worker-cpu.js")` for every `extensions/codex/src/app-server/*.test.ts` file. Setup now imports only the declaration preload for that path pattern at setup evaluation. The `worker-cpu` import itself stays in the `beforeEach`, after each file's mocks are registered, so no module binds earlier than before. One shared constant drives both checks. Every one of the 319 matching files already loaded a declaration through that hook whenever a case ran. The 15 that can skip every case on some platform already reach one statically, so no consumer starts loading one.
- **Per-file preloads (29 suites).** These suites re-import their subject per test (`vi.resetModules`, `vi.doMock`, cold-import guards), or their first load happens inside production code they call: lazy runtimes in Codex, Deepgram, Inworld, Telegram, Ollama, OpenAI OAuth, the memory-host auth adapter, and others. Extensions and the package use the SDK subpath. Core suites use the core module directly.
- **Static imports (3 suites).** `anthropic/cli-auth-seam`, plus the DeepInfra and xAI video transport suites. Their one-time subject import moved from a test or `beforeAll` to collection, with the same reset, unmock, and mock order (`vi.hoisted(() => vi.resetModules())`, an existing idiom).
- **Owner splits of the three line-capped core files.** `run-main.exit` splits into exit, gateway startup, command dispatch, and bare-root onboarding. `media/fetch` splits into reads and store. The official external catalog splits into metadata and hosted feed. Test names, assertions, and counts are unchanged (111 = 11+26+46+28, 72 = 28+44, 38 = 14+24). Only the six parts that load a declaration take the preload. The trimmed `run-main.exit` and catalog-metadata files stay declaration-free. Their max-lines baseline entries are removed, along with one already-stale entry the ratchet flagged (`chat.abort-persistence.test.ts`).
- **Protected CI selection follows the split.** The four destination suites that received protected `run-main.exit` and catalog cases join `PR_PROTECTED_RUNTIME_TEST_FILES`, so global inputs such as `pnpm-lock.yaml` still select them. The existing global-input planner test asserts this (ClawSweeper finding).
- **Bounded cleanups the gates required.** `sanitizeJitiCachePathSegment` moved unchanged into `sdk-alias-normalization.ts` so the baselined `sdk-alias.ts` does not grow. Five unused exports were dropped from the new CLI test-support module (dead-export scan).
- **Docs.** `docs/help/testing/writing-tests.md`, `docs/plugins/sdk-subpaths.md`, and `docs/plugins/sdk-testing.md` document the extension preload and when to use it.

No timeouts, retries, configs, worker pins, or assertions changed.
```
