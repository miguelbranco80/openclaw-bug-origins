## What Problem This Solves

`web_fetch` silently rounds JSON identifiers and high-precision decimals, turns large exponents into `null`, and rewrites negative zero as `0` before the model sees the response.

## User Impact

Models receive the server's exact numeric tokens, including `9223372036854775807`, `12345678901234567890`, high-precision decimals, `1e400`, and `-0`. Existing two-space JSON pretty-printing is retained so ordinary JSON output and truncation boundaries do not change. Content-type classification, malformed JSON fallback, size limits, external-content wrappers, and non-JSON responses are unchanged. No configuration change is required.

## Implementation

Keep the contributor's commits and use the native JSON reviver source context with `JSON.rawJSON` for numbers while retaining the existing serializer and indentation. Both APIs were exercised successfully in isolated Node 24.16.0 and 26.1.0 (the supported branch minima), Node 24.19.0 and 24.21.0 (CI versions), Node 26.10.0, and the repository-pinned OpenClaw Bun 1.4.3. A native runtime type declaration and optional callback context annotation bridge the missing ES2023 library typings without changing runtime behavior.

Thanks to @ly85206559 for reporting the problem, implementing the original fix, and adding HTTP regression coverage. The maintainer adjustment keeps main's formatting rather than returning source whitespace, avoiding an unrelated output change.
