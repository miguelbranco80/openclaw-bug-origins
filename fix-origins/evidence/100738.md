## Fix PR #184996 description (by hannesrudolph, opened 2026-10-26T20:34:03Z)

```text
## What Problem This Solves

Fixes session observer assessments stopping when discovery grants a model chat support but its static catalog entry is typed-only.

## User Impact

Utility calls can use the chat capability accepted for their current run without changing the selected model or adding a fallback. Existing runs retain their original capability facts; unsupported models and unrelated routes remain rejected.

## Why This Change Was Made

The shared model resolver checked only static declarations, even though admission had captured newer discovery facts. Use that captured declaration for the same model and physical route, retaining static behavior when the captured chat capability is absent. Transport and credential selection are unchanged.

## Evidence

- Regression fails on the original code and passes with the fix. Seven capture/resolution tests cover newly granted chat, older denied admissions, different endpoints/APIs, missing inference metadata, and generation isolation.
- Existing credential- and route-scoped utility integration passes.
- Production and changed-test typechecks, targeted type-aware lint, formatting, and runtime build pass.
- A real-provider check through the built production observer preparation/completion functions produced a schema-valid assessment with the selected utility model and no fallback.
- Required local review completed on the exact candidate with no actionable correctness or security findings.

Post-merge verification on the running Gateway at `28bad336` confirmed fresh, persisted model-generated observer assessments, including a repeat check at **2026-10-26 21:58:50 UTC**. The utility model remained unchanged with no fallback. No observer failures appeared in the checked post-restart logs.

}
```

Runtime validation now covers both standalone completion and the actual running Gateway. No schema migration or configuration change is required by this code fix.
