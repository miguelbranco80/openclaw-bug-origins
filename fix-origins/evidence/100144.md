## What Problem This Solves

Fixes background task replies going to an old external conversation instead of their originating WebChat, and Reef rejecting ordinary GitHub revision links as secrets.

## User Impact

WebChat task completions stay in WebChat, and mirroring an external send into a transcript no longer changes that transcript’s reply destination. Reef can carry GitHub commit, blob, and tree links without mistaking their revision ID for a credential.

The Reef exception is deliberately syntactic: only the exact 40-hex revision position skips the entropy heuristic. It does not verify that a repository or commit exists or is public, and a synthetic value in that position is indistinguishable locally. Known-credential rules and the model guard still inspect the unchanged full message. No configuration or database migration is needed; saved external routes remain available when explicitly selected or when no captured origin exists.

## Why This Change Was Made

Completion routing discarded a captured internal origin and substituted saved external delivery metadata. Separately, the Gateway send handler treated a transcript-mirror selector as the owner of destination-route persistence. The fixes retain the captured origin and separate destination routing from transcript mirroring.

Reef now distinguishes revision-position IDs from other high-entropy tokens. Whole containing URI-like tokens are recognized first, so query/fragment nesting, apostrophes, Markdown wrappers, and nonhierarchical URI schemes cannot create a broader exemption. Other path segments and message text remain scanned.
