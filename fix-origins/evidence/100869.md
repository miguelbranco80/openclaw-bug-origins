## Fix PR #174248 description (by steipete, opened 2026-10-16T13:22:40Z)

```text
## What Problem This Solves

Fixes reconnecting clients being rejected by the 128-task session reader limit when a large retained subagent backlog resumes after a Gateway restart.

## User Impact

Interactive session lists, history, and connection reads retain reader capacity while recovery catches up. Background cleanup proceeds under a bounded budget; no configuration changes are needed. This restores availability under the reproduced backlog, but substantial cold-start latency remains.

## Why This Change Was Made

Reuse the lifecycle controller's existing two-slot, per-Gateway limiter for detached cleanup, cleanup tails, expired-delivery finalization, and orphan reads. Restored requester wakes share that budget; live requester wakes retain their existing behavior. Worker counts, worker FIFO ordering, task/byte limits, and database ownership remain unchanged.

Queued work retains its Gateway root before waiting, so restart drain still joins it. Existing ownership checks run on dispatch. The separate requester-wake-only implementation is removed; production code grows by **14 lines** to apply the same owner to the other detached entry points without weakening admission or authority checks.

## Evidence

A fresh Linux-rig replay used 13,000 synthetic sessions, 6,000 retained runs, and the original reconnect harness at default limits. The complete pristine fixture was restored and audited before every launch. Every successful response contained exactly 100 rows and `totalCount=13000`.

| Successful storm p99 | Unavailable; all failed (error-response p99 0.391 s) | 13.08 s and 21.16 s |

No admission override was used. A separate diagnostic reached 128 outstanding tasks with one active task and only 271 KB of input against the 256 MiB byte budget; recovery orphan reads and target discovery filled the pools.

These measurements establish availability, **not a latency speedup**. Other isolated rig work increased load during the candidate observations. The rig workspace and owned processes were removed after collecting evidence.
```
