## What Problem This Solves

Database commands emit a string-valued `error` on operational failures, so scripts cannot use the documented CLI-wide JSON failure contract.

## User Impact

Failed JSON-mode database commands return `ok: false` and `error.type: "cli_error"` with exit status 1. Successful payloads, human diagnostics, and ownership/custody checks retain their existing behavior.

## Why This Change Was Made

The existing shared database error writer now uses `formatCliJsonFailure`, the canonical owner of CLI failure output. No second renderer, new error boundary, schema change, or config option is introduced.

Original fix and native proof by @Leon-SK668. Co-authored-by: Leon-SK668 <0668001470@xydigit.com>
