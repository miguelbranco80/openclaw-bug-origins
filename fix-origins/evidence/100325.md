```text
## What Problem This Solves

Fixes empty speaker headings in **Copy → Conversation as Markdown** and `/export` downloads when a conversation contains tool calls or other records without exportable text.

## User Impact

Copied and downloaded conversations contain only readable text sections. Existing sender labels, timestamps, message order, filtering, and nonempty text bytes remain unchanged. No configuration change or migration is required.

## Why This Change Was Made

The shared Markdown formatter emitted a heading before checking whether the existing text extractor returned any text. It now skips records with no non-whitespace text and reports an empty export when none remain. It preserves textual tool results and does not serialize tool arguments or media. The copy menu still loads available history; `/export` retains its existing loaded-history scope.

## Evidence

- The issue was first observed through the live conversation-copy menu. Original formatter regression: 5 failures and 8 passing siblings; the mixed transcript produced an empty `Tool` heading, and all-nontext transcripts incorrectly produced an export.
- Fixed formatter and existing full-history copy-menu owner tests: **40 passed** in **2.579s** wall time. Existing pagination, visibility, sender attribution, branch-change, and retired-view behavior remain covered. The changed formatter file alone: **13 passed**, **2.634s** wall time with one worker.
- Existing real-browser attribution fixture: **2 passed** in **9.027s** wall time (**7.90s** Vitest), exercising the actual clipboard menu and `/export` download against the canonical mocked Gateway. Both retain textual tool output and omit tool-only headings and arguments; no model request is sent. These extend existing cases without adding another browser boot.
- UI production and the owning UI chat/E2E test type graphs, scoped lint, formatting, line-cap/max-lines/assertion-safety guards, i18n verification, docs sanity, and diff check passed. Fresh independent review found no actionable P0–P2 issues.

Two existing browser fixtures were also corrected during CI follow-through:

- The idle-conversation measurement now waits for its accepted startup model-auth result. Hosted CI recorded foreign-event renders `[3,0,0]`; an exact merge/shard replay passed all **79 files / 375 tests** in **336.447s**, which is a non-reproduction. A controlled late model-auth + swarm completion reproduced the unchanged assertion at `[2,0,0]`. The corrected case passes at `[0,0,0]` (**1.172s** case, **16.650s** wrapper); the same delayed-swarm schedule passes at `[1,0,0]`, retaining all heartbeat, selected-title and viewer controls. The original CI third render remains unidentified; this fixes the demonstrated startup-readiness gap without changing thresholds or deadlines.
- The dismissed lazy-surface retry case installs the browser clock before navigation and advances the existing 1.5-second retry window virtually. Its case cost fell from **2.534s to 0.961s**. Both versions reject the same temporary generic-retry defect at the original document-request assertion; the mutation is absent.
```
