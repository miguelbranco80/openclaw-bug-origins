```text
Related: #153266

## What Problem This Solves

Fixes Chrome setup disappearing when a shipped Mac app loads an updated Gateway dashboard whose automatic extension-status request it does not support.

## User Impact

Older Mac apps retain their existing setup action and can report an installed extension after setup. Updated apps still detect installation automatically. An older reply with no enabled extensions stays unknown instead of incorrectly claiming the extension is missing.

## Why This Change Was Made

The shipped v2026.9.5 Mac bridge accepts installation but rejects the new status request, and its installation reply lacks the new installed-profile count. Preserve that supported app/Gateway upgrade boundary while keeping new status replies strict. No configuration migration is required. CI fixture repairs also wait for observable readiness and use the correct cleanup owner. Production behavior outside Chrome settings is unchanged.

## Evidence

- Verified the v2026.9.5 request decoder, setup reply, and same-major stable Gateway compatibility contract directly from the release tag.
- The shipped-bridge browser regression failed before the repair because setup was absent. Both current and shipped bridge Settings scenarios pass using source-matched synthetic replies and a mocked Gateway.
- 71 focused UI/bridge tests pass, including strict status parsing, old setup replies, unknown enabled-only counts, and stale responses.
- UI production/test types, i18n, focused lint, and formatting passed. Independent review completed with no accepted correctness finding remaining; the legacy count was verified against shipped code as enabled Store installations plus approved unpacked extension discoveries. All 11 selected browser cases passed after adopting the upstream chat repair.
- The native hook size-limit fixture reproduced its timeout failure with slow real locator lookup, then passed with only the fixture clock isolated. Its complete case now lives beside the deadline test; all 22 lifecycle cases pass, and the line-cap ratchet passes. The real HTTP transport, 500 ms socket timeout, 5,000,001-byte response and size assertion remain unchanged.
- Transcript startup reproduced both CI failures with real SQLite completion delayed by 1,250 ms. Waiting for the existing provider callback preserves note and ownership assertions; the delayed cases and all 19 normal cases pass.
- The model-catalog test reproduced its null bounding box with deferred popup activation. Waiting for visibility preserves its value and click assertions; delayed activation and all eight normal cases pass.
- Carries the canonical ACK test repair from #153296: cleanup supplies its actual claim and missing-row checks remain explicit. All four worker cases pass.
- CI exposed two existing main regressions. Their repairs landed upstream in #153260 and #153245; this refreshed branch includes them through its base. Their redundant local repairs were dropped. Subsequent CI fixture failures were reproduced and repaired as described above. The Chrome compatibility patch remains unchanged from the reviewed repair.
```
