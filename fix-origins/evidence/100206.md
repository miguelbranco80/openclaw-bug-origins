## What Problem This Solves

A root-anchored ignore rule such as `/build` was broadened to `build` by the shared ignore-rule prefixer. Standalone SDK sessions using `DefaultResourceLoader` consequently lost nested skills such as `deploy/build/SKILL.md`. Root-anchored negations were also broadened.

## User Impact

Root-anchored rules and negations remain rooted in SDK skill and package-resource scans using the shared matcher. Unanchored rules retain their existing recursive behavior. Thanks to @boeingchoco for reporting the bug and contributing this fix and regression test.

Scope clarification: the CLI `skills list` and embedded Gateway use a different, native workspace discovery path. That path does not apply these `.gitignore` rules; this PR does not change it. The real CLI listed both top-level and nested fixtures before and after this patch. The Gateway's resource loader explicitly disables ambient SDK skill discovery. The before/after evidence below therefore uses the actual affected consumer: standalone SDK sessions with `DefaultResourceLoader`.

## Why This Change Was Made

At the scan root the directory prefix is empty, so stripping the leading slash changed `/build` into `build`. Preserve the original pattern at the root and leave nested-directory prefixing unchanged. No new configuration or stored-data changes.

No overlap with Pash/Sarah changes.
