```text
## What Problem This Solves

Fixes: clicking the Home icon does not open Home when session attention replaces the icon with a warning, question, or approval indicator. Stale child-failure details can also make the navigation button look like an unrelated error.

## User Impact

User impact: Home stays recognizable and clickable regardless of session failures. Run/queued/unread activity and draft/outbox badges remain; session attention keeps its existing session and Inbox surfaces. No configuration or data migration.

## Why This Change Was Made

The generic session-row renderer puts an interactive attention tooltip inside the Home button. That tooltip stops click propagation. Home now uses the existing noninteractive session glyph directly rather than embedding a competing action. This complements the child-failure aggregation fix in #188309.

- Home context suite: 3/3 pass in 3.90 seconds; desktop/touch rail alignment: 2/2 pass. Combined invocation: 26.78 seconds including the production UI build.
- Existing sidebar interactions/footer tests: 77/77 pass (22.76-second invocation); rail tests: 34/34 pass (8.81-second invocation).

- Simplification: removes the generic session-row attention/action machinery from Home, with no new state owner. Production delta +11 lines; test delta +8 lines extends existing flows, with an exact 8-line regression allocation. Existing reactive effects/listeners and ownership APIs are unchanged.
```
