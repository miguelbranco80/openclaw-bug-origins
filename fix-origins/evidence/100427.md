## Fix PR #169101 description (by RomneyDa, opened 2026-10-11T12:38:44Z)

```text
## What Problem This Solves

Since #168992 (e63b5a01), every run on a session pinned to a native harness with session-runtime ownership (Codex) fails before dispatch whenever the lane has claimed the session writer:

> AgentHarnessPreflightError: Native model ownership changed during run preparation. Reattach the original native session before retrying.

Current `main` (0690a2ef) fails 5/10 tests in `src/agents/embedded-agent-runner/run.harness-auth-failover.test.ts` for this reason. That test file blocks CI for any PR that touches the embedded runner, for example #168401.

## Why This Change Was Made

Root cause:
- #168992 reused the run-admission session snapshot (`sessionAdmission.entry`) for the first native ownership read in `prepareNativeSessionRuntime` (`src/agents/embedded-agent-runner/run/model-setup.ts`).
- Admission runs in `prepareEmbeddedRunSession`. The lane controller claims the session writer later, in `claimAgentSessionWriter` in `lane-controller.ts`, and then sets `sessionTarget.expectedWriterRunId`.
- So the admitted snapshot never carries the claimed `activeWriterRunId`, and the ownership `assertCurrent` writer check always fails.
- I confirmed this by instrumenting the check: `expectedWriter: "run-1"`, `activeWriterRunId: undefined`, all other fields matching.

Fix: reuse the admitted snapshot only when it already carries the expected writer, or when there is no writer claim. Otherwise take the existing worker read, which is the behavior before #168992. The no-claim reuse that #168992 added (and its no-main-thread-SQL test) is unchanged.

Alternative considered: patching the claimed writer into the admitted snapshot, or refreshing admission inside the lane claim. Both would fabricate or relocate row state across owners. Rereading is the existing authoritative path.

## User Impact

Pinned native Codex sessions run again instead of failing every turn at preparation. There is no config or schema change.

## Evidence

- `git bisect` between bdcbb2d8 (good) and ff6f58a8 (bad), running `run.harness-auth-failover.test.ts`, names e63b5a01 as the first bad commit.
- New regression test, `model-setup.ownership.test.ts` "rereads native ownership when the writer claim follows run admission". It fails on `main` with the exact error above and passes with this fix.
- `pnpm test src/agents/embedded-agent-runner/run/model-setup.ownership.test.ts src/agents/embedded-agent-runner/run.harness-auth-failover.test.ts`: 42/42 pass. The 10 failover tests were 5/10 on `main`.
- Production LOC: +7/-1.

Note: `node scripts/check-changed.mjs` currently stops at `duplicate scan target coverage` because of the root `worker-heap-flag.mjs` added in #166581. That failure also happens on `main` and is unrelated to this change.
```
