## What Problem This Solves

An IRC channel with an explicit empty sender list can still pass messages to the bot when a wildcard channel allows the sender.

## User Impact

An empty per-channel `allowFrom` now blocks all senders in that channel, even when a wildcard channel or global group sender list allows them. Existing configurations with an empty per-channel list will take effect as a deny rule after upgrade. Operators who intended that channel to inherit sender access should remove the empty override or list the intended senders. Other channels continue to use their configured sender lists.

## Why This Change Was Made

The IRC monitor now distinguishes a missing per-channel list from an explicitly empty one and passes the selected list to the shared ingress sender gate. The documentation describes the empty-list behavior. The production change removes three net lines; the socket regression adds 31 test lines with a matching test-line allocation.

## Evidence

- Socket-level IRC monitor regression: the base revision dispatched a message from an empty-list channel; the new head denies it and admits the same sender in a wildcard channel. The full file passed 13/13 tests under both `allowlist` and `open` group policies (`pnpm test extensions/irc/src/monitor.test.ts --maxWorkers=1`).
- Running compiled Gateway with IRC plugin and a task-owned IRC server, on base and head, using a scripted local provider. The denied `#ops` message reached one provider request and one IRC reply on base, versus zero of each on head. The `#other` wildcard control reached one request and one reply on both. Both Gateway processes stopped normally.
- Published `openclaw@2026.11.2` and `@openclaw/irc@2026.11.2` loaded and replied in the isolated Gateway. After normal stop, the candidate Doctor completed and preserved the stored IRC channel settings in the same state directory. Two synthetic pending records inserted through the canonical ingress queue after Doctor drained on candidate Gateway restart: `#ops` produced zero provider requests and IRC replies; `#other` produced one of each. This tests candidate replay behavior, rather than migration of a pre-existing stable queue record.
