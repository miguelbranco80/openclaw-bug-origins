## What Problem This Solves

Fixes Gateway memory growth while attached managed-browser pages keep sending background network requests.

## User Impact

Long-lived tabs retain a bounded metadata log without retaining thousands of POST bodies. The existing 500-entry history, filters, clear behavior, redirects, worker/frame traffic, snapshots, navigation guards, and downloads remain available. No configuration, migration, dependency update, or browser reconnection is required.

## Why This Change Was Made

Permanent Playwright request/response listeners materialize full protocol objects for a log that only needs metadata. Playwright 1.64.1 retains these dispatchers up to a 10,000-object bucket. Its Chromium POST buffer allocation is in the installed `lib/coreBundle.js:37841–37852`, subscription dispatch is at `55689–55727`, and dispatcher retention is at `19900–19904,20108–20123`. A 16 KiB POST in the measured Node 26.12.1 workload pins a 65,600-byte backing store.

The browser transport now records scalar metadata from CDP messages it already receives. It adds no sessions, commands, polling, or Playwright-internal access. Transport/page retirement clears ownership; pending associations are bounded with the 500 records. Protocol normalization preserves child-session request transitions and successful HTTP 204 navigations.
