* fix(worktrees): resume repository repair after bounded passes

Inspect linked indexes individually and persist the last attempted checkout so a timed-out scan cannot starve later worktrees after restart. Preserve the existing fetch and maintenance limits. Acquire the content slot before the ref queue to avoid deadlocking active writers.

* fix(perf): drain workload receipts during Gateway stress

## What Problem This Solves

Fixes repeated five-minute repository-repair timeouts that prevent later linked worktree indexes from receiving missing objects during `openclaw worktrees gc --retry-deferred`.

## User Impact

Explicit retries make progress across checkouts, including after a Gateway restart, while preserving staged and working files. The five-minute repair budget, 4,096-object limit, two-child admission limit, low-priority Git, and explicit-only fetch policy remain. A single checkout whose own inventory exceeds the entire budget can still require repository repair; the cursor lets other checkouts proceed rather than declaring that checkout healthy. Nested-repository removal protection remains unchanged.

## Why This Change Was Made

Pack consolidation was already incremental in #182204; object repair still inventoried every linked index before its first fetch. Repair now inventories one checkout at a time and records the last attempted checkout in the existing machine-state database. That scheduling position survives interruption and is cleared after a complete sweep. It is never a health receipt or removal authorization. Healthy object IDs no longer fill the inventory output.

Maintenance also acquires a content slot before the ref queue, matching content writers. The reverse order could hold the ref queue while waiting for both slots occupied by writers waiting on that queue.

Runtime production code grows by 22 lines to retain the durable scheduling position and replace the global inventory loop. Benchmark/harness code grows by 89 lines; tests by 165 lines. The requested non-test/non-doc diff therefore totals +111 lines, including measurement tooling. There is no new schema, configuration option, cache, or alternate repair path.
