## Fix PR #201477 description (by steipete, opened 2026-11-18T22:02:16Z)

```text
## What Problem This Solves

A persisted user request can fail during initial replay preparation when another writer appends transcript metadata between selection and admission. The user then has to resend an unchanged request.

## User Impact

A benign transcript advance now gets one fresh preparation and admission attempt. A replaced user, completed turn, lost writer claim, or revoked authority still refuses replay. There are no runtime configuration or schema changes.

## Why This Change Was Made

The final-consumption path already retried once after #181473, but initial preparation used the same read owner without that recovery. Move the existing bounded retry into the shared owner, retain the original entry ID and generation across refresh, and record consumption before calling the consumer. This avoids a second retry layer and preserves exactly-once user-turn consumption.

Current readers throw `SessionTranscriptReadFenceError` for the reproduced version mismatch before returning context-validation facts. The owner handles that existing form and work-start invalidation without changing source, writer, or authority validation.
```
