Crabbox's exact-ID inspect reports these definitive absences only as text, so the provider now recognizes the exact DigitalOcean 'fixed lease is terminal' and ASCII Box 'not found (404)' results as an unrecognized lease; teardown then runs the existing stop confirmation, which verifies complete absence before clearing stale attachments. ## Fix PR #173825 description (by steipete, opened 2026-10-16T04:53:14Z)

```text
## What Problem This Solves

Fixes worker environments retrying teardown indefinitely when Crabbox inspection reports a terminal DigitalOcean fixed lease or a missing ASCII resource.

## User Impact

Requested teardown can finish and clear a stale session attachment once Crabbox confirms stop. Ambiguous inspection failures and unsuccessful stops remain retryable. No configuration or schema changes are required.

## Why This Change Was Made

Crabbox 0.78.1 returns these inspection failures as text instead of JSON. The adapter now recognizes only the matching provider, exit code, and complete diagnostic, then reports an unknown lease through the existing lifecycle path. That path still calls `crabbox stop`; inspection text alone never authorizes physical-stop settlement. This preserves Crabbox's stronger ASCII absence check (exact resource lookup plus complete inventory) and the existing attachment owner.

Production change: +12/-1 lines in the Crabbox adapter; tests: +161 lines using the existing public-plugin/Gateway integration fixture. No new teardown path or state was added.

## Evidence

- The real Crabbox plugin and Gateway service reproduce the defect with synthetic CLI responses: three terminal/absent scenarios failed before the fix because `stop` was never called; all six new scenarios pass afterward. Coverage includes attachment retention after a failed stop, successful retry, unresolved creation, unexpected exit code, mixed authentication diagnostics, and no repeated cleanup after settlement.
- `pnpm test src/gateway/worker-environments/provider-crabbox-runtime-preflight.test.ts extensions/crabbox/src/crabbox-worker-provider.test.ts --maxWorkers=1`: **103 tests passed**. Runner wall time: 261.28s, including worker build/transform; the six-case focused run took 112.02s wall / about 8.7s test execution. CI timing is pending.
- Targeted core type-aware lint, formatting, `git diff --check`, and independent Codex autoreview passed.
- Extension type-aware lint could not reach linting: shared plugin SDK declaration preparation hit its existing 300-second timeout on the busy local host. This check remains for CI; no source diagnostic was suppressed.
- Inspected Crabbox v0.78.1 source: `internal/cli/inspect.go`, `internal/cli/fixed_lease_protocol.go`, and the ASCII provider's `client.go`, `absence.go`, and absence-evidence tests. Exit code 4 alone also covers unresolved creation and is deliberately insufficient.
- Live dev-Gateway settlement was not run. Local read-only probes returned setup errors rather than the supplied terminal/404 diagnostics; no operator Gateway or live state was changed.
```
