## Fix PR #147136 description (by steipete, opened 2026-09-13T15:19:21Z)

```text
## What Problem This Solves

Fixes form edits remaining unsaved after reconnecting and choosing **Reload Config** in Settings.

## User Impact

A successful reload discards the old draft and restores autosave for subsequent edits. Reloading while offline still preserves pending edits, including when the connection drops while an earlier save is settling.

## Why This Change Was Made

Page reloads drained pending writes and replaced the draft without clearing the write coordinator's reconnect latch. All five callers now use that coordinator's existing discard operation. Its reload-only option preserves the pages' offline behavior; the footer's local discard behavior and background refreshes remain intact. The competing discard entry point, unused load-options export, and synchronous reset operation whose UI callers were removed in #107458 are retired. Production code decreases by 18 lines.

## Evidence

The browser regression failed before the fix: after reconnecting, reloading, and selecting a new model, the UI returned to **Autosave paused after reconnect** and sent no `config.set`. After the fix, the same flow saved the fresh edit against the reloaded revision.

- All four Agents browser cases passed against a freshly built production UI with a synthetic Gateway on the original fix, before the unused reset operation was removed.
- All 293 remaining tests across 18 configuration-owner and caller suites passed again on the rebased head, including main's updated default-agent configuration case. Offline reloads, disconnects during write draining, late acknowledgements, conflicts, and publication recovery remain covered.
- All required changed-file checks passed again on the rebased head, including core/UI typechecking, lint, i18n, and the dead-export scan. The original change and the reset retirement each passed independent P2 review without findings.
- [CI run 34770750927](https://github.com/openclaw/openclaw/actions/runs/34770750927) passed the startup-size check at **354,553 bytes across seven JavaScript requests**, also below the previous 355,719-byte limit. Main independently changed its budget and other UI code between runs; this PR changes no budget, and the size difference is not attributed solely to this cleanup.

That CI run failed only extension lint and the aggregate gate because main's Workboard test did not await its asynchronous harness cleanup. Main now includes that fix. This PR has been refreshed onto `fc1975991f22403d4a8a723c2a27071bbc16d55f` with the same patch; fresh CI for the rebased head is pending.

No operator Gateway or real provider/channel was used.
```
