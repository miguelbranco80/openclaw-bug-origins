## Fix message body

```text
Closes #154446

## What Problem This Solves

Fixes clipped Secrets row actions in narrow Settings tables, including tablet-sized touch layouts.

## User Impact

Operators can see and activate the complete actions button without resizing the window. The existing phone layout and 44px touch target remain intact; secret storage, values, access policy, and Gateway methods are unchanged.

## Why This Change Was Made

The fixed-layout actions column reserved 44px but its cell also carried horizontal padding. Size that existing column for the button plus both padding tokens. The regression keeps only the two failing narrow mouse/touch cases; existing desktop/phone tests and direct browser controls cover the unaffected layouts.

## Evidence

Current source base `502d4be3af70d92ffdcbe6dc10e4ad0b7c190483` and candidate `72b902d9e7f00bcc5796ec9889f97ba9bec3a854` were exercised through the actual Control UI and the existing mocked Gateway with synthetic secret metadata, not a live secret store.

| Viewport/input | Before | After |
| --- | --- | --- |
| 1000px mouse | Button ends 10px beyond the table | Button ends 16px inside the table |
| 1000px touch | Button ends 16px beyond the table | Button ends 16px inside; target remains 44×44px |
| 1440px desktop / 390px phone | Contained controls | Contained controls; phone layout unchanged |

Enter opened the actions menu in every candidate browser case. [Inspected current before/after screenshots](https://github.com/openclaw/openclaw/pull/154586#issuecomment-5761946653) are embedded in that comment and were verified rendering in the actual PR page. The same exact image pair was also delivered in the originating chat.

- Negative control: temporarily restoring the original 44px width made both focused regression cases fail (`943 > 933` and `949 > 933`). The fix was restored immediately afterward.
- Focused Secrets E2E suite: **9/9 passed**, including the real production UI bundle build. File test time: **12.777s**; new cases: **491ms + 711ms = 1.202s**. Vitest reported **21.40s**, **23.19s** command wall time, including a **6.94s** UI build.
- Scoped type-aware lint, stylesheet lint, and formatting checks passed. No project-wide suite was run.

The earlier contributor CI run on `a2f9253a3b44af0e727b75ef73c9077afc23e7b2` reported startup-corpus timeouts outside the UI files. That run is not claimed green or replayed here; applicable hosted CI for the new head remains the landing gate.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```
