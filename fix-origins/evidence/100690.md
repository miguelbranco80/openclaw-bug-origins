## Fix PR #189250 description (by steipete, opened 2026-10-31T09:22:29Z)

```text
## What Problem This Solves

Fixes the opening prompt and earlier rows disappearing when a refresh supersedes history recovery after stopping a long turn.

## User Impact

The chat keeps the transcript it already showed while reconciling the stopped turn. Routes, rendering, and the one-page recovery limit remain unchanged.

## Why This Change Was Made

The first recovery cleared its rejected cursor before its full-tail request finished. A superseding refresh therefore skipped reset recovery and could adopt a bounded tail after the active leaf changed. Retain the cursor until an accepted authoritative snapshot replaces it, so the existing recovery owner fills the held prefix.

If a fallback fails or is cancelled, a later retry may repeat one cheap rejected-cursor/reset exchange. Existing session, connection, and generation checks still own publication. Explicit window resets still clear their cursor.
```
