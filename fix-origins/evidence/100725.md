## Fix PR #162763 description (by roboclaw-bot, opened 2026-10-01T14:30:58Z)

```text
## What Problem This Solves

Fixes: a saved background reply can remain missing, or disappear after appearing, when its WebChat transcript update races an older history request.

## User Impact

User impact: completed results remain visible without asking the agent to repeat them or manually reloading the conversation. No configuration, storage schema, or migration changes are required.

## Why This Change Was Made

A transcript commit must invalidate a history read that began before it. Previously, idle panes could reuse the stale read without fetching the new result, while an active pane could admit the reply and then lose it when that stale snapshot advanced its transcript leaf.

The event handler now retires the older read before run settlement and uses the existing history loader's single queued refresh. Identity-only transcript invalidations use the same refresh contract. Session/connection fencing, branch replacement, message identity, and ordinary final delivery remain unchanged; there is no new retry loop or cache.

Contributor credit: Vito reported the missing final result and requested this repair.

- @VACInc
```
