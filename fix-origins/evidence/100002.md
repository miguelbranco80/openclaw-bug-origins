## Fix PR #156111 description (by steipete, opened 2026-09-23T02:34:20Z)

```text
## What Problem This Solves

Repeated follow-ups rejected because their task already finished can retain task tracking in Gateway memory. Follow-up to #156064 and its [terminal-receipt review finding](https://github.com/openclaw/openclaw/pull/156064#issuecomment-5787706273).

## User Impact

Rejected follow-ups release their lifecycle listener while preserving the existing completed, failed, cancelled, or timed-out task. No configuration or migration is required; stored formats and update behavior are unchanged.

## Why This Change Was Made

Creation can reuse a terminal row after an earlier tracking lookup found no task. Gateway registration correctly rejects that result, so it never receives responsibility for settling the new receipt. The existing creation owner now closes the listener before returning a terminal result. Running receipts keep their existing ownership and cleanup behavior.

## Evidence

The real Gateway/SQLite regression fails on the original code for all four terminal statuses, leaving one listener retained each time. With the fix, all 53 selected Gateway, run-owner, and event-lineage cases pass, including unchanged persisted snapshots on rejection. Independent P0–P2 review and the [completed ClawSweeper review](https://github.com/openclaw/openclaw/pull/156111#issuecomment-5788051613) found no remaining actionable issues.

The selected static plan is complete using remote proof and exact-head hosted CI: all 25 test type-check graphs, core types, dead exports, lint, and the selected guards passed. The redundant remote type pass was interrupted after preserving its completed prefix; it is not reported as a wholly successful invocation.

Full-file test cost on the same AWS c7a.4xlarge and Node 24.19.0, using `pnpm test src/gateway/agent-turn/agent-run-dispatch.sqlite.test.ts --maxWorkers=1`: baseline 15 cases passed in **55.85 s** command wall time; candidate 19 cases passed in **61.55 s** (+5.70 s for the four regression cases). Vitest durations were 53.06 s and 58.80 s. Each input used a separate filesystem module cache; these are single observations including startup and worker preparation.

[Exact-head CI passed on attempt 2](https://github.com/openclaw/openclaw/actions/runs/35810933046). The first attempt hit the unchanged 300-second no-output guard after 286 passing cases in a separate Gateway cohort; its compact job took 572.30 s and preserved unsettled resource claims. An independent control ran the exact CI source and original infrastructure-then-Gateway order: 355 + 286 cases passed with worker/resource cleanup joined. It used the same runtime/settings on a fresh host with an empty filesystem cache, so the original hosted hang remains unattributed. One targeted hosted retry then passed without a code, assertion, timeout, or guard change.

This is source-level listener cleanup proof. It makes no deployed performance-recovery claim and changes no UI or stored-data contract.
```
