## What Problem This Solves

Fixes private agents appearing in the Control UI picker and agent directory when the signed-in user’s role allows only a subset of agents.

## User Impact

Users discover only agents allowed by their existing role. A saved selection falls back to an allowed agent; an empty allowlist clears the selection. Reloads and reconnects wait for current discovery instead of showing an older browser roster or remembered picker identity. Owners and roles with `agents: "*"` retain the full roster.

## Why This Change Was Made

Filter `agents.list` using the current operator role after asynchronous preparation, then reconcile UI selection against the returned roster. Preserve Gateway routing defaults and ownership metadata; existing session/run authorization stays enforced. Discovery does not grant or revoke session-reading access. Remove the cached discovery fallback and require a live roster for new-session catalog targets; keep stored sessions, groups, transcripts, and draft intent.
