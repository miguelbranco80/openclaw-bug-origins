## Fix PR #197002 description (by Patrick-Erichsen, opened 2026-11-11T03:20:40Z)

```text
## What Problem This Solves

A scope-upgrade notification queued immediately before Gateway close can start another pairing-state read while restart markers are being saved.

## User Impact

Shutdown stops these read-only observers immediately and still lets accepted input finish restart preparation before mutation authority is cancelled.

## Why This Change Was Made

Split synchronous observer retirement from its existing awaited drain. Retire the coordinator beside the initial scheduler fence; keep the request-runtime sidecar responsible for joining cleanup. A guarded beginClose and one drain promise handle synchronous abort reentry without moving global cancellation earlier.

## Evidence

- Before: the strengthened existing public Gateway regression fails on unchanged main bdf56ed3 with postCloseReads expected0/got1 while real restart persistence is held (8pass/1fail;84.69s).
- After: **15/15** across public observer lifetime, coordinator, and accepted-ingress restart suites (91.21s). The queued-wake case verifies cancellation before restart persistence is released and retains the final pairing-state assertions.
- Production core types, affected test types, scoped type-aware runtime lint, formatting, and native max-lines/environment ratchets pass in the qualified integration checkout.
- Net25 regression lines receive the dedicated scope-upgrade-close allocation; the shared scalar is unchanged. The extra public-lifecycle gate proves the actual fence-to-persistence interval without a production test hook.

This preserves the delayed received-work cancellation introduced for restart durability. No schema, migration, permission, or live Gateway changes.
```
