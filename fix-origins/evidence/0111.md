## What Problem This Solves

Fixes Gateway event-loop stalls when plugin preparation creates source/native capture directories and their physical staging tokens on a filesystem waiting for a transaction commit.

Related: #200136, #200193, #200216. The motivating Team incident (25c97908, 2026-11-16 05:02 PST) blocked the Gateway MAIN thread for 1.97 seconds in `openat2(O_CREAT)` under `scheduler:update.remote-model-catalog`; the kernel waited in `btrfs_create → start_transaction → wait_current_trans`. The catalog's redundant lock was removed separately. This change handles the remaining physical capture-root owner.

## User Impact

Plugin preparation can wait on filesystem creation while the Gateway event loop remains responsive. There is no configuration or schema change and no operator action required.

The tradeoff is explicit: measured cold owner time increases from 183.267 to 453.257 ms, warm owner time from 141.459 to 182.479 ms, and whole process-tree CPU from 1,050 to 1,310 ms. A separate loaded-addon profile on the preceding revision observed 127.828 MiB RSS in the retained broker (summed process RSS increased 120.922 MiB; shared pages and profiling overhead included). The final revision proves ordinary same-process restarts reuse that broker; it does not remeasure that RSS observation. These costs are accepted for removing filesystem-transaction stalls from the Gateway thread, not described as an overall speedup.

## Why This Change Was Made

The existing broker resource owner now creates and retains the physical source/native roots and staging tokens. Preparation workers borrow paths; host cache and recovery leases retain the physical custody after execution ends. Loaded native code keeps its token until host exit. Ordinary Gateway restarts reuse the existing broker, and a fresh source replaces permanently failed or sealed authority without reopening old claims or inventing cleanup receipts.

This is the smallest complete root-custody cutover: moving only mkdir would leave token creation and lifetime operations on MAIN. Production grows by 685 lines across 21 production modules plus a net-zero build import adjustment. Twenty of those lines complete the shared lease type and preserve source-acquisition error classification across the new broker boundary. The growth is the private resource adapter and lifetime handoff; the old parent allocation callback and duplicate independent-resource count are removed. Existing pool/dependency declarations are moved intact to keep their owning modules within the repository's limits. No new manager, cache, database table or public protocol is introduced.

This does not claim all Gateway filesystem work is asynchronous. Recovery-copy/binding, runtime-selected synchronous JS/CJS/native imports, and the existing native-load realpath observation remain separate work.
