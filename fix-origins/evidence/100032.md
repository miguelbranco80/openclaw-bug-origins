## What Problem This Solves

Fixes Matrix message reads returning recent room history when a specific `--message-id` was requested.

## User Impact

Reading a specific message returns that event, or an error if it cannot be read. Reads without a message ID keep their existing pagination and thread behavior. No configuration changes are required.

## Why This Change Was Made

Select the requested event inside the existing Matrix read authorization and reuse its authorized client and message-summary path. Missing, redacted, malformed, or inaccessible events do not fall back to unrelated room history.

## Evidence

- 158 current-source tests pass, including 14 registered CLI and real-policy loopback cases.
- The registered CLI regression fails against the original code and passes with the repair.
- Disabled actions, delegated room/account restrictions, current-conversation authorization, client release, and no-ID history controls pass.
- 26 changed-file checks pass, including zero-warning lint and production/test type checks.
- Independent review found no actionable P0–P2 issues. Exact-head hosted CI remains required before landing.
- The loopback proof controls client acquisition and transport; it is not a live authenticated or encrypted-room Matrix test. Existing summary behavior still governs decryption and related poll events.

Original fix and reproduction by @masatohoshino; adapted to preserve current read authorization and client custody.
