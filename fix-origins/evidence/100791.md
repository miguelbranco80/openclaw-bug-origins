```text
## What Problem This Solves

Fixes agent entries in the session owner dropdown showing a generated face instead of the agent’s configured avatar (for example, Kitsune’s fox).

## User Impact

Owner and participant faces now use the agent’s configured emoji or image, consistently with the navigation rail. Agents without a configured avatar keep their generated face. No migration or configuration change is needed.

## Why This Change Was Made

The shared participant renderer only consumed the session actor’s image URL, losing text avatars. It now reads the existing reactive agent roster and hydrated identity, using the existing avatar resolvers without adding requests or a cache. Emoji faces also avoid inheriting the tiny initials font size.

Simplification: one shared fix covers the owner picker and participant faces; no picker-specific renderer or protocol field. Production delta: +28 net lines; regression coverage: +37 lines.

Reported by and co-authored with @vincentkoc.
```
