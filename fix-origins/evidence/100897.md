## Fix PR #153226 description (by steipete, opened 2026-09-19T22:55:55Z)

```text
## What Problem This Solves

Fixes cancelled background tasks remaining labeled “Waiting to send to parent” until the operator refreshes the task list.

## User Impact

The live Control UI receives the final cancellation and delivery state immediately. Execution duration and task cleanup deadlines remain unchanged; no configuration or migration is needed.

## Why This Change Was Made

Cancellation can publish a provisional terminal update before finalization arrives with an earlier execution timestamp. The shared task transition owner now gives substantive terminal corrections a newer publication timestamp while preserving their execution timestamps. Repeating the same finalization remains a no-op. Cleanup-only bookkeeping still persists without advancing activity or reordering the task list. This preserves the UI’s protection against stale responses.

## Evidence

Reproduced through a real Gateway and the shared Chrome profile: cancel an OpenClaw-created child and observe “Cancelled” alongside “Waiting to send to parent.” The durable row already had delivery disabled, but its older timestamp caused the UI to reject the correction.

Regression cases fail on the original source and pass with the fix for earlier and equal timestamps. The synchronous registry/publication path and worker transition path are covered, including persistence, unchanged cleanup deadlines, and duplicate-finalization idempotence. The selected sibling run passed 291 cases; the final extracted timestamp and worker run passed 18 cases. CI exposed a cleanup-only ordering regression and two retirement assertions that needed to protect the new freshness contract. The correction passes 254 selected cases, including the unchanged Gateway pagination test and both rotated-parent cases. Production and selected test type checks, scoped lint/format, ratchets, docs sanity, and diff checks passed. Independent Codex reviews found no actionable issues.

Live after-fix proof passed on the same local Gateway and shared Chrome profile with the final reviewed source integrated onto main. With the Tasks panel already open, one click on Stop cancelled a newly spawned child; the card changed to “Cancelled” and “No delivery required” without refreshing or reopening the panel. The persisted publication timestamp advanced 437 ms beyond the cancellation timestamp while execution duration remained unchanged. Both screenshots were inspected and delivered in the originating chat.
```
