## What Problem This Solves

Fixes unexplained gaps in `openclaw update` reports when candidate rehearsal, post-stop checks, or runtime activation takes a long time.

## User Impact

Operators can distinguish private-state copying, Doctor work, test Gateway startup, cleanup, and activation work instead of treating the entire quiet interval as a slow copy. Doctor diagnostics include section durations and the five slowest contributions.

The installed updater remains the driver: most new timings first appear on the update after installing this change. Pre/post-plugin Doctor timings can appear on the installing hop. Older Doctor candidates without section traces still work without section diagnostics.

## Why This Change Was Made

Git updates discarded successful candidate step results, successful temporary-copy cleanup had no step, and bounded run-history compaction could evict the timing receipts. Keep those receipts, expose the previously untimed activation phases, and reuse Doctor's existing startup-trace phases without introducing a tracing option or changing the run-record shape.

Copy-scope investigation: the canary already snapshots registered SQLite databases and copies exec approvals/configured plugin trees, not `worktrees/`, `workspace/`, or `tmp/`. Synthetic file counts do not change that copy. Peanutto's approximately 40-minute silent stretch is therefore not explained by copying those directories; these timings will identify the slow phase on the next real update. No copy-scope reduction is implemented.

- Retained synthetic-state experiment: adding 0, 25,000, 100,000, and 250,000 unrelated state files left the copied database byte count fixed at 1,757,184. - The existing `persists streamed candidate progress through its admitted worker (reopened)` test hit its unchanged 120-second timeout both here and on the exact clean merge base (`7008414e344`), including a single-worker isolated run. No timeout or assertion was weakened.

+import { recordMutableUpdateInterruption } from "./update-command-mutable-signals.js";
+import type { MutableUpdateExecutionResult } from "./update-command-result.js";

+type MutableUpdateSettlement = {
+  result: UpdateRunResult;
+  failure: MutableUpdateExecutionResult["failure"];
+  candidateFailureReason?: string;
+  databaseBackup?: UpdateDatabaseBackup;
+  databaseCaptureStep?: UpdateStepResult;
+  activationSteps: UpdateStepResult[];
+  doctorEntered: boolean;
+  packageTransaction?: PackageUpdateTransaction;
+  originalRun: MutableUpdateExecutionParams["opts"]["run"];
+  env?: NodeJS.ProcessEnv;
+  assertCurrent: () => void;
+};
+
+export async function settleMutableUpdateResult(
+  params: MutableUpdateExecutionParams,
+  settlement: MutableUpdateSettlement,
+): Promise<UpdateRunResult> {
+  const { opts } = params;
+  const { databaseBackup, databaseCaptureStep, activationSteps, packageTransaction } = settlement;
+  const originalRun = settlement.originalRun;
+  let result = recordMutableUpdateInterruption(opts, settlement.result);
+  if (
+    result.status === "ok" &&
+    opts.restart === false &&
+    result.steps.some(isUpdatePostInstallVerificationDeferred)
+  ) {
+    result = { ...result, status: "skipped", reason: "gateway-readiness-unverified" };
+  }
+  if (settlement.candidateFailureReason && result.status === "error") {
+    result.reason = settlement.candidateFailureReason;
+  }
+  if (databaseCaptureStep || activationSteps.length) {
+    result.steps = [
+      ...(databaseCaptureStep ? [databaseCaptureStep] : []),
+      ...result.steps,
+      ...activationSteps,
+    ];
+  }
+  const doctorSettled =
+    settlement.doctorEntered && !hasCommandProcessCleanupError(settlement.failure?.cause);
+  if (databaseBackup && originalRun && result.status === "error" && doctorSettled) {
+    // Execution has not entered finalization or admitted any candidate Gateway.
+    // Restore before schema inspection can hand an incompatible ledger to the candidate.
+    await restoreFailedUpdateDatabases({
+      backup: databaseBackup,
+      result,
+      runId: originalRun.runId,
+      env: settlement.env ?? originalRun.env,
+      assertCurrent: settlement.assertCurrent,
+      assertRollbackSafe: packageTransaction?.assertRollbackSafe,
+      progress: params.progress,
+    });
+  }
+  return result;
+}
