## Fix PR #157004 description (by steipete, opened 2026-09-24T04:19:28Z)

```text
Refs #156930. Thanks @Fuma2013 for the report and the restart/foreground control evidence.

## What Problem This Solves

Plugin-state failures appear in structured logs without their nested cause or the process that captured them, hiding why an older background reader rejects an upgraded database.

## User Impact

Structured records now include bounded nested causes, native error codes/errno, and the capturing process ID, thread ID, and OpenClaw version. Operators can distinguish a schema-version refusal from a file-open failure. Existing credential redaction remains active; arbitrary error properties and stacks are excluded.

For the reported 9.5 companion / 9.6 Gateway skew, update and relaunch OpenClaw.app; a Gateway-only restart leaves the old app worker in place. The diagnostics change must ship in the next npm release; the separate macOS-only rebuild cannot update the installed CLI/Gateway package.

## Why This Change Was Made

The tagged 9.5 app selects its signed private Node/OpenClaw payload, validates that payload against the app's version and build, and runs `node worker`; updating the external npm CLI does not replace it. The node-host plugin registry registers the same Codex catalog commands and keyed-state store. Its resident catalog reconciles every 30 seconds against the same profile's shared state database. Tagged 9.5 supports schema 17 and rechecks schema support even when reusing a read handle; 9.6 migrates the shared database to schema 18.

This establishes a version-skew mechanism consistent with a failing app-owned background reader, successful 9.6 foreground reads, and persistence across Gateway-only restarts. We have not captured the reporter's exact failing PID or nested cause, so this PR references the issue rather than claiming that attribution is independently proven.

The fix belongs to the plugin-state error and transport owners. One shared bounded cause serializer serves both worker transport and JSON logs; the existing canonical codec preserves typed/aggregate errors and now carries `errno`. JSON uses `errorCode` for native causes so OAuth-code redaction does not hide them; in-memory `.code` is unchanged. `owner` identifies where the plugin-state error was constructed, including the caller thread for pre-dispatch failures. No schema, migration, retention, or admission-policy changes.
```
