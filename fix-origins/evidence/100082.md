Related: #157819, #157886, #158047

## What Problem This Solves

Fixes Gateway shutdown hanging when a plugin replacement fails while publishing its configuration.

## User Impact

Failed, uncommitted plugin replacement can restore the previous runtime and configured model context limits, propagate the original error, and finish shutdown. Existing configuration and stored data need no migration.

## Why This Change Was Made

Plugin replacement gates model-catalog readers until activation or rollback finishes. On publication failure, secret rollback awaited catalog discovery inside the callback that the enclosing plugin rollback was waiting to finish.

Rollback now uses the context owner's existing synchronous reset steps: advance the generation, remove candidate configured limits, and prime the restored configuration. Snapshot ownership checks, discovered-metadata ownership, and generation fencing remain intact. Normal committed refresh still loads the catalog.
