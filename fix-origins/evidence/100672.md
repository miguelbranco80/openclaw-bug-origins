## Fix PR #172660 description (by steipete, opened 2026-10-15T00:22:42Z)

```text
Fixes #172648

## What Problem This Solves

Fixes Discord voice joins timing out, reconnecting muted, or switching channels when another guild member changes voice state.

## User Impact

Other members joining, leaving, moving, or changing mute/deaf settings no longer overwrite the bot's voice connection state. Participant rosters, occupancy-based auto-join, and follow-user behavior still receive those events. No configuration or migration is required.

## Why This Change Was Made

The Discord Gateway now records the bot user ID from `READY` and forwards only that member's voice-state packets to the adapter registered for the packet's guild. Voice-server updates have no user ID and continue to route by guild. This replaces the single-caller forwarding helper and removes its generic guild reader, reducing production code by 11 lines.

The adapter lookup and identity check happen synchronously in the Gateway owner before listener dispatch; this adds no detached or deferred effects and captures no stale authority, config, identity, session binding, path, or limit for later use.

## Evidence

- Source/history confirms the defect on main at `69d500b410f5d2f6ad169b9852f4d2c28cc720e0`: all guild members reached the adapter, whose dependency overwrites session identity and connection settings from each packet.
- Regression: `routes only the bot's own guild voice updates to its adapter while preserving other members' events` in `extensions/discord/src/internal/gateway.test.ts`. It uses the real socket dispatch, Client, and VoicePlugin with synthetic wire events, covering own join/leave, foreign join/move/leave, differing mute/deaf/session values, guild isolation for both event types, and roster/listener delivery.
```
