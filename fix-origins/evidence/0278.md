## Fix PR #194567 description (by steipete, opened 2026-11-07T09:34:47Z)

```text
Related: #194541

## What Problem This Solves

Fixes agent deletion failing with `worker task capacity reached` when hundreds of idle sessions are stored, and a deleting agent making the whole session catalog unavailable.

## User Impact

Interrupted deletion can complete on restart without flooding the worker pool. Healthy agents remain visible in catalogs while deletion is pending. Offline workspace recovery safeguards and explicit deleted-agent refusals remain intact. No configuration, schema, or migration changes.

## Why This Change Was Made

Deletion started every stored session drain concurrently, including worker-backed placement checks for idle sessions. The existing concurrency runner now limits that producer to four drains while agent-wide cancellation remains independent. Catalog planning and delivery use the journal's existing deletion fact to omit deleted scopes before explicit database admission.

Production grows by 15 lines: seven to replace eager fan-out with the existing bounded runner and eight to consume the existing catalog exclusion fact. There is no new scheduler, cache, retry policy, or dependency. The 85-line test allocation covers the capacity regression and catalog planning/delivery boundaries.

## Evidence
```
