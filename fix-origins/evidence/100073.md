Related: #153607 — the Doctor silent-failure portion only. Thanks @th-m-vogel for the report.

## What Problem This Solves

Doctor can print a plugin load failure inline, then report completion and exit successfully. This affects ENOSPC during runtime source capture as well as ordinary load errors.

## User Impact

Standalone `openclaw doctor --non-interactive` now emits an error finding naming the plugin, error class, and source path, and exits 1. ENOSPC is identified from the thrown errno code and includes disk-space guidance. Updater-invoked Doctor retains these failures as warnings and continues an otherwise safe update, including with published 2026.9.5 drivers.

This change addresses reporting and outcome only; it does not claim to fix scratch accumulation or tmpfs capacity.

## Why This Change Was Made

The loader already marked failed plugin records as errors. Doctor subsequently rebuilt metadata-only inventory, losing the failures from temporary runtime inspection registries. The loader now records structured errno information before logging and retains its diagnostic in an invocation-scoped collection. Doctor projects those observed failures through its existing plugin finding formatter at completion, including late loads, and deduplicates repeated reports. Metadata inventory stays lazy.

Production: 85 lines added, 16 removed (**+69 net**); regression tests: **+116**; docs: **+7**. The additional scoped lifetime and outcome handling are necessary because there was no separate inline-only loader path to remove.

## Evidence

- Before the fix, the ENOSPC capture-write and SyntaxError regressions both failed because Doctor made no nonzero exit call despite an errored plugin record.
- **375 repository tests passed** across the Doctor command regression, Doctor lifecycle, workspace status, main plugin loader, registry lifecycle, loader-record/SDK diagnostics, and setup-failure suites. The fixture injects an ENOSPC code with a message that does not contain that code at the real capture writer's filesystem seam. It also verifies deduplication and isolation between invocations. Unrelated Doctor checks are stubbed in the narrow regression.

Both normal update and parent-marker-only cases produce an error finding, exit 0 for the updater, and retain one warning with the plugin, ENOSPC, and path. This is boundary proof, not a full installation or tmpfs-pressure campaign.
- Runtime build passed. `pnpm check:changed` passed all selected gates. Fresh P1 Codex autoreview returned **scoped-clean** with no accepted/actionable P0 or P1 findings. The first lint run caught a duplicate fixture import; it was corrected and the four regression cases passed again.
