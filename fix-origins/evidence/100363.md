## What Problem This Solves

A conversation created by an agent can be visible in its custom sidebar group
but disappear from search and shared navigation when the user selects another
conversation. Searching for its title or something said in its transcript then
fails to provide a way back to that conversation.

## User Impact

Grouped conversations created by agents remain discoverable through the command
palette and shared session navigation after selection changes. Choosing a search
result reopens the matching conversation through the existing palette entry
points.

Subagent runs and ungrouped spawned sessions retain their discovery exclusions.
Grouping grants no access to private or incognito conversations and does not
override archive, agent, cron, or system-session filters. The shared inventory
rule also makes grouped ordinary conversations eligible in Activity and in
`sessions_list` when subagents are excluded. Runtime ownership and parent/child
relationships remain intact.

## Why This Change Was Made

The palette now sends its filters to the Gateway for both metadata and transcript
search. Its Gateway selector treated every entry carrying `spawnedBy` as a
subagent, so changing only the browser's visibility predicate could not restore
the search result.

The repair narrows that existing discovery classification: actual subagent keys
remain excluded, while an ordinary spawned conversation with an explicit custom
group remains eligible. The shared UI navigation filter uses the same group
distinction. Canonical category updates already invalidate the prepared session
metadata, including archived rows, so the repair needs no new stored state,
configuration, or protocol option.

zero metadata matches for the grouped conversation's title and zero transcript

found**. This fixture contains 205 newer conversations across five configured
