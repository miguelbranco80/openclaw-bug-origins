## What Problem This Solves

Fixes agents repeating unchanged `memory_search` results without reaching a critical block when `tools.loopDetection.enabled` is true.

Closes #169042.

## User Impact

Repeated searches with the same arguments and ordered hits now reach the existing loop threshold. Changing hit content, order, ranges, warnings, or stable backend metadata still counts as progress. Delivered scores and diagnostics are unchanged; no configuration or migration is required.

## Why This Change Was Made

The existing outcome-hash owner now excludes four per-call debug timings and each hit's time-decayed aggregate score. It preserves the remaining result metadata, including text/vector scores and provenance. Explicit error results and unstructured results keep full comparison, so new error text cannot be hidden by normalization.

Thanks @PatrickTrent for the detailed report and @ericcaiwx-star for the original fix. The contributor commits are preserved; current main was merged into the branch without rebasing.

Production: **+35/-0**; tests: **+113/-0**; docs: **+7/-0**. The added projection belongs to the existing hash owner, with no new state, config, or parallel mechanism. No obsolete nearby path could be removed to offset it without broadening the repair.
