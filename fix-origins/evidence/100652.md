```text
## What Problem This Solves

Trusted operator-created scheduled jobs have no inbound Discord sender. Before this change, `channel-edit` failed at the channel administration check even when the job had valid `message` access. Related: #140978.

This PR carries the canonical job grant through Discord channel editing, channel-name resolution, and provider retries. It uses the scheduled message admission and current tool-policy evaluation landed in #150166. It also fixes a caller completion check that discarded an accepted edit when disabling the job canceled its generated MCP request.

## User Impact

Operator-created jobs with `message` access can edit Discord channels and use the action's existing thread edit options. Configured account and action restrictions, the job's current capability, and Discord permissions continue to apply.

Disabling, removing, replacing, or narrowing a job blocks later requests and rate-limit retries. Caller or plugin retirement also blocks subsequent I/O. Configuration changes apply to the next invocation; an admitted operation retains its configuration. A confirmed provider result survives job cancellation and the original MCP request's abort.

## Why This Change Was Made

The optional SDK field `ChannelMessageActionAdapter.writeAuthorityActions?: readonly ChannelMessageActionName[]` declares that an adapter preserves the existing `assertDirectAdapterHandoff` callback through preparation and every provider request or retry. Action discovery and read support do not establish that write contract. The host independently selects eligible actions; Discord declares only `channel-edit` in this PR.

Admission checks the canonical job grant, configured action and account, and the active bundled or loader-verified official registration. Channel lookup retains the selected registration and request guard. Its read scope closes before the mutation, whose actual result is allowed to settle. The in-process Gateway retains the original signal and caller guards for later dispatches and mutation commits.

Older adapters remain source-compatible because the declaration is optional. Scheduled administration requires the updated adapter contract and its loaded registration. Account-created jobs do not inherit operator administration, and no run-wide owner flag or invented requester identity is introduced. Canonical SDK and automation documentation explains the interface, retained checks, configuration timing, and upgrade behavior.
