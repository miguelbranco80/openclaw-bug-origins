## Fix PR #150994 description (by steipete, opened 2026-09-17T16:28:40Z)

```text
## What Problem This Solves

Android chat gives little feedback while dictation starts, speech is finalized, or photos are prepared, making successful actions appear unresponsive.

## User Impact

The composer now shows Starting dictation, Listening, and Transcribing with an interim transcript, plus visible attachment preparation and message queuing. Users can cancel a pending transcription, and recognition failures explain how to retry without losing the existing draft.

## Why This Change Was Made

The existing recognizer and composer owners already track this work. Their state now drives the feedback, and dictation waits for the platform readiness callback before showing Listening. Final text is still inserted only once; cancellation rejects late callbacks. Message queuing describes local admission, with subsequent delivery reported by the existing outbox.

## Evidence

- Initial full CI exposed an existing connection-bootstrap race that changes Refresh to Refreshing during the approvals coherence test. The same ordering fails on the original code and passes when that test invokes the existing refresh owner. All terminal/card assertions and separate real-button coverage remain. The repaired head passes all 27 selected Settings/composer/controller tests and fresh P0–P2 review; [Full CI passes on the repaired head](https://github.com/openclaw/openclaw/actions/runs/35250380510).
- 19 focused controller and full-composer tests pass, including readiness, partial/final results, cancellation, stale callbacks, photo preparation, and send admission. The readiness and photo-progress regressions failed against the original implementation.
- Play debug and instrumentation APKs build. Native emulator instrumentation exercises pending photo import through the production composer owner, preserves the caption, and verifies the ready attachment.
- Changed-file checks, Android lint, native localization verification, and an independent P0–P2 review pass.
- These inspected emulator screenshots use synthetic chat and photo data. Physical microphone behavior and recognition accuracy were not tested. The acceptance scope is visible and cancellable UI state plus draft ownership through the production callback boundary. The recognizer/provider and audio-capture owner are unchanged; physical accuracy remains outside the tested claims.
```
