## Fix PR #176060 description (by steipete, opened 2026-10-18T04:16:40Z)

```text
## What Problem This Solves

Fixes: an embedded MCP App cannot save its state through its teardown handler before the Control UI removes its frame.

## User Impact

The App's graceful cleanup save can finish before detachment. Connection changes still revoke its requests, and the existing 250 ms teardown limit remains. There is no layout or appearance change.

## Why This Change Was Made

The reconnect change in #174046 made runtime bridge calls inherit the frame's setup cancellation signal. Teardown aborts setup before asking the App to save, so that save was rejected before reaching the MCP server. Keep setup cancellation on the initial view request. Give runtime calls the frame's own lifetime, cancel them when graceful teardown ends, and retain the existing connection authority checks.

The same change exposed an incomplete conformance fixture: its hand-built Gateway omitted handshake state and event subscriptions, causing both reported empty-frame failures. Use the real application Gateway owner instead. This removes the competing fixture handshake and lets the existing real-transport save-before-detach assertions catch the production defect. All assertions are retained.

## Evidence

- On main base `fee2073acc21`, both conformance cases failed with the reported missing inner frame. The browser error was missing `hello.auth`, rather than a CSP/frame-loading failure.
- Fixture repair alone: 1/2 passed; the remaining case recorded teardown received then frame detached, with no cleanup-save request reaching the MCP server. This is the negative control for the production fix.
- Final native UI E2E run: 2/2 passed (`node scripts/run-vitest.mjs run --config test/vitest/vitest.ui-e2e.config.ts --configLoader runner ui/src/e2e/mcp-app-conformance.e2e.test.ts --maxWorkers=1`; 76.89 s wall, 72.04 s Vitest). Both hosts recorded cleanup saved before frame detached; caller cancellation and composed-operation checks also passed.
- `pnpm test ui/src/components/mcp-app-view.test.ts ui/src/components/mcp-app-bridge.test.ts ui/src/components/mcp-app-retirement.test.tsx ui/src/components/mcp-app-unmount.test.tsx --maxWorkers=1`: 43/43 passed, 16.33 s wall. The updated view file also passed alone: 33/33 in 6.09 s wall.
- UI production, components-test and E2E-test tsgo passed; typed oxlint, boundary lint, formatting, diff check and full `check:architecture` passed.
- An independent P2 review identified missing cancellation after frame disposal in the first proposal; the final fix addresses it with a frame-owned signal and two regression cases. The final P2 review passed with no actionable findings; the two cancellation regressions failed before the correction and pass after it. PR CI remains the broad proof; no CI reruns or dispatches requested.

The production change is teardown ordering, so the proof is the actual Gateway/MCP/postMessage save receipt and detachment order rather than appearance screenshots. The reported blank frame came from the synthetic fixture.
```
