## Fix message body

```text
fix(computer): request structured elements from CUA window state



CUA 0.37 returns window state as a Markdown tree by default, but the computer-use adapter reads structured `elements`. On Linux, `get_window_state` therefore returned no usable element references, so element actions such as `set_value` could not target anything. The adapter now requests `tree_format: "elements"`. The `type` action is unchanged.

Evidence: built Gateway, an admitted agent turn and managed Linux X11/CUA with Mousepad. On main, two runs returned zero usable element references; with this change, two runs returned seven real references, and `set_value` landed and matched clipboard readback and fresh accessibility observations. The `type` control passed in all four runs. Details: https://github.com/openclaw/openclaw/pull/190700#issuecomment-6565031850.

Thanks @huidongchen148.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```

Explicitly request `tree_format: "elements"` at the existing driver boundary. Keep the normal opaque-reference lifecycle, permissions, observation requirements and native integrity checks unchanged. No model-facing schema/description, configuration, SDK or string-normalization changes.

Original one-line repair and regression by @huidongchen148; the contributor commit is preserved. Consolidate the driver's default behavior into the existing shared test fixture instead of duplicating setup, and remove the now-unneeded test allocation. Production **+1/-0**; tests **+6/-7 (net -1)** against merge base `94451cf42bb910c8eaa4c4fc13873a8b787708ce`. Provider documentation explains structured observations.

## Evidence

[Built runtime proof, exact results and inspected before/after screenshots](https://github.com/openclaw/openclaw/pull/190700#issuecomment-6565031850).

Four fresh runs through the **built Gateway → admitted agent turn → computer tool → real managed CUA/X11 → Mousepad** in secretless Debian 12/arm64 Docker, Node 24.22.1, CUA 0.37.0:

- Frozen main `e99c7b529d8e9d5d7c0062d48457ae8f71a13002`, twice: no usable native element refs.
- Candidate, twice: seven real refs; `set_value` using the actual observation/editor capabilities writes `restored native editor`.
- Independent actual clipboard readback and fresh accessibility observation verify both native edits.
- Unchanged keyboard `type` control succeeds on all four runs with exact clipboard readback.

Focused checks: commands, driver-result and reference-lifecycle suites **52/52 passed** (36.61s runner wall time; 29.04s Vitest duration including cold compilation). Targeted Oxfmt and `git diff --check` passed. Hosted CI owns broader checks and type/lint gates.

The deterministic local model-provider fixture supplies ordinary tool calls; it is not a live-provider claim. No mocked tool/transport/native provider, fabricated references, direct setter or capability bypass. Physical desktops, Wayland, macOS/Windows and released packages were not exercised. Full runtime/UI builds completed; CSS-size advisories were emitted without failing the builds.

This fixes the native-reference prerequisite observed in #190594, not that PR's separate whitespace behavior. Its three-action proof remains a separate task.

**Merge danger:** two-way door; reverting restores the previous tree request without migrating persistent data. Blast radius is CUA native window observations and consumers of their element capabilities.
