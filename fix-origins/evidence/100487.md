## Fix PR #170006 description (by steipete, opened 2026-10-12T16:28:03Z)

```text
## What Problem This Solves

The macOS app rejects its own managed `bun --no-install … gateway` command, leaving update and recovery verification incomplete even when the Gateway is healthy.

Fixes #169662.

## User Impact

Valid protected Bun services can reach the app's existing ownership and recovery verification. No configuration or service argument changes are required.

## Why This Change Was Made

`GatewayLaunchAgentManager.installedServiceCLI` skipped memory flags but treated `--no-install` as a second entrypoint. Recognize that exact flag only for a Bun executable, while retaining the full command prefix and all existing entrypoint, wrapper, custody, and runtime-pin checks.
```
