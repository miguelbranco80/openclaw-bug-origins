## Fix PR #171750 description (by steipete, opened 2026-10-14T04:54:31Z)

```text
Refs #171673

## What Problem This Solves

Qwen runtime hooks are skipped when the registry selects `dashscope` provider IDs or `modelstudio-native` endpoint owners, so existing quota-error handling is unavailable through those bindings.

## User Impact

These references now select the registered Qwen runtime hooks. In particular, a DashScope 429 reporting exhausted free credits is classified as billing, as it already is for the canonical Qwen provider.

## Why This Change Was Made

The Qwen manifest declares `dashscope` and the `modelstudio-native` endpoint class, but its runtime registration lacks both hook bindings. Add them through the existing internal `hookAliases` contract, matching the pattern used by Amazon Bedrock and Volcengine. Native endpoint metadata supplies the owner reference for custom provider IDs; exact registered provider IDs retain precedence.

Scope limit from code review: custom-provider coverage proves selection after Qwen is registered. Cold activation from a custom provider’s native URL remains a separate control-plane gap: the activation planner uses manifest provider/API references, not runtime hook aliases. This binding-only change does not claim to repair that path.

This PR does not change overflow wording or classification. That work belongs to the shared overflow table and is handled separately by #171712.

## Evidence

- Source inspection traced native URL classification through `resolveProviderEndpoint`, runtime preparation's endpoint owner, and `findProviderRuntimeRegistrationInRegistry`; the latter indexes internal hook aliases. - Regression names: `resolves Qwen quota hooks for dashscope` and `resolves Qwen quota hooks for custom-dashscope`.
```
