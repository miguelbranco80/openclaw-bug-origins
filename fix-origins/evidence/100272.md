## Fix PR #163787 description (by steipete, opened 2026-10-02T21:07:59Z)

```text
## What Problem This Solves

Fixes: a paired macOS app node shows no Claude Code sessions (and does not advertise the Claude session commands) when the user runs Claude Code with `CLAUDE_CONFIG_DIR` pointing somewhere other than `~/.claude`.

## User Impact

User impact: the Mac node now lists and opens Claude Code sessions from `$CLAUDE_CONFIG_DIR/projects/`, the same root the Gateway and headless TypeScript node already use. Behavior is unchanged when the variable is unset or blank. The macOS app reads its own process environment, so a Finder-launched app only sees `CLAUDE_CONFIG_DIR` when it is part of the app's launch environment.

## Why This Change Was Made

The TypeScript scan (`extensions/anthropic/session-catalog-scan.ts`) resolves the projects root as trimmed `CLAUDE_CONFIG_DIR`, else `HOME/.claude`, following Claude Code's "respect CLAUDE_CONFIG_DIR everywhere" convention. The native catalog hardcoded `~/.claude/projects` and recomputed it separately for list, read, read-lease store/lookup, and advertisement. It now resolves the root once per entry point with the same precedence and passes it down, so the existing root-containment and symlink checks apply to the resolved root and read pagination leases stay bound to it. Claude Desktop metadata stays `HOME/Library`-scoped, matching the TypeScript node commands. Tests now pass an explicit environment instead of inheriting the runner's.

## Evidence

- `swift test --package-path apps/macos --build-system native --filter MacNodeClaudeSessionCatalogTests`: 11/11 passed on this head's base. The new cases cover env set (whitespace-padded): custom root listed and readable, decoy in `~/.claude/projects` excluded, an index entry escaping into `~/.claude` rejected, Desktop title still applied, page two served from the lease without re-enumeration, advertisement following the custom root. They also cover unset, empty, and whitespace-only env falling back to `~/.claude/projects`.
- Regression probe: with env resolution forced off, the `CLAUDE_CONFIG_DIR` test fails with 5 issues while the fallback cases pass.
- `swift build --package-path apps/macos --build-system native --product OpenClaw`: passed.
- Changed-file `swiftlint --strict --config config/swiftlint.yml`, `swiftformat --lint`, oxfmt on the docs, and `git diff --check`: clean.
- Codex autoreview: scoped-clean.
```
