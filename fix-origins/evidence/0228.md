## Fix PR #195136 description (by steipete, opened 2026-11-08T08:43:27Z)

```text
## What Problem This Solves

Streaming plain-text tool-call repair repeatedly parses accumulated Markdown when literal call-like prose arrives in small chunks, creating avoidable CPU and allocation pressure.

## User Impact

Literal Markdown, tool-call promotion, and event replay stay byte-for-byte equivalent in the exercised streams while inline-code prose and false call prefixes allocate substantially less. No configuration, dependency, schema, or public API change.

## Why This Change Was Made

One candidate scan view now owns lazy code protection for sequence and trailing-prefix classification. Invalid prose no longer eagerly asks for Markdown ownership; already-resolved code ranges still skip grammar work. The existing carried fence scanner can reach a blank paragraph boundary before judging the first candidate, and can judge an unambiguous unfinished line without reparsing all prior output.

This does not replace the canonical Markdown parser or add a cross-delta cache. Cumulative snapshot scrubbing and real-call payload ownership still perform full parses. Runtime production code is **net −4 lines**; the two regression cases add 18 test lines with a matching scoped allocation, and the rerunnable benchmark adds 229 lines.
```
