```text
The update database generation check compared physical fingerprints, so a SQLite checkpoint that merely folded already-captured WAL frames into the main file (on Windows, triggered by the exclusive removal probe) was treated as a later write and rollback was refused with "Databases changed after snapshot capture"; the Windows lifecycle test failed in isolation. The check now compares committed pages plus retained WAL commit evidence: checkpoint-only transitions and exact reversals that leave byte-identical content are admitted (identical content cannot lose data on restore; recorded at the comparer with a regression), while any newer data is still refused. ## What Problem This Solves
```

```text
Fixes database and package rollback being refused when SQLite checkpoints already-captured WAL pages during Windows file-removal admission.

Related: #158163. Reproduces the failure reported by hourly run [36827062752](https://github.com/openclaw/openclaw/actions/runs/36827062752/job/110255226021).

## User Impact

An interrupted update can restore its previous package after a checkpoint-only transition. Newer committed data, database replacement, and changed retained write evidence still refuse restoration. An exact reversal leaving committed bytes and retained write evidence identical is intentionally admitted: it leaves no later data for rollback to discard.

No schema, dependency, configuration, CLI, or service-lifecycle change is included. Auto-merge is off.

## Why This Change Was Made

The snapshot/restore owner previously hashed physical database/WAL layout. The Windows exclusive-removal probe uses SQLite's private WAL index; closing it folds the WAL into the main file and can delete the WAL while leaving disk SHM unchanged. The old guard classified that checkpoint as an intervening write and refused database restoration before package restoration began.

The probe remains unchanged because Windows requires its native handle to close before files can be replaced. It is the checkpoint trigger in this reproduced flow; the shared generation owner also needs to tolerate ordinary checkpoints.

The generation owner now checkpoints a verified private copy and hashes committed pages with the original file identity and retained WAL transaction counter/last-frame checksum. SQLite interprets journals and WAL frames. Physical-generation and SHM publication checks still fence capture.

The command fixture incorrectly replaced the isolated snapshot worker with raw in-process copies while native SQLite handles remained live. Closing those descriptors can release SQLite's process-wide POSIX locks. Removing that substitute restores real snapshot/content-version dispatch and deletes its path bookkeeping.

### Order dependence

On baseline `40d9ed0924dafa3ef1bf8cf604679e79aa33a3e4`, the interruption case fails alone but passes after the complete eleven-case prefix, ending with `settles native Windows task enabled state after update finalization (none)`. The passing full run captures an empty WAL; isolation captures four frames (16,512 bytes), which the removal probe later checkpoints. Neither selector alone, both selectors, either Windows block, nor the full prefix with either selector omitted masks the failure. No single masking predecessor was established, and cases do not share database files.

With the unsafe substitute removed, the old owner also fails in the full file (20 passed, 1 failed). The repaired owner passes the full file and isolation. The owner regression explicitly constructs the WAL/checkpoint transition and does not depend on incidental case ordering.
```

```diff
+function readWalIndexHeader(pathname: string): Buffer | null {
+  const file = `${pathname}-shm`;
+  let descriptor: number;
+  try {
+    descriptor = fs.openSync(file, "r");
+  } catch (error) {
+    if (hasNodeErrorCode(error, "ENOENT")) {
+      return null;
+    }
+    throw error;
+  }

+    // reject a torn publication; bytes 96+ contain mutable reader/lock bookkeeping.
+    const first = fs.readSync(descriptor, header, 0, 48, 0);
+    const second = fs.readSync(descriptor, header, 48, 48, 48);
+    const after = fs.fstatSync(descriptor, { bigint: true });

+      !current.isFile() ||

+      before.dev !== current.dev ||
```
