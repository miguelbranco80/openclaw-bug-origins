## What Problem This Solves

Fixes: slow or interrupted connections replace usable chat and visualizations with errors, strand message delivery, and prevent previously signed-in users from reopening their work offline.

## User Impact

Users can keep reading cached conversations, editing text and attachment drafts, and queuing messages after a connection loss or an offline reload. Recovery appears in the existing bottom-left connection indicator, not a second chat banner. Loaded widgets retain their local interaction state.

Offline reload requires a prepared browser cache and an explicit browser-offline signal. Server actions and uncached external resources still require a connection. Previously signed-in proxy, Tailscale, and password users gain local access without storing their password or new bearer credentials; sending waits for account revalidation. People with access to the browser profile can read retained local data.

**Migration:** the derived transcript cache moves from IndexedDB version 3 to 4; unscoped old history is discarded and refilled online rather than assigned to another account. Unsent legacy drafts and queues remain available for explicit recovery, never automatic reassignment or sending. Retention limits remain unchanged; rollback does not turn account-qualified input back into an unowned queue.

## Why This Change Was Made

Keep presentation alive independently of connection authority. Retry transient reads within their existing recovery windows, reconcile uncertain writes using the original message ID, and scope local work to its Gateway/account. Same-client account replacement, stale handoffs, cross-tab retirement, and explicit credential-forget cannot transfer another account’s input. The service worker prepares only integrity-bound build assets and a generic shell, retains native online HTTP-auth navigation, and resumes interrupted preparation without holding updates indefinitely.
