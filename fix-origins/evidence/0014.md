## Fix PR #200784 description (by roboclaw-bot, opened 2026-11-17T20:17:33Z)

## What Problem This Solves

Native Codex model discovery uses the Codex client version. The bundled 0.164.0 runtime is behind the 0.169.0 CLI that @VACInc reports can see `gpt-6.2-sol` and `gpt-6.2-astra`. This updates the bundled runtime and matching protocol so the old native client does not hold back discovery.

Related: #200766 supplied the GPT-6.2 catalog and provider-transport support. Ben’s #197768 supplied native catalog forwarding through the inference relay and is now merged as [ed3230dd29d1](https://github.com/openclaw/openclaw/commit/ed3230dd29d1e162d814e38eff00f64dc77af64e). This PR includes that commit as an ancestor: it no longer contains the relay production changes and retains additional native-discovery and cleanup regression tests. It also preserves the subsequently merged #200811: the subscription picker independently requests `client_version=99.0.0`, while native app-server discovery still uses its actual binary version. The remaining OpenAI version fallback applies to Platform access-program discovery. These are complementary paths; actual native availability still depends on the account and backend.

## User Impact

Bundled Codex and the Platform access-program version fallback report version 0.169.0. Matching protocol validation accepts uploaded audio-file references without dropping a completed turn. This does not add GPT-6.2 catalog entries, change default models, or change authentication policy.

**Context limits stay unchanged:** the merged GPT-6.2 catalog records a 1,050,000-token model window, a 272,000-token default working budget, and a 128,000-token maximum output for Astra and Sol. User-selected limits and native context reporting remain unchanged. No files overlap the catalog/transport changes from #200766.

## Why This Change Was Made

- Update the package, lockfile, existing ACP version-parity override, runtime constant, OpenAI discovery fallback and documented version to 0.169.0.
- Regenerate the selected upstream schemas and standalone validators from `rust-v0.169.0`, using the existing repository generator helpers.
- Protect failed-turn settlement and visible errors for `modelNotFound`, `policyCapacityUnavailable` and `inferenceHookDenied`, including completed snapshots containing the new audio `fileId` representation.
- Recognize the new native `execve` launch diagnostic only when its path matches the native binary. Repair an HTTP test fixture that dropped shell arguments; production cleanup and permissions are unchanged.

<details>
<summary>Protocol compatibility and generation provenance</summary>

No client request methods were removed. Selected response roots retain their required fields; dynamic-tool call parameters and model-list responses are unchanged. Optional item timestamps, agent-message moderation, image generation IDs and thread attachment IDs require no consumer change. The regenerated mirror includes Account’s `gcp` variant, optional ChatGPT `workspaceName` and optional GetAccountResponse `userId`, without enabling new authentication behavior. Optional `ModelListParams.modelProvider` remains omitted to use the configured provider. New memory, guardian, approved-plan, provider/GCP/account/security setup methods are not called. Audio URL and uploaded-file variants both validate.

Source: [rust-v0.169.0](https://github.com/openai/codex/tree/d32063f96c2dff1dc96af839b3952abb6acfeda4/codex-rs/app-server-protocol/schema), commit `d32063f96c2dff1dc96af839b3952abb6acfeda4`. Used the checked-in experimental export archive with existing materialization, staging, compaction and formatting helpers, then `scripts/generate-codex-validators.mts`. All eight selected JSON schemas round-trip to those exports. No generated schema or validator was hand-edited. Rust/Cargo is unavailable here, so the Rust fixture compilation stage of `protocol:sync` was not rerun.

</details>
