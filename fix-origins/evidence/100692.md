## What Problem This Solves

Fixes: visiting distinct chat sessions leaves snapshot invalidation keys retained for the lifetime of the Control UI.

## User Impact

Long-running Control UI sessions release completed snapshot-read bookkeeping while preserving cached transcripts and stale-result rejection. No storage format or operator action changes.

## Why This Change Was Made

The retention census found that the revision map grew from 50 to 100 session keys across two blocks of navigation. Shared read identities now live only while reads and queued writes need them, and each operation releases its claim in `finally`. Same-key writes, deletion, scope invalidation, and global invalidation still retire old claims immediately. Queued writes retain their claims through settlement.

The existing sidebar persistence helper moves behind the same late snapshot-store import boundary to keep the owner within its file limit. The early database/prewarm graph remains unchanged.
