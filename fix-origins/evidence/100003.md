```text
Related: #158318. This addresses the explicit wait/cancellation path; it does not close the broader ingress and blocker-diagnostics request.

## What Problem This Solves

Targeted plugin reload gives up after 60 seconds even when healthy admitted work will finish shortly afterward, leaving operators to retry manually.

## User Impact

Operators can run `openclaw plugins reload <ids...> --wait` to wait for admitted work without restarting the Gateway. The default remains 60 seconds. Ctrl+C or requester disconnect cancels the pre-publication wait; admitted runs continue, and rollback restores dispatch when recovery succeeds. Cancellation after publication does not undo the new generation. Cleanup and recovery retain their existing deadlines.

Existing channel queue/replay guarantees remain unchanged. This does not add crash-durable ingress, identify leaked retention tokens, or make a reload invoked from a turn holding the same plugin able to finish itself. Run maintenance outside that turn.

## Why This Change Was Made

The reload owner now controls one abortable settlement observation instead of repeatedly applying five-second observers inside a sixty-second retry loop. Its signal reaches retained work, active calls, and finite consumers. Request cancellation is separate from Gateway-owned recovery and physical lease release. CLI and RPC use the same lifecycle transaction; the optional wire field also updates generated Swift models.

Production delta: +40 lines (190 added  / 150 removed), excluding generated output. The added capability is requester-owned cancellable waiting across CLI/RPC/lifecycle boundaries; the cleanup owner itself shrinks by 14 lines. Tests: +354 net; docs: +14; generated Swift: +4. Existing lifecycle plan construction moves to its plan owner, and its propagation regression moves out of the oversized main config suite.

### Named follow-up: macOS aliased state-directory ownership during concurrent session writes

An initial /tmp-based run hit SQLite backend-ownership conflicts and two missing replies after reload rollback. A no-reload control reproduced the ownership conflict but delivered all four replies. Source suggests lexical path aliases select competing execution owners for one physical database; the cause of the two missing replies remains unproven. These failures are retained as a separate investigation, not claimed fixed by this patch.
