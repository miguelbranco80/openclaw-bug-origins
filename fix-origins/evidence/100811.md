## Fix PR #179647 description (by steipete, opened 2026-10-21T15:38:40Z)

```text
## What Problem This Solves

With nine saved native gateways, the gateway submenu from the navigation rail clips its last gateway and Gateway Settings even though there is room above the trigger. The rail placement change in #179218 exposed a shared overlay issue: the height cap shrinks a menu into its initial anchor region before native positioning can detect overflow and flip it.

Measure side overlays against the viewport, allow the opposite vertical alignment, and retain bounded scrolling beside the trigger when neither anchored region fits. Keep the shared height default less specific than consumer panel styles. Otherwise lazy primitive CSS can override the agent menu's viewport budget with 420px, hiding 107px of agent rows at enlarged text. Placement remains owned by CSS; no JavaScript positioning or additional state is introduced.

## Evidence

- Original compact failure reproduced on hourly head `f960ba73bb16`, its parent, and main. Reversing only #179218's rail placement makes the complete scenario pass. Gateway 9 originally extended to y=912 in a 900px viewport while the menu ended at y=884.
- Follow-up CI regression reproduced **3/3** on `fb7153861be9`: `sidebar-interactions` reports 107px clipped at enlarged text. The unchanged complete file passes **3/3** at merge base `7f26958c4d65` (8 cases each).
- New consumer-height browser regression fails before the follow-up in both Chromium and WebKit (420px instead of its 500px budget), and passes afterward. The complete overlay presentation suite passes **26/26**, covering LTR/RTL, low and middle triggers, enlarged text, viewport bounds, and keyboard access to the last item.
- Repaired bundled sidebar and compact identity files pass **10/10**. The agent menu computes its intended 884px maximum, renders at 526.5px, and shows all five agent rows. Existing assertions and timeouts are unchanged.
- Direct overlay/menu/sidebar/tooltip browser suites: **452 passed, 1 inherited failure** across 40 Chromium/WebKit file runs. WebKit `popover.browser.test.tsx`, line 159, expects the Outside button to retain focus but receives `body`; this same failure was independently reproduced with unchanged base CSS. Its bottom-start placement is outside the side-placement change.
- All **72** requested side-menu/submenu E2E files ran through their native bundled or dedicated-server projects: **417 passed, 3 failed**. Two failures are the known agent-page position and native-titlebar hover assertions covered by the peer fix below. The remaining failure exposed an independent pinned-menu fixture race. The exact empty-width failure reproduced in **1/3 runs on both the merge base and repaired head**; this bottom-end menu is outside the changed CSS selectors. Diagnostics caught a detached SVG with `isConnected: false` and zero bounds: reactive menu refreshes retained the row but replaced its icon between locator resolution and evaluation. Query and measure the current SVG synchronously inside the retained row; keep the exact 16px, keyboard, and content assertions. The complete pinned-agent file then passed **3/3 runs, 18/18 tests**, including all four widths. No wait or retry was added.
- Component, UI E2E, and extension test typechecks, scoped oxlint, stylelint, formatting, and whitespace checks pass. Independent P0–P2 review of both the original fix and the follow-up found no actionable issues.
- No CI dispatch or rerun. The agent-page scope and Inbox expectation changes are covered by #179574. The lead owns landing.
```
