## What Problem This Solves

When a Gateway uses `gateway.controlUi.basePath`, an origin-only pairing URL sends the mobile embedded Settings page to `/settings` instead of its configured mount. New QR and Gateway pairing setup codes now include that mount.

The shared setup-code resolver owns the configured `device-pair.publicUrl` fallback and applies the normalized mount only when the selected URL has no path. Explicit CLI/RPC overrides, configured URLs that already contain a path, and remote Gateway URLs remain authoritative. This removes duplicated fallback selection from the CLI and RPC callers. Existing pairings are unchanged; generate a new setup code and re-pair to update their endpoint.
