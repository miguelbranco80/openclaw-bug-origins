## Fix PR #148604 description (by steipete, opened 2026-09-14T23:18:05Z)

```text
Fixes #148454
Related: #147720, #147615.

## What Problem This Solves

Managed Git and npm upgrades started by OpenClaw 2026.9.3 can stop the Gateway and then reject their own migrated finalizer with `Another update executor owns this installation`, leaving no `result.json` for the waiting updater.

## User Impact

The candidate can complete same-installation migration finalization, restart verification, and result publication while its legitimate legacy parent retains the installation lease. Other or revoked owners remain excluded.

## Why This Change Was Made

The shipped 2026.9.3 producer sends no executor grant and waits for the finalizer while still holding its lease. The candidate recognizes that contract from the recorded producer version, captured handoff/run metadata, unchanged canonical installation key, and private result/scratch selectors. Root moves retain their existing independent-admission path; the recorded key is never re-resolved through a newly retargeted symlink. The existing executor owner checks the matching live direct parent, pins the lease database, and registers the finalizer's own child lifetime without changing the parent's lease. Nested commands retain the existing delegation and settlement checks.

The shared child-delegation implementation moves to a focused module to keep the executor within the existing file-size limit. No configuration, schema, dependency, or recovery-policy changes are included.

## Evidence

The regression drives the actual candidate worker and lease store with legacy-shaped private input and a held parent lease. Both Git and npm cases failed before the fix:

```text
Another update executor owns this installation.
result.json exists: false: expected 1 to be +0
Tests 2 failed
```

Both passed after the repair, publishing the matching terminal result, performing the synthetic native restart, and preserving the parent's exact lease. Additional cases reject wrong handoff/run/root/version/scratch/parent identity, an existing child registration, and parent ownership/database replacement before native effects.

## Follow-up (owner decision)

Restoring migrated state and restarting the retained version after finalization fails remain outside this PR. The shipped [v2026.9.3 rollback owner refuses migrated-state rollback](https://github.com/openclaw/openclaw/blob/v2026.9.3/src/cli/update-cli/update-command-rollback.ts#L212), and its [managed helper requires verified restoration facts before restart](https://github.com/openclaw/openclaw/blob/v2026.9.3/src/infra/update-managed-service-handoff.ts#L1706) (lines 1706–1730). A failure result alone cannot establish those facts. Peter must decide the design and authorization for verified backup restoration; this repair makes the reported successful update path complete and does not claim new failure-recovery or legacy crash-survival guarantees.

Reported by @jalehman (#148454).
