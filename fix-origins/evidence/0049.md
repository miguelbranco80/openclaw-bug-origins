## Fix message body

```text
fix(devices): stop pending devices reads promptly on Ctrl+C

A Ctrl+C during a pending openclaw devices list or the devices approve preview did not reach the Gateway read, so the CLI kept the socket open until it was force-killed about 2 seconds later, and could still print a failure afterwards. The read-only list and approval-preview calls now pass the command's existing abort signal and print nothing once aborted. Explicit approve and reject calls are unchanged. The gateway-call helper moves to devices-cli-gateway.ts because devices-cli.runtime.ts is held by the max-lines ratchet. No text changes.

Evidence: a real Gateway with a real pending pairing request from a headless openclaw node run, a WebSocket proxy holding the device.pair.list response and Ctrl+C sent in a real PTY, two runs each. On main devices list --json and the devices approve --json preview were force-killed about 2.1 s after Ctrl+C with the socket closing only then; with this change both exit 130 within 0.03 s with a normal close and no further output. Without --json the spinner already handles Ctrl+C on both. An uninterrupted list, the unreachable-Gateway fallback and devices approve <id> behave the same on both. Net 0 test lines. Details: https://github.com/openclaw/openclaw/pull/197110#issuecomment-6790934424.

Thanks @Alix-007.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```
