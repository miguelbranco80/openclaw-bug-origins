## What Problem This Solves

Fixes a pending agent database write committing after root-wide asynchronous close begins while a retained resource is still draining.

## User Impact

Database shutdown rejects pending native writes as soon as close begins and still waits for retained resources to finish. Schemas, persisted formats, and update behavior are unchanged; no migration or operator action is required.

## Why This Change Was Made

Root-wide close previously awaited resource drainage before revoking pending native opens. Revoke matching opens synchronously, as exact-path close already does, while preserving the existing drain and native-join loop, cleanup ownership, and selected-root isolation.
