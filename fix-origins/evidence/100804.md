## Fix message body

```text
On native Windows, every command that opens the state database (onboard, doctor, gateway run) failed with 'undergoing offline maintenance' on a fresh install: the same process registered its schema-maintenance scope under one spelling of the database path and looked it up under another, so it refused its own scope. In-process state ownership and schema scopes now key on one canonical database identity (realpath via the nearest existing ancestor, compared case-insensitively on Windows); on-disk lock paths keep their existing names for mixed-version compatibility, and a missing same-process scope is reported as a typed internal error instead of the user-facing maintenance message.

Fixes #176163
```

## Fix PR #176174 description (by steipete, opened 2026-10-18T09:42:13Z)

```text
Fixes #176163.

## What Problem This Solves

Fresh Windows installs can reject onboarding, Doctor, and Gateway startup as “undergoing offline maintenance” even though the command holds its own schema lease.

## User Impact

State initialization keeps its maintenance authority when Windows path spelling changes. A missing same-process scope now produces a typed internal ownership error with retry/report guidance; real foreign maintenance still refuses access.

## Why This Change Was Made

The process-owner registry and schema scope were keyed by the lock pathname. Native realpath can change that pathname's spelling after directory creation, leaving the live scope unreachable while the persisted lock still identifies this PID. Both registries now use one canonical database identity, including Windows case and namespace normalization. Owners retain their acquired physical lock paths, and captured handles carry their prepared identity.

The existing on-disk lock names and hashes are unchanged, preserving exclusion with older processes. Contention errors now live beside the other ownership errors; the existing import surface is retained. No config, dependency, schema, or lock-protocol change is required. The ownership path uses built-in filesystem and AsyncLocalStorage operations; npm install scripts do not create or register its schema scopes.
