## Fix PR #188406 description (by steipete, opened 2026-10-30T14:05:59Z)

```text
## What Problem This Solves

Background task results accepted during an assistant run can appear at a different position when the conversation is reopened, breaking the previously sent prompt prefix. A result arriving during streaming can even move ahead of signed assistant output.

## User Impact

Background completions remain immediately durable and visible. Subsequent model requests preserve their recorded order across live execution and replay, including recovery after an interrupted run. Existing transcripts keep their current interpretation.

## Why This Change Was Made

The approved persisted-contract extension records placement with an immutable transcript marker at the next request boundary. It references the original result entries and the exact preceding entry. Live execution adopts those recorded results without importing foreign queued user input, rewriting accepted payloads, or waiting for the parent run to settle.

Bounded and model-context reads, compaction/reset, forks, and suffix cleanup preserve the marker's dependencies. Pending payloads remain recoverable before placement, including through cached reads. There is no database table migration or transcript version bump. Older readers omit newly pending results from model context; the results remain visible in transcript history.

This is one complete persisted-contract cutover: the producer, live loop, replay, and lifecycle consumers must agree before the new marker can be written. Production TypeScript is +789/−69 lines (net +720); tests are +724/−30 (net +694). The growth supports that contract across existing owners, rather than a parallel execution path. No test-line ceiling increase is needed.
```
