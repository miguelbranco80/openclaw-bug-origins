```text
## What Problem This Solves

Fixes: the Advisor and MCP Events plugins have no packaged identity or activity artwork, and the bundled plugin icon contract (`src/plugins/bundled-plugin-icons.test.ts`) fails with `ENOENT` for them in the release plugin sweep (Plugin Prerelease run 38662499961, 2026.10.10-beta.1).

## User Impact

User impact: Advisor and MCP Events show proper artwork in the Plugins catalog and in chat activity, and the release sweep's icon contract passes again.

## Why This Change Was Made

Every bundled plugin must ship a 512px `assets/icon.png` and a monochrome `assets/activity.svg`. Advisor (#169564) and MCP Events (#165399) landed without `assets/`. FRV only reported Advisor because the test stops at the first missing file. A scan of every tracked `extensions/*/openclaw.plugin.json` on main and on release/2026.10.10 finds these two plugins as the only gaps.

Both are native OpenClaw plugins, so, following #172299 (mcp-relay), they reuse the shared OpenClaw mascot identity byte-for-byte. Their new activity glyphs join the "Agent or task flow" family: a compass for Advisor's course correction, and a trigger bolt for MCP Events starting automations. Each glyph is one stroked path with the same attribute set as the `mcp-relay` and `acpx` glyphs. Both icon source inventories record the new rows.

## Evidence

- Before, on main: `pnpm test src/plugins/bundled-plugin-icons.test.ts --maxWorkers=1` fails with `ENOENT .../extensions/advisor/assets/icon.png`. With only Advisor fixed, it fails on `extensions/mcp-events/assets/icon.png`.
- After: 1/1 passes on this branch, and also with the patch applied to release tip `c92d7743aa9`.
- `pnpm test ui/src/pages/plugins/activity-icon-loader.browser.test.ts`: 187 passed. That test decodes every shipped activity glyph through the bounded Control UI SVG loader.
- `oxfmt --check` is clean for both inventories.
```
