## Fix PR #158624 description (by steipete, opened 2026-09-26T03:39:47Z)

```text
## What Problem This Solves

Inference help and shell completion load provider execution, authentication, configuration, and Gateway runtimes while building the command tree. That makes discovery depend on code needed only when an inference command actually runs.

## User Impact

Parent help, detailed subcommand help, the `capability` alias, and shell completion retain their command and option inventory without initializing inference execution runtimes. Existing command execution and provider-selection behavior is preserved.

## Why This Change Was Made

Move execution imports into their owning command actions and runners. Extract the existing provider-command registration into a lightweight module so listing the command tree does not import provider configuration. Keep the current main branch's consolidated image registrations, model-provider helper, model catalog handling, account-secret preparation, asynchronous resource disposal, and web exit behavior.

This replays campaign batch p007 (`bb21ea50e874af2246183bc5948c5f5420bc1590`) onto current main. The related lazy-domain selection change in #140327 does not address eager imports inside domain registrars. Conflicts in audio, image, model, shared, video, and web were resolved toward current main's implementation, then the equivalent import deferral was applied. The retired model-reference wrapper and duplicated image registrations were not restored; current provider-environment APIs were retained. The regression guard also covers the newer account-secret, configuration, and prepared-catalog imports.

The initial changed-file gate caught one counted line of growth in the oversized execution test. Its existing invocation helpers and collection-time subprocess setup now live in a small test harness; helper bodies and all assertions are preserved, and the original file shrinks.

No changed paths match `.github/CODEOWNERS`.
