## What Problem This Solves

Fixes workspace icons returning HTTP 500 after successful Gateway startup, with repeated AbortError stacks in the Gateway log.

## User Impact

HTTP reads use a live request lifetime. Disconnects cancel cooperating work quietly, shutdown closes unfinished responses, and acknowledged hooks continue under their independent Gateway lifetime. Unexpected errors retain their diagnostics. Operators can observe cancellations through `openclaw_gateway_http_cancelled_total{source="client"|"shutdown"}`. Normal cancellations stay out of the stability event buffer.

## Why This Change Was Made

HTTP listeners inherited the startup AsyncWorkScope after the run loop retired it. Requests now enter the live Gateway owner and get a disconnect-aware child scope. Cancellation and draining restore that request context so abort listeners can schedule cleanup and the Gateway joins it before releasing resources.

The transport owner records successful response completion before Node's normal connection-close handling. This matters on Node 24, which can emit `finish` with `writableFinished=true` after a buffered write loses its socket. Normal `Connection: close` responses and server-selected rejections remain excluded from cancellation counts.

Current UI already deduplicates these image loads. The tested virtual-remount flow issued one metadata request and one image request, retained the image across an actual row unmount/remount, and produced zero failed/cancelled media requests. No UI patch was justified by this evidence.

Non-test/non-doc LOC: **+120**, using the requested diff filter. The growth supplies the missing cancellation/cleanup lifetime and bounded metric. Existing metric cases move to their current timing owner, and the now-unneeded line-limit suppression is removed. No user configuration, schema, or dependency change.
