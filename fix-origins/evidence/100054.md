## Fix PR #160685 description (by steipete, opened 2026-09-28T20:05:42Z)

```text
## What Problem This Solves

When a read-only Control UI browser requests administrator access (**Limited access → Request admin**), the Inbox told the user to approve it by running `openclaw devices` on the Gateway. That command only prints help and approves nothing, so the user was left without a working next step.

## Why This Change Was Made

`ui/src/components/sidebar-issue-item.ts` (from cef071582ea) rendered a static string. The pending scope-upgrade state already carries the request ID, so the message now renders the exact command, `openclaw devices approve <requestId>`, through a `{command}` placeholder in `connection.scopeUpgrade.pending`. `docs/web/control-ui/connect-and-pair.md` is aligned. Scope and pairing policy are unchanged.

## User Impact

The Limited access notice shows a command that actually approves this browser. Running it reconnects the browser with admin scopes.

## Evidence

- **Regression test** (`ui/src/components/sidebar-issue-item.test.ts`): fails before the fix, and all 9 tests pass after.
- **Real isolated Gateway plus Chromium on a Blacksmith Testbox:** a read-only browser requested admin, and the Inbox rendered the real pending request ID. Running the displayed command reconnected the browser with admin scopes 981 ms after approval. Deny, expiry, and retry were exercised too.
```
