## Fix PR #150658 description (by steipete, opened 2026-09-17T06:00:28Z)

```text
## What Problem This Solves

Fixes an old write error appearing when Cancel cannot reload a plugin credential's saved configuration while applied-config polling is active.

Related: #150566 (the intermittent browser failure also reproduces on main; its request-cadence work is separate).

## User Impact

Cancel retains the credential draft and shows the failed read's error. A newer successful explicit refresh clears an earlier transient error. Unresolved draft conflicts and background polling's rejected-draft explanation remain intact. No visual design or copy change, configuration migration, or new setting.

## Why This Change Was Made

Field cancellation called the config reader outside the shared load registry. An overlapping applied-config poll could supersede that read, causing its later rejection to be ignored while the previous write error remained authoritative. Field cancellation now registers with the same loader as polling and raw-draft discard.

The browser fixture also arms its failure and clicks Cancel in one browser task: otherwise a poll can consume the deferred read before the click. All existing error, draft-preservation, and write assertions remain unchanged. The Settings documentation now describes failed Cancel reads.

## Evidence

- Controlled regression: original production code fails 2 cases (including `Expected: "Config read unavailable"`, `Received: "GatewayRequestError: Write rejected"`); fixed code passes all 16 field-discard cases. Covers polling during Cancel and a later explicit refresh succeeding or failing before the superseded Cancel read rejects.
- Config-owner and config-page tests: 338 passed across 22 files. UI test typecheck passed.
- `plugins-credentials.e2e.test.ts`: 20 consecutive final runs, 80 scenario passes, zero failures or retries, using CI's UI E2E configuration with `CI=true` and `OPENCLAW_UI_E2E_SKIP_REAL_GATEWAY=1`. The single-file inventory omits `--shard 6/12` so the selected test is actually run.
- `node scripts/check-changed.mjs` and `git diff --check` passed. Independent review is clean through P2.
- Base-comparison startup check passed: 7 startup JS requests, 359,495 gzip bytes; startup CSS unchanged at 48,249 bytes. No baseline, budget, timeout, retry policy, assertion, or skip was relaxed.

The first browser attempt exposed the fixture's pre-click deferral race and was stopped for the fixture repair before the final 20-run proof.
```
