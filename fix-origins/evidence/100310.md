fix(web-fetch): keep HTML table cells and preformatted text intact

web_fetch's HTML-to-Markdown rendering merged adjacent table cells, so separate values like "12" and "34" came out as a misleading "1234", and it flattened indentation in pre/code blocks. Cells now stay separated and preformatted blocks keep their indentation and the text that follows them.

Proof: built Gateway, /tools/invoke web_fetch on a local page. On main, numeric cells merged and code indentation was lost (twice, separate URLs); a plain-prose page was unchanged. With this change cells stay separate, indentation is kept, and the following paragraph is intact. Production +95 (cut from the original proposal by 77 lines; reuses the code-whitespace handling from #172389).

## Fix PR #176263 description (by sunlit-deng, opened 2026-10-18T15:39:17Z)

```text
## What problem this solves

Fixes #176244. Minified HTML tables currently return `EMEA12015` for the separate cells `EMEA`, `120`, and `15`. HTML preformatted code loses indentation and runs into the following paragraph.

## Changes

Separate table cells, protect preformatted text during prose normalization, and wrap it in a fence longer than its literal backticks. Treat markup inside a pre block as presentation, so anchors contribute literal text without Markdown link syntax. Escape input NULs before restoring internal markers in one forward pass.

Reuse the fenced-code whitespace preservation from #172389; the text extractor only gains matching-length fence recognition. Remove the extra literal-anchor state and custom marker-restoration scanner from the original proposal.

## Evidence

Built isolated Gateways, invoked `POST /tools/invoke` with `web_fetch` against a local HTTP page containing adjacent numeric cells and an indented pre block, twice with independent URLs plus an ordinary-prose control. Configuration was created through the shipped CLI.

Baseline output:
````text
EMEA12015
APAC987

def f(x):
 if x:
 return 1
 return 0Done with the example code above and more trailing words.
````

Candidate output:
````text
EMEA | 120 | 15
APAC | 98 | 7

```
def f(x):
    if x:
        return 1
    return 0
```

Done with the example code above and more trailing words.
````

The ordinary-prose control passes on both artifacts. The focused suite has 44 passing tests on the candidate; six new regressions fail on the baseline. Coverage includes literal links, longer fences, decoded marker-like input, long NUL runs, and the existing adjacent-code-block boundary. Targeted formatting and lint pass.

Whole-change deltas against the merge base: production +121/-26 (net +95), tests +59/-0. This removes 77 net production lines from the original proposal. Remaining growth is needed to keep code out of prose normalization, separate cells, and recognize the longer safe fences without reimplementing whitespace extraction.

Thanks to @sunlit-deng for the report and original implementation; their commits are retained.

Merge danger: two-way door; reverting restores the old extraction without a state migration. Blast radius is HTML rendering in web_fetch's Markdown extraction, basic fallback, and HTML error summaries, plus matching-length fenced-code conversion in text extraction.
```
