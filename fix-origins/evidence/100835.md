## Fix message body

```text
## What Problem This Solves

Fixes: normalized `web_search` results can present impossible calendar dates as optional publication metadata when a provider returns a date-shaped value such as `2026-02-30`.

## User Impact

User impact: invalid calendar prefixes are omitted from `published`, while the search results, their order, URLs, titles, snippets, and valid publication values stay intact. No configuration change is needed.

## Why This Change Was Made

Publication metadata represents a page date, not arbitrary display text. The existing output owner now uses the maintained date parser to round-trip only the calendar prefix. It keeps the original structural character filter and returns valid values verbatim, without interpreting or tightening timestamp suffixes or inventing a timezone.

This does not change provider selection, request parameters, caching, trust envelopes, the raw compatibility branch, or any public schema or permission. It is not strict full-timestamp validation or a guarantee that a provider's otherwise valid date is factually correct.

## Evidence

An actual normal Gateway invoked the registered Brave-backed `web_search` through `/tools/invoke`, using the supported Brave-compatible loopback endpoint and synthetic credentials. There was one native `/res/v1/web/search` request per revision; no manual provider registry or source-factory shortcut was used.

| Provider metadata | Before | After |
| --- | --- | --- |
| `2026-02-30` | Exposed | `published` omitted |
| `2026-13-01` | Exposed | `published` omitted |
| `1900-02-29` | Exposed | `published` omitted |
| `2000-02-29`, `0099-12-31`, `0000-02-29` | Preserved | Preserved verbatim |
| `2024-02-29T00:30:00+14:00`, existing `2026-09-21T` suffix shape | Preserved | Preserved verbatim |

Both model-facing tool text and diagnostic details show the correction. All eight rows and non-publication fields match the retained baseline after masking only generated content-envelope nonce IDs. The trust stamp is unchanged. Invalid fields are absent on the wire, not replaced with `null`.

- **79 focused tests pass** across the existing output/security and registered-wrapper suites (`--maxWorkers=1`, **25.12s wall**, including **11.864s** worker preparation). Added calendar cases report **0–1ms each**. Restoring the old assignment makes the three invalid-date cases fail while all five preservation controls pass.
- The actual affected **agents-tools test-type project** passes, as do scoped type-aware lint, formatting, and source-size/assertion-safety checks.
- The maintained runtime build and real Gateway candidate probe pass on the clean exact candidate. The contributor's original commit remains in its ancestry.

This is controlled protocol proof, not a request to the hosted Brave service or a paid model. The earlier Firecrawl-specific repair is unchanged; this correction covers the shared normalized-result boundary reached by Brave and other conforming providers.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```
