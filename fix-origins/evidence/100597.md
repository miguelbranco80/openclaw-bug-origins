## Fix message body

```text
fix(gateway): measure the terminal.open timeout with a monotonic clock

`terminal.open` set and checked its 30-second relative timeout with the wall clock. If the clock jumped back, the wait stretched past 30 seconds; if it jumped forward, a healthy open could fail early. The timeout is now measured with a monotonic clock. The 30-second budget and error handling are unchanged.

Proof: built Gateway RPC with a process-local libfaketime clock step (no system clock change). On main, both a backward and a forward step changed the effective timeout (twice). With this change both stay on budget; no-step controls are unchanged.

Thanks @SunnyShu0925.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```

## Fix PR #170665 description (by SunnyShu0925, opened 2026-10-13T05:14:46Z)

```text
## What Problem This Solves

Fixes terminal opens exceeding their 30-second deadline or failing prematurely when the host wall clock changes.

## User Impact

Terminal opens keep the same timeout budget during clock corrections. No configuration, permissions, or persisted data changes.

## Why This Change Was Made

The deadline and its final dispatch check now use the same monotonic clock as the timeout timer. This preserves the existing deadline owner and cancellation behavior without introducing another timeout path. Thanks to @SunnyShu0925 for the report, fix, and original regression coverage.

## Evidence

Built main (`b62a8f8dab531b3909fa63ef74b28f45d2fda5b9`) and the candidate in an isolated Linux container. Drove `terminal.open` through the shipped CLI and a running Gateway using an installed synthetic session-catalog plugin. Process-local libfaketime changed wall time only; the host clock was untouched.

- Main, twice: a 90-second rewind during a 31-second catalog lookup incorrectly opened a terminal after 32.07s and 31.94s. A forward jump incorrectly returned `UNAVAILABLE: terminal open timed out` after 0.71s. Normal-clock controls opened successfully.
- Candidate, same inputs: both over-budget lookups returned `UNAVAILABLE: terminal open timed out` after 32.76s and 33.80s; the forward-jump open and both normal-clock controls succeeded. The synthetic lookup deliberately blocks the event loop for 31 seconds, so rejection is observed after it yields, not exactly at 30 seconds.
- Focused deadline and Gateway-method suites: 33 tests passed (5.41s and 62.47s wall time). Formatting and lint passed for all four changed files.
- Shipped model-auth probe against OpenAI `gpt-5-mini`: `ok` (1.67s provider latency).

The simplification retains distinct pending-lookup, late-completion, and forward-jump regressions while removing redundant test commentary. Production delta: +6/-4 lines; test delta: +77/-1 lines against the merge base.
- Automated negative controls with the two production files reverted: the forward-jump regression fails because no terminal opens; the unresolved-lookup rewind regression times out. Both pass on the candidate. The unrelated native-incognito CI failure also reproduces identically on a clean main tree at `dbd0a216b2bdfff9f98da28d51652dd9e784ca2d` (8 passed, 1 failed); see the [classification and maintainer override evidence](https://github.com/openclaw/openclaw/pull/170665#issuecomment-6222225023).

Merge danger: two-way door. Reverting restores the prior clock behavior without data migration. Blast radius is Gateway terminal-open timeout and final node-dispatch authorization timing; other deadlines are unchanged.
```
