## What Problem This Solves

Fixes two reproduced update/recovery failures: an unfinished plugin migration rejects the package installation needed to repair it, and a missing core-matched ClawHub release never reaches the official package's declared npm alternative.

Refs #166554. Reported by @CodeForcer.

**The reported deletion is NOT yet reproduced.** The reporter's legacy `~/.openclaw/extensions/codex` layout is a leading hypothesis, not an established cause. We have requested the original install path and update step list. This PR is scoped to recovery admission and registry lag.

## User Impact

Plugin install/update can save a verified repair package while Doctor-owned data work remains pending; runtime activation stays deferred until that work is ready. Exact `config unset plugins.entries.<id>` succeeds with the normal config backup and leaves the data obligation pending. Doctor and update repair continue through their existing recovery entry points.

For an implicit exact-version official ClawHub target, the updater tries the catalog-declared trusted npm package at that same version. Catalog pins, newer recorded release pins, and security/integrity refusals remain authoritative. If no allowed source serves it, a verified compatible installed version stays selected with a version-skew warning and a retry instruction.

## Why This Change Was Made

The migration owner required state completion before publishing the package needed to complete it. It now separates repair publication from runtime activation and preserves unresolved and unrelated migration obligations. Config retention applies the same exact-entry-removal decision during validation and persistence.

The update owner now uses the existing source-fallback installer and payload verification, and the existing npm unavailable-release warning path also handles ClawHub records. No config, CLI, environment, dependency, or SQLite schema changes are introduced.

Removed the speculative backup scanner/restorer, Doctor/startup restoration and metadata refresh hooks, and their backup tests. The remaining prior-generation cleanup deferral belongs to repair publication: an unactivated replacement has not drained the old runtime. No new deletion-prevention guard remains.
