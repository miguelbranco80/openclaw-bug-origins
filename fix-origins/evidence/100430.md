Fixes #187088.

## What Problem This Solves

Hovering the sidebar rail’s New Session button opens a shortcut hint to its right. When that hint overlaps a neighboring session-group header, its keycap text receives the pointer instead of the header. Moving directly from the plus button to the group can prevent the group’s normal controls from responding.

## User Impact

The pointer can reach the adjacent group header and its actions while the informational hint is visible. The hint keeps its content, placement, and accessible description. New Session remains a native link: context menus, middle-click, and modified-click keep their normal behavior, and opening the form does not create a conversation or discard an unsent draft.

## Why This Change Was Made

The New Session link owns a read-only tooltip containing a shortcut hint or disabled explanation. It now opts into the shared tooltip’s existing `pointerThrough` capability. The shared default remains unchanged, so rich tooltips containing links continue to accept pointer input. No permission checks, routing rules, styles, timers, or new interaction mechanism are introduced.

The existing sidebar interaction scenario now waits for the rail tooltip to actually open and moves directly to the neighboring header. Removing the intermediate composer hover prevents the test from passing by dismissing the hint before it reaches the obstructed control. Group/catalog URLs, native-tab gestures, draft preservation, and no-session-creation assertions remain intact. The contribution adds one production line; the existing test changes by ten added and two removed lines.
