## What Problem This Solves

Fixes `update repair` completing without explaining that an already stopped managed Gateway remains offline, while omitting maintenance warnings from its final JSON outcome.

## User Impact

Standalone repair reports the intentional non-start and names `openclaw gateway start`, including the selected profile. Maintenance warnings appear in `postUpdate.doctor.warnings`, with `status: "warning"` and a successful exit when other work succeeds. Installation-drift remediation retains precedence over ordinary start guidance.

## Why This Change Was Made

Doctor maintenance already owns the service decision and its warning list. Finalization now collects those warnings after maintenance finishes. The Gateway stays stopped unless repair itself owns restoration; parent-owned activation remains with the updater.

RomneyDa's original commit is retained as a merge parent. This changes reporting only: no schema, persisted format, configuration option, or activation policy changes. It applies when the installed candidate runs repair/finalization; it cannot patch an older updater already running in memory. The original PR's published-2026.9.4 recovery-boundary trace remains historical compatibility evidence, not a new native smoke run.
