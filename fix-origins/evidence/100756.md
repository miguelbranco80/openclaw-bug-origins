## What Problem This Solves

Fixes: switching automations can show the previous task's runs under the newly selected task, and a successful run-history retry can leave the old failure banner visible.

## User Impact

History stays attached to the selected automation and filters. Refreshing the same history retains its last results while loading; a successful retry clears its own error while preserving feedback from other actions. No configuration or migration is required.

## Why This Change Was Made

Request ownership already rejected late responses, but retained rows had no lasting query identity and history failures shared the action error field. The history owner now uses the same query comparison for retained history and active requests, and owns history errors separately from action/status feedback. Pagination and coalesced refreshes keep their existing request authority.
