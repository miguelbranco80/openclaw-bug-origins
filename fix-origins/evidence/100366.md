## Fix message body

```text
## What Problem This Solves

Chat refused config changes such as runtime pins before offering approval. The suggested model-selection shortcut could not express the requested change.

## Why This Change Was Made

Remove the path bans and duplicated prohibition prompts. Approved writes use the existing config writer; failures return to the assistant for one corrective proposal with fresh approval. This state has one writer: the canonical config writer.

Owner decision: this is approval UX, not a new credential-switching system. Ordinary config writes gain no live model probe or path restrictions.

## User Impact

More settings can be changed from chat. Existing approval, schema, SecretRef, snapshot, and write-authority checks remain. Invalid-but-formatted API keys are not tested. Model setup keeps its existing live verification.

## Evidence

Before: the registered tool rejects a runtime-pin request before approval. After: it offers approval and the real writer saves the pin without a new model probe.

`node scripts/run-vitest.mjs run src/system-agent/config-write-validation.test.ts`

Real Telegram with a live model: approve an invalid boolean, receive its validation error, approve the correction separately, and read back the saved `false` value. The first failure no longer claims that nothing was written.

432 targeted tests pass; 65 final channel/approval consumer tests pass; 230 registered-owner tests pass on a fresh merge with main. The broader system-agent/config suites passed 856 tests before the approval-delivery correction. Two independent adversarial passes were completed and their findings fixed.

## Compatibility

No config key, schema, SDK, protocol, or migration change. The config writer and model-setup verification are unchanged.

## Consumers

Removed the classifier, duplicate guards, and ban-table tests.

## Invalidation

Existing runtime reload and session revalidation are unchanged.

## Tests

Covers no write before approval, real persistence, schema/ref rejection, fresh repair approval, and truthful write-failure reporting.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```
