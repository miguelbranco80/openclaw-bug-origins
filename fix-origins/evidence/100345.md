```text
## What Problem This Solves

Fixes misleading `/export` suggestions in the Control UI: the menu advertised an HTML file at a workspace path, while the command downloaded Markdown through the browser and silently ignored that path.

## User Impact

Both `/export` and `/export-session` now describe their Markdown download accurately. An unsupported path shows a clear correction and keeps the draft and staged attachments intact. Successful exports keep attachments ready for the next message and clear the previous command error when you retry. Other clients retain their separate server-side HTML export behavior.

## Why This Change Was Made

The UI inherited the shared server command's help despite handling export locally. The existing UI command adapter now describes its own behavior, and its dispatcher rejects unsupported arguments. Composer clearing happens only after successful export and only while the submitted draft and session are still current. The unreachable executor export branch is removed.

## Evidence

- Reproduced through the shared real Chrome profile: the original menu offered `[path]` and HTML, while both ordinary export and a supplied HTML path downloaded Markdown. The requested HTML file was never created.
- Four focused regressions failed on the original behavior; a further two failed on the stale error after a corrected retry. All 296 selected command/composer and lazy command-discovery cases pass after merging current main, with retained Markdown-content coverage.
- Local production and UI test type checks, formatting, lint, size/assertion guards, i18n, and docs checks passed. Fresh independent review found no actionable issues.
- Shared Chrome verification uses a synthetic local Gateway preview of the candidate: the hint describes Markdown, unsupported paths leave the draft intact without downloading, and a valid command produces an actual Markdown download. Correcting a rejected path then downloads Markdown, clears the composer, and removes the prior error banner.

Main integration: the lazy English command-palette catalog owns the export description. Main `36069552a27` now supplies the landed Gateway test-shard repair; all ten export feature files remain byte-identical to the previously reviewed candidate. All 296 focused tests pass again after this integration. The browser captures below predate these integrations and show the unchanged export repair.

CI investigation: the previous head also timed out in the mobile Swarm lifecycle test. An unchanged local replay of the exact 49-file shard passed all 206 cases, including that test. Local Node was 24.20.0 versus CI 24.19.0; runner scheduling/cache conditions differed. The original timeout remains unexplained. Fresh exact-head CI passed on `83768e654401e445c77dee223c3f7b107beebd3e`, including the previously failing UI shard ([run 35465766154](https://github.com/openclaw/openclaw/actions/runs/35465766154)). No test timeout, retry, or assertion was weakened.
```
