```text
## What Problem This Solves

Reading archived transcript usage uses an async API, but resolving the transcript filename still performs synchronous filesystem calls on the Gateway thread. The existing zero-sync-filesystem regression reproduces this on main.

## User Impact

Archived usage reads no longer block the Gateway thread during transcript path resolution. Candidate ordering, restored-root and sibling-agent fallback, and existing synchronous callers retain their current behavior. No configuration or migration is required.

## Why This Change Was Made

One shared path policy now accepts synchronous or asynchronous filesystem probes, rather than maintaining two containment implementations. Transcript candidate planning is likewise shared. The async usage reader selects the async resolver.

Compatibility review also found that native async realpath handles a symlink followed by a parent segment differently from the existing resolver. Normalize the input before resolving it and retain a regression proving sync/async agreement.

## Evidence

- Original public async usage entry reproduces synchronous realpath calls before the fix (1 failed, 27 skipped). Generated, relative and absolute filenames now retain usage results with zero observed synchronous filesystem calls.
- A separate symlink/parent-segment regression fails before the normalization correction and passes with it. Existing sibling symlink replacement, restored-root, unsafe-path and fallback cases exercise both resolvers.
- Final Node focused consumer proof: 83 tests pass across five files (usage, path policy, shutdown draining, history revocation and filesystem helpers).
- Final Bun proof: 41 tests pass across usage and path policy. Canonical five-file type-aware lint, core typecheck, formatting and diff checks pass.
- No native Windows execution was available; Windows coverage remains with PR CI. No timeouts or assertions were relaxed. Independent review was explicitly waived by the maintainer; local simplification and compatibility review completed.
```
