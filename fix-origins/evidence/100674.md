## What Problem This Solves

Fixes the first message to a cold configured session store failing before any provider request. This also breaks the parent turn in the heartbeat store-lifecycle product test before it can spawn a child.

## User Impact

The first turn can create its configured store and continue with the request's original authorization. Source replacement, credential revocation, and membership changes retain their existing refusal behavior.

## Why This Change Was Made

Regression from #169622 (`cbc53ac75eca`): native reply admission followed its own first-store registration, but the Gateway request's separate retained sharing witness did not. The witness invalidated itself on that registration.

Forward the existing committed registration callback through reply admission to that witness, after updating the admission selector and before public observers run. Keep asynchronous preparation and the reduced database work; add no SQL, retries, fallback reads, or new lifetime owner. Group the existing session-initialization callbacks in their small owner module while preserving their dispatch-time read. Schema, stored data, and update behavior stay unchanged.
