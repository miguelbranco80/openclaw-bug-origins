## What Problem This Solves

Immutable activation could be reported as verified while `sessions.list` failed, even though `/healthz`, `/readyz`, and the health RPC succeeded.

## User Impact

Verification now requires one authenticated compact session listing (`limit: 1`) from the verified Gateway boot. RPC errors and malformed results leave the activation unverified; an empty session list is valid. Existing timeout, failure, and recovery behavior remains in charge.

## Why This Change Was Made

HTTP readiness alone does not prove that the session store can serve requests. The verifier uses the existing read-only auth and TLS owners, checks the boot at dispatch and completion, and retains its final process/generation reconciliation. There are no descriptor, control-record, model-marker, plugin-policy, or bridge changes.

Diff: **2 files, +98/-2**; production **+67/-0**. This correctness fix adds a previously missing application check, so there is no superseded production path to remove. It adds one bounded RPC per verification, not a polling loop.
