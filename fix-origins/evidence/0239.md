```text
## What Problem This Solves

Fixes Agents API continuations that remain silent until the outer turn watchdog expires when a saved native session never produces an event. Reusing the same binding can repeat the delay on every turn.

## User Impact

Native startup now fails after 120 seconds without an event, followed by the existing bounded native cleanup, with actionable inspection/reset guidance. Shorter attempt deadlines still apply. Existing bindings are retained and can continue when the service recovers; reset must settle old work before clearing a binding. Automatic replacement could abandon running work or lose hosted files that transcript replay cannot restore. No configuration or migration is needed.

## Why This Change Was Made

The attempt owner reuses the existing deadline controller for the cloud first-event window and disarms it after native event projection or settlement. HTTP acknowledgments and SSE keepalives do not satisfy it; legitimate native work after progress keeps its existing deadlines. Startup failure retires the native attempt while leaving the host turn able to deliver the error. Attempt-start and binding logs now include a bounded native session ID.

This leaves quiet-stream completion/reconciliation work in #161357 and completed-result recovery in #161322 separate. Production growth is 35 lines for the missing liveness boundary, cleanup-safe failure, and diagnostics; no cache, polling loop, schema, or alternate session owner is added. The test-line allocation covers the focused startup boundary suite and its shared completion fixture.
```
