## What Problem This Solves

Fixes intermittent `openclaw agent --session-id <id>` failures immediately after a local Gateway becomes ready, while its session store is still initializing. Found during AOT/JIT differential QA and reproduced on both runtimes.

The CLI previously read local session metadata before dispatch even though the Gateway owns it. Local and remote calls now let the Gateway resolve the ID, including abort targeting. Stored IDs resume their existing session; unseen IDs use the Gateway's existing create-or-resume resolver. Other RPC callers retain existing-only behavior and session authorization.

An optional `createSessionIfMissing` field carries CLI intent. The Gateway advertises this capability, and the CLI checks it before dispatch. Older Gateways must be updated and restarted before this CLI's `--session-id` can be used; unsupported servers receive no turn. No protocol version bump or data migration is required. A small identity-helper extraction keeps the existing CLI module within its line-growth limit without changing scopes.

CI also exposed test readiness problems. The mobile drawer test now waits for drawer focus before Escape. The owners-picker test waits for its opening animation and verifies search focus before Escape. The skill-refresh integration test loads its server and embedded-agent subjects during collection, reducing time spent inside its unchanged 90-second behavioral deadline. These retain the original assertions and change no production UI behavior.

Release-note context: Gateway-backed CLI session IDs no longer depend on local session-store initialization; preserve named-session creation and check Gateway support before dispatch.
