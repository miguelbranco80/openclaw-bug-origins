## Fix PR #166846 description (by steipete, opened 2026-10-08T00:30:22Z)

```text
## What Problem This Solves

When the Gateway restarts while a parent session is waiting on subagents, the interrupted children are only reconciled by the subagent registry's periodic sweep, not at startup. The parent therefore waits for that maintenance pass before it learns its children were interrupted and can finish the task. In a stability-campaign crash test on main (parent launches two 20-second shell subagents, Gateway SIGKILLed while both run, then restarted), children were next active 46 s after the restarted Gateway became healthy, and the parent's final answer arrived at 93 s.

## User Impact

- After a crash or restart, parents learn about interrupted children right after startup instead of on the next maintenance tick. In the same crash test the children resumed at 27 s and the parent answered at 61 s, about a third faster end-to-end.
- A follow-up to an interrupted native child now says the missing or aborted tool output is an unknown outcome caused by the restart, so the child verifies effects before repeating an action instead of reporting "tool failed".
- Unchanged: interrupted children still settle through their normal completion path and are not relaunched automatically, the parent owns finishing the task, and recovery still pauses while the crash-loop breaker (#166238) is tripped.

## Why This Change Was Made

Registry activation already restored requester ownership but left interrupted runs to periodic maintenance. Activation now runs one interruption-only pass through the existing guarded recovery coordinator right after ownership is restored (`subagent-registry-restore.ts`). The coordinator is the single owner of the eligibility check, which moved out of the sweeper, so the startup pass and periodic sweeps share one gate. It respects the crash-loop pause and rechecks ownership after awaiting preparation. The periodic sweep remains the retry backstop. The restart-recovery note lives in one shared module (`restart-recovery-prompt.ts`), reused by main-session recovery and by `sessions_send` follow-ups to interrupted native children. It is distinct from the recovered-child failure diagnostics main already preserves (#166454). Prompt snapshot token delta is 0.
