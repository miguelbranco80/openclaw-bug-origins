## Fix PR #177991 description (by steipete, opened 2026-10-20T03:20:55Z)

```text
## What Problem This Solves

When Doctor rejects a newly installed package and a launcher cannot be restored, the update failure now names the affected launcher and its retained backup file, alongside the original I/O error. Operators can locate the recovery material instead of receiving only a generic rollback error and global-directory hint.

#177926 (`552a5d7419c9`) removed the post-restore verification that had supplied the launcher path. Its stated contract was “No intended user-visible change” and to keep “errors from every actual restore operation.” The backup still survives; the lost diagnostic context is restored at the actual launcher rollback operation, without bringing back the removed filesystem reads. The original exception remains the cause, and recovery status, authority checks, compensation order, and backup retention remain unchanged.

The repaired updater must drive the update; already-running older updater processes retain their current diagnostics. No migration or recovery-policy change is introduced.

The existing recovery regression now also checks that the exact backup path in the error is the retained file containing the old launcher bytes. The recovery guide documents that diagnostic.
```
