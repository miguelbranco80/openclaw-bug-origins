## What Problem This Solves

Fixes #155813.

A completion cancelled while OpenClaw prepares its transport host can still start a provider request. The PDF extraction and image-understanding fallbacks also check their retained resources before entering this asynchronous facade, leaving a window in which retired work can reach the provider.

## User Impact

Completions cancelled before dispatch now stop without invoking the provider. PDF and image completions whose prepared resources retire during transport setup stop at the same boundary. Current calls still dispatch once and return their existing result, and provider work already in flight keeps its existing cancellation and cleanup behavior.

Existing three-argument completion calls remain supported. The optional fourth currentness callback follows the existing `completeSimple` contract and is never included in provider options. There are no configuration, dependency, or persistence changes.

## Why This Change Was Made

`completeSimple` already revalidates its caller after awaiting transport initialization. `complete` now uses that same ordering: check currentness, check the existing abort signal, then invoke the selected runtime. The PDF tool and image-understanding fallback pass their existing retained-resource assertions into this check.

The repair stays at the dispatch owner and reuses the existing media resource lifecycles. It does not change model selection, provider fallback, or streaming dispatch.

The image case also verifies that resource retirement does not abort the request signal, so both guards are necessary.

The complete correction passes 74 cases across the completion facade, streaming, PDF resource/static-runtime/cancellation, and image resource/timeout suites on Blacksmith Testbox. These cover zero dispatch after cancellation or retirement, successful existing calls, unchanged provider options, timeout behavior, and retention of resources until admitted work settles. The selected core test-type graph also passes after keeping the image fixture's required numeric timeout and using its existing fake-clock pattern.
