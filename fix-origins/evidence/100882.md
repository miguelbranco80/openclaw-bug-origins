```text
## What Problem This Solves

Fixes QA capture module loading failures on supported older OpenClaw hosts that do not export async proxy capture operations. Related: #158848.

## User Impact

The capture modules can now load when the async capture exports are absent, then refuse required operations with upgrade guidance. Slack adapter creation refuses before loading its transport runtime, acquiring credentials, or contacting Slack. This fixes the capture-export boundary only: the current QA CLI still fails earlier on published 2026.9.6 because other required SDK imports, including `sqlite-runtime-testing`, are unavailable. Run QA from a matching current source checkout. No host compatibility floor changes or synchronous SQLite fallback are introduced.

## Why This Change Was Made

The QA plugin declares OpenClaw compatibility from 2026.9.4, but the published 2026.9.6 SDK lacks the two new async capture exports. Namespace access lets the existing capture owners validate the required capability when work is admitted, instead of failing ESM module linking. Existing accepted-operation draining, capture lease release, and Slack cleanup stay unchanged.

## Evidence

- `pnpm build` passed (16m26s cold build); fresh independent P2 autoreview was clean.
- The actual installed npm 2026.9.6 artifact reproduces both original missing-export errors. Candidate capture lifecycle and bundled Slack adapter load against that same unmodified SDK and reject the required operation with upgrade guidance, with no network calls or state files created.
- Current-source QA capture writes and reads a real SQLite event, rejects new work after admission closes, drains an accepted operation, and releases the lease. Main-thread SQLite methods were instrumented to throw during this proof.
- Focused capture and Slack adapter tests pass, including missing-capability refusal before credential acquisition and existing cancellation, uncertain-write retention, and cleanup coverage. The two changed test files take 3.41 seconds wall time together with one worker (15 tests; 2.21 seconds Vitest duration).
- Lab HTTP capture routes remain healthy for unrelated requests and report HTTP 500 for missing capture support; existing capture acquisition retry and Slack readback sibling coverage passed.

The published-host proof covers the changed capture boundaries. Whole QA plugin import on 2026.9.6 separately encounters the pre-existing missing `sqlite-runtime-testing` SDK subpath; this PR does not claim full-plugin compatibility. No live Slack messages were sent.
```
