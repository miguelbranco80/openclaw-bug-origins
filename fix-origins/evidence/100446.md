```text
Closes #160749

## What Problem This Solves

An agent on a CLI runtime (for example `claude-cli`) posts at the Slack channel root when it calls `message` without `threadId` during a turn that started in a thread.

## User Impact

Untargeted message-tool replies from Slack thread turns stay in the thread on CLI runtimes, as they already do on the embedded runtime. Explicit root sends and different channel targets keep their existing behavior. Standalone turns keep their current routing.

## Why This Change Was Made

The CLI candidate passed the raw inbound reply mode into the CLI run and MCP grant. On Slack channels that defaults to `"off"`. The embedded runtime instead asks the channel threading adapter, which upgrades a thread-originated turn to `replyToMode: "all"` and marks it `sameChannelThreadRequired`.

The CLI candidate now resolves the reply route through that same adapter, using the queued reply-route overlay used by the embedded path. When the adapter requires a same-channel thread, the CLI run takes its thread target and reply mode.

Other turns retain their existing CLI route facts. Adopting the standalone message's adapter anchor would change current-source reply classification, the separate embedded-side issue tracked in #142037.

No overlap with Pash/Sarah changes in the three changed files (checked current-main history).

Reported and implemented by @maxpuppet; the contributor commit is unchanged.
```
