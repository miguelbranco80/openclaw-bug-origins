## What Problem This Solves

Fixes: update status keeps showing an automatic update as applying after its handed-off run has already finished, including a preflight failure that leaves the original Gateway running.

## User Impact

Operators see that the update has finished instead of an indefinitely busy campaign. Active updates and unrelated campaigns remain intact. This does not repair the underlying update failure, change updater admission, or introduce a schema/configuration migration.

## Why This Change Was Made

The campaign owner now reconciles durable terminal outcomes before status responses and terminal watcher events. Both automatic admission and manual adoption retain the exact campaign run, so newer unrelated history cannot hide its completion. The owner rechecks campaign identity after asynchronous reads to preserve a replacement campaign.

This is backend lifecycle reconciliation, separate from the active-run presentation change in #155342; no UI rendering code changes.
