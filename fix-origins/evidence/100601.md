## Fix PR #167421 description (by LinzeShi, opened 2026-10-08T19:11:02Z)

```text
## What Problem This Solves

Fixes: PowerShell falls back to file completion when an option choice starts with a quote, such as `openclaw completion --shell 'f<Tab>`.

## User Impact

User impact: Tab completes quoted option values to valid choices, including unfinished single and double quotes. Regenerate an installed completion script to pick up the fix.

## Why This Change Was Made

PowerShell includes quotes in `wordToComplete`, so matching that text against choices like `fish` fails. Use the parser's literal value for string constants; expressions are not evaluated. Existing equals and short-option handling stays in place.

## Evidence

On Windows with PowerShell 7.6.5, generated the script with the production command registration and completion generator, loaded it into PowerShell, and called native `CommandCompletion.CompleteInput`:

| Input before Tab | Before | After |
| --- | --- | --- |
| `openclaw completion --shell 'f` | `.\fly.toml` | `fish` |
| `openclaw completion --shell "f` | `.\fly.toml` | `fish` |
| `openclaw completion --shell 'f'` | `.\fly.toml` | `fish` |

Applying the returned replacement spans produced `openclaw completion --shell fish` with no parse errors. Unquoted, quoted-equals, and attached-short-option controls also passed.

- Before the fix: the focused choice-completion tests had 3 expected failures and 3 passing controls.
- After: `pnpm test src/cli/completion-cli.test.ts --maxWorkers=1` passed (16 passed, 15 skipped; 14.17 s wall time). Other shell/platform paths were not exercised on this Windows host. The four added cases reuse the existing PowerShell fixture and took 24–31 ms each.
- Scoped format and lint checks, `pnpm tsgo:core`, and the canonical `core-test-config-cli` typecheck graph passed.
- Independent P0–P3 autoreview of this patch and supplied context: no findings.

CI timing is pending the first upstream run. The full CLI launcher build did not finish locally; the native proof above covers the production generator-to-PowerShell boundary, not a full CLI launch. The full repository suite was not run.
```
