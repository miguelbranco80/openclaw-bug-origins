Closes #199405

## What Problem This Solves

Fixes: inline Template review (`templates.drafts.review`) and publication (`templates.drafts.publish`) fail with `"Your ClawHub account needs a personal publisher handle."` (`clawhub_identity_required`) when ClawHub `/api/v1/whoami` returns a mixed-case GitHub OAuth `user.handle` (such as `MertBasar0`).

## User Impact

User impact: Control UI Template creators whose ClawHub / GitHub personal handle contains uppercase characters can now review and publish Templates inline under their canonical lowercase `@<handle>/<slug>` personal namespace without false `clawhub_identity_required` failures.

## Why This Change Was Made

ClawHub's `GET /api/v1/whoami` returns the GitHub-cased `user.handle` (for example `"MertBasar0"`), whereas ClawHub's publisher and package surfaces normalize personal handles to lowercase (`@mertbasar0/<slug>`, `ownerHandle: "mertbasar0"`, `https://clawhub.ai/mertbasar0/templates/<slug>`).

`personalPublisher` in `src/gateway/server-methods/templates-drafts.ts` is the sole `/api/v1/whoami` caller in `src/` (introduced in `f16e8bc092e7e`, carried through `d1c8d42588a4b` and `#196427`). Normalizing `result.user?.handle?.trim().toLowerCase()` at that producer boundary (net `0` production LOC: `+1/-1`) aligns review tokens, `prepareTemplateDraft`, upload `ownerHandle`, bound attempt status checks, and receipt URLs with ClawHub's canonical publisher handle.
