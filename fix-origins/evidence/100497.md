## What Problem This Solves

Fixes: every turn with Groq `qwen/qwen3.6-27b` fails with `400 reasoning_effort must be one of none or default` at the default thinking level, and the catalog advertises image input for it and for Cohere `north-mini-code-1-0`, which both reject images.

## User Impact

User impact: Groq Qwen 3.6 27B works at any thinking level (Off sends `none`; every other level sends `default`), its reasoning is returned as a separate thinking block instead of `<think>` text in the reply, and neither model is offered for image attachments it cannot accept.

## Why This Change Was Made

Both rows came from bulk catalog refreshes (#113681, #102489) without live capability checks. Groq's Qwen endpoint accepts only `none|default` for `reasoning_effort`, so the row now uses the same catalog-only effort map shape as the Cohere reasoning rows. With reasoning on, Groq inlines `<think>` text into `content` unless `reasoning_format` is set, so the Groq plugin's provider-owned payload hook requests `reasoning_format: "parsed"` for Qwen-family reasoning requests (not for effort `none`, not for GPT-OSS, which uses a different Groq contract); the existing completions stream already maps the separate reasoning field into a thinking block. Picker behavior is unchanged (Cohere-style aliased levels), so no shared picker code changes.
