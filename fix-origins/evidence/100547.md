## What Problem This Solves

Fixes Discord capability discovery initializing the optional Activity message sender even when no widget is requested or Activities is disabled.

## User Impact

Discord discovery does less unused startup work. Widget routing, persistence, delivery receipts, and rollback behavior remain unchanged. No configuration or migration is required.

## Why This Change Was Made

Import the sender inside the existing asynchronous presentation operation and its error/rollback boundary. A configured Discord provider also loads this graph through interactive handlers before provider readiness, so this does not eliminate all Discord startup cost or independently resolve Gateway plugin stalls.

The production change replaces one import and adds one dynamic import. The existing registration cases now protect the unused transport initialization boundary; the Linux benchmark records actual external plugin selection and process costs.
