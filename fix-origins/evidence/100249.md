## Fix PR #164207 description (by vincentkoc, opened 2026-10-03T09:15:24Z)

```text
## What Problem This Solves

Fixes: cancelling a queued chat turn can keep the session admission active and prevent the already-running predecessor from completing.

## User Impact

User impact: stopping a queued successor no longer leaves the current turn stuck until `agent.wait` times out.

## Why This Change Was Made

Queued chat custody retains a second reference to the source work admission. Cancellation released that queued reference but left the source reference owned by a dispatch that was itself waiting behind the predecessor. The cancellation owner now releases both references while leaving abort registration, terminal receipt publication, and detached dispatch finalization with their existing owners.

The regression fixture now uses the real `createChatSendWorkAdmission` reference counter instead of a release-only mock.

No changelog file was added because `CONTRIBUTING.md` reserves `CHANGELOG.md` and release-owned entries for the release workflow; this PR body and commit carry the release-note context.
```
