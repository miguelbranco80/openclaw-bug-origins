## What Problem This Solves

Codex sandbox directory listing corrupts valid filenames containing tabs or newlines, and recursive copying then fails with “file not found.”

## User Impact

Directory listing and recursive copy preserve these filenames and their contents. Public RPC fields, sandbox permissions, symlink classification, and error messages stay unchanged.

## Why This Change Was Made

The shell listing used tabs and newlines as separators even though both can appear in POSIX filenames. Its existing producer and parser now use NUL framing, which cannot occur in a basename. No configuration, persisted state, dependency, or public protocol changes are required.

## Evidence

- The added case failed against unchanged production through the actual WebSocket RPC and shell bridge, showing both corrupted listing and recursive-copy failure.
