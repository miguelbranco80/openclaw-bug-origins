## Fix PR #176852 description (by yinx65588-boop, opened 2026-10-19T03:12:03Z)

```text
Closes #123557.

## What Problem This Solves

Fresh ACP sessions accepted a project `cwd`, but tools ran in the default agent workspace and could edit the wrong project.

## User Impact

New bridge-owned sessions execute tools in their requested absolute directory. Selecting an existing session key or label preserves that session's Gateway-owned directory. Existing Gateway directory authorization applies; no configuration or protocol changes.

## Why This Change Was Made

Create fresh sessions through the existing `sessions.create` owner before storing the bridge session. That persists the execution directory without a second per-prompt cwd mechanism. Fresh keys need no reset before creation; existing session adoption and reset remain on their existing path.

## Evidence

Built current main `853171d64cd64d9d447b5b3b27ba924da11d0a55` and the candidate in isolated Linux containers. Drove the shipped ACP CLI over stdio (`initialize`, `session/new`, `session/prompt`) against a real Gateway and a local OpenAI-compatible HTTP provider emitting an ordinary built-in `exec` call without a workdir override. Created requested/existing directories through the shipped agent command and exec tool; created the adoption control through `sessions.create`.

Whole-change deltas against merge base: production +16/-4 (net +12), tests +71/-0, docs +7/-0. No additional state owner or per-prompt override was introduced.

Merge danger: two-way door. Reverting restores prior fresh-session behavior; this uses existing session fields and requires no migration. Blast radius is fresh editor ACP sessions; selected existing sessions keep their current routing.
