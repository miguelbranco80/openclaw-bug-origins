## Fix PR #152120 description (by steipete, opened 2026-09-18T19:53:15Z)

```text
Related: #151691, #151325; series B of the stale-service-definition repair, after #151777

## What Problem This Solves

Fixes upgrades leaving older managed Gateway service definitions stale, including the Discord report of missing systemd `KillMode=mixed` on 2026.9.4 and the Windows task with zero crash-restart retries in #151325.

## User Impact

After package activation, update repairs recognized stale definitions through the existing platform installer, backs up the previous files first, and records the changed keys in the update outcome, status, and bounded report. Operator edits and unknown or foreign definitions stay intact, with warnings that name the affected keys. Inspection or repair hiccups remain warnings; recovery refuses replacement when it cannot verify the retained bytes or current owner.

When published 2026.9.4 owns rollback, it restores the old package and uses that release’s install/restart flow, regenerating its previous definition with that release’s preservation behavior. Candidate-owned rollback restores the captured definition files byte for byte and restarts the verified previous runtime.

## Why This Change Was Made

The existing service audit remains the drift owner, now comparing the actual prepared install plan for settings the rewrite would discard. The existing systemd, launchd, and Scheduled Task installers remain the writers. Their publication hooks bind the audit to captured files, verify the installer’s output, and retain a private backup receipt for rollback; later operator changes prevent replacement. Warning projection uses the existing update ledger and report converter. Install path discovery recognizes the public shim and direct updater entrypoint of the same package, preserving PATH order without admitting a foreign installation.

B also retires updater-only Doctor writes and ensures updater restart retries preserve the definition, so neither can bypass the backup transaction. Standalone Doctor repair and the series documentation remain Part C. No new options, environment variables, dependencies, or database schema changes are included.

Net production growth is 1,221 lines (+2,047/−826), within B’s 1,225-line umbrella share: backup/receipt/reconciliation adds 676 lines, audit adds 355, native installers and shared installation identity add 241, update integration adds 121, and removing updater-only Doctor writers saves 172. Tests/support add 2,287 net lines (+3,054/−767). Round four is production +16/−19 (net −3) and tests +131/−0. Existing receipt compensation absorbs all transactional restoration; removing redundant installer recovery plumbing pays for the explicit delegation. No assertions, suppressions, or baselines were removed to fit the change.

The atomic-publication follow-up fixes a failed-write window in the Windows launcher and launchd environment/wrapper installers: truncating the live file before recording publication could leave recovery refusing an empty or partial launcher. Those installers now use the existing atomic-file primitive through the shared service publication hook. Systemd retains its existing atomic writer. Each replacement is prepared beside the target and renamed only after the backup receipt records the prepared file identity; publication is acknowledged after rename. After checkpoint I/O, the same backup owner revalidates live files and native inventory before publication without discarding prepared evidence. Recovery accepts unchanged original files or the exact prepared publication, while refusing later operator replacements, including identical bytes on another inode.

Windows uses Node’s native rename-over operation. If an open launcher prevents replacement (`EPERM`, `EBUSY`, or `EEXIST`), the old file stays intact and existing warning/compensation handling runs; there is no unlink/copy fallback or retry loop. The retained private receipt is a backup artifact replayable by the existing restore API, not a new whole-updater automatic-resume protocol.

Scheduled Task XML replacement now checkpoints its intended XML before `/Create /F`, both during installation and rollback. Recovery uses the existing task audit to recognize Scheduler’s SID/default normalization, records whether it found the previous or prepared policy, and rejects foreign policy before changing launchers. The systemd restore path also repeats its guarded `daemon-reload` when a prior attempt restored the unit but stopped before refreshing the manager; it reloads before removing old inputs.
