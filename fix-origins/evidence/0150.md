## Fix PR #197165 description (by lastguru-net, opened 2026-11-11T09:57:10Z)

```text
Related: #189522

## What Problem This Solves

Conversation participation/delivery guidance and current tool bindings have no subsection labels, so generated instructions leave them under the preceding Message Context or optional Delivery Format heading.

## User Impact

Generated prompts distinguish metadata, formatting, conversation behavior and tool availability. This is a prompt-structure correction, not a new rule or a change to routing, tool permissions or configuration; no migration is required. No improvement in model quality or instruction compliance is claimed.

## Why This Change Was Made

#189522 made the current conversation-instructions block explicit. Its contents still mix distinct responsibilities: trusted metadata has `### Message Context`, and a channel can add `### Delivery Format`, but neither the chat guidance nor the binding list starts a peer section. When the formatting contract is present, unrelated conversation guidance appears to continue that section.

Add `### Conversation Behavior` before the existing shared direct/group/channel guidance, and `### Tool Bindings` before the Codex wrapper's existing binding list. Group activation remains with conversation behavior. Keep Message Context because it identifies the metadata/trust boundary; deleting it would not resolve the optional Delivery Format inconsistency.

All existing instruction prose, section order, outer delimiters and supersession wording remain unchanged, including the warning that accepted tool declarations do not grant execution. Unknown chat types still produce no empty behavior section.

```text
Message Context
Delivery Format       (only when supplied by the channel)
Conversation Behavior (when source-conversation guidance exists)
Tool Bindings
```
