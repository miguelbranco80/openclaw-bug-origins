## Fix PR #171760 description (by roboclaw-bot, opened 2026-10-14T05:02:49Z)

```text
## What Problem This Solves

Fixes: long-running agent turns stop recovering from intermittent rate limits even when successful model responses occurred between failures. The final error can misleadingly show only a short provider retry hint.

## User Impact

Agent turns receive a fresh retry budget after a completed successful model response. Consecutive failures remain bounded, and terminal rate-limit errors explain actual automatic retry exhaustion. No new configuration or migration is required.

## Why This Change Was Made

The failover controller resets the consecutive-outage retry count, backoff, and window only on completed model responses; partial streams and tool activity alone do not replenish them. The outer recovery guard follows the same progress signal. Existing per-attempt timeouts, caller deadlines, cancellation, output-limit continuation caps, and fallback routing remain intact.

Controller-recorded exhaustion now travels through error, payload, fallback, and final-reply paths without replacing raw provider diagnostics. Progressing turns can exceed a single attempt budget in aggregate; no competing whole-turn timer is introduced.
```
