## Fix PR #169265 description (by SanderHelgesen, opened 2026-10-11T18:14:38Z)

```text
Closes #169264

## What Problem This Solves

Fixes: Codex turns drop from Ultrafast to Fast after the first message in a conversation when signed in with ChatGPT.

## User Impact

User impact: people who select Ultrafast now get it on every turn their account supports, not only the first. Other providers and accounts without Ultrafast are unchanged.

## Why This Change Was Made

For ChatGPT sign-in, OpenClaw stores conversations without a provider on purpose. On resumed and follow-up turns, the Ultrafast check read that empty provider as "not OpenAI" and skipped itself. The check now falls back to the run's own provider, the same fallback this file already uses for model-call reporting. The account's catalog still decides whether Ultrafast is sent.

Found and diagnosed with Claude Opus 5.5 (Claude Code): our live Codex logs showed only the first turn of each conversation on Ultrafast. We traced that to this check and confirmed that Codex itself treats a missing provider as `openai` (`codex-rs/core/src/config/mod.rs:3816-3819`, rust-v0.160.0).

Accepted edge case: if a user-home Codex config switches the native provider away from OpenAI while the OpenClaw route is still `openai`, follow-up turns now run the catalog check too. Ultrafast is still sent only if that catalog lists it for the model.
