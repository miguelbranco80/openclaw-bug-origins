## Fix PR #170094 description (by steipete, opened 2026-10-12T18:30:40Z)

```text
Closes #162422

## What Problem This Solves

Valid OpenAI-compatible API uploads that take more than 30 seconds receive HTTP 408 before they can reach inference.

## User Impact

Chat Completions, Responses, and embeddings requests now have 60 seconds to finish uploading their body. Uploads exceeding that deadline still receive HTTP 408. Webhook defaults remain 30 seconds, and existing byte limits are unchanged.

## Why This Change Was Made

The shared compatibility endpoint owner supplies the deadline through the existing JSON readers. The global body-reader default and post-upload authorization revalidation stay intact. A redundant connection-error mapping is removed because the body reader already supplies the same message.

Thanks to @boeingchoco for the report and reproduction.

## Evidence

- The 45-second regression fails on the original endpoint with HTTP 408. The fixed endpoint accepts it; uploads beyond 60 seconds and the unchanged 30-second default still return 408.
- Three final upload cases pass in 214 ms of case execution (345.65 seconds cold wrapper wall time). Another 34 adjacent HTTP cases pass. The initial combined run took 452.62 seconds and exposed a test-transport half-close issue; the corrected upload fixture was rerun successfully.
- The regression uses a real Node HTTP parser and JSON/body-limit readers over an in-memory connection; only authorization is stubbed. No real timer waits or Gateway boots are added to the tests.
- Production: +6/-6 lines. Tests: +89/-1. Docs: +5/-1. No configuration or prompt changes.

Live proof used `pnpm openclaw --profile triage-c gateway run --port 19592 --bind loopback` with isolated state and native Ollama `qwen3:4b` behind a loopback forwarding proxy that required the configured synthetic authorization and provider header. Both requests reached authenticated inference and returned `UPLOAD_MODEL_OK`.

| 64 KiB/s upload (about 48 s to send) | HTTP 408 at 30.011 s; no inference | HTTP 200; 59.171 s including inference; all 3,145,848 bytes sent |
```
