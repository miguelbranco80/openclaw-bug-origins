## Fix message body

```text
fix(telegram): let ACP final delivery recover buffered progress answers

In Telegram's progress streaming mode, a buffered ACP answer block was reported as already shown even though only the progress draft held it. ACP then skipped its existing final-delivery recovery, so the bound Telegram topic never received the reply, which appeared only in the session transcript. A buffered progress block is no longer reported as shown, so the existing recovery delivers the answer once. Partial and block streaming and non-ACP replies are unchanged. No text changes.

Evidence: the Telegram Test Server through the userbot runner with a Convex lease, a built Gateway in node:24.22.1, a forum topic bound with /acp spawn standin --mode persistent --thread here and a stand-in ACP agent answering with a unique marker, two runs each. In progress mode, main put the marker only in the ACP transcript and the topic received just "Session ids resolved."; with this change the marker arrives once in the topic as one message with no edits. Partial and block modes deliver the marker once on both, partial mode does not resend previewed text, and a plain non-ACP reply arrives once on every run. A progress row in the existing chunk test fails on main, at net 0 test lines. Details: https://github.com/openclaw/openclaw/pull/197191#issuecomment-6815984475.

Closes #195899. Thanks @bach205.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```

## Fix PR #197191 description (by bach205, opened 2026-11-11T11:03:44Z)

```text
Closes #195899

## What Problem This Solves

Fixes missing replies in Telegram topics bound to ACP sessions when ACP uses live delivery and Telegram uses progress mode.

## User Impact

Users receive ACP replies in the originating Telegram topic instead of having to read them in the session transcript.

## Why This Change Was Made

Telegram buffers answer blocks in progress mode but incorrectly reports them as already visible. ACP then skips its existing final-delivery recovery, leaving the buffered answer unsent.

Report these buffered blocks as non-visible so the existing recovery path can deliver them. Keep the visible result for blocks whose content already exists in a partial preview.

Adds a regression test covering buffered-block delivery receipts and subsequent final delivery.
```
