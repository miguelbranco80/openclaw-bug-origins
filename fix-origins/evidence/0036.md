Fixes #200612

## What Problem This Solves

When the available model list is empty, opening the model control shows a large blank picker with a search field instead of taking the user to setup. This also happens on a clean installation with automatic account selection, even when no provider or account has been configured.

## User Impact

User impact: after the model list finishes loading and is confirmed empty, users can select **Set up a model** directly from the composer to open model-provider setup.

Loading, error, offline, restricted, locked, and pending-provider states retain their existing behavior. Personal/shared account recovery and other session targets keep the picker. No Gateway changes, configuration changes, or migrations are required.

## Why This Change Was Made

Reuse the existing setup action and translated label rather than adding another setup flow. The shared model control chooses between the direct button and the picker in both existing chats and the new-session composer.

The earlier revision incorrectly treated the presence of any account section as a reason to retain the picker. The Gateway returns automatic account selection even before the first account is configured. The setup condition now accepts that selection while retaining the picker for a specifically selected personal or shared account.

The new-session page already shows its full-page setup action when no default model exists. The composer regression therefore also covers an empty available-model list with a configured default, where the shared picker is actually mounted.
