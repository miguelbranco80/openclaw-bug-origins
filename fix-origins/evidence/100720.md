## What Problem This Solves

An idle Windows Gateway can spend roughly 14 minutes admitting a large native plugin, while the catalog worker abandons it at 180 seconds and captures the same package again. Overlapping hardlink companion directories also repeat member verification. Removing that deadline alone leaves permanently blocked admission hanging without a diagnostic.

## User Impact

An unchanged verified native package is admitted once and reused across catalog refreshes. Slow admission can finish while member verification advances. After 180 seconds without progress, the Gateway records a failure naming the plugin and native reference verification stage, clears pending catalog status, and retains available model facts. That inventory does not automatically restart capture. Reload the plugin or restart the Gateway after addressing the cause to retry.

Parent probes, queued requests, and provider discovery remain bounded. No new configuration, environment switches, CLI options, dependencies, schema changes, or migration are required. Existing integrity checks and cleanup custody remain intact.

## Why This Change Was Made

Admission belongs to the plugin generation; its existing readiness exchange starts the separate provider-discovery deadline only after preparation. Verified package identities and worker generations remain prepared facts. Within a capture, successful member checks are shared across overlapping companion-directory placements; new placements, namespaces, explicit host selection, recovery, and changed or damaged bytes still require their existing checks.

The watchdog is now minimal: the existing native-reference verifier increments one counter after each verified member. The worker forwards it through the existing task message channel, throttled to once per second while a plugin remains active. The parent reuses its one timer as the 180-second idle window. Plugin changes are forwarded immediately for accurate stall attribution, but only an increasing counter renews that window.

Deleted the separate admission-watchdog, progress, and auth modules. Removed the source-file, hashing, namespace, artifact, inspection-worker, compiler-registration, and full-catalog plumbing from the rejected revision. No separate auth-failure handler remains. The existing worker transport gained a one-way notification because its request/reply exchange permits only one outstanding request and its consumption receipt transfers input custody; neither is a progress channel. This addition is net 9 production lines and does not settle tasks or renew deadlines itself.

Two small pieces remain because the stalled regression fails without them: always invoking the existing catalog failure callback also reports a cold catalog failure; an inventory-level terminal decision prevents a later parent-auth failure from recovering the stalled pool. The catalog mismatch error moved into the existing error module, and repeated completion predicates were consolidated to satisfy the existing line caps without suppressions or baseline changes.

This preserves the original admission fix and leaves the diagnostic probe in #166388 unchanged. Thanks to @martinderm for isolating the admission/deadline loop and @swampgorilla for the original report and diagnostics.
