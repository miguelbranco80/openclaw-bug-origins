## Fix PR #188414 description (by steipete, opened 2026-10-30T14:12:06Z)

```text
## What Problem This Solves

GitHub publication options can spend their five-second request budget on PR display metadata that recovery does not use. The publication projection already returns state-only candidates, but the shared branch loader first fetched diff statistics and check rollups for up to three open PRs. Repeated recovery reads also fetched the same immutable commit/tree coverage proof again.

## User Impact

Opening GitHub publication options can reconcile previous publication attempts without waiting for unrelated PR statistics or checks. Current permissions, stale display fallback, and visible retryable failures remain intact.

## Why This Change Was Made

The existing branch-cache owner now publishes list facts first and lazily shares optional metadata enrichment among display readers. Publication reads neither start nor await that enrichment. The display cap, all publication candidates, quota backoff, stale display fallback, and current-access checks remain owned by the same code. Pending metadata sharing now matches the prepared state/head signature, and replacement entries prevent a late older response from overwriting newer metadata.

Successful coverage proofs use the existing bounded retained-cache primitive (100 entries), keyed by credential scope, repository API root, PR head, accepted tree and source commit, with 90-second freshness. Each read still checks live authority and current PR candidates. Failures and pending credentialed requests are not cached. Existing visible, retryable options timeouts remain unchanged.

Runtime production LOC: **+58** across the three production modules; the standalone benchmark adds 206 developer-tool lines (**+264 non-test/non-doc lines total**). The growth retains the existing display/quota contract while separating its optional work, plus the bounded immutable-proof cache; there is no parallel publication loader or weaker authorization path. The benchmark is a separate developer tool with usage in its header.
```
