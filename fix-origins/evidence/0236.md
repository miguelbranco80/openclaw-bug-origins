## What Problem This Solves

A large retired-worktree deletion can keep generating filesystem metadata work for several minutes and delay chat transcript writes even below the 40 GiB reservation watermark added in #202563. One reported deletion lasted 392 seconds with a 6.34-second btrfs commit and multi-second foreground writer delays.

Related: #202197, #202563, #202204.

## User Impact

User impact: optional Linux cleanup yields sooner when filesystem commits slow down and splits large trees into shorter passes, giving foreground writers quiet intervals. Reclaiming a large tree takes longer by design. Retention, lossless removal and recovery snapshots are unchanged; no configuration or schema migration is required. This is a mitigation, not a guarantee of shared-filesystem transaction latency.

## Why This Change Was Made

Reuse the existing pressure probe: removal reacts to an in-progress or newly observed btrfs commit taking at least 500 ms. Linux deletion yields at pressure or 30 seconds elapsed. The existing serialized deletion owner keeps the queue quiet for 30 seconds, then resumes unfinished files behind already queued siblings. Its pending-path protection spans cooldowns, so orphan GC cannot take over an active removal. Files left in the retired directory provide restart progress; there is no new cursor store or scan cache.

The 40/20 GiB reservation policy remains; resumed passes start below the low watermark. Historical completed commit samples do not repeatedly block a restarted pass. Non-Linux platforms retain ordinary batch pacing. A single filesystem call can overshoot the pass budget, and each child retains its separate 30-minute timeout. Sustained external pressure can postpone reclamation indefinitely; failed or interrupted cleanup retains the existing recovery path.

We use observed commit statistics and quiet intervals instead of forcing `syncfs` on the shared filesystem. A forced sync would itself join the shared transaction; apparent file bytes are not a reliable delayed-reference estimate.

Also remove the two unused spawn-test fixtures left by #202522, along with their unused imports. Existing active fixture behavior and tests remain.

+    // Ten percent partial stalls or one percent whole-host stalls warrant a quiet tick.
+    let pressured =
+      Number(/^some avg10=([\d.]+)/m.exec(psi)?.[1]) >= 10 ||
+      Number(/^full avg10=([\d.]+)/m.exec(psi)?.[1]) >= 1;
+    const next = new Map<string, { commits: number; totalMs: number }>();
+    const filesystems = await fs.readdir("/sys/fs/btrfs").catch(() => []);
+    for (const id of filesystems) {
+      if (!/^[\da-f-]{36}$/i.test(id)) {
+        continue;
+      }
+      const stats = await readKernelCounter(`/sys/fs/btrfs/${id}/commit_stats`);
+      const value = (key: string) => Number(new RegExp(`^${key} (\\d+)$`, "m").exec(stats)?.[1]);
+      const commits = value("commits");
+      const totalMs = value("total_commit_ms");
+      if (!Number.isFinite(commits) || !Number.isFinite(totalMs)) {
+        continue;
+      }
+      const before = previous.get(id);
+      const fresh = !before || commits !== before.commits || totalMs !== before.totalMs;
+      // Lifetime max and unchanged last-commit values must never hold cleanup forever.
+      pressured ||= value("cur_commit_ms") >= SLOW_COMMIT_MS;
+      if (fresh) {
+        pressured ||= value("last_commit_ms") >= SLOW_COMMIT_MS;
+        if (before && commits > before.commits && totalMs >= before.totalMs) {
+          pressured ||= (totalMs - before.totalMs) / (commits - before.commits) >= SLOW_COMMIT_MS;
+        }
+      }
+      next.set(id, { commits, totalMs });
+    }
+    previous = next;
+    return pressured;
+  };
