## Fix PR #157701 description (by roboclaw-bot, opened 2026-09-24T23:31:16Z)

```text
Related: #157409

## What Problem This Solves

Android setup shows a long permission list, and a permanently denied permission can leave users tapping a row without a way to recover.

## User Impact

Setup shows four optional choices: Notifications, Microphone, Camera, and Location. Other existing permissions stay available under **Additional features**. Users can continue without granting access. Denied requests offer the existing Android Settings recovery dialog, and rows refresh when users return.

Existing camera/location opt-in, applying choices on Continue, and Gateway reapproval remain unchanged. This deliberately covers setup and denial recovery only—not automatic first-use prompts or background permission notifications.

## Why This Change Was Made

Keep the existing setup models and Android launcher; connect its denial callback to the existing `PermissionRequester` recovery method. The earlier notification/agent-attribution system and all `SecurePrefs`, runtime, dispatcher, SMS, and protocol changes are removed from the PR.

The final diff is **6 files, +199/−27 lines**: two production files (+46/−14), two test files, one README line, and the generated source-string inventory. No new storage, migration, dependencies, or permission policy.
```
