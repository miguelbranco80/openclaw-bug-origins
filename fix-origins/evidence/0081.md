## What problem this solves

After a Gateway restart, OpenClaw stops running subagents and resumes only their ordinary root session, which then re-instructs its children (#185730, `docs/gateway/restart-recovery.md`). Root discovery (`resolveRootSubagentRequester`) walked up the ancestry only while the session key looked like a hidden subagent (`agent:…:subagent:…`). A VISIBLE spawned child (a dashboard session created by `sessions_spawn` with `visible: true`) stopped the walk. Its restart marker was then rejected because it is a spawned child, and the real root was never marked.

Seen on a live Gateway: a root chat → visible coordinator → hidden workers tree stalled after a restart and needed a human message 25 minutes later.

## Change

- Follow RECORDED native spawn ownership up to the ordinary root: the session's `spawnedBy`, or `createdVia: "spawn"` with parent, controller or requester fallback. The walk now covers visible and hidden native children alike, and keeps the cycle guard, the recorded child-authority (owner) check and the session-incarnation match.
- `sessions_send` also registers requester edges, but it creates no child and carries no spawn metadata. Those sessions stay independent roots, which keeps the case #188402 narrowed the walk for: an ordinary conversation must not inherit an excluded cron requester. Run records cannot tell the two edges apart, so the walk reads the session's creation metadata in a worker, once per ancestry step. A session without a registry entry stops before any read.
- Selection snapshots live owners before those reads, keeps the live-root-before-parked precedence, and still runs inside the existing shutdown persistence budget.
- `docs/tools/subagents/operations.md` notes that visible spawned children resolve to their root.

## Evidence

Proof tier: source (`ocx test`).

- New `session-restart-resume.ancestry.test.ts`, with two cases: a hidden worker under a visible spawned coordinator, and a visible worker directly under the root. Both fail on unchanged `main` (`resumeAfterRestart` undefined on the root) and pass with the fix, through a real shutdown marker into the startup enqueue.
- Frozen head: 11 files, 110 tests pass, including the existing cron-ownership protection.
- `session-restart-resume.workspace.test.ts` timed out under heavy host load (load above 70). An instrumented run on the fix then passed in 27 s with no root-resolver calls or ancestry reads, and its close took 244 ms. It does not touch the changed path.
