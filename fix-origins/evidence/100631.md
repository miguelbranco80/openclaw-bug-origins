```text
Keep pending native page requests separate from bounded completed results so query pressure cannot start duplicate work or interrupt stale delivery. Preserve cache freshness, failed-refresh retries, per-config isolation, and completed-result capacity.
```

## Fix PR #148513 description (by steipete, opened 2026-09-14T20:11:34Z)

```text
Related: #127743

## What Problem This Solves

Fixes duplicate native Codex catalog reads and blocked stale-page delivery when other queries evict an unfinished page from the cache.

## User Impact

Overlapping refreshes keep sharing the active native read, and callers can keep using its last successful page while it refreshes.

## Why This Change Was Made

Pending reads now own their lifetime separately from completed-result retention. Success and failure both release that ownership; completed results retain the existing 32-entry limit and 32-second freshness window. Failed refreshes still retry on the next poll, including after a wall-clock correction.

## Evidence

- Four regression cases failed on the original owner: cold reads dispatched twice, and stale followers lost immediate delivery under query pressure.
- All 79 focused cache, listing and provenance tests pass on the final commit, including completed-cache capacity/recency, config replacement, failure cleanup and clock correction. The full changed-file gate and independent review pass.
- Native metadata proof on Blacksmith Testbox with Codex 0.154.0 passed: 71 list calls, real persistent fork creation over synthetic history, both cold and stale pressure phases, the unchanged 32-second TTL, and clean process closure. Complete export and independent result review passed.

The native test deliberately delays delivery of real replies while 32 other queries complete. It proves ownership under that controlled interleaving; it is candidate-only proof on four synthetic/native-created rows, not representative production latency or a CPU profile.

This repairs pending-work ownership. It does not establish the cause of every slow native catalog scan or change the broader Gateway catalog-expiry behavior described in the related issue.
```
