```text
## What Problem This Solves

Fixes #174447.

A managed installed helper could receive a trusted execution binding after synchronization copied it into a read-only sandbox directory, even when the guest could modify its original source. A managed installer symlink into the guest workspace retained its installed-source provenance and passed the copied-directory check.

## User Impact

Protected installed helpers now remain unavailable when their original package directory is writable through the guest workspace or a bind mount. Legitimate installer symlinks to host-only or read-only locations continue to qualify. An affected installation needs to move to a host-only or read-only location; no new setting or migration is introduced.

The selected installation, model authority, backend read-only requirement, and copied-directory protection remain unchanged. This correction does not add personal or project skill eligibility.

## Why This Change Was Made

The existing mount owner already resolves canonical host aliases and container overlay precedence for the copied package. Admission now supplies the selected original package directory to that same check. It keeps the package directory separate from terminal `SKILL.md` symlink resolution, so protecting an instruction-file child cannot hide a writable scripts sibling.

The repair stays at installed-helper admission. Skill discovery and synchronization continue to support legitimate installation symlinks and ordinary workspace skills.

## Evidence

The regression uses actual managed skill discovery, selected-source identity, synchronization, sandbox remapping, mount resolution, and the bundled plugin factory. On unmodified b646675ff84c03d90196d73952436ec87c2c40d0, the original directory resolved writable but the expected empty installed roots failed with the protected copy populated.

The same negative case reproduced at the final checked target 2a03d0aa803ea98332208bdc4e682004426df4e7. The six-case fixture passed on this PR. It covers writable workspace originals, a read-only instruction child inside a writable package, writable aliases and scripts-subtree mounts, and preserved host-only/read-only installer symlinks. Existing copied-package alias, overlay, tmpfs, and unsupported-backend controls remain in the affected test selection.

Changed-file formatting/lint and the selected production/test type checks passed. The five affected test files finished with 52 passes and four existing platform skips (three Windows cases and one macOS case) in 36.9 seconds of joined test execution. The two-file agent shard containing the new fixture took 34.0 seconds, mostly initial transformation; hosted CI completed successfully in 684 seconds of elapsed workflow time.

This is filesystem and capability-boundary proof. It does not claim a live container escape or credential exposure. [Hosted CI](https://github.com/openclaw/openclaw/actions/runs/38937567769) passed, and independent engineering and adversarial review found no actionable issues.
```
