```text
## What Problem This Solves

Fixes: Code Mode can keep rediscovering the same tools or resuming unchanged work because changing execution titles, telemetry counters, and bridge IDs disguise repeated activity as progress.

## User Impact

With loop detection enabled, repeated equivalent Code Mode activity reaches the existing warning/block/recovery path. Real output, returned data, errors, and changes to pending operations remain distinguishable. Receipts still show their original counters and IDs.

**Scope:** this does not classify arbitrary equivalent JavaScript rewrites, add a scheduler, alter notification settings, or make command processes survive a Gateway restart. No configuration migration, permission relaxation, or production deployment.

## Why This Change Was Made

The detector compared Code Mode bookkeeping as though it were task output. Code Mode now supplies a private, immutable comparison snapshot; suspended work records the actual operation and arguments instead of a fresh bridge ID. Execution titles remain display metadata rather than action identity. Guest-owned fields with the same names retain their meaning. Automatically retained results are compared using the original guest value, not their fresh reference IDs.

Requested by @VACInc.
```
