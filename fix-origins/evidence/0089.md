## Fix PR #203259 description (by roboclaw-bot, opened 2026-11-21T19:33:26Z)

```text
## What Problem This Solves

On New Session, tapping project search on a phone moved the text left of the **Recent** heading and shrank the field. In the redesigned device-folder picker, the **Absolute path on device** label started left of the path it described on both phone and desktop.

## User Impact

The search text stays aligned when you tap and type, and the field stays 40 px tall on phones. The device-path label now lines up with the entered path without moving or resizing the input. Selecting a folder still collapses it to the compact project control; reopening it preserves the path.

## Why This Change Was Made

The picker panel sets the field spacing in every input state. The device-path label uses the same text inset as its input. Both fixes belong to the current picker; neither restores the retired form or changes access to the folder browser.

## Evidence

Paired production builds: main `e6b0b9bda569` and candidate `3f7d26a69d15` (identical tree to published `cf379a3d649d`). Both were exercised in Chromium with the same synthetic Gateway, devices, and projects. No real device was browsed, project registered, or session created. Physical-device keyboards and cloud placement were not tested.

### Device folder: writer without admin access

The first dark pixel of the label moved **x=44 → 52** on phone and **x=624 → 632** on desktop, matching the path at both widths. The CSS text origins likewise align at x=51 and x=631. The field stayed **304 × 40** at 390 × 844 and **304 × 32** at 1440 × 900. The writer entered an absolute path, pressed Enter, reopened the compact selection, and returned with Back without a directory listing.

### Project search: touch focus in onboarding

At 390 × 844, the first dark pixel of both placeholder and typed query moved **x=44 → 52**, matching **Recent**. The focused field height changed **24.8 → 40 px**. At 1440 × 900 field and heading stayed at x=475. Typing filtered the project options; the sibling device search was also exercised.

Both focused regressions failed by 8 px on the pinned main build. All seven bundled device-folder and project-access tests passed after the fix. UI and UI-test typechecks, scoped formatting, CSS lint, and TypeScript lint passed. Local autoreview could not start its reviewer in this checkout. The native comparison on the two production builds passed: total CSS fell from 1,781,614 to 1,781,379 raw bytes (−235) and from 344,799 to 344,786 gzip bytes (−13). Both builds remain above the fixed total CSS ceilings.

**Historical evidence only.** [#203269](https://github.com/openclaw/openclaw/pull/203269) retired the persistent stacked label, field and hint. The original [before](https://github.com/user-attachments/assets/9dd1134e-3e83-42c8-a899-f0306dd2c7a4) / [after](https://github.com/user-attachments/assets/5d557bf8-1672-437d-9889-b9eb4689fb18) and [annotated before](https://github.com/user-attachments/assets/52e1d16b-9e2a-4cb3-9b5d-cd163583effc) / [after](https://github.com/user-attachments/assets/3cceea9f-ba03-4a17-99e3-c853142b43e1) document a 7 px offset in that old layout, not the current interface.
```
