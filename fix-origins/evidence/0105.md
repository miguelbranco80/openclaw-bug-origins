## Fix message body

```text
fix(memory): fire standing intents on terms inside unspaced CJK text

Standing intents are documented to fire when any trigger term appears in the turn, but terms inside Chinese, Japanese or Korean text written without spaces (for example 会议 in a Chinese sentence) were never matched, so the reminder was not injected. Matching now finds these terms inside unspaced CJK text. Creator, channel, sender, expiry and cooldown rules, the candidate and injection limits, and the injected text are unchanged.

Evidence: built Gateway with standing intents created through the shipped path and a local provider that captures requests. An anywhere-scoped CJK intent was not injected on main twice and was injected with this change twice. English intents fired on both refs, including across conversations, and sender-mismatch and cooldown controls were still enforced. The proof uses anywhere scope because conversation-scoped intents are separately broken (#192619). Details: https://github.com/openclaw/openclaw/pull/191603#issuecomment-6624601828.

Thanks @SunnyShu0925.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```

## Fix PR #191603 description (by SunnyShu0925, opened 2026-11-03T02:01:36Z)

```text
## What problem this solves

An intent armed with `会议` does not fire for `明天上午的会议改到下午三点`. SQLite FTS tokenizes the unspaced sentence as a single word, so neither the indexed candidate query nor whole-word comparison reaches its interior.

## Change

Keep indexed selection first. For turns containing Han, Hiragana, Katakana or Hangul, scan the same authorized scoped rows without the index afterward. Both passes share the existing 256-candidate and three-injection caps. Reuse one immutable scoped query rather than rebuilding scope predicates for each pass.

CJK terms match literally; other terms retain whole-word equality. Comparison buffers are lowercased then NFC-normalized, without rewriting descriptions or injected text. Creator identity, channel/sender scopes, expiry, cooldown and fire budgets remain authoritative. No schema, SDK export or new configuration.

Thanks to @SunnyShu0925 for the report and original fix; their commit is preserved.

## Evidence

Built Gateway before/after [recording-provider proof](https://github.com/openclaw/openclaw/pull/191603#issuecomment-6624601828): main twice omits the CJK reminder, candidate twice injects it. English anywhere intents fire twice on both; sender mismatch and cooldown remain enforced, including legitimate cross-conversation anywhere delivery. This uses the shipped QA channel and actual intent tool actions, not internal matcher calls. Conversation scoping is independently broken in that path (#192619), so the proof explicitly uses anywhere scope. The provider is a local protocol fixture, not a live model.

The real-database standing-intent suite passes all 20 cases on the candidate. The same suite on frozen main fails the four CJK/canonical-equivalence regressions. Changed-file formatting and lint passed. Hosted CI owns broad checks and PostgreSQL coverage.

The table also protects mixed-script deduplication and Latin word boundaries. Existing creator/scope tests were consolidated without dropping assertions; net test delta is zero and the +14-line allocation is removed. Against the merge base: production +129/-88 (net +41, gross 217); tests +23/-23. The retained growth implements the bounded second candidate pass; no new persistent state or index rebuild is needed.

## Merge danger

Two-way door: a revert restores the old matcher without migrations or configuration changes. Normal intent firing still updates existing fire-count and cooldown state. Blast radius is Memory Core standing-intent matching, particularly unspaced CJK prompts; ordinary indexed word matching and reminder text remain unchanged.
```
