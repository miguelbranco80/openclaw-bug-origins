## Fix PR #146802 description (by vincentkoc, opened 2026-09-13T06:31:41Z)

```text
## What Problem This Solves

Fixes unnecessary conversation-history rendering when the run status changes or clears after its five-second display window.

## User Impact

Status-only updates leave settled history idle. Completion and interruption feedback remains in the composer. Terminal events can still render history when message content or other relevant state changes.

## Why This Change Was Made

The status row moved out of the transcript in https://github.com/openclaw/openclaw/pull/127823, but two status dependencies still invalidated every history row. This removes those orphaned dependencies without changing the status lifecycle.

## Evidence

- Production: +0/-2 lines. Tests: +38 lines.
- Exact head `b5b9239455a95ba1e718c38ea2a6718c48335cd9`: independent owner/dependency review and fresh autoreview through P2 found no actionable issues; `git diff --check` passed.
- Added regressions exercise the real transcript renderer for done/interrupted status appearance, timestamp refresh, and clearing. They count message-render calls and retain bubble identity; existing composer and run-lifecycle tests cover visible status behavior.
- Linux proof at the exact head passed canonical source verification and frozen installation. The original projection reproduced four unexpected history render calls instead of zero; restoring the candidate passed the transcript invalidation/rendering, composer, and run-lifecycle suites across two Vitest shards. No end-to-end speedup is claimed.
- Hosted CI currently fails on an unrelated routing-fixture preload defect tracked by https://github.com/openclaw/openclaw/pull/146827; required green CI remains pending.
```
