```text
## What Problem This Solves

Fixes chat and other database writes becoming stuck when a progress-card save overlaps a history search.

## User Impact

Messages and progress-card updates can finish during concurrent history reads. No configuration, schema, stored-data, or migration changes are required.

## Why This Change Was Made

Writer-held session target discovery now uses a separate read-only worker lane, so its awaited cleanup cannot join a history task waiting for that same writer. The lane uses the existing lifecycle owner and starts on demand; the tradeoff is one additional lazy reader worker. FIFO ordering, current-target authorization, reader custody, and write settlement remain unchanged.
```
