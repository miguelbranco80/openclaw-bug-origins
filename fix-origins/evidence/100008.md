## Fix PR #151870 description (by steipete, opened 2026-09-18T14:36:52Z)

```text
## What Problem This Solves

A direct reply can reach its transport successfully and then fail while OpenClaw serializes opaque channel data solely for an obsolete bookkeeping index.

## User Impact

Successful direct replies no longer fail because that unused index cannot serialize circular values or BigInt. Delivery receipts, retry custody, fallback decisions, and waiting-status behavior remain unchanged. This does not add support for these values to transports or other serializers that reject them; no configuration or migration is required.

## Why This Change Was Made

Direct delivery already records each attempt and its outcome. The old content-key Set had no remaining key lookup: consumers only asked whether any terminal reply had succeeded. Record that settlement-time fact on the existing receipt and remove the Set and its serialization/plumbing.

Preserve the two distinct observation times: fallback reads historical receipt facts as delivery progresses; the completed execution result snapshots its Boolean before deferred cleanup and task draining. Later source-completeness changes or late delivery settlements must not rewrite that snapshot. Final/pipeline content-key deduplication is unchanged.

## Evidence

The pre-fix producer-to-execution regression reproduced both circular JSON and BigInt TypeErrors **after** the transport callback succeeded. Candidate execution keeps those successful sends, while transport rejection/serialization errors and ambiguous-send custody retain their behavior.

- 148 focused owner/sibling cases and 197 cases in the real `runReplyAgent` E2E suite passed (overlapping earlier runs are not added to these counts). Cases include completeness changes in both directions, first success during deferred cleanup or task draining, and earlier-success controls.
- All 36 selected changed-check labels passed, including core/test/script types, lint, line ratchets, boundaries and import cycles. Audit-seam classifications are unchanged.
- Independent managed Codex P2 review of the full patch and complete critical source returned no findings.
- Fixed baseline/candidate/candidate/baseline experiment: 2,508 turns across 57 cohorts, comprising 1,824 measured and 684 warmup turns. All 228 retained complete canonical observations and corresponding traces matched across revisions.

The measurements are mixed: 25/57 pooled wall medians and 25/57 pooled CPU medians are adverse. The synthetic 64 × 64 KB rich-payload cohort changed from 13.709 to 11.365 ms; the 512-nonterminal-prefix cohort changed from 2.406 to 2.507 ms. These are pooled medians, not a claim that every comparison order improved. Obsolete serialized key content reached 4,217,880 UTF-8 bytes in the largest fixture and is now absent; that is not a heap/RSS measurement.

Provider and transport are isolated test doubles, startup is excluded, and peer/OS activity is uncontrolled. This is a correctness and ownership cleanup with mixed timing evidence, not a general or live Gateway speedup claim. Production code is net −4 lines; added tests protect the timing and custody contracts.
```
