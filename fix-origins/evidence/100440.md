## Fix PR #145660 description (by obviyus, opened 2026-09-12T05:48:01Z)

```text
Closes #127444. Reported by @steipete.

Related: #133163, #132569, #145484, #145817.

## What Problem This Solves

A stale configuration draft could overwrite a newer value in an included file because the revision checked only the root file.

## Why This Change Was Made

The snapshot owner includes captured include content and targets in the revision. The mutation owner checks it under the existing lock, rereads saved configuration after writing, and returns configuration and revision from that same canonical reread. Audit records retain their raw-file identity so history still joins the correct changes.

## User Impact

Stale include edits return the existing reload conflict and preserve newer values. Refreshing the draft permits the write. Root-only revisions, stored formats, and update compatibility remain unchanged.

Consumers: configuration editors and writers now detect include changes; write responses return a matching configuration/revision pair; system change history retains correct grouping.

## Evidence

Authenticated config.patch, config.set, and config.apply tests cover stale rejection and refreshed writes. Concurrent config.set requests preserve both writes. Registered configure continuation and authenticated change-history regressions fail before the repair and pass after it. After rebase, 82 activation, setup, audit, and configure cases passed. Released-state startup and updater checks passed on earlier builds.
```
