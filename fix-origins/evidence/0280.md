## Fix PR #199404 description (by daniel-lxs, opened 2026-11-15T03:16:03Z)

```text
Part of #199401 (proposal 1).

## What Problem This Solves

Fixes: on a phone, dashboard reports are cut off and scroll inside small boxes, so swipes over them get stuck instead of scrolling the dashboard.

## User Impact

User impact: on a phone, native reports and session progress cards show all their content, and swiping anywhere on the dashboard scrolls the dashboard. A card's saved size is still the smallest it gets, so making a card bigger with the resize corner or a size preset works as before. Website, Browser, custom HTML and other plugin widgets keep their saved height.

Desktop does not change, including the dashboard panel docked beside chat (448 px wide): every card keeps the size the user gave it, and content that does not fit scrolls inside the card, as on `main`.

## Why This Change Was Made

Without this, stacked cards keep the row height they have on the 12-column desktop grid: a report pinned at the default size (6 × 4) gets a 220 px window for content that stacks to over 1,000 px at phone width, so it becomes an inner scroller. In the phone layout (the app's shared `PHONE_LAYOUT_QUERY` breakpoint), when the board stacks its cards, the grid rows are at least 56 px and grow with content-fitting cards: reports and session progress grow to their content but never below their saved size, and every other card keeps its saved height because its body is size-contained. The core widget registry marks which kinds fit their content. The rules are limited to the phone layout because on desktop users size cards to compose their dashboard, and scrolling inside a card is intended there.

Total Control UI CSS on `main` is over its cap, so a change may add at most 64 B. The phone layout rules add more than that, so this also removes two new-session styles that no page has rendered since #197820 (the project search status line and the browser list loading line).
```
