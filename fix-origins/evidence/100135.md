## Fix PR #174278 description (by steipete, opened 2026-10-16T13:59:39Z)

```text
## What Problem This Solves

Fixes saved `sessions_send` updates warning about a replaced endpoint on every Gateway boot. Recovery wrote a deduplicated notice but left the input interrupted, so every restart selected the same undeliverable work again.

## User Impact

After recording a durable conversation notice, recovery cancels automatic delivery for reset, archived, or replaced endpoints. The accepted input remains stored. Permission and storage failures remain eligible for later recovery. Resend an update if it is still needed; recovery does not redirect it across an endpoint fence.

Warnings now include a hashed session key, input ID, age, endpoint side, and previous/current session identity and lifecycle generation. They do not include message content or raw session keys.

## Why This Change Was Made

Reuse the existing worker-owned pending-input withdrawal operation and cancelled state. No schema, configuration, cache, or alternate delivery path is added. Save the notice before withdrawal: a crash between these writes can repeat cleanup, but cannot discard the input without a durable explanation. Existing identity checks do not establish authority to retarget a successor, so this change preserves them.

The restart test also exposed orphan repair rewinding past a notice omitted from model context. Repair now checks the already-loaded durable ancestry, including the exact rewind parent, before rewinding. When that tail contains an unloaded entry, it preserves the original conversation branch and leaves the current prompt unmerged. This retains the notice without injecting it into model context, loading more history, or replaying it.

## Evidence

- Before/after: one replacement warning per retained input on every recovery pass → one initial warning, zero on the next pass after settlement. No latency claim or benchmark.
- The real SQLite pending-input regression fails on the original code: its notice is durable but the input stays interrupted. The fixed recovery file passes all 24 tests with fake timers (11.16 seconds wrapper wall time).
- The notice-preservation regressions fail against the preceding repair code for notices before/after metadata and immediately before a later unanswered user message. All 17 boundary tests pass after the final fix (34.31 seconds wrapper wall time); the four embedded-attempt orphan sibling tests also pass.

- Targeted formatting, lint, and `git diff --check` pass. Independent Codex autoreview is scoped clean through P2, including the final assertion correction.
```
