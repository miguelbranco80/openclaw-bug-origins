* fix(gateway): post-ack webhook work fails with "Async work scope is closed"

Plugins that defer work through runDetachedWebhookWork after a turn ends
(e.g. post-agent_end memory extraction) now keep an independently owned
async work lifetime: the detached callback runs in a fresh AsyncWorkScope
so tracked work stays accepted after the caller's scope closes, while the
live-parent root reservation and acknowledgement ordering are preserved.

Fixes #144788
AI-assisted: yes

* fix(hooks): keep automatic reset hooks alive after request completion

* fix(agents): classify a Code Mode host-exchange deadline as a timeout

A headless run and the host exchange it drives observe the same deadline.
When the exchange rejects with that scope's own timeout or abort error before
the scope's abort controller settles, runCodeModeWorker only inspects
signal.reason, so the typed error falls through to codeModeFailureCode and the
run reports internal_error.

That code is the closed failure code cron automations classify with: only
timeout is retryable, so an expired wall clock was recorded as a permanent
internal failure and its notification lost the timeout cause.

(cherry picked from commit d586df557a134d4970ff4e1facff8a9ac0162bf0)

* test(agents): prove the headless deadline path through a real tool leg

The classification cells exercise runCodeModeWorker through a substituted host.
Add a case that runs the production headless entry end to end: a real worker, a
real tool and the real deadline scope, with only the timer clock virtual, so the
scope observes its own deadline inside the host exchange.

Without the classification repair this case reports internal_error while its own
message reads "code mode headless wall-clock timeout exceeded".

(cherry picked from commit 38752f6eba44ea1e5be972696a3f39505e2eb154)

* test(agents): force the headless deadline ordering without a startup assumption

The deadline case advanced the clock by a fixed margin below the wall clock and
relied on worker startup taking longer than that margin. A faster run left both
the inner deadline and the outer abort pending, and the assertion that would
have caught it ran after an await on a tool that never settles.

Park the run on a first tool leg for a fixed real span instead. The scope
measures its remaining budget with an unfaked performance clock, so the second
leg's deadline is always armed at least that far ahead of the abort timer, on
warm runs as well as cold ones.

(cherry picked from commit ff365359b30dfaebb3ee0d92593ec296c327b98d)

* fix(hooks): preserve existing webhook cancellation semantics

Keep the automatic-reset repair on the shared internal detached continuation, but restore the public webhook helper and its tests exactly to main. The public-helper migration remains in #144801; this PR no longer changes third-party cancellation inheritance.

* chore(hooks): remove temporary Code Mode dependency

Keep the automatic-reset lifetime repair and its shared helper unchanged. Restore the two Code Mode files to their pre-stack bytes while preserving the contributor history and webhook scope reduction.
