```text
## What Problem This Solves

Fixes: the first cancellation of a leaf command on Linux can synchronously collect an unnecessary whole-process report even when no adopted child needs reaping.

## User Impact

Leaf-command cleanup no longer initializes native reaping unless a fresh process-group scan finds an adopted direct-child zombie. Existing root wait ownership, live-descendant polling, cleanup budgets, and inspection-before-reap behavior remain intact. No configuration, dependency, or process-identity contract changes.

When native support is unavailable, discovery can now perform bounded procfs scans before finding a candidate, reaching two quiet scans, or reaching the existing deadline. Genuine first native use can still incur initialization work. This does not claim to fix the separately observed seconds-long Gateway stall or make all cancellations faster.

## Why This Change Was Made

The existing cleanup owner checked native availability before discovering whether native work was needed. Move that check into its eligible-zombie branch, within the existing best-effort error handling. No cache, second cleanup owner, or identity shortcut is added.

## Evidence

- Owning regression suite failed on the original source: **5 failed / 10 passed**. After repair: **15/15 passed**, including deferred admission, delayed adoption, tracked-root/unrelated-child protection, native unavailability and errors, fresh inspection, longer grace, deduplication, and deadline cleanup. - Isolated real-command before/after on **Node 26.8.2 with 16 ready idle Workers**: first cancellation **86.90 → 43.67 ms**, heartbeat excess **63.31 → 0.50 ms**, whole-process reports/native loads **1/1 → 0/0**. Output and cleanup assertions were unchanged. Normal exit and second cancellation produced no reports in either version. Second cancellation measured **43.08 → 54.10 ms**; no general speedup claim or hard timing SLA is asserted.
- Real adopted-child proof passed: tracked root exit code **0**, exactly **one native inspection and one reap** of the expected descendant, no other PID inspected or reaped.
- Canonical core and selected test type checks, targeted lint, formatting, diff checks, and fresh independent P0–P2 review passed.
```
