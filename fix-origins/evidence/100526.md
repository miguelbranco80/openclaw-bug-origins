```text
## What Problem This Solves

#181175 — `sendA2aChannelText` rejects a peer without `url` (and a peer whose `outboundToken` reference did not resolve) with a plain `Error`. Both guards run before any I/O and depend only on loaded config, so no retry can ever succeed — yet the rejection matches neither the typed no-dispatch contract nor `isPermanentDeliveryError`'s text patterns. The outbound delivery queue therefore replays the send: the report shows one requester-settle wake retried twice (30 s, then 120 s) plus a dead-lettered session-event turn — four agent turns minted for one deterministic configuration failure.

## User Impact

A reply addressed to an inbound-only peer — the documented Quick-setup shape (`peers.<peer>.token` without `url`) — fails deterministically. Because the failure is classified retryable, each attempt costs a full agent turn and ends in a dead-letter entry instead of one terminal settlement.

## Why This Change Was Made

Both pre-I/O config guards now throw `PlatformMessageNotDispatchedError` with `retryable: false` — the existing permanent no-dispatch contract (`openclaw/plugin-sdk/error-runtime`), the same pattern already used by the bundled feishu and googlechat channels for permanent pre-dispatch policy rejections:

- `findTerminalBatchRejection` settles the queued send terminally on the typed rejection (`src/infra/outbound/delivery-queue-recovery.ts`), so no replay turns are minted.
- Queue-side behavior is already proven by `src/infra/outbound/delivery-queue.recovery.test.ts` ("all-permanent batch" → terminal); this change makes the A2A producer speak that contract.
- The channel adapter (`extensions/a2a/src/channel.ts` send.text) and the cron announce route propagate the producer error unchanged, so no typed information is lost end to end.

The unresolved-`outboundToken` guard one statement below is the same deterministic pre-I/O config class and would spin the same retry loop, so it is classified in the same change.
