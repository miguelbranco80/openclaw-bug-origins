## Fix PR #130223 description (by jacobtomlinson, opened 2026-08-26T16:25:31Z)

```text
Fixes #161445
Fixes #167469
Related: #111470

## What Problem This Solves

`ask_user` can start a question on a channel that cannot reliably deliver or complete it: WhatsApp DMs fail with `REPLY_DISPATCH_DELIVERY_ERROR`, and Mattermost turns can wait on an unseen question.

## User Impact

Eligible primary sessions retain structured questions on WebChat/native OpenClaw clients, Discord, Slack, and Telegram. On Mattermost, iMessage, Signal, WhatsApp, and undeclared channels, the agent asks in ordinary plain text. Explicit tool denial still wins. Approval reactions remain unchanged.

Peter's product decision is to gate built-in `ask_user` by declared native question input and retire bundled question-reaction fallbacks. This addresses the built-in `ask_user` failure reported in #167469 by omitting the tool from Mattermost. The separate native Claude `AskUserQuestion` path also mentioned in that report bypasses this catalog and remains outside this fix.

## Why This Change Was Made

The conversation capability owner resolves `questionInputMode` once from the authoritative inbound channel. Coding tools, Gateway catalogs, and skill dispatch carry that fact into registration; a supported fallback provider cannot enable questions on an unsupported inbound surface.

Bundled question-reaction adapters and obsolete tests are removed. The reaction SDK factory and members shipped in stable v2026.9.8 remain unchanged for third-party compatibility, with no removal date. The only additive SDK contract is optional `agentPrompt.questionInputMode: "buttons"`, documented on the existing channel adapter; no new named export is needed.

Docs name the supported surfaces and explain plain-text questions elsewhere. A nearby CI fixture defect is also fixed: the final iMessage self-chat test left fake timers active during asynchronous database teardown. One file-level cleanup hook now replaces two incomplete per-suite hooks, without changing assertions or timeouts. No schema, retention, or new deferred side effect is introduced.

Original fix by @jacobtomlinson; maintainer cleanup reconciles current main, completes direct-catalog propagation, preserves shipped SDK contracts, and updates docs and regression coverage.
```
