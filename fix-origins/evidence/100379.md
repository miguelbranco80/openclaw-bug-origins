Closes #171792

## What Problem This Solves

Guests who can create sessions can select registered projects in New Session, but cannot choose a managed worktree when the project list correctly omits host paths. The repository controller treated those project rows as idle, hiding the checkout control even though creation by project ID already supports isolation.

## User Impact

A guest can select a registered or Gateway-cloned project, choose **New worktree**, and start an isolated session without broad operator scopes. Leaving the base reference blank lets the Gateway choose the repository default. The existing creation owner checks the current repository and authorization and reports unavailable sources; a refusal keeps the selected project and isolation intent available for correction or retry.

## Why This Change Was Made

The UI now distinguishes a path-redacted registered project awaiting creation-time validation from an inspected Git checkout. It carries the existing project ID and worktree choice to `sessions.create` without attempting host-path branch discovery. Clients with disclosed checkout paths retain their existing inspection flow. The change adds no Gateway fields, scope grants, configuration, or path disclosure.
