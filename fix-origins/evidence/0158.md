## Fix PR #197013 description (by steipete, opened 2026-11-11T03:52:30Z)

```text
## What Problem This Solves

Broad `sessions_search` queries repeatedly materialize large archived session inventories on the Gateway main thread.

## User Impact

Searches keep the same visible active and archived sessions while doing less Gateway work. Requests are attributed as `sessions-search` in list diagnostics.

## Why This Change Was Made

Discovery previously paged active and archived full rows across all agents, then repeated both scans for the requester's agent. It only consumes session identities and ownership relationships. One `dashboard` summary inventory preserves those facts. An exact requester-owned `global` lookup preserves the sentinel when another agent wins the combined listing, and is skipped when the inventory already supplied it. The embedded adapter now supports that metadata lookup too.

Search is on demand and rebuilds a fresh authorized inventory. A timestamp cursor alone would omit older searchable sessions; no retained authorization snapshot, new cache, configuration, or SQLite schema is introduced. Production grows by 35 lines including one generated validator line: the tool shrinks by 3, while the exact embedded lookup and bounded source tag account for the growth.

## Evidence

Synthetic workload: 3,500 sessions, 3,000 archived, four agents, real tool discovery through the embedded projection owner with serving Gateway state custody. Transcript FTS is excluded. Five counterbalanced A/B pairs per timing/allocation mode, three measured sweeps after two warmups, plus A/A controls. Baseline: `240d0ac7e9d3d`.
