```text
## Summary

- remove only a container allocated by the current provision attempt
- clean its registry entry after failed setup or publication when removal succeeds
- preserve the original setup error while surfacing cleanup failures

First slice of https://github.com/openclaw/openclaw/pull/144394. This generic sandbox cleanup invariant is independent of the contributor PR's worktree persistence design. Co-authored with @eleqtrizit.

## Security review

Current main can strand a newly allocated container when start, setup, or registry publication fails. This slice records allocation in the in-memory attempt before those fallible steps and attempts cleanup only after allocation. It does not claim durable reservation or recovery when cleanup itself fails.

Production LOC: +73 net. Tests: +183 net.

## Validation

- focused source audit covered setup failure, publication failure, create-name conflict, cleanup failure, and concurrent provisioning
- exact-head targeted and hosted checks are required before merge

## Deferred from the original PR

Worktree sandbox routing and durable provenance are not in this slice. The proposed SQLite semantics need the repository's material-store design checkpoint before implementation.
```
