## Fix message body

```text
fix(claude-cli): don't hold the final answer for stopped or earlier-input tasks

With the Claude CLI runtime, a real final answer could be held and then lost when a stopped background task, or a task started by an earlier input, was treated as work the current turn still owned. Stopped tasks now settle, and tasks from earlier inputs no longer hold the current final answer; genuinely running background work still holds it until its answer arrives. This does not resolve the broader missing-reply reports, which have other causes.

Evidence: real Claude Code 2.1.308 through built Gateway RPC in Docker with a local Messages fixture. On main the final answer was held in both cases; with this change stopped work settles and earlier-input work does not hold the current final, a live background Agent is still held until its answer, and the next input reuses the same native process and session. A live gpt-5.4-mini run passes. Production +53 (down from +148).

Thanks @cassthebandit.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```

## What Problem This Solves

Fixes the Claude CLI task-ownership bug where a stopped background task or a task belonging to an earlier input holds the current final answer. Native has already emitted a successful terminal result, but OpenClaw incorrectly counts unrelated work against the current input and leaves that answer provisional.

**Not fixed here:** the broader missing-reply reports #167580 and #166585 are not closure targets. Missing replies caused by native failing to emit a terminal `result`, or by the host watchdog/timeout handling of genuinely pending work, have different causes from incorrect task ownership and are not repaired here. #167580 does not establish stopped-task involvement or distinguish an absent stdout result from a held result. #166585 includes a stopped-task case this patch addresses, but its broader watchdog/reply-loss report is not claimed fully resolved. Watchdog waiting and timeout preservation are separate work in #166511.

## Changes

Stopped task notifications release only that task's hold; they do not reserve an answer slot. Task ownership follows the admitted input for the lifetime of the native session, including resumed Agents and subagent work. Notification results use native run IDs when available and otherwise retain ordered receipt matching. Earlier-input results cannot overwrite a held current-input answer. Foreground completions do not consume a background Agent's answer.

The per-turn subagent identity set is removed. Identity parsing lives in a small internal module, not a plugin-SDK API. The protocol fixture and held-answer regression are split out rather than suppressing line limits. Redundant synthetic stopped cases are removed in favor of captured native event orders and real-runtime proof. Production delta against main: +53 lines, reduced from the original +148-line proposal; focused tests retain distinct stop, sibling, subagent, stale-input, run-ID and injected-input boundaries. No config or persisted-state changes.

Built artifacts in an isolated Node 24.22.1 Docker container, with local provider fixtures configured through shipped commands and sessions created through Gateway RPC. The actual Claude Code binary generated native task events; no shortened watchdog or scratch backend descriptor was used. Native Bash/TaskStop/Agent are enabled with the shipped exec-host configuration.

- Candidate: earlier-input work no longer held `CURRENT_FINAL`; stopped-task final completed without the post-native hold, and the follow-up reused the same native process and session. Genuine background Agent work still held and completed normally after release.
