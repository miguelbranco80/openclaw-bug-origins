## What Problem This Solves

Fixes #168567. `doctor --fix` silently replaced malformed UTF-8 bytes when merging `MEMORY.md` with legacy `memory.md`, overwriting the canonical file and reporting success.

Supersedes #168490, thanks @wangmiao0668000666.

## User Impact

An invalid UTF-8 input now leaves both files byte-identical before any archive is created. If bytes become invalid during the archive move, Doctor refuses the merge, preserves the archive, and reports its path. The warning names the affected file and advises preserving the bytes and converting a copy to UTF-8. Valid Unicode, including a literal replacement character, still merges.

This is a best-effort skipped repair, not an update failure. No config, CLI, schema, or dependency changes.

## Why This Change Was Made

The existing bounded read helper now validates UTF-8 before decoding. Both preflight and post-archive reads use it, so the bytes actually used for merging are checked. The existing post-archive failure path retains the independent recovery copy.

Production: +22/-27 (net -5); tests: +60/-5 (net +55); docs: +2. Three private skip flags and their duplicated reason selection are replaced by one recorded skip reason. The assertion-safety baseline shrinks only the touched file's count from four to two, matching the removed casts.

Release-note context: prevent Doctor root-memory merge from corrupting malformed UTF-8; retain unchanged inputs or a named recovery archive. Human contribution: wangmiao0668000666 <wang.miao86@xydigit.com>.
