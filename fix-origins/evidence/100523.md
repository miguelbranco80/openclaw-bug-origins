## What Problem This Solves

Users connecting to OpenClaw currently have to choose Token or Password even though they already have the Gateway credential. That choice appears on both the login gate and Settings → Gateway, and choosing incorrectly adds unnecessary recovery steps.

## Why This Change Was Made

Both surfaces now offer one **Gateway secret** field with the placeholder “Paste the token or type the password.” The client supplies the entered secret in both connect fields, using the Gateway behavior introduced in #141456. Mode-specific errors explain what the Gateway expects; they never ask the user to select a mode. This builds on the login gate redesign in #141087.

Credential persistence waits for a successful hello: token-mode secrets are stored in sessionStorage for the Gateway origin, while password-mode secrets stay in memory. Settings writes and startup no longer persist an unclassified secret. Bootstrap/device-token precedence, explicit native credentials, and origin-scoped URL edits retain their existing behavior.

## User Impact

Users can paste a token or type a password into the same field and click **Connect**. Password rejection gives password-specific recovery instructions. Passwords are never written to browser storage; token-mode connections retain the current-tab convenience after a successful handshake.
