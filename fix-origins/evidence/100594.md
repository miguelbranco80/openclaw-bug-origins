## Fix PR #179631 description (by steipete, opened 2026-10-21T15:25:09Z)

```text
## What Problem This Solves

Repeated content can produce identical memory chunk IDs within one sync batch. PostgreSQL rejects the resulting multi-row upsert with "ON CONFLICT DO UPDATE command cannot affect row a second time", preventing fresh indexing, full reindex publication, and some incremental replacements. SQLite accepts those writes with last-write semantics.

## User Impact

The shared chunk writer now deduplicates each upsert in memory. Canonical content comes from the last row carrying an embedding; recall metadata and provenance come from the last row overall. A trailing metadata-only row preserves the earlier content and embedding.

Existing SQL statements, conflict-update fields, transaction boundaries, locks, schema, and vector-projection ownership are preserved. No extra database round trips or configuration changes are introduced.
```
