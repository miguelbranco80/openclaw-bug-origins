## Fix message body

```text
## What Problem This Solves

Fixes: scheduled gpt-6-astra runs report "the tools returned no results" (or a similar blind answer) while their tool calls are still running.

## User Impact

User impact: cron runs and other runs without `sessions_yield` wait for their tool results before answering, so the delivered run summary is the real result, not a premature blocker.

## Why This Change Was Made

The agent loop always asked the OpenAI transport for async tool execution. With async tools, results reach the model only after it calls a synchronous tool (`sessions_yield`); until then each call is fire-and-continue. Cron runs never have `sessions_yield` (it is removed for cron session keys), and a narrowed `toolsAllow` can drop it too. The model then answered without seeing any result. That answer was kept as the run's final, because later turns ended with `NO_REPLY`.

The loop now requests async tool execution only when the surface includes `sessions_yield`, the tool that collects async results. Other synchronous tools such as `plugins` cannot return async results, so they do not enable async mode. The gate uses the tool name because `sessions_yield` already crosses the closed worker tool-surface protocol by name; a new tool field would be a protocol change. Surfaces that keep `sessions_yield` behave as before.

## Evidence

- Production incident on 2026.10.5 (`4ddbcb45`): a forced cron run streamed 6 async calls in one response, wrote "Stock check blocked: the tools returned no results" before the first `read` result arrived, then completed the real check 3 minutes later. The cron receipt and the owner conversation kept the blind answer. The same code paths are unchanged on `main` (`f2c7e8dd337`).
- New regression (`openai-responses-client.continuation.test.ts`, "keeps Astra tools synchronous without sessions_yield to collect async results"): an Agent over the real Responses transport with `lookup` plus an unrelated synchronous `plugins` tool advertises no async tools, sends the lookup result in the next request, and answers with it. It fails on the base (`lookup` advertised `async: true`).
- Fixtures that rely on async tools (SSE continuation, Responses EOF retry session) now include `sessions_yield`.
- Local: continuation, Responses EOF, agent-loop async-tools, astra-async-tails and worker gateway tool-runtime tests pass; oxfmt and oxlint are clean on changed files.
- Gap: no live gpt-6-astra gateway repro in a container (needs a production provider key in a container).

Simplification: production delta is one gate line (+2 comment lines) in the loop that already owns the async request; no new state, fields or protocol changes. Tests: +1 transport-level regression; two fixtures gain `sessions_yield`.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```
