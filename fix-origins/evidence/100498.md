Refs #142586 #145284

Follows the landed Doctor recovery in #145284. This PR reuses that preservation owner for update admission.

## What Problem This Solves

Fixes an issue where users running `openclaw update` would be refused before Doctor could recover orphan `task_delivery_state` rows. Creating update history required a clean foreign-key check, so the updater could never reach the supported recovery.

## Why This Change Was Made

Integrity checks distinguish the exact cascade-owned task-delivery relation with typed relation, parent-table, and orphan-count metadata. Classification still refuses unresolved state and grants no write authority; other foreign-key violations and structural damage remain refusals.

Actual update admission invokes the existing preservation-first recovery under its ownership fence and immediate transaction. Foreign-key actions stay disabled so inbound dependents cannot cascade away. Removal and the ledger's recovery step commit together, recording the count and recovery directory. The receipt and its backup locator survive both step-count eviction and byte-budget compaction; optional progress diagnostics remain disposable. Preview intent reaches the writer: `--dry-run` reports repair guidance without recovering rows or creating history for that refused preview. Doctor uses the same integrity classifier.

Recovery reads `task_delivery_state` and checks parent existence in `task_runs`; it deletes only delivery rows whose task is missing under the declared `ON DELETE CASCADE` relation. It never recreates parents, replays deliveries, or deletes valid siblings. Before removal, the existing Doctor owner preserves a verified WAL-aware full database copy plus a lossless export of every removed row in the recovery directory. Admission records the count and directory in the existing `update_runs.steps_json` column in the same transaction. No schema, version, or row-shape changes are made, so older readers retain their existing schema contract.

## User Impact

A fixed updater preserves and recovers these known orphan rows before recording an update. If it cannot acquire repair authority or preserve the data, its refusal identifies the repairable condition and directs the operator to `openclaw doctor --fix`. Recovery does not reconstruct tasks or replay deliveries. Ordinary backups continue refusing unrepaired foreign-key violations.
