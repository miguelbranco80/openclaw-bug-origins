## What Problem This Solves

Fixes Linux Gateway pauses when exec tools and Git helpers launch commands from a large Gateway process.

## User Impact

When the broker starts successfully, covered command launches fork a small helper instead of blocking the Gateway while Linux copies its page tables. Commands keep their existing approvals, arguments, output, and cancellation owners. The broker starts automatically for the default Node runtime on Linux; there is no new configuration or state migration.

## Why This Change Was Made

A Gateway with 5.4 GB RSS spent 15.6% of its main thread inside 56 clone calls over 20 seconds, averaging 55.6 ms each. A CPU profile attributed 34% of main-thread work to native process spawning. The remaining commands are useful work; the expensive parent is the problem.

One process-scoped spawn broker starts before the heavy Gateway runtime. Native child, service-relay, and owned-worker launches transfer real stdio sockets and forward IPC messages. Execa runs in the broker while existing collectors, admission checks, process supervisors, and tree-termination policies stay with their owners. After first readiness, broker loss fails affected requests, cleans known children, and restarts with bounded backoff; it never silently retries through local spawning. Extracted PR-tool runtimes include the required broker client dependencies. Expected steady-state Gateway main-thread clone count for covered exec/Git launches with the broker ready: **0**.

If the broker fails on its initial start (spawn/entry error, exit before readiness, or the existing 15-second readiness deadline), the Gateway logs one error with the reason and runtime entry path and uses in-process spawning for the rest of the process lifetime. It does not retry that initial failure. Once the broker has become ready, in-flight failures retain `ERR_SPAWN_BROKER_UNAVAILABLE` and the existing bounded recovery behavior.

Buffered execa capture uses a bounded tee to a separate output socket so execa retains its buffering and maxBuffer enforcement; that path is not zero-copy. Native and unbuffered output use transferred sockets, with bounded preservation of any pre-transfer bytes. A small adapter checks Node's private pipe read-stop contract because ordinary Socket.pause() does not stop the sender's libuv reader during IPC handoff. Command context, pending cancellation, and late PID cleanup survive the asynchronous boundary.

The broker starts in its own process group. On broker loss, the Gateway terminates that group even if an individual child's PID has not yet been reported; service relays independently retain IPC parent-loss and anchor cleanup. A detached child can survive a broker crash before its PID is reported, matching the existing Gateway-crash residual for directly spawned children. The coordinator rejected a cgroup prerequisite for this lane: the current direct-spawn design also lacks pre-spawn custody on Gateway death, while group cleanup and relay ownership cover the non-detached and tree-owned paths here. The detached fault-injection probe is retained as evidence of the documented residual.

Explicit local paths remain for numeric/anonymous descriptors, independently launched applications, CLI-only helpers, Bun, macOS, and Windows. PTY sessions, app-server lifecycles, Windows anchors, worker-thread ownership, command frequency, and approvals/redaction are outside this change.
