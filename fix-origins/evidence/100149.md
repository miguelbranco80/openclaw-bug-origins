## Fix message body

```text
Closes #153357

## What Problem This Solves

Fixes a bare Gateway timeout making an already-dispatched CLI operation look like a definite failure, even when the Gateway has completed the write.

## User Impact

Human-facing timeout errors now explain that the outcome is unknown and advise checking state before retrying. Startup timeouts keep their existing wording. This does not shorten slow operations, change deadlines, retry writes, or alter deletion/fallback policy. Dedicated Gateway JSON errors retain their existing first-line-only message format.

## Why This Change Was Made

The existing request owner already distinguishes startup from a started primary request. The timeout formatter uses that fact without adding another dispatch state or recovery mechanism.

The two regression branches now share the existing Gateway-call suite; the duplicate 218-line test harness was removed. Existing connection details, typed errors, and JSON behavior remain covered.

## Evidence

- Ran the real `openclaw agents delete victim --force` CLI against an isolated token-authenticated Gateway through a WebSocket proxy. The proxy forwarded one deletion and withheld only its matching successful response. Readback from the same isolated state confirmed the victim was gone.
- Current main reported only the 10-second wrapper timeout. With this repair, the same flow retained exit code 1 and added the unknown-outcome/check-before-retry guidance.
- A mute startup endpoint produced unchanged timeout guidance and left the control agent present. A withheld read-only RPC confirmed the dedicated JSON error envelope remains unchanged. No deletion was retried.
- 163 focused Gateway-call tests passed; both affected cases passed again after the final test-only guard/helper cleanup. Against original production code, the dispatched regression failed and its startup control passed. Scoped lint, formatting, whitespace, and the affected `gateway-root` test-type graph passed. The line-cap check passes against the exact CI ratchet base; no compiler setting, baseline, or coverage exception was added.

Runtime proof used main `48bcfda392fc4848d6d032f661d0a589ad420984` plus the exact introduced repair. The normalized patch matches this branch, and the complete request lifecycle and formatter match; surrounding main-only changes concern device-helper extraction and abort scopes. This is not a full historical-branch runtime claim. No real operator state, vendor service, or credentials were used.
```
