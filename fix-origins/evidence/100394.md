```text
## What Problem This Solves

Fixes accepted chat messages failing with a session-refresh error when a previous run compacts the conversation while the next message is being prepared.

## User Impact

Messages continue automatically through verified compaction, including consecutive queued compactions, with the original send identity and one saved copy of the input. When continuation cannot be verified, the message stays visible with a readable explanation, full diagnostic details, and a Refresh action that preserves the draft without resending.

## Why This Change Was Made

Gateway preparation now retains its predecessor, and reply admission combines that evidence with the predecessor observed at dispatch. The existing owner verifies connected session history in the same physical database before passing the admitted session ID into initialization. Reset, restart, cancellation, and unrelated-store boundaries remain enforced. No configuration or data migration is required.

## Evidence

- Gateway regression exercises the real request handler, admission, session initialization, and SQLite transcript; model execution is replaced by a fixture. Completed, active, and successive compactions preserve the original run and save the input once. Replacement, foreign-store, restart, and cancellation cases cannot execute.

- Browser proof covers diagnostic expansion/copy, desktop and mobile layout, draft preservation, and no second `chat.send` when Refresh is selected.
```
