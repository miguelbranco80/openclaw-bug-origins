Closes #154884

## What Problem This Solves

Fixes: in Safari and other WebKit browsers, the agent avatar picker (Settings → Agents → Identity) rejects ordinary images well under 2 MB with "Pick an image file up to 2 MB."

## User Impact

User impact: detailed avatar images now work in WebKit browsers. When an image really can't fit, the error says it's too detailed and points to the CLI, instead of claiming the file is over 2 MB.

Tradeoff: in WebKit, a detailed image with transparency may be stored as a 64 or 48 px PNG instead of 96 px, so it can look slightly soft in the 56 px editor preview on high-DPI screens. Chromium and Firefox are unchanged; they still use 96 px WebP.

## Why This Change Was Made

The picker shrinks images to 96 px and keeps the data URL at or under 16,000 characters, because it's mirrored into the prompt-injected `IDENTITY.md`. WebKit ignores `toDataURL("image/webp")` and returns PNG. A detailed 96 px PNG with transparency comes to about 34K characters, so it was rejected. Every rejection reused the 2 MB file-size message.

When WebP isn't available:
- Fully opaque images use JPEG at 96 px.
- Other images are saved as PNG at 96 px, then 64, then 48, and the first one that fits is used.

`fileToAvatarDataUrl` now returns a result that says why it rejected an image: `unusable` (not an image, or over 2 MB) or `too-detailed`. The second maps to a new English string, `agents.identity.imageTooDetailed`. The existing string is unchanged, so its translations stay valid. The 16,000-character limit is also unchanged.

+// Control UI helper converts picked avatar images into compact data URLs.
+import { AVATAR_MAX_BYTES } from "../../../../src/shared/avatar-limits.js";
+
+/** Uploaded avatars also mirror into prompt-injected IDENTITY.md. Keep their
+    encoded form below the per-file bootstrap limit with room for identity text. */
+const AVATAR_TARGET_SIZE = 96;
+const AVATAR_EDITOR_MAX_DATA_URL_CHARS = 16_000;
+
+function boundAvatarDataUrl(value: string | null): string | null {
+  return value && value.length <= AVATAR_EDITOR_MAX_DATA_URL_CHARS ? value : null;
+}
+
+function readFileAsDataUrl(file: File): Promise<string | null> {
+  return new Promise((resolve) => {
+    const reader = new FileReader();
+    reader.addEventListener("load", () =>
+      resolve(boundAvatarDataUrl(typeof reader.result === "string" ? reader.result : null)),
+    );
+    reader.addEventListener("error", () => resolve(null));
+    reader.readAsDataURL(file);
+  });
+}
+
+/** Convert a picked image file into a data URL bounded for identity storage.
+    Returns null when the file is not an image or cannot be encoded. */
+export async function fileToAvatarDataUrl(file: File): Promise<string | null> {
+  if (!file.type.startsWith("image/") || file.size > AVATAR_MAX_BYTES) {
+    return null;
+  }
+  try {
+    const bitmap = await createImageBitmap(file);
+    const scale = Math.min(1, AVATAR_TARGET_SIZE / Math.max(bitmap.width, bitmap.height));
+    const width = Math.max(1, Math.round(bitmap.width * scale));
+    const height = Math.max(1, Math.round(bitmap.height * scale));
+    const canvas = document.createElement("canvas");
+    canvas.width = width;
+    canvas.height = height;
+    const context = canvas.getContext("2d");
+    if (!context) {
+      return readFileAsDataUrl(file);
+    }
+    context.drawImage(bitmap, 0, 0, width, height);
+    bitmap.close();
+    // toDataURL silently falls back to PNG when WebP is unsupported.
+    const encoded = canvas.toDataURL("image/webp", 0.8);
+    return boundAvatarDataUrl(
+      encoded.startsWith("data:image/webp") ? encoded : canvas.toDataURL("image/png"),
+    );
+  } catch {
+    // Non-rasterizable images (e.g. SVG without intrinsic size) pass through
+    // unscaled; the size gate above still bounds the persisted payload.
+    return readFileAsDataUrl(file);
+  }
+}
