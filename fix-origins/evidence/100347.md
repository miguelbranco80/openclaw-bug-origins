## Fix PR #171845 description (by vincentkoc, opened 2026-10-14T06:27:02Z)

```text
## What Problem This Solves

Memory Wiki compile validation repeatedly materializes the entire audit journal, causing large temporary memory spikes as compile history grows.

## User Impact

Vaults with long compile histories need much less transient memory during identity validation. Rollback detection, reservation ordering, publication validation, and existing log contents remain intact. No configuration or migration is required.

## Why This Change Was Made

Replay the existing causal reducer from one open file in 64 KiB chunks instead of retaining the whole UTF-8 journal and split-line array. Nonempty regular files use their initial extent; subsequent validation checkpoints replay independently. This is a bounded prefix observation, not an atomic snapshot. Memory scales with the chunk plus the largest physical record; CPU still scales with journal history. Full-history APIs and all six warm-compile validation reads are unchanged.

## Evidence

One paired local experiment used Node 26.7 on macOS arm64, the complete production identity reader and normalizer, identical journal bytes, and six sequential identity reads per child. Journal generation happened outside measured processes. These are owner-replay measurements, not six full compiles or a retained-memory leak claim.

| Historical compiles | Journal bytes | Peak process RSS before → after | CPU before → after |
| --- | ---: | ---: | ---: |
| 1,000 | 774,068 | 91.5 → 82.7 MiB | 36.8 → 13.7 ms |
| 10,000 | 7,740,068 | 178.6 → 88.3 MiB | 205.0 → 113.5 ms |
| 30,000 | 23,220,068 | 319.0 → 95.2 MiB | 573.6 → 305.4 ms |

Startup-only peak was about 80 MiB in both runs. Peaks include process startup; no forced GC or reduced heap limit was used. The single paired sample demonstrates the allocation improvement, not a guaranteed performance ratio.

- Four identity fields matched at every scale. Thirteen actual-file controls passed.
- Pinned oxfmt 0.71.0, native commit hooks, diff checks, and scoped independent source review passed; the later correction changes only error metadata, not the measured read algorithm.
- Fourteen new regression test bodies passed against the production owner using an explicitly isolated builtin `node:test` runner. They cover framing, authoritative EOF/UTF-8 boundaries, rollback authority, bounded reads, read/stat/close errors, append, truncate, and path replacement.
- [Official CI](https://github.com/openclaw/openclaw/actions/runs/38525624795) passed on exact head `535d3a83a527540f70fafbda4beaff93ec658b47`, covering the planned repository tests, type, lint and boundary checks. Local builtin proof remains separate from that hosted validation.
- Initial CI found a forbidden test-helper import, a stale readFile fault injection, and lint issues. The final head uses the public SDK helper and actual open seam, consolidates the test literal, and preserves the caught close error as AggregateError cause while retaining ordered errors. A fresh 14-body owner proof and scoped independent review passed for this error-metadata correction; the streaming algorithm and performance experiment were unchanged.
- The first candidate harness invocation stopped before measurement because Node's default reporter was `spec`; the corrected invocation explicitly selected TAP. No product assertion failed in that first invocation.

Release note: reduce Memory Wiki compile-validation memory spikes on long audit histories. Per the repository contribution policy, this note belongs in the PR rather than the generated release-owned changelog.
```
