## What Problem This Solves

Lossless recall can fail with a closed database after a settings reload. OpenClaw registers the replacement before cleaning up its predecessor, so old cleanup can invalidate the replacement's resources.

## User Impact

Plugin settings reload without restarting the Gateway. OpenClaw drains and disposes the old registration before acquiring replacement resources. If replacement fails before publication and cleanup succeeds, it automatically registers captured previous code and settings with fresh resource ownership. Unchanged plugins retain their registrations.

Cleanup is a safety barrier: delayed cleanup can be retried after settlement; an actual cleanup failure leaves the affected plugin fenced instead of admitting another resource owner. Healthy sibling channels resume independently after failed command-owner cleanup. Recovery restores the runtime, without rewriting externally edited configuration files.

## Why This Change Was Made

Keep validation, source capture, resource handoff, publication, and recovery in the existing reload owner. Captured-source recovery also works after installed files are replaced or removed. Package metadata hydration now preserves workspace provenance, descriptions, and normalized empty dependency maps so unchanged plugins are retained.
