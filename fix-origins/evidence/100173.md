## What Problem This Solves

Fixes duplicate deferred maintenance and incomplete cleanup when task lookup or creation invokes reentrant callbacks.

## User Impact

Repeated maintenance requests share one active run, and transferred engine and factory resources remain owned through preparation and cleanup.

## Why This Change Was Made

Reserve the existing tracked run before invoking task callbacks, and join preparation descendants before disposing resources. Synchronous task-runtime contracts remain unchanged; task persistence remains synchronous in this cut.

## Evidence

All 24 pure controls pass: seven scheduler regressions and 17 existing coordinator cases. Six regressions fail on the original code; the queue-rejection control already passed. Scoped types, lint, architecture guards, and isolated review pass. No native SQLite worker or provider scenario was run.
