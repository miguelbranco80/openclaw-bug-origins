## Problem and result

Feishu/Lark `/followup` could wait behind active work before reaching admission or reporting queue acceptance. Its retained ingress claim could then block the next message in that chat.

Authorized followups now reach the existing queue while work remains active, receive the runtime’s actual outcome, and execute FIFO under their submitting identity. Ordinary buffered messages retain their ordering. Broadcast observers consume control commands without executing them or leaving retryable ingress behind.

## Implementation

- Supply existing typed command facts before core turn acquisition.
- Release chat-lane occupancy only after the real deferred/adopted/abandoned lifecycle handoff. Durable ingress continues to own recovery custody.
- Consume observer control commands through the existing broadcast lane lifecycle before dispatch. Ordinary observer inference and active-agent admission remain unchanged.
- Run the existing logical-claim abandonment hook before releasing transport custody on stop.

No new queue, authority owner, SDK API, persistence, configuration, or core admission framework. Small existing-owner extractions preserve file-size limits: broadcast claim acquisition, supplemental-context filtering, and command fixtures.
