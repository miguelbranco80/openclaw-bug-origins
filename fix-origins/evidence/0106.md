```text
## What Problem This Solves

Fixes: the chat composer collapses to a single line in wider windows that use drawer navigation, hiding controls even when there is room to keep them visible.

## User Impact

Wider layouts keep the editor and its controls expanded. Phone-sized layouts keep the one-line resting composer, expand on click or focus, and stay open when a typed draft is left behind. No configuration changes are required.

## Why This Change Was Made

Drawer navigation and phone-sized composition have different width thresholds. Gate only the existing resting presentation with the established phone layout range: up to 640 CSS pixels, plus the existing short landscape-phone range. Keep the same editor, focus handling, mobile panels, and draft ownership.

## Evidence

- Reproduced on current main 491c2944f56ad7d: the new production-app regression fails at 900 px with hidden composer controls; passes with this fix.
- Production Control UI build and 2 focused composer-size E2E tests passed (4.06 s test time, 17.57 s including setup/build). Covers 900/820/768/641 px expanded, 640/390 px and 844 × 390 landscape compact, pointer/focus expansion, blur, resize, and draft/editor retention.
- 17 existing Chromium mobile/focus browser tests passed (5.90 s wall); 4 mobile interaction unit tests passed (3.48 s wall).
- UI and chat-E2E TypeScript checks, touched-file lint/format, Solid controller guard, and whitespace checks passed.
- Author simplification review: reuse the existing media-query primitive and resting-state owner; no alternate composer or extra persistence. Production +8 net lines; tests +82 net lines. No independent review run. CI duration is not yet available.
- Screenshots use the actual production app with synthetic Gateway data, light theme, and emulated viewports. Physical-device keyboard and Safari behavior were not requalified.
```
