## Fix PR #151371 description (by steipete, opened 2026-09-18T04:23:47Z)

```text
## What Problem This Solves

Fixes async tool launches being reclassified as safe to replay after the Codex adapter records their result, which can allow fallback to repeat work that already started.

## User Impact

Started background work retains its side-effect evidence through settlement. Native Codex receives the same two-field response, while OpenClaw keeps its diagnostics, previews, and execution facts locally. No configuration or runtime-version change is required.

## Why This Change Was Made

The bridge knew an async launch was unsafe to replay, but its terminal observer fell back to the tool name and overwrote that fact. Forward the exact classification and retain owner-mutation precedence. Plain host metadata plus the existing explicit wire serializer replaces eight property decorators, removing 176 production lines while preserving execution-snapshot ownership.

## Evidence

- The async bridge → timeout wrapper → real terminal observer → projector regression failed before repair; the synchronous control passed.
- 280 focused tests passed, followed by 174 bridge tests after assertion-helper cleanup. All selected repository checks passed locally.
- API-key-backed native Codex 0.154.0 invoked a synthetic async search through the production bridge, completed its final response, sent only `contentItems` and `success`, and retained `{ hadPotentialSideEffects: true, replaySafe: false }`.
- The same native tool round-trip passed in Linux Crabbox on Blacksmith Testbox `tbx_01m2sba978x9sr8mf5w99ak7hk` ([run](https://github.com/openclaw/openclaw/actions/runs/35305922545)); source carrier and native version were verified, with the key supplied by the maintained Testbox helper.
- Independent Codex review found no actionable P0-P2 findings. Compared directly with [Codex's native response contract](https://github.com/openai/codex/blob/c775dd3c332de1b69b25a4580f6c5bc44b94e284/codex-rs/app-server-protocol/src/protocol/v2/item.rs#L1664).
```
