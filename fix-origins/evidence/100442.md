## Fix PR #166426 description (by steipete, opened 2026-10-07T03:26:04Z)

```text
## What Problem This Solves

Three `openclaw agents` CLI behaviors disagreed with runtime routing, or reported success on failure:

1. **Bind and unbind ignored the configured default agent.** With `home` and `ops` configured and `agents.defaults.systemAgent.agentId=ops`, `agents list` showed `ops` as the default. But `agents bind --bind telegram:ops` and implicit unbind failed with "Multiple agents… no explicit owner."
2. **Account casing created shadow bindings.** With `ops` owning `telegram:ops`, binding `home` to `telegram:OPS` succeeded and stored a second route. Unbinding `telegram:Ops` reported the binding missing, with exit 0.
3. **A partially failed add reported success.** `agents add research --workspace <dir> --bind telegram:ops --non-interactive --json` created the agent, could not claim the already-owned binding, and still exited 0.

## Why This Change Was Made

1. `src/commands/agents.commands.bind.ts` used a restrictive resolver instead of the existing operation-owner resolver (`1ca60fbc3a3f`; `05177019f408` fixed default selection elsewhere but missed this caller). It now reuses the canonical owner and roster functions, which removes duplicate membership logic. An ownerless fleet still refuses ambiguity.
2. `src/commands/agents.bindings.ts` compared account ids by literal spelling, while runtime routing normalizes them (`8178ea472db1`). It now uses the existing account normalizer, keeping wildcard semantics. A competing owner exits 1, same-owner repetition is skipped, and mixed-case removal works.
3. The non-interactive output path in `src/commands/agents.commands.add.ts` omitted failure status (`629eec11cc50`). It now keeps the created agent, its successful work, and the conflict summary, and exits 1. The docs explain resolving the binding rather than recreating the agent.

A supporting commit removes one mock allowance that is now obsolete (a shrink-only baseline change).

## User Impact

Binding commands honor the configured default agent and the same account normalization routing uses. Scripts can trust the exit code of a non-interactive `agents add`.

## Evidence

- Four regressions failed before the fixes. After the rebase, 364 tests across 20 files pass (one Windows-only skip), along with the full `pnpm build` and `check-changed` on the final head.
- Real CLI and Gateway flows on an isolated remote box covered workspace creation, per-agent model persistence, two concurrent adds with no lost entries, identity updates, binding and routing, default-agent hot reload, implicit binding after a default change, and deleting an agent through the live Gateway. That deletion removed its session and cron job and kept the other agent's state. Doctor exited 0, and a restart kept the new default and the survivors.
- Production -6 net (+9/-15); tests +48 net; docs +2.
```
