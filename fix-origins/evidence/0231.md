## Fix PR #202074 description (by steipete, opened 2026-11-19T21:35:05Z)

```text
## What Problem This Solves

Agent validation commands can leave large temporary trees in host `/tmp`, outside OpenClaw's 24-hour scratch cleanup. On hosts where `/tmp` is tmpfs, that consumes memory and swap until an operator intervenes.

## User Impact

Local agent commands now default `TMPDIR`, `TMP`, and `TEMP` to their workspace's `.openclaw/tmp`. Temporary validation output is disposable under the existing 24-hour rule, even when artifacts reference it. Live and queued agent work remains protected; durable outputs belong outside scratch. After those runs settle, a detached background service alone does not extend the 24-hour lifetime of unchanged workspace scratch. Services needing longer-lived files must place them outside scratch or explicitly select a temp root with their own cleanup.

## Why This Change Was Made

Connect core exec, local CLI execution, and native Codex shell/Code Mode environment preparation to the existing scratch owner. Codex obtains the path through its run-bound host capability and applies it through thread shell policy, preserving shared app-server reuse. Docker/Podman commands use scratch in their writable workspace mount. Read-only workspaces keep writable temporary files in the container-private `/tmp` tmpfs, owned and released by the container lifecycle.

The existing cleanup inventory now includes configured agent and local sandbox workspaces, including sandbox directories left after container retirement. Queued protection uses the production session selector, including attachment grants and immutable skill-library isolation. Sandbox scope resolution and active-command custody reuse their existing owners. No new TTL implementation, configuration option, schema, reference-protection index, or cache. Explicit CLI/command/container environment overrides remain supported. Remote execution keeps its own paths. Programs that explicitly choose `/tmp` can bypass the policy; arbitrary host temp entries are not swept by name. Deep workspace paths can exceed Unix-domain socket limits: those tools need a short workspace or an explicit short-temp override with their own cleanup. The existing test runner already owns that exception.

Related: #193677. The short-lived native socket-path workaround from #196509 remains intact.

A real Docker read-only bind-mount probe fails before the temp-path correction and succeeds afterward.
