## What Problem This Solves

Fixes Node helper subprocesses selecting an unsupported system Node ahead of a supported installation when OpenClaw runs under Bun. In CI, Gateway post-ready maintenance launched Node 20.20.2 and failed to parse a compiled module's `using` declaration despite Node 24.22.1 being installed.

## User Impact

Node-only helpers select a runtime supported by OpenClaw. If none is available, the resolver returns `undefined` through its existing contract. PATH hardening, candidate order, required flags, and caller environment handling stay unchanged.

## Why This Change Was Made

The current-runtime fast path and standalone probe now use the existing canonical Node support predicate. The generated executable programs are regenerated through their owner. Existing resolver, generated-program, and child-process tests cover the behavior, and the SDK documentation describes the supported-runtime contract. Sparse CI and source-scanner fixtures retain the canonical version module required by the resolver.

## Evidence

- Real mixed-runtime reproduction in a qualified native checkout: the pinned Bun fork runs the existing Gateway post-ready `settles` case with official Node 20.20.2 ahead of supported Node in the test subprocess PATH. Scoped typecheck, lint, formatting, workflow validation, and diff checks pass; a fresh correction review found no actionable correctness or security defects.
