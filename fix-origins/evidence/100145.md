## Fix PR #166662 description (by jayzhou2309, opened 2026-10-07T16:45:41Z)

```text
Closes #166605

## What Problem This Solves

`openclaw config set` rejects an ACP agent's harness model (such as `composer-2.5` or `opencode/muse-spark-1.3`) in `agents.entries.<id>.model.primary`, although the ACP bindings docs say that field selects the harness model.

## User Impact

Operators can pin an ACP agent's harness model in OpenClaw config. Native refs on ACP agents (`model.fallbacks`, the inherited `agents.defaults.model`) remain validated, and removing `runtime.type: "acp"` validates the primary that becomes native.

Config admission now matches the Gateway's existing opaque ACP-primary admission; harness-specific model support remains an execution-time check in acpx, just as for hand-edited configs.

## Why This Change Was Made

The validator collected the agent's raw `model` and sent its primary to native model resolution. It now uses `resolveAgentModelConfigForRuntime`, the existing runtime policy owner, to exclude ACP primaries while retaining native fallbacks. Runtime changes count as model dependencies, and default inheritance uses `resolveAgentNativeModelPrimary`.

No schema, stored-data format, migration, or authentication changes. No overlap with Pash/Sarah changes in the two touched files.

## Evidence

Maintainer verification in secretless Docker, using isolated profiles, on head `e76834a24df765b9835e0bd28bf492301ade723e` against current main `c6698b1e9b2b4adc9e0c2b0ee10439fe9936b693`:

- Real CLI `config set agents.entries.qursor.model.primary composer-2.5`: base rejects; candidate accepts and writes. Candidate Gateway starts and `health --json` returns `ok: true` with the configured ACP primary retained.
- Unknown native ref `nonexistent-provider/definitely-invalid-166662`: rejected for a non-ACP agent on both revisions. Giving that agent `composer-2.5` also remains rejected on both.
- Base Gateway loads a directly authored unknown ACP primary and reports healthy. Candidate CLI accepts that same opaque ACP primary, matching existing config admission rather than claiming the external harness supports it.
- The PR's regression file on current main: 3 failures, 19 passes; candidate: 22 passes. Failures cover ACP-primary exclusion, ACP-to-native switches, and default inheritance.
- One live OpenAI Responses API smoke call, alongside exact-head CLI admission: `gpt-5-mini`, reasoning `low`, output budget 4096; HTTP 200, `ACP_CONFIG_LIVE_OK`. This is provider reachability evidence, not a live ACP harness execution claim.

Contributor-reported additional checks: all 15 `src/cli/config*.test.ts` files (274 tests), Doctor ACP checks (7), native/ACP model-selection checks (6), formatting, lint, and core typecheck. These broader checks were not rerun by the maintainer.

Not verified: a live external ACP harness turn; the changed contract is config admission.

Thanks to @jayzhou2309 for this fix and regression coverage, and the reporter of #166605. #166677 overlaps; this earlier fix reuses the existing runtime policy owner rather than duplicating it.
```
