## What Problem This Solves

Fixes CUA recording retries and execution close staying broken after a temporary resource-directory initialization failure.

## User Impact

Once the filesystem problem is repaired, the same computer execution can retry recording, or close and allow a fresh execution. The failed action reports its original error and never reaches the native driver.

## Why This Change Was Made

The existing resource owner keeps a rejected initialization promise indefinitely. Clear that promise only when its producer fails; successful resources keep their existing lifetime and cleanup behavior. No new state, shared abstraction, SDK, configuration or storage contract is added. A late initialization failure can already leave an empty directory; this repair does not expand that pre-existing cleanup policy.
