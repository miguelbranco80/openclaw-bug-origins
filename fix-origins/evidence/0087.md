## What Problem This Solves

Slow cron hydration warnings can report zero statements even while SQLite performs substantial reads. Workspace maintenance also repeatedly copies its entire pending graph frontier when selecting each 256-node batch.

Related: #191711, #190295, #190938.

## User Impact

Read-only agent diagnostics now attribute native execution, including iterators and cached queries. Workspace sweeps allocate less memory while preserving their candidates and coherent snapshot. This does not claim to reduce historical transcript or workspace database I/O; those remaining scans are documented below. No schema, index, config, cache, retention, or permission change.

## Why This Change Was Made

The ordinary read-only SQLite opener bypassed the engine opener's existing observation wrapper. Install that wrapper before statement caching. The prior hydration benchmark explicitly wrapped its own handle and therefore missed the production wiring defect; it now uses the actual read-only owner.

For sweeps, collect only the next batch from the pending Set instead of spreading the entire Set and slicing it. Traversal order, reachability, epoch checks, and query batches remain unchanged.

Production delta is +8 lines: two connect existing diagnostics, six replace unbounded transient copying with bounded collection. Tests grow by 53 lines, with a scoped allocation record: one real read-only attribution regression and wider coverage in the existing GC retention test. Existing benchmark scripts gain production-shaped payloads, native pager measurement, and a sweep workload.
