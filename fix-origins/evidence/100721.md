## Fix PR #156108 description (by galiniliev, opened 2026-09-23T02:26:10Z)

```text
## What Problem This Solves

Fixes slow and internally inconsistent SQLite schema inspection when metadata lives on network-backed storage or changes between related reads.

## User Impact

User impact: Gateway startup and schema verification inspect metadata from one committed snapshot, avoiding repeated lock acquisitions without changing schema repair behavior or requiring transaction-control authorization.

There is no schema-format, schema-version, migration, retention, or permission change. A continuous read snapshot can make rollback-journal writers wait or delay WAL checkpoint progress. Inspection and subsequent repair remain separate phases.

## Why This Change Was Made

Schema comparison and canonical-index inspection previously issued related metadata reads independently. A stepped `schema_version` statement now pins SQLite’s implicit read transaction until inspection finishes, then releases it before repair writes. This preserves top-level and nested read-only authorizers because it does not issue `BEGIN`, `COMMIT`, or `SAVEPOINT`.

Review found and fixed a recovery bug: failed initial snapshot acquisition could leave a cached statement carrying `SQLITE_BUSY`, making the next inspection fail even after the writer released its lock. The first cursor step is now inside the cleanup guard.
```
