## Fix PR #193263 description (by steipete, opened 2026-11-05T06:50:23Z)

```text
## What Problem This Solves

Fixes: an update interrupted with Ctrl-C or `SIGTERM` while verifying the restarted Gateway can sit for up to the update deadline printing `service=unknown ... health=ready`, even though the Gateway is healthy. Also fixes: on large state databases, candidate admission times out at a fixed 120 s and silently falls back to the installed updater's older checks.

## User Impact

User impact: an interrupted update now exits within seconds and leaves a healthy Gateway running, with the interruption reported instead of an apparent hang. Installs with a large state database now get the target release's own admission checks, as small installs do. No config, schema, or protocol change.

## Why This Change Was Made

A signal stops the update's forward command scope so its children end. Readiness polling kept running in that scope, so every new `systemctl` died at spawn, the unit read as `unknown`, and `health=ready` could never satisfy the managed-service requirement. `waitForGatewayHealthyRestart` now honours the enclosing scope's cancellation; the existing recovery path takes over from there.

Candidate admission passed `prepared.timeoutMs`, unset by default, so it used a fixed 120 s even though the step budget is 30 minutes. It now uses the inspection allowance derived from measured SQLite bytes, the same owner the rehearsal uses, capped by the step deadline. An explicit `--timeout` is unchanged. A candidate that hangs now takes longer to fall back; the Gateway is still serving during admission, so I accepted that.

The installed updater runs the first hop, so hops driven by a published updater keep today's behavior until a release containing this fix is the driver.

## Evidence

Native proof on Crabbox AWS Linux (c7a.8xlarge), systemd Gateway, process-group `SIGTERM`:

| Scenario | Before (main `5375b69c89b`) | After |
| --- | --- | --- |
| `SIGTERM` at `Phase: verifying`, small state | still polling 900+ s after the signal, killed by the lane; `service=unknown` 30 times while systemd said active/running | exit 143 in 11 s, `/readyz` ready, 0 `service=unknown` lines |
| `SIGTERM` at `Phase: verifying`, 3 GB state | not run on main at this exact point | exit 143 in 35 s, `/readyz` ready, 0 `service=unknown` lines |
| 3 GB state update, admission | fell back after 120 s (`Admission fallback: timeout`) | completed in about 187 s, `Update safety checks ran in the candidate updater` |
| 3 GB state update, total | rc=0, 1647 s, downtime 857 s | rc=0, 1770 s, downtime 888 s |

The diagnostic that identified the cause, from a patched driver: `systemctl --user status: signal; Command was terminated`.

Total time rises because admission now finishes instead of being abandoned. Timing comes from single runs and is not a clean A/B. Native proof ran on `6217c196307`; later commits change only docs and tests.

Tests:

- The cancellation regression fails with the fix reverted (`promise resolved ... instead of rejecting`) and passes with it.
- The admission budget test covers measured growth and the step-deadline cap.
- 98 tests across the restart-health, admission, and snapshot suites pass.
- `$autoreview` is scoped-clean and an independent Codex review returned NO FINDINGS.

Gaps:

- Proof ran on Linux only. The cancellation check is platform-neutral, but it was not exercised on Windows or macOS.
- The admission budget test is at the helper; the caller wiring is proven by the native lane.
- The interrupted run still logs a generic `Failed to reconcile gateway service ... AbortError` warning before recovery reports the interruption.
- A signal during update Doctor is unchanged: it exits in about 25 s but leaves the Gateway stopped with `rollback-state-unverified`, on main and with this fix. `openclaw update repair` exits 0 and names `openclaw gateway start`. That cause is not traced here.

Test lines: this adds a justified net 10 lines, recorded in `config/test-lines-allocations/update-interrupted-readiness-admission-budget.txt`.
```
