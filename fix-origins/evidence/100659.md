Fixes #186020

## What Problem This Solves

Middle-clicking **Open session** in a background-session completion toast does nothing.

## User Impact

The completed session can open in another tab while the current conversation or unsent draft stays visible. Normal left-click navigation is preserved.

## Why This Change Was Made

Render this navigation action as a native link using the existing session URL builder. Keep the captured Gateway-owner check for primary, modified, auxiliary, and context-menu events. Undo and Dismiss remain buttons.

## Evidence

- Real Chromium flow with a mocked Gateway: start a background session, complete it, then middle-click or Cmd/Ctrl-click the toast. Both open the expected session URL and preserve the current draft; right-click leaves the current page in place; left-click navigates once.
- The browser regression fails on the base because no new tab opens, and passes with the fix (3.76 seconds of test time; 6.47 seconds total).
- Existing toast tests: 19 passed. Background-completion tests: 20 passed, including stale Gateway/account/credential checks for alternative activation. Combined command wall time: 5.06 seconds.
- UI typecheck, targeted lint, formatting, and independent code review passed.

### Risk and coverage

No new state or navigation owner. Production delta: +43/-14 lines; test delta: +74/-1 lines. Browser proof uses synthetic Gateway responses; CI results are pending.
