## Fix PR #178650 description (by steipete, opened 2026-10-20T18:30:00Z)

```text
Related: #167796. Slice 1 of 4; the successor slices add controller-backed Automations execution and Claw review variants, migrate heartbeat declarations through Doctor, then remove retired heartbeat machinery and SDK exports. Each successor will start from the preceding landed result.

## What Problem This Solves

Fixes main-session scheduled reminders being recorded as successful before a session adopts them, then silently disappearing when the Gateway restarts.

## User Impact

Pending reminders remain running until their exact queued occurrence is adopted. A restart before adoption records one interrupted error and removes that occurrence without replaying it. No configuration or migration is required.

## Why This Change Was Made

The current Cron path treats a volatile queue insertion or heartbeat handoff as success ([original owner, lines 249–314](https://github.com/openclaw/openclaw/blob/4587f83864cbe77329aea2c27b3cd2d2cbba18cb/src/cron/service/timer-execution.ts#L249-L314)). The existing system-event queue now reports exact-occurrence adoption separately from removal, and Cron retains its existing durable running receipt and cancellation handle until that result. Ordinary prompt admission and dedicated Cron heartbeat prompts acknowledge only their selected events; coalesced exec turns leave deferred reminders pending. Waiting for admission does not spend the execution watchdog.

This is the live-defect slice of the Peter-approved heartbeat-to-Automations work. The other slices preserve the approved design and public-surface decisions; they are deliberately absent here. Existing boolean/void Cron dependency adapters retain their existing contract; the built-in Gateway supplies the adoption receipt. This does not guarantee exactly-once external effects after adoption.
