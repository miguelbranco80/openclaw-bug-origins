## Fix message body

```text
During candidate validation the new version's Doctor wrote bookkeeping-only config changes (meta, wizard) into the copied config; older updaters such as 2026.9.4 then reported a required config change and their repair refused it, a dead end. The config writer and Doctor now defer bookkeeping-only changes during rehearsal, preserving real migrations and normal metadata writes after activation. Released 9.4 validator now reports changedKeys=[]. Refs #169953 (the config.auth hang in that report is not reproduced).
```

## Fix PR #170195 description (by steipete, opened 2026-10-12T20:00:44Z)

```text
## What Problem This Solves

Released 2026.9.4 updaters can reject a successfully validated candidate with `repair-requires-config-change` when candidate Doctor changes only version, wizard, or migration bookkeeping in the rehearsal config.

Refs #169953. The reported `config.auth` hang remains unconfirmed and is outside this change.

## User Impact

Candidate validation preserves bookkeeping in the copied config, allowing older updaters to compare it without a false repair requirement. Real config migrations, webhook endpoint repairs, and plugin enablement remain intact. Normal writes after activation still persist current metadata. No new configuration, CLI options, schema, or dependencies.

## Why This Change Was Made

The candidate recognizes the complete rehearsal environment already supplied by released drivers. Config stamping defers metadata-only additions, Doctor leaves wizard history unchanged, and the existing state owner records webhook completion when no endpoint changed. Semantic migration changes and removal of deferred-migration markers still persist.

The reproduced `plugins` difference was actual activation: `plugins.allow` gained `openai` and `codex`, with their entries enabled. It was not install-record bookkeeping, so this behavior is preserved. The published-driver proof pre-enables those plugins to isolate bookkeeping.

The changed-path collector is moved unchanged to its existing owner to keep the writer within its line cap. The one-line `TransactionRecipes` visibility cleanup matches main commit `4cdac89cf0b656ef90cb22bb4fd3dfa9e7205bf9` and resolves the inherited dead-export gate.
```
