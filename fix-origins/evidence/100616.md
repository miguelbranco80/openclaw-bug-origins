```text
Closes #161051

## What Problem This Solves

Fixes native subagent spawns being rejected as unavailable after another agent replaces the shared Codex app-server client, even though the account remains signed in.

## User Impact

Users can continue multi-agent delegation after follow-up turns without manually refreshing the model catalog. A genuinely unavailable account or runtime still fails closed. No configuration change or migration is required.

## Why This Change Was Made

The spawn choice can read a published native readiness observation from a retired client. On a native readiness rejection, it now asks the existing catalog owner for one renewed observation and re-evaluates the same admission gate, including current ownership. If the renewed catalog no longer lists the selected model, admission fails closed instead of falling through to a synthetic host entry. If renewal fails, the rejection names the renewal error instead of incorrectly suggesting that the account must be restored. The config-write/published-choice path remains unchanged and does not perform network discovery under the write lock.
