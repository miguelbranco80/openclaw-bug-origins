## What Problem This Solves

Chat initialization could fail before replying when concurrent subagent maintenance changed prepared facts, even though SQLite confirmed rollback. CI also exposed a pre-existing model-fallback failure: retry instructions attempted to replace an already-dispatched user prompt.

## User Impact

Known rollback conflicts recover through the existing bounded initialization retry. Model fallback retains the original user turn and frozen projection while delivering retry instructions separately. Unknown transaction outcomes, mismatched receipts, and failed native-binding compensation remain terminal. No schema, stored-data, retention, permission, configuration, dependency, or update migration changes.

## Why This Change Was Made

Use the existing transaction settlement and serialized mutation-conflict owners, with the exact session-maintenance operation label. Do not add another retry owner. The prompt-state owner treats a fallback as internal continuation only when the factory-owned recorder confirms prior provider dispatch.

CI repairs preserve typed-error, native-write, resource-retirement, archive-retention, and recovery-owner assertions. Current main independently landed the earlier export cleanup and some fixture fixes.
