```text
Related: #189738

## What Problem This Solves

Unrelated Gateway updates can keep postponing the Control UI's pending boot-cache write, leaving reload recovery without the latest sidebar catalog.

## User Impact

Navigation, canvas-lease updates, and session-row activity no longer restart an unchanged boot record's write deadline. Actual catalog, identity, connection, and readiness changes still update the cache.

## Why This Change Was Made

The existing deadline protection only filtered session notifications. Gateway and agent notifications still reset the same timer. Compare the boot-record inputs at their shared persistence owner so every subscriber follows the same rule; retain the existing debounce for changed data.

## Evidence

- Scheduled run [41269343462](https://github.com/openclaw/openclaw/actions/runs/41269343462), `checks-ui (2/3)`, failed the boot-record deadline case.

- Focused Bun proof: 47 tests passed across boot-record and warm-boot recovery suites; original assertions remain intact.
- The same Bun deadline case passed 31 consecutive executions after the fix.
```
