## Fix message body

```text
* fix(config): name the rejected-config reason in directory-resolution warnings

readCurrentConfigForResolution degraded silently when the strict load
threw, emitting a generic 'Config unavailable' warning even for configs
that fail schema validation — the same files doctor repairs moments
later. Keep the degraded read, but surface the load failure through the
existing warning so operators see the actual rejection.

* test(config): assert the actual missing-file warning contract

Replace the wording-only negative assertion with a check of the full
plain availability message, so an accidentally appended rejection reason
on the absent-file branch would still fail the test.

---------

Co-authored-by: ruel225 <ruel225@users.noreply.github.com>
```

## Fix PR #167326 description (by ruel225, opened 2026-10-08T16:30:18Z)

```text
Closes #167314.

## What Problem This Solves

Directory inspection hides why an existing config was rejected.

## User Impact

Operators can see why their config was rejected while inspection continues with environment and default directory settings.

| Config state | Warning |
| --- | --- |
| Existing file rejected | Availability warning includes the original rejection reason |
| File absent | Existing plain availability warning |
| Valid file | No degradation warning |

## Why This Change Was Made

The warning retains the load failure; config admission stays unchanged.

## Evidence

- Paired Linux proof exercised actual Doctor config preflight and an admitted config repair with isolated state; the pre-fix control omitted the rejection reason.
- This does not claim a full Doctor health scan or live Gateway/service repair.
