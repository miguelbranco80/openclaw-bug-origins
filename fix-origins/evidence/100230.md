## Fix message body

```text
An in-place update replaces the package's hashed chunks while the old Gateway is still running. Shutdown then lazily imported cleanup modules that no longer existed: 2026.9.6 exited with ERR_MODULE_NOT_FOUND for the transcript capture-operations chunk, and other teardown paths (MCP runtime retirement, provider local services, browser relay and Chrome MCP, worker temp-artifact cleanup) had the same hazard.

Cleanup owners are now retained when their resources are created, so teardown never first-imports code. Transcript capture ownership moves into the eagerly loaded capture-startup module, and shutdown persists heuristic notes without starting optional model inference. Provider local services register their stop callback when they start. MCP cleanup has a lightweight owner module. Browser teardown peeks the lazy accessors that production ingress loads. The worker pool preloads artifact cleanup in its async preparation step before creating resources, which keeps chalk/tslog out of the native hook relay's static graph.

The provider-runtime-lifecycle stable tsdown entry stays, because published-update compatibility bridges map older hashed chunks onto it, and Knip treats it as an entry. Protection applies to updates from a release containing this change; older running Gateways keep the limitation, as docs/install/updating.md describes.

Proof: a built-runtime smoke removed 7,011 hashed chunks after startup and still shut down cleanly (exit 0, 6.3 s). Focused shutdown, transcript, worker-pool, browser and MCP suites pass, along with core types, import-cycle checks, Knip and the CLI bootstrap guard. Codex autoreview is scoped-clean. The final CI failures were main-side inventory breaks (wrapper components, suppression count), fixed on main by b3b34beebe08 and bd1138797711.
```

## What Problem This Solves

Fixes Gateway shutdown failing with `ERR_MODULE_NOT_FOUND` after an in-place update replaces the running installation's hashed bundles.

Related: #159699, whose published 2026.9.6 update proof exposed this failure.

## User Impact

Gateways containing this fix can finish cleanup after their package is replaced. This is fixed forward for updates **from** a release containing the fix: installing the candidate cannot repair code already running in an older Gateway, including 2026.9.6. Final transcript speech and deterministic notes are saved during shutdown; model notes can be regenerated afterward.

## Why This Change Was Made

Cleanup consumes state, callbacks, and module promises retained by the subsystem that created the resources. Transcript admission stays in its lightweight owner; Browser relay and Chrome MCP teardown use existing lazy module references; provider, MCP view, discarded-plugin-startup, and worker-artifact cleanup avoid first-loading implementations during retirement. Optional transcript inference is fenced during shutdown.

Worker preparation resolves one cached cleanup module in the pool's detached context before creating resources. Cancellation joins preparation and preserves caller-owned input settlement. Loading during worker preparation preserves the native hook relay's import budget. No Gateway-wide preload, startup budget increase, or timeout relaxation is added.

The audit covered session-end drain, plugin/channel close, sidecars, memory/database cleanup, and restart handoff. Loading a module elsewhere in the process is insufficient: Node can still resolve a new importer's first import against replaced files. Ordinary startup work and already-admitted turn execution remain separate from this cleanup contract.
