## Fix message body

```text
Commit 80778e082de5 started linking shared dist imports into each fresh plugin generation capture; later asset capture then tried to create the same destination exclusively and failed with EEXIST, so a fresh install's first setup.activate failed before any provider request (regression on main, not in 2026.10.6). Capture now tracks the shared-import links it created (and recovers existing ones at those exact paths) and skips only those destinations during asset capture; other collisions still fail. Fixes #181423, reported by @obviyus.
```

## What Problem This Solves

Fresh OpenAI setup can fail before its first provider request because plugin capture attempts to copy a shared file into a destination it already populated with a host-module symlink.

## User Impact

Shared import/asset references no longer cause `FsSafeError: creation target already exists`. Native Workers retain access to canonical host modules through capture recovery and disposal. No configuration, dependency, schema, or migration changes.

**Full packaged activation is not yet proven successful:** the smoke test reaches the local provider, then encounters further capture/packaging blockers described below.

## Why This Change Was Made

The overlap was introduced by [80778e082de5](https://github.com/openclaw/openclaw/commit/80778e082de5b30c079b5d7e6f38a2f0c3fd9fd3) (#181128). Shared imports create host links without entering copied-source bookkeeping; later asset capture reaches the exclusive file creator at the same destination.

The existing capture owner now records host-link destinations separately from copied plugin sources. Selective capture and recursive copying both preserve those destinations, including links retained during recovery. Denied file links still permit ordinary asset capture. Exclusive creation and host/SDK identity remain intact.

The regression extends the existing real Worker/recovery fixture with an import and an asset read of the same shared file. Production delta: +12/-1 lines; tests: +9/-1. The simplification pass retained one destination set shared by the two capture paths, with no new owner or fallback.
