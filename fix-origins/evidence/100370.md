## Fix message body

```text
* fix(sessions): keep transcript-byte latch unless accounting acts on the host transcript

Compaction accounting replaced transcriptByteCompactionLatch with whatever
the caller passed, so unlatched accounting (Codex native auto-compaction
facts) cleared a matching latch even though the host transcript stayed
oversized, re-arming the byte-fuse preflight every turn.

Accounting now takes an explicit transcriptByteLatch intent (set/clear);
absent intent preserves the stored latch. Only the byte-fuse refresh,
recordCompactionAccounting, and the SQLite compaction boundary pass intent.

* fix(sessions): clear the transcript-byte latch after manual host-rewrite compaction

Manual compaction entry points (the /compact command and the gateway
sessions.compact method) act on the host transcript, so their accounting
must lift byte-preflight suppression explicitly instead of inheriting the
accounting-only keep default introduced for native-thread rewrites.

* fix(sessions): clear the transcript-byte latch after automatic host compaction

Built-in automatic compaction commits a host successor (in place or as a
session rotation), but its accounting fact carried no latch intent, so the
accounting-only keep default preserved byte-preflight suppression across
the rewrite and the next turn skipped byte compaction for changed host
history. Durable facts now mark a committed host compaction, and both
persistence consumers clear the latch on that mark while native-only
accounting keeps the stored latch.

## Fix PR #168051 description (by ruel225, opened 2026-10-10T00:44:09Z)

```text
Fixes #168015

## What Problem This Solves

Fixes: native Codex auto-compaction clears a matching host transcript byte-fuse latch, causing another host compaction attempt on the next turn even though the host transcript is unchanged.

## User Impact

Oversized sessions avoid the redundant model request, latency, and compaction-start notice after native-only compaction. Current main already continues with bounded history after a failed byte compaction; this change fixes the remaining repeated-preflight defect. Host compaction can still clear or refresh suppression. No configuration, protocol, SDK, schema, or stored-format change is required.

## Why This Change Was Made

The shared accounting projection now preserves an omitted latch, sets a supplied value, and treats explicit `null` as clearing intent that survives the metadata-worker JSON boundary. Byte-preflight owners explicitly replace or clear their observation. Completed host rewrites carry a fact through reply, settlement, and direct-command accounting; folding a later native fact cannot erase that host fact. Manual native-only compaction preserves suppression, while manual host compaction clears it.

Maintainer cleanup removes the separate tagged intent type, shares the projection's parameter contract, removes repeated target fields, and simplifies the committed-result return without weakening session/writer authority. Private-state fixtures now use `InternalSessionEntry`.

Original fix by @ruel225; maintainer cleanup and complete consumer cutover by @steipete. Ordinary/follow-up regression coverage incorporates @xydigitLybnnnn's overlapping #168095, with verified human co-author credit in the maintainer commit. That PR remains open pending the coordinator's landing decision.
