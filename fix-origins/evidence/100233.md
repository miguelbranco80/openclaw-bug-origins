## Fix PR #151247 description (by steipete, opened 2026-09-17T23:31:49Z)

```text
Related: #151198 (Control UI request-side fix).

## What Problem This Solves

Fixes synchronized Control UI metadata refetches after model-call auth bookkeeping.

Reported production Gateway ledger evidence from September 17, 2026, 21:00–21:20 UTC: all approximately 25 Control UI connections produced bursts of 20–49 `models.authStatus`, `models.list`, and `chat.metadata` responses within one second. There were 60 bursts in 20 minutes, in clusters of 6–8 bursts approximately 3 seconds apart, separated by 30–300 second gaps. Of those bursts, 53 coincided with model-fetch activity within −3 to +1 seconds. At 416 model responses/minute, `models.authStatus` reached 2.8 requests/second, the largest reported Gateway request-rate amplifier.

## User Impact

Ordinary auth usage updates stop invalidating metadata across connected clients. Credential changes, profile additions/removals, ordering and ownership changes, and cooldown/blocked-state transitions still refresh model metadata. Usage accounting remains intact.

## Why This Change Was Made

Model-call bookkeeping replaces runtime auth snapshots and advances their full revision. Chat metadata used that revision in its generation facts, so subsequent reads or catalog events rebuilt metadata and broadcast `chat.metadata.changed`; clients then invalidated both metadata and auth-status caches.

Current main already suppresses most direct bookkeeping notifications, but its `runtimeInheritsMainState` marker can change solely because inherited usage changed. That still notifies listeners, retires matching prepared-model owners and dispatch state, and cascades through publication events. Conversely, its old ownership comparison omitted cooldowns entirely.

The auth snapshot owner now uses one comparison for metadata revisions and mutation notification. It includes credentials, profile ordering/provenance, owner rebinding, and availability deadlines/model scope, including inline API-key health. It excludes last-used timestamps, counters, success history, and the bookkeeping-derived inheritance marker. The separate replacement ownership comparison is removed. Chat metadata consumes this new per-store revision; full snapshot revisions remain unchanged for rollback and secret-activation fencing, and credential revisions/materialization invalidation retain their existing contracts.

Cooldowns are included because the model-list/metadata availability builders expose availability, failure reason, and retry time. Admin-only `models.authStatus.lastUsedAt` remains readable but intentionally does not trigger global invalidation. UI behavior changes belong to #151198.
