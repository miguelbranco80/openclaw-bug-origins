Closes #192066
Reported-by: [mtblackman16](https://github.com/mtblackman16) in #192066.

## What Problem This Solves

Update rehearsal can reject a healthy installation when an exec SecretRef needs credentials that intentionally remain outside disposable scratch state. The private candidate now leaves that capability cold and records an availability warning while validation continues.

## User Impact

An unavailable exec-provider prerequisite during private rehearsal produces a recorded warning rather than a failed update check. The existing snapshot receipt carries that warning into the update run report. Authored SecretRefs remain references; normal Gateway activation still checks credentials against the serving installation. Structural reference errors and explicitly required data/auth owner policies retain their checks.

## Why This Change Was Made

Rehearsal must not execute real secret providers or touch real credentials. Resolving against the real state root would cross that boundary even if intended to be read-only, because arbitrary exec-provider code can read or write there. The shared resolver therefore defers exec dispatch under the complete private-rehearsal contract, and the existing owner-isolation path leaves optional and legacy capability inputs cold. No credential files or resolved values are copied into rehearsal state, and no config option, schema, SDK contract, or protocol is added.
