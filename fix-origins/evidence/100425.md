## Fix PR #159760 description (by steipete, opened 2026-09-27T15:42:42Z)

```text
## What Problem This Solves

`docs/cli/index.md` ("JSON failures") promises that a command in JSON output mode that fails exits nonzero and writes one `{"ok":false,"error":{"type":"cli_error","message":...}}` document to stdout. `openclaw config unset browser.enabled --json` exited 1 with **empty stdout**, printing `--json can only be used with --dry-run.` only on stderr. `config patch --json` failures behaved the same way. Scripts that parse `--json` output got nothing parseable. Found by live QA on `main` (`244d4419723`).

## Why This Change Was Made

`handleConfigMutationError` (`src/cli/config-cli-runner.ts`) emitted JSON only when both `--dry-run` and `--json` were set, so it lost the caller's JSON output intent. Callers now pass that intent explicitly:

- `config set`: only `--dry-run --json`, because plain `config set --json` is the documented value-parsing alias, not an output mode.
- `config patch` and `config unset`: `--json`.

The handler reuses the shared `formatCliJsonFailure` envelope. Existing `--dry-run --json` results are unchanged. `exitCliAfterOutput` is typed `never`, so a failure writes exactly one JSON document. The related JSON tests were consolidated to stay under the test-file line cap; coverage is unchanged.

## User Impact

`config patch` and `config unset` in `--json` mode now return the documented machine-readable failure envelope on stdout, consistent with the rest of the CLI.

## Evidence

- Regressions for patch and unset failed on `main` because no JSON was emitted (with 6 passing controls). They pass now, and all 231 config CLI tests pass.
- Blacksmith Testbox: `node scripts/check-changed.mjs` passes.
- Rebased cleanly onto #159708, which touched the same handler. The merged handler emits the declined-write wording inside the JSON envelope. Exact-head CI covers the combination.
- Independent Codex autoreview through P2 is clean (0.91). It confirmed one envelope per failure, no stdout output in non-JSON modes, and preserved `set --json` alias semantics.
- LOC: production +23/−3, tests/support +84/−24.
```
