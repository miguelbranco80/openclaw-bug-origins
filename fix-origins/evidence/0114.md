## Fix PR #196742 description (by obviyus, opened 2026-11-10T16:12:42Z)

```text
Fixes #196717. Thanks @yixiaoer-520 for the report and the wire capture.

## Problem

Every Gemini or Vertex turn that exposes the built-in `read` tool fails with HTTP 400. The `read` tool declares `optional` as the boolean literal `true`, and the Gemini schema cleaner sends it as `{"type": "boolean", "enum": ["true"]}`. Google accepts `enum` only on string schemas with string entries (`Schema.enum` is `repeated string`, "Possible values of the element of Type.STRING with enum format" in `google/ai/generativelanguage/v1beta/content.proto`), so the whole request is rejected.

## Root cause

`cleanSchemaForGemini` stringifies `const` and `enum` entries. #104567 (1338b0d) first stringified them and retyped the schema to `string`; its final revision (80559325) deliberately kept the declared type "so tool argument generation and runtime validation still agree": a string-typed `optional` would make Gemini send `"true"`, which the canonical `Type.Literal(true)` validation (#185581) rejects. Keeping the type while emitting string entries leaves a non-string schema with an enum, which Google rejects. #182390 (5eab3f5) last touched this cleaner but only made `type` scalar; it does not change enum handling.

## Fix

In the Gemini cleaner, keep `const`/`enum` (stringified, as before) only when the declared type is `string` or absent. For any other declared type, keep the type and drop the enum. `read.optional` now goes out as `{"type": "boolean", "description": ...}`: Gemini accepts it, the model still generates a real boolean, and canonical validation still accepts only `true`. Numeric enums follow the same rule. Non-Gemini providers and string enums are unchanged.

## Evidence

Built Gateway (`pnpm build`, `openclaw gateway run`) on secretless Docker, Node 24.22.1. One `openclaw agent` turn through the Gateway per provider, with the default tool set (14 tools, `read` included). The Gemini provider (`google-generative-ai`) points at a local stand-in that applies Google's enum rule (enum only on STRING schemas with string entries) and answers violations with Google's `INVALID_ARGUMENT` 400 body; it records every request. Control provider: OpenAI-compatible on the same stand-in.

- Main `3686da563c54` (2/2 runs): Gemini request rejected, `* GenerateContentRequest.tools[0].function_declarations[9].parameters.properties[optional].enum: only allowed for STRING type`; the turn fails (`LLM request rejected ... | 400`, exit 1).
- Candidate `aa23553561d7` (2/2 runs): Gemini request accepted (200) and the turn completes. In run 2 the stand-in answers with `read({"path":"missing-196717.txt","optional":true})` (a real boolean); canonical validation accepts it and the real `read` tool returns `Optional file not found: missing-196717.txt.`
- `read.optional` on the Gemini wire: main `{"type":"boolean","enum":["true"],"description":...}`, candidate `{"type":"boolean","description":...}`.
- Controls: the other 13 Gemini tool schemas are byte-identical; the rest of `read` is unchanged; all 7 string enums (for example `exec.host`, `github_publish.action`) are unchanged; the OpenAI-compatible request's 14 tools are byte-identical to main (`read.optional` stays `{"type":"boolean","const":true,...}`).
- Focused tests: `clean-for-gemini`, `tool-search-runtime`, `agent-tools-parameter-schema`, `agent-tools.schema`, `agent-tools.prefix-stability`, `message-tool-schema` pass. The updated `clean-for-gemini` and `tool-search-runtime` cases fail on the base source (3 failures) and pass on head.

Captures: run 1 https://github.com/openclaw/openclaw/pull/196742#issuecomment-6772545537, run 2 with the tool-call round trip and the base-failing tests https://github.com/openclaw/openclaw/pull/196742#issuecomment-6772889817

Not covered: there is no live Google key in this loop, so acceptance is shown against the documented rule (`Schema.enum` in `google/ai/generativelanguage/v1beta/content.proto`) and the same real Gemini error other clients report for this shape (https://github.com/anomalyco/opencode/issues/28397), not a live Gemini call.
```
