## What Problem This Solves

An ingress monitor can retire claim ownership during shutdown while an accepted completion, release or failure write is still pending, allowing a replacement drain to race that settlement.

## User Impact

Shutdown joins already-started settlement writes before releasing claim ownership. If a write fails while the drain still owns the claim, shutdown reports the error and retains custody. Callback grace remains bounded, and standalone drains retain their existing abort/recovery behavior.

Existing databases, config, payloads, dedupe, retention and recovery policy stay unchanged. Updates require no migration or operator action. The maintainer approved the storage execution and settlement work in this stack.

## Why This Change Was Made

Register settlement before calling the write, retain the monitor-owned drain through settlement, and remove finished deliveries before failure handling awaits a write. Reuse the existing drain and monitor lifecycle; add no competing queue or shutdown owner. Deferred handoffs remain tracked even when adoption begins before delivery returns.

The exported drain function gains a backward-compatible optional retention argument and a joined-disposal overload. All existing calls retain their previous default. Monitors use the new path immediately. No schema or config changes are introduced.

This lifecycle change stays together because retirement, settlement tracking and joined disposal enforce one custody contract. The larger diff includes formatter-required indentation around the existing monitor options and shared fixture extraction; it does not add a second implementation.
