Closes #167675 — macOS status stays silent when isolated HOME selects an unrelated native service.

## What Problem This Solves

Fixes `status` producing no output beyond a caller's deadline when isolated macOS state/HOME causes diagnostics to wait on an unrelated native Gateway installation.

## User Impact

Isolated status callers receive the selected Gateway's report promptly instead of borrowing the host service's startup grace. Normal canonical native cold-start waits are retained. No new options, config/schema changes, migrations, dependency changes, or operator action.

The external report's exact argv, environment, and 30-second deadline owner remain unknown. This fixes an independently reproduced matching defect; it does not claim that the reporter's setup has been conclusively identified.

## Why This Change Was Made

Readiness elected a native service without checking whether that installation owned the selected state/config. With relocated HOME, strict macOS LaunchAgent command inspection fails while the real user's GUI domain still contains the unrelated job. The failure becomes unknown runtime and receives native startup grace. Piped report collection remains silent until readiness completes.

Reuse the existing canonical-install predicate, already used by native service status, at both native-command and native-runtime election boundaries. Foreground owner leases, verified legacy locks, selected-port listeners, migration handoff, and health checks remain on the same readiness flow. No timeout increase, retry, catch-and-mask path, or parallel fallback flow.

Production LOC: +30/-22 (net +8, including import/ternary reflow); tests: +19/-6 (net +13). The production growth adds the missing ownership fact once, reuses it at both election boundaries, and documents why unrelated inspection must not receive startup grace.
