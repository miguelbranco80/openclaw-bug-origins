## Fix PR #153010 description (by steipete, opened 2026-09-19T15:52:55Z)

```text
## What Problem This Solves

Fixes stale or missing session history after a managed write rolls back or a backup replaces the database.

## User Impact

History reflects committed messages and the current database. No migration, configuration change, or operator action is required.

## Why This Change Was Made

Shared recent/reset caches could retain an uncommitted snapshot whose generation and sequence were later reused. Reset/control entries could also survive a connection replacement. The existing transaction owner now identifies scopes that must bypass shared caching, and reset/control entries bind to the native database connection.

This preserves the existing cache keys, capacity, byte limits, caller-owned results, read fences, and incognito handling. Production code grows by 14 lines; no SQL, index, or schema changes are included.

## Evidence

- Four new regression cases fail on the original implementation. Six retained cache tests pass on the final diff; the broader history and Gateway readonly validation passed 75 tests across 10 files during the investigation.
- The complete changed-code gate passes: typechecking, formatting, lint, all three dead-code scans, repository guards, and zero runtime import cycles.
- Standalone real SQLite API probes verify rollback, reset rollback across reopen, physical backup replacement with matching generation/cursor, caller ownership, rewrites, and incognito boundaries.
- A mixed 16-session workload passes 128 exact parity comparisons with identical baseline/candidate traces: four misses and 78 payload parses per 64 reads. Median round p50 is 0.0798 ms baseline / 0.0790 ms candidate across four rounds of 384 reads. This shows no material regression, not a general latency improvement.

Validation is local synthetic SQLite, not a new live Gateway or Linux/Windows run. Raw manually opened transactions remain outside the managed-scope contract. Standalone physical-replacement fixtures logged maintenance-worker rejections during cleanup; their assertions and all cleanup calls completed, and the warnings are retained in the evidence.

Hosted CI on the first head failed because main moved `rejectConfigNonFiniteNumbers` without updating its include-writer import. The exact upstream repair is #153007. This PR remains draft until that fix lands and fresh CI can run against the final head.
```
