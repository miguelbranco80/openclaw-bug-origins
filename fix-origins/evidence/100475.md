```text
Matrix attachments sent without a caption carry their default filename in `body`. After media resolution succeeded, the monitor still forwarded that filename to the agent as user-authored text. Recognized media whose explicit filename equals its body now uses the already-resolved attachment placeholder. Real captions are kept, including filename-looking captions that differ.

Proof: a built Gateway with the Matrix plugin against a private local Synapse homeserver, with a real PNG uploaded and resolved. The base model request contained "IMG_1234.png" as user text; with this change it contains the "[matrix media]" placeholder. Controls (differing caption, filename-looking caption, missing filename, plain text) all match base. The regression tests fail on base and pass here.

## Fix PR #165419 description (by ooiuuii, opened 2026-10-05T07:28:57Z)

```text
Closes #165416

## What Problem This Solves

Matrix attachments without captions were forwarded to the agent with their default filename as user-authored body text even after media resolution succeeded.

## User Impact

Recognized media with an explicit filename equal to its body now uses the resolved attachment placeholder. Genuine differing captions, including filename-looking captions, retain their original text. Missing/blank filenames and non-media messages keep their existing behavior.

## Why This Change Was Made

The successful-media branch bypassed the existing Matrix attachment classifier. This reuses that owner for explicit filename metadata rather than guessing from extensions. Downloads, transport, authorization, failed-download markers, pending group history, and the separate audio-preflight heuristic are unchanged.

Thanks to @ooiuuii for the report and fix. The contributor's commit is unchanged. No overlap with Pash/Sarah changes in the two changed files.

Registered separate bot/sender accounts, created rooms through the Matrix client API, uploaded a real PNG through the media API, and sent `m.room.message` events through the client API. The Gateway performed its normal Matrix sync, media download, ingress handling, and model dispatch.
