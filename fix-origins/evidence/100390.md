## Fix PR #178701 description (by steipete, opened 2026-10-20T19:10:15Z)

```text
## What Problem This Solves

PostgreSQL sends a separate event insert and identity insert for each ordinary transcript append, adding three database round trips to a normal input, tool-result, and final-answer turn.

## User Impact

Ordinary PostgreSQL appends use fewer round trips inside their existing transactions. Transcript bytes, identity and idempotency behavior, SQLite writes, locks, and final commit authority remain unchanged. No migration or configuration change is required.

## Why This Change Was Made

The payload inserter can write the event and its identity in one PostgreSQL statement. The identity insert consumes the event's RETURNING rows; the final result reports event acceptance even when an identity conflict is ignored. The existing event-ID guard is preserved for cold scalar appends, while complete resident actors retain their own identity check.

Existing-owner key relocation keeps its ordered path: accept the event, clear the former owner's key, then insert the new identity. Batch/import and strict replacement paths retain their existing writers. The repeated window-touch conditions are carried into the same helper without changing when it writes.

## Evidence

The real actor regression fails on base `03834a76775d` with six event/identity insert trips and passes with three. Its three BEGINs, COMMITs, and advisory locks are unchanged. Exact transcript, identity, active projection, index watermark, search rows/results, replay, rollback, and revoked final commit checks are preserved.

Both-engine semantic tests cover duplicate events and idempotency keys, scan-assistant collisions, successful and rejected ownership relocation, and rollback. A direct PostgreSQL owner test also checks that an ignored identity conflict still reports an accepted event, while an unrelated unique-key conflict rolls the event back.

Final focused proof: **72/72 tests across six files**, including the existing payload, batch, store, and timestamp suites. Infra test execution: 45.48 s; runtime-config execution: 29.47 s; complete wrapper: 155.53 s. The exact PR1 baseline passes all eight original identity cases. Core and infra test typechecks, scoped lint, formatting, and Kysely guardrails pass. Independent Codex review is clean through P2. Production: +103/−42 lines (net +61); tests: +389; test routing: +1.

Initial CI identified a type-only import cycle; the binding type now derives from the already imported database schema. The exact failed Madge check passes with zero cycles, core typechecking passes, and the type-only repair has a separate clean review.
```
