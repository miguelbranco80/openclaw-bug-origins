## Fix PR #200787 description (by steipete, opened 2026-11-17T20:25:57Z)

```text
## What Problem This Solves

Changed sandbox commands in large local workspaces create and retire a filesystem snapshot for each checkpoint. On btrfs, snapshot creation can force filesystem-wide transaction work, while recursive retirement adds metadata work that competes with other Gateway writers.

## User Impact

Changed command checkpoints now pause their own guest while saving an immutable Git result, then resume before canonical publication. Command completion still waits for acceptance, unchanged commands remain pause-free, and later guest writes remain available for the next checkpoint. No configuration, schema, dependency, or host changes are required.

Owner accepts +~290 ms guest pause per changed command checkpoint (APFS measurement; btrfs unmeasured) in exchange for removing per-checkpoint btrfs snapshots/removals (2/2 → 0/0 per trace; −21 LOC), because each snapshot forces a global btrfs transaction commit on Team (production evidence: 11:40–12:10 PST Gateway SQLite waits 9–19.6 s, RPC p99 52 s).

The owner will verify guest pause p50/p99 on btrfs using `Local workspace unpause` logs after deployment. Revisit this trade-off if p99 exceeds 3 seconds. This PR does not deploy or change the host.

## Why This Change Was Made

Use the existing direct-capture and pause owner for ordinary command checkpoints. Remove the inventory-size/probe-duration snapshot selector and its plumbing (−21 production LOC). Reconciliation retains its existing snapshot, fallback, recovery, and bounded asynchronous retirement paths. The relevant tests now exercise snapshots at that remaining owner.

The unchanged probe already skips identical-content rewrites, identical atomic replacements, and ignored-output churn. An empty journal or unchanged Git commit alone cannot establish that guest files are unchanged. A time-based checkpoint skip would violate read-after-command acceptance; waiting for a timer would add completion latency.

Source inspection confirms that the btrfs branch of `@openclaw/fs-safe` 0.27.1 already issues one snapshot ioctl. This removes snapshot requests rather than replacing a per-file copy with an already-existing native snapshot. Retirement renames the capture before recursively removing it; it does not copy dependencies into the retired directory.

## Evidence

A/A/B used a synthetic 62,000-file, 1,100,004,000-byte projection: 22,000 eligible files and 40,000 dependency files. The ten-step trace included reads, identical rewrites, ignored dependency/artifact churn, one source edit, an identical atomic replacement, and one deletion. Every step verified canonical content/deletion and retained dependency content. All arms produced identical results.
```
