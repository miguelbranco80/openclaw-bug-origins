```text
## What Problem This Solves

Fixes: packaged upgrades fail during package activation when npm temporarily removes an install root reached through a POSIX directory alias such as macOS `/var` → `/private/var`.

## User Impact

Users can update a global npm installation through the normal updater without a false “requires its original POSIX npm directory” rollback.

## Why This Change Was Made

The update executor records the canonical installation identity while the package still exists. During activation, npm has temporarily removed that leaf; root resolution previously fell back to the raw alias spelling and rejected the same installation. The resolver now canonicalizes the existing parent only when the leaf is genuinely absent. Existing unresolved leaves, including dangling symlinks, remain fail-closed.

Update behavior: the installed updater still runs first. Candidate-side activation consumes the authority it recorded, canonicalizes only the missing package slot through its existing parent, and retains the same ownership, recovery, and rollback checks.

## Evidence

- Full Release Validation candidate run 36996097151 reproduced the failure in both macOS packaged-upgrade lanes for the exact `2026.9.7` → `2026.9.8` published-driver × candidate path.
- The regression fails before the fix on the missing leaf under an aliased parent and passes afterward; a dangling-symlink negative control remains unresolved/fail-closed.
- `pnpm test src/infra/package-update-publication-boundary.test.ts --maxWorkers=1`: 12/12 passed. Warm-cache wall 13.08 s; final cold compiler generation wall 31.62 s. The file exercises the real package publication boundary; the added assertions do not add a process boot or timer.
- `node scripts/check-changed.mjs`: passed on the final source.
- Independent P2 autoreview: scoped-clean after resolving its dangling-symlink ownership finding.
```
