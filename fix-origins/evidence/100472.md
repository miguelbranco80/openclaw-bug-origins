## What Problem This Solves

Fixes `gateway probe --timeout` exceeding its advertised overall budget when discovery is slow or finds many Gateways.

## User Impact

Known local and explicit Gateways are checked while discovery runs. Discovery, SSH configuration and tunnel setup, connections, and read checks share one deadline, and unfinished checks report a timeout. Existing options and standalone discovery behavior are preserved; no migration is needed. Connection and process cleanup can briefly extend elapsed command time.

## Why This Change Was Made

On the integrated main base (`431f80cf7ac4`), `src/commands/gateway-status.ts:135` resolves SSH configuration before cancellation exists, `:232` waits for discovery before probing known targets, and `:308` gives probes a fresh budget. `src/infra/bonjour-discovery.ts:264` also restarts the timeout for each DNS-SD resolution.

The command owns one monotonic deadline and cancellation signal. Its existing discovery, SSH, and probe owners consume the remaining budget. Direct checks on the tunnel's preferred loopback port finish before the tunnel can bind it, preserving credential routing. Main's consolidation in `32e8d817f7d1` is retained: SSH resolution and auto-discovery remain in the command, and the deleted `gateway-status/discovery.ts` is not restored. No additional timeout manager, fallback, or public option is introduced.

Against the integrated main base: production +229/-153 (net +76), tests +136/-6 (net +130), documentation +5/-0. The added production code supports concurrent checks and cancellation through the existing owners.
