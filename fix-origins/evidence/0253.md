## Fix message body

```text
fix(skills): stop skills status reads when skills list, info or check is interrupted

openclaw skills list, skills info and skills check read skills.status without the command's abort signal, so Ctrl-C or SIGTERM left the read running until the Gateway call timed out; the command then fell back to a local scan and printed the full report after the interrupt. The status read now takes the command's abort signal, matching skills update. Uninterrupted runs, missing-skill and auth failures, and skills update are unchanged. No new text.

Evidence: the built CLI in a secretless node:24.22.1 container against a real gateway run behind a relay that holds the skills.status reply, skills list, info and check, plain and --json, SIGINT and SIGTERM, main twice and candidate twice. On main the read kept going for about 1.9 s after the signal and the full late report printed. With this change the command exits 130 or 143 within about 0.03 s and prints only the existing interrupt line. Uninterrupted output, a missing skill, a wrong token and skills update --all behave the same on both. Net -1 test lines. Details: https://github.com/openclaw/openclaw/pull/198298#issuecomment-6856832229.

Thanks @Alix-007.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```
