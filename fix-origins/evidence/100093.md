```text
## What Problem This Solves

Fixes Android release uploads stopping after a successful build when Android SDK build-tools 37 verifies the APK.

## User Impact

Android release jobs can verify correctly signed APKs and reach the upload stage. Wrong signing certificates and multiple signers still fail closed. This change does not retry a release or modify store state.

## Why This Change Was Made

Build-tools 37 reports an unrotated signer as `V2 Signer:` rather than `Signer #1`. The existing verifier now recognizes the scheme-prefixed labels without changing cryptographic verification, the single-certificate requirement, or the pinned certificate fingerprint.

## Evidence

- [Android Internal distribution failure, run 39134315947](https://github.com/openclaw/openclaw/actions/runs/39134315947/job/117695617583): the unchanged main parser rejects the APK certificate output before upload.
- The exact retained APK from the original failed run verifies cryptographically with official build-tools 36 and 37; the repaired production `--verify-apk` entry point accepts it with build-tools 37.
- Expanded regression: four failures with the original parser, then **9/9 passing** with the repair, including wrong-certificate and multiple-signer rejection. Test time: **0.791 s**; wrapper wall time: **2.01 s**. CI timing is not yet available.
- Targeted typecheck, lint, formatting, and whitespace checks passed. Independent full-context P0–P2 Codex review completed with no findings.
- Preparation against pinned current main found the consumer, test, signing manifest, Fastlane caller, SDK setup, relevant tool versions, and retained repair unchanged; the earlier proof remains candidate-bound evidence, not current-head CI.

No new release build, store upload, or device qualification was run. Current-head CI and normal publication/review gates remain required.
```
