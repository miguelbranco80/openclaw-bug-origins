## Fix PR #150623 description (by goutamadwant, opened 2026-09-17T05:25:12Z)

```text
Closes #150579

## What Problem This Solves

Fixes: stale-usage preflight triggers unnecessary compaction after a session has already compacted but retains a large display history.

## User Impact

User impact: healthy compacted sessions proceed without another budget compaction. Genuinely oversized active contexts still trigger compaction.

## Why This Change Was Made

Use the existing asynchronous canonical model-context reader for the no-usage estimate, preserving the summary, retained tail, tool pairs, and newer messages while excluding superseded history. Headerless legacy projections retain their existing fallback.

The contributor's implementation and commits are preserved. Removed an unused re-export left by an earlier revision. Strengthened the real-Gateway regression to assert that no second compaction entry is persisted: one model request alone was not sufficient, because the baseline performed an unnecessary compaction without an extra provider request.

The new reader also recognizes an explicitly selected incognito database, not only an incognito-shaped session key. Such databases stay with their existing process-local owner instead of being reopened as empty worker-local databases.

No overlap with Pash/Sarah changes. Thanks to @goutamadwant for the fix and @BillBOT33 for the report.

## Evidence

Secretless Docker, built runtimes, synthetic persisted sessions, explicit isolated profiles, loopback mock Anthropic transport, and real authenticated Gateway `agent` turns. Baseline: current main `3f263ba918c56e5c227261cb67be910e64bef74d`.

Each healthy fixture retained 650,000 characters of superseded history behind a compaction boundary, with a short summary/tail and stale usage. The model window was 100,000 tokens; the blocking threshold was 80,000.

| Candidate, genuinely large active context | 93,758 | 93,765 | Budget compaction triggered and completed; reply completed |
```
