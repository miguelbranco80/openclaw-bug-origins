## Fix PR #179067 description (by steipete, opened 2026-10-21T05:35:16Z)

```text
Closes #168440
Related: #168441

## What Problem This Solves

A paired Mac appears again under **Connected without pairing** because its native presence beacon supplies an installation ID but omits its authenticated device ID.

## User Impact

New native Mac beacons associate with the existing paired device instead of creating another unpaired row. A pre-existing stale row can remain until the normal five-minute presence expiry.

## Why This Change Was Made

Use the authenticated connection's device identity only for macOS `Node:` beacons that omit one. Explicit beacon IDs, ordinary events, CLI clients, and device-less connections keep their existing behavior. This narrows the repair proposed in #168441; thanks @edosulai for identifying and fixing the original cause.

Production delta: **+6 lines** across one production file, with an owning regression and documentation update. No performance claim, new state, cleanup mechanism, or authentication policy.

## Evidence

- `system-event-routing.test.ts`: expected missing-device failure on base; **14/14 pass** with the repair. Green wall time 158.81s (136.68s Vitest), dominated by compilation.
- Synthetic Devices browser proof: **1/1 pass**, 5.477s scenario / 30.35s invocation. The same paired Gateway/operator/node remain; the extra unpaired Mac disappears. This is a real UI projection with synthetic Gateway responses, not a live macOS-app run.
- Formatting, scoped lint and diff checks pass. PR CI supplies broad runtime and static proof.
```
