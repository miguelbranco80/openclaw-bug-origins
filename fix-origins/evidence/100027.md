## Fix message body

```text
* fix(gateway): classify work interruptions before restart recovery

Why: Untyped session-work interruptions were recorded as gateway restarts even
when the Gateway had not restarted. The durable running/aborted row could then
admit a duplicate recovery turn after an ordinary message or lifecycle action.

What: Keep restart classification in the session admission owner and require an
explicit restart abort or Gateway drain. Route the four affected run handlers
through that classification while preserving their existing ownership checks.
Replace timer-bound classification tests with synchronous interruption and add
registered Gateway admission-to-persistence proof for ordinary and restart cases.

Evidence: 24 focused tests pass across reply, Gateway, command, and recovery
suites. Gateway test observes the persisted SQLite row after event subscription
and confirms ordinary interruption is inactive while explicit restart is
recoverable. Assertion, line-cap, and max-lines ratchets, oxlint, and Sol review
pass. Full core test typecheck was stopped after 11 relevant shards passed;
remaining coverage is delegated to exact-head CI.

* fix: preserve cancellation in serialized command admission

The outer recovery owner still replaced ordinary interruption errors with
restart aborts before the inner command saw them. Forward the original
reason while retaining serialized admission and exact recovery ownership.

The existing command regression exposed both false restart classification
and replacement of the explicit restart reason on the prior candidate.

* test: expect ordinary cancellation during reply lifecycle changes

Keep the plugin fallback notice regression aligned with ordinary admission
interruption, which no longer records a Gateway restart.
```

## What Problem This Solves

Fixes duplicate restart-recovery turns and blocked new messages when an ordinary session interruption is mistaken for a Gateway restart.

## User Impact

Interrupting an active turn lets the new message run without replaying the canceled turn. Stop remains terminal, and genuine Gateway restarts still recover interrupted work once per restart.

## Why This Change Was Made

Five admission paths were replacing ordinary cancellation reasons with restart errors, including the newer outer serialized command admission. Preserve the original reason and use the existing typed restart predicate where an outcome must be selected. The recovery owner receives the correct facts without another classifier, new state, or changes to registry-derived liveness, FIFO admission, exact recovery claims, or yielded continuation custody.
