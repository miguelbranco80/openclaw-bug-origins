## Fix message body

```text
Related: #159184

## What Problem This Solves

Fixes repeated same-model requests when an HTTP 400 rejection carries a generic transient inner code such as `rate_limit_exceeded`.

## User Impact

A rejected request now returns promptly or advances to a configured fallback instead of waiting through nine identical failures. Genuine throttling and server errors still retry.

This deliberately preserves existing rate-limit presentation, logging, cooldown and fallback reasons; it does not change the generic rate-limit error copy to prompt-size guidance. No settings, defaults, protocol or storage changes.

## Why This Change Was Made

The classifier records that a non-transient 4xx is not eligible for same-model retry when only its generic inner code makes it transient. The existing recovery gate consumes that fact for assistant failures and thrown provider exceptions, including coerced failover errors. HTTP 408/409/410/429/499 retain their previous policy. Independent transient message/detail evidence, Bedrock's structured `ThrottlingException`, and prepared provider-hook decisions remain eligible.

A blanket `400 => format` change would break intentional behavior: #133772 preserved structured-code presentation, including `RESOURCE_EXHAUSTED` behind a generic HTTP 400 invalid-request wrapper, and the existing corpus covers real Bedrock-style HTTP 400 throttling. Both remain unchanged and green. JSON error prose is evaluated separately from its code so the code cannot count as independent evidence for retrying itself.

[Ayaan accepted this broader retry policy](https://github.com/openclaw/openclaw/pull/159221#issuecomment-5852010332), including immediate fallback/failure for a genuine throttle that supplies only a generic transient code behind a non-transient 4xx.

## Evidence

Real isolated Gateway turns, using fresh builds and a local scripted OpenAI-compatible HTTP provider; no paid provider calls. Baseline: `4b225bae`; measured fix: `e02adc94`.

| Response | Baseline requests | Fixed requests | Observed result |
| --- | ---: | ---: | --- |
| HTTP 400 + `rate_limit_exceeded` + reported prompt-size prose | 10 | 1 | CLI completes in 1.54 s instead of 118.26 s; no same-model backoff |
| HTTP 400 + same code + generic `Request rejected` | — | 1 | Error surfaces in 1.33 s |
| HTTP 400 without an inner code | 1 | 1 | Same schema-rejection result |
| HTTP 429, twice, then success | 3 | 3 | Recovers successfully |
| HTTP 503, twice, then success | 3 | 3 | Recovers successfully |
| HTTP 400 `ThrottlingException`, twice, then success | 3 | 3 | Recovers successfully |

Baseline failing-request offsets were 0, 1053, 2220, 4972, 11518, 21524, 51629, 66995, 85563 and 115957 ms. The fixed fallback runs each made one rejected request followed by one successful next-model request, both with and without the inner code. The Bedrock control uses its response shape through the local compatible transport, not a live AWS call.

- The three classifier rejection cases fail on baseline and pass with the fix. Recovery-boundary tests also failed for raw and coerced prompt exceptions before repair; both now advance to fallback without backoff. Independent detail prose remains retryable, while the SDK's flat JSON `{code,message}` cannot promote its code into prose.
- 947 tests across seven classifier, classification corpus, structured presentation, error-normalization, attempt recovery and retry-controller suites passed in 26.66 s on `e02adc94`, then passed again in 42.19 s on `c606f7e9` after merging current main once. Existing #133772 copy and Bedrock corpus assertions were not changed.
- Fresh baseline and `e02adc94` builds, core types, scoped type-aware Oxlint, Oxfmt and whitespace checks passed. The merged head is covered by the fresh focused tests and required CI; the earlier runtime/build measurements are not a rebuild of that later merge.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```
