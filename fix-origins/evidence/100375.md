fix(matrix): stop tagging ordinary Matrix messages as text commands

Ordinary messages from authorized Matrix users were tagged as text commands, which bypassed normal reply visibility and intentional silence, so replies meant to stay private were posted to the room. Only real commands are tagged as commands now.

Evidence: built Gateway against a self-hosted Synapse homeserver. On main an ordinary message leaked a private final reply into the room (twice); with this change it stays private (twice). /status still works as a command, and NO_REPLY stays silent on both. A live gpt-5.4-mini turn passes.

## Fix PR #179506 description (by xiaopan-xydt, opened 2026-10-21T13:18:08Z)

```text
Fixes #179441

## What Problem This Solves

Matrix marks every inbound message as a text command. For an authorized room sender, that makes ordinary conversation a required command turn and bypasses normal reply-visibility policy. In particular, `messages.groupChat.visibleReplies: "message_tool"` still automatically posts the model's unsent final answer.

## What Changed

Reuse the ingress owner's existing control-command detection, including whether text commands are enabled. Only actual control commands receive `CommandSource: "text"`; ordinary messages keep their normal message classification. Document the distinction between command authorization and ordinary-message reply policy.

The contributor's small fix and credit are preserved. No configuration, defaults, SDK, or persisted-state changes.

## Evidence

Built OpenClaw Gateways connected to a private, self-hosted Synapse container over a Docker-only network, with an authorized real Matrix account posting messages through the homeserver APIs:

- Main twice: despite `visibleReplies: "message_tool"`, an ordinary message automatically posted the provider's `Private ordinary final` to the room.
- Candidate, same flow: the ordinary final stayed private. Two ordinary `NO_REPLY` turns remained silent. The `/status` control still posted its command response without a provider request.
- Main also respected `NO_REPLY` in this embedded-provider setup; the older reported `claude-cli` empty-response symptom is not claimed as reproduced here.
- Regression coverage distinguishes ordinary authorized messages from `/status`; focused Matrix suite passes (4 tests), and changed TypeScript files pass Oxfmt and Oxlint.
- A bounded real-provider call through the shipped agent CLI returned the requested `MATRIX_LIVE_OK` marker.
- Telegram Test Server delivery smoke on the same built candidate: the leased QA user observed exactly one `OPENCLAW_E2E_OK` bot message; credential and fixture cleanup completed.

Simplification retained one existing command-detection owner and no parallel parser or new abstraction. Whole change: production +3/-1 lines; tests +54/-0; documentation +2/-0. The extra ingress field carries the existing decision to context construction.

Two-way door: reverting restores the previous inbound classification without data migration. Blast radius is Matrix inbound command metadata and the reply policies that consume it; other channels are unchanged.
```
