## Fix PR #168170 description (by steipete, opened 2026-10-10T04:03:42Z)

```text
## What Problem This Solves

Open Control UI tabs could retain an old name or avatar after `IDENTITY.md` was saved through a Gateway file RPC. The connection-scoped identity cache introduced in #167968 had no notification for those writes.

## User Impact

Successful identity-file saves through `agents.files.set` and `sessions.files.set` refresh open chats, the roster, and forwarded avatars. Idle identity reads remain suppressed. Direct filesystem/shell edits still require reload or reconnect; native clients retain their existing catalog-loading behavior.

## Why This Change Was Made

The file RPCs publish `agent.identity.changed` only after a committed write. Session-file saves match the configured agent workspace's exact identity path, excluding unrelated project and nested files. Before publishing, the writer drains any older identity-file read so an immediate client refresh cannot join a stale in-flight result. The existing UI identity owner handles invalidation and stale-response rejection.

The obsolete TTL assertions reported by CI are already corrected on the main base. This PR adds the missing production notification path and its boundary regressions. The file-write tests use the existing real-storage fixture; the oversized mutation suite shrinks.

Non-test LOC delta: **+43**, needed for the write/event contract and read ordering. No new polling loop, cache, config option, module, export, or schema change.
```
