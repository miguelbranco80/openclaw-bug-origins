```text
## What Problem This Solves

`__proto__` assignments silently disappear when saving provider environment or MCP environment/header settings.

Supersedes #172325, thanks @wangmiao0668000666.

## User Impact

`--provider-env`, MCP `--env`, and MCP `--header` now reject `__proto__`, `constructor`, and `prototype` with a clear error before saving config. Ordinary keys and literal values retain their behavior. No migration is required.

## Why This Change Was Made

Both command families now use one KEY=VALUE parser and the existing `isBlockedObjectKey` guard used by config paths. This removes the two duplicate parsers: **production LOC −7**. Diagnostics identify the flag and reserved key without disclosing values; malformed provider-env diagnostics now use the same wording as MCP.

The extra 48 test lines cover all three reserved keys at all three CLI entry points, unchanged MCP config, provider secret redaction, and normal provider values (including empty values and embedded `=`). A dedicated test-line allocation records that regression coverage.
```
