## Fix message body

```text
Closes #158715

## What Problem This Solves

Plugins → Advanced can remain stuck on “Plugin settings schema is unavailable” after connection or a failed schema read. Reload previously refreshed configuration without recovering the missing schema.

## User Impact

Operators can recover global plugin loading, allow/deny lists, and capability slot settings without leaving the UI.

## Why This Change Was Made

Admit schema reads through the connected Plugins route and retry an absent schema after Reload. The existing runtime-config owner still handles Gateway config.schema, permissions, in-flight deduplication, and stale responses. No new schema source, configuration option, or API is added. Already-loaded schema invalidation remains separate (#127553).

## Evidence

- Fresh main 52fd3cd588b and candidate 498a4c312215a8f0e390ce7a6afecf0878e9261f were built and exercised in Chromium against an isolated real Gateway with the bundled Diffs plugin enabled. Normal main cold load works; the failure is conditional, not universal.
- Browser transport fault injection rejected an initial config.schema read while all other requests used the real Gateway. On main, Reload left the unavailable state and did not issue a second schema read. On the candidate, the same one-shot fault recovered through the connected lifecycle. With schema failures held until the page settled, releasing the fault and clicking Reload restored the real Gateway form. The transient error remained visible before recovery.
- Saved Memory Plugin as memory-core through Advanced, verified the Gateway-owned config persisted plugins.slots.memory, and verified the value after Reload.
- Diffs plugin-specific settings render from its real schema. Diagnostics OpenTelemetry has an empty settings schema and correctly shows no plugin-specific fields, only the standard permissions section.
- 43 focused tests pass across plugin schema, routing, generations, and runtime-config schema access (6.67 s wrapper time; new two-test bodies total 172 ms). The contributor previously demonstrated both new regressions failing before the fix.
- Fresh runtime/UI build, UI typecheck, touched-file Oxlint and formatting checks pass. The shared schema owner remains unchanged; production delta is -2 lines and test delta is +124.

Note: both unmodified main and the candidate display the Enable Plugins switch as off when plugins.enabled is omitted, despite the effective default being true and Diffs loading. This pre-existing default-display issue is outside this schema-loading repair.
```
