## Fix PR #165219 description (by steipete, opened 2026-10-05T00:36:30Z)

```text
## What Problem This Solves

Fixes: the session Publish PR card shows a permanent "GitHub publication session worktree owner is unavailable." error, with a full-width Refresh bar, after worktree cleanup retires the session's idle checkout, and failed publications fill the card with paragraphs of server text.

## User Impact

User impact: sessions whose worktree was retired after publishing no longer show a stuck error, and the publication card collapses to a single status line ("Publication failed", "Publication queued", …) with the details one click away and a small refresh icon instead of a full-width button.

## Why This Change Was Made

On Team, a session published its PR, then worktree GC snapshotted and retired the checkout (`removed_at` set, snapshot ref kept) while the session entry still named it. The shared publication observation (status and latest-receipt discovery, polled by the Control UI) found the published receipt, demanded a live worktree, and threw. Observation only qualifies the *current* workspace, so a retired or replaced checkout now reads as "no current publication", matching what publication availability already reports. Execution paths still re-prove the live worktree and fail closed, and a repository workspace owned by a different session still throws as an integrity error.

The UI now leads with a short status headline that expands to the account, server message, next action, and effects. In the "Publication attempt failed" history, which already has its own disclosure, the details render inline instead of nesting a second expander. Queued/in-progress states drop the refresh icon because their primary "Check publication" button already refreshes.
```
