fix(path): print --json refusal errors to stdout

With `--json`, handled refusals from the path commands (bad syntax, wildcards, invalid UTF-8) wrote their JSON error to stderr, so scripts reading stdout got nothing. They now print the standard CLI error document to stdout with the same code, message and exit status 2. Human-readable output still goes to stderr.

## What Problem This Solves

Scripts redirecting `openclaw path --json` receive empty stdout for handled path/file refusals because the plugin writes its structured error to stderr. That breaks the CLI's machine-readable stdout contract.

## Changes

Write the existing scrubbed refusal as one stdout JSON document with `ok: false`, `error.type: "cli_error"`, and the original domain code/message. Keep nonzero exit status, human diagnostics on stderr, sentinel scrubbing, and mutation refusal unchanged. Document the stream contract and update existing regressions rather than add a duplicate test harness.

Preserve Leon-SK668's commits and credit. Simplification leaves one existing output owner with no new abstraction, configuration, schema, state, or SDK surface. Production +3/-1; tests +16/-14; documentation +4/-0.

## Evidence

Use the built shipped CLI with the bundled plugin enabled through `plugins enable oc-path`, in secretless Linux Node 24.22.1 Docker with task-owned profiles. Capture stdout and stderr independently. All malformed bytes belong to a disposable input document, never OpenClaw state.

Main `3cd9bddb36d93d43b50595dfd0d5b18a4478a0c9`, twice each: invalid `oc://` syntax, an unsupported file wildcard, and a malformed-UTF-8 edit all exit 2 with empty stdout and the JSON error on stderr. Explicit `--human` diagnostics use stderr. Every refused mutation leaves the input bytes unchanged. A valid Unicode write and independent CLI readback succeed.

Candidate, twice each: all three refusals still exit 2, now with exactly one JSON stdout document carrying `ok: false`, `type: "cli_error"`, and the retained domain code/message; stderr is empty. Explicit human-mode output stays on stderr. Refused input bytes remain identical, and the Unicode write/readback control preserves `Café 🤖` and the neighboring field. All 69 focused CLI and input-limit tests pass, along with changed-file Oxfmt and Oxlint. The input-limit regression retains its size-refusal and byte-preservation checks while reading the corrected JSON stream.

Merge danger: two-way door; reverting restores the broken stream without changing stored data. Blast radius is scripts consuming handled JSON refusals from the bundled path CLI. Human diagnostics and successful output stay unchanged.
