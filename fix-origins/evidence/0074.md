## What Problem This Solves

Fixes: a steer accepted while an embedded turn prepares its next request misses that request and waits through an unnecessary model response, including after a failed Code Mode cell.

## User Impact

Corrections accepted during continuation preparation or background-result placement enter the next model request. One-at-a-time steering, FIFO delivery, cancellation, and exact-once transcript commitment remain intact. This does not interrupt non-interruptible tools or shorten the existing settlement ceiling.

## Why This Change Was Made

The loop checked for input before awaited request preparation, leaving a gap before inference. Move the initial checkpoint after preparation and check that boundary on continuations that have not already consumed a queued batch. Consolidate the duplicated input-commit loops into the existing steering owner, retaining cancellation checks around message-start publication and input-scope commitment before message-end publication.

Delivery confirmation measures transcript settlement and can lag provider injection. This change targets the reproduced checkpoint gap before model dispatch.

## Evidence

With a controlled 100 ms model-response hold, avoid the extra response, improve injection latency, and do not regress measured CPU/allocation.
