```text
Closes #147526

## What Problem This Solves

Browser output preparation accepts directories beneath symlinked ancestors and can create a trimmed directory name when the requested final component ends in whitespace.

## User Impact

Browser outputs preserve their requested directory names and reject symlinked ancestors consistently. Chrome MCP screenshots retain PNG/JPEG handling and clean their temporary workspace after both success and failure. No dependency update is required. Outputs previously routed through a user-created symlink must use their real directory path; macOS system aliases remain supported. The browser troubleshooting page documents this path requirement.

## Why This Change Was Made

Use the released fs-safe directory owner through the existing SDK, anchored at the filesystem root so validation includes every ancestor. Preserve macOS `/tmp` and `/var` aliases, existing filesystem-root outputs, and mkdir/umask behavior. Reuse the SDK temporary download workspace for screenshots.

This deletes both browser-local filesystem helpers: **42 fewer production lines**, with 29 additional test lines. It is part of the maintainer-requested fs-safe adoption.

## Evidence

- Baseline reproduced three directory failures: existing and missing descendants beneath a symlinked ancestor, and creation of a trimmed directory name.
- All 117 focused browser output-directory and Chrome MCP tests pass, including exact names, existing roots, PNG/JPEG bytes, and workspace cleanup after failure.
- Independent Codex review found no actionable P0–P2 findings.
- Full OpenClaw build and changed-file gate passed, including production/test typechecks, lint, boundary guards, dead-export scans, and import-cycle checks. All three screenshot cases were rerun successfully after a test-only lint correction.
- Actual output-writer proof preserved whitespace names, umask 0027, existing directory mode 0751, and file mode 0600; symlink descendants were rejected before the writer ran.
- Real isolated Chrome MCP 1.8.0 captured 900×600 PNG/JPEG screenshots. Both success workspaces and the invalid-target failure workspace were removed; all five owned browser/MCP processes shut down. The operator browser was untouched.
```
