## Fix message body

```text
## What Problem This Solves

Fixes local speech command strings dropping intentionally empty quoted arguments before starting the speech executable.

## User Impact

An argument such as `--voice ""` retains its empty value instead of shifting the following option into that position. Empty single-quoted values are preserved too. Nonempty quoted fragments, whitespace values, and explicit argument arrays keep their existing behavior. Shared shell/SDK argument parsing is unchanged.

## Why This Change Was Made

The existing private speech-command parser now tracks whether a token began separately from whether its contents are nonempty. The same process owner, timeouts, output limits, and cleanup remain in place. Regression coverage reuses the existing subprocess fixture instead of adding a second fixture or exporting the parser.

## Evidence

Ran authenticated `tts.setPersona` and `tts.speak` through an isolated built Gateway, the registered `tts-local-cli` provider, and a real Node subprocess. The executable independently recorded its arguments and returned a known 52-byte PCM WAV.

Before:
```json
["--voice", "--tts-text", "synthetic spoken words"]
```
After:
```json
["--voice", "", "--tts-text", "synthetic spoken words"]
```

- Eight before/after cases covered single/double empty quotes, consecutive empties, quoted whitespace, adjacent fragments, explicit-array values, ordinary arguments, and an intentional child exit 23. Candidate arguments and returned WAV bytes matched exactly; child failure remained a structured RPC error.
- The new consecutive-empty regression failed on the original parser. All four new argument rows and 33 other focused cases passed. One existing timeout test hit its 10-second test limit while cold compiled-worker preparation took 13.6 seconds; that local suite was not all green. No timeout increase, warmup, retry, or unrelated production repair was added.
- Runtime build, scoped lint, formatting, whitespace, and line-cap checks passed. Final static and matrix checks remain hosted.

Proof used main `d0192ed506c84a6f7bcebfb4fa405be8f15e2405` with the exact contributor parser bytes and the consolidated tests. The maintained minimal test Gateway omitted unrelated startup sidecars; authentication, speech registration, parser, process runner, and WAV response were real. No network egress occurred. This does not claim real-engine acoustic quality, telephony conversion, or full normal-startup coverage.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```
