## Fix PR #154688 description (by steipete, opened 2026-09-21T09:43:10Z)

```text
## What Problem This Solves

Fixes idle conversations becoming sluggish while other sessions update or presence heartbeats arrive.

## User Impact

The open conversation avoids unnecessary transcript rendering during background activity. Sidebar data remains current, and selected-session changes, viewers, approvals, model controls, sharing, and recovery continue updating normally. No configuration or migration is required.

## Why This Change Was Made

Shared session publications and fresh presence objects invalidated the whole foreground pane even when its rendered content was unchanged. Compare the session and presence facts consumed by that pane before scheduling a render, while always retaining the latest raw state and running existing reconciliation. Empty conversations still track recent sessions across the full roster.

## Evidence

A bundled Chromium test delivers real mocked Gateway events through the mounted application and verifies sidebar, header, and viewer DOM:

| Trigger | Before: conversation renders | After: conversation renders |
| --- | ---: | ---: |
| Three unrelated session title updates | 1, 1, 1 | 0, 0, 0 |
| Presence heartbeat | 1 | 0 |
| Selected conversation rename | 2 | 2 |
| Viewer arrival | 1 | 1 |

The test fails on the original rendering code for the unwanted renders and passes after the fix, including after integration with current main's session observation owner. The scenario takes 1.087 s; the browser suite takes 4.200 s (21.25 s including startup/build overhead).
```
