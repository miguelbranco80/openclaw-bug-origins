## Fix PR #185838 description (by steipete, opened 2026-10-27T11:15:38Z)

```text
## What Problem This Solves

Fixes: `doctor --non-interactive` can fail on healthy transcript history when one configured agent is idle and another holds an active database lease.

## User Impact

Doctor can inspect this healthy mixed idle/running state without requiring a Gateway shutdown. History that actually needs repair still requires exclusive maintenance custody. No schema or configuration changes are introduced.

## Why This Change Was Made

The preflight used the idle agent's lease to decide whether to write a historical migration-completion cursor, but the maintenance owner excludes writers across all agents. Observe the existing global lease boundary once per Doctor operation and defer optional cursor-only bookkeeping while any writer is active. Actual transcript and archive repair predicates and the final maintenance guard remain unchanged.

## Evidence

- Regression fails on the original owner for a clean idle agent plus a separate active agent lease; the actual-legacy control retains its refusal. All 23 migration tests pass with the fix.
- A fresh isolated hardened native Gateway completed a main turn and an eight-agent burst. The original native Doctor reproduced the lease refusal (exit 1); patched source `doctorCommand` then completed against the same Gateway (exit 0), followed by healthy status and a fresh successful agent turn. This proves the common Doctor owner against native-produced state; the repaired code has not yet been rebuilt into an AOT binary.
- Targeted typecheck, changed-file lint/format, and diff checks pass. Independent review found no actionable findings through P2.
```
