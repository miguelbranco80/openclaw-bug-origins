## Fix PR #148241 description (by steipete, opened 2026-09-14T12:20:24Z)

```text
Related: #144592

## What Problem This Solves

Async TaskFlow creation hides the original persistence error behind `TaskFlow persistence failed.`, leaving plugin callers unable to inspect why creation failed.

## User Impact

`api.runtime.tasks.async.managedFlows.createManaged` preserves the original persistence rejection in the thrown error's `cause`. The public error message, nullable `tryCreateManaged` behavior, and propagation of uncertain-outcome errors remain unchanged.

## Why This Change Was Made

Both methods consume one per-operation creation result that retains any caught error. Each call still makes one mutation attempt; preparation and input-validation errors continue to propagate directly.

## Evidence

The focused worker-boundary tests inject JavaScript results and errors without executing SQLite operations. Coverage includes ordinary failures, concurrent strict calls, nullable and successful results, preparation and validation errors, and direct/cause/aggregate `outcome-unknown` errors.

The final regression fixture fails on the original source for the missing cause (14 controls pass) and passes all 15 cases with this change. Selected changed-file typechecks, lint, and repository guards passed; independent P2 review reported no actionable findings.

This is a diagnostic fix. It does not establish the cause of any earlier persistence failure or change database recovery behavior.
```
