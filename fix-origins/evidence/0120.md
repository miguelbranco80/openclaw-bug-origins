```text
## What Problem This Solves

The macOS outbox attachment-budget test can accept a queued message but unexpectedly retain its input text. Initial composer-draft loading can advance the revision after the fixture captures the revision used by enqueue, so the production code correctly preserves the newer draft.

## User Impact

No product behavior changes. The test finishes draft setup before entering its input and exercising attachment rejection or acceptance.

## Why This Change Was Made

Await the existing composer-draft settlement helper before setting the test input. All three attachment budgets and their existing assertions remain unchanged.

## Evidence

- A controlled run through the existing attachment-policy gate reproduced the original input assertion failure: the captured revision was 1 and draft loading advanced it to 2.
- With the one-line wait, revisions stayed equal and all three cases passed under the same gate. The original ungated test also passed all three cases.
- Formatting, diff checks, and independent review passed.
- Local proof used a temporary relocation of the fixture’s temp base into the existing sandbox; baseline and candidate used the same relocation. Neither the relocation nor the scheduling probe is included in this change.
```
