## Fix message body

```text
* fix(memory): memory_search points disabled sessions corpus at sessions_search instead of config changes

The memory_search tool contract advertised corpus=sessions unconditionally even
though semantic session indexing is opt-in, and the unavailable-corpus response
only relayed configuration-change advice. State the opt-in requirement in the
tool description when session transcripts are not indexed, and point the
unavailable-corpus action at the sessions_search tool for exact transcript
lookup before describing the opt-in path. The opt-in gate and protected recall
boundary are unchanged.

Fixes #147258

* fix(memory): keep session guidance capability-aware

Keep static memory_search guidance neutral to the final tool inventory, leave named session follow-up guidance in the availability-aware prompt, and return a useful conditional recovery action when semantic session indexing is disabled.

---------

Co-authored-by: Vincent Koc <vincentkoc@ieee.org>
```

## Fix PR #147328 description (by LiuwqGit, opened 2026-09-13T19:32:05Z)

```text
Closes #147258

## What Problem This Solves

Fixes: `memory_search` could recommend `sessions_search` even when the effective tool policy removed that capability.

## User Impact

User impact: semantic session-search guidance remains accurate without sending agents toward an unavailable tool. No configuration, migration, or stored-data change is required.

## Why This Change Was Made

The static `memory_search` description now explains the sessions corpus without naming another tool. Named `sessions_search` guidance remains in the final availability-aware memory prompt, where the effective tool inventory is known. When semantic session indexing is disabled, the result suggests an exact session-history capability conditionally and otherwise gives the operator enablement path.
