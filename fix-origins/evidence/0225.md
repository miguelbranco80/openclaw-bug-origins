## Fix PR #200900 description (by vincentkoc, opened 2026-11-18T01:28:00Z)

```text
## What Problem This Solves

On Node 24, a bundled Codex executable that cannot run can lose its useful launch error. The official launcher aborts after reporting the native error, so OpenClaw can report a generic app-server failure instead of identifying the executable permission problem.

Related: https://github.com/openclaw/openclaw/pull/200784

## User Impact

Codex startup retains the actionable native launch error on Node 24. Unrecognized aborts and other signals still remain generic failures; runtime versions, dependencies, and launch policy do not change.

## Why This Change Was Made

Recognize Node's exact fatal `process.execve` diagnostic only together with `SIGABRT`, within the existing managed-launcher observer. Keep observing stderr when exit arrives first. Existing exit-1 and native-path checks remain intact.

## Evidence

- The two real-launcher cases failed in [hourly Codex shard 29](https://github.com/openclaw/openclaw/actions/runs/44211094904/job/134490120071).
- A standalone probe using the installed Codex 0.169.0 launcher and a nonexecutable synthetic native target reproduced `SIGABRT` plus the exact fatal header on Node 24.22.1. Node 26.13.0 instead produced the existing structured exit-1 diagnostic. This was local macOS producer evidence, not a Linux transport replay.
- The existing attribution table now covers the fatal header with early and late stderr, and rejects unrelated aborts, missing aborts, and other signals. It also checks listener cleanup.
- Fresh full-owner review of the complete corrected change: no P0–P3 findings. Targeted formatting and diff checks passed.
- Exact Node 24.22.1 transport proof in a native checkout with its own frozen dependencies: the base observer failed both original real-launcher cases and the two new positive abort cases (4 failed, 10 passed). The fix passed all 14 cases, including both real launches, rejected signals, and listener cleanup.
- Targeted type-aware lint passed. The supported package-boundary compile also passed (Codex only, 13.6 seconds), including owner-managed artifact preparation. An earlier bare package-config attempt lacked that preparation and is retained as setup-only evidence. No full Gateway or Linux transport replay is claimed; the local proof used macOS arm64 with the same Node 24.22.1 runtime and pinned Codex launcher.

The first PR CI run caught a read-only `signalCode` type in the test fixture. The fixture now declares and initializes that mutable field alongside `exitCode`. The exact extension-test typecheck passed, and the affected transport/registration suites passed 34 tests; 15 Linux procfs cases were skipped on macOS. Targeted lint and formatting also passed.
```

+    }
+  };
+  const onExit = (code: number | null) => {
+    startupFailure.complete();

+    );

+      startupFailure.error = described;
+    }
+  };

+  child.once("exit", onExit);
+  Object.assign(child, { startupFailure });
