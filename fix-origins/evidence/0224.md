Detailed session-usage reads combine requested session/month ranges with OR. When SQLite statistics still describe a small cache, the planner can scan the full cache table instead of reading the requested partitions. Separately, a completed detail report expires after 30 seconds even when its revision is unchanged, starting another inventory and rollup read behind the returned cached response.

## User Impact

Requested session/month reads stay indexed, and unchanged detailed dashboard polls reuse their completed snapshot. Totals, owner attribution, visibility, incomplete-result retries, byte-budget ordering, and cache eviction remain unchanged. No schema, index, or configuration changes are required.

The partition owner now combines independently indexed ranges with UNION ALL and retains the global key order and existing batch size. It shares the existing index-hint expression with the writer. The existing result-cache owner uses revision-based reuse for complete detail snapshots, as overview already does. The query/cache change is net zero production lines; two additional parentheses lines keep the existing SQL guard annotation attached to its expression. There is no new cache.
