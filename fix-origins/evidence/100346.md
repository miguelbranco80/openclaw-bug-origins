## Fix PR #161876 description (by steipete, opened 2026-09-30T12:59:04Z)

```text
Related: #157954

## What Problem This Solves

Fixes: the bundled x86_64 Mac node worker crashes (SIGSEGV, exit 139) at startup in native-first mode, which blocks the 2026.9.7 x86_64 and universal macOS release builds.

## User Impact

The Intel/universal macOS app can be packaged again. Intel Macs use the bounded `ps` process-identity path they used through 2026.9.6; Apple silicon keeps the faster native identity reads from #157954.

## Why This Change Was Made

#157954 reads Darwin process identity through Koffi and `libproc` on arm64 and x64. The release packaging proof runs the x86_64 worker under Rosetta on Apple-silicon runners, and there the query segfaults the worker every time it runs. The x86_64 path cannot be validated on the release infrastructure, and the pre-existing `ps` fallback already covers Intel, so the native query is limited to arm64.

## Evidence

- Release-ops runs 36659957509 and 36695080682: every x86_64 worker proof (x86_64 and universal variants) exits 139 in `native-first-default`; 2026.9.6 passed the same proof with no Darwin Koffi usage.
- Local repro under Rosetta with the 2026.9.7 worker package (x64 Node 24.19.0 and 24.21.0): native-first worker SIGSEGV 3/3; with only `readDarwinNativeIdentity` disabled, 0/3 crashes and the worker reaches `ready`. `NODE_DEBUG=module` shows `koffi.node` loaded from `pid-alive` right before the crash. Isolated x64 Koffi `proc_pidinfo` calls also segfault intermittently with Koffi 3.2.1 and 3.3.1.
- New x64 test fails on the old code and passes now; `node scripts/run-vitest.mjs src/shared/pid-alive*.test.ts`: 60 passed.
- Gap: not run on physical Intel hardware; the change returns Intel to the 2026.9.6 behavior instead.
```
