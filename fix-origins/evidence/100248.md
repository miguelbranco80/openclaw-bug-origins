```text
## What Problem This Solves

Starting a suggested task in a new session or worktree unexpectedly switches away from the conversation you are reading.

## User Impact

New-session and worktree launches now run in the background, leaving the current conversation and composer draft open. The accepted card disappears, and the new session can be opened from the sidebar. Starting in the current session keeps its existing behavior.

## Why This Change Was Made

The Gateway already owns creating and starting the task. Remove the UI's automatic navigation after acceptance; keep its request, duplicate-submission protection, error handling, and connection guards.

## Evidence

- The updated regression fails on the original code because acceptance navigates to the new session. All three new-session/worktree browser cases reproduced the unwanted route change.
- 18 focused component/lifecycle tests and all 8 suggested-task browser tests pass after the fix, including launch modes, draft preservation, dismissal, and reconnect behavior.
- Full local changed-file check passed (typechecks, formatting, lint, i18n, dependency/architecture guards, and dead-export scans). Independent review found no actionable P0–P2 findings.
- Verified before/after through the real Chrome profile against a local synthetic Gateway fixture. Screenshots below show the selected session and composer after the same action.
```
