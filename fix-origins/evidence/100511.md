## Fix PR #183456 description (by steipete, opened 2026-10-25T08:49:29Z)

```text
## What Problem This Solves

Fixes external-plugin resolver registration in experimental Bun AOT builds, where installing a plugin can fail with `A runtime plugin can't resolve the entry point ... because it was already compiled into this executable`.

## User Impact

External plugins can register their captured-source resolver without trying to intercept the executable's immutable entry. Native package selection and captured plugin ownership stay unchanged.

## Why This Change Was Made

Bun checks a runtime resolver's filter before invoking its callback. The captured-source resolver used a broad filter even though its callback only redirects owned plugin files. Exclude the exact `Bun.main` path, matching the existing standalone bootstrap contract, and keep similarly prefixed external paths eligible.

## Evidence

- The new owner-boundary regression fails before the fix and passes afterward; it covers entry exclusion, external redirection, and owner disposal.
- Owner test file: 11 passed, one existing Node-only skip; 1.12 seconds of test time (2.30 seconds wrapper wall time). CI timing will be available from the attached run.
- Targeted production/test type checks, lint, formatting, and diff sanity pass.
- An actual CB Bun AOT compiled fixture reproduces the original registration refusal and accepts the corrected resolver with C2 flags and `trim.allow:["run"]`, including a strict Developer ID runtime signature with an empty entitlement dictionary.

This addresses resolver registration. Complete installed-plugin execution also needs the separately tracked standalone external-loader admission repair; it is not claimed by this change.
```
