## Fix PR #191833 description (by roboclaw-bot, opened 2026-11-03T10:47:30Z)

```text
## What Problem This Solves

The desktop Details panel stopped showing subagent identity colors. The Subagents summary renders as overlapping gray robot glyphs instead of tinted, per-subagent avatars, in both the docked and floating panel.

Root cause: #189537 ("tighten the desktop Details panel") added a desktop-only override that set every `.chat-details-subagents__avatar` to `background: transparent; color: var(--muted)`. It also put the stacked summary avatars on the 16px row-icon slot with a 15px glyph, so with the stack's `-6px` overlap the bots crowd into each other. That PR's own comment says collapsed People "matches the native Subagents avatar" at 20px, so the stack was meant to keep its native size.

## Solution

In `ui/src/styles/chat/details-desktop.css`:

- Remove the muting override, so avatars use the hue tint and ink from `chat-details-subagents.css` again.
- Limit the row-icon slot sizing to row avatars (`:where(.chat-details-subagents__row) > .chat-details-subagents__avatar`). Stacked summary avatars go back to their native 20px chip with a 14px glyph. `:where()` keeps the shared `:is()` rules at the same specificity for every other icon in the list.

Expanded rows stay on #189537's shared icon and text axes and now show their colored icon.

Mobile Details is not changed. #189549 muted the mobile sheet avatars on purpose to make the rows quieter.

The stacked chips keep their existing 1px ring in the panel's surface color (`box-shadow: 0 0 0 1px var(--details-subagent-surface)`), which separates the overlapping chips. This PR does not change that ring. It matches the panel when the row is idle and stands out as a light outline only when the row is hovered, the same as before #189537.

## Impact

Visual only, desktop Details (docked at 1728 and floating at 1100). No behavior or data changes. The CSS gets slightly smaller.

## Evidence

- Regression assertion in `ui/src/e2e/session-details-background-work.e2e.test.ts`: at the docked (1728) and floating (1100) desktop widths, the four stacked avatars must have four distinct background tints.
  - Base CSS: **fails** with `expected 1 to be 4` (all four stacked avatars transparent). Rechecked on the current head's test.
  - With fix: `node scripts/run-vitest.mjs run --config test/vitest/vitest.ui-e2e.config.ts --configLoader runner ui/src/e2e/session-details-background-work.e2e.test.ts` passes (2/2).
- The test-lines ratchet passes locally against `origin/main` with the `config/test-lines-allocations/desktop-subagent-tint.txt` allocation (+5 lines).
- `stylelint` and `oxfmt --check` pass on the touched files, and `git diff --check` is clean.
- Before/after captures (mocked Control UI, synthetic fixture) are in the comment below.
```
