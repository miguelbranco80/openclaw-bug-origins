## Fix message body

```text
Candidate Doctor checked dependency targets imported by the private rehearsal copy of user-installed plugins only against that private copy. On Windows npm-global installs, the private host links resolve into the staged candidate package, so its own nested node_modules/typebox was rejected as "outside the temporary update copy" and every update rolled back.

Dependency targets imported from the private copy may now resolve into the canonical staged candidate package as well. Plugin entries and repair writes stay private-only. Candidate-sourced references keep main's unchecked scope. Targets in the serving installation or user directories are still rejected.

Fixes #200573
Reported-by: @desksk

Co-authored-by: steipete <58493+steipete@users.noreply.github.com>
```

## What Problem This Solves

Windows npm-global updates can roll back during candidate Doctor even when the rejected `typebox` dependency is present inside the staged package. The reporter encountered this four times across three target releases, leaving managed updates unusable on that installation.

## User Impact

Candidate Doctor accepts private plugin dependencies inside the staged OpenClaw package, including nested `node_modules`, without requiring an updated updater. Existing pnpm-store and npm-hoisted resolution from trusted candidate code stays unchanged. Plugin entries and repair writes remain private-only.

## Why This Change Was Made

The [main assertion at update-candidate-plugin-repair.ts:44](https://github.com/openclaw/openclaw/blob/176f2ff9652ea6539192a7c580940ced94b27942/src/infra/update-candidate-plugin-repair.ts#L44) checked resolved private-plugin dependencies only against the separate rehearsal directory. The snapshot owner intentionally links private plugins to the staged package, using Windows junctions, so a dependency inside that package could be rejected.

The fix preserves main's source predicate and private lookup rule exactly. For those private-sourced reads, [the accepted target roots](https://github.com/openclaw/openclaw/blob/c4dcd98dd457c6b639cce8d6dec528eeeddbacc3/src/infra/update-candidate-plugin-repair.ts#L81) are the private rehearsal root and the canonical candidate package root, checked after resolving links. Trusted candidate-sourced references retain their existing dependency resolution. Explicit external imports keep main's existing semantics. The stale `memory-wiki` install-record warning is separate and absent from the reproduction.
