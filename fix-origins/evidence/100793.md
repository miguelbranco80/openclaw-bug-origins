```text
The ingress-adoption renewal now starts before the pre-compaction memory flush, so a long flush no longer trips the claim-to-adoption watchdog, abort the turn and get the inbound event redelivered.
```

## Fix PR #137359 description (by ericcaiwx-star, opened 2026-09-03T15:02:25Z)

```text
Closes #137294

## What Problem This Solves

A required preflight memory flush can legitimately run longer than the shorter channel-ingress claim-to-adoption watchdog. Before compaction starts its existing heartbeat, the watchdog can abort and replay the message, restarting the same maintenance work.

## Why This Change Was Made

This reshapes the PR around the lifecycle already shipped by #150040 instead of introducing a second timeout owner. A runnable memory flush now starts the existing pre-adoption lifecycle heartbeat immediately before its bounded run context and stops it in the same cleanup path.

Skipped memory flushes do not start a heartbeat, so unrelated preparation stalls remain covered by the ingress watchdog. Compaction continues to use the same lifecycle helper. There is no new configuration, environment variable, public callback, or storage schema.

The existing prompt-token estimator now lives in `memory-flush.ts` and keeps the normalization `main` already uses. Production delta on this rebase is +18/-10.

## User Impact

Long, healthy memory checkpoints can finish without the ingress layer aborting and replaying the message. Turns that never enter bounded maintenance still retain the normal stall timeout and retry behavior.
```
