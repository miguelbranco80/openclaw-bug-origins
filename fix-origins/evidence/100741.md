## What Problem This Solves

Fixes missing Signal alias directory entries, command-palette catalog results, and local Codex history sessions when a query and the stored display text use canonically equivalent Unicode spellings.

## User Impact

Users can find decomposed names with precomposed queries, and vice versa, without changing displayed names, Signal targets, session IDs, or queries sent to the Gateway and Node.

## Why This Change Was Made

Apply lowercase-then-NFC only at the three local comparison owners. Signal alias lookup and strict target resolution retain their existing rules; target substring matching uses the original lowercase query, independently of the normalized alias comparison. The palette keeps its existing local catalog filter, and Codex keeps its existing history reader. No shared normalizer, storage migration, or transport rewrite is introduced.

This combines the contributor commits from @SunnyShu0925 (#188040, #188059, #188106) and @huwei-xydt (#188062), including both palette submissions. Duplicate Unicode tests are consolidated into existing directory, asynchronous catalog, and history cases, retaining strict Signal alias and pending-catalog coverage. Against the baseline: production +3 lines; tests +0 lines. #188107 is deliberately excluded: Zalo allowlist name-to-ID resolution is not a local display comparison.

## Evidence

[Runtime evidence and inspected before/after screenshots](https://github.com/openclaw/openclaw/pull/188138#issuecomment-6516379471).

Built main and candidate Gateways in isolated Node 24.22.1 Docker, with actual Gateway/Node protocol calls and Chromium 156 against the built Control UI:

- 58 Signal/Codex RPC observations. Both NFC→NFD and NFD→NFC comparisons fail on main and pass on candidate, twice per direction; same-form, ASCII, raw-ID, and negative controls remain correct. Raw Codex query bytes are verified on the Node wire.
- 26 real palette observations, including both cross-form directions twice on each build, same-form and ASCII controls, and exact original agent labels/IDs. All 26 outgoing palette search queries retain their input spelling. Before/after screenshots are attached in the evidence comment.
- Signal uses a task-local native HTTP daemon fixture for health/version/SSE, with no incoming messages; Codex uses a writer-contract `history.jsonl` fixture, not an authenticated Codex conversation.
- Codex's real writer is [`codex-rs/message-history/src/lib.rs`, `append_entry`, lines 104–170](https://github.com/openai/codex/blob/ce0323f2f2d3b25e82806cd555237da3db4e1897/codex-rs/message-history/src/lib.rs#L104-L170), inspected at `ce0323f2f2d3b25e82806cd555237da3db4e1897`. - Focused owner tests: Signal 6/6, Codex 22/22, palette controller 26/26 pass on candidate. Applying the same changed tests to main produces exactly the intended missing-result failure in each owner. Focused formatting and type-aware lint pass.
