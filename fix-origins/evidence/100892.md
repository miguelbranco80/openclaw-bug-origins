## Fix PR #157432 description (by steipete, opened 2026-09-24T17:12:49Z)

```text
## What Problem This Solves

Fixes Git availability checks downloading unrelated branch and tag histories, potentially consuming gigabytes, when a fresh SHA-only source installation has no local upstream ref yet. The Gateway's post-ready update check and `openclaw update status` share this path.

## User Impact

Checks refresh the selected upstream and preserve existing shallow boundaries, local refs and tags. Fresh detached Dev installations discover their upstream on the first check. Configured tracking wins; a matching saved receipt then preserves the intended upstream, including when its local cache ref must be restored. Only installations with neither configured tracking nor matching receipt intent infer the Dev default. Excluded, genuinely ambiguous or unresolvable receipt intent stays unknown instead of selecting another upstream.

This does not reclaim already-downloaded packs or impose a universal byte limit. Missing history belonging to the selected upstream may still be downloaded. Disconnected shallow histories remain unknown rather than being reported as ahead, behind or current.

## Why This Change Was Made

Resolve the selected source before fetching instead of falling back to an implicit `fetch --prune`. Git continues to own configured destination and force rules; the command selects one source, passes through negative refspecs and disables tag/prune side effects. Fresh `FETCH_HEAD` evidence must agree with the selected upstream before reporting a refreshed comparison.

Saved update receipts store a destination, sometimes abbreviated, without its source binding. The existing receipt format also permits a missing local cache. Reverse lookup therefore uses configured mappings and negative refspecs. Materialized names remain Git-resolved; missing full names use Git's ref validator. Missing abbreviations use the documented [Git refname namespaces](https://git-scm.com/docs/gitrevisions). Only spelling ambiguity on one configured remote can use one explicit `ls-remote --refs` query; local probes remain offline, and competing source bindings/remotes remain unknown. This preserves published receipt data without changing its format or guessing an alternative remote.

An initial implementation reconstructed force policy too; real Git experiments showed source-only fetch could leave that responsibility with Git, so that code was removed. Final production delta is +128 lines, justified by source selection and existing receipt spelling/freshness contracts; tests are +451 and docs +8. No updater lifecycle, service, schema, public configuration option or deployment changes.
