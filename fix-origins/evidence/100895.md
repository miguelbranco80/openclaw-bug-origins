## Fix PR #147425 description (by vincentkoc, opened 2026-09-13T21:17:09Z)

```text
## What Problem This Solves

Fixes an issue where QA release-candidate evidence identifies a live-provider run as a mock fixture, including when a missing candidate tarball blocks execution. A run spanning different platform models can also lose its known common provider or claim a model that does not apply to every selected platform.

## Why This Change Was Made

The release-candidate producer now uses the existing platform/model selection contract and records live-provider provenance. It records a common model only when the selected model references agree, and retains a known common provider when the models differ. Invalid or mixed provider metadata remains unknown without replacing the original blocked/failure result.

The script evidence writer passes the optional provider identity to the canonical evidence builder. Explicit model references retain precedence, mock-provider behavior and slim evidence remain unchanged, and canonical schema parsing still owns normalization. The producer imports model parsing through the QA Lab public API.

## User Impact

QA evidence consumers receive accurate provider/model provenance for release-candidate runs, including blocked runs, without changing the child runner arguments, execution outcome, or qualification authority.

## Evidence

- Five focused suites: **112 selected tests passed** (36 producer, 15 script writer, 32 evidence summary, 1 model resolver, 28 scenario runner); 110 model-resolver cases were intentionally unselected. Complete JSON reports were retained and independently checked.
- All **29 canonical changed-file checks** passed for the seven changed paths, including `tsgo:extensions`, `tsgo:extensions:test`, and `tsgo:test:root`; the selected doctor-contract tests passed 6/6.
- `OPENCLAW_BUILD_PRIVATE_QA=1 pnpm build` passed. Assertions against the built public QA API verified model parsing, canonical evidence round-trip, trimmed provider identity with an unknown model, and preservation of the blocked result.
- Exact-source native proof completed and its worker was positively stopped. Fresh PR CI, review, and native preparation will qualify the published head before landing.

These are deterministic provenance and script-evidence checks, not live-provider, VM install/update, or full-release validation. Earlier incomplete reports are not counted as passing proof.

Nonblocking tooling follow-ups retained: Vitest 5 default JSON output conflicts with exact-source receiver validation on a reused lease (the remaining reports used distinct ignored output paths); the changed-file guard advises migrating the producer test temporary directory to the existing cleanup tracker. Build warnings are retained with the proof.
```
