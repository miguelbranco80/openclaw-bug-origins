Fixes: the QA subagent-handoff scenario times out after a successful child completion when transcript metadata separates delivery from the requester’s reply.

## User Impact

QA runs recognize the completed handoff while continuing to reject replies from another turn or transcript branch. No configuration changes or migrations are required.

## Why This Change Was Made

Use the history owner’s active transcript selection instead of walking raw parent IDs, then require the matching settlement, visible assistant identity, and exact child result. Raw append ancestry can cross a side append into an earlier turn; the canonical selection keeps that branch distinction intact. This removes the separate parent-ID set; production grows by 27 net lines to reuse the owner and preserve ordering barriers.

Adapts Free Wortley’s branch-selection approach from https://github.com/openclaw/openclaw/pull/181239, with co-author credit. That branch is not maintainer-editable; this replacement preserves the current verbatim-result handling and turn/control boundaries.

+export async function findSubagentHandoffReply(
+  visibleMessages: readonly unknown[],
+  childSessionKey: string,
+  childReply: string,
+  readRequesterTranscript: () => Promise<readonly unknown[]>,
+): Promise<string | undefined> {
+  const visible = new Map<string, string>();
+  // Compare forward through the producer's lossy framing, never decode or accept a truncation.
+  const resultBlock = wrapPromptDataBlock({ label: "Child result", text: childReply });
+  if (!resultBlock) {
+    return undefined;
+  }
+  const expected = resultBlock.split("\n").slice(2, -1).join("\n");
+  for (const message of visibleMessages) {
+    if (!isRecord(message) || message.role !== "assistant" || message.phase === "commentary") {
+      continue;
+    }
+    const meta = message["__openclaw"];
+    if (!isRecord(meta) || typeof meta.id !== "string" || !meta.id) {
+      continue;
+    }
+    const text = extractGatewayMessageText(message);
+    // Consume the known result before looking for Evidence: it can contain that very label.
+    // The mock provider puts the verbatim result in a Markdown list.
+    const label = /^Delegated task:[\s\S]*?^Result:[ \t]*(?:\r?\n)?/im.exec(text);
+    const result = label && text.slice(label.index + label[0].length).trimStart();
+    if (
+      result &&
+      [expected, `- ${expected}`].some(
+        (value) =>
+          result.startsWith(value) && /^[ \t]*\r?\n\s*Evidence:/i.test(result.slice(value.length)),
+      )
+    ) {
+      visible.set(meta.id, text);
+    }
+  }
+  if (visible.size === 0) {
+    return undefined;
+  }
+
+  const afterDelivery = new Set<string>();
+  for (const event of await readRequesterTranscript()) {
+    if (
+      !isRecord(event) ||
+      event.type !== "message" ||
+      typeof event.id !== "string" ||
+      !isRecord(event.message)
+    ) {
+      continue;
+    }
+    const { id, parentId, message } = event;
+    if (message.role === "user") {
+      const p = message.provenance;
