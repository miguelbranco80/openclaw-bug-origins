## Fix PR #158207 description (by steipete, opened 2026-09-25T16:23:58Z)

```text
## What Problem This Solves

On a Mac where an ACP-capable CLI is installed but not signed in (here the Qwen CLI), OpenClaw auto-detects the `acp-qwen` provider and its catalog read ends with `auth-rejected`. `models.list` then reported `refreshFailed: true`, so the Control UI Automations page (and other catalog consumers) showed "Some models could not be refreshed. Open Models to try again." on every visit. Retrying can never clear it, because the provider's auth is rejected, not transiently failing. Observed live on `main` (`d36ba5479c3`): `acp-opencode` and `acp-copilot` were `ready`, `acp-qwen` was `auth-rejected`, 99 models listed, banner permanent.

## Why This Change Was Made

`src/agents/prepared-model-runtime.publication-events.ts` classified every non-`ready` provider outcome as a refresh failure. A rejected credential is a determinate provider state that is already surfaced per model (`availability: false`, `unavailableReason: "auth-failed"`) and, for installed ACP apps, as "Sign in required" in the picker. The publisher now counts only `unavailable` outcomes and recorded acquisition errors as refresh failures; auth rejections keep their diagnostics and the incomplete-inventory protection. The CLI's duplicate classification in `models list` is removed so it reads the same published fact.

Genuine refresh failures (timeouts, malformed catalogs, internal errors — the case #142372 surfaces) still set `refreshFailed`.

## User Impact

Having an installed-but-signed-out ACP CLI no longer puts a permanent "try again" warning on Automations, model search, and pickers; the provider still shows as needing sign-in.

## Evidence

- Producer tests: auth-rejected alone ⇒ no refresh failure; auth-rejected plus a genuine failure ⇒ refresh failure. Boundary tests for `models.list` provider outcomes, the native picker failure path, and `openclaw models list` prepared catalog. Regressions fail on current `main`.
- Direct Vitest over the affected suites: 104 passed.
- Consumers checked: `models.list` presentation, chat metadata `catalogRefreshFailed`, `/models`, CLI `models list`, picker/search, Automations, Agents, Settings.
- `oxfmt --check`, `git diff --check` pass; Codex autoreview scoped-clean ("patch is correct"). The repo-wide assertion-safety scan did not finish locally under extreme host load; CI is authoritative.
- Docs: `docs/cli/models.md` notes that rejected sign-in is not reported as a refresh failure.

Production LOC: −1 (+10 / −11). Tests: +109 / −63. Docs: +5.
```
