## Fix PR #180841 description (by steipete, opened 2026-10-22T17:41:00Z)

```text
Related: #178538, #176777, #172971

## What Problem This Solves

Fixes shutdown waiting indefinitely for optional worker reconciliation when an allocation lookup never returns or reconciliation is queued behind an admitted provider mutation.

## User Impact

A stopped Gateway can leave optional reconciliation without discarding the durable allocation or cleanup intent. Existing explicit destroys and admitted provider mutations still settle before their owner closes. Pending shutdown diagnostics now identify the environment, provider, and operation.

## Why This Change Was Made

The affected Team deployment included #178538. That change bounded inspection, but the allocation lookup in `provider-owner-lifecycle.ts:313` still entered the provider queue without the reconciliation cancellation signal. The environment lock also admitted an uncancellable observer wait, and placement joined the whole shared sweep.

The environment owner now passes reconciliation cancellation into read-only allocation lookup and checks it before recording errors or publishing a late allocation identity. Queued reconciliation can stop waiting before it acquires the lock; its retained callback checks shutdown before doing work. The shared sweep exposes a shutdown-cancellable observation while retaining actual work in the existing owner joins. Provider queue ownership for mutations is unchanged. No schema or public provider contract changes.

The complete incident journal does **not** identify an environment, provider, or leaf call. This fixes reproducible remaining cancellation gaps and adds bounded diagnostics, without claiming to have identified the production leaf. Pending traces name lock/inventory, installation/credential, and provider-call stages (inspect, resolve-allocation, provision, destroy, SSH identity). Provider identity is captured at call admission, so formatting still identifies the call after inventory reads are closed. Direct reconciliation preserves inventory recovery by awaiting readiness before reading diagnostic provider identity.

Accepted limitation: a provider mutation or admitted durable effect still has to settle; shutdown cannot safely abandon it or fabricate its receipt. Providers without a cancellation API may finish a read-only request later; its result cannot resume the cancelled reconciliation or cause destruction.
