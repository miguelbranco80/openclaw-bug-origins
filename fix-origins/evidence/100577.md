## Fix PR #153597 description (by steipete, opened 2026-09-20T09:27:05Z)

```text
## What Problem This Solves

Fixes browser inspection and actions that time out, use stale element refs, or leave labels behind when tabs close, controls disappear, or captures overlap cancellation.

## User Impact

Browser actions retain the captured element identity, healthy tabs keep their connection when another tab closes, and CLI callers receive the browser timeout diagnostic. Node requests retain their selected profile and recheck access before acting.

Chrome MCP can emit ambiguous element IDs across renderer documents. Affected snapshots now fail with a managed-profile alternative; ref-free screenshots still work. This change does not upgrade or patch Chrome MCP.

## Why This Change Was Made

The snapshot paths now share one implementation and validate capture lifetime and document identity before changing or publishing refs. Ignored accessibility wrappers retain their visible descendants. Labeled MCP captures group work by document and finish cleanup before reporting success.

Related: #153420.

## Compatibility Decisions

The two compatibility risks raised in review are accepted for this repair:

- Cross-document Chrome MCP ID collisions now return an explicit error. The pinned dependency accepts UID-only actions, so preserving the old behavior can target a different control. Ref-free screenshots remain available, and managed profiles support ref-based work on affected pages. The collision frequency across real sites is not measured; this PR does not claim it is rare or patch the dependency.
- A snapshot refresh retires earlier refs for that target, including a failed refresh or a condition wait that captures internally. The documented contract already limits refs to the latest snapshot, and the dependency may replace its handles before the refresh fails. Keeping those aliases cannot preserve their original identity. Callers must take a fresh snapshot after such a wait or failure; sibling-tab refs remain valid.

These are intentional corrections to element identity and ref lifetime within the requested browser repair. Existing Chromium and snapshot-identity regressions cover rejection, refresh failure, wait behavior, and sibling-tab isolation. No API shape, configuration option, or dependency version changes.

## Evidence

595 tests passed across 26 files, including 61 real Chromium cases. The live cases check actual element identity, cancellation after a delayed CDP response, same-process and cross-process frames, ignored accessibility roots, label cleanup, and screenshot geometry. The full browser CLI suite also passes 267 tests, including the sibling transport-budget assertions exercised by CI. The final protocol-fixture correction passed its 17 owning unit tests and production/test typechecks.

The complete changed-file gate passed; the final navigation fix and CLI test correction passed their selected-file gates. Independent review is clean through P2 for the complete production diff and the CLI follow-up.

The supported CLI → Gateway → node → Chromium flow reproduced a generic Gateway timeout before the fix. With the fix, the same 1,000 ms request returned the detailed browser timeout and recovered on the same tab. The isolated Testbox and its browser processes were stopped afterward.
```
