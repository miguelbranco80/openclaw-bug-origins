## Fix PR #170403 description (by vincentkoc, opened 2026-10-12T23:57:14Z)

```text
## What Problem This Solves

Fixes node service install, start, stop, restart, and uninstall failing when the node uses a custom state directory.

## User Impact

Operators can manage an existing node through its native service owner while preserving its configured state location and current service custody.

## Why This Change Was Made

Node services were incorrectly subject to Gateway-only installation identity checks. The shared service owner now applies those checks by service kind, while retaining its operation lock, current-authority checks, definition checks, and future-config refusal.

Node lifecycle commands validate configuration without startup maintenance or plugin discovery. The service's future-version check also reads without publishing config observations, so a controller can act on an older node without preparing its state before the service action.

## Evidence

- The real Node service adapter reproduced the custom-state refusal in all three existing success/revocation/definition-race rows; the Gateway controls remained valid.
- The registered CLI pre-action and real service guard reproduced config observation before future-version refusal.
- Focused final run: 35/35 tests across the three service files; 52.64 s command wall time (48.28 s Vitest). No new process or Gateway fixture.
- Core types, service test types, targeted type-aware lint, formatting, and line-limit ratchets passed.
- Independent owner review and fresh AutoReview found no actionable issues.
- Live fleet cutover proof remains separate and depends on the retained-service restore adapter.
```
