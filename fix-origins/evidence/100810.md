## Fix PR #158235 description (by steipete, opened 2026-09-25T17:50:12Z)

```text
## What Problem This Solves

Task-retention maintenance could block the Gateway event loop while waiting for SQLite write coordination. It now uses the existing read and write workers so unrelated Gateway work can continue.

## User Impact

Retention deadlines, cron-history limits, stored formats, and update behavior are unchanged. No operator migration is required.

## Why This Change Was Made

The read worker prepares the selected task and fingerprint; the write worker revalidates that source and live authority inside the transaction. A compact commit receipt settles a lost reply without replaying the write. The publication owner reconciles indexes, activity, and flow effects before notifying observers, preserving newer owners and unknown outcomes. The superseded synchronous retention APIs and callers are removed.

## Evidence

The real coordinator-contention regression passes with this cutover and fails on the original synchronous path at the responsiveness assertion. Retained proof covers retention, publication, delivery, restore and replacement races, shutdown, and lost-result settlement. The full build, benchmark flow, production types, all 25 test-type graphs, script types and selected guards passed. Counts from the successive proof batches overlap and are not a unique-test total.
```
