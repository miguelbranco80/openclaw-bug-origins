## Fix PR #172135 description (by steipete, opened 2026-10-14T12:48:17Z)

```text
## What Problem This Solves

When another plugin (for example Hindsight) owns the memory slot, `openclaw memory status` and Doctor's memory provider probe passed the provider an unresolved SecretRef, so it reported "Invalid API key" even though the Gateway resolved the credential and worked (#172098).

## Why This Change Was Made

`memory status` returned through the foreign-provider branch before `loadMemoryCommandConfig` ran, and that resolver only covered memory-embedding targets. Doctor's provider-runtime branch handed raw config to the provider. Both paths now resolve the selected slot owner's manifest-declared secret targets (new generic getter next to the existing ones in `src/cli/command-secret-targets.ts`) through the existing command secret resolution, and an unresolvable credential reports unavailable instead of probing with the ref. No Hindsight-specific code in core; Hindsight reporting `ready` after swallowing an auth error is a plugin-owned follow-up.

## User Impact

`memory status` and Doctor report the real state of foreign memory providers that use SecretRefs.

## Evidence

- Four regression cases (status and Doctor with a resolvable exec SecretRef; both with an unresolvable ref) fail before the fix and pass after.
- 26 focused tests across 3 files pass; formatting and review pass.
- Production +24 LOC, tests +164; one assertion-safety baseline entry removed (shrink only).
- Unrelated/inherited: `check:changed` reports the production env-var name budget at 455/454, reproducing on the untouched base.

Fixes #172098
```
