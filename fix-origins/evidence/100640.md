## Fix PR #185154 description (by roboclaw-bot, opened 2026-10-26T23:16:31Z)

```text
## What Problem This Solves

Fixes: pasted chat images keep a padded 3:2 frame until the conversation is remounted, even after their actual dimensions are available.

## User Impact

Single-image previews immediately use the image's aspect ratio and retain it after returning from Settings or reloading. Very wide and tall previews remain bounded without distortion, and their file actions remain reachable. No configuration changes or migration are required.

## Why This Change Was Made

The mounted frame deliberately froze its initial dimensions. It now derives geometry from the existing image presentation owner, using decoded dimensions only when durable upload dimensions are absent. The frame has one dedicated Solid component; no new cache or state owner is introduced. The obsolete untrack allowance and minimum-height letterboxing are removed.

The simplification pass retained the existing resource owner and moved its frame rather than introducing a parallel renderer. Production changes add 47 net lines for reactive geometry and reachable extreme-ratio actions; regression tests add 125 net lines.

## Evidence

- Reproduced the native clipboard paste/send problem against an isolated real Gateway: the 1200 × 563 image remained in a 3:2 frame before the fix.
- Replayed native ClipboardItem paste → send → upload receipt → Settings/back → reload. The patched surface stayed 400 × 187.65625 pixels at every stage. Only model inference used a synthetic loopback provider; clipboard, Gateway, media materialization, history, and browser rendering were real.
- 30 Chromium image-geometry cases, 55 image consumer tests, and 6 browser/Gateway end-to-end cases passed. UI build, TypeScript, targeted lint/format, stylesheet lint, and controller guards passed.
- Independent Codex P0–P2 review: no actionable findings. Its review covered the supplied patch, not executed tests; the live evidence above is from the implementation session.
```
