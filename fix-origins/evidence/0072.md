## Summary

### High Level TLDR

When several agent runs share one OAuth account, one run refreshes the expiring token and the others make their next model request during that refresh. Those other runs failed on the spot with `MCP authorization state is temporarily unavailable` (`MCP_AUTHORIZATION_UNAVAILABLE`) and the whole run ended. This change makes the request wait, bounded, for the peer's refresh to settle, then continue with the refreshed token. Retired, reconnected, closed, or aborted authorization still fails immediately.

### Change

- New `assertSettledAuthProfileAuthorization` (`src/agents/auth-profiles/authorization-settle.ts`): runs the existing `assertCurrent` check. Only on `MCP_AUTHORIZATION_UNAVAILABLE` does it poll (25 ms, abort-aware) until the observation settles, bounded by `OAUTH_REFRESH_CALL_TIMEOUT_MS`, the same bound the OAuth manager already uses when it observes a peer's refresh fence. Every other error is rethrown at once.
- `createEmbeddedRunAuthController` request auth `resolve()`: the two authorization checks around canonical credential resolution use the helper, and **both now run inside the existing `credential resolution` deadline** (`withAuthDeadline`) on its `credentialSignal`. A peer publication that begins as lookup completes is therefore bounded by the run's auth deadline (#189144, #189183), not by a separate budget. The helper's `OAUTH_REFRESH_CALL_TIMEOUT_MS` is only an outer cap. When the post-lookup check had to wait for a publication, the request **resolves credentials again** instead of returning the token read before it, so a superseded (possibly expired) access token is never handed to the transport. The helper returns whether it waited.
- Scope: one bug. The capture at run start, the egress `assertRequestCurrent`, and the authorization or fence model itself are unchanged.

## Root Cause

Before: a refresh by run A makes every concurrent request from runs B, C, D on the same OAuth profile throw `MCP_AUTHORIZATION_UNAVAILABLE`, and the embedded run ends as failed (`failoverReason=unknown`).

Code path:

1. The OAuth manager claims a refresh by persisting a durable pending fence over the credential (`createOAuthRefreshFence`, then `persistOAuthRefreshClaim` in `oauth-manager.ts`). Then it calls the provider and writes the new token. Credential writes also bump `owner.pending` through `fenceAuthProfileAuthorizationWrite`.
2. The authorization observation exposes both states as `unavailable`. `readFact()` throws when `owner.pending || owner.uncertain` (`authorization-observation.ts`), and `assertFacts()` throws when the selected fact is `status === "pending"` (`authorization.ts`).
3. Request auth `resolve()` in `auth-controller.ts` called `assertCurrent()`, which includes `authorization.assertCurrent()`, *before* `getApiKeyForModelCore`. Canonical resolution already knows how to wait for a peer's fence: the `observe` claim path uses `observeOAuthRefreshFenceSettlement`. But the gate threw first, so the request never reached that wait. The error propagated out of the attempt as a fatal run error.

The contract (`authorization-contract.ts`) already separates "known lifetime loss" (`retired`) from "a temporarily unavailable authority observation". The request path treated the transient state as fatal.

Observed in a real deployment: six parallel subagent runs on one Gemini OAuth profile. The stored token's expiry places the refresh's token response at about T+0.25 s after the first failure. Four runs failed between T and T+7 s, each on the first model request after a tool result, each with `MCP authorization state is temporarily unavailable`. A main-thread stall during the refresh settlement widened the window for the last three.

### Account authority during the wait

- **Closure / abort:** the wait polls the full `assertCurrent` (request signal, selection, authorization) every 25 ms and rethrows anything other than `MCP_AUTHORIZATION_UNAVAILABLE`, so closure ends the wait at once (new closure test above). Abort is also observed by `sleepWithAbort` on `credentialSignal`.
- **Disconnect / replacement:** a reconnect or replacement writes through `upsertAuthProfileWithLockOrThrow`, which takes the same profile lock the peer refresh holds, so it cannot land while the fence is pending. Once it lands, authorization reports `MCP_AUTHORIZATION_RETIRED`, which the helper rethrows immediately. A bearer already returned is refused by the unchanged final-egress `assertRequestCurrent`, covered by the existing `refuses a reconnected canonical account after-resolve without an automation binding` test in this run.
- Refresh admission (`assertRefreshAdmission`) and the account-identity validation inside canonical resolution are unchanged.

Performance (uncontended happy path, 10 rounds × 100 `resolve()` calls): base 1.30 ms, fix 1.30 ms median. The uncontended path still does one synchronous check.

## What was not tested

- No end-to-end rerun against a live Gateway or production provider transport with several real OAuth-backed runs racing a real token refresh. The race depends on token-expiry timing. The proof above uses real stores, fences, and the real request-auth capability with a mocked provider refresh.
- A sticky `owner.uncertain` publication (a write whose settlement is unknown) now waits up to `OAUTH_REFRESH_CALL_TIMEOUT_MS` before it surfaces the same `unavailable` error. Before, it surfaced immediately. Not separately exercised.
- Not changed or tested here: `captureAuthProfileAuthorization` at run start can still fail fast if a run *starts* during a peer refresh, and the egress-time `assertRequestCurrent` is unchanged.

+/**
+ * A peer's credential write (an OAuth refresh claim, then its result) leaves the shared
+ * authorization observation unavailable until it settles. Wait for that publication within
+ * the refresh-call bound instead of failing the caller; retirement and closure still throw.
+ * Returns whether it had to wait, so callers can discard state read before the publication.

+export async function assertSettledAuthProfileAuthorization(
+  assertCurrent: () => void,
+  signal: AbortSignal,
+): Promise<boolean> {
+  const deadline = performance.now() + OAUTH_REFRESH_CALL_TIMEOUT_MS;
+  for (let waited = false; ; waited = true) {
+    try {
+      assertCurrent();
+      return waited;
+    } catch (error) {
+      if (
+        !(error instanceof AuthProfileAuthorizationError) ||
+        error.code !== "MCP_AUTHORIZATION_UNAVAILABLE" ||
+        performance.now() >= deadline
+      ) {
+        throw error;
+      }
+    }
+    await sleepWithAbort(AUTHORIZATION_SETTLE_POLL_MS, signal);
+  }
