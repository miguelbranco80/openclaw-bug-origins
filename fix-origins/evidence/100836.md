## Fix PR #156160 description (by steipete, opened 2026-09-23T04:04:23Z)

```text
## What Problem This Solves

Fixes a Gateway crash after a diagnostic Doctor check closes its live worker-environment inventory, even though the shared database already has the current schema.

## User Impact

Routine checks keep existing worker environments usable. Actual repairs still retire the old database generation, including when cleanup fails after repair; ownership refusals preserve the live generation. There are no schema, configuration, or permission changes.

## Why This Change Was Made

The migration wrapper always closed shared-state resources after checking readiness. Move preparation and retirement into one asynchronous owner that records actual repair admission, preserving synchronous database transactions and the existing synchronous SDK repair API. Both migration callers use that owner.

Also keep a session-change callback from returning an already-tracked reconciliation promise into an ignored promise chain. The existing reconciliation owner continues to log failures and drain work at shutdown.

## Evidence

- Reproduced both no-op preparation modes with a real SQLite inventory: reads failed with `Worker environment inventory has closed` before the repair.
- Reproduced the unhandled rejection through the actual placement startup/session-change subscription.
- Reproduced a post-commit native-close failure that skipped resource retirement, with separate pre-admission refusal controls.
- Focused tests exercise inventory reads and writes after checks, actual repair/reopening, failure settlement, ownership refusals, and existing migration callers.

The production failure was observed during an update; isolated source and SQLite tests exercise its owning boundaries. No production state or schema version was changed for these proofs. 204 focused tests passed (199 across 16 files in 118.37s;5 selected large-suite cases in 8.80s).
```
