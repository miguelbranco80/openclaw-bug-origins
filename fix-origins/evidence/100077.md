## Fix PR #155676 description (by steipete, opened 2026-09-22T10:44:30Z)

```text
## What Problem This Solves

Catalog polling rebuilds unchanged resident session selections when multiple agents are configured, because each agent evicts the previous agent's cached selection.

## User Impact

Repeated catalog polls reuse their prepared agent selections and spend less main-thread CPU rebuilding row maps. Committed metadata changes remain visible on the next poll.

## Why This Change Was Made

Keep selections under the existing weak revision key, separated by stable topology scope and `activeOnly`. Each scope retains at most two broad selections for the current revision. Publications and disposal release the revision and its row graphs; keyed reads bypass this cache. Federation, visibility, and presentation continue through their existing owners.

## Evidence

The registered-handler regression reproduces repeated scans on the original code and passes with this change. It verifies separate identities and creators for two populated agents, a committed label update, and reuse after that update. The retention test now holds all three scope forms and both `activeOnly` variants, then proves collection after publication and disposal. All 28 focused cases pass across the final changed file and the three owner/sentinel/retention siblings. The materially changed catalog test file takes 30.98 seconds through the single-worker wrapper, including transformation and startup; its five test bodies total about seven seconds.

A fixed local A/B/B/A fixture with 1,000 rows, four configured agents, and 200 sequential registered-handler polls per run retained identical responses. Baseline runs used 60.076/62.001 ms of main-thread CPU; candidate runs used 40.990/37.275 ms. The mean reduction is 35.9%, or 0.110 ms per poll. Repeated broad selections fell from 800 to zero, and repeated row selections from 200,000 to zero. Only one agent has rows in this CPU fixture. These four runs measure the whole fixture loop, including counters and assertions; the saving is limited to that workload.

Managed independent P0–P2 review is scoped-clean. The complete selected changed-file gate passed, including core/test types, typed lint, formatting, and repository guards.
```
