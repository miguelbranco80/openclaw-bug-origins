Fixes a follow-up to the long-turn Stop history repair: an opening prompt can disappear behind **Show earlier** when the pane previously read a complete server prefix and Stop advances the active transcript leaf.

The older-page decision treated the previous row count as proof that the pane could reuse that prefix. The branch-identity guard correctly rejects held rows from a different leaf, so the two decisions could publish only the bounded tail. Remove the count shortcut and fetch the existing, bounded authoritative older page before publishing the replacement. Session/request ownership, branch isolation, window-reset behavior, the 1,000-row bound, and the retryable failure boundary remain unchanged.

This deliberately accepts one extra bounded history read for an already-held prefix after a cursor reset. There is no new cache, state mirror, protocol, retry, or startup import. This is a correctness repair, with no latency-win claim.

+export async function fillHeldHistoryGap<Tail extends ChatHistoryResult>(

+  client: NonNullable<ChatState["client"]>,
