## Fix PR #168383 description (by dhruv1220, opened 2026-10-10T10:19:40Z)

```text
Fixes #168366

## What Problem This Solves

Fixes: Telegram rich replies nest a preceding Markdown table inside a following quote or silently omit it before a following list.

## User Impact

Tables and their neighboring quotes, lists, headings, code blocks, and paragraphs retain their authored boundaries. Tables at the end of a quote or list also stay in their container. Rich delivery and the plain-text recovery path preserve every table value. No configuration, schema, protocol, or SDK surface changes are required.

## Why This Change Was Made

A native table previously consumed no Markdown IR coordinates, allowing an unrelated following block to share its position. The parser now reserves one whitespace coordinate for each native table and preserves it through quote closure and final trimming. Telegram can use ordinary block ordering; its table-specific ownership heuristic is deleted. The quote boundary is calculated once for both style and structural metadata.

Original fix by @dhruv1220; maintainer cleanup moves boundary preservation to the shared Markdown parser, removes the renderer special case, and extends the regressions to sibling and trailing-container cases. The contributor's ancestry and human co-author credit are preserved.
