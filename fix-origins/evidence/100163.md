## Fix PR #169322 description (by steipete, opened 2026-10-11T19:52:54Z)

```text
## What Problem This Solves

Fixes: an overlapping OpenAI Responses SSE request loses saved reasoning-effort controls when another request in the same session owns the continuation cache.

## User Impact

Matching conversation history keeps its original prompt prefix and reasoning changes during parallel requests.

## Why This Change Was Made

The request preparation now restores persisted effort controls even when no continuation claim is available. The existing cache owner still controls continuation state. Production code decreases by one line.

## Evidence

The regression uses the real OpenAI SDK and captures serialized HTTP requests at a local server. It establishes low-to-high reasoning history, holds one request at response acceptance, and admits another request in the same session. Before the fix, the concurrent request sent only the current medium effort; afterward, it preserves the original low effort and both historical controls.
```
