## Fix PR #181966 description (by holgergruenhagen, opened 2026-10-23T22:09:16Z)

```text
Fixes #181945

## What Problem This Solves

Fixes: a Claude CLI chat loses its whole conversation when the user stops the very first turn; every following turn starts a new native session until one turn finishes normally.

## User Impact

User impact: stopping the first turn of a Claude CLI chat (Control UI Stop, `chat.abort`) keeps the native session, so the next turn resumes it and the model still knows what was said. Affected today: every native-login Claude CLI chat whose first turn is stopped (for example a long first research turn); later turns see no history, because history reseeding across the auth boundary is refused (`auth-unknown`). Turns that already had a binding were not affected and behave as before.

## Why This Change Was Made

A stopped turn returns its partial output, but `executeCliAttempt` then calls `assertCurrent()` (`src/agents/cli-runner.ts`) and rethrows the abort before settlement. For a resumed turn that is fine: the existing binding stays. For a first turn nothing was bound yet, so the new native session id is dropped even though its transcript is on disk.

The runner now catches only that case at the same boundary, hands the new session to a store write owned by the turn's placement settlement, and rethrows the unchanged abort. Nothing else changes for the stopped run: no settlement, no transcript or hook writes, no replay, no fallback.

The write is deliberately narrow:

- only a direct user stop (`isAgentRunDirectAbortReason`); superseded, restart and generation aborts bind nothing;
- only a first turn: no reusable session and no resume id, so resumed turns, fork successors and fresh-session retries are untouched;
- only Claude CLI with session binding enabled, and only after `isCliBindingFlushed` finds the native transcript on disk (also for live sessions);
- only into an empty binding, under the turn's `assertSettlementCurrent` and the exact local session id, lifecycle revision and active writer (`patchCliSessionBindingInStore`), so a reset, released or replaced session is never written;
- not for room events or provenance that preserves user-facing session state;
- a refused write is logged and the abort still propagates.

On https://github.com/openclaw/openclaw/pull/147139 ("New claims … retain their abort guards"): that PR protects an established binding from being replaced by an unfinished claim. This change keeps all of those guards. It does not settle a cancelled run or let a new claim replace anything; it only fills a binding that is still empty, for the one session the stopped first turn created. The caller-abort check of the normal publication path (`assertCliSessionBindingResultCommitAllowed`) is unchanged.

The binding uses the same facts as normal settlement (auth profile/epoch, prompt and tool hashes, cwd, MCP hashes, reseed receipt), now built by shared helpers `buildCliSessionBinding` and `buildCliReseedReceipt` in `cli-run-settlement.ts`.

Not covered: the command path (`src/agents/command/attempt-execution.ts`) and scheduled runs keep their current behavior; the reported case and the reproduction go through the chat reply path.
