## Fix message body

```text
fix(ui): show later slash completions in command drafts

Fixes #164838.

In the chat composer, when a draft started with a command (for example `/name Draft /statu after`), the slash menu did not show completions for a later command at the cursor, and Enter sent the whole draft instead of the command the user was typing. The cursor's command now takes precedence over the leading command's arguments. Enter or a click sends only the selected command, `/status` here, and the rest of the draft stays in the composer unsent. Tab still only completes. Ordinary command arguments, active freeform arguments and the `canRun` checks are unchanged. The fix is ported to the current Solid menu-state owner.

Evidence: built Control UI in Linux Chromium with only the Gateway transport mocked, twice per ref. On main, no `/status` completion appeared and Enter sent the whole draft. With this change Enter and a click sent only `/status`, and `/name Draft after` stayed unsent. Argument controls behaved the same on both refs. Details and screenshots: https://github.com/openclaw/openclaw/pull/164839#issuecomment-6556066820.

Thanks @ooiuuii.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```
