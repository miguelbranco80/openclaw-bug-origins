## What Problem This Solves

Fixes undersized context and output limits when Microsoft Foundry creates configuration for documented GPT-5 model families, including GPT-5 mini deployment aliases.

## User Impact

New configurations for the known GPT-5, GPT-5.1, GPT-5.2, and GPT-5.3 Codex families receive 400,000 context tokens and 128,000 output tokens. Existing configured limits survive model selection and runtime normalization, including deliberate 128,000/16,384 caps with canonical model identity already present. Previously generated undersized entries remain unchanged and can be adjusted explicitly.

## Why This Change Was Made

The exact-family resolver in `extensions/microsoft-foundry/shared.ts:206` only covered GPT-5.4 mini/nano in the 400K family. Older documented families fell through to the generic 128K/16K fallback. Extend that existing mapping while preserving the separate large-context families, chat models, and unknown-model fallback.

This rewrite omits the old PR's automatic persisted-limit repair: canonical model identity does not establish who chose the limits, and normal normalization adds that identity itself. It also defers the disputed Codex Max reasoning change. No migration, new setting, or reasoning-policy change is included.
