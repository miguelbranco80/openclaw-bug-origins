## What Problem This Solves

Fixes: a chat turn rejected because its operator authority became inactive gives no recovery instruction, leaving users to repeat the same request without knowing what to change.

## User Impact

The existing source and execution authority errors now say to reconnect to the Gateway and resend the message. If access is denied, they direct the user to an administrator. The guidance appears in chat error details and in callers that surface the owner error.

## Why This Change Was Made

The authority owner supplies the recovery text, so sandbox wrappers and other consumers receive the same advice. Every closure-bound lifetime and revocation check remains unchanged; reconnecting never revives old tools or callbacks. No configuration, schema, cache, or automatic retry is added. Production growth is three lines for the shared message.

This is a recovery-guidance fix. Investigation did not establish a persistent stale-authority record: both baseline and candidate admit fresh authenticated requests and prepare the same sandbox after an old source is revoked. The triggering revocation in the reported incident remains unattributed; this PR does not claim to eliminate it.
