```text
The iOS composer only accepted text paste, so an image-only clipboard
(for example a cropped screenshot shared with Copy and Delete) offered
no Paste action. Port the macOS composer's image paste contract to the
```

## Fix PR #161627 description (by Marvinthebored, opened 2026-09-30T05:07:53Z)

```text
Closes #161626

## What Problem This Solves

Fixes an issue where iOS users who copy an image and try to paste it into the chat composer get no attachment. For example, a user takes a screenshot, crops it, and taps **Copy and Delete**. Then the user long-presses the composer, and the edit menu offers no **Paste** action (only **AutoFill**). The only workaround was to save the image to Photos and attach it through the photo picker.

The macOS composer already supports image paste. The iOS composer only accepted text paste.

## Why This Change Was Made

The iOS composer text view now uses the same paste contract as the macOS composer (`ChatComposerNSTextView`):

- It offers **Paste** when the pasteboard has images.
- It stages each pasted item through the existing `onPasteImageAttachment` → `addImageAttachment` path, so size limits, JPEG transcoding, and session ownership are the same as for other image attachments.
- It leaves text-only paste to UIKit.

Each item uses its first representation that ImageIO can decode, because the upload transcoder uses ImageIO. For example, an item that offers SVG before PNG uses the PNG. When the composer is embedded with attachments disabled, the paste callback is nil and UIKit's default paste behavior is not changed.

Non-goals, same as macOS: when one paste has both an image and text, the image wins and the text is not inserted. File URLs from the Files app are not handled.

## User Impact

On iPhone and iPad, a long-press **Paste** (or hardware ⌘V) in the chat composer now attaches a copied image, such as a cropped screenshot, a photo copied from Photos, or an image copied from Safari. The image appears as a normal attachment chip that can be removed or sent. Text paste does not change.
```
