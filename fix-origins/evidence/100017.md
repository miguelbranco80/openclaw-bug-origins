## What Problem This Solves

Fixes: Gateway shutdown can hang on usage backfill while catalog pricing preparation is pending.

## User Impact

Stopping the usage sidecar now cancels its pricing wait and releases its refresh lock. Committed cost-cache rows remain intact; unfinished refresh work is rebuilt on the next startup. No configuration, schema, or migration changes.

## Why This Change Was Made

The sidecar already aborts its work scope, but `prepareUsageCostPricing` awaited catalog preparation without observing that signal. The worker runtime holds its refresh lock across this await. Race this optional preparation against the existing scope signal, retaining the existing joins for native workers and admitted cache writes. Shared catalog preparation may finish independently; the cancelled refresh cannot continue to scan or write.

The incident journal identifies the usage sidecar as the only pending named owner at the 82-second shutdown deadline, but cannot identify its inner await. This regression proves a remaining cancellation hole after #187877; it does not establish that every production SIGKILL has this cause. Earlier stops with no pending close steps also recorded service-child cleanup failures, which need separate investigation.

+export async function resolveUsageCostPricingFingerprint(
+  config?: OpenClawConfig,
+  agentDir?: string,

+  await prepareModelPricingContext(config);
+  return resolveModelCostConfigFingerprint(config, agentDir);
+}
+
+export function createUsageCostResolver(params?: {
+  config?: OpenClawConfig;
+  agentDir?: string;
+}): UsageCostResolver {
+  const cache = new Map<string, ModelCostConfig | undefined>();
+  return ({ provider, model }) => {
+    const key = `${provider ?? ""}\0${model ?? ""}`;
+    if (cache.has(key)) {
+      return cache.get(key);
+    }
+    const cost = resolveModelCostConfig({
+      provider,
+      model,
+      config: params?.config,
+      agentDir: params?.agentDir,
+    });
+    cache.set(key, cost);
+    return cost;
+  };
+}
+
+/** Diagnostic readers prepare only when a record actually needs an estimate. */
+export async function parseUsageCostTranscriptEntryAsync(
+  parsed: Record<string, unknown>,
+  resolveCost: UsageCostResolver,
+  config?: OpenClawConfig,
+): Promise<ParsedTranscriptEntry | null> {
+  const entry = parseUsageCostTranscriptRecord(parsed);
+  if (!needsUsageCostEstimate(entry)) {
+    return entry;
+  }
+  await prepareModelPricingContext(config);
+  return applyUsageCostEstimate(entry, resolveCost);
+}

Related: #140086

## What Problem This Solves

Makes each usage-cost operation retain one hosted pricing context, preparing usage accounting for catalog updates that can occur while an operation is running.

## User Impact

No user-visible change in this PR. Catalog downloads still require a Gateway restart to activate. Existing recorded costs, configured overrides, local model prices, and tier handling keep their current behavior. There are no configuration, protocol, SDK, or storage changes.

This is the maintainer-requested accounting prerequisite for live catalog publication, not the activation change itself.

## Why This Change Was Made

Usage refresh previously selected its pricing fingerprint and each lazily resolved model price independently. The refresh now captures the hosted pricing context once and uses it for both. Diagnostic readers retain lazy preparation and capture their context when estimation first becomes necessary; subsequent model lookups retain that context.

The ordinary synchronous pricing APIs still use the same resolver and preserve their existing lookup behavior. Fingerprint-only reads do not allocate an unused captured resolver.
