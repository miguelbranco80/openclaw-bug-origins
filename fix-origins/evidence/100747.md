## Fix PR #167895 description (by obviyus, opened 2026-10-09T17:55:14Z)

```text
## What Problem This Solves

Fixes explicit `[[reply_to_current]]` and `[[reply_to:<id>]]` tags being ignored when Telegram partial streaming finalizes a preview with a different reply target.

## User Impact

Explicit reply tags work with partial streaming, including when implicit threading is off. If an existing preview has the wrong target, the final answer uses normal delivery and the preview is removed after the replacement is accepted. No configuration, SDK, or stored-state changes.

## Why This Change Was Made

The preview-reuse guard compared the final payload's target to the same incoming payload's target. That detected targets introduced by transcript recovery, but not explicit targets already present in the prepared final. Telegram edits cannot change a message's reply target.

Compare the resolved reply ID to the stream's actual message snapshot instead, and remove the obsolete pre-recovery-target parameter. The existing mismatch path owns replacement delivery and preview cleanup.

The earlier transcript test passed because recovery changed an initially absent target. Its table now distinguishes recovered and initially present current-message targets; the new row fails on the original code.

Related: #129289 repairs explicit targets in durable/legacy sending; this fixes preview reuse before those senders are reached. #130722 preserves model-authored completion directives upstream; the directives are already present in this reproduction.
```
