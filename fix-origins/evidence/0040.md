## Fix PR #190221 description (by steipete, opened 2026-11-01T10:02:54Z)

```text
## What Problem This Solves

Typing in Automations search repeatedly invalidates retained rows' owner-permission bindings. After #189749, the 500-job scenario rose from roughly 14 ms to 48 ms of desktop Chromium scripting.

## User Impact

Restores responsive multi-keystroke search while preserving human-owner editing, transfer, live permission changes, and the existing mutation-time authority checks. Thanks @VACInc for the owner-management feature in #189749.

## Why This Change Was Made

The permission callback was reached through the whole page's reactive props. Each search publication could re-enter the retained row controls, including speculative rendering that never became DOM mutations. The renderer now derives permission invalidation from actual Gateway/auth/identity and profile-directory changes, supplies those bindings separately, and suppresses equal per-row results. The permission policy stays with the existing owner; there is no new authorization cache or request-coalescing change.

## Evidence

The committed `cron-search-typing` scenario loads 500 jobs, types `Warm automation 0499` using `pressSequentially`, and waits for the final response and single matching row. This uses the production renderer and benchmark HTTP server with synthetic Gateway data; it makes no provider/network latency claim.
