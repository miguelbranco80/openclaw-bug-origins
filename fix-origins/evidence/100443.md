## Fix PR #148962 description (by vincentkoc, opened 2026-09-15T09:19:16Z)

```text
## What Problem This Solves

Managed worktree cleanup could retain many failed records while reporting a healthy result. The idle pass also tried the same failed worktree again during count or size enforcement, doubling work and producing misleading `limits still exceeded` logs.

## User Impact

Operators now get a bounded per-worktree failure or deferral reason from `openclaw worktrees gc --json`. Partial cleanup returns a non-zero CLI status, scheduled cleanup writes a health error, and Gateway callers receive an explicit non-retryable error after any deletions that did succeed.

## Why This Change Was Made

Each managed worktree ID now receives at most one automatic-removal decision in a GC pass. Failed records stay protected, confirmed removals continue, and up to 64 ID/reason dispositions are returned with a total count when additional results are omitted. The existing three-field Gateway success payload remains unchanged for completed cleanup.

## Evidence

- Blacksmith Testbox `tbx_01m30yxdbzb5k2cn22m6wzx8xk`: dependency install succeeded; formatter identified two files, then both were formatted with the repository command.
- Focused coverage: a missing repository control path is retained, reported once by ID, and skipped by the limit pass; CLI JSON is written before failure; scheduled maintenance logs partial results; Gateway reports partial progress without retrying.
- Hosted exact-head CI and ClawSweeper re-review requested on `c80caf5854d413f240d549adb0425050040eae04`.

Related: #150940
```
