## Fix PR #157629 description (by stevenlee-oai, opened 2026-09-24T22:15:02Z)

```text
Follow-up to the merged #148567, rebased onto `main`. This PR contains only the two account-identity commits.

## What Problem This Solves

SIWC connections omit the signed-in email, and the composer hides account identity behind a generic subscription label, making multiple credentials hard to distinguish.

## User Impact

The provider screen can show the SIWC email. The composer's selected account shows email and sign-in method, such as `account@example.test · Sign in with ChatGPT`, with readable account rows on desktop and mobile. Existing profiles pick up email on their next token refresh, or by reconnecting.

Automatic selection remains explicit: this describes the selected account, not which credential ultimately served or billed a request. Other people's private account details remain hidden.

## Why This Change Was Made

The SIWC parser discarded the email claim from the verified ID token. This saves that claim through the existing credential metadata, reuses it when refresh omits a new ID token, and replaces it when a new token is supplied. Account labels now include both existing email and display name, and the UI no longer suppresses identity when only one account exists.

No credential ownership, account-binding, routing, schema, or permission changes. The incremental diff is nine files and 17 net production lines; the rest is focused regression coverage.
```
