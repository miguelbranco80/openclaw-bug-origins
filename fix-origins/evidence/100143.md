## What Problem This Solves

Visible children created without a model choice failed after a primary rate limit instead of using their configured backup. Closes #148886.

## Why This Change Was Made

The shared spawn planner records automatic intent; creation stores the validated provider and model. Chat and direct `agent` requests carry the stored child relationship to `resolveModelFallbackAvailability`, which owns the backup list. Initial provenance has one writer: session creation.

## User Impact

Children without an explicit model choice use their configured backups during initial and later direct requests. Explicit choices and empty backup lists remain strict; profile suffixes are preserved.

## Evidence

On main, real `chat.send` → `sessions_spawn` children stored user provenance, made ten primary HTTP 429 requests, and failed without a backup request.

The new direct-request cases also reproduced a remaining defect on prior head `1f075e91b09a94c85346baf2fa55ccf63177f000`: later `agent` requests used the agent backup despite distinct or empty child lists.

All eleven Gateway cases passed again using the frozen merge source committed unchanged as `647e2a8ee0cc0087d8a2e90b0e45708c445c66f5` (tree `458047fbe0e057646a3fc73344a9505a5755554a`).
