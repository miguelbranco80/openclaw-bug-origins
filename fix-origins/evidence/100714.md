* fix(compaction): finalize the safeguard summary inside the persistence cap

Replaces this branch's context-window-scaled summary budget with the shipped
16,000-char cap, and fixes the one place main's finalizer could still lose
required facts to that cap.

The session owner caps every stored summary at MAX_COMPACTION_SUMMARY_CHARS
before it appends the boundary. The window-scaled budget let the safeguard
audit up to a tenth of the window, so on a 300k window it audited a
60,305-char summary and the owner stored the first 16,000 chars, cutting the
Pending user asks and Exact identifiers sections the audit had passed.
Whether that cap should scale with the window is a persistence decision; this
keeps it, and drops the scaled budget, its estimated-char conversion and
rawCharsWithinEstimate with it.

fitCompactionSummary searches downward for an artifact that fits the
foreground request budget. A candidate below the retention plan's minimum has
already dropped the required facts, and dense CJK prose made those candidates
cheap enough that the search settled on one: the audited path then cancelled
with "required facts exceed the finalized summary budget" although ~1,850
chars of ASCII ask context fit a 4,000-token budget. The fit callback now
skips candidates under the minimum below the full cap, so the search pays for
the required facts first and trims the prose.

formatRequiredAskContext moves into compaction-safeguard-quality.ts, beside
the retention plan that protects its output, to keep compaction-safeguard.ts
within its line-cap ratchet.

* test(compaction): pin that unaffordable required facts still cancel

Skipping candidates below the retention minimum must not turn a request
budget that cannot hold the required facts into a lossy success. With a
400-token budget and ~1,850 chars of ask context, the fit fails and the
safeguard cancels with the fit's budget error. Without the skip it also
cancels, but with "required facts exceed the finalized summary budget",
which is how the test tells the two paths apart.

* test(vitest): route the safeguard-budget session test through the database-worker project

The test persists a compaction boundary through the SQLite transcript and
reopens it, which main's shared agent-database worker lifecycle
(d22782a7f0, #153150) admits only on the host-owned main thread. It was
added before that guard, so it ran in worker threads and failed with
"Agent admission requires its host owner". Registering it in
databaseWorkerCoreTestFiles routes it to the infra forks project, the same
project its sibling compaction and session tests use.

* test(compaction): drain the agent database before reopening the safeguard-budget session

Since #156095 moved streamed assistant appends onto the SQLite writer worker,
the synchronous close only starts revoking the agent database's async
resources. The next prompt's assistant append then registered a worker store
while the path was still closing and failed with "Agent database resources
are closing". Use closeOpenClawAgentDatabaseByPathAsync, which drains the
owner before it returns, as the sibling reopen tests do.

* docs(compaction): say why the fit skips candidates below the retention minimum

The fit callback's comment said dense CJK made truncated candidates cheap
enough to win. A probe of the regression case shows the opposite at the
boundary: below the retention minimum budgetCompactionSummary falls back to
a head cut of the body, so the 2,000-char cut (leading U+3400 prose) cost
23,351 estimated chars while the 3,000-char retained candidate cost 13,583.
The bisection read the 2,000 overrun as "everything above is too big" and
settled on a 1,387-char cut flagged qualityRetentionInfeasible. Describe
that, and drop two test comments that still referred to the withdrawn
window-scaled budget and CJK-rate conversion.

* refactor(compaction): bound safeguard runtime settings beside the runtime registry

The fit guard adds three counted lines to compaction-safeguard.ts,
which sits over the 700-line cap. This branch used to pay for them by
moving formatRequiredAskContext out, and main's c0c6ca35fce has since
moved that formatter into agent-core itself, so the line-cap ratchet
rejected the merged head (1222 -> 1225). The recentTurnsPreserve and
qualityGuardMaxRetries bounds normalize values the runtime registry
holds, so they move to compaction-safeguard-runtime.ts unchanged.

* fix(compaction): exclude summaries that cannot retain required facts

Keep mixed-script fitting above the retention minimum and remove invalid head-cut candidates. Reuse the shared density estimator and retain the owner cap and fail-closed behavior.

## Fix PR #138416 description (by amittell, opened 2026-09-04T17:02:15Z)

## What Problem This Solves

Fixes safeguard compaction canceling with “required facts exceed the finalized summary budget” when a CJK-heavy summary can fit after trimming optional prose. The preserved history otherwise sends the next turn into the same failure.

Related: #119272, #130393.

## User Impact

Small-context sessions can retain required requests and identifiers while compacting mixed-script summaries. Truly unaffordable required facts still cancel compaction and preserve history. No configuration, dependency, persistence-cap, or token-estimator changes.

## Why This Change Was Made

The shared fitter searches summary character budgets, then applies the existing CJK-aware estimate. Below the required-fact minimum, the safeguard used to return a dense head cut that dropped those facts. Its higher token cost could exclude larger candidates that actually fit. The producer now reports that candidate as too small through the fitter’s existing contract; the redundant later rejection path is removed.

Thanks to @amittell for the original fix and investigation. Contributor commits are preserved, with current main merged into the branch. The final diff removes the obsolete persistence-cap test and unrelated helper relocation: production +6/-11, tests +94/-20, docs +3/-1 relative to the merged main head.
