## What Problem This Solves

Fixes repeated Codex conversation recovery failures after a provider error when another thread keeps the shared app-server active.

## User Impact

A failed conversation can resume its original thread and history with refreshed instructions while sibling work continues. Healthy conversations also wait for asynchronous teardown before resuming. User-owned Codex homes and external proxy/socket connections retain their native retention settings. Provider rate limits still apply.

## Why This Change Was Made

OpenClaw already owns warm subscription retention and child-work protection. Managed local agent-home app-servers now launch with `thread_unload_delay_secs=0`. The lifecycle owner waits for the matching `notLoaded` notification for up to two seconds, aborting with the run. Missing confirmation preserves the binding; the existing guarded whole-client replacement remains available for settled failures only when no sibling work would be interrupted.

Original fix by @zhuyankarl; maintainer cleanup coordinates healthy-thread teardown, preserves external connection behavior, replaces the expensive new native test with focused lifecycle cases, and updates the existing Gateway recovery controls.
