* fix(ui): clear the Mac titlebar on collapsed-navigation page headers

In the Mac app's web-chrome mode, collapsing the sidebar left non-chat page headers under the traffic lights and hosted titlebar buttons: the browser 48px header clearance excluded native hosts and nothing replaced it. The clearance is now a token that follows the app titlebar height on native hosts, and stacks on the lowered in-page cluster for older Mac builds. Adds e2e coverage for both hosts.

* improve(ui): lift page header actions into the Mac titlebar row

With the sidebar collapsed on native macOS hosts, page headers now behave like a native toolbar: the actions ride in the titlebar row on the right, centered with the window controls, while the title stays below the row aligned with the page content instead of the whole header dropping under an empty band. Hub tabs keep their end alignment so the two-row breakpoint applies the clearance once. The page-header e2e proof moves into its own file to stay under the sidebar toggle file's line cap.

* improve(ui): lift any trailing header cell and clear headerless pages on Mac

A page gallery in the collapsed native host showed the meetings page (its own actions class) and the dashboards count not lifting, and plugin panels without a page header still sitting under the titlebar. The lifted cell is now the header's trailing child, and headerless content pads past the titlebar row.

* improve(ui): turn page headers into one toolbar row

Every non-chat, non-settings desktop page header is now a single row: the title centered like a window title (hub pages center their tabs there instead, keeping the h1 for assistive tech), the trailing actions cell at the right edge, intro text below. In the Mac app the row is the 52px titlebar, so the traffic lights and hosted buttons share its centerline once the sidebar collapses; in browsers the collapsed-sidebar control cluster lands on the same line, which retires the old 48px header push-down. Pages that used their own header shapes (meetings, dashboards, plugins hub) now match without per-page rules.

* test(ui): mirror the Mac app's sidebar titlebar padding in the web-chrome fixture

The native web-chrome e2e fixture stamped the host classes and titlebar height but not the stylesheet the app injects to pad the expanded sidebar and settings sidebar past the window controls, so mock captures showed hosted titlebar buttons over the sidebar brand row, which the real app never renders.

* improve(ui): keep the page toolbar row clear of chrome in narrow columns

A screenshot sweep across widths showed the centered title running under the actions at 800px in the Mac app with the sidebar open, and hub tabs under the hosted titlebar cluster at 700px collapsed. The row is now a grid whose leading column reserves the floating chrome width and whose trailing column cannot shrink under its actions, so the middle cell stays exactly centered when space allows and shifts, never overlaps, when it does not. The intro line also gets a little more room under the row.

* improve(ui): keep the page toolbar row clear of desktop caption buttons

Tauri desktop hosts draw their window controls fixed over the row's trailing edge on Linux and Windows; the header now pads its end by the host's window-controls width so page actions stop short of them.

* test(ui): return void from the legacy-host init callback

Playwright 1.63 makes addInitScript resolve to a Disposable, which no longer satisfies the helper's Promise<void> install callback in the test-types check.
