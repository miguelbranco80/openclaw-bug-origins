Supersedes #173609, thanks @Winoren.

## What Problem This Solves

Fixes: browser document reads report revoked access when an allowed navigation invalidates the in-flight read, prompting agents to request permission again.

## User Impact

Interrupted reads now explain that the document changed and tell the agent to inspect the current page before retrying. Stale results remain blocked. Real revocation, restricted pages, and detached debuggers still reject commands; no permission decision changes.

## Why This Change Was Made

Choose the diagnostic only after the existing access check rejects, using the existing proven-tab authority check to distinguish document lifetime from access revocation. No command scope, dispatch, or acceptance checks change.

Reimplemented on trusted main rather than executing the contributor branch. Every commit preserves human contributor credit. Simplification kept the existing owner and state: production is +7 lines because the explicit document and authority checks are necessary; no safe dead or duplicate production code was found to remove. Tests grow five lines by extending existing full-background read-completion cases to both access modes; the matching isolated allocation covers that regression. The extra relay test fixture from the initial revision was removed in favor of these existing tests.
