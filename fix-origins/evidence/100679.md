## What Problem This Solves

Fixes Thinking **Off** still producing reasoning, and missing **Low/High** choices, for OpenCode Zen's `kimi-k3`.

Closes #168174 (misleading OpenCode Zen Kimi K3 thinking controls).

## User Impact

Kimi K3 on Zen offers **Off / Low / High / Max**; Off explicitly disables reasoning. The provider default becomes High, while explicit saved selections remain supported. Ultra remains the separate harness mode. No configuration migration is needed.

This is scoped to Zen. OpenCode Go was not changed: the available account returned an inactive-subscription response, so its contract was not inferred from Zen.

## Why This Change Was Made

The plugin advertised only Max and stripped the effort field for Off. Zen treats an omitted effort as reasoning-enabled. Its upstream public catalog also still advertises only Max, so correcting the seed alone would be undone by refresh.

The owning plugin now preserves the live-verified `none/low/high/max` contract through catalog refresh. The existing shared request policy handles Off→`none`; the redundant K3-only stream wrapper is removed. Production delta: **−2 lines** (15 added / 17 removed); tests/test support: **+153 net** (194 added / 41 removed); docs: **+8**; no core-provider special case or new setting.

## Evidence

- Eight boundary regression cases failed on baseline `0c91469b2dabc593638e7080b6674fda5f1dee3b`, then passed: offline/refreshed catalogs × four settings, each through both direct and managed completion transports.
- **84 focused tests passed**, including Zen Responses/tool-schema handling, other model profiles, and the unchanged Go plugin.
- **4 authenticated live streaming tests passed** through the registered Zen provider: Off, Low, High, Max. Each emitted the exact expected effort and answered `391`; Off emitted no thinking.
- Baseline live API comparison: omitted effort produced 32 reasoning tokens; explicit `none` produced zero. Low/High/Max were accepted. The upstream public feed still reported Max only on October 9, 2026.
- Required independent Codex autoreview: complete, scoped-clean, no actionable P0 findings.
- Patched `pnpm build`, provider changed gates, and the additional core/tooling fixture changed gates passed. A fresh, isolated dev Gateway exposed Off/Low/High/Max (plus the separate Ultra harness mode), accepted Low from the real picker, and completed a real Kimi conversation (`17 × 19 → 323`). Inspected, sanitized before/after screenshots and an after video are attached.
- Two inherited CI fixtures are repaired alongside this change: agent-config mutation tests now release their deliberately held activation barrier before awaiting the activation-aware RPC; release-wrapper tests use the canonical source loader so foreign-CWD, no-dist execution resolves workspace sources. No production behavior was changed for these fixtures.
