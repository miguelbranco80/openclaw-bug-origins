## Fix PR #183473 description (by steipete, opened 2026-10-25T09:08:03Z)

```text
## What Problem This Solves

Fixes worker deployment from standalone builds: a paired node cannot receive a worker because the standalone sidecar drops the canonical deployment archive, and downloaded scripts are launched through the embedded-entry dispatcher.

## User Impact

Standalone packages retain the existing worker transfer archive and route downloaded worker scripts through the same executable's generic runtime. Embedded supervisor entries keep their compiled dispatch path. No host Node fallback or new compatibility restriction is added.

## Why This Change Was Made

Reuse the canonical worker packager before sidecar pruning, retain its hash-named archive, and let an empty loose-worker directory fall back to that archive. A shared runtime environment selector keeps downloaded targets and embedded relays distinct while preserving bundle verification and authenticated assignment.

## Evidence

- The signed standalone pairs successfully but fails before worker launch because its worker directory is empty and its archive is absent.
- Four regression boundaries fail before the change and pass afterward. All 152 affected sibling tests, targeted typechecks, lint, formatting, and independent review pass. Test wrapper wall time: 52.61 seconds; CI timing pending.
- Canonical archive preparation, pruning, and consumption pass with a synthetic package on Bun.
- Full signed run-only worker E2E remains blocked by a separate SQLite/FFI runtime issue: the exact portable archive reaches SQLite prewarm, where the hardened generic runtime reports `bun:ffi requires the JIT`; the same archive passes on ordinary Bun. This change repairs archive delivery and launch routing, while that backend issue needs its own repair. Portable worker code runs interpreted through the generic runtime; this does not add a JIT entitlement or claim native AOT worker execution.
```
