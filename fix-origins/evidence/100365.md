## Fix PR #160091 description (by chopin-op60, opened 2026-09-28T04:07:54Z)

```text
Related: #160054

## What Problem This Solves

Failed Dashboard update requests are logged at INFO without their reason. The current-base reproduction returns `status=error`; the original report observed `status=skipped`.

## User Impact

Failed requests now log a warning with the public reason and a safe error summary. Successful, pending-handoff, and intentional no-op logs remain unchanged.

## Why This Change Was Made

Use the existing outcome classifier at the Gateway logging boundary. Error summaries contain only recognized public error identifiers and exit codes, never command output or arbitrary exception text. Unknown reasons remain unavailable rather than exposing private data.

Update behavior: Gateway-side logging only; no effect on the installed updater or rollback. No new report writer, ledger changes, RPC response fields, settings, or permissions.

No overlap with Pash/Sarah changes.

Thanks to @chopin-op60 for the original fix and @BoatAngle for the report.

## Evidence

- Isolated Gateway plus the Dashboard's real `update.run` RPC path: an explicit mismatched upstream target is refused without changing an installation. Base logged INFO `status=error` without a reason; candidate logs WARN `status=error reason=update-target-upstream-mismatch error="Update request refused"`.
- Real externally supervised no-op on both versions: INFO completion message unchanged, apart from the per-connection ID.
- Success, already-current, external-supervisor no-op, and pending-handoff log messages are byte-identical to the baseline logger for identical inputs. Success was checked at the logging boundary, not by updating an installation.
- Failure and no-op RPC `result` bytes are identical. Complete responses are identical after accounting for per-run UUIDs, timestamps, and the deliberately different isolated profile names in the doctor hint; raw complete responses are not literally identical across independent runs.
- Focused regression fails with the baseline handler and passes with the candidate. After integrating the main-branch request-lifetime test repair, all eight tests in `update-unexpected-error.test.ts` pass: 32.58s command wall time including artifact preparation; the added case took 576ms. Hosted CI timing pending.
- A separate logging-boundary smoke confirmed unknown private reasons, command tails, paths, and exception text do not appear in the new warning summary.
```
