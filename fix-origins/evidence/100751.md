## What Problem This Solves

Activity clients could miss recap refreshes after successful session compaction even though the stored recap was fresh. Deferred row publication inherited the compaction or scheduler work scope, which closed before the notification reached subscribers. No later push arrived during the 110-second observation.

## Why This Change Was Made

Keep accepted recap notifications with the existing Gateway subscription owner: retain any admitted root, detach only the producer's async cancellation scope, and join publication before clients and the row projection close. Reject new notifications once the scheduler/connection close prelude begins. Already accepted publication does not request new admission or wait behind suspension. Existing physical-store/generation checks, prepared-row publication, coalescing, and ordering remain in place.

## User Impact

Subscribed Activity clients receive the updating and fresh recap notifications after compaction. This is release-note context for the user-visible fix. No schema, persistence, retention, SDK signature, configuration, or update migration changes are required.
