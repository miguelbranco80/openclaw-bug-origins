## Fix PR #166402 description (by DonnieFi, opened 2026-10-07T02:42:15Z)

```text
Fixes #166318

## What Problem This Solves

Fixes: Android browsers grey out `.stl` models, and any other file type outside a fixed list, in the chat and New Session **File** picker, so those files can't be attached from the Control UI.

## User Impact

User impact: the **File** picker in chat and New Session now lets you pick any file, matching what the composer and Gateway already accept. **Photo** and **Take photo** still only offer images. Size and empty-file checks are unchanged.

## Why This Change Was Made

The general file input had a hard-coded `accept` allowlist. Desktop pickers usually offer "All files", but Android pickers enforce `accept` and disable everything else. UI attachment admission and Gateway `chat.send` (`acceptNonImage: true`) already take any non-empty file within the size limits, so the picker filter was the only thing blocking these files. This removes `accept` from the general input only (no `*/*`) and deletes the now-unused allowlist constant. Chat and New Session render the same input, so one change covers both. Copy is unchanged because the menu labels don't list file types.

## Evidence

- New regression test in `ui/src/pages/chat/components/chat-attachment-inputs.test.ts`: "leaves the general file picker unrestricted while photo and camera stay image-only".
  - Fails on `main` (072a6b36f53f) with the production file restored: `AssertionError: expected true to be false`, 1 failed | 3 passed.
  - Passes on this branch: 4/4. The file takes about 5.8 s wall time and the new test about 4 ms.
- Mutations, each applied to the branch and reverted:
  - M1, the old allowlist restored: fails the new test.
  - M2, `accept="*/*"` on the general input: fails the new test.
  - M3, photo input loses `image/*`: fails only the new test.
  - M4, camera input loses `image/*`: fails 3 tests (the new test and both native-capture cases).
  - Dropping `capture` is already caught by the existing camera tests.
- `chat-view.test.ts`: removed the single assertion that pinned `video/*` in the old list. The rest of that test, which selects an MP4 and checks its preview, is unchanged and passes.
- Related suites pass: `chat-attachment-inputs`, `chat-view`, `chat-view.attachment-paste`, `chat-pane-attachment-handoff`, `new-session/composer-attachments`, `new-session/composer`.

- The `autoreview` skill hasn't been run yet. A separate reviewer checked the change by hand instead: the test fails on main, M1 to M4 are each caught, and the scoped checks pass.
- The Control UI itself has no visual change; only the OS picker's file filter changes.
- Android emulator proof (throwaway API 36 emulator, Chrome 133, not a real phone) at 75175ced7f8: the File picker lists `.stl` as selectable, picking it adds a file chip, and Photo shows images only.
```
