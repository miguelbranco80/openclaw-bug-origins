## What Problem This Solves

Fixes: compaction aborts a healthy summary request that is still streaming output, because the timeout window (`agents.defaults.compaction.timeoutSeconds`, 180 s default) caps each request's total duration instead of its silence. On a large session or a slower model the user sees "⚠️ This conversation is too long, and shortening it took too long." while the model was still writing the summary.

## User Impact

User impact: large sessions compact even when a single summary request runs longer than `timeoutSeconds`, as long as it keeps streaming. A request that goes silent is still aborted one window after its last output, so a hung provider still fails at about the same time as before. No new config keys, messages, or warnings; the timeout error and its user-facing text are unchanged.

New bound: the whole compaction stops after 10 windows (30 minutes at the default) even if output keeps trickling. Built-in compaction had no operation-level ceiling on `main` once #130993 made every request start a fresh window; plugin-owned compaction keeps its one-window bound.

## Why This Change Was Made

**Root cause.** The host compaction watchdog is refreshed only at request boundaries: after setup, when each provider request starts (`onStarted` in `src/agents/embedded-agent-runner/compaction-session-execution.ts:343-348` on `main`), and after success or before a thinking fallback. Nothing refreshes it while a request streams, so a single request is bounded by `timeoutSeconds` from its start no matter how much output it produces.

**Provenance.** #130993 (a93a015a5695) introduced the per-request refresh ("keep staged compaction progress alive") and kept plugin compaction "bounded once at the host boundary". #163636 (02ec714206d) moved the refresh capability onto the operation's composed abort signal (`compactionWatchdogResets`) so delegating plugins get it too. Both left single-request progress open, as noted in the issue thread. Both invariants are kept here. #164246 (c0c6ca35fce, merged after this PR opened) made an automatic compaction whose summary times out commit a deterministic reduction instead of failing; this PR keeps that outcome reachable at the new ceiling (see *Summary cutoff*).

**Fix.**
- *Progress = a streamed model output delta.* The compaction diagnostic stream wrapper already sees every provider event. It now calls a new `onOutputDelta` callback for each non-empty `text_delta`, `thinking_delta` or `toolcall_delta` (`attempt.model-diagnostic-lifecycle.ts`). Compaction wires it to the same refresh as `onStarted`, which resets both the native and delegated watchdogs. These are parsed provider events, not raw bytes: SSE keepalives, `response.in_progress`-style frames, structural `*_start`/`*_end` events, empty deltas and loop ticks never count (the point from the issue's idleDeadline/totalDeadline comment). Reasoning deltas count because the model is producing output; a provider that hangs produces none.
- *Ceiling.* `runAbortableTimeout` takes an optional `maxTotalMs`: each reset arms `min(timeoutMs, deadline - now)` (never below 0), and resets at or after the deadline leave the due timer alone. The host watchdog (`compactContextEngineWithSafetyTimeout`) fixes its ceiling at `10 × timeoutMs` from the operation start, so there is no new config key. It is derived from the existing knob: raising `timeoutSeconds` raises both. At the default that is 30 minutes: 5.5× the 327 s this 963k-token session's compaction took in run 2 below, and 3.4× the slowest earlier measurement of a similar session (527 s, #163636).
- *Summary cutoff.* The host registers `{ reset, deadlineAt }` for its signal (`compactionWatchdogs`, replacing the reset-only `compactionWatchdogResets`), and `delegateCompactionToRuntime` forwards both. The native summary watchdog ends one window before the host ceiling, so a summary still streaming at the ceiling times out on its own watchdog: an automatic compaction commits #164246's deterministic reduction inside the reserved window, and manual `/compact` keeps failing with "Compaction timed out". Without this, the host deadline fired first (it starts before the summary), aborted the caller signal, and the automatic fallback was skipped (found by the post-rebase review). Direct compaction without a host keeps its own 10-window ceiling.
- *Plugin work stays bounded once.* Only the runtime delegate's model requests refresh the host window. Plugin code before or after delegating, and engines that never delegate, still get one window. The #163636 test "keeps plugin-owned work after the delegate under one host window" and the #130993 test "threads timeout cancellation into the plugin compactor" are unchanged and pass.
- *Same model everywhere.* Manual `/compact`, `sessions.compact` and preflight/overflow/timeout recovery all enter through `compactContextEngineWithSafetyTimeout`. When they reach built-in compaction, they share the runtime delegate, the native watchdog and the same wrapped stream. #133260 (Stop honored) and #159105 (run timeout stops recovery) are untouched: caller cancellation still aborts the composed signal immediately.

## Compatibility

`agents.defaults.compaction.timeoutSeconds` changes meaning. On `main` it is the duration of each built-in compaction model request, restarted when the next serial request begins. With this PR it is how long a request may go **without progress**, where progress means a request start or a non-empty streamed text, reasoning or tool-call delta. Keepalives and empty deltas don't count. It also sets a new **operation ceiling of 10 × timeoutSeconds** (30 minutes at the default 180 s) on built-in compaction, which `main` didn't have.

- Who notices: a built-in compaction that keeps making progress for more than 10 windows now stops: the summary request ends one window before the ceiling, an automatic compaction then commits #164246's deterministic reduction, and manual `/compact` fails with the existing "Compaction timed out". The measured runs are well inside that: 327 s (1.8 windows) for the 963k-token session in run 2 above, and 527 s (2.9 windows) for the slowest similar run measured in #163636.
