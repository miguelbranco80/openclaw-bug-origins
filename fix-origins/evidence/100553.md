## Fix PR #185523 description (by jalehman, opened 2026-10-27T05:44:53Z)

```text
## What Problem This Solves

Fixes: on phones, the Knowledge Browse tab looks broken while page types load. The "Everything" chip stretches into a tall green oval next to a stacked list of placeholder bars.

## User Impact

On narrow screens, the type row now stays one chip high while it loads. It shows a few empty chip-shaped placeholders next to "Everything", and real type chips replace them when the vocabulary arrives. The desktop sidebar is unchanged.

## Why This Change Was Made

At widths up to 650px, the type facets become a horizontal chip row. The "Loading types…" placeholder was still a stacked four-row list inside that row, so the row grew to the list's height and the "Everything" chip stretched to match. This adds CSS inside the existing mobile media query: the placeholder wrappers become `display: contents`, each placeholder block becomes a chip-sized pill, and the "Loading types…" status text is visually hidden but still announced by screen readers.

## Evidence

The screenshots come from a static page that copies the facet loading markup from `renderBrowse` and loads the Knowledge stylesheet, captured in headless Chromium. The "before" capture matches the layout reported on a real phone.
```
