## What Problem This Solves

Re-dispatching a Workboard card after changing `workspace.branch` could silently start its worker in the retained checkout at the original base.

## User Impact

Workboard dispatch now reports both the retained and requested base refs before starting a worker. The existing checkout and local work are preserved, including when the checkout is clean. Restore the original base ref to continue the card, or create a new card for a different base. Reusing the same ref or omitting it keeps the existing checkout without refreshing it when a branch advances.

## Why This Change Was Made

The existing owner-reuse entry point checks repository identity but ignores the requested base. It now applies the new base-ref refusal **only to retained Workboard-owned records**. Keeping this check in the owner implementation preserves its existing repository validation, lifecycle, and authority checks before a retained checkout is returned.

Manual, default-manual, and session callers of the shared worktree service retain their previous reuse behavior, including requests with equivalent ref names or a later commit. Gateway session preparation retains its separate, existing selection validation. Named snapshot restoration is unchanged. No public API, configuration, or stored-data format is added. The Workboard tool description and managed-worktree guide document the card's reuse lifecycle.

+export async function withWorktreeSource<T>(
+  params: CreateManagedWorktreeParams & WorktreeAllocationGuard,
+  run: (current: CreateManagedWorktreeParams & WorktreeAllocationGuard) => T | Promise<T>,
+): Promise<T> {
+  const { withSource, ...operation } = params;
+  if (!withSource) {
+    return await run(operation);
+  }
+  params.commitGuard?.();
+  return await withSource((source) => {
+    const commitGuard = () => {
+      params.commitGuard?.();
+      source.assertCurrent();
+    };
+    commitGuard();
+    const signal =
+      params.signal && source.signal
+        ? AbortSignal.any([params.signal, source.signal])
+        : (source.signal ?? params.signal);
+    const rollbackGuard = () => {
+      params.rollbackGuard();
+      source.assertCheckoutCurrent?.();
+    };
+    return run({ ...operation, signal, commitGuard, rollbackGuard });
+  });
