## Fix PR #152236 description (by jalehman, opened 2026-09-18T23:21:46Z)

```text
## What Problem This Solves

Agent plugin loading could reject a valid structured SecretRef because it validated the prepared credential string against the authored configuration schema. Plugins now validate the authored source captured with their runtime generation while continuing to receive prepared runtime values.

## Why This Change Was Made

The agent loader now uses the existing source-projection owner in direct, planned, and scoped loading. Planner activation changes are projected onto that captured source; unchanged plans retain the captured source by identity. A later configuration rotation cannot substitute a different source generation. No new settings, credential resolution, or persisted-state migration are introduced.

## Evidence

- Exact head `de08035c754c78779e8e5c86be716fc21b95c778`: 37 focused tests passed in `src/agents/runtime-plugins.config-capture.test.ts` and `src/agents/runtime-plugins.test.ts`, covering the real planner's 200-load identity case and all four combinations of changed/unchanged policy plans and original/rotated snapshots.
- Independently replaced only the production module with its pre-fix version: all four new SecretRef regression cases failed at schema validation. Restored the exact reviewed source and all four passed.
- Fresh managed independent review found no actionable P0–P2 findings. Formatting/diff checks pass, and the required exact-head `openclaw/ci-gate` passed: https://github.com/openclaw/openclaw/actions/runs/35406879541.
- The original implementation also reported production/test typechecks, scoped lint, and a full build before its final identity repair; the final repair was checked by focused proof and hosted CI. No live deployment or Gateway restart is claimed.

Thanks to @jalehman for the implementation and regression coverage.
```

```text
giving up to full discovery: explicit base -> request-scope registry ->
metadata snapshot pluginIds -> active runtime plugin ids -> unrestricted.

harness, memory, and context-engine owners on top, so any selected provider
outside the startup set keeps joining the immutable run generation. Hosts
with no active registry (pure library use) keep full discovery.

Live re-verification on the same rig: cold burst answered in 8.03s with the
designed 503 partial fan-out response, probe max latency 4.56s (was a 31.5s
outage), longest event-loop block 5.5s (was 42.6s), and only startup-registry
plugins load.
```
