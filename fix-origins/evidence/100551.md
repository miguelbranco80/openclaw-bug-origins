## What Problem This Solves

Fixes July npm upgrades failing in candidate Doctor before it can record deferred plugin migrations.

## User Impact

Updates from `2026.7.1-2` and `2026.7.1-1` can prepare their older shared database before plugin bookkeeping. Existing data-risk refusals and durable pending-plugin inputs remain protected. This removes the first upgrade blocker; the full survivor matrix still exposes separate post-core completion and retained-session receipt defects owned by the campaign's M2 lane.

## Why This Change Was Made

Candidate Doctor previously attempted a writable pending-plugin record before its shared-schema repair stage, so the July database failed on repairable `audit-events-v2`. Explicit repair preflight now reuses the existing conditional schema step and refusal receipts before those writes. No schema version changes. Plugin-index persistence now owns its existing post-write identity checks, preserving their order and error behavior.

The existing schema transaction remains the recovery boundary. This does not promise a whole-update rollback after a later Doctor failure; package rollback can refuse an incompatible migrated schema.

Maintainer landing scope: accept this prerequisite repair with the disclosed transaction and recovery boundary. Complete July-upgrade recovery remains a separate campaign gate; package rollback alone is not claimed to reverse database migrations.

Related: #149705 documents the separate M2 product repairs and fixes the harness's false-success summaries and discarded migration diagnostics. M10 does not duplicate those product repairs.
