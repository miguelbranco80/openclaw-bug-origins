## What Problem This Solves

During managed updates, Doctor emits phase messages while the updater captures its output until the child exits. JSON updates disable coarse progress too, leaving long maintenance work silent.

Related: https://github.com/openclaw/openclaw/issues/154636 and https://github.com/openclaw/openclaw/pull/167055.

## User Impact

Operators see bounded core Doctor phases on stderr before activation and pre/post-plugin Doctor children finish, including with `--json`. Messages respect informational log filtering and JSON console style. Stdout remains reserved for the final JSON result.

Phase messages are advisory, not success receipts. Deferred ledger writes, schema ownership, cancellation, cleanup, and terminal diagnostics retain their existing behavior. Pre/post-plugin terminal diagnostic replay can repeat a phase already shown live.

## Why This Change Was Made

The existing Doctor stderr decoder now recognizes a producer-owned vocabulary of fixed core phases and sends only those bounded messages to the existing CLI diagnostic output. Plugin labels, unknown text, private suffixes, controls, and overlong lines are not forwarded live. Synchronous display exceptions cannot cancel the child through its output observer; the CLI's existing asynchronous broken-output policy is unchanged.

Both activation and fresh pre/post-plugin Doctor use this callback. Candidate validation keeps its existing output contract. The related contributor PR addresses finalization integrity heartbeats and broader repair behavior; this repair covers the shared core-phase visibility gap without replacing that work.
