## Fix PR #197052 description (by obviyus, opened 2026-11-11T05:47:11Z)

```text
## What Problem This Solves

The Share extension's activation rule lets iOS offer OpenClaw for up to 10 images or a video. The extension only sends the first 3 images (`maxImageAttachments = 3`) and cannot send videos yet. Any omitted item puts the sheet in a blocked state, where Send stays disabled ("Only 3 of 4 images can be sent. Remove omitted items and share again."). So for 4+ photos or any video, the share sheet offered OpenClaw but the user could only cancel.

## Change

The activation rule now matches what the extension can send: at most 3 images, and no movie key. I changed `project.yml` and regenerated the Info.plist with `pnpm ios:gen`.

## Evidence

iPhone 17 simulator (iOS 27), synthetic photos and a video added with `simctl addmedia`, shared from Photos:

| Selection | `main` | This PR |
|---|---|---|
| 4 images | OpenClaw offered; Send disabled with the omission message | OpenClaw not offered |
| 1 video | OpenClaw offered; Send disabled | OpenClaw not offered |
| 2 images | OpenClaw offered; Send enabled once text is typed | Same |

The simulator kept the old share-extension registration after an in-place install, so the PR results above are from a fresh install after a simulator reboot.

Found by an audit of the iOS app.
```
