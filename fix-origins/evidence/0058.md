## Fix PR #201766 description (by jalehman, opened 2026-11-19T10:17:42Z)

```text
## What Problem This Solves

Sometimes an agent runs a tool and then ends its turn without a final answer. A typical case is a reply of `NO_REPLY` to a `sessions_send` request that needs a result. OpenClaw then runs a short tool-free step to get the answer. That step crashed with `RangeError: Invalid time value` before it made any model call when the session used a context engine that adds messages without a timestamp. Lossless Claw adds summary, focus-brief and recall messages that way. The requester got no answer and the turn was logged as incomplete (incident run `bd2d3478-18a1-4ee0-b7db-43c2d83dd497`, 2026-11-19).

## User Impact

User impact: sessions that use a timestamp-less context engine such as Lossless Claw get a real final answer again after a tool-only turn, instead of an "incomplete turn" error. Ordinary turns send the same model requests as before.

## Why This Change Was Made

The tool-free step first trims the turn's messages to fit the model-context limit. To do that it builds temporary bookkeeping entries, and it gave each one a timestamp converted from its message's timestamp. A message without a timestamp made that conversion throw. Every entry now gets the same fixed timestamp. Nothing reads these timestamps: the trimming logic does not look at them, and the entries are never saved or sent to the model. Sizing and model input come from the messages themselves, so request bytes are unchanged.

Rejected alternative: filling in missing timestamps where the context engine's output enters OpenClaw. OpenClaw adds a time stamp to user-message text from the message timestamp, so this would change summary text the model sees. A current time would break the prompt cache, and a fixed time would show the model a 1970 date. A separate Lossless Claw change will add timestamps on the plugin side. This PR is the guard on the OpenClaw side.

Accepted risk: if a later change makes the trimming logic read entry timestamps, this path would give it the 1970 value. The new test checks the trimmed result, not just that nothing throws, so such a change would fail it. No other `new Date(x).toISOString()` call in `src/agents/embedded-agent-runner` or `src/agents/harness` converts a timestamp taken from a message. The others use the current clock or validated dates.

## Evidence

**Regression test** (`attempt-history-prepare.test.ts`, two cases). The tool-free step gets a summary-style user message with no timestamp, one with a `NaN` timestamp, and an exec tool call and result. With the default limit, all four messages reach the agent unchanged. With a tight limit, the large tool result is replaced by the usual omission notice while the timestamp-less messages stay. Both cases fail on `origin/main` with `RangeError: Invalid time value` and pass with the fix. Neighboring suites pass: `settled-turn-finalization`, `finalization-scope` and `attempt-prompt-phase` (79 tests). `pnpm check:changed` passes, including typecheck, lint and format.

**Real behavior on the Mac Studio.** Each commit ran in a Crabbox `local-container` lease launched on the Studio (`node:24.22.1-trixie`, image `sha256:f1e03497…`, 8 CPU / 24 GB) from a clone at the pushed commit. Each run used:

I used a small test engine instead of Lossless Claw 40833c3 because it isolates the one trigger, missing timestamps, and needs no Lossless Claw database setup. The scenario matches the incident. A requester session asks the model to call `sessions_send` into a WebChat session. There the model runs one `exec`, then replies `NO_REPLY`, which the request does not allow.
```

```text
fix(agents): use the context engine's selected view for isolated final answers

Isolated final-answer finalization rebuilt the request from the raw session history instead of the view the context engine had selected, so the finalizer request restored history the engine had excluded and could grow very large. Finalization now uses a private, frozen snapshot of the engine-selected view.

Evidence: built Gateway turns where the context engine excluded history and finalization ran isolated. On main the finalizer request was about 52 KB and contained the excluded raw history (three runs); with this change it was about 2.5 KB with the engine-selected summary and the current write receipt, and no excluded history (three runs, including on the head merged with current main). Finalizers offered no tools and added no context-engine lifecycle calls, and normal finalization works on both refs. Details: https://github.com/openclaw/openclaw/pull/186288#issuecomment-6456933305.
```
