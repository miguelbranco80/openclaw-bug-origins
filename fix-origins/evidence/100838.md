## Fix PR #184044 description (by steipete, opened 2026-10-26T01:24:47Z)

```text
## What Problem This Solves

On Linux, every supervised non-PTY exec failed when the Gateway ran with instrumentation startup hooks in `NODE_OPTIONS`. Typical examples are `NODE_OPTIONS=--import=<otel/sentry/dd-trace bootstrap>`, or an empty `--import` module. The error was `service child cleanup identity lost: native owner closed without kernel descendant extinction`. A live subagent stress run hit this 584 times across four Gateways. Agents saw it as random `exec` failures.

## User Impact

Supervised commands work when the Gateway uses instrumentation startup hooks, while the commands themselves retain the caller's instrumentation. No configuration migration or user action is required.

## Why This Change Was Made

### Root cause

The native process helpers (service-child relay and anchor owner) inherited the Gateway's `NODE_OPTIONS`. `linux-child-subreaper.ts` correctly refuses child-subreaper ownership for processes started with source-loader hooks, which is documented in `docs/gateway/background-process.md`. So an inherited instrumentation `--import` made the helper fail that guard, and the owner closed without proving descendant extinction. The restriction is aimed at source installs with an independent loader. It was never meant to apply to built helpers that happened to inherit a caller's hook.

### Fix

Both helper launch paths, `spawn-broker/relay-integration.ts` and `supervisor/service-child-relay.ts`, pass `NODE_OPTIONS` through a shared `stripNodeStartupHooks`. It drops `--import`, `--require`/`-r`, `--loader` and `--experimental-loader`, and keeps unrelated flags such as `--max-old-space-size`. The relay host now passes the executed command's environment explicitly, so the command itself keeps the caller's instrumentation. A genuine source loader that is needed to run an unbuilt helper is still rejected for Linux child ownership. Docs updated.

## Evidence

- Built owners, 100 concurrent supervised spawns: base **100/100 without instrumentation, 0/100 with `NODE_OPTIONS=--import=<empty module>`**. Fixed: 100/100 in both.
- Regressions in `supervisor.anchored-shell.real.test.ts` and `service-child-relay.native-owner.test.ts` fail on base (`native owner closed without kernel descendant extinction`, inherited `--import` observed) and pass with the fix.
- Nine supervisor/relay/subreaper suites green twice (216 passed, Windows-only case skipped).
- Live Gateway A/B: the same 6-fleet subagent burst with the Gateway started without the `--import` hook showed zero new extinction failures.
- Format, lint, `pnpm build qaRuntime` pass.
```
