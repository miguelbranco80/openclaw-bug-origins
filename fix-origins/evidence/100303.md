## Fix PR #153020 description (by steipete, opened 2026-09-19T16:08:01Z)

```text
## What Problem This Solves

Gateway `update.run` and `/update` can successfully hand an update to a managed helper, then reject that helper at activation as running inside the Gateway process tree. Reported on macOS by Discord user svenmy76.

Refs #144447. This fixes the managed-helper ancestry guard defect for updates driven by the fixed runtime. The issue's separate candidate-startup timeout and original Git/dev installation remain unverified, so this does not claim to resolve the entire issue.

## User Impact

Managed update helpers use their recorded live authority through the shared maintenance checks and the native LaunchAgent stop. Ordinary nested commands retain the shipped refusal, and losing the handoff lease before native stop prevents `bootout`.

**2026.9.4 macOS upgrade note:** the published driver runs the faulty guard before swapping packages. This fix helps updates **from** the fixed version onward; a 2026.9.4 → next-release update through `update.run` on macOS still needs the owner to run `openclaw update` once from an independent Terminal outside the Gateway process tree, using the same installation and state/configuration. The update docs now explain this limitation and recovery.

## Why This Change Was Made

The shared resolver previously exempted authenticated helpers only on Linux during activation. Removing that platform condition was necessary but incomplete: ClawSweeper correctly found a second, unconditional ancestry refusal in `stopLaunchAgent` after `service.stop()` was called.

[ClawSweeper's native-stop finding](https://github.com/openclaw/openclaw/pull/153020#issuecomment-5743400885) is addressed by carrying the original update root/run identity to the native owner. After the awaited ancestry probe, `stopLaunchAgent` revalidates that identity through the same existing `isCurrentManagedServiceUpdateHandoffProcess` predicate. The identity is not a grant; matching run metadata, the current handoff lease, executor PID, and live process identity remain required. No new CLI/config/environment options, schema, or dependency changes.

The systemd and Scheduled Tasks stop owners have no equivalent independent ancestry guard, so neither was changed. Scheduled Tasks process-tree cleanup is unchanged; native Windows survival is not claimed.

## Evidence

- **Real native-stop regression:** two authorized-helper cases failed pre-fix with the exact `Refusing to stop LaunchAgent ... from inside the same launchd service` error. The fixed tests call the real `stopLaunchAgent`, both directly and through update activation, with ancestry injected through the existing detector seam. Missing authority, an ordinary nested caller, and lease revocation during native inspection still refuse before `bootout`. The five cases use real SQLite handoff records and mock only external observations/commands, not `service.stop`.
- **Focused tests:** 272 passed: 186 launchd lifecycle tests and 86 maintenance tests, including the new native boundary. The earlier shared-resolver regressions remain covered.
- **Native Linux survival/readiness:** [fresh Testbox run](https://github.com/openclaw/openclaw/actions/runs/35458478723), lease `tbx_01m2xbpn9gaz3j73c1707192j1`, command exit 0. On Linux x86_64 / Node 24.19.0, helper PID 7827 (start identity 66171) survived the original Gateway PID 7603 disappearing during activation. The same helper remained alive when successor PID 10179 returned `/readyz` ready during verification. At both observations, updater PID 7835 matched its recorded driver start identity 66227. The ledger finished `succeeded`; final serving version `2026.9.99-first-hop.0` and build identity matched the target, with `booted`, `serviceRunning`, `versionMatch`, `readyz`, and `settled` true and no plugin errors. The version is a metadata-only first-hop fixture of the candidate runtime, installed through the repository loopback npm registry. All four changed production hashes and source tree `39dc80f3e1774599c0e1d31817a53b2725b85def` were verified. Gateway cleanup was inactive/PID 0; the lease is completed.
- **Checks:** P1 cumulative autoreview scoped-clean. Full `node scripts/check-changed.mjs`: exit 0, including production/test types, changed-file lint, line caps, and dead-export/import-cycle checks. `git diff --check` passed.
- **macOS live-proof blocker:** published 2026.9.4 `gateway install` rejects the worktree-isolated HOME/state/configuration and requires the OS account home plus canonical state/config paths for its profile. The task forbids using the host's canonical state, LaunchAgent, or existing Gateway. Live launchd proof and the published-driver independent-Terminal recovery cell therefore await a dedicated macOS account. This PR supplies real-stop fixture proof and native Linux proof; it does not substitute those for live macOS or Windows evidence.
```
