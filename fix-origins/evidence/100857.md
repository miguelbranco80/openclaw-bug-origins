## What Problem This Solves

Fixes temporary paths escaping their chosen directory when a plugin supplies a UUID override containing path separators. Downloaded artifact names also avoid reserved Windows device basenames.

## User Impact

The temp-path SDK rejects unsafe UUID overrides. Relative `tmpDir` spelling, trimmed or blank UUIDs, compound extensions, original download metadata, and owned cleanup behavior are preserved. For example, a registry artifact named `NUL.tgz` is staged locally as `NUL_.tgz` while its original metadata stays intact.

Use the released fs-safe 0.18.0 filename helpers as the shared owner, removing 17 production lines. OpenClaw retains its existing temp-root selection and private workspace lifecycle.

* fix(infra): reject dot segments in sanitized temp file names

sanitizeTempFileName keeps "." in its allowed character class and only
falls back to "download.bin" on an empty result, so "." and ".." pass
straight through. fs-safe's assertWorkspaceFileName rejects both, and
createTempDownloadTarget evaluates the target path eagerly right after
mkdtemp, so the caller gets "Invalid temp workspace file name" and never
receives the cleanup handle for the directory that was just created.

Reachable from clawhub-artifacts.ts: the X-ClawHub-Npm-Tarball-Name
response header goes through normalizeOptionalString, which only trims,
and lands in stageClawHubArchive as fileName. sanitizeTempFileName is
also public plugin SDK surface.

Fixed at the sanitizer, which is the only producer of that name; every
string it can now return satisfies assertWorkspaceFileName.

* fix(infra): consolidate temporary download cleanup

Keep dot-segment filenames inside the safe temporary-file contract and remove
the duplicate target builder whose cleanup methods were immediately replaced.
Exercise four dot-segment names and verify real writes and directory cleanup
for every filename case.
