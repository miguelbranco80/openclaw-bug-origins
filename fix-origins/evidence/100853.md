## Fix message body

```text
fix(policy): print JSON errors on stdout for policy check, compare and watch failures

`openclaw policy check`, `policy compare` and `policy watch` printed nothing on stdout when the command itself failed, even with --json or with output piped to another program, which broke scripts that read the documented machine-readable error. Each failure now prints one standard cli_error JSON document on stdout; piped output matches --json, and stderr and terminal output are unchanged.

Evidence: built CLI. On main the three failures printed 0 bytes on stdout (twice); with this change they print one cli_error document each (123, 95 and 89 bytes) (twice), with the same result when piped. Real terminal runs and all stderr output are unchanged.

Thanks @Leon-SK668.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>

## Fix PR #181758 description (by Leon-SK668, opened 2026-10-23T16:29:09Z)

```text
## What Problem This Solves

Command-owned failures in `policy check`, `policy compare`, and `policy watch` return exit 2 and a stderr diagnostic but leave stdout empty, even when JSON was explicitly requested or stdout is piped. Scripts cannot consume the ordinary machine-readable failure envelope.

## What Changed

The existing shared failure handler now receives the command's output options and uses the existing runtime JSON writer for explicit JSON or non-terminal stdout. It preserves stderr and exit 2. Human terminal failures remain text diagnostics, and a watch failure is one compact NDJSON record rather than a multiline fragment.

Contributor commits and credit are preserved. No policy evaluation, enforcement, configuration, dependency, persisted-format or SDK change.

## Evidence

Built Linux CLI, Node 24.22.1, fresh isolated state authored through shipped config commands. Main `a8aee07e387023fc4fb11335fdcd0d26292ee09a` ran twice; candidate `e1b761e2ffeec60e6cddc2c9a23ec02172f344c0` ran the same scenarios. Each arm captured stdout and stderr separately for all three commands in four modes: piped `--json`, piped without `--json`, real PTY human output, and real PTY with `--json`. No process.stdout.isTTY mock was used. The existing OPENCLAW_HIDE_BANNER setting consistently excludes the unrelated startup banner; NO_COLOR is set.

| `policy watch --interval-ms invalid --once` | 0 bytes | 0 bytes | 95 bytes | 2 |
