## Fix PR #160904 description (by steipete, opened 2026-09-29T02:36:47Z)

```text
## What Problem This Solves

Cold cloud-worker enrollment over a slow Gateway uplink (a home connection, or a Cloudflare quick tunnel as `gateway.publicOrigin`) could not finish. Live, with #160655 and #160687 in place, a Crabbox Hetzner cold dispatch over a ~160 KB/s tunnel resumed its interrupted download correctly (Range, no 404), but was killed at +1,105 s:

```
Crabbox node enrollment setup did not exit normally (timeout): ... download-body Cloud worker bootstrap download body failed (ECONNRESET); retrying download attempt 2/3 ... download-http-response ... download-body
```

The node bootstrap artifact (~45 MB) and the worker bundle (~28 MB) download concurrently. Crabbox capped the whole enrollment command at a fixed `CRABBOX_NODE_ENROLLMENT_TIMEOUT_MS = 15 min`, which also covers Node/npm install and setup. Core already sizes these same transfers from their byte counts (125 KB/s floor, `workerBootstrapOperationTimeoutMs`), so the plugin's fixed deadline contradicted core's own transfer policy. Each HTTP attempt also had a hard 10-minute cap, so three attempts could not move 250 MB at the floor rate.

## User Impact

Slow-uplink Gateways can enroll cold cloud workers. Stalled download connections are detected within two minutes and resumed from the last byte, and slow-but-progressing transfers are never cut by a per-attempt limit.

## Why This Change Was Made

- **One owner for transfer timing.** The size-derived policy moves out of the SSH-heavy `bootstrap.ts` into `bootstrap-timeouts.ts`, and all consumers are migrated. Node enrollment grants now carry a core-owned `bootstrapTimeoutMs`, sized from the combined bytes of the artifacts that download concurrently through one uplink. That window also sizes both transfer tokens.
- **Crabbox consumes the fact rather than a constant.** The enrollment and runtime-preparation command deadlines use the grant's window, with the existing 15 minutes kept as a floor when no fact is supplied. Provisioning resolves its outer timeout before grants exist, so core passes its policy maximum (`MAX_NODE_BOOTSTRAP_TIMEOUT_MS`: the largest operation window plus the node connection wait) to `resolveProvisionTimeoutMs` and `provision`, and the outer budget can always contain the derived command deadline.
- **Stall detection instead of per-attempt caps.** The download script drops the per-attempt `AbortSignal.timeout`. A two-minute socket inactivity timeout raises a transient `ETIMEDOUT`, so the existing retry and Range resume continue from the partial file. Attempt count, authority checks, busy-503 handling, integrity verification and cleanup are unchanged.
- **SDK:** additive, optional timing facts on existing contracts (`WorkerNodeBootstrapAccess.bootstrapTimeoutMs`, provision option `nodeBootstrapTimeoutMs`, and an optional second argument to `resolveProvisionTimeoutMs`), documented in `docs/plugins/sdk-overview/capabilities.md`. They add no authority, subpath, protocol or schema.

Not changed: the node pairing credential keeps its 10-minute lifetime. Enrollment closure does not currently revoke it (redemption checks durable environment eligibility, not the live enrollment binding), so extending it would widen that gap. That is tracked separately. Until then, a cold enrollment whose downloads take longer than 10 minutes can still fail at pairing; the docs say so.

## Evidence

- Negative controls fail on `main`: grant timing facts are missing, a 900,000 ms vs 5,700,000 ms command deadline, an insufficient outer budget, and progressing transfers cut by the old attempt caps (3 of 42 download cases fail).
- New fake-time regressions: 48/46-minute progressing transfers complete on one attempt each; header and body stalls abort as transient and resume with Range; grant windows are sized from combined bytes; the pre-grant outer budget contains the derived deadline. The download suite runs in 3.9 s wall (42 tests), and the grant-window case takes 13.0 s, including its database fixture.
- Suites: crabbox provider/read-budget/node-enrollment(-replay/-windows)/bootstrap-download give 273 + 42 passed; worker-environments node-enrollment, provider-provisioning-node, bootstrap, artifact-transfer-http, worker-bootstrap-artifact-transfer, node-worker-bundle-transfer-service/installer and provider-bootstrap give 156 + 77 passed. After rebasing onto current `main`: 119 + 42 passed.
- Types: core production types, all 27 core-test graphs, and extension production/test graphs pass. The line-cap and max-lines ratchets are OK, the `OPENCLAW_*` count is 476/476, and oxfmt/oxlint and `git diff --check` are clean. Codex autoreview P2 is scoped-clean in branch mode for both commits.
- The live rerun of the slow-tunnel cold Hetzner cell will be added after merge.
```

```diff
+// The base timeout remains the floor; the cap keeps transfer bounded and fail-closed.
+export function bundleTransferTimeoutMs(tarballBytes: number, floorMs: number): number {
+  if (!Number.isSafeInteger(tarballBytes) || tarballBytes < 0) {
+    throw new Error("Worker bundle artifact has an invalid tarball size");
+  }
+  return Math.min(
+    BUNDLE_TRANSFER_TIMEOUT_MAX_MS,
+    Math.max(
+      floorMs,
+      Math.ceil(tarballBytes / BUNDLE_TRANSFER_MIN_THROUGHPUT_BYTES_PER_SECOND) * 1000,
+    ),
+  );
+}
```
