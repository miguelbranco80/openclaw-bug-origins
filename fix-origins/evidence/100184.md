## Fix PR #145573 description (by steipete, opened 2026-09-12T03:36:32Z)

```text
Follow-up to #145527.

## What Problem This Solves

Fixes an issue where owners using default tool profiles could not ask the existing update tool to update OpenClaw. The added English-phrase shortcut worked around that gap with a separate pre-model confirmation path and duplicated guidance.

## Why This Change Was Made

Natural-language updates now use the existing `gateway` tool. The minimal, coding, and messaging profiles expose only `update.run`, with the current installation fixed by trusted runtime context. Configuration-read actions and their URL/token/path arguments are omitted and rejected at execution unless the effective profiles grant them. Full/unset profiles retain their existing actions; each limited main/provider profile can explicitly grant configuration reads through its existing `alsoAllow` policy.

One decision in the existing effective-policy owner supplies the action restriction to agent assembly, Gateway tool resolution, and skill dispatch. Gateway-scoped calls carry the admitted sender ID into actual update authorization. The shared update handler enforces current external-chat ownership and `commands.restart`, including managed installations and changes during awaited acknowledgement; operator UI/API updates retain their admission rules. Normal tool-name allow/deny rules, sandbox and runtime caps, subagent restrictions, and current owner authorization still apply. Tool Search receives the same assembled schema. The English matcher, early reply branch, special button prompt, and obsolete tests are removed.

## User Impact

Owners can ask to update using normal tool calling with default profiles. `/update` remains the model-independent fallback, and the web UI retains its existing update controls. All three use the same Gateway `update.run` backend. Explicit owner enrollment from the earlier PR is preserved.

No new tool name, configuration option, persistence format, migration, or update executor is introduced. The installed update driver, install ownership, recovery, and current-owner checks remain the existing owners' responsibility.

## Evidence

- Red-before/green-after regressions cover missing default-profile availability, attempted hidden config actions, and blank `alsoAllow` entries accidentally matching all tools.
- Real agent assembly covers all limited profiles, full/unset profiles, explicit grants, provider intersections, separate policy/execution identity, and deny/owner/subagent/runtime restrictions. Gateway and skill-dispatch tests verify their actual action schemas.
- Focused suites pass for Gateway actions, `/update`, tool profiles, tool resolution, skill dispatch, prompts/cache boundaries, and Tool Search.
- Independent Codex review through P2 is clean on the combined patch. The 124 Gateway/execution tests cover supervised enable/disable, permission revocation during acknowledgement, and a real assembled tool reaching current-owner authorization. Security-audit tests reflect the new tool inventory without lowering severity or suppressing findings.
- The initial candidate passed local build, changed-file checks, all seven prompt snapshots, and the relocated 27-case suite. Changed-file checks pass for the final execution corrections. [Exact-head CI run 34672548868](https://github.com/openclaw/openclaw/actions/runs/34672548868) passes on `00da800deaaa0d91f17c237d83f07be2f71a76c9`, including the rebuilt artifact and corrected audit tests.
- Validation uses isolated local tests and mocked Gateway dispatch. No production Gateway update or live channel message is performed.
```
