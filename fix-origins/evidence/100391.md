## Fix PR #157881 description (by vincentkoc, opened 2026-09-25T04:01:30Z)

```text
## What Problem This Solves

Choosing **Disabled** in Twitch setup could still admit mentioned chat when the account had no user ID allowlist.

## User Impact

Disabled now blocks chat for the selected account, including base/default and named-account configurations. Open and Disabled discard previous user IDs; switching back to Allowlist does not restore them and uses moderator/VIP roles unless a nonempty ID list is configured.

Legacy configurations with empty or absent roles and no `allowFrom` remain open. There is no automatic migration because those values do not record the intended policy. Reselect **Disabled** or set `allowFrom: []` to block chat.

## Why This Change Was Made

Use the existing channel configuration patch helper to explicitly empty or remove the allowlist, and report the policy using the runtime's precedence. Preserve account fields and enable behavior without changing the runtime, DM policy, credential writer, schema, or SDK.

Config-aware status checks also accept the intentional empty allowlist instead of recommending its removal. Other configuration and runtime diagnostics remain intact.
```
