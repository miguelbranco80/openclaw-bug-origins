## Fix message body

```text
Large fleets repeatedly serialized configuration and rebuilt discovery facts during model preparation, starving Gateway health and status requests. Publish batched discovery as shared immutable facts, reuse config and catalog fingerprints, and yield at guarded lifecycle boundaries while preserving agent-specific credentials, cancellation, and serialized publication.

Keep captured observation config distinct from public config stamps so native catalog selection survives stamp advancement. Preserve invalid-config reset and diagnostic behavior by keeping invalid values out of object-keyed hashing, and include the new shared modules in the native wrapper inventory.

Related: #149538, #148529. Thanks to @609NFT for the 632-agent reports, profiles, and startup breakdowns that identified this bottleneck. Scoped performance measurements, regression proof, and remaining upgrade and fleet-recovery limits are recorded in #150223.
```

Related: #149538, #148529

Thanks to @609NFT for the 632-agent reports and detailed profiles in #149538 and #148529.

## What Problem This Solves

Large fleets keep the Gateway's main thread inside `buildSnapshotBatch` on the microtask queue during model preparation and post-ready rebuilds, delaying health and status requests. The [lead's separate 632-agent × 54-model reproduction](https://github.com/openclaw/openclaw/issues/149538#issuecomment-5701606329) recorded a 730-second gap around bind/model preparation, a 23.4-second post-ready gap, and 22 timed-out health probes out of 300 after readiness. This PR isolates and measures the batch owner with a 200-agent reproduction.

## Why This Change Was Made

The reported profiles put 71–96% under `buildSnapshotBatch`: repeated activation/config serialization and fleet roster walks, followed by 49.5 seconds in recursive plugin argument restoration. Already-resolved promises kept that work on the microtask queue.

Preparation now captures one immutable runtime/authored config pair per fleet generation and carries its provenance forward. Activation fingerprints, roster indexes, and argument-graph analysis reuse those prepared facts. Unchanged plugin selections preserve capture identity. Nine real event-loop yields separate bounded workspace/agent/source/registry/snapshot work, with current-owner checks after yielding and auth replay tied to the credential-capture boundary.

Valid config hashing retains the lazy memo keyed by the actual deeply frozen object. Invalid diagnostic snapshots short-circuit in the reset/bootstrap comparison and `config.get` before hashing; reset still compares selected target, existence, validity, and raw revision. Valid fresh-install defaults retain their resolved revision even when the physical config file is absent. Capture records carry source/origin provenance, without eager fingerprints.

Catalog finalization now prepares the shared `{agents, plugins}` fingerprint in the existing build-local config map. Per-agent native source fingerprints combine it with that agent's selections and configured refs. Worker-generation code separately memoizes runtime/source config digests by immutable object identity, using its existing SHA-256/stable-stringify encoding; mutable worker reconstructions rehash. That separate encoding preserves distinctions such as undefined versus null. Full worker payloads, credential data, serialized SecretRef provenance, and generation checks remain intact.

Merged #149314 is already in the benchmark baseline. It covers immutable **metadata-inventory fingerprint caching** and other startup work; it does not change activation result/config hashing or plugin argument restoration. This PR complements PR A #149600 (cron skill-review reconciliation), PR B #149716 (chat metadata), and PR C #150004 (eager Codex catalog-home roster construction). PR C merged after the measured baseline; these measured revisions do not include it.

The pre-rebase 200-agent measurement restored model preparation near the prior fast candidate: **22.499 s** finally, versus **23.331 s** in V2, **46.531 s** in the record-based sample, and **68.872 s** before this PR. The Gateway answers health during preparation (8/23 within the phase), with phase RSS reduced to **943.9 MiB**. The final 11.950-second blocked overlap and phase-health result remain worse than the best V2 sample; this PR does not claim all startup stalls are resolved.

Explicit dev reset recovers invalid config without a WeakMap exception. No new operator setting, CLI option, dependency, schema migration, or action is required. Normal update/recovery ownership is preserved; no published-driver × candidate upgrade result is claimed.

**The 30-second full `openclaw status --json` gate is NOT fully met: 1/3 final attempts succeeded.** The separate online CLI status follow-up landed in #150269; these historical measurements do not include that change.
