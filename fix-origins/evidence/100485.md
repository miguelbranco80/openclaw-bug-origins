## What Problem This Solves

Fixes: the Gateway's model-catalog worker can fail over and over (for example `ERR_WORKER_OUT_OF_MEMORY` at its 512 MB heap limit) with nothing in the log and no failure shown in `status`, even though every failure republishes all borrowing agent catalogs.

## User Impact

Operators now get one warning per failed catalog worker, with the worker's reason (out of memory, exit code, or timeout) and the number of agent catalogs to republish on a new worker. `status` gains `workerPools.modelCatalog.workerFailures`, and the startup `memory.ready` trace gains `modelCatalogWorkerFailures`, both counting failures since the Gateway started. A worker that exits while idle is counted and logged when it exits; the next catalog request replaces it.

No config, stored data, migration, or recovery behavior changes. Shutdown, plugin retirement and pool rotation are not counted or logged.

## Why This Change Was Made

Background renewals drop their rejection, and a failed pool is replaced by one whose `getSnapshot()` starts again at `workersCreated: 1`. So a worker that died every few minutes looked like a healthy one. On 2026.9.6 about 90 silent worker deaths in a day went unnoticed until filesystem monitoring caught the capture folders turning over (details in #161738).

With crash restart off, a catalog pool closes itself when its worker fails, exits or times out, even if no request is waiting. Catalog pools are now a small internal `WorkerTaskPool` subclass that reports its first close to the pool owner (`getGatewayCatalogPool`); no plugin SDK option changes. When the pool closed itself, the owner counts the failure and logs the reason right then; recovery still republishes the affected catalogs with the next request. A pool its owner closes (shutdown, plugin retirement, rotation) is marked `closing` first, so those closes are not reported. The counter lives on the existing global pool singleton, so it survives pool replacement. Pool construction and the worker-data type moved to `prepared-model-catalog-worker.pool.ts` with the subclass, which keeps `prepared-model-catalog-worker.ts` under its 700-line cap (677 counted lines, was 700). `docs/logging.md` and `docs/plugins/architecture.md` describe the new field and warning.
