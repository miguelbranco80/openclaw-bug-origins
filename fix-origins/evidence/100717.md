## Fix PR #180763 description (by roboclaw-bot, opened 2026-10-22T16:08:36Z)

```text
## What Problem This Solves

When a gallery video's original URL is still loading, Shift+Tab from Close can focus the unavailable **Open in new tab** link. The link has no destination and is already marked `tabindex="-1"`, but the lightbox's manual focus wrapping still treats it as the last control. Keyboard users therefore land on an action they cannot use.

## User Impact

Keyboard wrapping skips the pending link and reaches Next. Once the original link becomes available, it joins the wrap sequence again. Native video controls, intentionally focusable gallery navigation buttons, and focus return to the opener retain their existing behavior. There is no configuration or migration change.

## Why This Change Was Made

The lightbox already owns a registry of its controls and excludes disconnected elements and natively disabled buttons when choosing wrap boundaries. This change adds the existing tab-index contract to that filter. It keeps the fix at the focus owner without changing the modal implementation, original-link loading, media lifecycle, or navigation policy.

The regression exercises the rendered video gallery with actual browser keyboard input. It checks pending and ready wrap boundaries, native video seeking without gallery movement, traversal through native controls, and focus restoration on close.

## Evidence

The regression fails on the base production owner in both Chromium and WebKit: focus lands on the unavailable original anchor rather than Next. The candidate passes all 50 selected unit tests and all 22 browser cases across Chromium and WebKit.

Changed-file formatting and lint, UI i18n verification, and the selected production and test type graphs passed. The unit batch took 10.07 seconds and the two-engine browser run took 11.34 seconds in the test runner. The [full hosted CI run](https://github.com/openclaw/openclaw/actions/runs/39955097167) also passed, including all three UI shards, nine UI E2E rows, and both real-Gateway E2E shards.

The browser test retains Chromium’s native seeking assertion. A standalone-video comparison confirmed that WebKit does not seek when ArrowRight targets the video host; both engines verify that the lightbox leaves that key uncancelled and does not move the gallery.
```
