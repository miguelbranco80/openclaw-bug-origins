## Fix PR #184384 description (by steipete, opened 2026-10-26T08:11:22Z)

```text
## What Problem This Solves

Fixes updates failing on a selected profile because inspection accidentally reads a different profile's newer database schema.

## User Impact

Update inspection and snapshots use the selected installation's state directory even when an older updater omits that field from its restricted environment payload. No configuration or database schema changes are required. An old updater that runs its own inspection worker still needs an updated runtime; the candidate-side repair applies when it delegates to the new worker.

## Why This Change Was Made

The worker already receives an authoritative `stateDir`, but plugin metadata discovery also resolves machine state through the supplied environment. Bind that existing environment field once at worker ingress, preserving the restricted payload and leaving physical-path-only requests unchanged. This covers both inspection and snapshot senders without adding separate sender workarounds.

The regression also exposed an incomplete existing WAL test fixture: its machine-state table omitted `updated_at_ms`. Complete that fixture rather than weakening its assertions. Production delta: +5 lines, including the ownership comment.

## Evidence

A real subprocess regression with a healthy selected database and an incompatible default-profile database failed before the fix with the wrong-profile schema error and passes afterward. The snapshot row also supplies a contradictory environment root and verifies that explicit `stateDir` wins; unrelated database bytes remain unchanged.

- Schema inspection suite: 11 passed.
- Legacy/local schema and snapshot plugin siblings: 6 passed.
- Core and infrastructure test typechecks, targeted lint, formatting, and diff checks passed.
- Independent canonical autoreview: no actionable findings through P2.

Proof uses synthetic databases through the actual inspection/snapshot subprocesses; it does not claim a full published-package upgrade run.
```
