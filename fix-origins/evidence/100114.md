## Fix PR #159161 description (by steipete, opened 2026-09-26T20:22:19Z)

```text
## What Problem This Solves

A queued plugin Doctor repair could mutate channel ingress after its repair window closed, and ingress writes with unknown native outcomes could be replayed by retry or settlement handling.

## User Impact

Expired Doctor repair writes now roll back. An unknown append, completion, release, or dead-letter outcome remains terminal instead of being retried or acknowledged as a known success. Ordinary transient retries and claim ownership behavior remain intact. There is no schema, configuration, retention, durability, or update protocol change, and no migration is required.

## Why This Change Was Made

Doctor now passes its existing live repair authority to the queue's worker admission boundary. The existing worker error classifier guards both write retry loops and the settlement owner. Retaining the rejected settlement prevents the outer dispatch error handler or a later callback from starting another write, while clearing the in-flight marker lets joined shutdown report the failure without spinning. Read-only Doctor inspection retains its noncreating behavior.

Updates continue to permit writes within the active repair section; a queued write whose lease expires refuses at transaction or commit admission under the same owner.

## Evidence

Two additional real drain controls proved that release and dead-letter writes ran twice through outer settlement reentry even after the inner retry guard was fixed. They now run once, retain claim ownership, and joined disposal reports the original unknown failure.

+/** Bounded tombstone write retries — wedged ownership beats silent double-dispatch. */
+const INGRESS_TOMBSTONE_RETRY_MAX_ATTEMPTS = 8;
+
+/**
+ * Claim-token fenced writes can throw OR return false when the lease was
+ * reclaimed. For complete, false is ownership loss (do not settle success).
+ * For release/fail, false means the row is already gone from this owner —
+ * treat as done so abandon races do not wedge.
+ */
+export function createIngressWriter<TPayload, TMetadata, TCompletedMetadata>(
+  options: { abortSignal?: AbortSignal },
+  {
+    queue,
+    now,
+    formatError,
+    log,
+    isStopped,
+  }: {
+    queue: ChannelIngressQueue<TPayload, TMetadata, TCompletedMetadata>;
+    now: () => number;
+    formatError: (err: unknown) => string;
+    log: (message: string) => void;
+    isStopped: () => boolean;
+  },
+) {
+  const commitClaimWriteWithRetry = async (params: {
+    claim: ChannelIngressQueueClaim<TPayload, TMetadata>;
+    label: "tombstone" | "dead-letter" | "release";
+    write: () => Promise<boolean>;
+    falseMeansReclaimed: boolean;
+  }): Promise<void> => {
+    let attempt = 0;
+    for (;;) {

+      // (failed-retryable requeue, post-dispatch tombstone) must not be blocked.
+      // Stop only cuts retry backoffs (webhook stop / dispose mid-retry).
+      if (attempt > 0 && isStopped()) {
+        throw new Error("ingress drain stopped during claim write");
+      }
+      try {
+        const committed = await params.write();
+        if (!committed) {
+          if (params.falseMeansReclaimed) {
+            throw new IngressAdoptionLostError("reclaimed");
+          }
+          return;

+        return;
+      } catch (err) {
