## Fix message body

```text
fix(ui): keep Usage filter search open when Enter confirms IME input

In the Usage provider and creator filter pickers, the search box checked only `event.isComposing`, so an Enter that confirms Chinese or Japanese IME input and arrives as keyCode 229 or right after `compositionend` (the Safari/WebKit order) selected the first match, sent a usage request and, for the single-choice creator picker, closed the picker. The search box now uses the shared `ui/src/lib/ime.ts` guard, as the chat and Ask OpenClaw composers do. No new text; Control UI gzip growth is 0 B.

Evidence: production Control UI served by an isolated loopback Gateway with synthetic usage records written through the normal owners; Chromium with trusted CDP composition and key events, twice per side. Base: each confirming Enter (keyCode 229, and Enter right after compositionend) selected the first match with one acknowledged sessions.usage request, and the creator picker closed. This change: the search text and focus stay, nothing is selected and no request is sent; a plain Enter afterwards selects exactly once. Active composition, plain Enter, Escape and closing the picker behave the same on both. Unit: both regressions fail on base, 28 pass here; typecheck, full build and packed smoke pass. Screenshots and request counts: https://github.com/openclaw/openclaw/pull/199872#issuecomment-6905516379.

Thanks @zhangguiping-xydt.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```

## What Problem This Solves

Fixes Usage filters changing or search focus leaving the input when Enter confirms IME composition. Confirming a provider search can select the first match and silently narrow the displayed usage; a creator picker can select a person and close.

## User Impact

Users can confirm composed text while retaining the search, focus and current filters. A following ordinary Enter still selects the first search result. No configuration or migration is required.

## Why This Change Was Made

Use the existing input-local IME helper in the shared value picker, including keyCode 229 and Enter immediately after compositionend. For composition-confirming Enter, stop propagation to the parent menu without preventing the browser default. Clear composition tracking on key-up and blur, as the neighboring query search already does. The shared change covers both multi-value filters and the single-choice creator picker.

Related: #195087, an external-contributor Usage query IME fix merged by @obviyus on November 8. That fix covered the query field; this fixes the separate value-search handler.
