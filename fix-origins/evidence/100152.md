## Fix PR #151316 description (by steipete, opened 2026-09-18T02:17:04Z)

```text
Related: #151247, #151229.

## What Problem This Solves

Provider catalog renewals can trigger synchronized metadata refetches and make session lists wait for catalog-dependent projection work even when a usable catalog is already resident.

Production at `1e6ca9fe6e39`, including #151247, showed about 24 connections refetching `models.authStatus`, `models.list`, and `chat.metadata` together: 29 bursts in 35 minutes on September 18, 2026, 01:00–01:35 UTC, at intervals of 3–300 seconds.

New operator-provided evidence from production at `f5c0aa37ef96` (including #151229/#151247, without this PR), September 18, 2026, 04:15–04:35 UTC: **219** `[sessions] slow session list operation=sessions.list` warnings in 20 minutes. Every warning spent its time in `modelCatalog`: minimum **948 ms**, p50 **1,945 ms**, p90 **3,132 ms**, maximum **5,572 ms**; the other phases were single-digit milliseconds. The main-thread profile attributed **22%** to session-row projection refresh/materialization across approximately **4,300 resident rows**, despite transcript coalescing already being deployed.

## User Impact

Identical renewals preserve cached metadata and leave resident rows clean. Lists and descriptions use the existing catalog while an asynchronous replacement loads, then refresh their rows when the replacement arrives. Startup without a catalog still waits. Real catalog changes still invalidate all rows; refresh failures and recovery remain visible to clients. No configuration or migration is required.

## Why This Change Was Made

The first commit retains the previous full-catalog snapshot when inventory, authority/completeness, provider outcomes, and relevant auth facts are unchanged. It removes discovery-start notifications and excludes transient pending-provider status from chat metadata generations.

The second commit makes `modelFactsChanged` follow that retained snapshot's identity. Projection and chat subscribers skip unchanged publications; reporter-owned `refreshStatusChanged` keeps failure recovery observable without creating another status cache. `catalog-failed` semantics remain intact.

The projection owns one catalog snapshot and one refresh promise. Its catalog lifecycle is factored into a sibling module to meet the existing line cap. Warm readers materialize with the current snapshot without joining the catalog promise. Catalog adoption and row invalidation happen in the same synchronous continuation; revision, disposal, and epoch fences remain intact. A genuinely changed catalog still causes full row rematerialization. The logging docs explain the behavior and the meaning of the `modelCatalog` phase.

Source verification qualifies the proposed production explanation: `f5c0aa37ef96` already marks discovery-start notifications as unchanged, and its completion helper compares a subset of model facts. Its production batch reader selects published catalogs synchronously after the module import; it does not explicitly await the renewal promise. The logged `modelCatalog` phase covers the entire projection readiness drain, including row materialization. The production timings establish that cost center, while deferred-catalog tests independently reproduce the old projection's read-blocking behavior.
```

```diff
+  modelCatalog?: Inputs["modelCatalog"];

+}) {

+  let catalogDirty = params.getModelCatalog ? Symbol("catalog") : undefined;
+  let pending: Promise<void> | undefined;
+  let disposed = false;
+  const unsubscribe = registerPreparedModelRuntimePublicationListener((event) => {
+    // An incomplete catalog read still needs the next publication to recover its rows.
+    if (
+      (event.phase === "catalog-published" || event.phase === "catalog-failed") &&
+      event.modelFactsChanged === false &&
+      modelCatalog !== undefined &&
+      (!(modelCatalog instanceof Map) || ![...modelCatalog.values()].includes(undefined))
+    ) {
+      return;
+    }
+    params.onInvalidated();
+  });
+  return {
+    get current() {
+      return modelCatalog;
+    },
+    get needsInitialRead() {
+      return Boolean(catalogDirty) && modelCatalog === undefined;
+    },
+    invalidate() {
+      if (params.getModelCatalog) {
+        catalogDirty = Symbol("catalog");
+      }
+    },
+    refresh() {
+      if (disposed || !catalogDirty) {
+        return Promise.resolve();
+      }
+      if (pending) {
+        return pending;
+      }
+      const revision = catalogDirty;
+      const work = (async () => {
+        try {
+          const next = await params.getModelCatalog?.();
+          pending = undefined;
+          if (disposed || catalogDirty !== revision) {
+            if (!disposed) {
+              params.onRefreshed(false);
+            }
+            return;
+          }
+          // Catalog visibility and row invalidation share one synchronous publication.
+          modelCatalog = next;
+          catalogDirty = undefined;
+          params.onRefreshed(true);
+        } catch (error) {
+          pending = undefined;
+          // Keep the revision dirty so the next publication or read can retry.
+          throw error;
+        }
+      })();
+      pending = work;
+      void work.catch(() => {});
+      return work;
+    },

+      unsubscribe();
+    },
+  };
```
