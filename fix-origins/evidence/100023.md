## Problem

An unexpected exit of the shared Memory file watcher worker permanently stopped file observation until the Gateway restarted. The failed transport also erased watcher health, so this could appear healthy while missing edits.

## Change

Keep supervision in the existing shared watcher transport. An unexpected exit logs a warning and publishes unavailable/degraded health, then retries after 0.5, 2, and 5 seconds. Each replacement receives every live subscription and uses the existing watcher baseline reconciliation to catch edits missed during downtime and rebuild shared-root selection/exclusion unions. Four failures within a rolling minute stop automatic restarts and retain explicit unavailable health with restart guidance. Searches keep the existing background refresh fallback; recovered ready health clears that fallback.

Final subscription shutdown cancels recovery and joins native cleanup, worker exit, and accepted indexing. Closed subscriptions are not replayed. The old permanently failed transport path is removed. This adds no SQL, schema, SDK, or main-thread filesystem scan.

Accepted edge case: changes during backoff are eventually indexed by the replacement's baseline rescan. Persistent worker failure requires explicit lifecycle restart after the bounded retry budget. No security-boundary checks were removed or weakened.
