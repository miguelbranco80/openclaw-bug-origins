## Fix message body

```text
fix(browser): keep the download quiet window on the monotonic clock

The browser plugin measured the download quiet window with Date.now, so a forward wall-clock step while a download was in progress ended the window early and a following download was missed. The window now uses performance.now(), as the other extension budgets do since #186484.

Evidence: built Gateway with real Chromium over the browser HTTP bridge. A process-local +10 s Date.now step was placed between the window's timestamp write and its elapsed-time read, and logs confirm the order. Main missed the second download (twice); with this change both files were captured (twice). No-step controls captured both on each ref, and the system clock was not touched. Details: https://github.com/openclaw/openclaw/pull/186850#issuecomment-6486955204.

Thanks @SunnyShu0925.

Co-authored-by: SunnyShu <0668000539@local>
Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```
