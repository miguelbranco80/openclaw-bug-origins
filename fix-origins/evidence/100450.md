## What Problem This Solves

An update can fill the home/state volume even when `TMPDIR` points to a roomy volume, then fail while recording recovery state.

## User Impact

Update-time runtime copies, plugin source captures, and SQLite inspection snapshots honor `TMPDIR` (SQLite retains an explicit `XDG_CACHE_HOME` override). Optional original-state captures stay beside state for durable recovery discovery, but check their known payload budget before writing and warn when there is insufficient space. npm's independent cache and the locations that must remain with the installation/state are documented.

## Why This Change Was Made

The retained-runtime owner preferred a sibling even with explicit `TMPDIR`; plugin capture and SQLite snapshot owners defaulted to state/home storage; the original-capture owner only budgeted its databases, not declared file resources. Reuse those owners: respect explicit scratch placement and check the existing file inventory plus metadata headroom, including a second check after database acquisition. Required rollback and live-authority checks remain intact. Disk-full worker recovery already landed in #176902; this change does not replace it.

Production: +46/-8 (net +38); tests: +166/-116 (net +50); docs: +18. Necessary growth is the file-payload space check and four distinct placement/capacity regressions. An existing retention test moves to its owner suite to keep the database backup suite under its line budget. No new configuration, schema, dependencies, or parallel storage owner.
