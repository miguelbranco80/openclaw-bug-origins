## What Problem This Solves

Fixes #185716.

An async question card puts `role="status"` / `aria-live="polite"` on `.chat-question-summary`, and that container also holds the card's Retry and Answer buttons. Live regions should not contain focusable controls, so those controls become part of every announcement and focusing one interrupts it.

## User Impact

Async question cards now announce their text without repeating the action buttons. Both buttons render and work exactly as before.

## Why This Change Was Made

`role="status"` and `aria-live="polite"` sat on the `.chat-question-summary` wrapper, which also contains the Retry and Answer `<button>` elements. Focusable controls inside a live region are re-announced on every update, and focusing one interrupts the reader mid-sentence.

Wrap only the card text in the live region, leaving both buttons outside it. The visible markup is unchanged; the wrapper keeps `.chat-question-summary` and the assertions that read its `textContent` still hold.

## Evidence

Latest exact-head verification on `050c1fe71c7923461977f2153829b86c26bed5f4`: https://github.com/openclaw/openclaw/pull/185565#issuecomment-6438236929. Two fresh built-Gateway Chromium runs confirm Retry restored inline beside the label, separate polite delivery/error text regions, controls outside live regions, 3px question gaps, and keyboard Retry preserving the payload. Includes an inspected fresh screenshot. Earlier layout-placement question is resolved by this head.

Independent built-Gateway Chromium comparison (main twice, original head twice, current head twice), CDP accessibility-tree ancestry, measured row gaps, keyboard controls, and inspected before/after screenshots: https://github.com/openclaw/openclaw/pull/185565#issuecomment-6437299418. +export function parseGeneratedAsyncAnswer(
+  question: AsyncQuestions,
+  message: string,
+): Map<string, QuestionDraft> | null {
+  if (!message.startsWith("> ")) {
+    return null;
+  }
+  let offset = 0;
+  const answers = new Map<string, QuestionDraft>();
+  for (const [index, current] of question.questions.entries()) {
+    const prefix = `${quoteQuestion(current.title)}\n\n`;
+    if (!message.startsWith(prefix, offset)) {
+      return null;
+    }
+    offset += prefix.length;
+    const next = question.questions[index + 1];
+    const separator = next ? `\n\n${quoteQuestion(next.title)}\n\n` : undefined;
+    const answerEnd = separator ? message.indexOf(separator, offset) : message.length;
+    // Free text can contain quoted headings. Do not guess a section boundary.
+    if (
+      answerEnd < offset ||
+      (separator && message.includes(separator, answerEnd + separator.length))
+    ) {
+      return null;
+    }
+    const answer = message.slice(offset, answerEnd);
+    if (!answer.trim()) {
+      return null;
+    }
+    const values = answer.split(", ");
+    const selected = values.every((value) => current.options?.includes(value))
+      ? new Set(values)
+      : new Set<string>();
+    answers.set(String(index), { selected, freeText: selected.size > 0 ? "" : answer });
+    offset = answerEnd + (separator ? 2 : 0);
+  }
+  return offset === message.length ? answers : null;
+}
+
+export function quoteQuestion(title: string): string {
+  const encoder = new TextEncoder();
+  let quote = "";
+  let bytes = 0;
+  for (const character of title) {
+    bytes += encoder.encode(character).length;
+    if (bytes > 512) {
+      break;
+    }
+    quote += character;
+  }
+  return `> ${quote.replace(/[\r\n]/g, " ")}`;
+}
