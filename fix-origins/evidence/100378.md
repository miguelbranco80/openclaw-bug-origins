## What Problem This Solves

Fixes an issue where users restarting a supervised Gateway could get an immediate startup failure while another OpenClaw process still held lifecycle ownership. Repeated failed starts could exhaust systemd's start limit and leave the Gateway down.

Reported by @waynegault (#146142).

## Why This Change Was Made

Gateway acquisition now waits for lifecycle-coordinator contention under a five-minute monotonic deadline, with backoff from 250 ms to 2 seconds. It logs the initial wait and successful acquisition, and includes the elapsed wait in a terminal ownership error. The deadline loop is shared with the startup-migration lease fix from #120959; migration owner classification and polling cadence stay intact.

Supervised startup recognizes lifecycle contention and passes the same absolute deadline into acquisition, including time spent loading startup code. A healthy port cannot turn coordinator contention into successful startup. Generated systemd units allow ten starts per 300 seconds while retaining the five-second restart delay; both documented unit examples match. Launchd already has throttling without a finite start-limit latch.

The coordinator remains an anonymous SQLite lock. Holder identity is a follow-up pending Peter's persistence design decision. A foreign live owner receives the same bounded wait and still fails if it never releases; the code never steals ownership. Normal restart already releases ownership before handing off in both v2026.9.3 and this branch, so the reporter's exact overlapping process remains unidentified.

## User Impact

A restarted Gateway waits, with a generous bounded budget, for its predecessor to release lifecycle ownership instead of failing immediately and tripping systemd's start limit.

The candidate Gateway owns this behavior, so an older installed updater or existing unit can benefit without learning a new handoff marker. The revised systemd limits apply when the service definition is rewritten. No configuration options, dependencies, schemas, or retained-state semantics change.

+export async function acquireWithWait<T>(params: {
+  acquire: () => T;
+  shouldRetry: (error: unknown) => boolean;
+  deadlineMs: number;

+  maxPollIntervalMs?: number;

+}): Promise<T> {
+  const now = params.now ?? performance.now.bind(performance);
+  let delayMs = params.pollIntervalMs;
+  for (;;) {
+    try {
+      return params.acquire();
+    } catch (error) {
+      if (!params.shouldRetry(error)) {
+        throw error;
+      }
+      const remainingMs = params.deadlineMs - now();
+      if (remainingMs <= 0) {
+        throw error;
+      }
+      await (params.sleep ?? sleep)(Math.min(delayMs, remainingMs));
+      delayMs = Math.min(delayMs * 2, params.maxPollIntervalMs ?? params.pollIntervalMs);
+    }
+  }
