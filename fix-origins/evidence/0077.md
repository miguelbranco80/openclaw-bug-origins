## Fix PR #201637 description (by Patrick-Erichsen, opened 2026-11-19T05:41:04Z)

```text
## What Problem This Solves

When the agent recommends a plugin in chat, the card shows an **Install** button. Selecting it did not install anything: it opened the plugin page, where you had to find and select **Install** a second time, and you lost your place in the conversation.

## User Impact

User impact: selecting **Install** on an official plugin card now installs the plugin right there. The card shows **Installing**, then **Installed** (or **Connect** when the plugin needs an account), and the chat stays open.

Unchanged on purpose:

- Community plugin cards and skill cards still open their details, as the chat docs describe. A community package is installed from its plugin overview.
- A configured install-policy warning still needs an explicit acknowledgment. When an official plugin has one, the card opens the plugin overview, which is where that review is presented.

## Why This Change Was Made

The card's button was wired to navigate to the plugin page with an install hint that the page deliberately ignores, so the click could never start an install. The card now sends the install itself, through the same install owner and config write queue the plugin page uses, so progress, failures and retries look the same in both places and an install started in chat is visible on the plugin page too.

A second click before the first request is admitted does not queue a second install. A retryable failure retries from the card. Anything the card cannot present (a policy review, or a config write refused before a request was sent, for example during an update) opens the plugin page instead of failing silently. Warnings returned with a successful install, which the plugin page lists beside the plugin's row, are announced in a toast because a card has no row to hold them.

## Evidence
```

```diff
+/**
+ * Installs a recommended plugin without leaving the chat. The shared install
+ * owner presents progress and failures on every card and on the plugin page;
+ * warnings from a successful install are announced.
+ *
+ * Resolves true when only the plugin page can continue: it reviews
+ * install-policy findings and explains a refusal that sent no request.
+ */
+export async function installPluginFromChatCard(
+  context: Pick<ApplicationContext, "gateway" | "runtimeConfig">,
+  client: GatewayBrowserClient,
+  request: PluginInstallRequest,
+  catalogId: string,
+): Promise<boolean> {
+  try {
+    const { value, refreshError } = await runPluginConfigMutation(
+      context.runtimeConfig,
+      client,
+      (admitted) =>
+        pluginInstallOperations(context.gateway).run(admitted, request, "install:" + catalogId),
+    );
+    // The plugin page lists these beside its row; a card has no row to hold them.
+    const warnings = [
+      ...(value.warnings ?? []).map((warning) => formatUiExternalText(warning)),
+      ...(refreshError ? [t("pluginsPage.configRefreshFailed", { error: refreshError })] : []),
+    ];
+    if (warnings.length) {
+      showToast({ severity: "warning", message: warnings.join("\n"), durationMs: 12_000 });
+    }
+    return false;
+  } catch (error) {
+    return (
+      readPluginInstallPolicyWarning(error) !== undefined ||
+      error instanceof ConfigMutationRefusedError
+    );
+  }
```

+### ClawHub recommendation cards
+
+Ask about a capability, such as “Can you install WhatsApp?”, to let the agent find
+an official plugin or skill on ClawHub. When the `message` tool is available, it
+can present up to three matching cards in the conversation.
+
+If you use the `coding` tool profile, include `"message"` in `tools.alsoAllow`
+(for example, `tools: { profile: "coding", alsoAllow: ["message"] }`). Existing
+deny rules still apply. See [Tool access configuration](/gateway/config-tools).
+
+Select a card to open its listing inside the Control UI: plugins open in
+**Plugins**, and skills open in **Skills**. A plugin's **Install** button opens
+the existing installation review; a skill's **Install** button opens its details.
+**Dismiss** dismisses the card from the current view.
+
+An installed capability shows a green checkmark and **Installed**. This means the
+plugin package or linked skill is present. A plugin may still need to be enabled,
+configured, or connected to an account before the agent can use it. The card
+checks the current installation status; select **Status unavailable · Retry** if
+that check fails.
+
+The agent requests cards through `message` with a capability query:
+
+```json
+{
+  "action": "send",
+  "clawhub": { "query": "whatsapp", "kind": "plugin" }
+}
+```
+
+`query` is required; `kind` can be `plugin` or `skill`. Omit `kind` to check plugins
+first, then skills if no official plugin matches. Omit `channel` and `target` to
+reply to the current Control UI conversation. ClawHub supplies the official
+designation, and the Gateway checks installation status; the agent cannot assign
+those badges. A search with no official match or an unavailable catalog returns
+an explanation in chat.
