## What Problem This Solves

Config loading treats an inaccessible root as a missing file: the synchronous existence probe hides read failures, and the asynchronous probe converts every rejection into `false`. OpenClaw can therefore silently load fresh-install defaults instead of reporting an unreadable configuration.

## User Impact

An inaccessible configured root is reported as an I/O failure instead of silently loading unrelated fresh-install defaults. A genuinely missing config retains existing defaults. No configuration or migration action is required.

## Why This Change Was Made

Read the root once. Reuse the existing synchronous reader and apply the same ENOENT-only absence policy asynchronously. Genuine absence retains the existing defaults; other failures reach the existing environment rollback, path-bearing error log, and original-error rethrow. Config validation, includes, recovery, materialization, and public config/SDK/protocol shapes are unchanged.

Production delta: +11/-11, zero net lines. The 64-line regression exercises both actual factory APIs through filesystem faults; it adds no production testing seam.

## Best-effort tradeoffs accepted

- A root disappearing before its single read is ordinary absence. An unavailable root now visibly fails instead of falling back to unrelated defaults. No retry or second existence check is added.
