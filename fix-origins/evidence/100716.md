## Fix PR #178192 description (by steipete, opened 2026-10-20T07:01:03Z)

```text
## What Problem This Solves

When a model returns an empty or non-visible stop right after settled tool calls, the embedded runner gives it one "settled tool terminal continuation". That continuation is text-only (tools disabled, reduced transcript) so a model cannot repeat side effects. It also ran when every settled tool in the attempt was read-only. A model that stalled mid-task could then only answer that it cannot read the remaining files.

Live, Groq `openai/gpt-oss-120b` on a six-file read task: after 4-5 successful `read` calls Groq returns a genuinely empty completion (`finish_reason: stop`, no content, no reasoning; wire-captured through a logging proxy). The text-only continuation then produced "I'm unable to read the remaining files without tool access" or a partial answer. In one run it returned raw tool-call markup as the reply. The same model in a direct API loop completes the task, so the empty stop is transient.

## User Impact

Turns that stall after read-only tool work can now continue the task with their tools. Turns that may have caused side effects, or that lack side-effect evidence, keep the existing text-only finalization unchanged.

## Why This Change Was Made

The decision point in `incomplete-turn-recovery.ts` now keeps normal tools and transcript for the one continuation only when current-attempt replay evidence explicitly reports `hadPotentialSideEffects === false`. That is the same classifier the replay-safety paths already use. The instruction says to continue the task and not repeat completed calls. The retry budget (one continuation) and silent-reply handling are unchanged. `terminal-resolution.ts` routes those attempts to the normal continuation instead of isolated finalization; the finalizer itself is untouched.

## Evidence

- Live A/B, `openclaw agent --local`, Groq gpt-oss-120b, six sequential reads, 4 runs each: main 0/4 correct (7/7 failures across the investigation); this branch 2/4 fully correct. The other two reached 5 of 6 words before a second empty stop exhausted the unchanged one-retry budget.
- Regression: Claude Haiku 5.5 and DeepSeek V4 Pro unchanged on the same task.
- Tests: 307 across 21 files, including read-only, side-effecting, and missing-evidence regressions plus prompt-prefix stability.
- Codex autoreview (P1, focus on side-effect classification, loops, NO_REPLY semantics): scoped-clean.
```

## Problem

OpenClaw conflated deliberate silence, missing output, and an undelivered answer. Canned assistant replies masked missing results, required turns overrode explicit `NO_REPLY`, and consumers used different silence heuristics.

## Fix and user impact

- A final is silent only when its trimmed raw text is exactly `NO_REPLY`. A leading `NO_REPLY` followed by a newline and text delivers that text. Punctuation, lowercase, quotes, JSON, reasoning wrappers, and prose remain visible.
- `prepareAgentRunTerminalReply` classifies once and publishes `meta.terminalReply`. Consumers use that fact; stored-row readers use one exact helper.
- External chats honor `NO_REPLY`, including required turns. Subagents, private completions, and WebChat/Control UI require a result by default. Trusted input handling can explicitly mark result consumption optional, avoiding a duplicate answer to a late peer result.
- When a result is owed, an empty final goes through recovery, then fallback, then one system notice: **"No answer was returned. Ask again if you still need one."** The notice is never an assistant row. External recovery permits an answer or `NO_REPLY`; result-required recovery requires an answer.
- A required, undelivered final in message-tool-only mode gets one hidden retry (send it or choose `NO_REPLY`), then the notice. Optional turns keep private finals quiet.
- Optional turns owe no result: an empty final ends quietly without recovery or notice. Native and CLI results retain the reply obligation through fallback; a clean empty result without an explicitly optional policy still remains fallback-eligible.
- A yielded CLI turn returns its paused continuation metadata even when a result is required. Merely spawning a child without yielding still requires a real private result.
- Canned stand-ins are removed. Authored acknowledgments, classified failure guidance, restart/session-recovery notices, tool warnings, uncertain-delivery notices, media no-ack behavior, and retention warnings remain.

This reverses #168571's suppression of punctuated reasoning placeholders. Replies rejected by narrowed permissions report failure rather than completion. Yields without an authored acknowledgment stay quiet.
