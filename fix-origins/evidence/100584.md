## Fix PR #167241 description (by steipete, opened 2026-10-08T13:10:45Z)

```text
Fixes #167077

## What Problem This Solves

Fixes Claude CLI conversations forking into stale branches when channel messages and `chat.send` alternate in the same session.

## User Impact

Every turn continues the latest native conversation, regardless of its inbound route. Account-private standing approvals remain isolated. No configuration, protocol, schema, or migration changes are required.

## Why This Change Was Made

The warm-process registry and queue included the inbound account and auth profile in their owner key, allowing one conversation to retain competing processes. Both now use conversation identity. Account changes participate in the existing process compatibility fingerprint, so the runtime retires and awaits the previous process before resuming. Approval grants are available only to the prepared turn that owns the activated process.

Thanks @cmatrx0 for the report. The separate manual-compaction retirement repair is tracked in #157766; session reset still creates a distinct conversation identity.
