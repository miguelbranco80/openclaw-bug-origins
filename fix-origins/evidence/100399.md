## Fix message body

```text
## What Problem This Solves

Fixes: after a Gateway restart, `models.list` stays without some models until someone runs an explicit refresh. These are hosted-catalog models for providers that have no credentials (for example Kimi, x-ai and some Anthropic models) and native CLI models such as Claude CLI. On two production Gateways a restart left 18 and 14 models missing. They came back only after a manual `models list --all --refresh`.

## User Impact

After a restart, the model list and pickers show the same models an explicit refresh would, with no manual refresh.

## Why This Change Was Made

At startup the Gateway only discovers models for providers that have credentials. It then treats that partial result as the complete catalog. The full discovery that finds hosted rows for providers without credentials runs only on an explicit refresh or when a new hosted catalog arrives. Ordinary reads no longer trigger discovery since #167008, so nothing ran it after a restart.

When an agent has no saved provider inventory, its startup pass now runs the full discovery an explicit refresh would run. That is always the case after a restart. A later configuration or credential reload that keeps its inventory still rediscovers only the providers that changed. Startup discovery still runs in the background after the Gateway publishes its catalog, so readiness does not wait for it.

Known cost: on a cold start the Gateway now calls the discovery endpoints of configured providers that have no credentials, the same calls an explicit refresh makes. Each agent's startup discovery is now a full one, run one at a time through the existing catalog-build limit. Discovery responses are shared, so a second agent did not repeat any network call in the measurement below. Existing discovery timeouts bound each call. An explicit refresh issued while startup discovery is still running now joins it instead of starting a second run.

## Evidence

- Regression test in `prepared-model-runtime.scoped-refresh.test.ts`. At cold start the worker is asked for the full catalog, and a row that only full discovery finds is published. After a credential reload that keeps inventory, discovery is scoped to the changed provider and the row stays. On `main` the test fails because startup discovery is scoped (`["demo"]`) and the row is missing.
- Isolated Gateway (real OpenAI and OpenRouter discovery, hosted catalog bundle already stored, restarted with no refresh), polling `models.list` for 45–90 s after readiness:
  - `main`: 501 rows (openai 33, openrouter 468). No Claude CLI or Kimi rows in any of 7 restarts.
  - This change: 516 rows (adds claude-cli 11 and kimi 4) a few seconds after readiness, in all 7 restarts. Before this change the same 516 appeared only after an explicit `models.list {refresh: true}`.
- Readiness is not delayed. Time from process start to `/readyz` 200, with `main` and this change alternating on the same machine: `main` 14.8 / 14.5 / 10.9 / 12.3 s, this change 12.3 / 10.7 / 12.0 / 16.1 s. Three earlier sequential runs: `main` 12.0 / 11.0 / 19.4 s, this change 9.4 / 19.7 / 15.1 s. Mean over 7 runs: 13.6 s for both.
- Two agents, outbound discovery calls counted per host in all threads during the first 60 s: `main` and this change both made one request each to `openrouter.ai/api/v1/models` and `api.openai.com/v1/models`. Both agents listed the full 516 rows with this change.
- Updated tests that assumed startup did no provider discovery:
  - catalog-publication, remote-publication and the worker-pool deadline test now let startup discovery finish first.
  - The chat-metadata fixture's worker returns the same catalog as its static builder.
  - The native-lifecycle Gateway test now expects the startup request to the provider endpoint without credentials.
- Focused prepared-catalog, chat-metadata and models-list suites pass. Five worker and auth catalog integration tests (`scope`, `metadata`, worker OAuth rotation, `models-auth-login`, `models-auth-refresh`) fail locally on the same unmodified `main` commit, and they also fail with this change.
- Test cost: `pnpm test src/agents/prepared-model-runtime.scoped-refresh.test.ts --maxWorkers=1` took 51 s wall time locally (20 tests; Vitest duration 23 s). The new case takes about 0.2 s.

No overlap with Pash/Sarah changes.

Merge danger: two-way door. No stored state, config or contract changes; a revert restores scoped startup discovery. Blast radius: Gateway startup catalog discovery for every install. If it is wrong, the risk is extra startup discovery calls in the background, not missing models.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```
