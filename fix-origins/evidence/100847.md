```text
* fix(control-ui): old tabs 404 on lazy chunks after every update

Retained Control UI generations let already-open documents from the
previous build load hashed lazy assets after `openclaw update` restarts
the Gateway. A current build manifest lists 53,113,860 bytes per
generation, 18,023,582 of them precompressed .br/.gz sidecars, so the
current generation plus one prior (106.2 MB) no longer fit the 96 MiB
budget and every preparation after an update pruned the previous build.

retained sidecar is already served as identity bytes, so stale tabs keep
working with uncompressed responses while the current build still uses
its sidecars from the bundled root. Current plus previous now needs
70.2 MB. Existing full-format cache directories remain valid generations
in both upgrade and downgrade directions; every verification property is
unchanged. Pruning now warns when the byte budget drops the newest prior
generation, so a future build that outgrows the budget is visible.

* test(control-ui): await async retained lookups and pin identity-only HTTP serving
```

## Fix PR #163099 description (by steipete, opened 2026-10-01T23:39:04Z)

```text
Related: #129922, #131930, #163090

## What Problem This Solves

Fixes: already-open Control UI tabs fail to load routes they had not visited yet after every `openclaw update`, because the retained-asset cache always prunes the previous build.

## User Impact

After an update, an open tab from the previous build can still load its lazy chunks. Those responses are uncompressed (identity bytes) instead of Brotli/gzip; the current build still serves its precompressed sidecars. The retained cache now holds about 70 MB on disk (current plus previous build) instead of about 53 MB (current only). If a future build grows too large for the previous generation to fit, the Gateway logs `Control UI asset retention cannot keep the previous generation` instead of failing silently.

## Why This Change Was Made

The retention owner keeps at most 3 generations within 96 MiB (100,663,296 B), current first. When #129922 set that budget, a generation was 24.6 MB. A fresh `pnpm ui:build` today lists 1,434 assets totaling 53.1 MB, about a third of which is precompressed sidecars:

| Manifest bytes (df8c0ee207c1) | Bytes |
| --- | ---: |
| Identity assets (401 `.js`, 69 `.css`, 24 `.webp`) | 35,090,278 |
| `.br` sidecars (470) | 8,430,582 |
| `.gz` sidecars (470) | 9,593,000 |
| Total per generation | 53,113,860 |
| Current + previous, full | 106,227,720 (over budget) |
| Current + previous, identity only | 70,180,556 (fits) |

Retained generations now store an identity-only manifest, named by its own hash. That is what old documents need: bundled `.br`/`.gz` URLs are never directly addressable (`control-ui.ts` 404s them), and the HTTP path already falls back to identity bytes when a retained sidecar is missing. The sidecar rule comes from the static-response owner (`isControlUiPrecompressedAssetExtension`), so retention follows that owner's sidecar policy.

Options weighed:

- **Chosen: drop sidecars from retained generations.** Each generation shrinks by 34%, the absolute disk bound and generation limit stay unchanged, and no state or config is added.
- **Budget derived from the measured build:** rejected. It removes the disk bound exactly when a build bloats, and the generation count limit already scales with build size.
- **Count only the bytes prior documents need:** counting identity bytes while still storing sidecars would make the budget misreport real disk use. Storing only what is counted is the chosen option.

Tradeoffs: a stale tab downloads lazy chunks uncompressed during the post-update window, about 4 times the Brotli size (33.5 MB of JavaScript in this build is 8.4 MB as Brotli). A third generation (105.3 MB identity) no longer fits today's build; one prior covers the update contract. Identity bytes can grow to 48 MiB (50.3 MB) per build, about +43%, before the previous generation stops fitting. Locale catalogs are 19.1 MB (55%) of identity and grow with UI strings across 20 locales, so the new warning is the early signal.

Compatibility: the manifest format is unchanged. Directories written by older Gateways (full format, sidecars included) still verify as generations and count at their real size. On the first update onto this change, the new 35.09 MB identity-only current plus the old 53.11 MB full prior is 88.2 MB, so the operator's existing previous build survives. After a downgrade, an older Gateway reads identity-only directories as ordinary generations and serves identity bytes. All verification properties are untouched: manifest parse and hash, directory name equals generation, per-asset size and SHA-256, path containment, symlink and hardlink policy, staging and collision handling, prune claims, and cancellation.

Coordination: #163090 (on-miss lookups await the startup inventory) landed first by agreement, making `resolveAsset` async. This branch merges main and converts the new budget test's lookups to `await`. It also adds the identity-only HTTP case to #163090's `control-ui-retained-assets.http.test.ts`: the real owner publishes a prior build that ships `.br`/`.gz` sidecars, and a client accepting `br, gzip` gets 200 identity bytes with no `Content-Encoding`. That case fails on the pre-PR retention code, which answers with Brotli.
```
