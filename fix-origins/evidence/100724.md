## Fix PR #169068 description (by steipete, opened 2026-10-11T10:40:10Z)

```text
## What Problem This Solves

Fixes misleading “Session counts unavailable” labels on saved sidebar shortcuts when switching agents or opening a session outside the loaded sidebar window.

## User Impact

Unloaded session shortcuts now say **Open session**, and unavailable plugin shortcuts say **Plugin**. Opening a missing session reports **Session not found**; a failed lookup asks the user to try again.

## Why This Change Was Made

The shortcut fallback reused the Online view's session-count error. This changes the label at its existing owner and preserves bounded sidebar loading, on-demand session lookup, and suppression of stale errors after newer navigation.

## Evidence

The mounted sidebar regression failed on the original label. The full sidebar suite passes **21/21** (`pnpm test ui/src/components/app-sidebar-rail.test.ts --maxWorkers=1`, **5.226 seconds wall**); existing dashboard navigation and stale-result coverage remain intact. A first green run exposed an invalid synthetic plugin key in the new test; correcting it to the documented `plugin/id` format resolved that fixture failure without changing production behavior.

The full app with an isolated mock Gateway reproduces the before state and verifies the after state through real hover and click actions. Both captures passed (8.967 seconds before, 8.224 seconds after). Inspected screenshots contain synthetic data only.

Keyless i18n baseline/verification, formatting, conflict-marker, assertion-safety, and diff checks passed. Fresh managed review is clean through P2. UI production types (46.162 seconds), owning UI-components test types (43.716 seconds), and targeted lint passed. The three UI shard jobs took 262, 334, and 348 seconds end to end; these are shard costs, not the individual test runtime.
```
