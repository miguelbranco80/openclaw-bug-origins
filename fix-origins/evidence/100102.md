## Fix PR #188612 description (by shakkernerd, opened 2026-10-30T18:37:59Z)

```text
## What Problem This Solves

`chat.history` adds numeric `hasMore` metadata to centered and retained cursor reads when an older source-bound cursor exists. These responses intentionally omit numeric paging metadata; clients continue with their source-bound cursors.

## User Impact

Centered and retained reads keep their valid cursors and omit numeric continuation metadata. Default-tail and explicit-offset reads retain numeric continuation, including real exhaustion and response-budget trimming. The Control UI keeps its existing cursor-based history loading.

## Why This Change Was Made

The response owner now selects numeric metadata from the page's numeric pagination capability. Cursor availability is independent of that capability. The reader's exhausted-prefix result and response-byte trimming still determine whether a numeric page has older rows.

This preserves the landed numeric continuation and hidden-gap repairs in #188488 and #188557. It restores the original centered omission assertion and strengthens the existing retained-reset scenario without adding test lines. Cursor generation, admission, storage and asynchronous ownership are unchanged. The existing client documentation already describes this contract.
```
