## Fix PR #150094 description (by steipete, opened 2026-09-16T13:54:28Z)

```text
Related: #150135

## What Problem This Solves

Feishu account shutdown could finish while accepted synthetic events or deferred message and broadcast replay work still owned pending writes, including handlers whose five-minute per-chat ordering slot had already expired.

## User Impact

Shutdown closes new event admission and waits for accepted handlers and replay writes to settle before releasing account resources. Pending work can therefore extend account cleanup. Menu/card acknowledgments, card-token behavior, VC auto-join defaults, and the five-minute queue limit remain unchanged. No configuration or migration is required.

## Why This Change Was Made

The account lifecycle tracks accepted handlers through deferred settlement, while the existing durable ingress owner continues to drain message admission. Broadcast settlement starts at fanout creation, joins admitted lane commits through failure, and retires late adoption. Transport adoption still precedes logical replay commits.

The persistence backend now runs in SQLite workers, so this change also incorporates the remaining fixture preparation from #150135: route all fourteen current Feishu persistence test roots through the worker lane, join accepted fixture work before database close, and preserve shutdown and close failures. Restart checks close and reopen SQLite before testing replay suppression.

## Evidence

594 tests across 20 files passed: 303 Feishu database-worker tests, 61 ordinary Feishu tests, 193 test-routing checks, and 37 shared ingress-monitor checks. These exercise real SQLite restart persistence, registered message/card/menu/meeting shutdown, deferred broadcast commits, original handlers after queue-slot eviction, and loopback webhook behavior.

Production and test type checks, scoped lint, formatting, line-cap, max-lines, and assertion-safety checks passed. Independent P2 review and the maintainer ownership audit completed with no accepted finding. The changed-check plan was inspected and proportional checks ran; the full local check:changed orchestration was not run.

This establishes isolated SQLite and channel-boundary behavior. It does not claim live Feishu provider validation.
```
