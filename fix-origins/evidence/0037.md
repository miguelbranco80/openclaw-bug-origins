## Fix PR #192024 description (by steipete, opened 2026-11-03T15:33:26Z)

```text
Closes #191957

## What Problem This Solves

Fixes: on btrfs, `openclaw doctor --fix` refuses the NOCOW rewrite for agent stores with "store files are open (pids: <Doctor's own PID>)", and rerunning Doctor hits the same refusal, so those stores can never be repaired.

## User Impact

User impact: one `openclaw doctor --fix` run with the Gateway stopped now rewrites every agent store on btrfs, not only the ones Doctor's checks happened not to read.

## Why This Change Was Made

During its checks, Doctor runs memory status through memory-core's search worker. That worker thread lives in Doctor's process and keeps an idle read-only reader per agent store it touched. Doctor's maintenance cleanup drains only main-thread handles, so `fuser` still saw those descriptors and attributed them to Doctor's PID.

OpenClaw already has a process-wide "close retained agent readers" request that reaches every worker pool; agent deletion uses it. The NOCOW repair now sends that request for the stores it is about to rewrite, right after Doctor drains its own handles. Holder refusal is unchanged: the pre-copy and pre-exchange `fuser` checks still refuse any descriptor that remains, including a reader reopened in between.

Rejected: excluding Doctor's own PID from the holder check. That would let the exchange proceed under a live reader in a worker thread.

Production code +20 lines; test lines net 0.

## Evidence

- **Native reproduction on published 2026.10.10** (Crabbox AWS Linux, state on a loop-mounted btrfs at `~/.openclaw`, 6 agents with copy-on-write stores, Gateway stopped). `openclaw doctor --fix` rewrote the shared state but refused all 6 agent directories with `store files are open (pids: <Doctor PID>)`, matching the report.
- **Holder identified:** a `node:sqlite` open/close tracer preloaded into that Doctor run found exactly 6 unclosed agent-store connections, all on worker thread 19, opened by `retainOpenClawAgentDatabaseReadOnly` in `manager-search.worker`. These are memory-core's cached idle readers.
- **Native red/green on one package built from this branch** (same btrfs baseline restored before each run):
  - With only the new `closeAgentDatabaseReaders` call disabled in the installed dist, all 6 agent directories were skipped with `store files are open (pids: <Doctor PID>)`.
  - Unmodified, all 7 store directories (state plus 6 agents) were rewritten with NOCOW in one `doctor --fix` run. `lsattr` shows `C` on every directory, and the Gateway came back `active` with `/readyz` ready.
  - The rebuilt final head `2cd55940246` repeated the green result: 7 of 7 directories rewritten, 0 skipped.
- **Regression test:** the existing Linux native-`fuser` drain test in `src/commands/doctor-sqlite-nocow.test.ts` now also holds a stand-in retained reader on an agent store. It runs in two variants:
  - The shared close succeeds: every store is rewritten.
  - The shared close throws: the close failure is reported as a warning, the holder check refuses only that store, and the maintenance scope is restored.
  - Both variants fail on base and pass with the fix on a Linux box. The full file passes locally on macOS (Linux-only cases skipped).
  - To keep the test-lines ratchet at net 0, the test's tracked-connection instrumentation was removed. Native `fuser` already refuses any open descriptor on those paths.
- **Review:** `$autoreview` came back scoped-clean on both heads. An independent Codex review found one P2 on the first head: a close failure aborted Doctor outside the scope-restoring `finally`. That is fixed in the second commit, and its re-review found nothing.
- **Gap:** the tests stand in for the worker's cached reader with a reader-closer in the main isolate. The worker broadcast path is proven only by the native run above.
```
