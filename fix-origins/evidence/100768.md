```text
## What Problem This Solves

Fixes: a strict MCP subprocess connection closes when several valid messages arrive together and their combined stdout chunk exceeds the per-message limit.

## User Impact

The strict MCP client used by the CUA adapter and plugin SDK accepts individually bounded messages regardless of how the pipe groups them. Oversized messages still retire the connection; the configured limit includes the terminating newline.

## Why This Change Was Made

The inherited check counted the entire incoming chunk against one frame. The decoder now validates each frame before retaining the chunk, preserving pending bytes if any complete or partial frame is too large. Ordinary chunks that fit still take the existing fast path. The SDK's separate default stdio buffer and its limit are unchanged.
```
