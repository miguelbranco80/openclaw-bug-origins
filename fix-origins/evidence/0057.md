## User Impact

This improves developer and release-operator diagnostics and makes nested-checkout worker builds select their own dependency files. It does not relax release acceptance, change database admission policy, or alter Telegram authorization, retry, or timeout behavior. No configuration or dependency changes.

- Resolve worker dependency entries against the owning checkout instead of treating bare `node_modules` paths as package specifiers.
- Preserve independent RSS endpoints and samples while keeping derived comparisons and release validation strict. Report bounded, payload-free sampling failures.
- Exercise incompatible database replacements before admission in both synchronous and asynchronous fixtures.
