## Fix message body

```text
Doctor's models.json credential migration deduplicated only identical keys, so an older models.json apiKey became an agent-local <provider>:models-json profile. Agent-local profiles override the shared read-through store, so the stale key silently replaced a valid shared credential and inference failed with 401. The migration now keeps the effective shared profile, skips creating the shadow, and warns without changing the catalog source. Existing shadows have no migration provenance, so Doctor preserves them and prints the exact removal command.

Fixes #187680. Thanks @paterskip for the report.
```

## What Problem This Solves

Doctor could turn an old `models.json` API key into an agent-local profile that takes precedence over a working shared profile, silently breaking inference and fallback with authentication errors.

Fixes #187680. Thanks @paterskip for the report.

## User Impact

`doctor --fix` and `update repair` preserve effective shared auth instead of importing a competing catalog key. The warning names the provider and shared profile; the original catalog stays untouched.

Existing `:models-json` shadows, including main-agent overrides after shared-store relocation, are preserved. Doctor shows the exact scoped logout command so the operator can confirm the shared account before removing a local credential. The migration records neither a credential-origin receipt nor credential metadata, so the profile name alone cannot authorize automatic removal.

## Why This Change Was Made

The migration previously deduplicated only identical credential values. A different key received another profile ID, and local profiles enter the merged auth store before shared profiles. The migration now uses the existing read-only auth selection owner to detect effective shared credentials, both when collecting catalog keys and at the store update after any repair prompt. Explicit config credential imports retain their existing behavior.

This stays in the existing migration owner and warning recorder, without adding storage, schema, options, or credential deletion. Production delta: +73/-2 lines (net +71); regression-test delta: +75/-2 (net +73); docs: +12. No baseline or allocation changes.
