## Fix PR #201563 description (by steipete, opened 2026-11-19T01:47:48Z)

```text
## What Problem This Solves

A yielded requester could lose several finished child results when one member of its completion batch had no live Gateway binding. This can happen after restoration, but also during ordinary visible spawning or binding cleanup. The whole batch failed together, and a later requester turn could prevent the failure notice from appearing before the child rows were retired.

## User Impact

Bound children now deliver their results independently of incompatible siblings. Unbound children settle separately, and retired children leave a visible failure that tells the user to inspect their saved results. No configuration or schema changes are required.

## Why This Change Was Made

Visible spawning and watched follow-ups now preserve the caller's captured Gateway binding at registration. The registry partitions frozen batches by Gateway owner and retirement state before dispatch or failure settlement. Native settlement commits the admitted partition while leaving other members pending; the existing sibling wake mechanism advances them.

Failure reporting uses the existing required-completion owner for yielded batches, including when the original requester turn has ended. It verifies that the notice was appended and preserves the existing recovery receipt if publication fails. Failure notices preserve the existing chat-addressed contract across transcript replacement; live writer and completion-delivery lifecycle protections remain intact. Missing or stopped chats receive no notice. This removes the duplicate stable-batch notice path and redundant whole-wave validation; production code is net −12 lines.

Talk final attachments now follow admitted partitions while retaining pending siblings, exact full-cohort revocation, and consume-before-append replay protection. A retired row can resume its settle wake to record a visible failure, while ordinary delivery remains blocked.

Related: #195275. This fixes the separate mixed-binding failure before completion dispatch.

## Evidence

Five regression cases fail on base `0b18f610` and pass with this change: restored unbound membership, live never-bound membership, live binding retirement, visible-spawn registration, and a failed settle after a newer requester yield. The native registry harness asserts actual bound-result delivery and a visible transcript failure for a retired row. Focused persistence, requester-wake and affected tool suites pass (96 tests). All four real-Gateway turnover controls also pass, including model error, reset and Stop. Final `pnpm check:changed`, the session-identity ratchet and isolated Codex autoreview through P2 pass. CI exposed a regression in the consolidated failure-notice path: it must follow the current chat after reset or compaction and preserve the original error detail. The unchanged retry-lifetime suite now passes (17 tests), along with five affected requester-wake regressions rerun after that repair.

Hosted Codex and ClawSweeper identified the Talk attachment contract. The repair adds success-first/failure-first replay controls and extends all three native mixed-binding cases to assert the Talk callback. Those cases fail on the earlier PR head and pass after the repair, including restoration processed first. The complete requester-wake suite passes 41 tests, attachment/dispatch/yield/Talk controls pass 92 tests, and restore/resume controls pass 4 tests. The existing serial-delegation Talk regression from #142830 remains green. Persisted row types, codec and schema are unchanged; the restored case writes, removes the in-memory owner, reloads through the native store, and verifies both delivered siblings and a visible retirement failure.

The 30-minute ordinary completion expiry can defer settle wakes while another delivery owner holds the row. This repair isolates the eventual batch failure; it does not change that timeout or claim to establish the cause of every delayed completion.

Final-head synthetic measurement used a 35.2 GiB agent database, 5,000 sessions, 6,000 retained runs and 62,000 workspace files (1.116 GB), with no production data. Five fresh-process A1/A2/B cycles each used six warmups and 30 measured four-child waves through the real settle owner and native SQLite mutations, with scripted delivery.
```
