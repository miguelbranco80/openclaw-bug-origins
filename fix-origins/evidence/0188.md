## Fix message body

```text
fix(cron): record the real cause when a scheduled session event fails

When a scheduled session-target job failed, the run record and the job's lastError kept only the generic "Session event execution failed", while the real cause appeared only in the Gateway log. The recorded error now carries the operation's existing error, as isolated scheduled jobs already do; a failure with no cause still records the generic text. No new text.

Evidence: built main and candidate in a secretless node:24.22.1 container, with a session-target job created by cron add --session, a stored auth profile added and the inline key removed through the shipped CLI, then cron run --wait read back with cron runs and cron list --json, twice each. On main the run error and lastError were "Session event execution failed"; with this change they show the existing unrecorded inference account refusal with its next steps. A successful job and a model timeout record the same on both. Maintainer Gateway proof on Crabbox by @vincentkoc agrees. The focused regression fails on main, at net 0 test lines. Details: https://github.com/openclaw/openclaw/pull/195901#issuecomment-6840901912.

Closes #195802. Thanks @ericcurtin.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```
