Closes #161929. Thanks @saizero-dr for the report and reproduction details.

## What Problem This Solves

Fixes local TLS Gateway health checks failing with `Cannot read properties of undefined (reading 'defaultProtocol')` when a managed HTTP proxy is enabled.

## User Impact

Doctor and shared Gateway restart/readiness checks can reach the local TLS Gateway without disabling the configured proxy. Default loopback traffic stays direct; explicit `proxy` and `block` loopback modes remain enforced. No dependency, updater, or configuration-schema changes.

## Why This Change Was Made

Node handles `agent: false` by constructing the global agent's class without arguments. Proxyline's global agent requires options. The probe now selects an explicit agent through the existing proxy-routing helpers and applies the existing Gateway loopback policy check. Direct TLS probes disable socket and session reuse so certificate rotation remains subject to the fingerprint check.
