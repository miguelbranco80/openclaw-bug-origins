## What Problem This Solves

Skill source installation fails for paired-node workspaces even though Skill discovery and dependency installation work. Source records and ClawHub update/removal are also missing from that adapter.

## User Impact

Paired-node workspaces can install and track Skill sources, update ClawHub Skills, and remove them through the existing workspace lifecycle. Operators must allow the documented Skill and metadata paths. Installed files remain on the node.

## Why This Change Was Made

Connect the existing workspace contract to the native Skill workers. Gateway retains policy decisions and change hooks; the node owns source files, installation records, and temporary archive cleanup. Publication rechecks Gateway authority within the native installer's existing rollback boundaries. On cancellation, the node closes the installer's input and drains it so native rollback can restore a displaced Skill before exit; a 30-second forced-stop fallback bounds a stuck worker.

The added publication checkpoints are explicitly enabled by the node adapter. Existing SSH publishers retain their single policy reply and stdin-close protocol. Local installers keep their current path. This does not add channel menus or a new public uninstall API.
