## Fix message body

```text
Fixes #202172. Reported by @garrytan, whose repro test is committed here.

## What Problem This Solves

Byte-triggered compaction compares `maxActiveTranscriptBytes` with the active transcript byte count. That count includes every `openclaw.system-prompt` checkpoint: the saved system prompt plus the tool surface. On a setup with about 200 MCP tools, the checkpoint alone is about 150 KB against a 256 KB cap. Compaction then fires early, and the post-compaction size stays over the cap. That sets the latch, and every reply shows the "bounded recent context" notice.

The bad state comes from `transcriptEventContextEligibility` (`session-transcript-projection-append.ts`), which returns 1 for a `custom` entry. Every byte counter then adds those rows:
- SQLite: `readVisibleTranscriptStats`, the sum of `serialized_bytes` over `context_eligible = 1`
- actor: `projectSessionActorContextMetadata`, `seedSessionActorContextMetadata`, `appendSessionActorContextStats` and rewrite deltas
- memory actor: `contextAccountingRows`

## Why This Change Was Made

- A `custom` entry holds host or plugin state and never projects into a model message (`projectSessionEntryMessage` returns nothing for it). It is not conversation, so the counters no longer charge it.
- Eligibility itself is unchanged. Bounded acquisition still needs these control rows ("Control facts still belong in bounded context acquisition"), and existing rows already store `context_eligible = 1`. The change is only in what the counters add.
- `transcriptEventChargesContextBytes` names the rule. Each counter applies it: the TypeScript counters call it, and the SQLite counter uses the stored `navigation_type` predicate.
- The latch, the notice and the cap are unchanged.

## User Impact

A session with many tools compacts on conversation size only, stays under the cap after compaction, and no longer shows the bounded-context notice on every reply.

## Evidence

- Repro test from the issue, through the SQLite counter, the hydrated actor counter and an actor append: fails on main (`byteSize: 150339, eventCount: 3`) and passes with the fix (`198, 2`).
- Memory actor counter: fails on main (`150421, 3`) and passes with the fix (`280, 2`).
- Existing count tests expected custom entries to be counted (`session-transcript-context-eligibility.test.ts`, `session-accessor.sqlite-transcript-store.test.ts`); their expectations now leave the custom entry out.

**Gateway E2E** (dist builds; 200 verbose plugin tools make a 97 KB `openclaw.system-prompt` checkpoint; `maxActiveTranscriptBytes: 150kb`; one small turn, seven turns with about 27 KB of text each, one small turn; real model):

| `transcriptByteCompactionLatch` after the final small turn | set (156269 bytes) | none |

The later head `3aa2516` changes only tests.
```
