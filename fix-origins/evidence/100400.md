## Fix PR #145329 description (by steipete, opened 2026-09-11T21:57:32Z)

```text
## What Problem This Solves

Fixes an issue where users could select **Off** in the reasoning effort picker for a Codex model that does not support disabling reasoning. Selecting that option could use the model's default effort instead of turning reasoning off.

## Why This Change Was Made

The OpenAI provider now builds catalog-backed thinking choices from the supported effort list without prepending an extra Off option. Explicitly advertised `none` still maps to Off, and an empty list remains empty. The shared provider policy supplies Chat, New Session, and thinking-command choices.

## User Impact

Models without disabled reasoning start at their lowest supported effort. Models that advertise `none` retain Off. Session validation and queued model switches use the same corrected capabilities. Queued requests retain their original preference while execution clamps unsupported Off to Low; no settings migration is needed.

## Evidence

- Updated regression cases failed on the original implementation because it added an extra Off choice; they pass after the fix.
- Focused OpenAI provider tests passed (164 tests), along with the existing core and UI tests for empty profiles and persisted selections.
- Independent Codex reviews found no actionable P0–P2 findings in the provider fix or its test follow-up.
- Checked native Codex's model catalog projection and effort picker: both use the advertised effort presets rather than adding None.
- Changed-file checks passed, including extension production/test typechecks, lint, formatting, plugin boundaries, and runtime import-cycle checks.
- Full Control UI in real Chrome with synthetic Gateway data: before, Home selected Off; after, Home selects Low, Right selects Medium, and Home returns to Low. The fixed slider has six supported stops instead of seven.

- Initial CI exposed incidental Off inputs in two Gateway ordering fixtures and stale queued-switch expectations. The fixtures now use Low, and queue tests verify unsupported Off clamps to Low while preserving the original request. All 46 tests in those three affected suites pass locally.
```
