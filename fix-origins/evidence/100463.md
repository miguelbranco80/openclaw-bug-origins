## Fix PR #148830 description (by steipete, opened 2026-09-15T06:03:48Z)

```text
## What Problem This Solves

The update UI marks unavailable version evidence as a failed check, the CLI can leave its spinner running after a failed final history read, and removing an API key immediately after saving it can wrongly report that the key changed.

## User Impact

The version badge shows **Not verified** when identity evidence is unavailable and **Failed** only for an observed mismatch. The recorded update outcome stays unchanged. CLI progress releases its resources while preserving the original ledger-read error. Saving a model API key waits for the Gateway to apply changed provider settings before reporting normal success; an unconfirmed application returns a warning while preserving the saved key.

## Why This Change Was Made

Use the report's existing identity classifier for the badge and dispose the CLI observer and spinner in `finally`. Remove a copied translation catalog that had drifted from the real English strings, a redundant test, unnecessary type assertions and guards, and explanatory comment repetition. Keep the receipt, recovery, localization, and connection-ownership coverage. API-key saving now uses the existing configuration application receipt and originating request continuation, as credential removal already does. Authentication refresh consumes the applied configuration. Concurrent binding/credential guards and disabled-reload policy remain unchanged.

Update execution, schemas, stored outcomes, and installed-updater behavior are unchanged. Historical `versionMatch: false` records use the classification already established by #147553.

Related: #147993, #147553, #148769, #148790.
```
