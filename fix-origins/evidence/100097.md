## Fix PR #153540 description (by steipete, opened 2026-09-20T07:32:34Z)

```text
## What Problem This Solves

Fixes update and restart verification waiting until its deadline on a healthy trusted-proxy Gateway when the local CLI is already paired but no shared token or password is configured.

## User Impact

Verification can authenticate with the service profile's existing device credentials, including when that profile differs from the invoking shell. Existing shared-token, password, and auth-none probes remain unchanged. No new pairing, credential rotation, configuration option, or schema change is required.

The installed updater runs before candidate activation: unchanged older drivers cannot acquire this caller fix by retrying the same update. For an affected source installation, the canonical owner can drain and stop its existing service, run the existing updater with `--no-restart` against the fixed target, then use the fixed CLI to `gateway restart --preserve-definition`. The stopped-service branch avoids the defective old pre-activation verifier; native update, Doctor, recovery and authentication remain in control. This route has been source-verified against an affected older driver; production execution is still pending the landed fix.

## Why This Change Was Made

The verifier forced a null device identity, so the Gateway correctly rejected its handshake. It now reads the existing identity and operator token from the target service environment and carries those prepared credentials through the canonical read-only Gateway client. Server authentication and scope checks remain intact.

The forced-null path was introduced by a5f3623302fd31f917bd83a5abeac56a09a7c737 (#136995). Production delta is +19 lines for explicit service-state ownership; test and documentation changes are separate.

- Regression separates the client/service profile from ambient Gateway state and verifies unchanged identity/token plus no pending pairing request.
- Fixed call owner and restart siblings: 191 tests passed, including shared token/password/auth-none and trusted-proxy local-password cases.
```
