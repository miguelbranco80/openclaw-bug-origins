## What Problem This Solves

Fixes `openclaw update repair` leaving a prepared package activation blocked when the live installation already serves its recorded candidate.

Refs #166377. Thanks @cbhawthorne84 for reporting the stranded recovery record.

## User Impact

Repair verifies the installed candidate, records `publication-settled-external-change`, retains the original recovery evidence, and clears the activation's `update-recovery-pending` block. Failed verification and live executor conflicts keep recovery armed. Use an updater containing this fix; it does not change an older installed repair command.

## Why This Change Was Made

The activation owner excluded `prepared` from candidate-matching settlement. Include that phase in the existing path, reusing the same dist content inventory, manifest, launcher, current-ownership, durability, receipt, and archival checks as publication settlement. No second verifier, schema change, dependency, config, environment, or CLI option is added.
