## What Problem This Solves

Resolves two live ClawHub validation defects left after the Docker fixture was isolated:

1. Live-mode plugin sweeps inherited the synthetic fixture package, so the public lane did not exercise the published `@openclaw/kitchen-sink` plugin.
2. The public artifact resolver returned npm-pack `size` metadata, but the top-level adapter dropped it. Installation succeeded, then lifecycle validation rejected the incomplete install record.

#148129 separately landed the stale Docker helper assertion repair. That assertion is preserved on `main` and is not part of this PR's remaining diff.

## Why This Change Was Made

The ClawHub sweep now selects its default package after choosing live or fixture mode, while explicit package and runtime-ID overrides still win. Executable coverage verifies fixture default, live default, and explicit override routing.

The live artifact adapter now carries the registry-owned `size` fact into the existing metadata normalizer. Missing or malformed sizes remain optional; no downstream recomputation or fallback was added.

The weaker static fixture-literal assertion is removed because the executable routing matrix now protects the actual behavior.

## User Impact

Full release validation now exercises the published ClawHub plugin in live mode. ClawHub npm-pack installs also retain the advertised artifact size in their canonical install metadata.
