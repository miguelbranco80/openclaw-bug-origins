Fixes #174343

## What Problem This Solves

Fixes the update dead end where pre-July JSON state makes current Doctor or update admission require an intermediate release that cannot complete the operator's repair.

## User Impact

Operators can run current `openclaw doctor --fix` and continue upgrading. Doctor imports legacy cron definitions/runtime state, referenced OAuth credentials, Voice Wake settings, conversation bindings, and default-home plugin approvals into existing SQLite owners. Current SQLite data wins, and original bytes are preserved in named archives.

Obsolete delivery queues, plugin indexes, sandbox registries, replay ledgers, and restart notifications are archived with recovery instructions. Old deliveries are never replayed automatically. Doctor tries both historical OAuth key files and, in an interactive terminal, the existing macOS Keychain entry; missing keys leave archived ciphertext and give `openclaw models auth login --provider openai` as the forward path. Restoring archived sources does not replay a completed credential import.

## Why This Change Was Made

Importer removal left refusal guards as the only owner of several shipped state formats. The base [refusal at lines 37–40](https://github.com/openclaw/openclaw/blob/5aec205816506ceb6983a5ab1c549c9e0b301a61/src/infra/state-migrations.retired-files.ts#L37-L40) still directs operators to 2026.9.7. Source history identifies removals in `ff96d47c3506` (delivery queues), `a8c1182c16eb` (cron), `d12a2cf036c5` (OAuth sidecars), `f77ceef31812` (pre-June OAuth), and `3543c6bb0895` (runtime JSON).

Restore the shipped parsing logic under Doctor's existing maintenance and migration owners, and reuse the existing verified backup/receipt owners for archival. Runtime readers stay on current formats. Admission keeps importable user-state sources pending until current Doctor has committed them, and refuses sources it cannot inspect; transient archives remain advisory. Config-only recovery retains the guard against discarding a custom cron locator before its source is imported; its recovery action is current Doctor. No schema, dependency, or public option changes.

The simplification removes obsolete refusal paths and refusal-only tests. The remaining growth is the one-shot import logic needed to repair every refused category together. A binary archive regression also fixes a shared verifier that hashed decoded UTF-8 instead of original bytes. The historical OAuth reader only tried its first key-file candidate; Doctor now tries both existing locations without adding an environment option. Missing sidecars leave the auth source pending so correcting a stale locator and rerunning Doctor still recovers the credentials. Unattended runs preserve the existing no-Keychain-prompt contract.
