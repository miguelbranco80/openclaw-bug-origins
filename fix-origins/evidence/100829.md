## Fix PR #154215 description (by steipete, opened 2026-09-21T00:37:22Z)

```text
## What Problem This Solves

Fixes existing-session browser waits discarding usable element references, and stale references targeting the wrong element after iframe renderer replacement.

## User Impact

A snapshot → wait → action sequence keeps working, including cross-origin frames. Navigation invalidates references from the replaced document and the next snapshot recovers. The default MCP server is installed with OpenClaw, so browser startup no longer needs an npm download.

The bundled runtime adds approximately 13 MB unpacked. Custom MCP executables remain operator-managed and need the upstream identity fix for the same guarantees.

## Why This Change Was Made

One per-target snapshot owner now retains document identity and references during polling, invalidates only a replaced document, and checks the admitted URL immediately before evaluating a predicate. Polling skips DOM-stability waits.

The published MCP server can reuse backend node IDs across frames and renderer lifetimes. This carries the repair from https://github.com/ChromeDevTools/chrome-devtools-mcp/pull/2788 as a pnpm patch against exact version 1.8.0. OpenClaw bundles the patched dependency and launches its installed CLI through Node, retiring the old CI npm prewarm/cache/offline setup and its source-regex test; tarball checks verify the version, complete runtime payload, licenses, and patched hashes. Remove the patch after adopting a fixed upstream release that passes the same contract suite.

## Evidence

Compatibility: snapshot maps are process-local state recreated on MCP connection; this change writes no database or persisted browser-reference format and requires no data migration. Existing custom executable settings remain supported, and explicit `mcpCommand: "npx"` still selects the managed server. The SDK change only exports the existing Node resolver.

- Published 1.8.0 reproduced 243 duplicate element IDs and an old iframe reference resolving to an unrelated replacement button. The patched package passed frame-specific click, fill, evaluation, screenshot, stale-reference rejection, and recovery checks over actual MCP stdio.
- 44 Chromium and package contract cases, 228 focused browser cases, and 102 existing package-validator cases passed on Blacksmith Testbox. Fresh independent review found no actionable P0–P2 findings.
- Both npm and pnpm packaging preserved patched bytes through offline consumer installs. The complete OpenClaw build, canonical tarball validation, normal npm installation, and installed CLI passed.
- Exact-head Linux browser/package contract and both Windows CI partitions passed, including the bundled-MCP pack/install/hash/CLI cases. The only failed CI job stalled while the published 2026.9.4 baseline installed its Discord companion, before candidate installation; retained diagnostics show a silent npm timeout. Its exact-head rerun passed without changing code or timeouts; the underlying stall cause remains unknown.
- A separate staging-recovery timeout did not reproduce in the unchanged standalone file (16 passed) or original 32-file shard order (850 passed, 6 skipped). Its cause remains unresolved; no timeout or assertion was weakened.
- The installed OpenClaw browser runtime passed default-server launch, snapshot → wait → click, cross-origin iframe action, stale renderer rejection, fresh recovery, and natural process shutdown while preserving the caller-owned browser.

The [hosted browser contract run](https://github.com/openclaw/openclaw/actions/runs/35548320732) passed on the runtime commit. The [final full CI run](https://github.com/openclaw/openclaw/actions/runs/35558753243) and [exact-head browser/package contract](https://github.com/openclaw/openclaw/actions/runs/35558753203) passed.
```
