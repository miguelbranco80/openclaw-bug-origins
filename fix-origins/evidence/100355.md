## Fix PR #174826 description (by steipete, opened 2026-10-16T23:24:32Z)

```text
Related: #165957

## What Problem This Solves

Fixes forced worker abandonment failing a replacement placement or discarding its pending workspace result when cleanup resumes after the session's owner changes.

## User Impact

A replacement turn keeps its placement, claim, tools, and pending workspace result when delayed cleanup for the previous owner resumes. Ordinary forced abandonment still closes its own tool admission, joins entered work, and records the abandoned result.

If ownership changes at the native transition boundary, teardown rejects the stale operation rather than taking over the replacement. Operators can retry against the current owner. Filesystem rollback remains best effort; failed rollback journals remain available for recovery. No schema, configuration, or protocol change is required.

## Why This Change Was Made

On base `472b7f94d52d`, `placement-force-abandon.ts:112` rereads the reconciliation inventory after awaited journal/result work and then tears down whichever placement it finds. `placement-transitions.worker.ts:123` checks the placement tuple but has no caller-captured turn constraint, so a replacement claim at the same generation can be cleared.

Capture the selected placements and claims once, close their tool admission before cleanup preparation, preserve changed owners and their artifacts, and carry the original claim or claimlessness through the existing drain/reconcile transactions. Reconciliation reuses the existing exact-claim predicate. Main's returned-row optimization remains intact. This is independent of the session-controller changes in #165957.

The simplification pass retained the existing placement, tool-admission, and SQLite writer owners; it adds no controller, scheduler, persistent state, or compatibility path. Production delta: **+127/-10 (net +117)**. Test delta: **+245/-44 (net +201)**. Documentation: one existing paragraph clarified. The production growth captures ownership across awaits and supplies the missing transaction guard.
