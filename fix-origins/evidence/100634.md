## What Problem This Solves

Fixes ACP harness resets failing with `EACCES` from a read-only installation, while preserving sessions stored under the former `<workspace>/state` default during upgrades.

## User Impact

GitHub Copilot, Kilo Code, OpenCode, Pi, and Qwen Code reset hooks use `acpx/` under the Gateway state directory, honoring `OPENCLAW_STATE_DIR`. Other reset-hook failures warn once per harness ID per process; subsequent resets still retry.

**Upgrade behavior:** when no explicit `plugins.entries.acpx.config.stateDir` is configured and the new default is empty, ACPX startup or `openclaw doctor --fix` automatically adopts the old state directory, including its sessions and other files. Set the existing override only to retain the old location. An occupied destination and explicit overrides are preserved. Failed adoption warns with the override to set and retains the applicable legacy path for that process. Inspection errors on an already-used destination preserve that destination.

## Why This Change Was Made

The existing ACPX session-owner migration module owns adoption for both Doctor and service startup, before runtime storage is opened. It uses the already-declared `fs-safe` move primitive for same-filesystem rename and source-verified cross-filesystem copying and cleanup. Pending/completed markers live in existing plugin state, so completion can recover after a marker-write failure and completed adoption never revisits stale legacy files. Doctor declares both directories for update backup and reports adoption problems as recoverable warnings.

No new configuration, dependency, filesystem sidecar, or runtime cache is added. The migration follow-up adds about 200 production lines for recovery, notices, backup inventory, and both entry points. The existing filesystem implementation owns the actual move.
