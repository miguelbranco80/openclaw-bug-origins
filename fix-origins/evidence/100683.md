Fixes #175429: a consistent third-party npm plugin install is reported as `provenance-invalid`, prompting a reinstall that cannot change its catalog status.

Supersedes #175451, thanks @LiuwqGit.

## User Impact

Inspection reports `third-party-npm` for consistent, non-catalog npm installs. Explicitly allowed plugins no longer produce the unverified-install warning, and hook-turn refusals explain that reinstalling the same package cannot grant official trust. Trust eligibility is unchanged; conflicting identities, local artifacts, official-ID namesakes, and catalog packages recorded under another ID retain their existing classifications.

The shared install-record classifier conflated valid third-party provenance with invalid official provenance. Reuse the existing npm identity parser and catalog checks to distinguish them at that owner. Keep all trust-gated capability decisions unchanged. Remove a one-use official-name helper and simplify identity collection and redundant temporary control flow in the same owner.
