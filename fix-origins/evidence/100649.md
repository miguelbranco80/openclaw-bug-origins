## Fix PR #152335 description (by steipete, opened 2026-09-19T01:13:38Z)

```text
## What Problem This Solves

Blocked migration receipts identify the earlier failing step but omit its actual refusal reason, making an individual receipt insufficient to diagnose a stopped Doctor run.

[Main CI run 35403665608](https://github.com/openclaw/openclaw/actions/runs/35403665608) exposed this diagnostic gap while investigating a caller-mode test failure. This change does not claim to fix that original flake.

## User Impact

Operators and diagnostic consumers can read the originating step ID, refusal code, and message directly from a blocked execution receipt.

Update behavior: none intended. The optional field is additive; migration selection, execution, refusal outcomes, storage schemas, retention, and durability are unchanged. The installed 2026.9.4 updater does not consume raw step receipts and ignores unknown result keys.

## Why This Change Was Made

`originatingRefusal` carries `{ stepId, code, message }` from the actual halted receipt through every blocked-tail handoff. Using the execution receipt preserves runtime failures that are absent from the planned step descriptor. Prelude execution returns its result and halted receipt together instead of retaining a separate mutable failure flag.

## Evidence

- Four owner regression cases and the compiled Doctor error JSON reader pass. The pre-fix owner run exposed missing origin fields in three cases; returned and thrown schema refusals are now covered separately. Existing caller-mode tests are unchanged.
- New tests explicitly assert the origin fields: Vitest subset diffs can omit fields that an assertion does not inspect.
- Independent P1 review: clean.
- Published updater compatibility: verified the npm 2026.9.4 tarball's SHA-512 integrity and inspected its packaged result parser against the released tag.
- All 78 state-migration test files: 77 passed, one platform-only file skipped; 1,067 tests passed and four skipped (Node 24, eight workers).
- Eight Doctor/update unit files: 206 tests passed. Compiled Doctor refusal-JSON test passed; existing reader tests accept receipts without the new field.
- `node scripts/check-changed.mjs` passed with `DEVELOPER_DIR` exported, including production/core-test typechecks and normal type-aware lint (no substitute needed). Formatting, line-cap ratchet against `origin/main`, diff check, Kysely guardrails, and changed-doc checks passed.
- Additional legacy-mode Doctor E2E check was not green: initially four failures, including a 30-second timeout while worker preparation ran and downstream mock errors. An exploratory collection-time preparation change reduced this to two failures: the first test timed out and the next failed in plugin convergence with `Plugin state changed during preparation; retry the operation.` The exploratory harness edit is excluded from this PR. No timeout, assertion, or migration caller-mode tests were changed; this broader E2E coverage remains a validation gap.

Opened for review; not for landing in this task.
```
