```text
## What Problem This Solves

Fixes the first Codex turn failing on a busy host when discovery times out while the shared app-server is still starting.

## User Impact

A caller abandoning discovery no longer cancels shared startup. Later requests can use the ready server, configured startup budgets are honored, and expired acquisitions release their lease without sending a late RPC. Explicit supervision connections keep their existing connection policy.

## Why This Change Was Made

The shared service owns physical startup; each caller owns its wait and subsequent request budget. Timeout normalization now uses the config owner without repeating harness connection admission. Timeout diagnostics and control observations retain the phase that failed before successful cleanup, while cleanup-originated failures retain their own phase.

The original contributor's work and ancestry are preserved. The correction was independently reviewed, then integrated through the native baseline workflow with frozen main `d4babe8e8ba448bd21bdc4c89de0d223a4353faa`.
```
