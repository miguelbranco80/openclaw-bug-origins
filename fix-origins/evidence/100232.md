## What Problem This Solves

An explicit model-catalog refresh already admits a 180-second acquisition, but the shared HTTP acquisition helpers still default to five seconds. A healthy slow discovery can therefore appear unavailable before the existing refresh budget expires.

Related: #168356 and [Homelab #1992](https://github.com/jlapenna/homelab/issues/1992). This fixes propagation of the existing budget; it does not add a configuration option or close the broader runtime-adoption request.

## User Impact

Explicit refreshes can use their existing admitted budget. Ordinary discovery retains its five-second limit, and an explicitly tighter HTTP timeout remains binding. Existing zero-timeout meanings are preserved.

## Why This Change Was Made

Carry the admitted deadline through the existing catalog-expiry context and HTTP helpers. Separate pending loads by their stable effective budget while continuing to share healthy completed values with their original TTL. Preserve shared-load cancellation/cache warming, generation ownership, auth, SSRF protection, pagination and body limits.

This is separate from the held diagnostics PR #165915. Both touch implicit-provider discovery and its scope tests; that branch and its diagnostics changes remain untouched.
