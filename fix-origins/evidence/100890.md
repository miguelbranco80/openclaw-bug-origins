Reuse the existing inherited-cache respawn handoff, preserving the supervised PID on supported platforms and the child bridge on Windows. ## Fix PR #171358 description (by steipete, opened 2026-10-13T20:48:41Z)

## What Problem This Solves

Node compile-cache persistence synchronously blocks the Gateway main thread. The earlier startup flush in #171298 moved this cost before readiness; the compilecache2 experiment measured a 3.8-second cold main-thread flush. Disable caching on the Gateway main thread while retaining the existing build-scoped cache owner for workers and their existing flush boundaries.

## User Impact

Ordinary Gateway launches no longer pause the main event loop to persist Node bytecode. Worker caching remains enabled, preserving its startup benefit.

## Why This Change Was Made

The launcher, compiled entry, and direct CLI entry pass the Gateway role to the shared owner. An inherited active cache uses the existing respawn handoff marker to start Node uncached, then restores worker caching. No new environment flag. Remove the two Gateway flush calls. Short-lived CLI commands, explicit prewarming, and caller-authored NODE_DISABLE_COMPILE_CACHE retain their existing policies. Node permission mode retains an already-active caller cache because it may forbid process replacement; optional caching must not prevent startup.

## Scope and measurements
