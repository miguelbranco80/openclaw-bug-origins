## Fix message body

```text
* fix(logging): surface structured warn fields on plain console sinks

Warn, error, and fatal subsystem records carried their structured fields
only into the JSONL file sink and the `json` console style. A Gateway under
systemd writes stdout to journald, so operators reading the unit journal saw
a bare `[session-catalog] slow Codex catalog list phases` line with none of
the phase timings the diagnostic collects.

Append those fields as one compact `key=value` tail for warn, error, and
fatal in the pretty and compact console styles. Scalars render bare, strings
containing whitespace and nested values render as JSON, `Error` values render
as their message, `undefined` fields are skipped, and the tail is capped at
2 KiB. Info and lower console lines stay message-only, an explicit
`consoleMessage` override still owns its console text, and the file sink is
unchanged. The tail is built before the formatter's redaction pass, so
secrets in field values are masked like the rest of the line.

* fix(logging): report console meta values without a JSON form

JSON.stringify yields undefined for functions and symbols and throws on
circular structures, and String() on those values is both unsafe and
uninformative. Reuse this file's inspect formatter for that fallback, collapse
its whitespace to keep the record on one line, and cover it with a test so
such a field is reported instead of silently dropped.

* fix(logging): redact console meta through the shared transport owner

Flattening structured fields into text lost the key-aware protection the
redactor applies by field name, so a sensitive key such as `apiToken` holding
an opaque value reached a plain sink unmasked. The 2 KiB cap also ran before
redaction, so a registered secret straddling that boundary could leave a
surviving prefix in the journal. The tail was built even in `json` style, where
it is discarded, serializing a stateful `toJSON` value twice.

Build the tail from `redactLogRecordForTransport(meta, { format: "console" })`,
the same owner the `json` console style uses, and skip it entirely for that
style. Masking now happens by key before structure is lost, and the cap can
only clip text that is already masked.

That owner also handles circular references, bigints, and values with no JSON
form, so the local inspect fallback is gone. It does reduce an Error to `{}`,
so Errors map to their message first. A failure to serialize omits the tail
rather than costing the console its message.
```

## Fix PR #151215 description (by steipete, opened 2026-09-17T22:51:28Z)

```text
## Problem

Warn-level diagnostics on a systemd-managed Gateway lose their structured fields. `journalctl -u openclaw-gateway` shows only

```
2026-09-17T20:58:17.379+00:00 [session-catalog] slow Codex catalog list phases
```

while the record itself carries `elapsedMs`, `admissionWaitMs`, `controlWaitSumMs`, `nodeWaitSumMs`, `provenanceMs`, `exclusionMarkCalls` and friends. The same gap hits `slow Codex catalog page producer`, `[sessions] slow session list` and `slow session catalog provider list`. The phase timings are exactly what an operator needs at the moment the warning fires, and journald only ever sees the console line.

The cause is in the subsystem logger, not the console transport: those writes bypass console capture and go straight to the raw sink. `emitLog` passed `meta` to the file sink and to the `json` console formatter, but handed the pretty/compact formatter the message string alone. The JSONL file sink was not a workable substitute on that host, having captured only a subset of subsystems before stopping shortly after startup.

## Solution

Render the structured fields as one compact `key=value` tail and append it to warn, error, and fatal console lines in the pretty and compact styles.

- The fields first go through `redactLogRecordForTransport` with the console format, the same redaction owner the `json` console style already uses. Key-aware masking therefore applies before the structure is flattened, and the length cap can only clip text that is already masked.
- Scalars render bare, strings containing whitespace or `=` and nested values render as JSON, `Error` values render as their message, and `undefined` fields are skipped.
- That shared owner also handles circular references, bigints, and values with no JSON form, so this code carries no fallback of its own. Functions and symbols drop out exactly as they already do in the file sink.
- The tail is capped at 2 KiB and marked `...(truncated)` past that.
- Info and lower console lines stay message-only, so routine output does not get noisier, and the `json` style skips the tail entirely so its metadata is serialized once.
- An explicit `consoleMessage` override still owns its console text with no tail, keeping the embedded-agent and model-fallback callers that rely on it unchanged.
- The tail is assembled before the formatter's `redactSensitiveText` pass, so secret values in fields are masked like the rest of the line.

I chose unconditional emission over a config flag: warn-and-above records with metadata are rare, and a flag defaulting to off would leave the defect in place for exactly the operator who needs the fields.

## Impact

File sink semantics are untouched, and `openclaw logs --json` still carries the original `raw` record. `logging.consoleStyle: "json"` is unchanged. After this lands, the journal line reads

```
[session-catalog] slow Codex catalog list phases elapsedMs=14211 admissionWaitMs=3 controlWaitSumMs=0 nodeWaitSumMs=9800 provenanceMs=120 exclusionMarkCalls=42
```

ClawSweeper then blocked the merge with three findings, all of them real and all now fixed:

- Flattening lost the redactor's key-aware protection, so a sensitive key holding an opaque value could reach a plain sink unmasked.
- The 2 KiB cap ran before redaction, so a registered secret straddling that boundary could leave a surviving prefix.
- The tail was built even in `json` style, where it is discarded, serializing a stateful `toJSON` value twice.

Routing the tail through the shared console redactor closes the first two, and skipping it in `json` style closes the third. Protection is now stronger than the original revision: a pattern-matched token that previously showed as `sk-sup…2345` is masked outright once its key is recognized. The change also got smaller, since the shared owner subsumes the local fallback.
```
