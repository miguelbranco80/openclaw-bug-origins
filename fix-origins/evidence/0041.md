## Fix PR #199889 description (by daniel-lxs, opened 2026-11-16T01:55:21Z)

```text
## What Problem This Solves

Memory imports through the Gateway (`migrations.memory.apply`, used by the Control UI memory import page) and migrations started during onboarding write a pre-migration backup archive without an output path. It lands in the process's current directory. A Gateway started from a source checkout drops the user's backup into the checkout, and the migration resource tests leave real archives in the repo root.

Fixes #199888.

## Fix

The backup engine gets a `preferHomeOutput` option (`src/infra/backup-create.ts`). With no `output`, it writes to the home folder unless the home folder is inside a backed-up source (for example, when an agent workspace is the home folder). Otherwise it keeps the existing default: the current directory, or home when the current directory is itself backed up. The check uses the same included-source list as the engine's existing "must not be written inside a source path" refusal.

`applyProviderMemoryImport` and `offerPostInstallMigrations` set `preferHomeBackupOutput`, which `runMigrationApply` passes through to the backup. `openclaw migrate` and `openclaw backup create` keep their documented current-directory default. `docs/cli/migrate.md` says where each one writes.

## Evidence

Captured output is in the proof comment below. All runs are real Gateway or onboarding runs in a clean macOS VM with the bundled Claude import plugin, made-up Claude Code memory and an isolated HOME. `main` is efc03e24624; "this branch" is 709007e4600.

**Gateway memory import** (`migrations.memory.plan` then `migrations.memory.apply` over `openclaw gateway call`):

| Agent workspace | Gateway started from | `main` | this branch |
|---|---|---|---|
| `HOME/workspace` | a folder outside HOME | imported, archive in that folder | imported, archive in HOME |
| HOME | a folder outside HOME | imported, archive in that folder | imported, archive in that folder |
| HOME | the state dir | fails: "Backup output must not be written inside a source path" | same failure, unchanged |

No case is worse than `main`. The last row fails the same way on `main` and is out of scope here.

**Onboarding:** interactive `openclaw onboard --classic`, started from a folder outside HOME, with Enter pressed at each prompt (the memory import prompt defaults to yes). Both runs report "Claude: 1 migrated". On `main` the archive is written to the onboarding folder; on this branch it is written to HOME.

**Post-install migration offer** (`offerPostInstallMigrations`): an existing install whose OpenAI models run on the Codex runtime re-runs `openclaw onboard --classic` from a folder outside HOME, picks OpenAI with an API key, and accepts the Codex migration offer for made-up `HOME/.codex` state. Every run reports "demo-notes (Migrated)". With the workspace at `HOME/workspace`, `main` writes the archive to the start folder and this branch writes it to HOME. With the workspace at HOME, both write it to the start folder.

**Upgrade from latest stable:** 2026.11.3 sets up the state and imports one memory file (archive in the Gateway's folder). Then this branch runs `doctor --fix --non-interactive` (exit 0) and starts its Gateway on the same state. Gateway port, auth, plugin and workspace settings are unchanged. The memory imported on stable is still there and is planned as a conflict instead of being imported again. A new memory file imports, with the archive in HOME.

**Tests:**

- `src/commands/backup.test.ts`: new case for `preferHomeOutput` with the current directory outside home. Workspace inside the state dir: archive in home. Workspace is home: archive in the current directory. Without the source check, the workspace-is-home case fails with the same "must not be written inside a source path" error as the VM run. With it, the file passes (20 tests).
- `src/gateway/server-methods/migrations.resources.test.ts` asserts that `backupPath` is directly under `HOME`. With the test on `main`'s code, 2 of 5 fail (`Received: <repo root>`) and 4 archives are left in the repo root.
- With this branch, all three resource suites pass (5, 3 and 11 tests), and no archives are left in the repo.
```
