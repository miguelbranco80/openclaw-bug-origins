## Fix message body

```text
On Windows the managed update swap renamed the live package tree to its backup location once; a transient EPERM/EBUSY/EACCES from an antivirus, indexer, or Scheduled Task handle failed the swap and rolled the update back. The filesystem owner of the swap now retries those codes with bounded backoff (16 attempts), records each retry, re-checks package identity and update authority between attempts, and reports a named failure after the bound. POSIX behavior is unchanged.

Refs #162027
```

## Fix PR #162231 description (by steipete, opened 2026-10-01T00:34:14Z)

```text
Refs #162027

## What Problem This Solves

Windows npm updates fail immediately when antivirus, indexing, or another process briefly holds the live package directory during its backup rename.

## User Impact

Updates can now finish after transient `EPERM`, `EBUSY`, or `EACCES` failures at that boundary. Each retry is recorded as a warning. Persistent failures still fail, name the source and backup paths, and preserve the installed package. The POSIX rename remains a single attempt.

This change belongs to the installed updater; a newer candidate cannot patch an already-running 2026.9.6 driver. The issue's separate exit-13 failure was already fixed in 2026.9.7 by #157042; this PR does not close the issue or claim to fix its repair-finalization symptoms.

## Why This Change Was Made

The swap owner delegates the backup rename to its existing filesystem owner. Windows uses the existing retry scheduler for 16 attempts with 250 ms initial backoff, capped at 5 seconds, totaling 57.75 seconds of waiting. Each attempt rechecks update authority, source/parent identity, and backup-path absence. There is no copy/delete fallback for the live package.

[Node's `fs.rename` reference](https://nodejs.org/docs/latest-v24.x/api/fs.html#fsrenameoldpath-newpath-callback) defines the rename/error contract. The explicit Windows antivirus-lock note is in [`graceful-fs`'s rename implementation](https://github.com/isaacs/node-graceful-fs/blob/v4.2.11/polyfills.js#L87), which documents locks lasting up to a minute and the same three retryable error codes; that note is not currently present in Node's `fs.rename` documentation.

The regression is registered in the existing `test:windows:ci:2` inventory. The actual changed-scope selector enables Windows for it, and the actual Windows planner assigns it exactly once to `checks-windows-node-test-3`.
```
