## Fix message body

```text
Result: plugin harnesses (Codex app-server, Agents API, Muse) now read session history with the same guard as the embedded runner. Their history keeps everything since the latest compaction and only grows between compactions. Follow-up to #203536.

## What Problem This Solves

`resolveAgentHarnessHistoryLimits` (Plugin SDK) still computed its own byte cap: `contextTokenBudget × 8`. Each Codex hook/continuity read, Agents API prompt-hook read and Muse session transfer therefore cut the oldest turns once history passed 8 bytes per budget token. Reasoning, images and tool payloads reach that size far below the token budget. Each new attempt reread and cut the history again, so it was rewritten outside compaction. This is the same class #203536 fixed for the embedded runner.

## Why This Change Was Made

- `resolveAgentHarnessHistoryLimits` now returns `resolveEmbeddedSessionContextLimits({})` (16 MiB / 10,000 events) plus its existing `toolResultOverflow: "omit"`. There is one owner for the bound, and the duplicate budget-based computation is gone.
- The export keeps its name and signature. Its `contextTokenBudget` argument is still accepted, but it is **deprecated and ignored** (documented in the doc comment and in `docs/plugins/sdk-agent-harness/attempt-runtime.md`).
- Bundled callers stop passing it. Codex drops the `contextTokenBudget` argument from `readCodexMirroredSessionHistoryMessages` / `readMirroredSessionHistoryMessages`. Agents API drops the limits from its history-reuse scope key: the limits are now constant, so a budget change no longer forces a fresh read. Muse calls it with no argument.
- No schema, protocol or dependency change.

Tests that asserted the removed budget cut are deleted or rewritten:
- Codex `session-history.test.ts`: the budget-128 cut and budget-512 omission tests are replaced by the regression test below.
- `run-attempt.bounded-continuity.test.ts`: the "assistant-only bounded suffix" case is kept. Its user turn is now larger than the 16 MiB guard, so it still covers the fallback past the guard.
- Agents API: the "new budget" retry case is removed, and the pinned `maxBytes: 256_000` assertion is removed.

## Evidence

Regression test through the Codex harness history consumer (`readCodexMirroredSessionHistoryMessages`): 1.3 MB of history, which is past the old default-budget cut and far below compaction. Two consecutive reads with a new turn appended between them.
- Base `2754763da236`: red, `expected … to have a length of 43 but got 25` (the oldest turns were cut).
- Head: green. All 43 messages are returned, and the second read extends the first one exactly.
- Mutation: head with the harness cap set back to `128_000 × 8` is red again (the same 25-message cut).

Tests: the touched test files plus every test file that imports a changed source (25 files), oxfmt/oxlint on the changed files, and `pnpm check:changed`.

## What Changes for Users

Codex, Agents API and Muse sessions with reasoning, screenshots or large tool output keep their whole history (and the provider cache prefix) until compaction. Before, old turns dropped silently on each attempt.

## Merge danger

Two-way door. A revert restores the budget-based cut. Third-party plugins that pass a budget get the shared guard; their call still compiles.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```

```text
## What Problem This Solves

OpenClaw cannot run agents through Meta's Muse Code CLI. Muse has no ACP support, so the acpx route does not work, and `meta/*` models only run on the built-in runtime.

## User Impact

Users can install the external `@openclaw/muse` plugin and set `agentRuntime: { id: "muse" }` on a `meta/*` model or on the `meta` provider. Turns then run through `muse serve`, using Muse's own sign-in (subscription browser login, stored key, or `META_API_KEY`). Muse owns its native tools, sandbox, MCP servers and session state. OpenClaw keeps channels, approvals, the transcript and session mapping. The runtime is opt-in and never auto-selected.

## Why This Change Was Made

- New external plugin `extensions/muse`. It registers an `AgentHarnessV2` with id `muse` and talks to Muse through the official `@muse-code/sdk` over the Muse Session Protocol. The SDK is pinned to 1.4.2, the newest version the repo's `minimumReleaseAge` policy admits.
- **Exec policy.** The effective policy is resolved through the SDK `execPolicy` contract across the global, agent and override layers, including `tools.exec.mode`, then tightened by the host-local exec-approval floors (`loadExecApprovalsReadOnlyAsync`, `minSecurity`/`maxAsk`). An explicit full-session elevation is the only bypass. Deny becomes `muse serve --disable-shell --disable-write` with `denyUnmatched`. Full with `ask: off` becomes `allowAll`. Everything else becomes `promptUnmatched`, and each Muse request goes to OpenClaw's approval flow (allow-once or deny, server-offered choices only, 120-second wait). Exec allowlist, `ask: always`, OpenClaw sandbox, workspace-only file access, restricted tool policy and `adaptive` thinking are refused before Muse starts, with a user-visible message.
- **Settlement.** On abort, timeout, approval failure or transcript failure, the harness interrupts and then waits for the native turn's terminal outcome before releasing the attempt. If no terminal arrives, it closes the host after 5 seconds.
- **Sessions.**
  - Bindings live in plugin keyed state (SQLite) and are published only after Muse accepts the turn. A Muse session is resumed only when workspace, model, credential, read-only posture and approval mode are unchanged.
  - A server-authored resume refusal starts a new session and logs why. Muse ran nothing in that case.
  - `reset` and `withSessionContextReset` (after a committed history cut) drop the binding.
- **Context.** A fresh Muse session (first turn, model change, refused resume, or committed context reset) is seeded once with OpenClaw workspace bootstrap context (`resolveBootstrapContextForRun`) and the retained conversation (`openModelContextAsync`, bounded by `resolveAgentHarnessHistoryLimits`). If the retained context cannot be read, the turn fails visibly before anything is dispatched.
- **Input and results.** Prepared images are forwarded as MSP image parts. Native tool failures carry `lastToolError` back to core.
- **Failure reporting.** Failures are logged to the Gateway log with Muse's stderr tail. Muse's `authRequired` failure becomes "not signed in on the Gateway host; run `muse login`".
- **Config baseline (maintainer-approved).** The plugin config budget goes from 4553 to 4575. 21 entries are the generic `plugins.entries.muse.*` entries every plugin gets; 1 is `binaryPath`, which is needed when the Gateway service's PATH lacks `~/.local/bin`.
- **Data-model compatibility.** The plugin is new. It adds no tables or columns and uses only its own plugin keyed-state namespace, so there is no existing stored data to migrate.

Known gaps (documented in `docs/plugins/muse.md`):
- OpenClaw agent tools are not bridged: MSP has no client-tool contract.
- No live steering, compaction, isolated completion or `/btw` through Muse.
- Model Setup cannot activate a new `meta` API key while `meta/*` routes to `muse`.
- Chat shows a generic failure notice; the actionable cause is in the Gateway log.
```
