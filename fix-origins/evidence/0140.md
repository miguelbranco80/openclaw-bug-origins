## Fix PR #198763 description (by obviyus, opened 2026-11-14T08:30:15Z)

```text
## Summary

Gemini 3.1 Pro supports `LOW`, `MEDIUM` and `HIGH` thinking ([Gemini thinking docs](https://ai.google.dev/gemini-api/docs/thinking), per-model table). OpenClaw treated every 3.x Pro id like the retired Gemini 3 Pro preview, which only had `LOW` and `HIGH`:

- The Google thinking profile hid `medium` for `google/gemini-3.1-pro-preview`, so `--thinking medium` was refused.
- `getGoogleThinkingLevel` (`packages/ai`) and the payload sanitizer (`resolveGoogleGemini3ThinkingLevel`) rewrote `medium` and mid-size budgets to `HIGH`. Any provider whose own payload carried `MEDIUM` on the `google-generative-ai` API was silently upgraded to `HIGH`, which costs more and is slower.

`gemini-3-pro` and `gemini-3-pro-preview` already normalize to `gemini-3.1-pro-preview`, so no live id still needs the old rule. Pro now differs from the other thinking-level models in one way only: it has no `MINIMAL`. That fact lives in `googleFlashSupportsMinimalThinking`, and the separate Pro branches are removed. Net −8 lines of production code.

## Proof

I ran an isolated scratch Gateway with a Gemini API key (env-scrubbed `HOME`, `OPENCLAW_STATE_DIR` and `OPENCLAW_CONFIG_PATH`). The `google` provider pointed at a loopback pass-through to `generativelanguage.googleapis.com` that logged only `generationConfig.thinkingConfig`. Each case was one `openclaw agent --model google/gemini-3.1-pro-preview --thinking <level>` turn.

| `--thinking` | main `06bfea7a5706` | this PR `fdfb7e99f491` |
| --- | --- | --- |
| `medium` | refused: `Thinking level "medium" is not supported … Use one of: off, low, adaptive, high, ultra.` | `{"includeThoughts":true,"thinkingLevel":"MEDIUM"}`, 200, reply `Ready.` |
| `low` | `LOW`, 200 | `LOW`, 200 |
| `high` | `HIGH`, 200 | `HIGH`, 200 |
| `off` | `{"thinkingLevel":"LOW"}`, 200 | `{"thinkingLevel":"LOW"}`, 200 (3.1 Pro cannot disable thinking) |
| `minimal` | not offered | still refused; levels are now `off, low, medium, adaptive, high, ultra` |

Sibling check on the same Gateway: a provider plugin on the `google-generative-ai` API with `gemini-3.8-flash --thinking medium` still sends `MEDIUM`.

## Tests

- `extensions/google/thinking.test.ts`: Pro level and budget mapping (`medium` → `MEDIUM`, budget 2049 → `MEDIUM`, budget 8193 → `HIGH`).
- `extensions/google/provider-policy-api.test.ts`: Pro profile includes `medium` and still omits `minimal`.
- `extensions/google/transport-stream.test.ts`: the existing 3.1 Pro `reasoning: "medium"` request expected `HIGH`, which was the bug. It now expects `MEDIUM`.
- `src/llm/providers/stream-wrappers/google.test.ts`: the sanitizer keeps a provider's `MEDIUM` on 3.1 Pro.

`ocx test` on `extensions/google`, `packages/ai/src/providers`, `src/llm/providers/stream-wrappers`, the catalog thinking-profile contract and the embedded runner extra-params tests all pass.
```
