## Fix message body

```text
fix(qa): stop the coverage report from overwriting its own summary input

The QA coverage command wrote its report to the output path even when that path was the summary file it was reading, directly or through a hardlink or symlink. The input was destroyed. The command now rejects an output path that resolves to the input and leaves the input unchanged.

Evidence: 46 real CLI invocations on Linux, Node 24.22.1. For direct-path, hardlink and symlink collisions in JSON and Markdown, main corrupted 12 of 12 inputs; with this change all 12 were rejected with the input hashes and completed status preserved (twice each). Distinct outputs and stdout reporting pass 8 of 8 on both refs, and the running, malformed and missing-summary errors are unchanged. Details: https://github.com/openclaw/openclaw/pull/186743#issuecomment-6470953745.

Thanks @Alix-007.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```

## What Problem This Solves

`openclaw qa coverage --tools --summary input.json --output input.json` overwrites a completed suite summary with the coverage report. Hardlink and symlink output aliases can destroy the same input, in either JSON or Markdown mode.

## User Impact

Coverage reports reject an output that identifies their summary input, preserving the completed artifact for later reporting. Distinct output files and stdout reports keep working, including reports whose coverage verdict is nonzero.

## Why This Change Was Made

Summary inputs now share the existing evidence-input protection and inode guard. Both report formats and ordinary file aliases use the same owner; summary-reader errors and evidence protections remain intact. No new filesystem-attacker guarantees, output formats, options or configuration are introduced.

The original commit by @Alix-007 is retained unchanged. The focused existing-owner implementation needs no additional production repair: production **+24/−13 (net +11)**; test consolidation **+53/−53 (net 0)**; no test-ceiling increase.

## Evidence

[Fresh Linux Node 24.22.1 public CLI comparison, checksums and controls](https://github.com/openclaw/openclaw/pull/186743#issuecomment-6470953745).

Main `e094e4c8ceb6bfe1579d443fb299ddba0b5f9915` and exact candidate `aea4bf87b9734186a2fc150889ed028011cd1138` ran in secretless Docker through the supported source-checkout entry `node scripts/run-node.mjs qa coverage`. The normal source fallback was observed; this is not an installed-release/private-QA-dist claim. Inputs were synthetic completed fixture artifacts constructed and atomically published by the production summary builder/publisher. No model, provider credentials, QA scenario execution or Gateway was needed.

- Two repetitions of same-path, hardlink and symlink collisions in both JSON and Markdown: main corrupts **12/12** inputs; candidate rejects **12/12** and preserves exact SHA-256 bytes plus completed status.
- Distinct-file and stdout-only controls, both formats and repetitions: **8/8 per version** produce valid reports and preserve inputs.
- Running, malformed-JSON and missing-summary controls preserve existing reader errors on both versions.
- Ordinary reports intentionally lack runtime-tool evidence and exit **1 for the coverage verdict while still writing successfully**. Collision protection was judged from error text and independent file hashes, not exit status alone.
- **46 real public CLI invocations** total. Candidate **11/11** focused tests pass (**14.67 s** cold invocation); the same summary-protection regression is red on main because it resolves instead of rejecting the collision. Scoped lint and repository oxfmt/Bun formatter parity pass.

## Merge danger

Two-way door: reverting restores previous output selection; no state migration, schema, public API or configuration changes. Blast radius is coverage-report output collision checks and their shared evidence-input guard. Input byte preservation, valid distinct/stdout output and reader-error precedence are covered; no concurrent-filesystem-attacker rescope is included.
