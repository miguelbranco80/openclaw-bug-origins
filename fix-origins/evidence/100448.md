## Fix PR #183605 description (by ericcurtin, opened 2026-10-25T12:59:53Z)

```text
## What Problem This Solves

Fixes: the browser `close` action reports success while the tab stays open when Chrome acknowledges the request without removing the tab.

## User Impact

User impact: HTTP CDP profiles now report a confirmed close or an actionable error. Confirmation can take up to two seconds. A blocked close preserves the selected tab; an unreadable tab list reports an unknown outcome and asks the caller to check the browser before retrying. Playwright and Chrome MCP close behavior is unchanged.

## Why This Change Was Made

Chrome's `/json/close/<id>` acknowledges the request before the page disappears. The existing close owner now waits for the target to leave discovery before retiring its selection. Thanks to @ericcurtin for the fix and live reproduction.

## Evidence

Two regression cases fail on main `d1470c8514ce8a683c1f189caf7ff7a66b04a2c3` and pass with this fix: an acknowledged close that leaves the tab listed, and a failed listing after acknowledgement. Both used to resolve successfully. The integrated candidate passes all 73 tests across `server-context.tab-selection-state`, `server-context.remote-profile-tab-ops.fallback`, and `routes/tabs`. The post-reboot targeted rerun also passes both regressions. New timing cases use fake timers. Full targeted run: 111.92 seconds wall time on the final candidate, about 2 seconds executing tests; the rest was compilation/startup. Targeted oxfmt and whitespace checks pass. Local oxlint/typecheck refuse the linked worktree installation with the declaration-input-outside-checkout guard; exact-head PR CI covers those checks.

Contributor live proof used `pnpm openclaw browser close` through an isolated Gateway and Chrome 156, with an HTTP CDP pass-through proxy:

| Scenario | Before | After (`fb04fb6`) |
|---|---|---|
| Close acknowledged, target remains listed | `closed tab`, exit 0 (`83fb195`) | Still-open error, exit 1 |
| Close acknowledged, then discovery returns 429 | `closed tab`, exit 0 (`bc627d1`) | Unknown-outcome error, exit 1 |
| Ordinary close | — | Success; target disappears |
| Retry after clearing the blocker | — | Success |

Later contributor commits only changed fake-timer coverage and recovery wording. This live fault-injection proof was not repeated during integration because it requires additional proxy setup. A real page prompt did not keep the tested Chrome version open. Accepted edge: closing the last tab may exit Chrome and report an unknown outcome when discovery becomes unavailable.

Whole-change delta: production +50 lines, tests +124, docs +5. The production growth supplies bounded confirmation and distinguishes a still-open tab from an unreadable result; no existing completion primitive serves this HTTP path.

Final-head CI: [run 40373964024](https://github.com/openclaw/openclaw/actions/runs/40373964024) passed all 58 jobs on `8e7a4fcd5800`. ClawSweeper found no actionable code issues on that head. The security approval guard names `src/gateway/tool-resolution-authority.ts`, which is unchanged from integrated main; that approval remains pending. The separate labeler failed on a GitHub search API 502.
```
