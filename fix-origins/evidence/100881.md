## Fix PR #173201 description (by vincentkoc, opened 2026-10-15T14:32:58Z)

```text
## What Problem This Solves

Updates copy local database images to check engine compatibility even when the target already declares PostgreSQL support. Repeated Git admission checks repeat that unnecessary disk I/O.

## User Impact

Compatible updates skip these redundant database copies. Targets without PostgreSQL support still refuse updates that would strand an installed PostgreSQL store, including retained stores from disabled plugins. No configuration changes or migrations are required.

## Why This Change Was Made

Package validation and both Git admission callbacks already hold the target declaration. Pass that value directly and decide compatibility before discovering physical stores. This removes the internal lazy callback path while preserving downgrade rejection; backup, schema, and integrity checks keep their existing owners.

## Evidence

- Red-to-green boundary proof: original production code made 4 engine-image reads across Git inspection and activation, 1 each for package and staged-package admission, and 2 for repeated Git inspection. The fixed code makes 0 in every case.
- Both focused suites pass: 12 tests, including unsupported/malformed target declarations, SQLite-only state, retained disabled PostgreSQL stores, and inaccessible historical backups.
- Targeted formatting and lint, core typecheck, and the CLI-update and infra test type configurations pass.
- Independent final review found no actionable P0–P2 findings. Production delta: 4 fewer lines.
- Proof ran locally on macOS with Node 26.7.0 and the frozen dependency install after Testbox returned a provider error before the test payload. No live update-duration benchmark or remote-platform proof is claimed.
```

+import { resolveStateDir } from "../config/paths.js";
+import type { OpenClawConfig } from "../config/types.openclaw.js";
+import { UpdatePreMutationError } from "./update-pre-mutation-error.js";
+
+/** The installed driver checks physical stores before candidate database mutation or publication. */
+export async function assertUpdateDatabaseEngineContexts(
+  contexts: readonly { config: OpenClawConfig; env: NodeJS.ProcessEnv }[],
+  readTargetEngines: () => Promise<unknown>,
+): Promise<void> {
+  const { discoverBackupDatabasePaths } = await import("./backup-sqlite-snapshot.js");
+  const { readBackupEngine } = await import("../snapshot/database-backup.js");
+  for (const context of contexts) {
+    const paths = await discoverBackupDatabasePaths({
+      ...context,
+      stateDir: resolveStateDir(context.env),
+    });
+    const postgres = paths.find((pathname) => readBackupEngine(pathname).engine === "postgres");
+    if (!postgres) {
+      continue;
+    }
+    const engines = (await readTargetEngines()) ?? ["sqlite"];
+    if (!Array.isArray(engines) || !engines.includes("postgres")) {
+      throw new UpdatePreMutationError(
+        "database-engine-preflight",
+        `Update refused: the target does not support the PostgreSQL store at ${postgres}. Reverse-port to SQLite with the current binary before updating, or stay on the current version. See https://docs.openclaw.ai/reference/database-engines.`,
+      );
+    }
+  }
