## What Problem This Solves

Fixes Gateway shutdown waiting minutes for a worker-environment teardown during reconciliation, until the service supervisor kills the process.

## User Impact

Shutdown can interrupt Crabbox capture, stop, and checkpoint cleanup, retain their durable recovery state, and retry the same cleanup after restart. Pending replies, terminal persistence, and actual child-process settlement keep their existing drain obligations. There is no schema, configuration, or retention change.

## Why This Change Was Made

The observed pending operation was provider `destroy`, not inspection. Production traces showed it still pending after 219 seconds; another timeout had no active turns or pending owners. Both the earlier inspection cancellation fix (#180841) and cleanup-acceptance change (#182138) were already in the affected build. Crabbox's bounded stop budget is 16 minutes 45 seconds, but reconciliation dropped cancellation before reaching it.

The teardown owner now supplies Gateway lifecycle cancellation for normal, failed-bootstrap, and expired-preparation cleanup, and Crabbox forwards it through its command chain. Explicit turn cancellation still runs compensating cleanup; it does not cancel teardown. The existing provider deadline also aborts destroy. The owner still joins the underlying mutation; a timeout or cancellation does not falsely declare physical teardown complete. The additive optional `destroy.signal` provider contract documents that requirement.

## Evidence

- Core shutdown and provider-timeout regressions fail on unchanged main because destroy receives no cancellation signal. Candidate tests verify interruption, retained identity, reopening the store, and cleanup retry after restart; failed-bootstrap cleanup preserves the original failure.
- Crabbox real-child regressions cover capture, stop, and post-stop checkpoint deletion. Interrupted deletion retains retirement debt, and normal provider maintenance clears it later. All 46 tests in the three focused plugin files pass.
- Existing preserve-only drain and real Gateway-close persistence tests pass. Focused reconciliation/allocation proof: 32/32; provisioning, node provisioning, explicit-cancellation, and lifecycle siblings also exercised. Targeted core typecheck, changed-file lint/format, export collision guard, and 22 closure tests pass. PR CI supplies broad validation.
- Independent subagent review (autoreview route unavailable): addressed cancellation gaps in bootstrap-failure cleanup and post-stop checkpoint retirement; final review clean.

Acceptance declared before the process/load measurements: the real isolated dist Gateway must interrupt a hanging fixture destroy and exit cleanly within a 20-second budget, retain the exact lease, and complete cleanup after restart. Base must reproduce the blocked shutdown. Required Team-shaped load comparison uses the canonical harness, 10-minute arms, two counterbalanced timing and allocation pairs. Report server-side latency and host load, and obtain A/A controls before treating an adverse load metric as a regression.

Runtime code delta: +32 net lines for lifecycle cancellation, the existing deadline abort, and the additive provider contract. No second lifecycle owner or state store was introduced. The separate 340-line script is reproducible process proof.

Real dist-Gateway reproduction passed on base `9db139fcf842` versus candidate `5c33ee10cc36`: baseline remained blocked at the 20,002.5 ms harness deadline and required SIGKILL; candidate aborted provider teardown and exited cleanly in 801.7 ms. This is isolated synthetic process evidence, not a live deployment timing claim.

Both full builds passed; all 281 shared compiled package files are byte-identical between builds.
