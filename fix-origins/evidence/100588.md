Fixes #172123

## What Problem This Solves

Editing a Markdown body with `openclaw path set` can silently discard unrelated multiline descriptions, nested metadata, and comments while reporting success. Frontmatter edits also re-render the body and change its bytes.

## User Impact

Body edits and item/section insertions retain the original frontmatter. Frontmatter edits and insertions retain the body. Untouched source keeps its comments, quoting, key order, blank lines, BOM, LF/CRLF, and final-newline convention. No migration or configuration change is required. Markdown frontmatter remains `---`-delimited; `+++` remains ordinary body text.

## Why This Change Was Made

Replace the lossy whole-file Markdown renderer with source-range edits, using shared line offsets and newline selection extracted from the JSONL preservation fix in #172410. The existing YAML parser identifies the selected frontmatter value's extent without serializing unrelated metadata or removing anchors still referenced by aliases. Preserve the in-memory addressing index across edits: reparsing a literal multiline value as Markdown would create unintended addressable items.

Original fix by @fhgffy; maintainer cleanup completes preservation in both directions, removes the renderer and source-cache invalidation path, strengthens complete-file regressions, and incorporates the merged JSONL and quoted-positional-key repairs.
