## Fix message body

```text
Per-database SQLite admission metadata was never retired, so every new worker inherited it for every database the process had ever opened (41.5 MB after 300 closed databases), and the 64 MiB Code Mode worker ran out of memory before executing. The admission registry now retires a database's facts after its final close or worker exit; open databases keep shared facts and a reopen re-admits. Also fixes a token collision across reopen. Inherited metadata after 300 closes: 2 bytes.
```

## Fix PR #169956 description (by steipete, opened 2026-10-12T14:34:29Z)

```text
## What Problem This Solves

Fixes Code Mode workers running out of memory after a long-running Gateway has opened and closed many databases. Closed SQLite admissions retained full schema and row-write metadata, which every new worker inherited.

## User Impact

Workers can start after hundreds of databases close, using the existing memory limits. Open siblings continue sharing validation facts; reopening after the final connection closes validates again. No migration or operator action is required.

## Why This Change Was Made

The admission registry retires payloads after the final native connection closes or its worker exits. Only the host decides final retirement, because a worker can have an older view of its siblings. Reopening creates a fresh admission; both scoped and unscoped row-cache tokens identify that generation.

The existing open-identity map guards repeated close callbacks. Intermediate handle count changes use the shared cells directly; only a thread's first/final handle publishes and exchanges metadata. Minimal host-owned identity descriptors remain until explicit retirement to preserve SQLite POSIX locks.

Production is +199/-159 lines (net +40), down from net +122 in the first revision. The reduction removes the parallel close-tracking WeakSet and duplicate connection ownership, consolidates generation reads/increments and schema revocation, and unifies the committed/pending scoped-token construction. Tests are +451/-65 lines.

The final reproducer retains zero records (2 serialized bytes); the same worker starts after 300 closes with 21,287,536 bytes of heap, under its unchanged 64 MiB limit.
