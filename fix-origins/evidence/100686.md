## Fix PR #165282 description (by steipete, opened 2026-10-05T02:40:37Z)

```text
## What Problem This Solves

Fixes SDK aliases returning slash-normalized filenames instead of native Windows filenames when plugins call `require.resolve()` under Bun.

## User Impact

Plugin authors get platform-native SDK filenames from native resolution while Jiti keeps its existing alias-map representation. No configuration change or migration is required.

## Why This Change Was Made

The native resolver was returning Jiti's Windows alias spelling directly. Normalize the filename at that adapter boundary, where native resolution owns the result. The regression checks both representations and real `require.resolve()` behavior. Production code remains the same size.

The executable Commander fixtures now release their uncached plugin registries through the CLI invocation owner after command parsing. Those registries retain captured source files and SQLite ownership tokens that must close before Windows fixture deletion. The explicit session case keeps its caller-owned path, asserts that it has no executable invocation resources, and disposes its actual raw registry after the original retention assertions. All six registration cases remain intact.
```
