```text
## What Problem This Solves

The built-in MCP stderr logger copied arbitrary external server output into ordinary debug records. Server stderr can contain message text,tool arguments or tool results; secret redaction does not make that content appropriate for ordinary logs.

## User Impact

Debug logs report stderr activity once per connection under the configured server prefix,without copying server text. The stream continues draining through shutdown. Startup/connection failures,raw transport behavior and explicit SDK collectors with returned failure tails are unchanged.

## Why This Change Was Made

Replace raw per-line/progress/truncation logs with one fixed `stderr output omitted` notice and keep the data-draining listener until disposal detaches it. Delete the now-unnecessary decoder,log tail buffer,line splitting,progress timer,final flush and callback bookkeeping. No per-module redactor or new instrumentation.

Update the narrow troubleshooting paragraph. Retain forced-disposal ownership and actual-child shutdown privacy proof with synthetic message/tool markers; delete only tests of retired raw-log buffering/progress behavior and a redundant same-path mapping case.

## Best-effort tradeoffs accepted

- Raw stderr prose and repeated progress/truncation markers are intentionally unavailable in ordinary logs. The privacy rule takes precedence over the old diagnostic-text promise introduced by #110652; one fixed activity notice and existing startup/connection failure owners remain. That feature had an operator consumer; no human production incident or speculative-guard provenance is invented.
- No UTF-8 decoding,8KiB log buffer or250ms logging timer remains because stderr text is no longer logged. This removes diagnostic formatting machinery,not the raw transport/explicit SDK collector resource bounds,authorization or shutdown settlement.
```
