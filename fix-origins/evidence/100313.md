## What problem this solves

A small schema migration currently copies and validates the entire database for rollback. A measured 38 GB deployment snapshot spends about 514 seconds validating the backup and 36 seconds copying it, although agent v27 changes only the outbox and planner statistics.

Doctor now finishes each fully declared version phase before broader maintenance. Eligible agent v26→v27 and shared-state v22→v23 migrations can therefore use a table-scoped rollback archive. Installed updater drivers retain their full-file checkpoint contract, and every selected source still receives integrity admission before its checkpoint.

## What changed

The agent version runner separates the declared outbox/statistics migration from later startup-column/index repair, session normalization, orphan recovery, transcript repairs, historical media/directives, ACP accounting, and plugin maintenance. Those later operations retain their existing transactions and preserving repair owners. Retained-content rewrites preserve their original image only when an actual rewrite is needed. Older SQLite versions use bounded `ANALYZE` for statistics refresh through the existing statistics owner.

The automated-review P2 is fixed: version-phase receipts contain only admitted agent targets. A real preflight regression produces an older database that is both pending and indeterminate; before the fix it throws `Missing discovered agent migration target`. The fixed path returns no receipt for that excluded database and leaves it at v26.

Main is merged through R9 (#172755, `c58d6181af08`). Its shared-state v23 declaration remains exactly `["meeting_transcript_sessions"]`; the resolver adds `schema_meta` and `config_machine_state`. The state version phase runs before agent maintenance leases can open shared state. Unrelated index repair, orphan recovery, quarantine cleanup, and full runtime-shape admission remain with later Doctor maintenance. Scoped restoration preserves current undeclared planner statistics with the archive's existing byte-preserving row codec, including raw text bytes, bigint rowids, and later `ANALYZE` results. Explicitly declared statistics retain archive-restore semantics. No migration declaration, schema number, retention policy, or public API is changed by this PR.

The declared phase reuses integrity admission under the same offline Doctor custody; it adds no foreign-write polling. Recording backup completion after commit is best effort: failure emits a warning and leaves the original image protected.
