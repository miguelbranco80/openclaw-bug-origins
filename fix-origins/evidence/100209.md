## Fix message body

```text
Calling a direct-only tool through `tool_call` used to return "Unknown tool id… Use tool_search", which the model could not recover from: `tool_search` never lists direct-only tools. `tool_call` now recognizes a direct-only tool the model can see this turn and replies with a short fixed instruction to call that tool directly by name. The model then calls it successfully. `tool_call` still refuses direct-only tools that aren't visible this turn, catalog tools run unchanged, and unknown IDs still get the catalog-miss hint.

Fixes #161022. Reported by @jgs-jeeves.

Proof: real agent turns with a scripted model and a local plugin registering a direct-only tool. The old build hit the dead end; this build returned the direct-call guidance, and the next turn invoked the tool successfully. 130 Tool Search tests and 9 prompt-policy tests pass.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```

## Fix PR #161055 description (by obviyus, opened 2026-09-29T07:14:40Z)

```text
Closes #161022

## What Problem This Solves

Fixes: agents are sent into an impossible Tool Search recovery loop when they mistakenly call a visible direct-only tool through `tool_call`.

## User Impact

The agent now receives a short instruction to call the already-declared tool directly, rather than searching a catalog that intentionally excludes it. There are no configuration changes or expanded tool permissions.

## Why This Change Was Made

Direct-only tools remain outside the catalog. The bridge tracks only direct-only names declared for the current turn, including prompt-hook restrictions, and returns fixed recovery guidance without executing them. Catalog calls and unknown-tool errors are unchanged.

Thanks to @jgs-jeeves for the report and per-turn tool manifest.

## Evidence

- Real `pnpm openclaw agent --local` turn using a scripted model and a local plugin: baseline returned the unrecoverable search hint for visible `watcher_search`; candidate tells the model to call it directly, and the subsequent direct invocation succeeds.
- Same before/after flow: catalog tool execution succeeds; an unknown ID and a policy-hidden direct-only tool retain the ordinary catalog-miss hint.
- Focused `src/agents/tool-search.test.ts`: 130 passed, 32.22s measured duration, including hide/restore through the production prompt-build helper. That regression failed before the baseline-preservation correction and passed afterward.
- `attempt-prompt-tool-policy.test.ts`: 9 passed, 13.51s. Combined command wall time: 49.32s.
```

```diff
+        allowedToolNames: new Set(allowedEntries.map((entry) => entry.name)),

+      const tools = baselineTools.filter((tool) => {

+        tools,
+        callableToolNames: normalizeUniqueStringEntries([
```
