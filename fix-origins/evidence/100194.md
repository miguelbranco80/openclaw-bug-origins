## Fix PR #184033 description (by MarMarLabs, opened 2026-10-26T01:13:55Z)

```text
Closes #184032

## What Problem This Solves

Fixes: the Gateway can stay alive after shutdown when a restart overtakes a slow Discord startup and leaves its socket open.

## User Impact

Failed startup now releases its Discord connection so shutdown can finish. No configuration change or migration is required.

## Why This Change Was Made

The startup producer owns the gateway until it returns successfully. If registration or presence setup fails, it disconnects the gateway and disposes any supervisor, preserving the original error even if cleanup fails. Successful startup keeps its existing lifecycle ownership.

Thanks to @MarMarLabs for the fix and live reproduction.

## Evidence

- On main `584e043803862a1df0b7765d76f495058f10329d`, both new regressions fail: a real closed scheduler after delayed registration leaves the gateway/supervisor unreleased, and a registration failure never disconnects. Four existing tests pass.
- With the fix, all 36 tests across startup, auto-presence, gateway supervision, and provider lifecycle pass. Wrapper wall time: 93.80 seconds; the two regressions take 14 ms and 4 ms.
- Focused boundary lint, formatting, and whitespace checks pass. Full typed extension lint cannot prepare declarations from this shared worktree installation; PR CI supplies that coverage.
- Independent review found no actionable P0–P2 issues. The integrated startup file also passed all 6 tests (86.62 seconds wrapper wall).
- Production +23 lines; tests +35 lines against integrated main. Independent cleanup attempts need the extra production code. Two distinct regressions replace the original four-case addition.
- The contributor's built-Gateway loopback proof below observed a leaked socket on base and normal shutdown on the fix. No fresh built-Gateway or real Discord round trip was run: rebuilding the stand-in setup exceeds the bounded live-proof budget, and QA broker credentials are unavailable.
