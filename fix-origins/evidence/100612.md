## What Problem This Solves

`mcp add` silently trims quoted executable and working-directory paths. This can make a valid executable disappear or select a different directory.

## User Impact

MCP servers retain the exact executable and directory paths supplied by the operator. Whitespace-only commands remain rejected, and HTTP flags keep their existing normalization.

## Why This Change Was Made

Use the existing `readNonBlankString` helper at the flag adapter, matching the stdio runtime and JSON configuration contracts. Inline the single-use probe condition to keep the production file smaller. No migration or new option is needed.

Thanks @Alix-007 for the original fix and regression coverage. Contributor commits are preserved by merging current `main` into the branch.

- On integrated head `a369cdde8358`, the same four focused cases passed again: Vitest 160.63s, complete runner 441.38s. Initial worker compilation required restoring existing workspace dependency links; that setup attempt ran no tests, and no dependencies were installed or changed.

- Change against `main`: production +4/-5 (net -1), tests +19, documentation +1.
- The baseline full MCP CLI suite also exposed an existing 10-second real-probe timeout and a following mock-log count failure on this heavily loaded host. These occurred before production edits; no assertions or timeouts were weakened.
- Live gap: a fresh real MCP child-process round-trip was not run because the existing real-probe test timed out on this heavily loaded host. Focused CLI-handler persistence/readback proof covers the changed adapter; exact-head PR CI supplies broader validation.
