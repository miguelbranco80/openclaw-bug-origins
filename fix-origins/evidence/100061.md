```text
## What Problem This Solves

Fixes chats remaining “Waiting for turn to start” after a Gateway restart restores a completion batch whose child executions have been superseded.

## User Impact

New messages can start without being parked indefinitely behind an obsolete, unprepared completion reservation. A mixed batch can still deliver its current children's findings, and cancelled children that have not been superseded still report their outcome.

## Why This Change Was Made

Restoration could reserve the full frozen completion cohort, while live preparation used the filtered findings list to revalidate that same cohort. An obsolete member made preparation return before adopting the reservation, leaving later inputs blocked in FIFO even with no active execution.

Use the existing current-cohort predicate before reserving wholly obsolete batches. Keep full-cohort identity and durable outcome custody separate from findings selection, quietly complete batches with no eligible findings, and recheck selected findings before effects. The existing completion-finalization composition moves into the adjacent state module to keep the dispatcher within its existing size limit.

Messaging policy, execution authority, schemas, and stored formats are unchanged. This is a follow-up bug fix to the lifecycle consolidation merged in #177698, independent of the outstanding policy proposals.
