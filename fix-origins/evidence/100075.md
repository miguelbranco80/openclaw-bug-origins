## What Problem This Solves

The managed Codex runtime still uses 0.158.0, whose bundled `model/list` catalog does not include GPT-6.1 Sol. Updating a separately installed CLI does not update the runtime selected by the official Codex plugin.

## Why This Change Was Made

Upgrade the managed CLI to [Codex 0.159.1](https://github.com/openai/codex/releases/tag/rust-v0.159.1), which adds GPT-6.1 Sol to its bundled catalog. Keep the managed version, ACP adapter override, OpenAI catalog client-version hint, native binary expectations, and generated dependency lock aligned. Refresh the harness documentation from the new runtime's actual `model/list` response and regenerate the protocol schemas so new terminal errors, including strict Guardian `tooManyDenials`, complete normally instead of timing out.

This complements #161400, which handles GPT-6.1 Sol provider metadata and request capabilities without changing the managed CLI dependency.

## User Impact

Accounts with access can discover GPT-6.1 Sol through the updated native runtime, including its advertised low, medium, high, xhigh, max, and ultra effort choices and priority/Fast tier. Full GPT-6.1 Sol routing also needs the provider metadata change in #161400; the CLI update alone does not supply those OpenClaw route facts. Catalog membership does not grant account access. Existing configured model selections and the external-runtime compatibility floor remain unchanged.
