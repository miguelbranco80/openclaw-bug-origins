## Fix PR #179233 description (by steipete, opened 2026-10-21T07:32:06Z)

```text
## What Problem This Solves

The degenerate tool-call guard from #177659 aborts a Responses tool-call argument stream after 32 KiB of consecutive whitespace. Live, a sub-agent's runaway argument stream emitted about 100 whitespace characters per second. Its last real progress was at 06:13:16 and the guard fired at 06:18:41, so the run stalled for 325 s and was saved only about 35 s before the 360 s session watchdog.

## User Impact

Runaway Responses tool-call whitespace now aborts in about 40 s and goes through the existing bounded retry, while large arguments with ordinary indentation remain unaffected.

## Why This Change Was Made

The limit is now 4 KiB. Tool-call arguments are JSON text, where newlines inside strings are escaped, so real whitespace runs (indentation and spacing) stay far below 4 KiB. The same runaway now aborts in about 40 s and goes through the same bounded retry. `docs/concepts/retry.md` is updated.

## Evidence

`openai-responses-client.terminal-error.test.ts`: the churn case now aborts after 4 deltas of 1 KiB (red on base, where it expected 32), and the file passes 17/17 (run on the Crabbox host). The existing "accepts 200 KiB of arguments with whitespace runs interrupted by code" case, which uses 1,023-space runs, still passes, so real large arguments are unaffected. oxfmt, oxlint and the line-cap ratchet are clean.
```
