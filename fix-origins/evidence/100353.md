```text
Closes #160149. Related: #129423 and #115904. Thanks @neyudo for the precise report.

## What Problem This Solves

Fixes already-compacted conversation reappearing in later summaries when a tool-only preparation cuts before the previous compaction's physical marker.

## User Impact

Long-running sessions keep previously compacted conversation out of new summarization requests. Stored transcript entries remain intact; no configuration, schema, or provider API changes are required.

## Why This Change Was Made

The fallback previously sliced away a compaction marker before asking the core context projector to enforce its replay boundary. Preserve reset and compaction markers while restricting message entries to the prepared range, so the existing core projector remains the boundary owner. Normal prepared-message summarization is unchanged.

## Evidence

- Seeded a real SQLite session through the supported SessionManager test surface, installed the production safeguard extension and a capturing CompactionProvider, and triggered real AgentSession.compact(). This is a session-runtime test, not a Gateway/CLI run.
- On base `3b8ed47b09e61e165ac7ac95e1a03a379d791609`, the fallback ran with the new first-kept entry at index 3, before the previous physical compaction marker, and the provider received the old `Tetris` user message. The regression failed on that input.
- The same candidate flow passed only the expected retained tool-call/result pair to the provider. Exact transcript storage rows remained unchanged except for the appended compaction, and SQLite `user_version` was unchanged.
- Focused session-compaction, boundary, and safeguard suites: 174 tests passed in 39.85 seconds including runner preparation. The boundary regression ran in 1.553 seconds in the agents-support lane. Existing normal summarization and #129423 bounded recovery controls passed.
- The regression lives in `agent-session-compaction-boundary.test.ts` to keep the existing suite within its lint line limit. Scoped Oxfmt and Oxlint checks passed for the changed files. No project-wide checks were run locally.
```
