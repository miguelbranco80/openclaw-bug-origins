## Fix PR #154568 description (by steipete, opened 2026-09-21T07:32:19Z)

```text
## What Problem This Solves

Repeated model-catalog preparation across plugin configuration revisions retains every previous worker generation, causing heap growth in long-running multi-agent Gateways.

## User Impact

Superseded catalog registrations can be collected while the current generation remains usable. Catalog contents, authentication behavior, source-generation checks, and stored data are unchanged. Both catalog-worker host paths request a 512 MiB V8 old-generation limit. Explicit process-wide heap flags override that limit, and native/external allocations are outside it; large real-provider working sets remain unverified. Maintainer decision: retain this selected catalog-specific budget under the explicit instruction to add a sized limit for these workers; the capacity tradeoff is accepted separately from the retention proof.

## Why This Change Was Made

Heap retainer inspection found two independent roots. The worker's cached registry loader left disposed instances in the process plugin cache. Its inline release closure also captured the request's `previous` generation, linking the current generation to every predecessor. Moving release creation to module scope and unlinking successfully disposed instances from their birth inventories removes both roots. The plugin cache owns insertion/removal bookkeeping; the instance lifecycle releases custody only after physical cleanup succeeds. Active, adopted, draining, and failed instances retain their existing ownership guarantees. The original cached loader remains in place so unchanged agents share one source graph. The worker still retains only its current prepared generation, with predecessor/successor overlap during replacement; no new catalog cache or configuration surface is introduced.

This complements #154408's generic worker idle-GC and pressure-retirement work. It does not change generic worker lifecycle code. No schema, persistence, update, or rollback changes are needed.
```
