## What Problem This Solves

Fixes missing assistant commentary when a small history page splits the display fragments of one stored transcript row.

## User Impact

Complete source-row groups remain reachable when opening and paging history. Ordinary tail and numeric-offset pages can now return directional history cursors, allowing clients to continue through bounded pages without reopening an anchor.

The requested message count is a soft target, including on the initial tail: a complete source group may exceed it. The existing response byte budget and fetchable oversized-message references still apply. Existing numeric pagination remains available.

## Why This Change Was Made

The initial-tail count cap could return only the final fragment of an assistant row, while `nextOffset` skipped that entire stored row. Reuse the existing source-group pagination policy for both head and offset admission, removing the separate adjacent-only offset cap and strict head slice. Record consumed message endpoints before display filtering and carry those primitive facts into the existing cursor owner; hidden pages can then make progress without retaining another raw-message array.

Native cursor identity, current sharing checks, retained reset intervals, active-leaf and delta metadata remain governed by their existing owners. Claude CLI paging keeps its injected sequence resolver and source-reset semantics. No schema, config or runtime adapter changes.
