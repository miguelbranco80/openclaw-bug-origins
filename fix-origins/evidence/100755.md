## Fix PR #148583 description (by steipete, opened 2026-09-14T22:43:39Z)

```text
## What Problem This Solves

Cold media status, prompt, and duplicate lookups could block on configuration state when a restored task lacked a recorded requester, or lose that task while preparing requester facts.

## User Impact

Restored media tasks remain visible to their requester, completed or failed tasks produce the correct duplicate decision, and requester preparation uses the existing asynchronous config owner. A configuration-source change during the lookup rejects the interrupted lookup instead of returning missing or stale requester facts. Ordinary same-source config reloads preserve the captured snapshot. No schema, retention, provider, permission, or update migration changes are required.

## Why This Change Was Made

One preparation serves all enabled media prompt sections. Recorded identities and agent-scoped session keys avoid config loading; terminal-only status and prompt reads do too. After config preparation succeeds or fails, the lookup refreshes task rows and rechecks the captured owners before selection. The shared config reader exposes its existing source-currentness check so callers can retain it across subsequent awaits without duplicating selector policy.
```
