```text
Related: #174278

## What Problem This Solves

Fixes misleading “Session delivery endpoint was replaced” warnings and blocked-delivery notices after restart when an accepted peer input belongs to otherwise unchanged archived sessions.

## User Impact

Archiving either endpoint still prevents automatic execution. Recovery retains a cancelled input receipt without adding an interruption notice. Actual session resets or replacements still block replay and record a durable notice; permission and storage failures retain their existing behavior.

## Why This Change Was Made

The endpoint check treated `archivedAt` as an identity mismatch. Recovery now checks both exact endpoint identities first, then settles archive cancellation through the existing pending-input withdrawal owner. Debug diagnostics use `endpoint-archived`; replacement warnings use `endpoint-replaced`. This follows the existing archive contract in the session-tool docs rather than reviving archived work.

No schema, configuration, or public API changes. Production delta: +13/-3 lines (+10 net), needed to separate expected archive cancellation from genuine replacement while reusing the existing persistence owner. The archived path removes notice construction and the transcript report write; no additional cache or settlement owner.
```
