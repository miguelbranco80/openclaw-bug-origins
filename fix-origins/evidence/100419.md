## What Problem This Solves

Removes the new provider-owner sort suppression introduced by #172481, which contributes to the production lint-suppression guard failure.

## User Impact

No user-visible change. Provider ownership keeps deterministic alphabetical order, provider-over-CLI precedence, shared frozen results, and independent registry generations.

## Why This Change Was Made

Use `toSorted` with the existing comparator, freeze the resulting array, and install it under the same map key before publication. The extra copy happens only during first index construction; cached lookups are unchanged. No suppression allowlist or assertion changes.

The separate deadcode cleanup is already covered by ready #172574; this PR does not duplicate it.

## Evidence

- Existing provider ownership tests: 4/4 generation/immutability cases and 16/16 provider-resolution siblings pass.
- Targeted strict production typecheck, typed lint, formatting and diff checks pass. Independent P2 review has no actionable findings.
- Suppression guard: baseline 95 entries versus 92 allowed; this change reduces it to 94. Its two remaining unlisted summaries are in unchanged `src/agents/mcp-event-request.ts`. The other two suppression tests pass. No passing aggregate suppression claim.
- Local production Knip reproduces the assigned stale exports covered by #172574, plus an unused `renderCopyButton` export and six generated Mermaid files. The all-exports scan reproduces the retired Lit helpers. These findings are outside this one-file change; exact-head PR CI remains the broad proof.
