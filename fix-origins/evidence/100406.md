## Fix message body

```text
fix(backup): give each SQLite header probe batch its own deadline

backup create sent every path in the state directory to one SQLite header-probe child with a fixed 10 s timeout. Probe time grows with the file count, so a state directory with a few hundred thousand files (for example agent worktrees) timed out and the backup aborted with a generic error, even though every file was readable. Paths are now probed in bounded batches, each with its own deadline, and a probe failure names its underlying cause. SQLite classification and the backup format are unchanged.

Evidence: built Linux CLI with a state directory of 2,502,506 real text files plus a real SQLite database. On main, one child probed every path, hit the 10 s ETIMEDOUT and published no archive (twice); with this change 611 children probed at most 4,096 paths each, and both archives passed a standalone backup verify of all 2,502,506 entries, including the SQLite inventory (twice). Small-state controls pass on both refs, and the SQLite file is detected in every run. Details: https://github.com/openclaw/openclaw/pull/187197#issuecomment-6489064098.

Thanks @wr-web.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```

## What Problem This Solves

`openclaw backup create` sends every state-directory path to one isolated SQLite header-probe child with a fixed 10-second deadline. For sufficiently large state directories, the child times out and the backup aborts even though the files are readable.

Bound the existing child's workload to 4,096 paths per invocation, giving each batch the same existing 10-second deadline. Keep deduplication, result validation, worker-process isolation and fail-closed behavior at the existing owner. The original wr-web commit is preserved.

## User Impact

Large state directories can complete backup creation without a file-count-dependent single-child timeout. Backup format, source selection, SQLite classification, snapshot handling, error-message policy and per-child limits remain unchanged. A failed batch still aborts before archive publication.

## Simplification

Final merge-base delta: **production +34/−26 (60 changed lines, down from 75); tests +7/−8 (net −1)**.

## Merge danger

Two-way door: reverting restores the previous probe scheduling without a migration. No backup-format or storage-policy change. Blast radius is SQLite header discovery during backup preparation; partial or failed probe batches still fail closed before an archive is published.
