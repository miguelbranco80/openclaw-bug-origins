## Fix PR #179379 description (by steipete, opened 2026-10-21T10:34:38Z)

```text
## What Problem This Solves

Fixes wide Markdown tables clipping their first columns when a saved percentage reading width is restored and desktop Details opens.

## User Impact

Tables stay inside the conversation's available space in LTR, RTL, and split panes. The scrollbar stays at the pane edge, and dense tables retain horizontal scrolling.

## Why This Change Was Made

The scrollbar layout in #179059 extends the transcript through the Details gutter. Table expansion still treated that reserved gutter as spare space on both sides of the reading column. Pass the desktop reservation into the existing CSS calculation; no new observer or layout loop is needed. The existing regression now reports each table's containment and column state while requiring both tables.

## Evidence

- Reproduced the original failure on hourly head `94e1fbf31a13`, its parent `63aad5a11f4f`, and main. At 1920 px, the wide table extended 75.27 px beyond the pane while its published column width was current.
- Removing only the reservation calculation reproduces the containment failure; restoring it passes without changing any geometry budget, timeout, or retry policy.
- Native bundled UI E2E: all 16 cases across Markdown-table interactions, message-width settings, content copy, and Details-scrollbar scenarios passed (56.21 s test invocation). Final table file: 11/11 passed, 27.07 s file time, 70.74 s invocation including the production UI build under local load. CI timing is pending.
- Matching UI E2E and extensions test typecheck leaves, targeted TypeScript/CSS lint, format, docs MDX check, and `git diff --check` passed. Independent review found no actionable P0–P2 issues.
- The separate automation-management failure reproduces before provider execution and is handed to its admission-repair owner; it is not changed here. PR CI supplies broad proof. No CI was dispatched or rerun.
```
