## Fix PR #169853 description (by steipete, opened 2026-10-12T11:03:45Z)

```text
## What Problem This Solves

Session-list refreshes reread entry, participant, and summary-watermark facts that the Gateway already received from the same committed write.

## User Impact

Session rows reuse committed facts during transcript updates and entry snapshot enrichment, reducing repeated worker reads without changing stored data, permissions, schema, or update behavior.

## Why This Change Was Made

The entry publisher compared a process-wide transcript notification counter before exposing a receipt. Installing a combined entry/transcript receipt advances that counter itself, so the publisher could discard its own current watermark. The row projection separately correlated display notifications with another retained transcript-authority object. Message-less or delayed notifications therefore discarded usable facts.

Use the existing receipt owner: remove both global-counter comparisons and the duplicate notification authority, and retain the actor's Board/summary projection when entry reads add snapshot fields. Starting a new actor command also keeps the previous committed snapshot until a write changes its token; a stale reader evicts that snapshot without canceling the pending command's fresh receipt. Entry, participant display, and watermark facts remain covered by the same committed-write token. Physical source binding, keyed receipt supersession, membership revocation, and current authority at real effects remain enforced. No new cache, SQL, fencing, or worker handshake is introduced.

Removed checks and accepted edges:

- Process-wide transcript-counter capture/rechecks: an unrelated session notification no longer discards this row's receipt. Gateway writes remain ordered through receipt installation; unsupported reentrant native writes from a delivery callback may briefly retain earlier display facts until the writer publishes.
- Notification session/lifecycle/message/sequence correlation and duplicate `Row.transcriptAuthority`: a delayed or message-less notification may schedule an unnecessary refresh of the current row. Notifications never supply the stored watermark.
- Eager replica eviction at command start: readers may observe the preceding committed snapshot while the next command awaits execution, just as a database snapshot read would. The existing write token rejects it after commit; effectful commands still validate current worker-owned state. Stale-read eviction no longer revokes the pending receipt.

Writer coverage remains with existing receipts/tokens: entry create/update/snapshots, aliases/reset/delete; owner/member/participant changes including count-only participant writes; Board changes; native session deletion; append/bulk/rewrite/import/suffix/compaction; cold archive/restore and projection rebuild; window/cascade deletion; raw fixture clears. Scoped writes invalidate the affected key/session; unscoped DML advances the token shared by every scope. Unknown outcomes revoke facts. The change preserves only previously current projection facts; it does not carry an old watermark across a new metadata-write token.

Related: #169748. Reuses the projection-watermark idiom from #169753 without changing its reply-tail implementation.
```
