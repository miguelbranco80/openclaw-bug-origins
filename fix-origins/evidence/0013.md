## Fix PR #199402 description (by roboclaw-bot, opened 2026-11-15T03:14:47Z)

```text
## What Problem This Solves

Fixes: a plugin’s Permissions section keeps looking busy after its inspection request has failed, even though other settings are already usable.

## User Impact

User impact: the finished failure no longer shows a loading skeleton or claims that unknown permissions mean there are no settings. The real error and Try again remain. Existing settings stay usable, and confirmed permission controls return after retry. No grants, authorization or configuration writes change.

## Why This Change Was Made

The view previously treated missing inspection as permanent loading. It now derives pending state from the existing inspection read and carries the accepted-data distinction into the editor’s empty-state decision. This also avoids replacing the misleading skeleton with misleading “no configurable settings” guidance for plugins that only expose permission settings.

Actual compiled Control UI with a supported synthetic Gateway, light theme, 1280×1200 desktop. The inspected, annotated 900×900 crops preserve the error, existing settings and affected Permissions region. No live plugin operation or permission change occurred.
```
