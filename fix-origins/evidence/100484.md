## User Impact

Sandboxed Bun runtimes can reuse an existing Codex login without allowing `ps` execution. Setup keeps detection and inspection failures visible. Genuine absence, sign-in-required behavior, and fallback after ordinary model failures remain covered. Shipped v2026.10.4 contains the old snapshot path, so existing users under rejecting sandboxes are affected. No credential migration or proc-safe release is needed.

## Why This Change Was Made

One core Darwin owner now supplies Codex snapshots and process-group census through the documented `openclaw/plugin-sdk/process-runtime` contract. Bun uses libproc for topology/start identity and the pinned proc-safe reader for arguments. Node has no FFI and the pinned package has no Darwin census API, so Node retains bounded `ps` inspection and its topology-only group projection. Normalized UTC start identities remain compatible with persisted Codex registrations.

Darwin restricts full start-time records across UIDs. Collect complete short-record topology, then read full identities only for relevant Codex roots/descendants and the observer. Relevant denials stay errors. The retained PR-tooling inventory includes the new core dependency.
