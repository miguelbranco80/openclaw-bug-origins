## Fix PR #169629 description (by steipete, opened 2026-10-12T05:22:13Z)

```text
## What Problem This Solves

Fixes: extension commands report a normal result after cancellation even when forced cleanup fails and a descendant remains alive.

## User Impact

Extension callers now receive the existing `CommandProcessCleanupError` when command cleanup is uncertain. Captured output and the root command's exit result remain available in the error's cause. Successful cleanup, cancellation, output limits, and bounded startup behavior keep their existing results.

## Why This Change Was Made

The termination owner already records whether cleanup succeeded, but extension exec discarded that verdict. Await the owner's settlement directly and propagate its canonical cleanup error. The async completion path replaces the nested completion promise and callback chain, reducing production code by two lines without adding a result schema, configuration, or retry policy.

## Evidence

The Linux regression invokes real `ExtensionAPI.exec` through the extension factory/runtime. A real root command spawns a real descendant; the test denies only the exact owned group's forced stop, then verifies actual descendant and group liveness. The baseline returned a normal result while that group remained alive. The repaired path rejects with the canonical cleanup error and preserves captured output in its cause. A positive control verifies successful forced cleanup. Each case independently restores signalling and cleans its own process group before completing.

The baseline failed as expected before the production edit: one failed case, 404 ms test time, 62.03 s command wall time. The repaired focused command passed all 19 cases across the native API test and existing exec-command controls:

```sh

```

The tests use a Date-only fake clock to cross the existing cleanup budget while native timers, signals, exits, and liveness checks remain real. Native proof is Linux-specific.

Formatting, conflict markers, staged line-cap/max-lines/environment/assertion/database/test-fixture ratchets, import-cycle checks, and diff checks passed. Hosted CI seconds remain pending.
