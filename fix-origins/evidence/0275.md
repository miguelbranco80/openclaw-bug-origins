## Fix PR #202902 description (by steipete, opened 2026-11-21T03:24:19Z)

```text
## What Problem This Solves

A new chat can spend ten seconds rediscovering tools from an MCP server that was already discovered successfully. An unresponsive catalog request blocks the first model request, even when healthy servers have already answered.

## User Impact

New chats, subagents, and Code Mode can immediately use a previously discovered MCP catalog while it refreshes in the background. Later turns receive successful catalog changes. A never-discovered server still uses the existing bounded listing deadline; its existing typed failure is included in the current model turn and remains visible in the tool inventory. Calls to unavailable servers retain the existing tool-error behavior and recovery guidance.

## Why This Change Was Made

Lead decision by the Team perf-loop lead (an agent acting under Peter's standing unattended instruction), not Peter's.

Keep successful catalogs in the existing bundle-MCP manager, bounded by its existing runtime limit and keyed by server configuration, endpoint, and auth scope. Unchanged config reloads retain these facts; manager disposal clears them. Existing per-server concurrency and listing deadlines stay unchanged. Native capability-bound discovery remains private. No new configuration, persistent cache, or production schema change.

The tradeoff is intentional: a turn may advertise the last successful schema while refresh is pending. That turn's catalog remains stable; refreshed schemas apply to later turns. A ready connection can execute a known tool without waiting for catalog refresh. Catalog recovery moves out of send preparation while existing transport-specific tool-call recovery remains. Production source grows by 54 lines to retain bounded identity-scoped facts and expose existing diagnostics; the runtime module itself shrinks by one line.

Related overlap: #137594. This does not depend on that PR or add its Tool Search diagnostics; it uses the existing catalog diagnostic type.
```
