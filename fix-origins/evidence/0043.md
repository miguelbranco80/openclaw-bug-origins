## Fix PR #199368 description (by roboclaw-bot, opened 2026-11-15T01:36:48Z)

```text
## What Problem This Solves

Fixes: Profile’s GitHub help incorrectly says agents always use the shared account and all cloud work must return to the current computer before personal publication.

## User Impact

User impact: the help now respects each agent’s own or inherited GitHub account and does not tell users to move work unnecessarily when a repository checkpoint already supports publication. Personal publishing still requires an explicit choice, session write access and finished, accepted work.

This is a copy-only correction. Credentials, permissions, publication eligibility and cloud-work recovery are unchanged.

## Why This Change Was Made

The account owner prefers an agent override before the shared account. Personal publication supports accepted repository-only checkpoints without a Gateway checkout; remote work sourced from a Gateway checkout retains its separate stop/reconciliation requirement. The general Profile explanation should not impose the latter restriction on every cloud session or confuse the browser computer with the Gateway.

One canonical English paragraph is shortened. The specific account explanations above it and the existing per-session publication guidance remain the owners of those details. No new controls, state, helpers or compatibility paths are added.

## Evidence

- Maintainer validation: the existing full built-app Chromium personal-account flow passed before (13.97s) and after (12.25s) removing four redundant copy assertions. The final diff changes only the English help paragraph; it adds no permanent tests. It opens and closes the real help, copies a synthetic device code, connects the personal fixture and disconnects it without changing the shared account or configuration. No live GitHub sign-in or external publication is exercised by the test.
- Original implementation verification: 61 focused GitHub UI/controller tests passed. Six selected backend contracts pass: agent-override precedence, selected-versus-effective identity, personal repository-checkpoint publication, and three busy/local-worktree refusal states. These are selected tests, not full backend suites.
- UI typecheck, scoped lint, i18n verification, formatting and diff checks pass. An initial backend proof invocation was invalidated because I edited the locale during its compilation; it ran no tests. The source was then held stable and the selected tests passed. No broad CI or E2E matrix was run.
```
