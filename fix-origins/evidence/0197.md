## Fix PR #191348 description (by steipete, opened 2026-11-02T17:47:50Z)

```text
Related: #188978

## What Problem This Solves

Fixes: `openclaw update` rolls back the whole core update when one managed npm plugin is damaged (its install directory exists but `package.json` is missing).

## User Impact

User impact: a damaged plugin no longer blocks core updates. The core update proceeds, the damaged plugin keeps its install record, and the next update (or plugin repair) can restore it. If the core update has to roll back, rollback restores that plugin directory exactly as it was. Not yet in a release: #188978 is only on main.

## Why This Change Was Made

#188978 added a plugin-cohort preimage that records every prior npm plugin's directory identity plus a SHA-256 of its `package.json` before the core package swap. Reading a missing `package.json` threw `ENOENT`, which failed `package-swap`, so the core update rolled back and the update reported failure. The main `update-corrupt-plugin` Docker lane has failed deterministically since then ("Unavailable plugin target blocked the core update").

Prior-artifact identities now record a `null` manifest digest when `package.json` is missing. The directory identity (dev, ino, realPath) is still recorded and checked, so rollback restores that exact damaged state and refuses if it changed. Artifacts the update stages or publishes keep the strict reader: a missing `package.json` there still throws `ENOENT`, which `beforePublication` already treats as an unpublished target. A missing directory is still the only absent baseline. A dangling-symlink `installPath` stays an error, as before.

Accepted edge case: if a later step repairs the damaged plugin in place and the core update then rolls back, rollback sees the manifest changed and leaves cohort recovery for `openclaw update repair`. It does not overwrite the repaired plugin.

## Evidence

- **Regression test:** `src/plugins/update-cohort-recovery.test.ts` › "keeps a damaged npm payload without package.json as its rollback baseline".
  - Red on base with the production error: `ENOENT ... cohort-fixture/package.json` at `readPluginCohortArtifactIdentity` via `beginUpdatePluginCohort`.
  - Green on head: rollback restores the original record and leaves the damaged directory untouched.
- **Neighboring suites:** cohort recovery/records/commit/handoff, update plugin persistence, install transaction, server restart update run, repair package activation, Doctor delegation and plugin peer link all pass locally.
- **Checks:** `pnpm tsgo:core` and the plugins test typecheck shard are clean. Changed files are formatted and linted.
- **Lane on base:** control run 41474947350 on `ed2def8f795` failed the `update-corrupt-plugin` lane. `package-swap` failed with `ENOENT` at `update-run-recovery-store` (`readPluginCohortArtifactIdentity`), then rolled back.
- **Lane on head:** pinned rerun with `workflow_ref` equal to `package_ref`; result is in the comments below.
- **Reviews:**
  - `$autoreview` (Codex) is scoped-clean.
  - The independent Codex review found two P2 issues, both fixed: a dangling-symlink baseline regression and nullable fixture identities in test types.
```
