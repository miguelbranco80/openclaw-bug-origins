```text
fix(ui): show the selected tab when opening the browser focus page cold

Fixes #187645.

Opening the browser focus page directly (for example from the mobile app) showed "Couldn't load browser: This tab is no longer available" instead of the selected startup tab, because the focus page did not pass the selected tab through the existing referenced-tabs API the way the chat panel does. It now passes it, so the selected tab shows. When the target tab is really closed, the page still does not switch to another tab. No Gateway policy change.

Evidence: built Gateway `/focus/browser` with real Chromium. Main showed the tab as unavailable twice; with this change the exact selected startup tab showed twice. Tracked-open controls passed, and closing the target never substituted another live tab. Details and screenshots: https://github.com/openclaw/openclaw/pull/191538#issuecomment-6605970691 and https://github.com/openclaw/openclaw/pull/191538#issuecomment-6605943059.

Thanks @anmol0b.
```

## Fix PR #191538 description (by anmol0b, opened 2026-11-02T23:48:57Z)

```text
Closes #187645

## What Problem This Solves

The embedded Agent browser panel can stay blank after cold navigation even though the agent's browser tab is live. `/focus/browser` passes the exact `fixedTab` and session key but omits that tab from the existing reference list. The intentionally session-filtered Gateway list therefore hides Chrome's reused, untracked startup tab.

## User Impact

The focus page now displays its selected cold-start tab without switching to a different tab. Android embeds this Gateway page; no Android app code changes. Closed/stopped targets remain unavailable.

## Why This Change Was Made

Since #159891, scoped tab lists include tracked tabs plus explicitly referenced tabs. The chat side panel already passes transcript references through `sessionTabs`; `BrowserDocument` must supply its own fixed-tab reference through that same API. Tracking the reused tab instead would incorrectly grant the session cleanup ownership. Retrying or selecting the first remaining tab would violate the exact-tab contract.

This keeps the Gateway's route/profile matching, filtering, permissions, registry and cleanup unchanged. Anmol Bhardwaj's original fix commit is preserved.

## Evidence
```
