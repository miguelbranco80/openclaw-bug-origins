## What Problem This Solves

Native SQLite session workers load actor creation, host orchestration, and configuration modules they do not need. Every isolate retains its own copy of that import graph.

## User Impact

Existing session operations keep their behavior while loading less host code in native workers. No feature is disabled and no public configuration, schema, protocol, or SDK surface is added. Stable process RSS and latency savings are not yet established.

## Why This Change Was Made

- Separate the existing actor registry and binding reads from actor creation/acquisition. Preserve global registry identity, binding precedence, stale-handle custody, and release ordering.

- Prepare routing dependencies for each relevant command, including a Goal command arriving after worker initialization. Keep preparation outside transactions.
