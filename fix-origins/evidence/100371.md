## Fix PR #159360 description (by kevinlin-openai, opened 2026-09-27T03:03:19Z)

```text
## What Problem This Solves

Fixes paired nodes failing to restart with `--pair-if-needed` after their fallback setup code expires.

## User Impact

Nodes with an existing identity and device token can reconnect to their saved Gateway after the setup code expires. New enrollment and explicit `--pair` still reject expired codes, and a missing or revoked device token cannot fall back to the expired bootstrap or shared config credentials.

## Why This Change Was Made

Keep payload validation in the CLI and let the node-host credential owner enforce expiry before changing node configuration or starting the runtime. Expired fallback recovery requires every selected endpoint to match the saved Gateway scope and supplies only the saved device-token authentication path.

## Evidence

- Reproduced the original failure through registered CLI regression coverage before applying the fix.
- 150 focused tests passed across node CLI registration, node-host startup/authentication, gateway options, and pairing setup-code parsing. Covers missing identity/token/state, mixed endpoint scopes, malformed payloads, explicit pairing, and token loss during startup without shared-auth fallback.
- Single-worker focused invocation: `node scripts/run-vitest.mjs src/cli/node-cli/register.test.ts src/node-host/runner.test.ts src/cli/node-cli/gateway-options.test.ts src/pairing/setup-code.test.ts --maxWorkers=1 --reporter=dot` — 76.73 seconds including compiler preparation. Changed test-file durations: registration 4.45 seconds; node-host runner 8.04 seconds (about 1.4 seconds executing tests).
- Core and source-test TypeScript checking, changed-file formatting/lint, and `git diff --check` passed.
- Independent source review and repository autoreview completed; accepted findings addressed, no remaining P0/P1 findings.
- Real process end-to-end proof passed on built commit `7f546046032aa2edfe9a41990a85e944ec99a5f3`: started a token-authenticated loopback Gateway, paired a node using a node-only setup code, and invoked `system.which`. Stopped the node, waited for the unchanged setup code’s actual ten-minute expiry, then restarted with the same state and `--pair-if-needed`. The same device reconnected and executed the command again. The node had no shared Gateway credentials in its environment.
- Negative controls produced the expected expiry errors for fresh node state and explicit `--pair`, without adding another paired node. A separate fresh-state CLI check confirmed exit 1 without harness termination.
- Gateway and node test processes were stopped after verification. This is an isolated real Gateway/node proof; no production deployment or runtime image update was performed.
```
