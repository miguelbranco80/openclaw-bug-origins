Closes #186333

## What Problem This Solves

An unrelated config reload replaces Teams startup-resolved allowlists with raw configuration. Previously allowed senders stop receiving replies, and name-keyed team/channel restrictions lose their resolved identity until the Teams channel restarts.

## User Impact

Resolved sender and team/channel identities keep working after unrelated reloads. Allowlist edits still take effect immediately; removed or disabled accounts remain disabled. With the default hot-reload mode, a Teams config edit also restarts the channel and resolves the new names.

## Why This Change Was Made

The existing handler config reader owns the live projection. Between an allowlist edit and the normal channel restart, the edited values apply as written, preserving the existing behavior. Retain its startup-resolved allowlists only while the effective account inputs (`allowFrom`, `groupAllowFrom`, `teams`, and `dangerouslyAllowNameMatching`) remain equal. Reuse the normal account-projection path instead of duplicating a default-account branch.

Original fix and regression coverage by @nxmxbbd. The pending-message authorization cases now extend the existing sibling-isolation tests, avoiding a duplicate fixture while still proving revocation after an unrelated reload.
