## Fix PR #182407 description (by steipete, opened 2026-10-24T08:13:13Z)

```text
## What Problem This Solves

Fixes: `openclaw security audit` reports `hooks.token` and `gateway.auth.password` as stored plaintext secrets when they are set through `${VAR}` environment substitution.

## User Impact

Operators who keep these secrets in environment variables no longer get a false plaintext warning; literal values and escaped `$${VAR}` placeholders still warn.

## Why This Change Was Made

The config loader already records env provenance for substituted values, but the stored-secret collector only checked unresolved paths. The collector now consumes those existing resolution facts for both fields. It also moves into `src/security/audit-secrets.ts` so the over-cap synchronous collector module shrinks, with the runtime facade and test import migrated to the new owner. The security CLI docs describe the distinction.

Production LOC +46/-31 (net +15, of which 30 lines are the moved collector; +16/-1 excluding the move); tests +76/-3; docs +2/-0.

## Evidence

- Red on main: the new resolved-env collector regression in `src/security/audit-extra.sync.test.ts` and the real config-load plus audit regression in `src/security/audit-gateway.test.ts` both failed; literal and escaped controls passed.
- Green: `node scripts/run-vitest.mjs src/security/audit-extra.sync.test.ts src/security/audit-gateway.test.ts` passed all 15 tests.
- Targeted typecheck, oxlint, oxfmt, `pnpm check:line-cap-ratchet`, and `git diff --check` passed.
- Independent review: clean, no actionable findings.
- Gap: the outer `openclaw security audit --json` CLI was not run end to end because the source launcher refused before starting the audit. The real config loader plus `runSecurityAuditCore` integration is covered by the tests above, and PR CI remains the broad proof.

Fixes #62438
```
