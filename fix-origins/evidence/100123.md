## Fix PR #154955 description (by steipete, opened 2026-09-21T15:11:28Z)

```text
## What Problem This Solves

Fixes leftover Gemini credential files when publishing a staged OAuth update fails.

## User Impact

Failed Gemini CLI preparation preserves the previous credentials and removes the staged replacement from the persistent profile directory. Existing profile-directory aliases and private file modes continue to work.

## Why This Change Was Made

The private-file writer created a sibling temporary file but never removed it after a failed rename. Reuse the existing fs-safe atomic replacement export for credentials, settings, and isolated execution files. Resolve the existing parent directory first to preserve directory aliases and the existing-parent requirement. This removes four production lines while keeping rename-only publication.

The regression extends the existing atomic-staging coverage through backend preparation. Shared test fixtures move into one helper to keep the auth suite within its line cap.

## Evidence

- The new ordinary-directory and directory-alias cases both failed on the original writer because credential temporary files remained after an injected rename failure. They passed after the change, preserving the previous target and permitting a successful subsequent write; both cases took 19 ms in the final run.
```
