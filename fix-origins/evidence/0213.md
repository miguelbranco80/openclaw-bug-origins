```text
## What Problem This Solves

Tool-call history in the Control UI mixed subagent launches, stops and completions into ordinary activity, used generic labels, and showed nothing when a subagent the agent waited on timed out or failed.

## User Impact

User impact: tool-call history reads as a clear timeline. Launches and stops share compact rows, each settled subagent gets a row ("A finished", "B timed out"), commands appear as one-line "Ran …" rows, and subagent roster listings read "Listed subagents". This works the same whether the agent calls tools directly or through tool search, live and after reload.

## Why This Change Was Made

- Consecutive lifecycle events of the same kind share one row. Completion rows use recorded execution identities, survive output truncation and reload, and deduplicate repeated collection results.
- A collected child that ended without finishing (timed out, failed or stopped) keeps its own outcome row, so a failure is never hidden behind the coordination wait.
- Tool search wraps calls and results in a dispatch envelope. The UI reads the called tool's result and presents the nested call, so dispatched launches and listings render like direct ones.
- Internal coordination payloads stay out of the main transcript. Stopped-agent names remain after the child leaves the roster and open that subagent. A collection wait that returned a per-ID error stays visible after the output cap and reload.
- The Control UI bundle budget is raised by the measured cost (chat boot JS +10,244 B gzip; total CSS +209 B gzip, +2,064 B raw), approved by a maintainer.

## Evidence

- Real Gateway with a real model and a real browser, on both the direct tool path and the default tool-search path: two collector subagents (one finishes, one times out), a collection wait and a roster listing. Each path showed "Launched A and B", "A finished", "B timed out" and "Listed subagents", unchanged after reload. Screenshots are in the PR comments.
- Regressions that fail without the fixes cover dispatched launch receipts, the dispatched roster row, a failed child's completion fact surviving the output cap, and the timed-out collection row in the swarm e2e.
- Type checks, lint, format, test-line, assertion-safety and wrapper-inventory checks pass; chat unit, browser and affected e2e suites pass.
- Known unrelated failures on `main`: the session-management trailing-state e2e and a Codex app-server context-engine test fail identically on the merge base.
- Stop marker behavior is unchanged from `main` (#186073). An earlier version of this PR changed the empty abort marker and broke 5 gateway-method tests that pass on `main`, so that change was reverted.
```

```diff
+export function ChatSubagentCompletion(props: {
+  completions: readonly SubagentCompletion[];
+  onOpenSession?: (key: string) => void;
+}) {
+  // A batch can settle with mixed outcomes; each outcome reads as its own sentence.
+  return (
+    <For each={groupSubagentCompletions(props.completions)} keyed={(group) => group.key}>
+      {(group) => (
+        <CompletionSentence
+          completions={group().entries}
+          sentenceKey={group().key}
+          failed={group().failed}
+          onOpenSession={props.onOpenSession}
+        />
+      )}
+    </For>
+  );
+}

+function CompletionSentence(props: {
+  completions: readonly SubagentCompletion[];
+  sentenceKey: string;
+  failed: boolean;
+  onOpenSession?: (key: string) => void;
+}) {
+  const names = createMemo(() => subagentCompletionNames(props.completions));
+  const parts = createMemo(() => {
+    if (props.completions.some((entry) => !entry.label)) {
+      return [{ type: "literal", value: names() }];
+    }
+    return new Intl.ListFormat(getLocale(), { type: "conjunction" }).formatToParts([
+      ...props.completions.slice(0, 2).map((_, index) => String(index)),
+      ...(props.completions.length > 2 ? ["more"] : []),
+    ]);
+  });
+  const sentence = createMemo(() => {
+    const marker = "￼";
+    return t(`chat.toolCards.${props.sentenceKey}`, { names: marker }).split(marker);
+  });
+  return (
+    <div class="chat-tool-msg-collapse">
+      <div
+        class="chat-tool-msg-summary chat-tool-row chat-tool-row--subagent"
+        aria-label={t(`chat.toolCards.${props.sentenceKey}`, { names: names() })}
+      >
+        <span class="chat-tool-msg-summary__icon" aria-hidden="true">
+          <Icon name="bot" />
+        </span>
+        <span class="chat-tool-disclosure__content" style={{ gap: "0" }}>
+          <span class="chat-tool-row__verb" style={{ "white-space": "pre" }}>
+            {sentence()[0]}
+          </span>
+          <span class="chat-tool-row__title chat-tool-row__subagent-name" title={names()}>
+            <For each={parts()} keyed={(part) => part.type + part.value}>
+              {(part) => (
+                <Show when={part().type === "element"} fallback={part().value}>
+                  <Show
+                    when={part().value !== "more"}
+                    fallback={t("chat.toolCards.lifecycleMoreCount", {
+                      count: String(props.completions.length - 2),
+                    })}
+                  >
+                    <Show
+                      when={props.onOpenSession}
+                      fallback={props.completions[Number(part().value)]?.label}
+                    >
+                      <button
+                        type="button"
+                        class="chat-tool-row__subagent-link"
+                        onClick={() => {
+                          const entry = props.completions[Number(part().value)];
+                          if (entry) {
+                            props.onOpenSession?.(entry.sessionKey);
+                          }
+                        }}
+                      >
+                        {props.completions[Number(part().value)]?.label}
```
