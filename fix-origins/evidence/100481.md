## Fix PR #163046 description (by steipete, opened 2026-10-01T22:32:43Z)

```text
## What Problem This Solves

The QA scenario `channel-top-level-reply-shape` passed even when the Discord final was sent as a reply (carrying `message_reference`) instead of a top-level message. A matching preview was enough to satisfy it, so a real reply-shape regression could ship behind a green QA run.

## Why This Change Was Made

Three gaps combined (from `35bfbb537752` and `253b784468c6`):

- `extensions/qa-lab/src/crabline-transport.ts` dropped native Discord quote metadata when recording messages.
- Crabline config generation ignored the scenario's `topLevelReplies` policy.
- `qa/scenarios/channels/channel-top-level-reply-shape.yaml` accepted the first matching preview rather than the completed final.

The Crabline transport now preserves native reply metadata (new `crabline-discord-replies.ts`), honors `topLevelReplies`, waits for delivery completion, and the scenario judges the final identified by its native delivery receipt; if that exact message is missing (for example deleted after a matching preview), the scenario fails instead of falling back to an earlier message. A second commit fixes a stale Discord roundtrip assertion that expected runtime traffic in the startup-only readiness snapshot (from `a2c698f3d32`), distinguishing startup evidence from the runtime recorder without weakening delivery assertions.

The Crabline relay is payload-transparent: it rewrites only endpoint-bearing fields (gateway discovery `url`, READY `resume_gateway_url`, attachment `url`/`proxy_url`) and never message, embed, or attachment-description text, so QA always exercises the exact prompt and reply.

## User Impact

QA-only: the reply-shape scenario now fails when a final is delivered as a reply and passes when it is top-level (also after a quoted preview); edited-wrong and deleted finals fail too. No product runtime changes.

## Evidence

- Before: two new regression assertions fail on main (quoted final accepted). After: quoted finals fail, top-level finals pass, and preview -> final -> deleted final fails explicitly.
- Blacksmith Testbox on rebased head: private QA build, 188 tests across 22 related qa-lab suites (including a regression that origin-prefixed message and embed text stays byte-identical), `check-changed`, 2/2 Discord Crabline E2E (mock provider), typechecks.
- Sibling scenarios using first-preview matching (`thread-reply-override.yaml:48`, `thread-follow-up.yaml:108`, `thread-isolation.yaml:125`, `telegram-reply-chain-exact-marker.yaml:41`) were checked; not reproduced as false-greens, left unchanged and noted for follow-up.
- QA runtime roughly +250/-85 LOC (new `crabline-discord-replies.ts` receipt tracking); tests/scenario roughly +270/-15; docs +11.
```
