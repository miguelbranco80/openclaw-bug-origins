## Fix PR #166650 description (by jlapenna, opened 2026-10-07T15:47:06Z)

```text
Fixes #166644

## What Problem This Solves

Hidden pre-compaction memory-saving turns can regain unrelated execution tools after their persistence-only tool set has been selected, allowing project work while a user's request waits.

## User Impact

File-backed saving retains `read` and its append-only daily-memory writer. Provider-backed saving retains `read` and the selected memory plugin's declared persistence and lookup tools. Normal foreground tooling remains available. No operator configuration or stored-state migration is required.

## Why This Change Was Made

Keep the existing memory projection authoritative through host-tool collection, MCP/LSP/client assembly, and final harness presentation. Embedded and Copilot callers forward the existing generic run trigger; supplied presentation facts cannot restore discovery or Code Mode on a memory turn.

The existing attempt contract carries the trigger, but the tool-surface factory and resolved wire presentation did not. The factory's optional generic `trigger` input preserves omitted-field source compatibility; the wire schema stays unchanged. The SDK documentation now tells harnesses to forward it, and a narrow type contract ties it to the existing attempt trigger. Selected-provider tool ownership and persistence accounting stay with their existing owners.

Maintainer cleanup shares auxiliary-tool eligibility and catalog dispatch, reducing production code by two lines against integrated main `2f71f0f03fcc531abe37530c94b70c27c247bc6e`.

Original fix by @jlapenna; maintainer cleanup by Peter Steinberger. The maintainer commit retains the contributor ancestry and includes Joe LaPenna's co-author credit. No force push or merge was performed.
