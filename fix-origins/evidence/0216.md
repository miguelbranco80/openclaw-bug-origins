## Fix PR #191271 description (by pgondhi987, opened 2026-11-02T16:26:23Z)

```text
## What Problem This Solves

Fixes: strict browser SSRF policy cannot inspect redirect hops when navigation or a new tab uses an existing-session Chrome MCP profile.

## User Impact

When `browser.ssrfPolicy.dangerouslyAllowPrivateNetwork` is explicitly `false`, existing-session profiles now reject HTTP(S) navigation and tab opens before sending a Chrome MCP command. Use a profile with driver `openclaw` for strict navigation. `about:blank` remains available, and other policy modes retain their existing behavior.

## Why This Change Was Made

Reuse the browser navigation policy owner for a shared Chrome MCP preflight at both entry points. This applies the existing requirement for redirect inspection to a transport that cannot provide it. The added guard is needed at these two dispatch boundaries; no new configuration or state is introduced.
