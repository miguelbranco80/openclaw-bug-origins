## Fix message body

```text
fix(ui): match the agent Skills filter across Unicode normalization forms

The agent Skills filter compared names without Unicode normalization, so a skill such as `München` stored in one form (NFC or NFD) didn't match a filter typed in the other form, and the panel said no skills were found. The filter now lowercases and NFC-normalizes both sides for the local comparison only. Raw queries, names, keys and files are unchanged, and filtering sends no Gateway requests.

Evidence: built Gateway and Control UI in real Chromium with real workspace SKILL.md discovery. NFC-to-NFD and NFD-to-NFC filters failed twice each on main and matched twice each with this change. ASCII, same-form, no-match and clear controls behaved the same on both refs. Details and screenshots: https://github.com/openclaw/openclaw/pull/189276#issuecomment-6543690531.
```
