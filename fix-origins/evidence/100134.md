## Fix PR #160329 description (by steipete, opened 2026-09-28T09:22:17Z)

```text
## What Problem This Solves

Fixes: HTTP request rejections (413 body limits, pre-auth body profiles, pipelined-request fencing) misbehave on Bun builds that include upstream Bun's node:http rework (#43557). 9 of 31 `http-request-lifecycle` cases fail on the OpenClaw Bun fork's current main: clients get `ECONNRESET` instead of a complete 413, and queued HEAD rejections lose their half-close.

## User Impact

Gateway and plugin HTTP endpoints (a2a, admin-http-rpc, discord activities, feishu, and others that call `sendHttpRequestRejection`) keep delivering an exact rejection response and a clean half-close on the new Bun, over HTTP and HTTPS. This unblocks moving OpenClaw's CI and apps to the new fork release. The next stock Bun release will pick up the same upstream change, so it needs this too. Node and older Bun (stock 1.4.x, current pins) behave exactly as before.

## Why This Change Was Made

OpenClaw's rejection transport had a Bun-only branch that called `res.end(body)` and relied on older Bun half-closing the socket afterwards. Upstream Bun #43557 changed `res.end()` on a `Connection: close` response to Node's `destroySoon`, which destroys the socket before the client sees the half-close. Identical probe scripts behave the same on Node 24 and the new Bun. On Node, OpenClaw never used `res.end()` here for exactly this reason: it writes the framed response, then half-closes with `socket.end()`.

The change adds one selection helper, `httpRejectionTransport`. Bun builds with #43557 give the request socket its own `destroySoon`; older Bun inherits `net.Socket`'s. Bun sockets carrying that override take the same ordered half-close path as Node. Older Bun keeps the native `res.end` branch, which its framing needs (the Node path fails 16 of 31 cases on stock 1.4.2). Version strings cannot tell these builds apart: fork builds before and after the sync both report `1.4.3-canary.1`.

A queued HEAD response on the new Bun waits for its `socket` assignment, then flushes through the response write callback. It does not depend on the `http.server.response.finish` diagnostics event, which Bun did not publish (openclaw/bun#23 adds it for Node parity). The SDK documentation for the rejection helper now describes the behavior per runtime.
```
