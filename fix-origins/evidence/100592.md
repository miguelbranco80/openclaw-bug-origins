```text
## What Problem This Solves

Local provider readiness and process-stop deadlines used wall-clock time. A backward clock correction extended configured timeouts; a forward correction prematurely expired them. Use monotonic elapsed time for these deadlines without changing their configured budgets or settlement behavior.

The regression test now uses the existing local-service fixture's `claimPort()`, retaining the reservation until managed-child shutdown finishes instead of releasing a `getFreePort()` reservation before startup.

## Evidence

Built the shipped Gateway and CLI on main (`bdf12f6b6b1235f10ee361687e0c32db94dd3a6b`) and this candidate. A configured local provider served real HTTP readiness responses and Responses inference. Only the Gateway process's `Date.now()` was stepped; system time, timers, and monotonic clocks were unchanged. Every recorded case required an owned child spawn, an HTTP probe, and child close.

- Backward five-second step, twice per ref: a 1.5-second readiness budget took 6.75–6.78 seconds on main versus 1.69–1.70 seconds on the candidate, including probe/startup overhead. Both emitted the readiness failure and closed the child.
- Backward step after SIGTERM, twice per ref: the two-second grace window reached SIGKILL in 7.00–7.05 seconds on main versus 2.05–2.06 seconds on the candidate; child close followed within 11 ms.
- No-step controls on both refs preserved approximately 1.66-second readiness failure and two-second shutdown escalation.
- Forward five-second controls: main prematurely stopped readiness at 0.58 seconds and escalated shutdown after 30 ms; the candidate retained approximately 1.55-second readiness and two-second shutdown budgets.
- All healthy-readiness/shutdown cases completed an actual agent request with the local provider's `LOCAL_CLOCK_OK` response before idle shutdown. These Linux signal/close observations do not claim native Windows taskkill coverage.

The focused local-service, monotonic, settlement, and shutdown suites pass: **30 tests across four files**. The existing failed one-shot-host subprocess fixture now accelerates `performance.now()` rather than `Date.now()`, preserving real child cleanup without a 60-second readiness wait. Its previous clock-domain mismatch reproduced on the first candidate and passed on main; adapting the fixture resolves it. Formatting and lint checks pass for all six changed files.

## Compatibility and Merge Danger

No configuration, persisted state, or public API changes. This is a two-way door: reverting restores wall-clock deadline behavior. The blast radius is configured local-provider readiness and managed-process shutdown; inference transports and unrelated provider selection are unchanged.
```
