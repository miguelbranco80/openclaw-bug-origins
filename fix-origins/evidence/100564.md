```text
## What Problem This Solves

Fixes the Files panel losing its parent-folder button when the folder being viewed becomes unavailable after a refresh, leaving the project browser empty and unable to navigate back.

## User Impact

Files keeps the parent-folder action and explains that the folder is unavailable. You can return to the parent and continue browsing without reloading the page or switching sessions.

## Why This Change Was Made

Parent navigation depended on the latest folder listing, which can omit an unavailable folder. The view now also receives the existing controller's selected path and derives the parent from that intent when a settled non-root listing is unavailable. The existing scoped navigation and request owners still handle the action. Search and loading states keep their existing behavior; no automatic redirect, Gateway API, storage, or permission changes are introduced.

## Evidence

The original production-browser flow passed for a normal folder and failed for an unavailable folder. The repaired file passes all three browser cases, including navigating to the parent and opening a sibling folder, plus the existing late-directory-response case.
```
