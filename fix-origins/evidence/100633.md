## What Problem This Solves

A Git checkout can have the requested source commit and matching build provenance while still missing required runtime artifacts.
In that state, `openclaw update` currently takes the `already-current` shortcut instead of rebuilding.
The final safety check then rejects the incomplete runtime, leaving the operator with an update failure and no repair.
This completes the artifact checks for the source-current workflow covered by #156996.

## User Impact

A source-current checkout with missing build stamps, runtime entry, or Control UI startup assets now reaches the existing candidate build and validation path.
A complete checkout still skips core activation, and package-to-Git conversion still performs its required exposure work.
The existing service admission, external-supervisor guard, migration boundaries, and post-update maintenance remain in place.

Git status JSON also includes an optional `update.git.artifacts` observation with readiness and, when ready, the build identity and version.
The version comes from current build metadata, with the existing CLI package-version fallback when that metadata has no version.
The observation does not establish remote freshness, running Gateway health, candidate validation, or permission to restore state.
Package-install status remains unchanged, and no configuration or migration is added.

## Why This Change Was Made

The updater already computes complete native artifact verification, but its shortcut used only the recorded build commit.
Both the immediate target match and the fallback to the installed commit now use that existing verified result.
The artifact owner also produces the status observation so its version cannot drift to an edited source `package.json` while the installed build remains unchanged.

The patch preserves the separate `sourceRuntimePrepared` fact introduced by #158849 and its existing admission and finalization behavior.
Preferred-target reporting and external-manager client/UI changes are outside this PR.
