## Fix PR #152207 description (by steipete, opened 2026-09-18T22:29:37Z)

```text
## What Problem This Solves

Fixes private subagent results getting stuck after the spawning turn finishes in a channel conversation whose runtime policy uses a separate peer-scoped session key.

## User Impact

The parent can review a completed private child, start the next child, and finish the conversation. Private completion remains private.

## Why This Change Was Made

The channel runner passed its policy key as the logical run's conversation identity. Child settlement therefore could not find the children registered to the actual conversation. Use the conversation key for run identity and keep the peer-scoped key with harness policy.

Related: #151879. The failure also blocked the unchanged QA Smoke scenario in [PR #152173's CI](https://github.com/openclaw/openclaw/actions/runs/35397117590/job/105768605179).

## Evidence

- The maintained `subagent-completion-direct-fallback` scenario reproduced the original private-phase timeout at its unchanged 90-second deadline. With this fix, the complete public → restart → private child chain → restart flow passed in 51 seconds, using Node 24.19.0, the mock provider, and isolated Crabline Telegram fixtures. Both private children delivered and their spawning-turn ownership cleared.
- The focused caller regression fails on the original policy-key handoff. All 12 tests in its owning file pass with the fix; it uses the real fallback resolver, canonical admission, and the real run-entry settlement path.
- Private QA runtime build and the full selected changed-file check passed, including core and all 20 test type graphs, typed lint, formatting, line ratchets, unused exports, and runtime import-cycle guards.
- Independent full-diff P0–P2 review found no actionable issues.

The first repair CI run exposed two lifecycle tests that selected the first event as completion. Correctly attributing model-status events to the conversation made that assumption visible. The tests now use the existing terminal-event selector, require exactly one terminal event, and retain the session and result assertions; the unused first-event helper is removed. The unchanged tests reproduced both failures locally, and all 35 progress/session-state tests pass after correction. The affected test type graph, typed lint, formatting, guards, and all unused-export scans pass; fresh full-diff review is clean. [CI for the updated head passed](https://github.com/openclaw/openclaw/actions/runs/35403145464), including the previously failing compact shard. QA Smoke was skipped on this test-only update; the full scenario evidence above is the isolated local run.
```
