## What Problem This Solves

Fixes unnecessary Gateway downtime when updates run optional Doctor inspections while the service is stopped.

## User Impact

Updates driven by this version run 12 inspection-only checks after the Gateway is ready, preserving their findings in the update result. Repairs, migrations, readiness gates, and diagnostics that cannot be reproduced by the deferred path remain in the stopped window.

## Why This Change Was Made

The installed updater advertises that it will finish the inspection pass after restart. Doctor defers only lint-backed, read-only checks. The finalizer runs those checks with explicit selectors and informational findings enabled, after verified readiness. An incomplete pass is advisory; uncertain child-process cleanup still propagates through the existing recovery boundary.

The capability is internal, not a new configuration option. Older installed updaters do not advertise it, so an upgrade from 2026.9.8 retains the original inspection behavior rather than losing diagnostics. `--no-restart`, unowned/stopped plugin-only services, and copied-state rehearsals retain their existing behavior. The performance improvement applies once the new updater is installed.

`session-snapshots` stays in-window because lint omits snapshot metadata scan-error diagnostics. `workspace-status` stays because lint omits errored plugin identities.
