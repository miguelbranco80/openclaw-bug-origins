Fixes #177065

## What Problem This Solves

Fixes: `sessions.subscribe` clients keep showing a session as busy after a Gateway-started backend run, such as an exec completion notice, finishes.

## User Impact

Subscribers receive the settled activity update without waiting for another message. The existing Gateway projection computes current aggregate activity, so overlapping work can still keep the session busy. No configuration, migration, or client protocol changes are required.

## Why This Change Was Made

The terminal backend event can precede release of the session controller's execution ownership. RPC-started runs publish a settled update from their finalizers, but autonomous runs have no such finalizer. The existing controller release now emits `agent.input.settled` through the runtime lifecycle event pipeline after releasing custody. Backend-free maintenance and operations claimed by an RPC source stay quiet.

The maintainer update merges main through `4ee4606426786` without rebasing, keeps the contributor's production fix, and resolves the lifecycle-test conflict using main's slimmed fixtures. One regression table exercises autonomous backend completion, backend-free maintenance, and RPC backend completion through the real turn owner. The RPC lookup runs once at owner settlement, not on streaming events; exact operation matching also covers sources retained across owner rekeying.

Thanks @ayaangazali for the original fix and regression. The contributor commit remains in this PR's history.
