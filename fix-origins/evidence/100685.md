## Fix PR #187157 description (by shakkernerd, opened 2026-10-29T01:39:57Z)

```text
Fixes #187143

## What Problem This Solves

An ordinary Control UI request can disappear from chat history when a graceful Gateway restart interrupts it before the first response. The resumed task can finish successfully while the conversation shows only the restart instruction and the resulting work. The original bytes remain stored, but orphan recovery has moved the original message off the active history branch.

## User Impact

The accepted human prompt remains visible as its original message, separately from the new system resume instruction. Recovery keeps the same session and creator, and continues to use current authority. This requires no configuration change or migration and does not replay the original execution or promise exactly-once behavior for arbitrary interrupted external actions.

## Why This Change Was Made

Fresh restart inputs carry `internal_system` provenance with source `restart`. The session-boundary orphan repair did not recognize that continuation when deciding whether to preserve an unanswered human message. It reset the active branch and folded the old text into the new input's private model projection instead.

This change handles that existing restart input in the existing preservation guard. It leaves shared provenance policies used by fallback, accounting, and other runtimes unchanged. The regression reopens persisted history and checks that the original row and a distinct resume row remain. The real-Gateway case also checks original message identity and provenance, creator identity, one disabled automation, and visibility after reloading the page.

## Evidence

- On base `0b538f7d5a4d9e3328f572cc07fe23402f733f36`, the real Control UI/native Gateway replacement case reproduced original history and rendered-message counts changing from one to zero. Selected identity/hash observations showed the stored original was unchanged while a new leaf-control record detached it; the returned page contained only four messages, so the history limit was not responsible.
- The focused persisted-boundary regression failed on the unfixed owner and passed with the correction. All 11 selected owner/caller/control files passed, totaling 148 tests, including prompt-prefix stability and restart authority controls.
- Changed-file formatting/lint and the selected compiler checks passed. The existing real-Gateway restart case passed on the committed tree: original message once with the same ID, separate resume instruction once, unchanged session/creator, one disabled job, and original text visible after reload. The scenario took 25.1 seconds of test time (84.3 seconds including Vitest setup/transform).

The deterministic case uses a controlled Responses provider and its existing routing marker. A separate normal guest request for an onboarding plan was exercised on the production-identical `74cebbb` runtime.
```
