## Fix PR #176106 description (by freeqaz-openai, opened 2026-10-18T06:20:22Z)

```text
Closes #176098

## What Problem This Solves

The `subagent-handoff` QA scenario passed when a spawn was refused, no child ran, and the parent accurately reported “no child was created.” It checked a planned call and the shape of the parent’s answer rather than whether the handoff completed.

## User Impact

A passing handoff now shows that the requester reported this accepted child’s result. This changes QA scoring, not what agents can do.

## Why This Change Was Made

Ask the requester to yield after the spawn is accepted. Follow that child run to a successful, visible terminal result, find the result in the requester’s settlement, and require the subsequent public `Result:` to report it as delivered. Transcript IDs and parent links establish the order even when both messages arrive between polls. Normal child cleanup does not invalidate the check.

The check uses the settlement producer’s formatter through the existing private QA facade (for example, `2 < 3` arrives as `2 &lt; 3`); it does not try to reverse it or claim byte-for-byte identity before encoding. This tests the yielded, single-child handoff. A result available only in private runtime context cannot satisfy it.

## Evidence

Reproduced the false pass, then exercised the real scenario evaluator, tool-receipt parser, prompt-data formatter, and mock requester with synthetic runtime observations and Internet sockets disabled. The requester’s actual multiline report (including an interior `Evidence:` line and an escaped comparison) passed. A refused spawn, a correct guess before delivery, and the right text in the wrong field, child, or transcript branch did not pass. No live provider was used.

Synced with current `main` in [`0222f7b1`](https://github.com/openclaw/openclaw/commit/0222f7b1a7e0b03037ff3ad198340b6bc511703c); [CI for this integration](https://github.com/openclaw/openclaw/actions/runs/39172334144) is separate from the earlier results below. I checked the intervening changes to isolated QA workers and child delivery, including a completion that remains pending after a requester timeout. A pending handoff is not evidence of delivery.

In a bounded evaluator check against the integrated source, current main still passed the synthetic refused-spawn case without reading a child result. The correction accepted 11 positive cases and rejected all 23 negative cases, including a report with the right result on the wrong transcript branch. This exercises the scoring contract, not a live Agent or provider; it doesn't replace the upstream build.

[Upstream ran all 18 handoff cases on the previous head `33e0c0d1`](https://github.com/openclaw/openclaw/actions/runs/39104272069/job/117606922561); their shard passed 433/433 tests. [Extension lint](https://github.com/openclaw/openclaw/actions/runs/39104272069/job/117607526034), production types, and test types also passed. An earlier head failed three lint rules; this head fixes those without changing the behavioral results.

Locally, the configured registry returned HTTP 403 for a locked dependency, so I did not run the full suite. The separate local automated review helper timed out and produced no verdict.
```
