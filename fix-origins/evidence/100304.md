## What Problem This Solves

Database registration could fail when an unrelated agent deletion changed the journal after claim preparation. The claim compared the whole prepared journal with current rows, rejecting harmless progress even when the claimed identity and paths did not overlap.

Check current deletion ownership inside the existing claim transaction. Remove the preparatory journal read, whole-journal equality check and tests that only pinned that check. Lease and registration owners pass their claimed path into state initialization. Current identity, canonical database/WAL paths, cleanup authority, recreation and draining-settlement protections remain.

Accepted edge: another deletion may begin or advance after preparation; it blocks the claim only when its current identity or paths overlap. The initialization fixture expects the existing deleted-agent identity error while still requiring refusal before mutation, zero registrations, unchanged schema/version and byte-identical external data.

The readiness fixture recognizes the existing five-second competing-deletion wait. Exactly one deletion must succeed; the loser must receive either the target's missing-agent `INVALID_REQUEST` or a typed `UNAVAILABLE` with that target's lease diagnostic and `OPENCLAW_STATE_LEASE_HELD`. The target must disappear from published config after settlement. Accepted edge: the loser can exhaust that existing wait while the winner finishes cleanup. No production deadline changes.
