## What Problem This Solves

`gateway restart` can stop waiting at 60 seconds even after the replacement reports a new startup phase and becomes healthy shortly afterward.

Related: #161158

## User Impact

Restarts and Doctor restoration keep observing a progressing startup within the existing five-minute cap. Verified readiness succeeds; failed and unverified outcomes retain their distinct nonzero exit codes.

This covers native restart progress. The source updater's arbitrary shell callback/exit-2 contract and native `gateway start` deadline remain unresolved parts of #161158, so this PR does not close it. A silent pre-listener startup cannot earn progress credit without observable migration activity.

## Why This Change Was Made

Count each new `/startupz` phase from the running replacement's own listener in the existing progress watchdog. Repeated phases, foreign listeners, and a later process cannot renew the window. Explicit deadlines, migration progress, identity/health checks, and the cap remain unchanged; no timeout increase or new configuration.

The original exit-0-on-failure defect is already repaired on main. Add a stopped-replacement regression through the CLI failure reporter to preserve exit 1, alongside the existing pending/success contracts.
