## Fix PR #196080 description (by roboclaw-bot, opened 2026-11-09T15:53:05Z)

```text
Related: #179823, #161072

## What Problem This Solves

Fixes: a model calling a hidden Code Mode tool directly receives a misleading “Tool not found” error with no recovery guidance.

## User Impact

The model gets actionable guidance to call the tool from JavaScript inside `exec`, instead of mistaking it for an unavailable capability. Rejected native calls still execute nothing; permissions and the model-visible tool surface are unchanged. No configuration or migration is required.

## Why This Change Was Made

Use the existing deferred-tool error contract to explain Code Mode recovery only for names in the current run catalog. Unknown, denied, and removed names keep the generic error. Directory-mode hydration and direct-only tools retain their existing behavior. Discovery guidance handles normalized names, collisions, and MCP namespaces without assuming the original name is a JavaScript callable.

## Evidence

- Observed a live native `write` rejection followed by a successful bridged write in the reported session; the rejected call never reached the filesystem writer.
- Both new regressions failed on unchanged production source, then passed with the repair. The touched session suite passes 26/26, including the real Agent loop, Code Mode executor/bridge and file writer. It checks zero executions before recovery, one execution afterward, persisted file content, unchanged provider surface, and unknown/denied/removed names.
- Sibling Code Mode loop tests: 21/21; prefix stability: 14/14. Targeted typecheck, lint, format, MDX and regression-budget checks passed; `git diff --check` passed.
```
