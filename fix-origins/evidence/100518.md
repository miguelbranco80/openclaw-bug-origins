Closes #153970. Thanks @RJAILLC for the report and reproduction details.

## What Problem This Solves

Fixes `backup create --verify` refusing duplicate registrations of one agent database and prevents registered hardlink aliases from losing committed WAL-only rows in the archive.

## User Impact

Verified backups preserve committed database rows regardless of alias pathname order, including with `--no-include-workspace`. Genuine two-owner conflicts and unsafe or changing journal ownership still refuse publication with a recorded reason. No new options, schema changes, or live registry rewrites are required.

## Why This Change Was Made

The workspace enclosing the state directory succeeds on its own. The original refusal reproduces when the captured registry carries two spellings of one agent database path, such as `agents/main/agent/openclaw-agent.sqlite` and `agents/main/agent/./openclaw-agent.sqlite`, or a physical alias. The report did not include the reporter's registry rows, so its exact historical spelling is unknown. `sealBackupResourceInventory` deduplicates physical ownership while preserving archive alias names and rejecting different registered owners. The dry-run `skipped: covered` entries suppress duplicate top-level assets; discovery already deduplicates state/agent traversal.

ClawSweeper's P1 identified a data-loss hole in that first repair: the first registered hardlink pathname supplied every alias snapshot, and canonical sources bypassed WAL-aware grouping. An earlier-sorting alias without the owner's WAL could therefore omit committed rows. All sources now use the existing `planBackupSqliteSourceGroups` owner to select the journal-owning source independently of pathname order. Canonical validation, sanitization, cold-archive anchors, and final registration identity checks remain intact. The initial global group and private image remain authoritative for both the captured registry and later global aliases.

A separate-process alias writer can checkpoint and truncate its WAL between journal checks while a primary reader is pinned. The shared grouping owner now also checks the existing main-file mutation fingerprint (device/inode, size, and birth/change/modification timestamps) for multi-path groups, including cached-image copies. This refuses the transient checkpoint race without opening raw file descriptors that could release SQLite locks. Ordinary WAL appends remain valid.

The original duplicate-registration repair was +34 production LOC. The additional growth covers shared source planning, initial global-group ownership, and the checkpoint-race guard; the canonical bypass and separate alias snapshot path were removed.
