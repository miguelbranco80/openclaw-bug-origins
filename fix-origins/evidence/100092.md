## What Problem This Solves

The managed Codex runtime is still 0.159.1 and does not include the SQLite startup fixes shipped in [Codex 0.160.0](https://github.com/openai/codex/releases/tag/rust-v0.160.0).

## User Impact

Managed installations receive upstream fixes that avoid unnecessary SQLite writer-lock acquisition during connection setup, preserve existing vacuum modes, surface initial connection errors, and reduce blocking stderr span logging. The external app-server minimum remains 0.149.0.

This is a supported runtime upgrade, not evidence that a particular production initialize timeout or Bun issue is fixed.

## Why This Change Was Made

Align the managed dependency, ACP override, provider client-version hint, lock, native expectations, and docs. The official release source contains [the connection/logging fix](https://github.com/openai/codex/pull/49032) and [the vacuum/error follow-up](https://github.com/openai/codex/pull/49102). The launcher and app-server protocol source are unchanged from 0.159.1, so those implementations remain unchanged.

- 176 focused tests passed across seven files: managed pin/selection, initialize and external-version floor, models, protocol validators, schema normalization, and OpenAI provider discovery. The six Codex files took 43.59 seconds; the provider file took 14.15 seconds. No new test or CI cost was added.
- The official binary exported 440 experimental JSON schemas matching the exact release source. All eight selected schemas and nine compact artifacts match the existing bridge. This used the binary exporter and source precomputed export; the Cargo generator was not run.
- A fresh unauthenticated home exercised the real managed resolver and client: initialize reported 0.160.0, model/list returned the same eight documented visible models, and config/read preserved the configured effort and config bytes. No authenticated inference or live deployment was performed.
- Joined shutdown returned `exited: true, cleanup: uncertain`; the stronger clean-shutdown assertion did not pass. Separate task-specific process and file-holder checks found no remaining fixture processes or holders, then removed the fixture. This is a disclosed cleanup-proof limitation, not a clean-shutdown claim.
