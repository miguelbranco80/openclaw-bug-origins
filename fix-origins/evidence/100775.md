## What Problem This Solves

Fixes Linux Gateway and node installs that start successfully but then report a runtime-pin readback failure when the service omits `WorkingDirectory`.

## User Impact

Pinned installs and reinstalls can finish and preserve the selected runtime. Existing service arguments, operator overrides, and unknown-inspection safeguards remain enforced; no configuration or schema migration is added.

## Why This Change Was Made

Systemd supplies the user's home as the effective working directory when the unit omits it. The service reader discarded the authored definition after finding no overrides, so pin verification compared the authored omission with that effective default. Retaining the known-empty override result preserves both views and fixes the producer without weakening verification or special-casing home paths.

The same distinction covers resource-only drop-ins. The change also prevents native defaults and specifier expansion from being mistaken for operator-owned launcher or environment overrides. macOS and Windows use their existing authored-definition readers.

## Evidence

- Reproduced through a real Linux `node install --runtime-path` flow: identical command arguments, omitted planned working directory, effective home directory, and the exact pin-readback failure after startup.
- Both new regression cases fail before the fix with that error and pass afterward, including native pin persistence and rereading in isolated SQLite state. The focused reader, systemd, and runtime-pin suites pass 274 tests.
- Live patched-reader proof against the same systemd service passes strict definition validation and isolated pin persistence, without restarting or modifying the production service.
- Full selected changed-file checks passed, including core/test typechecks, lint, dead-export scans, storage/import-cycle/pairing guards; independent P0–P2 review found no actionable findings.
- Systemd's documented default is in [`systemd.exec`, `WorkingDirectory`](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html#WorkingDirectory=).

Production delta is +4/-2: the functional change is net-neutral; two comment lines explain the authored/effective boundary. The existing specifier regression moved into the smaller command-reader suite so it shares the relevant fixtures.
