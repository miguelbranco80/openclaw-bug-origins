## What Problem This Solves

FreeBSD self-updates could replace files owned by `pkg`, including files reached through an installation alias or a global launcher. CLI and Gateway update admission did not verify native package ownership.

## Why This Change Was Made

One bounded native `pkg` inventory inspector protects CLI/Gateway admission and package/Git mutation boundaries. It checks installation roots and launcher directory entries, including aliases, before activation, rollback, and cleanup. Owned or incompletely inspected paths produce an actionable refusal. The query cannot bootstrap `pkg`, invoke a configured query alias, or initialize a pkg plugin.

The inspection observes started asynchronous work and reports deadline failures. Launcher backup capture retains partial state so a later copy failure cleans earlier backups without moving the installation. Existing runtime preparation and Gateway admission remain behind their existing owners.

## User Impact

Package-managed installations update through their owning pkg or Ports deployment. Independently managed installations remain eligible when ownership is verified. Complete-inventory refusal is intentional: unreadable registered parents or exhausted inspection budgets cannot establish non-ownership. The observations do not atomically exclude a concurrent external pkg writer. Normal Linux, macOS, and Windows behavior is unchanged.

Published 2026.9.4 cannot acquire its FreeBSD update executor because process-start identity support is missing. A new target or `--no-restart` cannot repair that installed driver. The update guide now explains installation-owner recovery, preserving the existing prefix, configuration, state, and actual supervisor. pkg-owned installations must use pkg/Ports; npm must not overwrite them.

This does not complete rc.d/default-profile update support or certify a FreeBSD release. Both related issues remain open.
