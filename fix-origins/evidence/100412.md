## Fix PR #152976 description (by fuller-stack-dev, opened 2026-09-19T15:07:04Z)

```text
Related: #152914

## What Problem This Solves

An update refused because an agent database is in use loses its useful refusal reason in the public failure report.

## User Impact

Operators receive a fixed explanation and retry guidance instead of a generic Doctor failure. Unsafe maintenance still refuses, private lease details remain redacted, and existing resource release and service restoration behavior is preserved.

This PR fixes refusal reporting. It does not claim to diagnose or resolve the original macOS incident in #152914.

## Why This Change Was Made

Classify the real typed lease refusal at Doctor admission, carry the safe fact through the existing Doctor result and update finalization path, and allow only the exact public code and guidance through redaction. External-service preflight can only refuse; an empty or failed observation cannot authorize repairs and still requires both coordinators and the held-owner check.

Current-main integration preserves awaited coordinator acquisition and the existing service owner. A macOS test expectation now matches the canonical service policy: a loaded launchd job is not offline merely because it is disabled.

## Evidence

- Production candidate `b234aa53d5c15b78c97197414569243592ad1212`: 209 focused tests passed across Doctor flow, maintenance settlement/installation, public identifiers, and redaction.
- Fresh independent review of the final production/test delta is scoped-clean at P0–P2.
- Two genuine built-CLI lease-refusal cases passed (external preflight and held-owner admission): exit 1, exact safe typed IPC fact, unchanged config/state database hashes, and active lease retained. The child used only disposable synthetic state; no native service or live Gateway was changed.
- Full local build and both changed-file static-check runs passed (types, lint, formatting, unused-export scans and repository guards).
- [CI run 35572588091](https://github.com/openclaw/openclaw/actions/runs/35572588091) exposed an inherited Codex elicitation test race: it inspected a prompt after answer waiting started but before delivery. Follow-up `6a4dd2f84901a987d97a3c1867789a0e38cadb30` adds one wait on actual prompt delivery; all pending/answer assertions remain. Its 26 targeted tests and independent P0–P2 review passed. No production/package inputs changed, so the prior build and built-CLI proof remain applicable. The resulting exact-head [CI run 35573749019](https://github.com/openclaw/openclaw/actions/runs/35573749019) completed successfully. Dependency and security-sensitive reviews also passed.

## Compatibility and bounded acceptance

No schema, migration, backfill, retention, protocol field, or database write-admission change is introduced. The existing Doctor failure-fact contract is reused. The lease reader opens the existing database read-only, never repairs its schema or deletes stale rows, and the held-owner assertion still checks it before repairs.

Historical published 2026.9.4-driver evidence established actual candidate-child refusal, unchanged synthetic state and config, and continued service availability. That older parent does not support typed failureFacts; its nonzero/stderr result is not typed-parent evidence. Historical rollback-verification timeout (52,991 ms) and backup-retention exit 1 (84,668 ms) remain unresolved in the broader updater investigation, not established regressions introduced by this reporting delta. This PR does not claim end-to-end update recovery, no-loss, global descriptor history, or native-service acceptance from source tests.

The landing assessment scopes those broader investigations separately. Resulting-source review, affected real-state flow tests, built-CLI refusal/IPC proof, unchanged main-owned restoration code, and exact-head CI establish the bounded reporting change; no live operator Gateway or retained investigation fixture is used.
```
