```text
## What Problem This Solves

Adopts fs-safe 0.13.1 while keeping attachment staging, migration claims, Memory Wiki rollback, and completion installation working with native filesystem operations.

## User Impact

Supported installations select the native helper automatically, so atomic moves preserve competing destinations and Worker-backed operations remain quiet during normal execution and error cleanup. Explicit native-mode settings and sealed workers' native-off policy remain honored.

Maintainer decision: retain atomic no-clobber semantics and accept the documented need for operator intervention when native support is disabled or absent. With effective native mode `off`, or a missing helper in `auto`, a no-clobber move to an absent destination rejects with `helper-unavailable` (`native no-replace move is unavailable`). Compiled-package tests verify unchanged source bytes and no destination file. An existing destination instead returns `already-exists`; these are separate outcomes.

Operator recovery: change the effective explicit override to `auto` or remove it, install OpenClaw with optional platform dependencies enabled on a supported runtime/filesystem, then restart and retry. Unsupported runtimes need a supported environment for these operations. No unsafe fallback or automatic mode override is added. The [platform-defaults documentation](https://github.com/openclaw/openclaw/blob/6ed8ada97f4650410a297a8501fa409e62523b79/docs/gateway/security/secure-file-operations.md#platform-defaults) records the modes, supported helpers, and refusal behavior.

The upstream descriptor fix covers normal and error closure; descriptor reclamation after forced `Worker.terminate()` remains unsupported.

Missing or unusable attachment names stay omitted, and media without a usable original basename retains its UUID-only storage key.

## Why This Change Was Made

Pins all four consumers to the [verified 0.13.1 release](https://github.com/openclaw/fs-safe/releases/tag/v0.13.1), including the native descriptor-ownership correction found during adoption. Removes both implicit native-off defaults and the write-error decorator now supplied by fs-safe. The generated lockfile retains exact native package edges; eight version-specific cooldown exceptions expire seven days after actual publication.

Fault-injection tests now observe guarded publication and Root operations, retaining collision, authority, cancellation, content, durability, and ownership-aware cleanup assertions. Linux staging replacements keep the original inode open so immediate reuse cannot defeat the intended identity race. Temp-root tests exercise the real secure resolver; diagnostic fixtures isolate logging from their mocked platform; Fish completion tests assert shell-quoted paths. No production logging or shell behavior changes were needed.

Main's OnePassword publication preparation, bundled-plugin deferrals, catalog entries, packaged IMAP regression, and current publisher-inventory equality checks remain intact.
```
