## Fix PR #166549 description (by ly85206559, opened 2026-10-07T09:48:43Z)

```text
## What Problem This Solves

Terminal table sizing measures a multiline cell as if all its visible lines were one line. In `openclaw plugins list`, a source plus description can consume width needed by the Name column and unnecessarily wrap an otherwise fitting plugin name.

## User Impact

At 122 terminal columns, a plugin with a 40-character name and a 30-character source/description currently splits its name 35+5 despite enough room for the widest source line. After this change, the name stays together while the description remains on its own line. Ordinary single-line, JSON and verbose output are unchanged.

## Why This Change Was Made

Measure natural header/cell width using the existing renderer's logical lines and their maximum visible width. Reusing its ANSI-aware line handling keeps CR/LF/CRLF, color and OSC payload boundaries consistent; `visibleWidth` and the shared ANSI parser are not changed. This is one sizing defect, not a command-specific width override.
