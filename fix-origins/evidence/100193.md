## Problem

Full Release Validation's published-driver compatibility lane for `2026.9.3 → candidate` deterministically refused candidate validation with `managed-service-preflight`.

The shipped 2026.9.2/2026.9.3 updater handoff predates `serviceManagerUid`. After that updater stops a Linux native service, systemd may collect the unit before the candidate reinspects it. Candidate validation then lacks the manager boundary needed to load the collected unit and treats the managed service as unavailable.

## Solution

For a verified Linux handoff that is already stopped, has a captured service environment, and omits the newer manager UID, retain the running installed updater account as the native manager boundary. Explicit recorded manager identity continues to take precedence.

This is limited to legacy stopped handoffs under the existing current-authority assertion.
