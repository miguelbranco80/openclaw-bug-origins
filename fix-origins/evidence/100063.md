* fix(agents): carry isolated CLI completion turns into the next resume

- A preserved inter-session turn that runs outside the bound native CLI
  session reports its prompt and reply; the binding owner stores them on
  that binding, bounded like other context blocks, only when the auth
  identity matches.
- The next turn that resumes the bound session prepends them once as a
  marked context block; any completed turn in that session consumes them,
  and a fresh session recovers them from saved history instead.
- The completion turn's tool projection, MCP configuration, and loopback
  grant are unchanged.
- A real-seam regression covers continuity and denial; store guard,
  resume-context order, and chat-history dedupe tests cover the new
  binding field.
- The Claude CLI Gateway live announce probe now sends one more requester
  turn and checks Claude's transcript for the session it resumed.
- CLI backend and sub-agent tool policy docs describe the contract.

* fix(agents): replay carried CLI exchanges only under the history account boundary

- The resume renderer prepends pending completion exchanges only when the turn holds the CLI history writer, the authority that already gates saved-history recovery
- Settlement keeps no exchange for a binding without an auth epoch (opaque native login)
- Regression covers a named account (carried once), an opaque native login (nothing kept) and an identity-less login whose token is replaced (withheld and dropped)
- The live continuity probe expects the exchange only when the requester's history boundary is known
- Docs state the account requirement

* fix(agents): carry completion replies from the canonical transcript

- Drop the persisted unseenTurns binding field, its settlement
  (settlePreservedCliSessionTurn) and the cliUnseenTurn run meta; the
  native binding contract is back to main's
- Derive the carried context at resume time from the requester transcript:
  completion replies saved after the bound session's last ordinary Claude
  reply, recognized by their announce run id (announce:) or by a saved user
  row with completion provenance, newest 8, each bounded like context JSON
- Replay still requires the turn's CLI history writer; without it the
  session-gap note now counts those completion turns instead of treating
  the completion reply as the last turn the session saw
- Add isAnnounceIdempotencyKey next to buildAnnounceIdempotencyKey
- Regression harness mirrors the Gateway: completions run under the
  announce key and save no user row; credential replacement covers a named
  account as well as an identity-less login
- Move the transcript-derivation unit test to
  session-history.preserved-turns.test.ts (line cap)

* fix(agents): name carried completion turns as delivered events

- Label the carried block as completion events delivered in a separate
  session, each with the reply sent then, and give each record its
  source tool; with only a bare reply, installed Claude answered the
  next message as if no completion had arrived
- Read the transcript run id with asOptionalRecord
- Keep the preserved-turn check inside session-history; input-provenance
  is unchanged
- Publish the runtime config snapshot in the regression harness, as the
  sibling attempt tests do since #169714
- Pin the newest-8 bound in the preserved-turns test

* test(gateway): match the carried completion record in the live announce probe

The live CLI-backend announce probe searched the resumed Claude session's
user turns for the inter-session prompt envelope. A completion saved without
a user row renders a reply-only record, so the authorized branch failed even
when the resumed session received the result; when the handoff resumed the
bound session instead, the probe matched the handoff prompt itself.

Parse the marked context blocks of the follow-up turn and match the record's
source and reply. Whether the handoff resumed the bound session (prompt drift
only) or ran in its own session (an MCP hash change) is recorded, not
asserted: the follow-up turn owes the record either way.

* fix(agents): describe carried completions without naming where they ran

A completion handoff resumes the requester's bound Claude session when only
prompt content drifted, and runs in its own session when its MCP projection
hashes differently. The transcript does not record which one happened, yet
the carried-completion label told Claude the events arrived in a separate
session, and the session-gap note for a withheld login said they occurred
outside this session. Both were wrong in the resumed case.

Say what is known: the completion events were recorded in the conversation
since the session's last reply here, and the session may already hold some
of them. The gap note counts preserved turns with the same wording, and the
prompt-text stripper recognizes it like the existing notes. The account gate
and the bounded carry are unchanged.

* fix(agents): simplify resumed Claude completion context

Keep completion recovery in the canonical transcript owner, reuse bounded context rendering, and preserve account-authorized replay. Retain focused history, renderer, and import regressions; remove duplicate live proof scaffolding. Mark historical facts and preserve original user transcript text.

## What Problem This Solves

A Claude CLI requester can announce a completed sub-agent's result, then resume an older native session on the next user turn and claim that the child has not reported back.

## User Impact

The next resumed turn receives recorded completion exchanges when its existing history account boundary permits replay. When content is withheld, the turn receives a metadata-only gap notice that includes those completions. Tool restrictions and account boundaries stay in place.

## Why This Change Was Made

The CLI history owner reads pending completion exchanges from the canonical transcript, distinguishing ordinary replies, state-preserving handoffs, and background refreshes. An ordinary reply consumes the carry. The newest eight exchanges use the existing context JSON sanitizer and its 2,000-character string limit. The renderer requires the existing history writer; the existing transport revalidates that authority immediately before disclosure. No parallel store, schema change, or new configuration is introduced.

The wording covers both isolated and already-resumed completion turns, and tells the model to verify current facts before acting on historical records. The original user prompt remains the stored transcript input, and native-history import strips the marked context.
