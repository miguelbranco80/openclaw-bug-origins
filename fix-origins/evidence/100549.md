## What Problem This Solves

Fixes: the Control UI model picker lists every Claude model twice, both labelled "Claude CLI · native", after `openclaw onboard` sets up Claude CLI. `openclaw models list` without a running Gateway shows the same duplicates.

## User Impact

People who chose Claude CLI during onboarding now see each Claude model once: the configured `anthropic/*` row, which keeps its alias, its Default tag and the Claude CLI route label. API rows and Claude CLI rows stay separate, and `claude-cli/*` models you haven't configured (for example Haiku 4.5) still appear. Standalone `openclaw models list --refresh` lists the same rows as the picker.

## Why This Change Was Made

Onboarding pins each `anthropic/claude-*` model to `agentRuntime: claude-cli`. That pin is deliberate: without it, gateway turns fell through to Anthropic API billing (#82546, #84374), and Doctor canonicalizes `claude-cli/*` refs to `anthropic/*` plus the pin. The bundled Claude CLI catalog still publishes `claude-cli/<same model>`, so `models.list` returned two rows for one model on one route.

The `models.list` read (shared by `models.list`, `chat.metadata` and `openclaw models list`) now drops a `<cli-runtime>/<model>` row when the canonical `<modelProvider>/<model>` row is published on that runtime **and** config pins it there (`resolveModelRuntimePolicy`).

### Twin routes come from the catalog owner's registry

Which rows are twins is plugin policy: the CLI backend `modelProvider` bindings and the provider's catalog model id (`resolveProviderModelCatalogId`). Both are resolved from the same registry that decides availability:

- `createModelCatalogDecisions` exposes the CLI backend bindings it already resolves from the owner's `pluginRegistry` as `cliRuntimeBindings`.
- `resolveCliRuntimeTwinRoute` runs during preparation, inside `prepareEntry`, which runs in the owner's registry scope. It maps a `claude-cli/*` row to its canonical provider, resolves the catalog model id, and reads the config pin with the runtime id normalized (so a padded or mixed-case ` Claude-CLI ` pin still matches).
- The read path stays a pure projection. `omitCliRuntimeAliasTwins` only compares the prepared twin routes with each row's own `agentRuntime`; it calls no plugin or registry code. This keeps the Gateway and the standalone CLI (whose ambient registry differs from the owner's, see #166361) on the same answer.

### Selection policies keep the alias

A `claude-cli/*` row stays when some selection policy allows it but not its `anthropic/*` twin. The policies checked are the agent's manual model policy and every `gateway.roles.definitions[*].modelPolicy`, prepared once with the owner's manifest metadata. So an operator role or agent policy that allows only `claude-cli/*` still sees those rows and can select them.

These are left alone too:
- canonical rows on Claude CLI only because of a session runtime override. Choosing that row (or Default) resets to the configured route, so the CLI twin is still a different choice;
- rows whose canonical twin runs on another runtime, such as the API route;
- the `all` inventory view.

No selected-row exception is needed. Session display identity already maps CLI runtime refs to their canonical provider (`resolveSessionDisplayModelIdentityRefCached`, `src/gateway/session-utils-model.ts`), so a session on `claude-cli/claude-opus-5` renders as `anthropic/claude-opus-5` and the picker checks that row.

This keeps #153707's invariant (API and Claude CLI routes stay distinguishable) and removes the second copy of the same route. The CLI wizard picker already hides CLI runtime providers (`createModelPickerVisibleProviderPredicate`); only `models.list` was missing the canonical collapse.

+/**
+ * Resolves an entry's twin route during owner-scoped preparation; model-id equivalence is plugin
+ * policy, so reads must not recompute it. A runtime chosen only by a session override has no
+ * twin: choosing that canonical row can reset to a different configured route.
+ */
+export function resolveCliRuntimeTwinRoute(
+  entry: { provider: string; id: string },
+  scope: {
+    config: OpenClawConfig;
+    agentId: string;
+    cliRuntimeBindings: readonly { provider: string; runtime: string }[];
+  },
+): CliRuntimeTwinRoute | undefined {
+  const provider = normalizeProviderId(entry.provider);
+  const aliasOf = scope.cliRuntimeBindings.find(({ runtime }) => runtime === provider)?.provider;
+  const runtime = aliasOf
+    ? provider
+    : normalizeOptionalAgentRuntimeId(
+        resolveModelRuntimePolicy({
+          config: scope.config,
+          agentId: scope.agentId,
+          provider: entry.provider,
+          modelId: entry.id,
+        }).policy?.id,
+      );
+  if (!runtime || !scope.cliRuntimeBindings.some((binding) => binding.runtime === runtime)) {
+    return undefined;
+  }

+  const modelId =
