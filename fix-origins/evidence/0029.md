## Fix message body

```text
* fix(ui): stop iPhone Safari offering contact AutoFill in the chat composer

The chat composer textarea was named only by aria-label. Safari AutoFill
reads a field's label element and, when there is none, guesses the field
type from the visible page text around it; aria-label and
autocomplete="off" do not stop that guess. While a reply streams, its text
sits right before the composer with no control in between, so an everyday
word such as "name" or "address" made Safari show AutoFill Contact over
the iPhone keyboard.

Name the textarea with a visually hidden label element instead. Its
accessible name stays "Chat composer". Scripts that selected the textarea
by its aria-label now select it by its place in the composer.

* fix(ui): keep the chat composer's aria-label beside the AutoFill label

The mention editor copies the textarea's aria-label onto its CodeMirror
textbox, and the composer draft-sizing browser test asserts it, so removing
aria-label left the mention editor unnamed. Keep aria-label as the accessible
name and hide the label element, which only Safari AutoFill needs, from
assistive technology. The script selectors go back to the aria-label.

* fix(ui): shorten the chat composer label id to fit the chat boot budget

The composer input id only has to be unique per pane, so the shorter
suffix is enough. It keeps the chat boot JS gzip growth inside the 64 B
build variance allowed while the base is over its cap.
```

## Fix PR #199090 description (by daniel-lxs, opened 2026-11-14T18:33:45Z)

```text
Fixes #199088

## What Problem This Solves

Fixes: iPhone Safari shows "AutoFill Contact" over the keyboard, with the user's own name or email as the suggestion, when they tap the chat composer while a nearby message contains words like "name", "email" or "address".

## User Impact

User impact: on iPhone Safari the chat composer opens the normal keyboard with typing suggestions, and no longer offers the user's contact card. The composer's accessible name stays "Chat composer", including in the mention editor.

## Why This Change Was Made

Safari AutoFill reads a field's `<label>` element, and when there is none it guesses the field type from the visible page text around the field; `aria-label` and `autocomplete="off"` do not stop that guess. The composer textarea had only an `aria-label`, and while a reply streams its text sits directly before the composer, so contact-like words in it made Safari treat the composer as a contact field.

The textarea gets a `<label for>` that Safari reads instead of the surrounding text. The label is visually hidden and hidden from assistive technology: `aria-label` stays the accessible name, which the mention editor also copies onto its own textbox.

## Evidence

iOS 27 Simulator, Safari, with a made-up My Info card and the Control UI on the repo's mocked Gateway. Same chat state in both shots: an assistant reply containing "name on the account… work address" is still streaming, and the composer is focused.
```
