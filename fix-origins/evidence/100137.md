## What Problem This Solves

Fixes excessive SQLite work on ordinary chat turns after proactive Usage projections were introduced in #169660. Every transcript publication could acquire and release a durable refresh lock and rescan transcript pages even when no Usage report was open.

## User Impact

Usage projections remain proactive, and an overview read flushes pending publication work so completed turn usage is immediately available. Startup backfills retain their existing nonblocking partial-report behavior. No configuration, schema, retention, or update migration changes.

## Why This Change Was Made

The existing usage owner now coalesces publications for 100 ms, skips explicit user/metadata-only publications, and resumes SQLite scans after the previous sequence. It reads the transcript owner's existing rewrite watermark once; rewrites, rewinds, and branch changes rebuild visible ancestry. Each payload page is decoded once and retained only as navigation and small usage contributions.

Cache refresh exclusion belongs to the Gateway process. A process-local reservation replaces lock discovery/acquire/release SQL; the writer atomically upserts the checkpoint and changed month partitions. Incognito keeps its separate compute-owned locking. Usage-only writes continue to publish no session-fact invalidations. The unused lock-status worker API is deleted.

Removed checks and accepted edges:

- Durable lock PID/nonce discovery and release recovery: unsupported simultaneous foreign cache writers are not coordinated; the Gateway owns the database.
- Previous-envelope compare-and-swap: one refresh reservation owns these derived writes; explicit deletion still drains the retained writer.
- Repeated anchor, navigation/payload, post-scan metadata, and tail rereads: a concurrent rewrite may briefly leave a stale derived projection; its next publication rebuilds it using the existing rewrite watermark.
- Full-cache pruning on an incremental refresh: deletion/topology and full discovery retain pruning ownership.
