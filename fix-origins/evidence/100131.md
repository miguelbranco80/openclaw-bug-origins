## Fix message body

```text
fix(automation): reject an empty --command on edit instead of silently keeping the old one

`automation edit --command ''` (or a whitespace-only command) reported success but left the previously scheduled command in place, so the user thought the job had changed when it had not. An empty or whitespace-only command is now rejected with the same validation used when creating a job, and nothing is changed. Metadata-only edits and real command replacements work as before.

Proof: built CLI. On main, editing with an empty or whitespace command reported success and kept the old command. With this change both are rejected and the command and name are unchanged; metadata-only edits and byte-preserving replacements still work.

Thanks @zhangguiping-xydt.

Co-authored-by: Ayaan Zaidi <hi@obviy.us>
```
