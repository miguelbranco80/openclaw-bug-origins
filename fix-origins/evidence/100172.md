Related: #142095, #142679, #143463.

## What Problem This Solves

Fixes an issue where users opening the cloud operating-system picker could not see macOS or Windows choices when the installed Crabbox binary was too old or its version could not be verified. The same omission left Cloud Workers settings without an explanation or upgrade path.

## Why This Change Was Made

Keep provider-advertised unavailable operating systems in the catalog with a bounded, optional repair explanation. New Session, Move, and Cloud Workers settings show those choices disabled; session pickers wrap the explanation below the OS name. Provider version requirements, machine filtering, and provisioning rejection remain enforced. The generic catalog contract carries availability; Crabbox owns its version policy.

This intentionally expands discovery responses to include unavailable choices. Catalog consumers should honor the optional `disabledReason`; the maintained pickers are updated together and allocation checks remain independent. No configuration, stored record, SQLite schema, or persisted default changes, so no data migration is required.

## User Impact

Users can see why an OS is unavailable and that upgrading Crabbox and restarting the Gateway enables supported choices. Linux selection and dispatch retain their existing behavior. Configured provider defaults remain intact.
