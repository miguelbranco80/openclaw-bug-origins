## The bug (from the fix-origins reader)
- Origin: never-worked (confidence high)
- Fix: fix: keep large workspace recovery packs off the Gateway thread (#200623)
- What the user saw: Connected clients could become temporarily unresponsive while the Gateway reconciled a large managed workspace.
- What the fix does: The fix prepares a transferable copy of the rollback pack in the Git worker, sends it to SQLite outside the serialized command, and moves oversized mutation diagnostics into the SQLite worker.
- What in the causing PR was wrong: The worker migration added `const capturedMutation = structuredClone(mutation);` and passed `mutation: capturedMutation` into `localWorkspace.mutate`, so the Gateway copied the entire rollback pack and serialized it before dispatch.
- Reasoning: The migration replaced a direct SQLite write with a worker command that carried the existing `journal_pack: journal.basePack` field, and the SQLite client at that commit synchronously serialized the entire command input before dispatch. The worker publication path therefore processed the full pack on the Gateway thread from its first version, and later compression changes retained that cost.
