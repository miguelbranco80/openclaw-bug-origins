- Origin: never-worked (confidence high)
- Fix: fix(cli): emit JSON errors for invalid config output flags (#159760)
- What the user saw: Running `config patch` or `config unset` with `--json` and without `--dry-run` exited with status 1 and printed a diagnostic to stderr, leaving stdout empty.
- What the fix does: The fix makes `config patch` and `config unset` emit the standard JSON failure envelope when `--json` is used without `--dry-run`.
- What in the causing PR was wrong: The new `onError: (err) =>` callback called `defaultRuntime.writeJson(formatCliJsonFailure(err))`, but the config mutation handler caught these usage errors and exited before that callback could run.
- Reasoning: I checked #124849 and its parent and confirmed that both commands already caught this usage error locally, where the handler wrote JSON only if `dryRun && json` and otherwise printed to stderr and exited. #124849 introduced the documented JSON failure contract but left that handler unchanged, so these invocations fell short of the contract from the day it shipped.
