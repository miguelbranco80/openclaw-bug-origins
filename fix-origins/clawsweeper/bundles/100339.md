## The bug (from the fix-origins reader)
- Origin: regression (confidence high)
- Fix: fix(doctor): defer idle transcript bookkeeping while agents are active (#185838)
- What the user saw: `openclaw doctor --non-interactive` could exit with a database-in-use error on healthy transcript history when one configured agent was idle and another held a writer lease.
- What the fix does: Doctor now checks for active writers across all agents and defers migration cursor bookkeeping while any writer is active, while still requiring exclusive maintenance for actual repairs.
- What in the causing PR was wrong: The diff added `return !hasActiveAgentDatabaseLease(params.agentId, params.env);` and `await withAgentDatabaseMaintenanceLease({ env }, async () => {`, so an idle agent could trigger a global maintenance request for cursor bookkeeping while another agent held a writer lease.
- Reasoning: The parent already ran the historical transcript migration and could record completion on the idle agent's database while another agent held a lease. PR #133563 paired a per-agent preflight with an existing global maintenance guard, creating the false refusal, and I checked that the later PostgreSQL rewrite preserved the same predicate for native databases.
