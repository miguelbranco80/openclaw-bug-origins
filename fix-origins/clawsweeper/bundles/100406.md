# Rank 100406: fix #187197 <- cause #148857

## The bug (from the fix-origins reader)
- Origin: regression (confidence high)
- Fix: fix(backup): give each SQLite header probe batch its own deadline (#187197)
- What the user saw: When the state directory contained enough readable files to exceed the probe deadline, `openclaw backup create` stopped with a SQLite detection error and produced no archive.
- What the fix does: The fix probes SQLite headers in batches of at most 4,096 paths, gives each batch its own 10-second deadline, and reports the underlying error if a batch fails.
- What in the causing PR was wrong: Backup discovery added `probeSqliteDatabaseHeaders(probePaths)`, and the helper sent the entire deduplicated list to one `spawnSync` with `input: JSON.stringify(paths)` and `timeout: 10_000`.
- Reasoning: I checked the parent of #148857 and confirmed that existing backup discovery classified SQLite candidates by filename, so ordinary files could be backed up without passing through a timed header scan. #148857 added a single probe with a fixed deadline to that existing backup path, and #183476 kept the same workload and deadline when it moved the probe to a declared worker. The fix bundle records two timeouts before batching and two verified archives afterward using the same large file set.
