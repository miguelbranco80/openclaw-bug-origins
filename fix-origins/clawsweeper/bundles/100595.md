- Fix: fix(telegram): preserve webhook delivery on 2026.9.6 hosts (#159844)
- What the user saw: After updating the separately installed Telegram plugin on OpenClaw 2026.9.6, operators stopped receiving Telegram messages through their existing webhook endpoint.
- What the fix does: The fix restores Telegram’s per-account webhook listener on 2026.9.6, packages the helpers needed on that host, and preserves Gateway-owned listeners on newer hosts.
- What in the causing PR was wrong: The refactor removed `listenHttpServer({ server, port, host })`, delegated the legacy port to `registerPluginHttpRoute({ ... legacyListener: ... })`, and added a named import of `getWebhookLegacyListener` that the 2026.9.6 host did not export.
- Reasoning: I checked the 2026.9.6 release code and the refactor’s parent, where Telegram bound its own HTTP listener and acknowledged callbacks after durable admission. The refactor removed that listener and relied on Gateway listener support and an SDK export absent from the 2026.9.6 host, breaking an existing webhook setup.
