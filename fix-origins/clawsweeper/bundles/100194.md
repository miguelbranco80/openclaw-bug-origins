## The bug (from the fix-origins reader)
- Origin: regression (confidence high)
- Fix: fix: close Discord gateway socket when late startup fails (#184033)
- What the user saw: If a restart overtook slow Discord startup, the Gateway process could hang during shutdown because a Discord connection stayed open.
- What the fix does: Discord startup now disconnects the gateway socket and disposes any created supervisor if registration or presence setup fails, while preserving the original error.
- What in the causing PR was wrong: The migration added `const scheduler = params.scheduler.scope();` to Discord presence setup after socket registration, and the new `scope()` calls `assertOpen()`, which throws `Plugin service scheduler is closed` after account retirement.
- Reasoning: I checked the scheduler migration and its parent: the old presence setup used a local timer, returned the socket to the provider, and let the existing lifecycle disconnect it on an already-aborted signal. The migration made account abort close the scheduler, so late presence setup could throw before handing off the socket. The fix also covers the older cleanup gap when registration itself rejects.
