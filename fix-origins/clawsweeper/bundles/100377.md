# Rank 100377: fix #149354 <- cause #149284

## The bug (from the fix-origins reader)
- Origin: regression (confidence high)
- Fix: fix(browser): preserve running browsers and locked profile data (#149354)
- What the user saw: The next browser action could restart a healthy managed Chrome after a slow startup and close its open tabs.
- What the fix does: The fix gives startup and subsequent managed Chrome operations the same readiness allowance, propagates cancellation, and preserves profile data when browser ownership is uncertain.
- What in the causing PR was wrong: Changing `CDP_READY_AFTER_LAUNCH_MAX_TIMEOUT_MS` from `250` to `1500` let startup accept responses that the unchanged 300 ms HTTP probe on the next operation would time out on, triggering a restart.
- Reasoning: The parent code already reused a running Chrome when its probes passed, and startup readiness had a 250 ms cap within the next operation's 300 ms HTTP budget. PR #149284 widened startup alone, so a 750 ms response could now produce a successful start followed by an unnecessary restart. The fix extends the existing 750 ms startup test to cover the next operation and assert that the same process survives.
