## The bug (from the fix-origins reader)
- Origin: regression (confidence medium)
- Fix: fix(gateway): publish node reapproval with committed pairing facts
- What the user saw: A node could lose its live gateway session during a successful reapproval and miss the approval notification.
- What the fix does: The fix uses the worker’s commit receipt to update the live node’s permissions and pairing generation before registry readers can reconcile the session.
- What in the causing PR was wrong: The worker migration added `mutation.publish(receipt)` to a callback registered through `publication.servicePending(install)`, allowing a binding reader to see the committed generation before the approval handler updated the live session.
- Reasoning: I checked the migration’s parent, where approval and the follow-up binding read used local database access and an existing test verified that the same connection received the approval event and could republish its inventory. The worker migration let readers observe the committed generation while the handler was still awaiting approval or its follow-up read, so reconciliation could retire the connection as stale. The fix’s new test covers reconciliation before worker reply delivery, although the available history does not establish when that timing first occurred in production.
