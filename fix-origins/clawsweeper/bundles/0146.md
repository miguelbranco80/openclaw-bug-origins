## The bug (from the fix-origins reader)
- Origin: never-worked (confidence high)
- Fix: fix(openai): ChatGPT sign-in fails when port 8080 is already in use (#191508)
- What the user saw: Sign in with ChatGPT failed before opening the browser when another app was already using port 8080 on IPv4 loopback.
- What the fix does: The fix binds the OAuth callback to an available loopback port and uses the resulting redirect URI for both authorization and token exchange.
- What in the causing PR was wrong: The initial implementation called `server.listen(8080, "127.0.0.1", resolve);`, so the sign-in callback could not start if another app already held that address and port.
- Reasoning: The introducing diff added both the fixed port 8080 redirect URI and a listener that required that same port, so the failure was present at launch on setups where the port was occupied. The later move to the shared callback server kept the same redirect URI and IPv4 bind, preserving the collision.
