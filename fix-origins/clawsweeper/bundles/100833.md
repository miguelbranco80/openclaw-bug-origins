## The bug (from the fix-origins reader)
- Origin: never-worked (confidence high)
- Fix: fix(ui): preserve menu focus when drawer gestures load
- What the user saw: If swipe support loaded while the mobile sidebar roster menu was open, the menu lost keyboard focus and the first Escape press could dismiss an unrelated tooltip.
- What the fix does: The fix moves initial drawer focus into the shell’s open transition so attaching gesture listeners preserves the active menu item.
- What in the causing PR was wrong: The new gesture runtime’s `connect()` ran `if (this.host.navDrawerOpen) { this.opened(); }`, and `opened()` moved focus with `(this.focusable()[0] ?? drawer)?.focus({ preventScroll: true });`.
- Reasoning: I checked the introducing diff and confirmed that the same squash merge added the lazy import and the connection callback that refocused an already-open drawer. The fix’s test isolates that original timing bug by focusing a nested control before connecting the gesture runtime.
