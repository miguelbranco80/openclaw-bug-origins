- Fix: fix(node): reconnect after fallback pairing code expires (#159360)
- What the user saw: Restarting an already paired node with the same `--pair-if-needed` command failed with “Pairing setup code has expired” once the fallback code expired.
- What the fix does: The fix lets `--pair-if-needed` reconnect to the saved Gateway using only the saved device token after the fallback code expires, while explicit pairing and fresh enrollment still reject expired codes.

- Reasoning: Path history identifies #150734 as the commit that introduced `--pair-if-needed` and documented restarting with the same command. I checked the resolver and decoder at that commit and confirmed that expiry threw before the node could reach saved-token authentication, so the post-expiry restart failed from the feature’s first release.
