- What the user saw: Talk stayed connected, but spoken requests sent after setup silently aborted without an agent reply.
- What the fix does: The fix gives each Talk consultation its own detached work scope while preserving suspension and restart admission checks.
- What in the causing PR was wrong: The new HTTP wrapper runs the offer under `await work.track(() => runHttpConnectionRequest(` and closes that scope with `await requestContext(() => work.drain());`, leaving later sideband callbacks with an already-aborted signal.
- Reasoning: I checked the parent of #167697 and confirmed that the existing native Talk path handled delegations after the offer returned, with tests covering successful replies and an HTTP dispatcher that created no per-request work scope. The new wrapper installed an ambient scope and aborted it when the offer finished, while Talk's separate root admission left that scope in place. The fix's regression test reproduces the failure by delivering a delegation from the captured callback context after draining the offer scope.
