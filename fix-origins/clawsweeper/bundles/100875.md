- What the user saw: Chat turns and task lists could fail with “SQLite transaction admission was refused” when a busy Gateway delayed the admission decision.
- What the fix does: The fix keeps SQLite worker admission pending until the host grants or refuses the request.
- What in the causing PR was wrong: The initial implementation set `ADMISSION_TIMEOUT_MS = 5_000`, then used `Atomics.wait(decision, 0, REQUESTED, ADMISSION_TIMEOUT_MS)` and `Atomics.compareExchange(decision, 0, REQUESTED, REFUSED)` to refuse requests the host had yet to decide.
- Reasoning: The introducing diff added the worker admission protocol and its five-second deadline together, so host scheduling delays could cause false refusals from the first version. The path history and the later task-worker diff show that task operations inherited the existing deadline.
