## The bug (from the fix-origins reader)
- Origin: never-worked (confidence medium)
- Fix: fix(ui): keep bounded update and plugin failure text surrogate-safe (#194954)
- What the user saw: A long update failure cause or plugin UI activation error that was cut inside an emoji ended with a broken character in Settings > Updates and in the stored plugin activation report.
- What the fix does: Replaced three raw .slice() truncations (update failure cause, plugin grant error, plugin activation error) with the surrogate-safe truncateUtf16Safe helper.
- What in the causing PR was wrong: The plugin UI runtime's reportActivation was added with `error: formatUiError(error, "Plugin UI activation failed.").slice(0, 512)`, a raw UTF-16 slice that can split a surrogate pair.
- Reasoning: Each truncation was a plain slice from the start, so the defect shipped with the code, not from a later change. The plugin activation slice came in with 6a97159 (#134943) and fef5402 (#179157) only moved it and copied it to the grant-error path; the update overlay's `last.slice(0, MAX_UPDATE_FAILURE_CAUSE_CHARS)` predates the 2026-09-03 shallow graft and its origin was not traced, hence medium confidence for one cause covering both sites.
