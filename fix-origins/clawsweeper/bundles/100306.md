- Origin: never-worked (confidence high)
- Fix: fix: preserve reviewed titles in managed squash merges (#176071)
- What the user saw: A one-commit PR landed with its original generic commit subject even after its title was improved during review.
- What the fix does: The Gateway now sends the current PR title as `commit_title` when it requests a managed squash merge.
- What in the causing PR was wrong: The initial merge payload sent `sha: params.expectedHeadCommit`, `merge_method: params.mergeMethod`, and an optional `commit_message`, leaving `commit_title` unset and allowing GitHub to use the original commit subject.
- Reasoning: The introducing diff already delegated the squash title to GitHub, whose default for an affected one-commit PR could use the original commit subject even if the title had been edited on GitHub. The later metadata-edit feature added an in-tool way to change the title while retaining the same merge behavior, and first-parent history shows the fix was the first commit to send `commit_title` from this handler.
