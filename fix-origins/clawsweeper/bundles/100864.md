- Origin: never-worked (confidence high)
- Fix: fix(update): stop returning exit 0 for detached, unfinished updates (#150799)
- What the user saw: Scripts received exit code 0 from a Gateway-launched `openclaw update` while the detached helper was still running the update.
- What the fix does: The update CLI now exits with code 75 after successfully handing an unfinished update to the detached helper.
- What in the causing PR was wrong: The new handoff function ended with `return true;` after transferring ownership, and its caller handled that result with `throw new UpdateCommandAbort();`, which was caught without setting an exit code.
- Reasoning: The introducing diff added the detached CLI handoff for agent-launched updates, where the previous path refused to stop an ancestor Gateway. I checked that the original successful transfer took the normal CLI exit path without setting an exit status and that the fix changes the process-level test expectation from 0 to 75.
