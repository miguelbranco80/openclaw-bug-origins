## The bug (from the fix-origins reader)
- Origin: regression (confidence high)
- Fix: fix: images pasted while the agent is working disappear after the next tool call
- What the user saw: An image pasted while the agent was working became unavailable to the agent after its next tool call if the image had to be resized.
- What the fix does: The fix sanitizes inline images before checking their saved hashes and counts only newly missing or changed images as additional failures.
- What in the causing PR was wrong: The new replay path called `params.existingImages.filter((image) => [...previous.hashes.values()].some((hashes) => hashes.has(imageHash(image))))` before sanitization, so resized images were discarded when their raw hashes differed from the saved output hashes.
- Reasoning: I checked the causing commit's parent and confirmed that replay passed inline images directly to the loader, which sanitized them on each request. PR #185567 added a filter that compared raw input hashes against saved sanitized output hashes, so an image could reach the model on the first request and be dropped on the next. The fix's test covers that sequence with an inline image above the configured size limit.
