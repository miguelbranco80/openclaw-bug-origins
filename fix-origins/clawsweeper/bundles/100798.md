## The bug (from the fix-origins reader)
- Origin: never-worked (confidence high)
- Fix: fix(agents): fall back to the primary's CLI runtime when the derived utility model has no credential (#157867)
- What the user saw: On Claude CLI-only setups, session digests failed with a missing Anthropic API key error and the observer disabled itself after two attempts.
- What the fix does: Automatically derived utility completions now borrow the primary model’s pinned CLI runtime when the derived model lacks usable provider credentials.
- What in the causing PR was wrong: The new utility preparation returned `provider: selection.provider, model: selection.modelId`, and the isolated runner used `resolveEffectiveAgentRuntime({ cfg: config, provider, modelId: request.model, agentId })` when no override was present, so the derived model could not pick up the primary model’s CLI pin.
- Reasoning: The earlier automatic model derivation selected a separate provider-declared model, and the observer still used API credential preparation before #135711. That PR introduced runtime-aware utility execution, but its dispatch resolved runtime policy against the derived model’s identity, so a CLI pin scoped to the primary was missed from the first release of that routing.
