## The bug (from the fix-origins reader)
- Origin: never-worked (confidence high)
- Fix: fix(gateway): renew identity-less hellos when managed Serve returns (#197967)
- What the user saw: After a brief managed Tailscale Serve outage or a Gateway startup race, the macOS dashboard stayed on the shared token profile (default theme, no pins) until the app was relaunched.
- What the fix does: Made operator hellos sent while no managed Serve route is published subscribe to a next-Serve-publication signal so those connections are closed with 1012 and re-hello with the identity URL once Serve returns.
- What in the causing PR was wrong: resolveControlUiIdentity only set an origin and abort signal `if (published?.mode === "serve")`, otherwise returning undefined with no signal, so a hello sent while Serve was unpublished was never renewed when the route returned (only withdrawal aborted connections).
- Reasoning: control-ui-identity.ts and tailscale-published-origin.ts were both created by 0d2bc80eee0 (#137933) and untouched since; that diff advertises the identity URL only while a Serve route is published and wires an abort signal only for withdrawal/replacement of a published route, with no signal for the unpublished case. The missing reverse renewal thus shipped with the feature.
