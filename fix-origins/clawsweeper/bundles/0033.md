## The bug (from the fix-origins reader)
- Origin: never-worked (confidence high)
- Fix: fix(ui): hide snoozed pinned sessions until wake
- What the user saw: A snoozed session that was pinned kept showing in the Control UI sidebar's Pinned section instead of hiding until its wake time.
- What the fix does: Pinned-section row selection and the pinned-listing predicate now exclude sessions whose snoozedUntil is in the future, re-evaluating on a visible clock until they wake, and the sidebar snapshot carries snoozedUntil.
- What in the causing PR was wrong: The new sidebarPinnedSessionRows filtered pinned rows only by `row && row.archived !== true && !archiveVisibility?.(row.key)`, and isListedInPinnedSection only by `row.archived !== true`, with no snooze check.
- Reasoning: Before #178066, pinning only added a rail shortcut and ordinary list sections applied the status filter that hides snoozed rows (app-sidebar-session-archive-visibility.ts). #178066 introduced the separate Pinned section with its own row selector that handled archive but not snooze, so the Pinned feature shipped with this gap; the fix adds !isSessionSnoozed to exactly those lines.
