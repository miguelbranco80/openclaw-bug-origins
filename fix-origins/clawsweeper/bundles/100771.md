## The bug (from the fix-origins reader)
- Origin: never-worked (confidence high)
- Fix: fix(ui): keep chat and drafts usable when connections fail (#162428)
- What the user saw: On a warm reload, users could see their cached chat disappear behind the sign-in screen when the first Gateway connection attempt failed.
- What the fix does: The fix keeps cached chat, drafts, queued messages, and loaded widgets usable during connection failures and adds account-scoped offline reload and delivery recovery.
- What in the causing PR was wrong: The warm-reload implementation added `const warmConnectPending = initialConnectPending && runtime.warmBoot && !this.loginGatePinned;`, so a transport error made the cached shell ineligible even while the Gateway was still retrying.
- Reasoning: I traced the warm-reload failure to the commit that introduced rendering cached chat before the Gateway connected. In that revision, the Gateway store already kept a retrying first connection in `connecting` while setting `lastError`, which made `initialConnectPending` false and returned the UI to sign-in. The same condition remained in the fix's parent, and the fix adds a test that keeps the warm shell visible through an unreachable Gateway retry.
