# Rank 100227: fix #128320 <- cause #107295

## The bug (from the fix-origins reader)
- Origin: regression (confidence high)
- Fix: fix(qqbot): scope account SecretRef owners (#128320)
- What the user saw: The Gateway could fail to start when a single enabled QQ Bot account's SecretRef pointed to a missing credential.
- What the fix does: The fix assigns default and named QQ Bot SecretRefs to separate account owners so a missing credential affects only its own account.
- What in the causing PR was wrong: The migration replaced `collectConditionalChannelFieldAssignments({ channelKey: "qqbot", field: "clientSecret", … })` with direct `collectSecretInputAssignment({ value: channel[field.field], … })` and `collectSecretInputAssignment({ value: account[field.field], … })` calls that omitted `owner`.
- Reasoning: Before the Tencent package migration, the bundled QQ Bot contract used a shared helper that attached isolatable account owners to active default and named credentials. The migration diff replaced that helper with direct calls that omitted ownership, and the resolver at that commit classified those assignments as `unknown` and rethrew their resolution failures.
