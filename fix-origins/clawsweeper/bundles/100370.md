## The bug (from the fix-origins reader)
- Origin: never-worked (confidence high)
- Fix: fix(sessions): avoid repeated host compaction after native compaction (#168051)
- What the user saw: After Codex compacted its native context, the next turn in an oversized session could show another compaction-start notice and wait for an unnecessary model request.
- What the fix does: Compaction accounting now preserves the host transcript byte latch when Codex compacts only its native context and explicitly clears or refreshes it when host transcript accounting calls for it.
- What in the causing PR was wrong: The diff removed `!isCodexRuntime &&` from the host byte-latch check and carried forward `transcriptByteCompactionLatch: params.transcriptByteCompactionLatch`, so native accounting that omitted the latch could erase it.
- Reasoning: The original byte latch explicitly excluded Codex, and #136533 first enabled it for Codex host-transcript preflight. At that commit, native compaction already called the shared accounting path without a latch, and the session patch merged the resulting undefined value over the stored latch. The defect therefore shipped with Codex latch support.
