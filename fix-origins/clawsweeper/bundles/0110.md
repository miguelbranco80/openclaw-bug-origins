- Origin: never-worked (confidence high)
- Fix: fix(cua): recover failed resource initialization (#192001)
- What the user saw: After a temporary failure creating the CUA resource directory, recording retries and closing the computer execution kept failing with the original error even once the filesystem was repaired.
- What the fix does: Clears the memoized CUA execution-resources promise when initialization rejects so the same execution can retry recording or close.
- What in the causing PR was wrong: The new file added `const resources = () => (resourcesPromise ??= createCuaExecutionResources(options));` and dispose awaited `(await resourcesPromise).dispose(discard)`, so a rejected initialization promise was cached and rethrown forever.
- Reasoning: GraphQL blame beyond the graft shows the memoized `resourcesPromise ??=` line came from the recording feature 079bb341 (#124035, file added), with 94a06613 (#124156) only dropping the options argument; the feature cached rejections from the start. The fix wraps the same promise in a catch that resets it, matching the reported stuck retry/close.
