- What the user saw: Stopping the Gateway could hang while usage backfill was waiting for catalog pricing.
- What the fix does: The fix lets shutdown interrupt the pricing wait so the usage refresh releases its lock before dispatching a worker scan.
- What in the causing PR was wrong: #148709 added `await prepareModelPricingContext(config);` to the pricing fingerprint helper and made the existing refresh await it while holding its lock, without observing the refresh's abort signal.

The worker refactors preserved the new await, and #169660 reused it for startup backfill in the usage sidecar. The fix's test isolates that wait on the later sidecar path, while attribution to the earlier refresh path rests on source inspection.
