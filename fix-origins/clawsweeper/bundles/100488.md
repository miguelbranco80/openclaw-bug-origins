## The bug (from the fix-origins reader)
- Origin: regression (confidence high)
- Fix: fix(ui): restore policy-owned web search checkbox state
- What the user saw: After clearing a stale session override, the Web search checkbox appeared checked even though web search was globally disabled.
- What the fix does: The fix resets the Web search checkbox to the effective policy state before handling the selection.
- What in the causing PR was wrong: The Solid port replaced `.checked=${live(options.checked)}` with `prop:checked={options.checked}`, so the checkbox stopped reconciling Web Awesome’s own toggle when the effective value stayed false.
- Reasoning: PR #121557 added the live checkbox binding and a browser assertion that clearing a stale override leaves the checkbox unchecked. The Solid port removed that binding while retaining the stale-clear behavior, so Web Awesome could leave the checkbox checked because the effective value stayed false throughout the interaction.
