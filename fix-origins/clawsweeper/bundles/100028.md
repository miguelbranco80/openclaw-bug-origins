## The bug (from the fix-origins reader)
- Origin: never-worked (confidence high)
- Fix: fix(ui): keep visited lightbox images loaded when navigating back (#182105)
- What the user saw: Going back to a recently viewed image in a chat lightbox could make it download again.
- What the fix does: The fix keeps each decoded image alive as long as its gallery item stays cached.
- What in the causing PR was wrong: The original gallery ran `await image.decode();` and then `return item;`, so the promise cached by `this.images.set(index, pending);` kept the URL but released its reference to the decoded `Image`.
- Reasoning: The gallery’s first implementation cached the item and swapped the displayed image’s URL on navigation, leaving the previous image resource eligible for garbage collection. I checked that the Gateway already served those attachment URLs with `no-cache` and without validators, so a return visit could require a full download from the start. The later rendition change preserved that cache constraint.
