- Fix: fix(feishu): acknowledge followups during active work (#188100)
- What the user saw: A Feishu or Lark user's /followup could go unacknowledged until the active turn finished, and the next message in the chat could also be held up.
- What the fix does: The fix classifies Feishu commands before turn acquisition, releases the chat lane when a followup hands off to the runtime queue, and settles broadcast observer commands without dispatching them.
- What in the causing PR was wrong: The introducing diff required `turn.kind !== "normal" && turn.authorized && turn.commandName?.toLowerCase() === "followup"` for explicit followup admission, but Feishu supplied command text and authorization without the command metadata needed to satisfy that condition.
- Reasoning: PR #157806 registered /followup and added its busy-turn admission exception in the same commit. At that revision, Feishu's context builder supplied command text and authorization without a typed command, so core could recognize the text as a control command while failing the explicit followup check that let it reach queue admission during active work. Feishu's per-chat durable ingress lane predated /followup and compounded the delay for subsequent messages.
