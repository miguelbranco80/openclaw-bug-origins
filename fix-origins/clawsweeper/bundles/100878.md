- Fix: fix(ui): keep palette typing responsive during model updates (#173100)
- What the user saw: Typing and moving through command palette results could feel sluggish when many models were available.
- What the fix does: The fix caches palette model choices, filters catalog updates by scope, and writes to the native textarea only when its value changes.
- What in the causing PR was wrong: The commit added `...(models ? toCommandPaletteItems(getCommandPaletteModelItems(models)) : []),` inside the palette render path, rebuilding model choices whenever the user moved the active result.
- Reasoning: In the causing commit’s parent, the catalog loader built model rows once per load and keyboard navigation reused those rows from `this.catalogItems`. PR #151022 moved model choice construction into rendering, and the fix’s browser reproduction counted 18,944 model-name reads on ArrowDown before the fix. The later Solid migration introduced a separate textarea binding issue that this fix also addressed.
