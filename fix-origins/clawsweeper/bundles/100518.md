- What the fix does: Backup creation now deduplicates registrations for the same database owner and uses the journal-owning path to preserve committed rows across aliases.
- What in the causing PR was wrong: The diff added `const exact = owners.filter((database) => path.resolve(database.sourcePath) === candidate)` and throws on `if (aliases.length > 1)`, so two registry rows for the same agent whose paths normalize to the same file are counted as conflicting owners.
- Reasoning: I checked the causing commit’s parent, where backup discovered the canonical agent database once from the filesystem and verification selected archive files by path, so a second registry spelling for that database had no effect. PR #146700 switched backup discovery to the captured registry and counted each matching row as an owner, causing the refusal reproduced by the fix’s duplicate-path fixture.
