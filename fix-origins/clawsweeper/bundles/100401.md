- Fix: fix(control-ui): old tabs 404 on lazy chunks for seconds after the Gateway restarts (#163090)
- What the user saw: For several seconds after a Gateway restart, an already-open Control UI tab could get a 404 and fail to open a view it had not yet loaded.
- What the fix does: The fix makes retained asset requests that miss during startup verification wait for the inventory and retry the lookup.
- What in the causing PR was wrong: The introducing diff initialized `let generations: RetainedGeneration[] = [];`, populated it with `generations = await loadCachedGenerations(cacheDir, operation);`, and called `rootState.retainedAssets?.resolveAsset(fileRel)` synchronously, so requests during verification missed.
- Reasoning: The introducing diff added both the retained-asset HTTP fallback and post-ready preparation, so the server could accept requests while the retained generation list was still empty. The #131930 diff reduced startup work but still populated that list only after inventory verification, preserving the startup window that shipped with the feature.
