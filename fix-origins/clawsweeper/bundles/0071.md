# Rank 71: fix #194384 <- cause #181802

## The bug (from the fix-origins reader)
- Origin: never-worked (confidence high)
- Fix: fix(cron): keep one-shot finalization working on PostgreSQL 16 (#194384)
- What the user saw: On PostgreSQL 16, retained one-shot cron jobs could not finish and enabling or disabling a cron job failed with `function json(unknown) does not exist`.
- What the fix does: Added an engine-owned jsonValue helper that casts bound JSON text with ::json on PostgreSQL and uses json(...) on SQLite, and used it in the cron enabled-state update.
- What in the causing PR was wrong: The PostgreSQL port of cron finalization kept `eb.fn<string>("json", [eb.val(enabled ? "true" : "false")])` as the jsonSetPath replacement, emitting json($1), a function PostgreSQL 16 does not have.
- Reasoning: Before e96c704 the cron enabled update used SQLite json_set and could not run on PostgreSQL at all; e96c704 introduced the PostgreSQL path via jsonSetPath but kept the SQLite-only json(...) call for the replacement, which only resolves on PG17+ (SQL/JSON constructor), so the PG16 case shipped broken with the port. I read e96c704's diff and jsonSetPath at that commit, which passes the replacement through as `${replacement}::jsonb`, leaving json($1) in the SQL.
