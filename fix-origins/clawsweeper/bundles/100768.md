## The bug (from the fix-origins reader)
- Origin: never-worked (confidence high)
- Fix: fix(mcp): accept grouped frames in strict stdio clients (#156165)
- What the user saw: The strict MCP client reported a line-size error and disconnected when one stdout read contained valid messages whose combined size exceeded the per-message limit.
- What the fix does: The strict stdio decoder now applies the configured byte limit to each newline-delimited frame and rejects an oversized frame before retaining any of the incoming chunk.
- What in the causing PR was wrong: The original CUA client appended the entire stdout chunk with `this.stdout = Buffer.concat([this.stdout, chunk]);` and checked `if (this.stdout.length > MAX_MCP_LINE_BYTES)` before looking for a newline.
- Reasoning: The diff that introduced the embedded CUA MCP client applied the line-size check to the combined buffer before splitting it, so a pipe read could push the buffer over the limit even when every message fit. I traced that same pre-split check through the buffer optimization, the private decoder extraction, and the move to the core strict client.
