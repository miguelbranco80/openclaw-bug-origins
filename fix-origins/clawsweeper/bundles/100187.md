- Fix: fix(ui): keep toast notifications at the viewport corner (#186040)
- What the user saw: When a background session finished with the command palette open, its toast appeared inside the palette and jumped back to the viewport corner when the palette closed.
- What the fix does: The fix presents the toast host as a manual popover so it keeps its viewport position and responsive offset while remaining usable inside the modal.
- What in the causing PR was wrong: The migration changed the handoff to `modal.container.append(host)` and gave the enclosing open `<dialog>` `scale: 1`, which made the dialog the containing block for the fixed toast.
- Reasoning: The migration's parent already showed background-session completion toasts and handed them to the legacy modal host, whose palette styles applied no persistent transform. The migration moved the fixed toast inside a native dialog with a persistent scale, which explains the reported displacement. The earlier placement was inferred from the source because browser verification was outside the checkout's read-only scope.
