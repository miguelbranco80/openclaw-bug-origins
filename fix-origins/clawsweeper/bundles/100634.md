## The bug (from the fix-origins reader)
- Origin: never-worked (confidence high)
- Fix: fix(acp): allow harness resets from read-only installations (#158551)
- What the user saw: On a read-only installation, ACP harness resets failed with an `EACCES` warning.
- What the fix does: The fix moves default ACPX storage under the Gateway state directory, migrates existing sessions, and limits reset warnings to one per harness per process.
- What in the causing PR was wrong: The new reset hook called `retire()`, which ran `const runtime = await runtimeFor();` without a workspace directory, so ACPX attempted to create `state` under the process working directory.
- Reasoning: I checked the introducing commit and its parent: the parent registered the ACPX service, and #150224 added the native harness reset hooks and their runtime initialization path. From the first version, a reset that initialized the runtime without a workspace fell back to `process.cwd()/state`, which failed when the process was running from a read-only package directory.
