# Rank 11: fix #197698 <- cause #145688

## The bug (from the fix-origins reader)
- Origin: never-worked (confidence medium)
- Fix: fix(runtime): skip unsupported Node runtimes for helper processes (#197698)
- What the user saw: When OpenClaw ran under Bun with an old Node (e.g. 20) earlier on PATH, Node-only helper processes such as Gateway post-ready maintenance crashed with a syntax error on a `using` declaration.
- What the fix does: Made the Node helper resolver fast path and the standalone probe also require isSupportedOpenClawNodeVersion, so unsupported Node installs are skipped in favor of a supported one.
- What in the causing PR was wrong: The new resolver accepted any non-Bun node via `!process.versions.bun && (!requiredFlag || process.allowedNodeEnvironmentFlags.has(requiredFlag))` in both the fast path and the probe, with no check against the supported Node floor.
- Reasoning: The resolver was introduced in #145688 without any version gate, while node-version.mjs and package.json engines at that commit already required Node >=24.16, so it could select an unsupported Node from day one; later commits (#183120, #183493) only moved the same predicate into a generated probe. Medium rather than high because the visible crash also needed compiled code using newer syntax, but the missing check against an already-existing support contract is the defect.
