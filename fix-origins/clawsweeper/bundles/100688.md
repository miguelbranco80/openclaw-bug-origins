- What the user saw: When two transcript writes raced to create a new session store, one could fail with an error saying the store changed and asking for a retry.
- What the fix does: The fix checks synchronously for a missing transcript database, skips cold restoration when it is absent, and lets the normal writer create it.
- What in the causing PR was wrong: The refactor added `source(target.path, target.path)` before the worker metadata read and `if (!source.isCurrent())` afterward, so a database created by another writer during that read was rejected as a changed source.
- Reasoning: I checked the causing commit's parent and found that write preflight read metadata synchronously and returned when there was no archive, and the SDK already had a test asserting that concurrent locked appends finished in order and stored one message. The refactor introduced an asynchronous worker read between capturing and rechecking file identity, and the matcher treats the appearance of a previously absent file as an identity change.
