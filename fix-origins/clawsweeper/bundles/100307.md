## The bug (from the fix-origins reader)
- Origin: regression (confidence high)
- Fix: fix(cron): agent turns stall when running an automation bound to their own conversation (#162683)
- What the user saw: When the agent manually ran an automation tied to the same conversation, its reply stalled for the full wait, 60 seconds by default, and the tool returned without a run outcome.
- What the fix does: The fix makes manual agent-turn automation runs acknowledge immediately when their execution or announced result depends on the calling conversation.
- What in the causing PR was wrong: The new `await context.cron.waitForManualRun(` was gated by `!runQueuesBehindCaller`, but the guard only checked `job.sessionTarget === "main" || resolveCronSessionTargetSessionKey(job.sessionTarget) === callerSessionKey`, missing current-session delivery and named aliases of the caller.
- Reasoning: The causing diff shows that manual runs previously acknowledged as soon as they were enqueued and that #162481 made the agent tool request a bounded completion wait. I checked that named-session canonicalization and serialized current-session delivery predated that change, so the new wait could hold the caller's turn open while the run needed that turn to end.
