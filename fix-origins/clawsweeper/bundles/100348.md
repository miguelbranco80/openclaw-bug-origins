# Rank 100348: fix #170196 <- cause #168859

## The bug (from the fix-origins reader)
- Origin: regression (confidence high)
- Fix: fix(infra): tolerate normal lock release during reclaim (#170196)
- What the user saw: A managed update could fail with `sidecar changed during reclaim policy callback` if another process released the lock while the updater was checking whether it could reclaim it.
- What the fix does: The fix restores retries within the original deadline when a completed reclaim callback finds that the lock sidecar has disappeared, and preserves bounded stdout and stderr from each contention test child.
- What in the causing PR was wrong: The diff replaced the `for (;;) {` retry loop and its catch for `sidecar changed during reclaim policy callback` with a single `const lock = acquireFileLockSync(path, {` call, allowing the error to abort admission when the holder released normally.
- Reasoning: First-parent history and the production diffs confirm that #167051 introduced the bounded retry and that it was present immediately before #168859. The earlier release test expected the contender to acquire the lock after normal release, and #168859 removed both that test case and the error handler that made acquisition possible.
