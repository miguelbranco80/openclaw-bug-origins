- What the user saw: Operators saw Gateway requests stall after commands changed files in large btrfs sandbox workspaces.
- What the fix does: Changed command checkpoints now save an immutable Git result while the guest is paused, with filesystem snapshots reserved for reconciliation.
- What in the causing PR was wrong: For eligible btrfs workspaces, the new command-checkpoint path called `await nativeWorktreeFilesystem.copy(projectionPath, root, options)` to create a snapshot and then removed the capture after checkpoint completion.
- Reasoning: I checked the introducing diff against its parent, where command checkpoints already published changes through `state.synchronize("canonical", { captureRejected: true })` without creating a per-command filesystem snapshot. PR #196662 added snapshot creation and removal to that working path, introducing filesystem-wide transaction work and cleanup contention on btrfs. PR #196727 later narrowed snapshot selection but kept it for large workspaces, the case covered by this fix.
