## The bug (from the fix-origins reader)
- Origin: regression (confidence high)
- Fix: fix(cron): fail closed when sandboxed sessions inherit CLI-backed models (#173419)
- What the user saw: A cron run reported as sandboxed could execute the inherited CLI model's native tools on the gateway host outside Docker.
- What the fix does: The fix rejects every CLI-backed model candidate before process launch when the cron session is sandboxed or requires isolation.
- What in the causing PR was wrong: The diff moved `...(agentConfig?.model ? [{ raw: agentConfig.model, source: "agent" as const }] : []),` below the `params.cfg.agents?.defaults?.subagents?.model` candidate, so a global CLI default could displace a sandbox-compatible agent primary.
- Reasoning: I checked the parent of #58823 and confirmed that cron already used the shared selector, which chose the agent's API-backed primary ahead of the global subagent default and routed it to the embedded runner's sandbox setup. The precedence change sent that same configuration through the existing host CLI path without a sandbox check. This identifies where the inherited-default case regressed, while the origin of the older unguarded CLI path remains unverified.
