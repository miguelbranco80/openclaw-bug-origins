## The bug (from the fix-origins reader)
- Origin: never-worked (confidence high)
- Fix: fix(update): recover when the package publication journal no longer matches the installation (#186355)
- What the user saw: After an external install superseded an interrupted npm update, later CLI or Control UI updates failed with `update-recovery-pending`.
- What the fix does: The fix lets update admission retire an obsolete publication journal with a warning and preserve its recovery evidence once the recorded package generations and published launchers are no longer installed.
- What in the causing PR was wrong: The npm publication journal’s decoder added `descriptor.journalParentIdentity !== journalParentIdentity ||` to the condition that threw `Package publication journal does not match its installation`, so a copied control directory blocked recovery before the updater could determine whether any recorded publication was still installed.
- Reasoning: The earlier admission code only read legacy journals, and #158491 introduced the durable npm publication flow with a strict journal identity check shared by update admission and repair. The later remount fix still required the recorded inodes to match, leaving a copied journal unable to reach settlement even after an external install replaced its package and launchers.
