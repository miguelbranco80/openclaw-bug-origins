# Rank 100113: fix #181474 <- cause #129416

## The bug (from the fix-origins reader)
- Origin: regression (confidence high)
- Fix: fix: validate gateway host literals (#181474)
- What the user saw: On iOS, entering `gateway.example.com:8443` in the manual Gateway Host field left Connect enabled and showed no host-only guidance.
- What the fix does: The shared gateway endpoint builder now adds brackets only to valid IPv6 literals, so manual iOS forms reject hostnames with an embedded port.
- What in the causing PR was wrong: The change to `components.host = self.host.contains(":") && !self.host.hasPrefix("[") ? "[" + self.host + "]" : self.host` wrapped `gateway.example.com:8443` in brackets, allowing it to pass URL construction as though it were IPv6.
- Reasoning: The parent of #129416 shows that manual iOS connections already used the shared builder and stopped when it returned nil, and the builder passed the unbracketed hostname and port directly to URLComponents as the host, which it rejected. The diff for #129416 changed that behavior through broad colon-based bracketing. First-parent history shows that #169875 later added inline guidance and the failing assertion, exposing the existing endpoint regression.
