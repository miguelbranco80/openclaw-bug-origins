## The bug (from the fix-origins reader)
- Origin: never-worked (confidence high)
- Fix: fix(browser): reject replaced native host files before pairing (#155833)
- What the user saw: Chrome extension pairing could succeed with a replacement native-host manifest that had never passed the ownership and permission checks.
- What the fix does: The browser plugin now uses a shared reader that checks and reads native-host artifacts through the same open file descriptor during pairing and registration inspection.
- What in the causing PR was wrong: The original code used `const manifestPath = await validateOwnedFile(params.manifestPath, false);` and later `const parsed: unknown = JSON.parse(await fs.readFile(manifestPath, "utf8"));`, so the read could consume a different file from the one whose ownership and mode were checked.
- Reasoning: The path history and introducing diff show that zero-click Chrome extension pairing shipped with separate manifest validation and read operations. The fix addresses that original gap by tying the ownership and mode checks to the file descriptor used to read the bytes.
