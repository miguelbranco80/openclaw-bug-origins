# Rank 105: fix #191603 <- cause #114819

## The bug (from the fix-origins reader)
- Origin: never-worked (confidence high)
- Fix: fix(memory): match standing intents in unspaced CJK prompts (#191603)
- What the user saw: A standing intent armed with a Chinese, Japanese or Korean term (for example 会议) never fired when the term appeared inside an unspaced CJK sentence, so the reminder was not injected.
- What the fix does: Standing-intent matching adds a second unindexed candidate pass for prompts containing CJK script and matches CJK trigger terms literally (with lowercase and NFC normalization), keeping whole-word matching for other terms.
- What in the causing PR was wrong: The introducing commit matched intents only via whole-word tokens, `text.toLowerCase().match(/[\p{L}\p{N}_-]+/gu)` plus an FTS `match` join and `keywordTokens.every((token) => promptTokens.has(token))`, so a CJK term inside an unspaced run (one token) could never match.
- Reasoning: The full-history listing shows standing intents were introduced in 28630a9a (#114819); its diff (read via gh api) already had the same tokenizeIntentText regex, FTS-gated candidate selection and whole-token comparison that this fix replaces, and later commits only moved or refactored that logic. Since the documented 'any trigger term appears' contract never held for unspaced CJK text, the defect shipped with the feature.
