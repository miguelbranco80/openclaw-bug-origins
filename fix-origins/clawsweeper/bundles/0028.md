- Fix: fix: existing device folders stay disabled for models on the default runtime (#190065)
- What the user saw: New Session disabled Existing folder on a paired device and said it required a worker-turn runtime, even though the selected model used the default OpenClaw runtime.
- What the fix does: The fix publishes the resolved runtime on every model row and keeps implicit runtimes out of explicit session runtime selections.
- What in the causing PR was wrong: The new folder picker gated access on `this.devicePlacementRuntime()?.cloudPlacementExecutionMode !== "worker-turn"`, which disabled the option when the selected model row omitted its implicit OpenClaw runtime.
- Reasoning: The diff for #169722 introduced both existing folders on paired devices and the runtime check that disabled them for explicitly selected models with an omitted runtime. At that commit, I verified that the gateway omitted the implicit OpenClaw runtime from those rows and that the UI resolver read the selected row without a fallback.
