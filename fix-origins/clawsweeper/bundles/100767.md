- Origin: regression (confidence high)
- Fix: fix(macos): preserve Chrome setup across native app upgrades (#153289)
- What the user saw: After upgrading the Gateway dashboard, users running the older Mac app saw Chrome extension status as unavailable and lost the Set up Chrome on this Mac button.
- What the fix does: The fix restores manual Chrome setup when automatic status checks fail and accepts older setup replies while still requiring an installed-profile count in status replies.
- What in the causing PR was wrong: The diff added `const needsSetup = result !== null && (!installed || !result.nativeHostRegistered);`, which hid Setup when the older bridge rejected the status request, and made `installedProfiles: z.number().int().nonnegative(),` mandatory for setup replies that previously omitted it.
- Reasoning: The causing diff shows that the parent dashboard offered Setup without a status check and accepted the three-field reply produced by the existing Swift install handler. PR #153266 gated that existing action on a successful reply and required a new field in the shared parser, breaking compatibility with the older bridge. The release tag was unavailable locally, so the shipped version identification comes from the fix PR.
