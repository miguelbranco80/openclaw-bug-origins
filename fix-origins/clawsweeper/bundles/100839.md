- Origin: regression (confidence medium)
- Fix: fix(agents): avoid stale tool failure replies while waiting for children (#153779)
- What the user saw: The agent displayed an earlier “Exec failed” warning as it paused to wait for child work.
- What the fix does: The fix omits retained tool errors from reply generation on successful yields while preserving them for diagnostics.
- What in the causing PR was wrong: The new `recordSuccess(toolName)` clears `lastToolError` only when `normalizeLowercaseStringOrEmpty(lastToolError.toolName) === normalizeLowercaseStringOrEmpty(toolName)`, so a successful tool call under a different name can leave a stale error for the yield reply.
- Reasoning: I checked that yielding already existed before #126542 and that the previous error tracker cleared a non-mutating failure after a different tool succeeded when no mutation failure remained. The new tracker retained that error and the reply builder could surface it on an otherwise silent pause. The fix's test starts with an already-retained error, so it does not establish which tool events retained the error in the reported session.
