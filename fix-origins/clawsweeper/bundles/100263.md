## The bug (from the fix-origins reader)
- Origin: regression (confidence medium)
- Fix: fix(gateway): Windows Bun Gateway fails schema preflight on busy snapshot cleanup (#169572)
- What the user saw: On native Windows with stock Bun, the Gateway stopped at schema preflight with an EBUSY cleanup error, and `gateway status --deep` failed with a snapshot lease cleanup error.
- What the fix does: The fix defers EBUSY snapshot cleanup after successful reads on runtimes without reliable native SQLite close and makes deep status preserve the underlying removal error.
- What in the causing PR was wrong: The new startup path passed `signal: options.signal` into snapshot preparation, which allocated an owned staging root and made removal failure throw via `else if (ownedRoot) { throw new Error(...) }`.
- Reasoning: I checked the parent of #138986 and confirmed that Gateway schema preflight already read private snapshots and ignored the cleanup return value, so a busy removal could leave the directory pending without aborting preflight. #138986 made that same startup cleanup fatal by passing a signal, while #156265 later made a false cleanup result fatal as well. The history establishes the change in error handling, but I could not verify a successful Windows Bun startup on the earlier revision.
