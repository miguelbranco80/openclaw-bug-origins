# Rank 13: fix #199402 <- cause #142713

## The bug (from the fix-origins reader)
- Origin: regression (confidence medium)
- Fix: fix(plugins): stop loading permissions after inspection fails (#199402)
- What the user saw: In the Control UI plugin settings, the Permissions section kept showing a loading skeleton after the inspection request had failed, next to the error and Try again button.
- What the fix does: Derived the permissions loading flag from the inspection read's pending state and added a `known` flag so a failed inspection shows neither a loading skeleton nor a false empty-settings message.
- What in the causing PR was wrong: In renderAccess it removed `if (props.inspectionError) { return renderRetryError(props.inspectionError, props.onRetryInspection); }`, leaving `if (!props.inspection) { return renderSettingsLoadingSkeleton({ rows: 3, carapace: true }); }`, so a failed inspection showed a permanent loading skeleton under the moved panel-level error banner.
- Reasoning: The original plugin settings view (#135840) checked inspectionError before falling back to the skeleton, so failed inspection rendered a retry error instead of loading; #142713 moved the error to a panel-level banner and dropped that check, and the bare `!inspection -> loading` condition then survived through #149246, #150234 (`{ fields: [], details: skeleton }`), #150235 (`loading: true`) and the Solid port #168758 until this fix. Medium because the Permissions section was reshaped several times after #142713, though the defective condition carried through unchanged.
