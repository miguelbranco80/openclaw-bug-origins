- What the user saw: A plugin tool’s finished answer could end the turn while another tool call had failed or still needed follow-up.
- What the fix does: The fix evaluates tool-authored replies against the finalized batch, keeps sibling failures eligible for model follow-up, and suppresses only the originating turn’s preamble.
- What in the causing PR was wrong: The Codex release check used `state.currentTurnHadNonTerminalDynamicToolResult && !state.currentTurnHadToolAuthoredFinalReply`, so a finished reply could override a sibling result that required the model to continue.
- Reasoning: The diff for #164558 introduced direct delivery of tool-authored replies and the completion rules that hid sibling failures. It also added an embedded-runtime hook that used `context.toolResults.some(...)` to complete the turn on one eligible reply, regardless of the other results. Both paths shipped with the defect in the feature’s first commit.
