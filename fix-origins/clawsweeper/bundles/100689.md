## The bug (from the fix-origins reader)
- Origin: never-worked (confidence high)
- Fix: fix: recover interrupted updates after the original PR closes (#186717)
- What the user saw: After GitHub accepted an update but confirmation was interrupted, recovery could create a replacement PR if the original had closed or report a failure after the branch was deleted or merged.
- What the fix does: The Gateway now verifies and records an interrupted update against its original PR before retrying publication, preserving later local work and allowing explicitly new requests.
- What in the causing PR was wrong: The initial broker matched a closed PR only when `candidate.state === "closed" && candidate.body.includes(params.marker)`, so an accepted update on a PR whose body still held the original request marker fell through to `if (!pullRequestUrl)` and could create a replacement.
- Reasoning: The initial broker already supported pushes to existing open PRs and restart recovery, but its lookup required the current request marker in the body of a closed PR even though pushes left that body intact. I checked the original diff and tests, the requester-recovery change, and the later guest PR feature, which added special handling for imported PRs while the ordinary authorized retry retained the original gap.
