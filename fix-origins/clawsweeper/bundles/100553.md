- 2026-10-23T04:15:04Z jalehman: **Subject inference (`subject-infer.ts`): keeping as-is.**

When the agent passes `subject`, `knowledge_remember` resolves it by exact page ID, title or alias and never guesses. Inference runs only when `subject` is omitted and `infer_subject` is not `false`. It links a claim only when the claim text names exactly one current entity page by exact ID, title or alias, and names no other capitalized name. Bare first names that only prefix a title, two resolved entities, or any competing name leave the claim unlinked.

In the example, "Atlas acquired nimbus." links to Atlas, which is the claim's subject. A claim only ever links to a page its text names, and keyword search still finds the claim through "nimbus".

Removing inference means claims saved without `subject` never appear on entity pages, and the maintenance relink pass links only claims that carry a `source_page`. That would cut what every entity page shows in order to change how a lowercase second name is handled. Claims the deterministic pass leaves unlinked go to the agent through the `knowledge-unlinked-claims` skill, which chooses their subject pages with judgment. This is exact-match identity resolution with deterministic rules, not interpretation of meaning, and I couldn't find the contract cited in the finding in the repository's `AGENTS.md` files or review docs.
