## The bug (from the fix-origins reader)
- Origin: regression (confidence medium)
- Fix: fix: avoid cloning live SQLite inspection snapshots (#188009)
- What the user saw: On a Btrfs host with a large, fragmented live SQLite database, Gateway database writes stalled while a read-only inspection snapshot was being taken.
- What the fix does: Artifact-preserving SQLite inspection copies (sync and async) now use byte copies with clone: "never" instead of reflink/copy-offload, while offline snapshot publication keeps clone-first.
- What in the causing PR was wrong: copySourceFile replaced the plain `copyFileDescriptorSync(source.descriptor, target)` byte copy with `copyRootFileSync({ ..., clone: "auto", ... })`, so artifact-preserving inspection snapshots started reflinking (FICLONE) the live database inode.
- Reasoning: Before #172763 the synchronous inspection copy was a plain descriptor byte copy, which does not hold the source inode in Btrfs clone metadata reservation; #172763 switched it to clone "auto", and the fix's regression test (sync inspection returned a clone/offload transfer) targets exactly that line. The async inspection path got clone "auto" earlier in #162466 (9a0146355c02), and the incident's exact caller and latency attribution are not established in the PR, so confidence is medium.
