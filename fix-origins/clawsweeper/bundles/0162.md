## The bug (from the fix-origins reader)
- Origin: regression (confidence medium)
- Fix: fix(cli): avoid state snapshot for gateway status (#191782)
- What the user saw: `openclaw gateway status` took tens of seconds on large state databases while copying them into a snapshot cache, and killing it could leave a multi-gigabyte partial snapshot behind.
- What the fix does: Dropped artifactPreservingReadOnly from the gateway status plugin-ledger read so status uses the native read-only state connection instead of staging a database snapshot.
- What in the causing PR was wrong: In gatherDaemonStatus, #135862 added `artifactPreservingReadOnly: true,` to the loadInstalledPluginIndexInstallRecords call, routing the status ledger read through withExistingOpenClawStateDatabaseArtifactPreservingReadOnly, which copies the state database ("Copy in a child") before reading.
- Reasoning: The removed line was added by 34a6d38b187f (#135862, sub-commit "preserve state artifacts during status reads"); at that commit the row reader already switched to withExistingOpenClawStateDatabaseArtifactPreservingReadOnly, which copies the database via prepareSqliteReadOnlyLocationSync, whereas before it status used the plain read-only connection. Medium rather than high because the cost depends on database size and the copy was a deliberate choice whose original justification I could not fully assess; it could also be read as a performance improvement.
