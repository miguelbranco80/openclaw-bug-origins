## The bug (from the fix-origins reader)
- Origin: regression (confidence medium)
- Fix: fix(agents): npm-installed Claude CLI fails to launch on Windows (#138504)
- What the user saw: On Windows, agent turns using an npm-installed Claude CLI failed to start and returned no reply.
- What the fix does: The fix resolves Windows npm launchers against the child working directory and passes the actual executable and any required leading arguments to the Claude CLI transport.
- What in the causing PR was wrong: The new plugin runner used `const command = resolveExecutablePath(params.executionCommand, { cwd, env: params.env });` and passed that path to the SDK, bypassing the supervisor that unwrapped Windows npm launchers.
- Reasoning: Before #128131, ordinary Claude turns used the process supervisor, whose Windows adapter resolved npm wrappers and prepended the JavaScript entry point when needed. The SDK refactor replaced that path with generic executable lookup, and #138707 retained that lookup when it switched to direct CLI spawning. The bundle reproduces the failure on the direct transport, but the SDK-era failure is inferred from the code and the report that the original repair targeted that adapter.
