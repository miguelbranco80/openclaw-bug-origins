## The bug (from the fix-origins reader)
- Origin: never-worked (confidence high)
- Fix: fix(codex): retain pending catalog page ownership (#148513)
- What the user saw: When enough other queries ran during a Codex catalog refresh, reopening the same page could start another native read and make the user wait for a page they had already seen.
- What the fix does: The fix tracks pending Codex catalog reads separately from the 32-entry completed-page cache so overlapping calls can share the active read and still receive the last successful page during refresh.
- What in the causing PR was wrong: The new single-flight cache ran `cache.set(key, entry)` and evicted the oldest entry with `cache.delete(oldest.value)` before `return await page`, so it could discard a request that was still running.
- Reasoning: I checked the first single-flight implementation, which replaced direct listing with a bounded map that could evict an unresolved promise and let the next identical query start a second read. The later stale-while-revalidate change kept pending refreshes and their stale pages in that same map, so eviction also interrupted immediate stale-page delivery from the day that behavior shipped.
