# Rank 100457: fix #172579 <- cause #169757

## The bug (from the fix-origins reader)
- Origin: regression (confidence high)
- Fix: fix(gateway): read worktree file-read guard from the session's SQLite source (#172579)
- What the user saw: The Control UI showed “Session workspace changed during file read” when users tried to list or open files in an unchanged managed worktree session.
- What the fix does: The Gateway now uses the session’s captured SQLite read source to recheck worktree ownership during file reads.
- What in the causing PR was wrong: The replacement call `readRetainedSessionEntryFacts({ agentId, path: storePath }, ...)` passed the logical store path to a reader that requires the physical SQLite path.
- Reasoning: The worktree guard already existed, and I verified that immediately before #169757 its fallback resolved the session by key and agent through the Gateway’s normal store lookup. The replacement reader returns undefined when it cannot find a SQLite write token for the supplied path, so passing the logical path made the guard reject an unchanged session.
