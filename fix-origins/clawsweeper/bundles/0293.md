- Origin: never-worked (confidence medium)
- Fix: fix(claude-cli): per-requester MCP servers missing from Claude CLI turns (#191722)
- What the user saw: On Claude CLI turns, a per-requester OAuth or resolver-based MCP server's tools never appeared, even for a connected user, with no log or notice saying why, while the default runtime listed and called them.
- What the fix does: Serves requester-scoped MCP tools on Claude CLI loopback turns through the shared harness owner bound to the turn's verified sender, and lists a refusing sign-in tool with an explicit message on senderless turns.
- What in the causing PR was wrong: The new loopback-bundle-mcp.ts acquired configured MCP with `requesterSenderId: undefined` (commented "Requester-scoped servers need a verified sender, which completions and automations lack"), so per-requester servers were dropped from every Claude CLI turn.
- Reasoning: Per-requester MCP servers never reached Claude CLI: before #172026 the native Claude path resolved OAuth with the operator identity and acquired the runtime without a requester, and only the Codex app-server called materializeRequesterScopedMcpToolsForHarnessRunCore (checked with git grep at 77d9f42c86bf^). #172026 introduced the loopback bridge for configured MCP with an explicit `requesterSenderId: undefined` and docs saying requester-scoped servers "are not offered on these turns", so the gap shipped with the path the fix repairs rather than breaking a working one. Medium confidence because the omission was deliberate and could also be read as a missing feature.
