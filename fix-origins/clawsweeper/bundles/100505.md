## The bug (from the fix-origins reader)
- Origin: regression (confidence high)
- Fix: fix(memory): rebuild reuses cached embeddings instead of evicting them first (#182968)
- What the user saw: A full memory rebuild at cache capacity could send every chunk to the embedding provider again, even when most chunks already had cached embeddings.
- What the fix does: The fix defers embedding cache eviction until the full rebuild is published or discarded and keeps the existing capacity bound for incremental writes.
- What in the causing PR was wrong: The new `persistGeneratedEmbeddings` passed `maxEntries: this.cache.maxEntries` to `upsertMemoryEmbeddingCache`, causing it to evict older vectors before later rebuild batches could read them.
- Reasoning: I checked the causing commit's parent and confirmed that full rebuilds copied cached vectors into the shadow database, read them there, and pruned only after indexing finished. PR #144404 switched rebuilds to reading and writing the same canonical cache and added capacity enforcement to each generated batch write, allowing early misses to evict vectors that later batches would have reused.
