- What the user saw: The chat model picker could snap shut immediately after reopening during a pane update, leaving newly available models out of view.
- What the fix does: The fix requests a pane render after every model-picker toggle so the picker stays open on reopen and shows the refreshed catalog.
- What in the causing PR was wrong: The commit added `?open=${params.open === true}` and a toggle callback that only assigned `state.chatModelPickerOpenSessionKey = open ? state.sessionKey : null;`, allowing a pane render to overwrite a native reopen before its queued toggle ran.
- Reasoning: The parent commit already had a native picker and an end-to-end case that checked that closing and reopening it fetched and displayed newly discovered models. I checked that the causing diff added Lit control of the native `open` attribute while the close callback updated only non-reactive state, so an ordinary pane render could commit the pending closed state before the reopen toggle ran. The fix PR reports reproducing that ordering on the original code and resolving it with the added render request.
