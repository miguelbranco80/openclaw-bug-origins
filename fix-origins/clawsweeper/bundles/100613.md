- Origin: regression (confidence high)
- Fix: fix(tasks): task list fails when metadata overlaps completion (#153371)
- What the user saw: A Gateway task-list request could fail instead of showing the completed task when a metadata write overlapped completion.
- What the fix does: The fix limits strict row checks to recovered publications and uses the write witness to suppress superseded notifications.
- What in the causing PR was wrong: The added `recovery?.bindExpected(pending.publication?.records.get(scope.taskId));` applied the recovery guard to ordinary successful metadata receipts, so `recovery?.assertCurrent();` threw when task completion superseded the receipt.
- Reasoning: The parent already served `tasks.list` and persisted agent-event metadata synchronously, so the list could return a completed task without waiting for a worker receipt. The causing commit moved metadata persistence to a worker and made list reads wait for accepted events, allowing the new recovery guard to turn normal receipt supersession into a request failure. The fix's Gateway test covers that exact ordering.
