- Fix: fix: preserve member agent policy for session creation (#199413)
- What the user saw: An OpenClaw ID member whose membership role excluded an agent could still create, or reset into existence, a session for that agent when linked to a local profile with broader permissions.
- What the fix does: Passes the captured operator run authority into session creation, reset and catalog import so authorizeGatewaySessionCreation uses the membership role policy instead of the linked profile's named role.

- Reasoning: 59b8a114 (#192345) introduced OpenClaw ID membership roles and applied them in resolveOperatorRolePolicy(client) and the run-authority capture, but authorizeGatewaySessionCreation's actor/profileId branch (resolveOperatorRolePolicyForProfile) used by session create/reset never consulted the membership policy, so the cap was missing from creation from the start. Later commits (07c8e14 linking, 4fc7acf member-role definitions) extended the feature without closing this path; confidence is medium because I did not confirm that the member-to-profile link path was reachable exactly as of 59b8a114.
