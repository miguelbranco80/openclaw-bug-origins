- Fix: fix: SQLite snapshot reads fail in EFS-encrypted Windows caches (#190087)
- What the user saw: On affected Windows installations, SQLite snapshot reads failed and Doctor could not detect migrations.
- What the fix does: The fix removes the intermediate copy rename and falls back to a guarded, flushed copy when final snapshot publication returns `EXDEV`.
- What in the causing PR was wrong: The commit added `fs.renameSync(staged, `${location}${suffix}`);` to `publishPreparedCopy`, making even online backups fail when an EFS cache rejects the rename with `EXDEV`.
- Reasoning: The parent already staged online backups in the private user cache, wrote them directly to `database.sqlite`, and adopted them without a rename. The September staging change added a mandatory final rename to that working path, and the October commit moved the same code into the cleanup module. Some copy branches already depended on an earlier rename, which the November fix also removes.
