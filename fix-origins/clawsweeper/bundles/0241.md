- Fix: fix(claude-cli): retain deep descendant answers in any snapshot order (#193453)
- What the user saw: With the Claude CLI runtime, answers from nested subagents or workflows were lost because the turn ended after the root agent's answer when a task snapshot listed a child before its parent.
- What the fix does: Replaced the single-pass background-task hold scan with a fixed-point scan (after recording ownership for the whole snapshot) so children listed before parents still get held.
- What in the causing PR was wrong: Inside the single for-loop over message.tasks it added the gate `(parentTaskId === undefined || input.pendingBackgroundTaskIds.has(parentTaskId) || input.pendingBackgroundTaskIds.has(id))`, so a child seen before its parent in the same snapshot found no held parent and was skipped.
- Reasoning: Before 3d7f8fbf (#182516) nested Agents/Workflows with a parent_task_id were owner=false and never held; that commit introduced holding children of held parents, with the parent-held check evaluated in one pass in snapshot order, which is exactly the ordering defect fixed here. Intervening commits (c93890f, etc.) only renamed calls to tasks.*; the PR body confirms main's scan was single-pass.
