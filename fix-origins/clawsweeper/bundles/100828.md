## The bug (from the fix-origins reader)
- Origin: regression (confidence high)
- Fix: fix(update): finish 2026.9.3 managed upgrades after migration (#148604)
- What the user saw: A managed Git or npm upgrade from 2026.9.3 could stop the Gateway, report “Another update executor owns this installation,” and leave the Gateway stopped.
- What the fix does: The fix lets a verified legacy finalizer use its live parent’s lease for the same installation so it can verify the Gateway restart and publish the upgrade result.
- What in the causing PR was wrong: The grantless finalizer replaced `await finalizeInput(input);` with a path that restores the original lease selectors and calls `const fence = await executor.enter(input.params.result.root ?? input.params.root);`, forcing the child to acquire the installation lease its parent still holds.
- Reasoning: I checked the earlier producer, which sent no executor grant and waited for `result.json`, and the worker immediately before #143905, which ran grantless finalization and wrote that result without acquiring a second installation lease. The #143905 diff routed that existing path through executor admission, where the worker’s PID differed from the lease holder’s PID and the fresh acquisition was refused. The fix bundle reports pre-fix failures and post-fix success for both Git and npm using the real worker and lease store with synthetic legacy input.
