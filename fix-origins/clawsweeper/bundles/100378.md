## The bug (from the fix-origins reader)
- Origin: regression (confidence high)
- Fix: fix(gateway): wait for lifecycle ownership during restart (#146189)
- What the user saw: A supervised Gateway restart could fail repeatedly while another OpenClaw process held lifecycle ownership, leaving the Gateway down after systemd hit its start limit.
- What the fix does: The fix gives Gateway startup a shared five-minute deadline to wait for lifecycle ownership and raises the start limit in generated systemd units.
- What in the causing PR was wrong: The commit put `stateLifecycle = acquireGatewayLifecycleCoordinator({ ... busyTimeoutMs: opts.timeoutMs })` before the existing lock retry loop and immediately threw `new GatewayLockError("failed to acquire gateway state ownership", error)` on contention.
- Reasoning: I checked the causing commit’s parent and confirmed that the existing restart path acquired its locks through a polling loop that could tolerate a briefly held lock. The causing commit added a coordinator ahead of that loop with a zero default SQLite busy timeout, making the same startup path fail immediately on temporary contention. The fix PR reproduced the failure with a separate process holding the coordinator, while the holder in the original WSL2 incident remains unidentified.
