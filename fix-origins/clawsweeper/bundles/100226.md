- What the user saw: A Gateway request to create the first session in a fresh store could fail while a background usage refresh was starting.
- What the fix does: Usage refresh now retains the original absent-store identity so first-session creation can share the same database owner.
- What in the causing PR was wrong: The worker refactor added `const writer = createCacheWriter(options);` during refresh-lock preparation, and the writer called `captureOpenClawAgentDatabaseExecution(options)` without passing the identity of the absent store.

Later changes allowed callers to share an owner with a matching creation identity, but the usage writer still supplied none.
