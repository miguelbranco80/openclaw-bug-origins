- Origin: regression (confidence high)
- Fix: fix: preserve database safety across update Doctor handoffs (#175300)
- What the user saw: An update could keep using a database schema newer than the updater supported after Doctor exited, and Doctor could move legacy session files while the shared-state database was missing and its SQLite sidecars remained.
- What the fix does: The fix closes retained parent database handles after Doctor exits and blocks destructive session migration when the shared-state database is missing and its SQLite sidecars remain.
- What in the causing PR was wrong: PR #175077 removed `assertSupportedStateSchemaVersion(db, database.path);` from the cached SQLite read path, letting the update parent reuse an open handle after Doctor revoked its schema admission.
- Reasoning: Before #175077, the Doctor handoff revoked admission and cached reads rechecked schema compatibility when admission facts changed or disappeared, with an existing test covering both successful and unsuccessful child exits. The #175077 diff removed that recheck, so it is the primary cause recorded here. The same fix also addresses a separate regression from #175129, which replaced the unconditional registry read with a lazy read that canonical paths could skip, bypassing the orphan-sidecar refusal.
