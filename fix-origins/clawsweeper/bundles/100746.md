- Fix: fix: keep Home clickable after session failures (#188421)
- What the user saw: Clicking the Home icon did not open Home when the icon showed a failed run, a pending question, or an approval request.
- What the fix does: Home now uses a noninteractive glyph that preserves running, queued, unread, draft, and outbox indicators.
- What in the causing PR was wrong: The compact rail put `renderSessionLeadingState(home, undefined, "owned", undefined, undefined, false, ...).leadingIndicator` inside the Home button, so session attention could replace the Home icon with a control that stopped clicks from reaching the button.
- Reasoning: I checked the compact-rail commit against its parent, where the existing Home panel button rendered `icons.home` directly and dispatched the toggle event on click regardless of session attention. The new leading-state renderer substituted the attention icon when a run failed, and that icon's existing click handler called `event.stopPropagation()`. The later Solid migration carried that behavior forward.
