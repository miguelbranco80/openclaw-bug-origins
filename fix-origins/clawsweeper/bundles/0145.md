## The bug (from the fix-origins reader)
- Origin: never-worked (confidence medium)
- Fix: fix(ai): keep provider checkpoints across model switches (#200208)
- What the user saw: Sessions that switched models (fallbacks, overrides, alternation) dropped their server compaction checkpoint, resent the full raw history and fell back to client summarization.
- What the fix does: Removed the model id from the provider replay fence so compaction checkpoints and replay items survive model switches within the same provider API, endpoint and session.
- What in the causing PR was wrong: The server-compaction replay match introduced in openai-responses-compaction-replay.ts included `state.model === context.model &&`, so a checkpoint written by one model was never replayed after a model switch.
- Reasoning: GraphQL blame puts the removed `state.model === context.model` line in #135727 (ef681015), a refactor that moved the fence; #200063's description says the fence was added in #120457, and that PR's diff (47f78a32) adds `state.model === context.model &&` to the original compaction replay match. Server compaction therefore never survived a model switch from the start, which the incident host saw on 357 of 800 dropped-checkpoint turns. The fence was a deliberate conservative choice, now relaxed after raw API checks showed providers accept cross-model items; that makes the not-a-defect reading arguable, so cause confidence is medium.
