# Case 8

## The bug that later had to be fixed
- What the user saw: In Safari and Firefox a long collapsed tool activity summary ran past the right edge of the reply text and under the Details panel, and in Chromium it was cut mid-word without an ellipsis.
- What the later fix did: Gave the activity group a `minmax(0, 1fr)` column track, applied ellipsis to every summary label, and replaced the 760px fallback cap on tool rows and the activity block with 100%.
- What in the reviewed change was wrong: The commit added `display: grid; gap: 4px;` to `.chat-activity-group` without a column template, so the summary's `max-width: 100%` (from `.chat-inline-disclosure`) resolved against an auto-sized grid track instead of the reading column.
- Why: Checking every version of tool-cards.css shows `.chat-activity-group` first became `display: grid` in 7fa041d (#186041); before it the group was a block and the summary (inline-flex, `width: fit-content; max-width: 100%`) was bounded by the column, so the cross-browser overflow the fix targets began there. The missing ellipsis on non-live labels is older (present at the root import), and the WebKit/Firefox track-sizing mechanism comes from the fix PR's measurements rather than my own run, hence medium confidence.

## Reviewers' findings
### Reviewer A (4 findings)
1. **Tool activity text loses contrast in light themes** — `ui/src/styles/chat/tool-cards.css`:91 (confidence high)
   In Absolutely Light, resting tool labels and file links drop from about 4.6:1 to 3.6:1 against the transcript background. Beacon Light drops from about 7.5:1 to 5.6:1, and the new secondary color gives directory hints and subagent status text about 2.8:1. Users who rely on those themes for readability get harder-to-read narration and status text.
2. **Handoff disclosure arrows disappear in every state** — `ui/src/styles/chat/tool-cards.css`:139 (confidence high)
   When a run waits on multiple child sessions or resumes after a handoff, the session-list button uses the shared chevron class without any of the classes targeted by the reveal rules. Its arrow stays invisible when collapsed, expanded, hovered, or keyboard-focused, so users lose the visual cue that they can open or close the list.
3. **Bubble-mode activity disclosures lose their touch padding** — `ui/src/styles/chat/grouped.css`:2159 (confidence high)
   On a touchscreen in bubble mode, the more specific zero-padding rule overrides the 8px top and bottom padding for coarse pointers. At the default text scale, a completed activity or “Worked for” disclosure shrinks from a roughly 35px-tall tap target to about 20px. Its collapsed arrow is also hidden before the first tap, making the control harder to spot and activate.
4. **Bubble-mode disclosures stretch across the transcript** — `ui/src/styles/chat/tool-cards.css`:1038 (confidence high)
   In bubble mode, the summary button has width auto. Making its parent a grid stretches the button across the activity column. A short live status now appears centered inside a wide bordered bar, and tapping blank space far beyond a completed activity label toggles its details.

### Reviewer B (2 findings)
1. **Tool disclosures lose their touch hit area** — `ui/src/styles/chat/tool-cards.css`:109 (confidence high)
   On a coarse-pointer device, expanded activity groups render each tool disclosure with zero vertical padding; the only coarse-pointer rule restores padding for activity-group summaries, not tool rows. Each toggle therefore shrinks to roughly the 19.5px text line height, down from the previous padded row, making dense adjacent tool rows substantially easier to mistap.
2. **Completed bubble activity collapses to a tiny toggle** — `ui/src/styles/chat/grouped.css`:2159 (confidence high)
   In bubble mode, an activity disclosure has a 40px target while it is working, but once the run completes and the `chat-activity-group--working` class is removed, this rule leaves it with zero padding and no minimum height. The completed activity toggle becomes only about one 13px text line tall on touch screens, instead of retaining the previous 28px minimum, so users get a difficult-to-tap control for reopening completed details.

### Reviewer D (1 findings)
1. **Handoff disclosure arrows become permanently invisible** — `ui/src/styles/chat/tool-cards.css`:140 (confidence high)
   When a run waits on multiple subagents or displays a resumed handoff with session details, its disclosure uses chat-tool-row__chevron inside chat-subagent-wait__toggle or chat-handoff-resume__rule. ### Reviewer E (1 findings)
1. **Keep handoff disclosure arrows visible** — `ui/src/styles/chat/tool-cards.css`:140 (confidence high)
   ChatSubagentWaitLine and ChatHandoffResume also use .chat-tool-row__chevron, but their buttons lack .chat-inline-disclosure. Setting the shared class to opacity: 0 hides their arrows permanently: none of the reveal selectors match on hover, keyboard focus, or expansion. Users see waiting/resume text without the disclosure indicator that makes the session list discoverable or indicates its expanded state.

### Reviewer F (3 findings)
1. **Subagent-wait toggle chevron becomes permanently invisible** — `ui/src/styles/chat/tool-cards.css`:139 (confidence high)
   `.chat-tool-row__chevron` now defaults to `opacity: 0`, and every rule that reveals it again is scoped to `.chat-inline-disclosure` (hover, focus-within, aria-expanded) or to file and subagent rows. ChatSubagentWaitLine (chat-handoff-sessions.tsx) puts the same chevron class inside `.chat-subagent-wait__toggle`, which is not a `.chat-inline-disclosure`. Before this change that chevron showed at 0.55 opacity. When a handoff waits on several sessions, the 'Waiting on N sessions' toggle no longer shows a chevron in any state (collapsed, expanded, hovered or focused), so nothing on screen says the line can open or close.
2. **Grid on .chat-activity-group stretches the bubble-mode working pill and summaries to full width** — `ui/src/styles/chat/tool-cards.css`:1038 (confidence medium)
   `.chat-activity-group` is now `display: grid`. In bubble mode, `.chat-activity-group--bubble > .chat-activity-group__summary` sets `width: auto`, which overrides the `width: fit-content` from `.chat-inline-disclosure`. A grid item with `width: auto` stretches to fill its column; before, as an inline-flex child of a block container, it shrank to fit its content. The live 'working' bubble summary has a border, an elevated background, an 18px radius and centered dots. It now draws as a wide bar across the whole activity group (up to the 760px max width) instead of a compact pill. Completed bubble summaries likewise get a full-width click target and focus outline.
3. **Tool row text stays highlighted after a mouse click** — `ui/src/styles/chat/tool-cards.css`:295 (confidence low)
   The new `.chat-tool-msg-summary:focus-within { color: var(--text) }` rule matches any focus inside the row, including focus from a mouse click. When a user clicks a tool row to expand or collapse it, or clicks its file link, the button keeps focus, so that row stays in full text color while every other row stays muted. It keeps the hover look until the user clicks somewhere else. The existing focus-visible rule kept the highlight for keyboard focus only.
