# Case 130

## The bug that later had to be fixed
- What the user saw: Opening Review for an old session whose worktree had been cleaned up showed "Local workspace review owner changed" with no way to recover.
- What the later fix did: Splits the removed or missing worktree case out of the owner-changed check in readLocalWorkspaceReviewBase, throwing guidance to use Restore in Settings > Worktrees, and checks the registry even when no review-base row exists.
- What in the reviewed change was wrong: #176001 created readLocalWorkspaceReviewBase with `if (!worktree || worktree.removedAt !== undefined || worktree.ownerKind !== "session" || ...) { throw new Error("Local workspace review owner changed"); }`, folding a removed or missing worktree into the owner-mismatch error.
- Why: local-workspace-review.ts has a single commit before the fix, 1d71aef2b129 (#176001), which created the file with the combined removal/owner-mismatch condition that produced the misleading error, so the defect shipped with the code. It is mostly a wrong diagnosis and missing recovery step rather than a broken review (the worktree really is gone), hence medium confidence; the fix also stops a missing review-base row from skipping the removal check.

## Reviewers' findings
### Reviewer A (3 findings)
1. **Review of an archived sandboxed session now throws instead of returning an empty/unavailable diff** — `src/gateway/worker-environments/local-workspace-review.ts`:392 (confidence medium)
   Archiving a session with a managed worktree keeps entry.worktree and spawnedCwd but removes the worktree (registry removedAt set, snapshotRef kept); the local workspace projection row is only deleted later by retention expiry. Opening Review on such an archived session now finds the projection row, matches the binding, then hits `worktree.removedAt !== undefined` and throws "Local workspace review owner changed". Before the change the missing checkout made loadCheckoutRevision return undefined and sessions.diff returned an empty not_git result; now the operator sees an RPC error in the Review panel for every archived sandboxed session until the projection expires (about 31 days).
2. **Accepted base is HEAD at sandbox preparation, so pre-existing branch commits disappear from All changes and history** — `src/gateway/server-methods/sessions-diff.ts`:107 (confidence low)
   The projection's base_commit is set at first sandbox prepare to the worktree's current `HEAD` (local-workspace-state.ts prepare), not to the merge base with the default branch. When the session's worktree already had commits before the sandbox projection was created (for example the session ran unsandboxed and committed, or the operator committed in the worktree before the first sandboxed turn), Review now passes that HEAD as baseCommit: All changes, aheadCount and the commit list omit those commits, and scope=commit for them returns unknown_commit, although they are part of the branch the PR row/publication diffs against the default-branch merge base.
3. **Pending/conflicted base refresh leaves stale base_commit while canonical checkout already contains upstream** — `src/gateway/worker-environments/local-workspace-review.ts`:401 (confidence low)
   During refresh_base the staged result is applied to the canonical worktree first (pending_target switches to projection) and base_commit is only advanced after the projection side applies without conflicts. If the projection side conflicts, the row stays pending with the old base_commit while the canonical checkout already holds the upstream content. Review now forces the old accepted base, so it shows every upstream-only file as a task change (the very symptom being fixed), even when the default-branch refs are current and the previous ref-based base would have hidden them.

### Reviewer B (1 findings)
1. **[P2] First sandbox use hides earlier task commits from Review** — `src/gateway/worker-environments/local-workspace-review.ts`:61 (confidence high)
   A session can make and commit task changes while running without a sandbox, then enable sandbox execution in the same managed worktree. When the projection is first created, local-workspace-state.ts initializes base_commit from the current HEAD, including those task commits. Returning that value unconditionally as the Review base makes the earlier changes disappear from All changes and branch history; requesting those commits individually returns unknown_commit. Previously, Review compared against the branch merge base and retained those changes. The projection's initial checkout HEAD must be distinguished from an accepted upstream base before using it for task Review.

### Reviewer C (1 findings)
1. **Creating a sandbox hides task commits made before sandbox creation** — `src/gateway/worker-environments/local-workspace-review.ts`:61 (confidence high)
   If a session commits task changes while sandboxing is off, then enables a local sandbox, projectionOperations.prepare initializes the new projection's base_commit to the checkout's current HEAD. This change unconditionally uses that value as Review's base, even though no upstream refresh occurred. Previously visible task changes disappear from All changes, their commits disappear from branch history, and selecting those commits returns unknown_commit. The projection's initial checkout revision is not necessarily the task's upstream base.

### Reviewer D (4 findings)
1. **Review shows upstream changes after an already-current base refresh** — `src/gateway/server-methods/sessions-diff.ts`:107 (confidence high)
   If an operator fetches a newer default-branch tip and rebases the managed task onto it, `refresh_base` sees that tip in HEAD's ancestry and returns `current` without updating the projection's `base_commit`. Review now uses the older stored SHA even though the default-branch ref is up to date. The file list, ahead count, and commit picker include upstream changes that the previous merge-base calculation excluded.
2. **Concurrent refresh can pair an old base with the refreshed checkout** — `src/gateway/worker-environments/local-workspace-review.ts`:45 (confidence high)
   If Review reads the projection just before `refresh_base` accepts a new base, and its queued Git read starts after the refresh finishes, it compares the refreshed checkout to the old SHA. Refresh changes neither the session binding nor the registry identity, so both final guards pass. Review can return upstream-only files and commits in the task diff.
3. **Archived Review reports an ownership error after normal cleanup** — `src/gateway/worker-environments/local-workspace-review.ts`:52 (confidence high)
   Archiving a projected session preserves its worktree binding. Background cleanup then removes the checkout and marks its registry record removed while retaining the projection for recovery. An authorized Review request now fails with `Local workspace review owner changed`. Previously the missing checkout returned `not_git`, which the panel displays as an unavailable-checkout message.
4. **Review applies the outer repository's base to a nested checkout** — `src/gateway/worker-environments/local-workspace-review.ts`:57 (confidence medium)
   Worktree preparation supports a session whose cwd is a subdirectory of the managed checkout. If that directory becomes a separate Git checkout after the projection is created, the path containment check still passes. Git resolves the nested repository from the session cwd, but Review supplies the outer repository's SHA. When that SHA is absent from the nested repository, All changes fails with `Unable to read tracked Git changes`. Previously Review used the nested repository's own refs.

### Reviewer E (2 findings)
1. **Enabling sandboxing hides earlier task commits** — `src/gateway/server-methods/sessions-diff.ts`:107 (confidence high)
   If a managed session commits task changes before first enabling its local sandbox, projectionOperations.prepare initializes base_commit to the checkout's current HEAD. Passing that value here makes Review exclude all those task commits: a clean checkout shows no changes, its history disappears, and selecting an earlier task commit returns unknown_commit. The projection's initial checkout commit is not necessarily the task's upstream base.
2. **Base refresh can invalidate the selected base without invalidating the read** — `src/gateway/worker-environments/local-workspace-review.ts`:45 (confidence high)
   A Review request can read base A, then wait while refresh_base integrates upstream B and updates the projection's base_commit. The returned guard checks session and registry lifecycle only; neither changes during this refresh. Git can therefore compare the refreshed checkout against A and successfully return upstream-only changes and history. The projection base must also remain current across the Git read, or the request must retry.

### Reviewer F (1 findings)
1. **Base refresh can race Review and return a stale diff** — `src/gateway/worker-environments/local-workspace-review.ts`:61 (confidence high)
   If Review reads accepted base A, then a concurrent base refresh advances the projection to B while the request waits for the Git read, the returned guard does not detect it: it watches only session state and registry identity/removal, not the projection revision or base_commit. The Git read can therefore compare the refreshed checkout against A, so the user sees newly accepted upstream changes as task changes and incorrect branch history even though the refresh completed before the response.
