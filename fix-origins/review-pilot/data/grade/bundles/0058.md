# Case 58

## The bug that later had to be fixed
- What the user saw: In sessions using a context engine such as Lossless Claw, a tool-only turn ended with an incomplete-turn error (or NO_REPLY_RECEIVED to a sessions_send requester) instead of a final answer.
- What the later fix did: Gave the temporary bookkeeping entries in settled-turn finalization a fixed timestamp instead of converting each message's possibly missing timestamp.
- What in the reviewed change was wrong: #186288 fed the context engine's selected messages into settled finalization through the new boundSettledFinalizationMessages, which builds each entry with `timestamp: new Date(message.timestamp).toISOString()`, throwing RangeError for engine messages without a timestamp.
- Why: Settled-turn finalization predates the graft (settled-turn-finalization.ts history goes back before 2026-09) and previously rebuilt from raw session history with no timestamp conversion. Commit 1714e20 (#186288) switched it to the engine-selected view and added the per-message toISOString conversion; I read that diff, including builtin-openclaw.ts passing the context-engine messages in, and new Date(undefined).toISOString() throws exactly the RangeError the fix's incident and regression test show.

## Reviewers' findings
### Reviewer A (2 findings)
1. **Settled-view bounding throws on messages without a valid numeric timestamp** — `src/agents/embedded-agent-runner/run/attempt-history-prepare.ts`:32 (confidence medium)
   boundSettledFinalizationMessages builds a synthetic entry with `new Date(message.timestamp).toISOString()` for every message in the frozen settled view (only to fill a field the selector never reads). The settled view now comes from activeSession.messages, which for context-engine sessions is whatever the engine's assemble() returned; assembled messages are not normalized and a plugin-produced summary/custom message without a timestamp (or with a non-date string) makes toISOString throw RangeError('Invalid time value'). prepareEmbeddedAttemptHistory then fails, the isolated finalizer errors, and the turn ends as 'settled-turn finalization failed — preserving failed recovery' with no final answer, where before the change finalization rehydrated the transcript and succeeded.
2. **Compaction summary in the settled view loses its required-boundary treatment** — `src/agents/embedded-agent-runner/run/attempt-history-prepare.ts`:29 (confidence low)
   Every settled message, including a compactionSummary produced by compaction during the source attempt, is wrapped as an entry of type 'message'. selectBoundedModelRequests only pins entries of type 'compaction'/'reset' as the boundary, so under byte pressure (e.g. screenshot-heavy turns exceeding contextTokenBudget*8 bytes) the summary at the head of the view is the first thing cut. The finalizer then answers without the summarized earlier context, whereas transcript hydration always retained the compaction boundary.

### Reviewer B (3 findings)
1. **Storage-only tool details can prevent finalization** — `src/agents/embedded-agent-runner/run/attempt-history-prepare.ts`:54 (confidence high)
   A plugin tool can return a short success receipt with a diagnostic details field larger than the finalizer's byte limit. The live tool result retains those details, while durable model-context hydration strips them. The new sizing pass counts the details before replay cleanup, and replacing the result body leaves them in place. If this is the last tool result and the model then returns an empty answer, the selector cannot retain the completed tool frame. Finalization fails before contacting the provider, leaving the user without a summary of the completed work.
2. **A legacy message timestamp can abort finalization** — `src/agents/embedded-agent-runner/run/attempt-history-prepare.ts`:33 (confidence high)
   An imported transcript can contain a historical user message with a valid entry timestamp and no timestamp inside the message payload. Session hydration preserves that payload, and a provider such as OpenAI Responses can replay its text. When a later tool turn needs finalization, converting the missing payload timestamp to ISO throws before the selector can even decide whether to retain that row. The completed tool turn gets no final answer.
3. **Finalization can discard the active compaction summary** — `src/agents/embedded-agent-runner/run/attempt-history-prepare.ts`:30 (confidence high)
   A compacted session can start a tool turn with a summary and retained history that fit the byte limit, then exceed that limit after the current request and completed tool exchanges are added. Durable hydration reserves space for the compaction summary before selecting the recent suffix. The new wrapper labels the summary as an ordinary message, so the suffix cut can discard it even when the summary and current turn fit together. The finalizer can then answer without decisions or constraints recorded only in that summary.

### Reviewer C (1 findings)
1. **[P2] Exclude tool-result metadata before applying the byte limit** — `src/agents/embedded-agent-runner/run/attempt-history-prepare.ts`:54 (confidence high)
   Settled snapshots retain newly completed tools' `details`, but this sizing callback counts those storage-only fields before `sanitizeSessionHistory` removes them. A tool returning a short receipt with sufficiently large metadata can therefore exceed the finalizer's byte limit even though its model-visible content fits. The omission projection also retains `details`, so the selector can discard the completed tool frame or reject finalization altogether. Previously, transcript hydration stripped these fields before bounding. Users consequently lose the final summary or receive an answer without the completed operation's evidence.

### Reviewer D (1 findings)
1. **Preserve compaction boundaries when bounding the settled view** — `src/agents/embedded-agent-runner/run/attempt-history-prepare.ts`:30 (confidence high)
   Every snapshot item is wrapped as a normal message, including compactionSummary messages. selectBoundedModelRequests protects summaries only when their entry type is compaction. Consequently, when a compacted session's settled snapshot exceeds the byte or event limit—even after tool-result omission—the suffix selection can silently discard its compaction summary. Previously, transcript hydration reserved that boundary and retained it alongside the bounded suffix. The finalizer can now answer a follow-up using tool receipts without the summarized requirements or decisions needed to interpret them, producing an incorrect final answer.

### Reviewer E (1 findings)
1. **Strip tool-result metadata before applying the context byte limit** — `src/agents/embedded-agent-runner/run/attempt-history-prepare.ts`:54 (confidence high)
   Settled snapshots retain tool-result `details`, but this sizing callback counts them, and the omission projection only replaces `content`. A tool returning small model-facing content with metadata larger than the context byte limit therefore causes the selector to discard its completed tool evidence or throw before finalization. The user gets a final answer without the operation's result, or failed finalization. Previously, transcript hydration stripped `details` before sizing; ordinary model requests also strip them. Apply that same projection before bounding the snapshot.

### Reviewer F (2 findings)
1. **Finalizer bounds storage-only tool details as model input** — `src/agents/embedded-agent-runner/run/attempt-history-prepare.ts`:54 (confidence high)
   When the completed current-turn tool result carries large or non-JSON-serializable `details` (for example aggregated process output), sizing serializes those details before `sanitizeSessionHistory` strips them from model context. The selector can therefore discard usable history, throw the context-limit error, or fail during JSON serialization, leaving the user without the final answer even though the actual provider input would fit.
2. **Rebounding loses the mandatory compaction summary** — `src/agents/embedded-agent-runner/run/attempt-history-prepare.ts`:30 (confidence high)
   Every frozen message is represented as an ordinary `message`, including a `compactionSummary` that came from the transcript's mandatory compaction boundary. If the snapshot contains that summary, a retained old turn, and a new completed tool turn that pushes the snapshot over the limit, suffix selection drops the old turn together with the summary. The finalizer then answers without the only surviving summary of earlier instructions, even though the canonical selector would keep the boundary while dropping only the retained turn.
