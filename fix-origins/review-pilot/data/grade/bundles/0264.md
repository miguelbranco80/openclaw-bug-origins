# Case 264

## The bug that later had to be fixed
- What the user saw: Starting dictation in New Session no longer showed the animated recording border around the message box.
- What the later fix did: Moves the New Session image-drop tint from the message input's ::after to its unused ::before so it no longer overrides the dictation border.
- What in the reviewed change was wrong: It changed the drop-tint selector from `.new-session-page__composer::after` to `.new-session-page__composer > .agent-chat__input::after`, the same pseudo-element that `.agent-chat__input--dictating::after` in composer.css uses for the dictation border, overriding it with opacity 0 and inset 0.
- Why: At 1f3524e's parent, composer.css already drew the dictation border with `.agent-chat__input--dictating::after`, and the drop tint lived on the composer shell's own ::after. 1f3524e (#200758) retargeted the tint to `.agent-chat__input::after` with a more specific selector, so the tint rules replaced the border's styles; the fix PR describes the same mechanism and adds a red/green regression for it.

## Reviewers' findings
### Reviewer A (1 findings)
1. **Preserve the dictation indicator when adding the drop overlay** — `ui/src/styles/new-session.css`:820 (confidence high)
   Starting voice dictation in New Session adds `agent-chat__input--dictating`, whose animated recording border already uses `::after` in chat/composer.css. This new, more specific selector overrides that same pseudo-element's background and sets its opacity to zero. Users therefore lose the animated recording indicator throughout dictation, even without dragging a file.

### Reviewer C (1 findings)
1. **Drop-tint ::after on the message surface overrides and hides the dictation edge animation in New Session** — `ui/src/styles/new-session.css`:820 (confidence high)
   The New Session message surface is the same element that gets `agent-chat__input--dictating` (composer.tsx:542-545), whose dictation comet is drawn with `.agent-chat__input--dictating::after` (composer.css:87, specificity 0,1,1). The new `.new-session-page__composer > .agent-chat__input::after` rule (specificity 0,2,1) now targets that same pseudo-element and wins every shared property: `opacity: 0`, `background: var(--accent)` instead of the conic gradient, `inset: 0` instead of -1px, `z-index: 1` instead of 5. When a user starts dictation on the New Session page, the travelling accent edge that signals capture is active is invisible (opacity 0). If they then drag a file over the composer while dictating, they see a flat 10% accent ring masked to 1px instead of the drop tint or the comet. Before this change the drop tint lived on the shell's ::after, so the two never collided.

### Reviewer D (1 findings)
