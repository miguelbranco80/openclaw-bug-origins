# Case 76

## The bug that later had to be fixed
- What the user saw: On a phone, the Systems desktop viewer's size selector read 'Act…' instead of 'Actual' after choosing it.
- What the later fix did: Reserves a 28px chevron inset (instead of the shared 36px) for the desktop sizing select in the compact Systems toolbar so the 'Actual' label fits.
- What in the reviewed change was wrong: It changed the sizing select to class="settings-select desktop-sizing" and dropped its own `padding: 0 6px`, so the shared `select.settings-select:not([multiple]) { appearance: none; padding-right: 36px; }` rule left the 88px control only ~42px of text width.
- Why: The 88px .desktop-sizing select had its own native styling with 6px padding until 8689fa8f6b8 moved it into the shared settings-select family, whose 36px right padding leaves 88-2-8-36=42px, the exact width the PR reports before the fix. I did not render the pre-8689fa8 state to confirm 'Actual' fit in the native select, so confidence is medium; 6a9965ad7731 (blame top) only added the compact toolbar layout rules, not the padding.

## Reviewers' findings
### Reviewer A (1 findings)
1. **Truncation hides the distinction between media devices** — `ui/src/styles/components.css`:1175 (confidence high)
   In browsers supporting base-select, opening the microphone or camera picker in Settings now truncates long device names to one line. MediaDeviceField renders raw options without title attributes, so devices whose labels share a long prefix but differ at the end appear identical, with no way to reveal the distinguishing suffix visually. Previously the popup could grow or wrap to display those names. Preserve a way to inspect full labels before choosing a device.

### Reviewer B (4 findings)
1. **Systems machine picker loses its keyboard focus indicator** — `ui/src/styles/systems.css`:656 (confidence high)
   At viewport widths of 768px or less, tabbing to the Systems machine picker in standard color mode produces no visible focus indicator. The new shared class removes the focus outline, and the more specific Systems border rule overrides the shared focus border color.
2. **Long camera and microphone names become indistinguishable** — `ui/src/styles/components.css`:1138 (confidence high)
   On a wide screen in a browser that supports customizable selects, two camera or microphone labels that share a long prefix and differ only at the end can appear identical in Settings. The popup previously had room to grow with the labels. It now stops at the 340px trigger minimum, clips the distinguishing suffixes, and the device options have no tooltip that reveals the full names.
3. **The chevron overlaps selected text in right-to-left layouts** — `ui/src/styles/components.css`:1109 (confidence high)
   With Arabic or Persian selected in a browser that supports customizable selects, the chevron moves to the left but the extra padding stays on the right. A long selected value, such as a session group name, can extend under the chevron and obscure the end of the visible label or its ellipsis.
4. **The desktop sizing control truncates short mode labels on phones** — `ui/src/components/desktop/desktop-panel.css`:141 (confidence high)
   In the touch desktop viewer at a 430px viewport width, the sizing select remains 88px wide. The new shared padding and 16px touch font leave only 42px for the selected label, so an English mode such as Actual can appear truncated even though it fit with the previous native control.

### Reviewer C (1 findings)
1. **Popup cap hides full dashboard author names** — `ui/src/styles/components.css`:1138 (confidence high)
   In a browser supporting `appearance: base-select`, open the dashboard Author filter when owner labels are longer than 320px (especially labels sharing the same prefix). The new 320px popup cap and single-line option clipping truncate those labels, while the raw dashboard `<option>` elements have no `title`; users can see identical ellipsized entries and cannot determine which author they are selecting. Previously the picker could expand nearly to the viewport and the options were not forcibly clipped.

### Reviewer D (1 findings)
1. **Desktop size select keeps 88px width but now carries the shared select's wide chevron padding, truncating its value on touch** — `ui/src/components/desktop/desktop-panel.css`:140 (confidence medium)
   The desktop sizing select (non-menu presentation, including the desktop-touch-toolbar in document mode) stays at a fixed 88px but now takes settings-select chrome: --field-padding-inline (10px) on the left and calc(26px + 0.5em) on the right (36px in browsers without base-select), plus borders, instead of the old 0 6px padding and 12px type. That leaves about 40-42px for the value. On a coarse-pointer device the global 16px !important select floor applies, so 'Actual' (and 'Match') no longer fit and render as 'Actu...' / 'Matc...' via the new one-line clamp (or are clipped in Firefox). Longer translations are truncated even at desktop type size. The user cannot read the current sizing mode in the touch toolbar.
