# Case 89

## The bug that later had to be fixed
- What the user saw: In New Session the 'Absolute path on device' label sat about 8 px left of the path it described, and on phones the project search text jumped left and the field shrank when tapped.
- What the later fix did: Wraps the device-path label text in a span inset to match its input and scopes the picker input geometry to the picker panel so it holds in every focus state, including touch focus.
- What in the reviewed change was wrong: #203269 added `<label class="new-session-page__device-path-entry">{t("newSession.deviceFolderPath")}<input .../>` styled with `padding: var(--picker-inset)` while the picker input adds `padding-inline: var(--picker-row-inset)`, so the label text starts left of the path text.
- Why: The device-path misalignment is in the redesigned compact device-folder picker that 6946824aa91c (#203269) introduced the same day; its diff adds the bare label text with only the panel inset while the input text gets an extra row inset, which plainly produces the 8 px offset the fix measures. The second issue (project search losing its padding and height on touch focus) dates to the picker CSS from e80a6dd9fdb4 (#197820) and later selector edits, but I could not identify which competing rule wins on touch focus, so overall confidence is medium.

### Reviewer E (3 findings)
1. **Applying a browsed replacement can silently keep the old folder** — `ui/src/pages/new-session/project-picker-content.tsx`:120 (confidence high)
   An admin selects a device folder, reopens the browser to replace it, and the device loses its last available worker slot while the picker is open. Use this folder remains enabled, but selectDeviceFolder rejects the change because the device is no longer selectable. The browser still closes. When a slot frees up, Start uses the old folder. The previous code still updated an existing selection in this situation.
2. **Background updates erase an unsubmitted manual path** — `ui/src/pages/new-session/project-picker-content.tsx`:65 (confidence high)
   While an operator types a path, an unrelated New Session update such as an agent roster refresh rebuilds the picker params. The writable signal re-derives from the saved selection and replaces the typed text with the previous path or an empty field. The editor stays open, so the operator can lose the edit without dismissing it.
3. **Touch users cannot verify the full folder path before retrying** — `ui/src/pages/new-session/project-chip.tsx`:63 (confidence high)
   After a pending device-folder session is restored on a phone, the picker trigger is disabled and shows only the final folder name. The full path is available through hover or assistive technology, so a sighted touch user cannot tell whether a retry will use /srv/client-a/project or /srv/client-b/project. The previous disabled field displayed the saved path directly.
