# Case 112

## The bug that later had to be fixed
- What the user saw: Hovering the info icon next to "Security audit" on plugin and Template pages showed a link page preview instead of any explanation of the audit.
- What the later fix did: Moved the security-audit info icon out of the audit link into its own tooltip button with explanatory copy, keeping the link on the verdict row.
- What in the reviewed change was wrong: In ui/src/components/tooltip-title.ts the title-hint suppression changed from `previewTargetForAnchor(link)` to `ownsHoverPreview(link)`, and the new `resolveHoverPreviewTarget` returns a page preview for any external http(s) link, so the hint nested in the ClawHub audit link was suppressed in favor of the page preview.
- Why: The `<span title="View security audit">` info hint inside the external audit link already existed at 8c7f96b00b4^ (security-audit.ts line 45), when title tooltips were suppressed only for plugin link-reader targets; #152758 extended hover previews to all ordinary external links and made tooltip-title defer to `ownsHoverPreview`, which hides nested title hints on those links. Medium confidence because the preview only applies when link previews (automaticallyFetchFavicons) are on and I did not run the UI; the fix also rewrote the hint copy, which is partly a content improvement.

## Reviewers' findings
### Reviewer A (1 findings)
1. **Shadow DOM link previews miss pointer transitions** — `ui/src/components/link-reader-hovercard.ts`:373 (confidence high)
   In a rendered Markdown skill preview, links live inside the file-preview component's shadow root. Moving from surrounding text onto a link does not deliver pointerover to the outer provider: the browser trims events whose target and relatedTarget retarget to the same shadow host. Consequently, ordinary hovers there never open previews. Entering the component directly over a link can open a preview, but moving onto surrounding text similarly hides pointerout from the provider, leaving the card stuck open. Composed ancestor lookup does not address this; pointer intent must be observed within the shadow root or on the anchor.

### Reviewer B (1 findings)
1. **Hovering any external link makes the Gateway GET the full URL, consuming one-time/action links** — `ui/src/components/link-reader-target.ts`:1551 (confidence medium)
   resolveHoverPreviewTarget accepts every http(s) cross-origin anchor that isn't one of a few hard-coded markers (only the wizard sign-in button was opted out via data-link-reader-external). A chat transcript or settings page containing a magic-login, email-confirmation, password-reset, unsubscribe, invite-accept or OAuth authorize link (with its token in path/query) will, on a 250 ms mouse hover or keyboard focus, be sent to controlUi.linkPreview and fetched by the Gateway with a plain GET. Sites that act on GET consume the one-time token or perform the action (confirm/unsubscribe), so when the operator later clicks the link it reports 'link expired/already used', or the action happened without a click. The change itself recognizes this hazard for the wizard sign-in URL but leaves all other authorization/action links in transcripts exposed.

### Reviewer D (1 findings)
1. **Channel authorization URLs are fetched on hover** — `ui/src/pages/channels/wizard-view.ts`:201 (confidence high)
   Channel setup uses the same WizardStep.externalUrl mechanism for provider OAuth URLs (including state/query credentials), but this anchor lacks data-link-reader-external. Hovering or keyboard-focusing it now calls controlUi.linkPreview and makes an anonymous GET to the authorization URL before the user chooses to open it, potentially leaking or consuming a signed/one-time flow. Only the model wizard's equivalent link was excluded.

### Reviewer E (4 findings)
1. **Hover sends a prefilled update report to GitHub** — `ui/src/components/link-reader-target.ts`:131 (confidence high)
   When update reporting falls back to a prefilled GitHub issue and its URL is at most 2,048 characters, hovering or keyboard-focusing Open prefilled issue sends the URL through the Gateway to GitHub. The query contains the full report title and diagnostic body, so GitHub receives them even if the operator leaves without opening the issue form.
2. **Hover and focus changes inside the link reader go unnoticed** — `ui/src/components/link-reader-hovercard.ts`:295 (confidence high)
   Links in a GitHub issue body are inside the link reader panel's shadow root. When the pointer moves from issue text onto a link, or keyboard focus moves between controls in that same root, the browser keeps the transition events inside the root. The provider's outside listeners miss them, so previews can fail to open. If a preview was opened by entering the link from outside the root, moving onto nearby issue text can leave the preview open and allow a brief hover to trigger a fetch.
3. **Hovercards lose their styles inside shadow-root modals** — `ui/src/components/portaled-hovercard.ts`:365 (confidence high)
   Hovering Open original in a chat lightbox for an external image or video mounts the preview inside the lightbox's shadow root. The document stylesheet cannot reach the card there, even after popover promotion. The preview uses browser-default layout and loses its intended width, height, and image sizing.
4. **Empty previews hide authored link hints** — `ui/src/components/tooltip-title.ts`:67 (confidence high)
   After the hover runtime loads, a Markdown link with a title such as Requires administrator access loses that hint whenever public preview is enabled. If the destination has no metadata or the request fails, the card falls back to the visible link text and hostname, leaving the authored warning unavailable on both hover and keyboard focus.
