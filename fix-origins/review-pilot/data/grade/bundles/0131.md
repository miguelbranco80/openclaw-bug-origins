# Case 131

## The bug that later had to be fixed
- What the user saw: In WebKit browsers the Control UI used noticeably more CPU and GPU-process time on every frame while any spinner was visible (e.g. running sessions in the sidebar).
- What the later fix did: Moved each spinner's SVG mask from the rotating element onto a static shared ::before child so WebKit no longer repaints a masked layer every frame.
- What in the reviewed change was wrong: #189847 replaced the border-drawn spinners (e.g. `border: 1.5px solid color-mix(...)`; `border-top-color: currentColor`) with `background: currentColor; mask: var(--spinner-mask);` on the same element that runs `animation: btn-spinner-spin`.
- Why: The cause diff (6feb40ee5b4, #189847) swaps the border-drawn spinner art for a currentColor background masked on the rotating element across all spinner hosts, and the fix PR measured GPU-process time at 0 with the old border art versus 1.4-2.4% with the mask, so the cost was newly introduced by that commit. The spinners were cheap before, making this a performance regression rather than an optimization of code that was never faster; #194146 only removed an amplifying hidden animation.

1. **Loading rings disappear under same-origin-only image policies** — `ui/src/styles/base.css`:366 (confidence high)
