# Case 225

## The bug that later had to be fixed
- What the user saw: On Node 24, a bundled Codex executable that could not run produced a generic app-server startup failure instead of the actionable executable-permission/missing-binary error.
- What the later fix did: The managed Codex launcher observer now recognizes Node 24's fatal `process.execve failed with error code X` header together with a SIGABRT exit and records it as the native spawn failure.
- What in the reviewed change was wrong: It bumped `"@openai/codex": "0.164.0"` to `"0.169.0"`, whose launcher uses process.execve, and taught the observer only the structured form (`/syscall: ['"]execve['"]/` plus a matching `path:` line), which Node 24 never prints because it aborts with SIGABRT and a bare `process.execve failed with error code ...` header.
- Why: Native launch-error attribution worked with the 0.164 launcher (spawn-style exit-1 diagnostics, #154489/#161419); the PR names #200784 as related, and that commit's diff bumps Codex to 0.169.0 (an execve-based launcher) while adding only the Node 26 structured execve branch, so on Node 24 the diagnostic was lost and the real-launcher tests failed in the hourly Codex shard right after. It could also be read as latent (upstream launcher change with #200784 as trigger), but the in-repo bump and its incomplete adaptation are one commit, so I call it a regression with medium confidence.

### Reviewer D (3 findings)
1. **Codex can escape orphan cleanup after the launcher replaces itself** — `extensions/codex/package.json`:11 (confidence medium)
   With the new execve launcher on POSIX, process registration can read and hash the Node launcher's command line before it replaces itself with Codex at the same PID. If the Gateway is then killed while that app-server is still alive, the next Gateway sees the native command line, treats it as a different process, and deletes the registration without reaping the old app-server or its descendants.
2. **Inline-command benchmarks reject the bundled Codex version** — `scripts/perf/inline-command-build-verification.mjs`:53 (confidence high)
   When an operator selects a checkout containing this change as the candidate for either inline-command benchmark, the verifier reads the installed Codex version as 0.169.0 and asserts that it is 0.164.0. Both benchmark entry points abort before collecting measurements, even when the candidate is the only selected cell.
3. **Execve launch errors are missed for escaped installation paths** — `extensions/codex/src/app-server/managed-launcher-failure.ts`:35 (confidence high)
   If a POSIX installation path contains a literal backslash and the bundled binary lacks execute permission, Node escapes the backslash in the printed EACCES path. The observer compares that escaped text with the literal filesystem path, so the operator gets a generic startup failure and later requests retry the same unusable binary instead of using the recorded launch failure.
