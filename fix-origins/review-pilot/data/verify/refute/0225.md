# Case 0225: findings to check

## F1: Inline-command benchmarks reject the bundled Codex version
- Where: `scripts/perf/inline-command-build-verification.mjs`:53
- Claimed failure: When an operator selects a checkout containing this change as the candidate for either inline-command benchmark, the verifier reads the installed Codex version as 0.169.0 and asserts that it is 0.164.0. Both benchmark entry points abort before collecting measurements, even when the candidate is the only selected cell.

## F2: New gcp Account variant is treated as an unauthenticated source account in plugin migration
- Where: `extensions/codex/src/migration/source.ts`:343
- Claimed failure: The bumped 0.169.0 protocol adds an Account variant {type: "gcp"} (Vertex AI with external credentials), but readSourceCodexAccount only maps chatgpt/apiKey/amazonBedrock and falls through to "missing" for gcp. A user whose source Codex is authenticated through GCP and who migrates Codex plugins that own apps gets every such plugin blocked with codex_account_unavailable and the message 'Codex app-server did not report an authenticated source account' instead of the codex_subscription_required explanation that other non-ChatGPT accounts get; /codex account likewise shows only 'available'. The CodexGetAccountResponse type in protocol.ts was not extended either.

## F3: Codex can escape orphan cleanup after the launcher replaces itself
- Where: `extensions/codex/package.json`:11
- Claimed failure: With the new execve launcher on POSIX, process registration can read and hash the Node launcher's command line before it replaces itself with Codex at the same PID. If the Gateway is then killed while that app-server is still alive, the next Gateway sees the native command line, treats it as a different process, and deletes the registration without reaping the old app-server or its descendants.

## F4: Execve launch errors are missed for escaped installation paths
- Where: `extensions/codex/src/app-server/managed-launcher-failure.ts`:35
- Claimed failure: If a POSIX installation path contains a literal backslash and the bundled binary lacks execute permission, Node escapes the backslash in the printed EACCES path. The observer compares that escaped text with the literal filesystem path, so the operator gets a generic startup failure and later requests retry the same unusable binary instead of using the recorded launch failure.
