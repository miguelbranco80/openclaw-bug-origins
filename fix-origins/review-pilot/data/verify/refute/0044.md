# Case 0044: findings to check

## F1: Composer clips the history Retry button in short panes
- Where: `ui/src/styles/chat/startup-layout.css`:182
- Claimed failure: Open a conversation whose history fails to load and has no cached messages, in a pane short enough that the error screen must scroll. The fallback uses its own scroll container and receives none of the new transcript bottom padding. Even at the bottom of its scroll range, the composer can cover most of the Retry button when the error text wraps.

## F2: Scroll to latest can cover a mobile Goal pill
- Where: `ui/src/styles/chat/layout.css`:811
- Claimed failure: In a short mobile pane with a pending approval and a Goal pill that reaches the center, the approval can shrink while the pill keeps its full height. Clearance is tested against the button position before the overlap offset is applied. The test can miss the pill, then CSS raises the button into it. When the user has scrolled up, tapping the covered part of the Goal pill jumps to the latest message instead of opening the goal.

## F3: Full-pane history-error view gets the footer overlap without compensating bottom padding
- Where: `ui/src/styles/chat/startup-layout.css`:182
- Claimed failure: The extra bottom padding was added only to .chat-thread-viewport/.chat-thread, but the footer's negative margin applies whatever sits above it. When history fails with an empty transcript, the fallback .chat-history-error (an overflow:auto scrollport whose stage has min-height 260px and only 24px padding) occupies that slot. The footer now covers its bottom 28-35px: in a short pane where the stage scrolls, scrolling to the end leaves the last few pixels of the Retry control under the composer, and in taller panes the centered error art/text is centered in a box that extends behind the composer, so it sits visibly lower than the space actually visible above the composer.

## F4: Overlapping full-width footer swallows pointer input on the transcript's bottom band, including its scrollbar
- Where: `ui/src/styles/chat/startup-layout.css`:182
- Claimed failure: The new negative margin-top pulls .chat-footer (position: relative, full pane width, no pointer-events: none) 28px (35px at corner scale 1.25) up over .chat-thread-viewport, and as the later positioned sibling it paints and hit-tests above the transcript. The transcript's scrollbar sits at the pane edge (scrollbar-gutter both-edges), outside the centered composer, so the bottom 28-35px of the scrollbar track, and on Windows/Linux classic scrollbars the down-arrow button, now lie under the transparent footer: clicking or dragging there hits the footer instead of the scrollbar. Likewise, while scrolled mid-conversation, links, buttons and text in messages passing through that band beside the composer's rounded corners are visible but not clickable or selectable. Wheel input is forwarded, but mouse clicks and drags are not.

## F5: Transparent footer intercepts clicks on visible transcript links
- Where: `ui/src/styles/chat/startup-layout.css`:182
- Claimed failure: In a desktop chat with a centered composer notice, scroll until a message link sits beside the notice in the bottom 28–35 pixels of the transcript. The link is visible, but the full-width footer sits above it and receives the click. The link opens only after the user scrolls it above the overlap.
