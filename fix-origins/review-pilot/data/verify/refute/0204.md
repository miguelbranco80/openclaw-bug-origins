# Case 0204: findings to check

## F1: Canvas inventory throws on an unreadable legacy root and aborts the whole recovery capture
- Where: `extensions/canvas/doctor-contract-api.ts`:41
- Claimed failure: collectBackupResources calls listLegacyCanvasDocumentIds, which throws for any non-ENOENT error (EACCES, ENOTDIR) on plugins.entries.canvas.config.host.root/documents. preparePluginDoctorMigrationResources does not catch collector errors, so captureUpdateRecoveryBaseline (and rehearsal plan collection in state-migrations.plugin-doctor.ts) fails outright. Before this change the same config only produced the undeclared-resources warning and detectLegacyState's failure was caught as a 'Failed detecting' warning; now an operator with a stale or permission-restricted retired Canvas root cannot update at all until they fix that directory.

## F2: A valid default legacy memory index prevents recovery capture from sealing
- Where: `extensions/memory-core/src/migration/doctor-memory-sidecar.ts`:515
- Claimed failure: When a valid legacy index exists at stateDir/memory/main.sqlite, the retry inventory also declares main.sqlite-wal, main.sqlite-shm, and main.sqlite-journal as recovery roots, even when those files are absent. The backup consolidates the SQLite database and strips companion entries from the manifest while retaining their roots. Manifest validation rejects the entire capture with “Update recovery manifest is missing a root entry.” Doctor or the updater can then proceed without a pre-migration recovery copy.

## F3: Already-migrated host-event archives are declared forever, permanently deferring Memory Core in rehearsal
- Where: `extensions/memory-core/src/migration/doctor-host-events.ts`:547
- Claimed failure: collectLegacyMemoryHostEventSources returns every events.jsonl.migrated[.N] archive as a ready 'archive' source even after its checkpoint matches and no migration is needed, and the collector declares it unconditionally. Those archives are never deleted, so every later update capture copies them again, and in an update rehearsal whose agent workspace lies outside the rehearsal root (a configured absolute workspace) the path is read-only, so preparePluginDoctorMigrationResources defers the whole memory-core plugin on every update from then on, skipping its sidecar and other migrations in rehearsal with only a 'deferred' notice.

## F4: An empty legacy .sqlite placeholder aborts the entire recovery capture
- Where: `extensions/memory-core/src/migration/doctor-memory-sidecar.ts`:504
- Claimed failure: When a configured legacy memory index points to a zero-byte file named main.sqlite, declaring it as kind file still sends it through the SQLite snapshot path because the backup classifier recognizes the .sqlite suffix before checking the header. The snapshot requires a nonempty source and aborts the entire capture. Doctor can then continue and delete the placeholder without a sealed recovery copy of the rest of the pre-repair state.
