# Case 0071: findings to check

## F1: PostgreSQL still cannot finalize jobs with escaped NULs in their definitions
- Where: `src/cron/store/row-codec.ts`:660
- Claimed failure: A retained one-shot job can be created with a NUL in its agent prompt. The cron store serializes it as an escaped \u0000 in the PostgreSQL text column. When the run finishes, the new enablement update casts the entire definition to jsonb, which rejects that escape even though the update only changes the enabled flag. The finalization transaction rolls back, leaving the job marked as running and its terminal result absent from history.
