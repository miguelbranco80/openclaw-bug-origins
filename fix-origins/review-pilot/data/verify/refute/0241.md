# Case 0241: findings to check

## F1: Parent counted as running until its own task_notification, so a child forwarded to the main stream after the parent ended can be treated as consumed by the subagent
- Where: `extensions/anthropic/cli-runtime-tasks.ts`:88
- Claimed failure: recordRunningDescendants removes a launcher from the running map only when that launcher's own task_notification arrives. A background_tasks_changed snapshot that no longer lists the launcher does not remove it, and the fixture shows native emits that snapshot before the launcher's notification. Suppose the nested child's task_notification arrives in that window: the launcher has ended (it has left the snapshot), but its notification has not been processed. Native routes the child's completion to the main conversation, yet parentRuns is true. acceptMessage then deletes the child from pendingBackgroundTaskIds and taskNotifications. The next main-stream result is delivered as terminal and the turn completes. The forwarded child answer arrives after the turn has settled, so the user never gets the nested agent's final answer. The remaining entries in runningDescendants can also make completeTurn abort the warm process.

## F2: Stopping the last nested task leaves the turn open
- Where: `extensions/anthropic/cli.runtime.ts`:484
- Claimed failure: When a background parent has already returned its answer and its nested Agent or Workflow is the only remaining hold, the runtime emits the parent's answer as interim. If Claude then reports the child as stopped, this branch clears the hold, but turn settlement still requires a later result. Stopped tasks produce no follow-up result, so the turn stays active until the watchdog fires.
