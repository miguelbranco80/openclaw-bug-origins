# Case 0205: findings to check

## F1: Bottom size-change anchor makes user-expanded content near the live edge grow upward
- Where: `apps/shared/OpenClawKit/Sources/OpenClawChatUI/ChatView.swift`:485
- Claimed failure: defaultScrollAnchor(.bottom, for: .sizeChanges) applies to every content size change whenever followTarget == .latest and the user is not dragging, not only to the growing live bubble. A reader at the bottom who taps a completed-work disclosure or expands a long user message near the end sees the content above the bottom jump upward. The tapped header can move off the top of the screen and the expanded content grows upward, where before it expanded downward in place.

## F2: A saved reply can appear alongside its stale streaming prefix
- Where: `apps/shared/OpenClawKit/Sources/OpenClawChatUI/ChatViewModel+TranscriptCache.swift`:28
- Claimed failure: If the live bubble shows “Hello” and the stream has already received “Hello world,” a saved “Hello world” message arriving before the next display update is compared against “Hello.” The transcript shows both the full reply and its stale prefix until the display update or a terminal event clears the live bubble. Touch tracking can defer that display update.

## F3: Paced live text lags durable history, so duplicate suppression fails and a partial live bubble shows under the recorded answer
- Where: `apps/shared/OpenClawKit/Sources/OpenClawChatUI/ChatViewModel+TranscriptCache.swift`:28
- Claimed failure: liveText() hides the live bubble only when the newest assistant row's raw text exactly equals the live text. The bubble and the shape now feed it displayedStreamingAssistantText, which can trail streamingAssistantText by up to 150 ms, and longer while a touch or scroll keeps the run loop out of default mode. Suppose a history refresh or narration settle records an assistant row with the full text while the run is still live, for example an intermediate item before a tool call, or another client's completion while a local run keeps the stream. If the last delta arrived inside the pacing window, the displayed prefix does not match the durable row. The user then sees the full recorded message plus a truncated duplicate live bubble until the paced flush runs. Before this change the authoritative text matched and the duplicate never showed.

## F4: Jump to latest can stay hidden while a reply grows
- Where: `apps/shared/OpenClawKit/Sources/OpenClawChatUI/ChatViewModel.swift`:816
- Claimed failure: If a history refresh introduces a new user message and buffered reply text together, the transcript anchors to the question and clears the flag that shows Jump to latest. Subsequent chunks of already-visible reply text no longer trigger the timeline update that sets the flag. The reply can grow below the viewport while the button stays hidden until another timeline event or a manual scroll.
