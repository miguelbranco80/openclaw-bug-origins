## F1: Retained search reader skips persisted corruption quarantine on every request after the first
- Where: `extensions/memory-core/src/memory/manager-search.worker.ts`:137
- Claimed failure: Previously every keyword/curated/index-state/vector request opened a fresh connection through openOpenClawAgentDatabaseReadOnly, which runs revalidateAgentDatabaseTerminalOpen and readOpenClawDatabaseQuarantineFailure and throws when the database has been quarantined as corrupt. With retainOpenClawAgentDatabaseReadOnly the cached scope reuses its idle reader and only calls assertAgentDatabaseTerminalOpenAllowed, whose latch is a per-thread global singleton that the search worker thread does not register. Once the Gateway (another thread) quarantines a damaged memory/agent database, the search worker keeps serving recall and search results from the quarantined file instead of failing with the quarantine error; because each recall turn refreshes the idle timer, under steady traffic this can last indefinitely.

## F2: Warmed memory readers bypass newly recorded quarantine
- Where: `extensions/memory-core/src/memory/manager-search.worker.ts`:137
- Claimed failure: If a search worker has already opened an agent database and the Gateway verifier then quarantines that same file, a queued curated recall request can still return snippets from it. The verifier closes handles and sets the terminal latch in the Gateway isolate. The worker keeps its own handle and checks only the file identity and its worker-local latch when borrowing it again. If the corruption is outside the memory tables, the curated query can succeed and supply snippets to automatic recall even after quarantine has been recorded. The previous fresh-open path checked the persisted quarantine before running the query.

## F3: Failed search keeps its broken connection for later requests
- Where: `extensions/memory-core/src/memory/manager-search.worker.ts`:216
- Claimed failure: The finally block always just releases the borrow, even when the request threw (e.g. SqliteSchemaMismatchError 'schema admission changed; retry the request', SQLITE_CORRUPT, or an I/O error). The cached scope's own read() path discards the connection on error for exactly this reason, but retain() has no such handling, so the next search request on that worker reuses the same connection and can fail the same way, whereas the old per-request open recovered on the next request.
