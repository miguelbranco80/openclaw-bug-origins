## F3: Paced live text lags durable history, so duplicate suppression fails and a partial live bubble shows under the recorded answer
- Where: `apps/shared/OpenClawKit/Sources/OpenClawChatUI/ChatViewModel+TranscriptCache.swift`:28
- Claimed failure: liveText() hides the live bubble only when the newest assistant row's raw text exactly equals the live text. The bubble and the shape now feed it displayedStreamingAssistantText, which can trail streamingAssistantText by up to 150 ms, and longer while a touch or scroll keeps the run loop out of default mode. Suppose a history refresh or narration settle records an assistant row with the full text while the run is still live, for example an intermediate item before a tool call, or another client's completion while a local run keeps the stream. If the last delta arrived inside the pacing window, the displayed prefix does not match the durable row. The user then sees the full recorded message plus a truncated duplicate live bubble until the paced flush runs. Before this change the authoritative text matched and the duplicate never showed.
