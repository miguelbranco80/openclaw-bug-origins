## F1: Compaction summary in the settled view loses its required-boundary treatment
- Where: `src/agents/embedded-agent-runner/run/attempt-history-prepare.ts`:29
- Claimed failure: Every settled message, including a compactionSummary produced by compaction during the source attempt, is wrapped as an entry of type 'message'. selectBoundedModelRequests only pins entries of type 'compaction'/'reset' as the boundary, so under byte pressure (e.g. screenshot-heavy turns exceeding contextTokenBudget*8 bytes) the summary at the head of the view is the first thing cut. The finalizer then answers without the summarized earlier context, whereas transcript hydration always retained the compaction boundary.

## F2: Settled-view bounding throws on messages without a valid numeric timestamp
- Where: `src/agents/embedded-agent-runner/run/attempt-history-prepare.ts`:32
- Claimed failure: boundSettledFinalizationMessages builds a synthetic entry with `new Date(message.timestamp).toISOString()` for every message in the frozen settled view (only to fill a field the selector never reads). The settled view now comes from activeSession.messages, which for context-engine sessions is whatever the engine's assemble() returned; assembled messages are not normalized and a plugin-produced summary/custom message without a timestamp (or with a non-date string) makes toISOString throw RangeError('Invalid time value'). prepareEmbeddedAttemptHistory then fails, the isolated finalizer errors, and the turn ends as 'settled-turn finalization failed — preserving failed recovery' with no final answer, where before the change finalization rehydrated the transcript and succeeded.

## F3: Storage-only tool details can prevent finalization
- Where: `src/agents/embedded-agent-runner/run/attempt-history-prepare.ts`:54
- Claimed failure: A plugin tool can return a short success receipt with a diagnostic details field larger than the finalizer's byte limit. The live tool result retains those details, while durable model-context hydration strips them. The new sizing pass counts the details before replay cleanup, and replacing the result body leaves them in place. If this is the last tool result and the model then returns an empty answer, the selector cannot retain the completed tool frame. Finalization fails before contacting the provider, leaving the user without a summary of the completed work.

## F4: A legacy message timestamp can abort finalization
- Where: `src/agents/embedded-agent-runner/run/attempt-history-prepare.ts`:33
- Claimed failure: An imported transcript can contain a historical user message with a valid entry timestamp and no timestamp inside the message payload. Session hydration preserves that payload, and a provider such as OpenAI Responses can replay its text. When a later tool turn needs finalization, converting the missing payload timestamp to ISO throws before the selector can even decide whether to retain that row. The completed tool turn gets no final answer.

## F5: Finalization can discard the active compaction summary
- Where: `src/agents/embedded-agent-runner/run/attempt-history-prepare.ts`:30
- Claimed failure: A compacted session can start a tool turn with a summary and retained history that fit the byte limit, then exceed that limit after the current request and completed tool exchanges are added. Durable hydration reserves space for the compaction summary before selecting the recent suffix. The new wrapper labels the summary as an ordinary message, so the suffix cut can discard it even when the summary and current turn fit together. The finalizer can then answer without decisions or constraints recorded only in that summary.
