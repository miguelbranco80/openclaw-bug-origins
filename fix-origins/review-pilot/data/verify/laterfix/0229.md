## F5: Candidate Doctor preflight throws on unparseable copied plugin source even when the snapshot is complete
- Where: `src/infra/update-candidate-plugin-repair.ts`:116
- Claimed failure: completeUpdateCandidatePluginRehearsal inspects every selected entry in the private copy, including Doctor contract modules of disabled plugins, with an unguarded inspectPluginSourceDependencies([entry]). Only the later inspection of the original source is wrapped in try/catch. Errors propagate through createDoctorRehearsalSnapshotPreparation into readDoctorConfigPreflightSnapshot, so they fail candidate Doctor preflight. Example: an enabled plugin, or a disabled plugin's doctor-contract module, has a source file the static inspector cannot parse or capture, even though it needs no repair. Every update driven by a published updater then fails in candidate Doctor, where before the plugin was at most reported by Doctor or plugin loading. The 'invalid source' handling only covers the original tree, and the malformed-plugin tests only cover the runtime entries of disabled plugins.

## F7: Update preparation now aborts when any plugin's source cannot be statically inspected
- Where: `src/infra/update-candidate-plugins.ts`:349
- Claimed failure: prepareUpdateCandidatePlugins now runs inspectPluginSourceDependencies over every enabled plugin entry, setup entry and every declared Doctor contract module (including those of disabled plugins), and nothing catches its errors. inspectPluginSourceDependencies rethrows anything outside a short list of module-not-found codes: parse/lexer failures from visitPluginSourceReferences, 'Plugin source link leaves its package', non-regular build inputs, and so on. The repair path in the same change expects such failures from original sources and turns them into warnings, but this path has no such handling. A user whose custom or npm plugin, or a disabled plugin's doctor-contract file, contains syntax the inspector rejects or a link it refuses could update before this change, because the tree copier just copied the directory. Now the whole update rehearsal fails with an inspection error that is unrelated to the update.
