## F1: Concurrent refresh can pair an old base with the refreshed checkout
- Where: `src/gateway/worker-environments/local-workspace-review.ts`:45
- Claimed failure: If Review reads the projection just before `refresh_base` accepts a new base, and its queued Git read starts after the refresh finishes, it compares the refreshed checkout to the old SHA. Refresh changes neither the session binding nor the registry identity, so both final guards pass. Review can return upstream-only files and commits in the task diff.

## F2: Review applies the outer repository's base to a nested checkout
- Where: `src/gateway/worker-environments/local-workspace-review.ts`:57
- Claimed failure: Worktree preparation supports a session whose cwd is a subdirectory of the managed checkout. If that directory becomes a separate Git checkout after the projection is created, the path containment check still passes. Git resolves the nested repository from the session cwd, but Review supplies the outer repository's SHA. When that SHA is absent from the nested repository, All changes fails with `Unable to read tracked Git changes`. Previously Review used the nested repository's own refs.

## F3: Review of an archived sandboxed session now throws instead of returning an empty/unavailable diff
- Where: `src/gateway/worker-environments/local-workspace-review.ts`:392
- Claimed failure: Archiving a session with a managed worktree keeps entry.worktree and spawnedCwd but removes the worktree (registry removedAt set, snapshotRef kept); the local workspace projection row is only deleted later by retention expiry. Opening Review on such an archived session now finds the projection row, matches the binding, then hits `worktree.removedAt !== undefined` and throws "Local workspace review owner changed". Before the change the missing checkout made loadCheckoutRevision return undefined and sessions.diff returned an empty not_git result; now the operator sees an RPC error in the Review panel for every archived sandboxed session until the projection expires (about 31 days).

## F7: Pending/conflicted base refresh leaves stale base_commit while canonical checkout already contains upstream
- Where: `src/gateway/worker-environments/local-workspace-review.ts`:401
- Claimed failure: During refresh_base the staged result is applied to the canonical worktree first (pending_target switches to projection) and base_commit is only advanced after the projection side applies without conflicts. If the projection side conflicts, the row stays pending with the old base_commit while the canonical checkout already holds the upstream content. Review now forces the old accepted base, so it shows every upstream-only file as a task change (the very symptom being fixed), even when the default-branch refs are current and the previous ref-based base would have hidden them.
