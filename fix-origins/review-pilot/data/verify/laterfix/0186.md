- Where: `extensions/codex/src/app-server/session-history.ts`:134
- Claimed failure: The catch now rethrows any error for view "model-context", not only the new RangeError from the limit. Before this change, ordinary read failures such as SessionTranscriptReadFenceError ("Session transcript changed during context read" when an unadmitted async read races an append), a CodexHistoryRejection for a malformed header, or the 60 s worker timeout returned undefined. Callers then logged a warning and continued with empty or previous history (attempt-context.ts warn branch, run-attempt-context `?? []` and `?? historyState.messages`). Those transient failures now abort the whole Codex attempt during prompt preparation, so the user sees a failed turn where the run used to continue.

## F6: Byte budget counts raw payload bytes such as base64 images against tokens*8, so one large recent message truncates or fails the read
- Where: `src/config/sessions/session-accessor.sqlite-model-context.ts`:172
- Claimed failure: maxBytes is contextTokenBudget*8 (about 1 MB at 128k tokens), measured as octet_length of the projected event JSON. Inline image data and large tool outputs count byte for byte, although they cost few tokens or are sanitized later. The tail scan breaks at the first entry that does not fit instead of skipping it. So one recent 2-4 MB photo or screenshot tool result drops all older history from before_prompt_build hooks and context-engine input, even though the history would easily fit the model's context. If that entry is in the newest message or tool frame, the read throws "cannot fit the model-context limit" and the turn or compaction handling fails until the user runs /reset.
