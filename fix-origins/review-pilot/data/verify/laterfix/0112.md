## F2: Hovering any external link makes the Gateway GET the full URL, consuming one-time/action links
- Where: `ui/src/components/link-reader-target.ts`:1551
- Claimed failure: resolveHoverPreviewTarget accepts every http(s) cross-origin anchor that isn't one of a few hard-coded markers (only the wizard sign-in button was opted out via data-link-reader-external). A chat transcript or settings page containing a magic-login, email-confirmation, password-reset, unsubscribe, invite-accept or OAuth authorize link (with its token in path/query) will, on a 250 ms mouse hover or keyboard focus, be sent to controlUi.linkPreview and fetched by the Gateway with a plain GET. Sites that act on GET consume the one-time token or perform the action (confirm/unsubscribe), so when the operator later clicks the link it reports 'link expired/already used', or the action happened without a click. The change itself recognizes this hazard for the wizard sign-in URL but leaves all other authorization/action links in transcripts exposed.

## F3: Hover and focus changes inside the link reader go unnoticed
- Where: `ui/src/components/link-reader-hovercard.ts`:295
- Claimed failure: Links in a GitHub issue body are inside the link reader panel's shadow root. When the pointer moves from issue text onto a link, or keyboard focus moves between controls in that same root, the browser keeps the transition events inside the root. The provider's outside listeners miss them, so previews can fail to open. If a preview was opened by entering the link from outside the root, moving onto nearby issue text can leave the preview open and allow a brief hover to trigger a fetch.
