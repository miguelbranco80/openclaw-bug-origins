## F1: Desktop size select keeps 88px width but now carries the shared select's wide chevron padding, truncating its value on touch
- Where: `ui/src/components/desktop/desktop-panel.css`:140
- Claimed failure: The desktop sizing select (non-menu presentation, including the desktop-touch-toolbar in document mode) stays at a fixed 88px but now takes settings-select chrome: --field-padding-inline (10px) on the left and calc(26px + 0.5em) on the right (36px in browsers without base-select), plus borders, instead of the old 0 6px padding and 12px type. That leaves about 40-42px for the value. On a coarse-pointer device the global 16px !important select floor applies, so 'Actual' (and 'Match') no longer fit and render as 'Actu...' / 'Matc...' via the new one-line clamp (or are clipped in Firefox). Longer translations are truncated even at desktop type size. The user cannot read the current sizing mode in the touch toolbar.
